# v1.1 插件包与隔离界面 ADR

> 决策编号：ADR-v1.1-R11-01  
> 创建时间：2026-09-21；最后状态同步：2026-09-23（Asia/Shanghai）
> 状态：已接受为 R11-01 合同基线；v4 PDF Viewer 的隔离 UI、Bridge、发布发现和用户配置已有实现。通用 Runtime、安装状态机与目标环境浏览器/恢复证据仍需后续任务验证。
> 关联计划：[v1.1 插件自包含与动态加载重构计划](02-v1.1插件自包含与动态加载重构计划书.md)

## 1. 决策

插件源码使用 `plugins/<plugin-key>/plugin.yaml` 的 `campusos.plugin/v4` Manifest；源码、安装产物和安装暂存分离，
分别为 `plugins/<key>/`、`plugins/.installed/`、`plugins/.staging/`。发现目录不等于安装、启用或执行。

插件用户/管理员页面将在后续以独立 Origin 的 sandbox iframe 加载。宿主只内置通用 Host、路由、弹层、授权、配置表单和 Bridge；
不在主站动态 import、`eval` 或注入插件 JS。插件不能指定自身 Origin、宿主文件路径、数据库表、命令、URL 或凭据。

R11-01 已在 `internal/plugin/v4` 固化 Manifest、受限配置 Schema 以及 `campusos.bridge/v1` 消息类型。后续实现已让 `campusos.pdf-viewer` 的已验证发布包通过独立 Origin iframe 与 Host Bridge 运行；它没有接入旧 v1-v3 安装器，也没有在主站动态执行任何 `plugins/` 源码页面。

## 2. 保护对象与信任边界

| 对象 | 所有者 | 不可交给插件的内容 |
| --- | --- | --- |
| 登录会话、JWT、管理员身份 | 宿主 Identity | Cookie、Token、管理员万能权限 |
| 文章、个人空间、个人文档及 Object | 业务模块 | 任意 owner、路径、对象 ID 或绕过 ACL 的 Range 读取 |
| 插件安装、版本、Grant、Consent、Secret | 平台插件服务 | 自行批准能力、伪造授权、明文 Secret |
| 用户配置文件 | 用户配置服务 | 其他用户目录、直接磁盘挂载、任意 schema/脚本 |
| 插件私有运行数据 | 对应 Runtime | PostgreSQL/Redis/NATS 连接、宿主环境变量、其他插件目录 |

iframe 与主站、静态资产网关与 Host Gateway、安装产物与源码树、系统配置与用户配置、管理员操作与插件页面均为独立信任边界。

## 3. 冻结的 v4 合同

1. `plugin.yaml` 必须声明精确 API/UI/Bridge 版本、安全包内路径、稳定 key、SemVer、发布者、UI audience、Surface、可选的 Preview Provider、`self` Scope Capability 和可选配置定义。
2. Runtime 只可声明 `none`、`wasm`、`container`；Manifest 不携带 shell 命令。选择 Runtime 不代表已经可运行。
3. JSON 配置 schema 只允许受限声明式子集；禁止远程 `$ref`、可执行验证器和根级未知字段。`$schema` 仅接受固定 JSON Schema vocabulary，并且宿主不会联网获取它。
4. `campusos.bridge/v1` 只预留 `config.*`、`resource.describe/readRange`、具名 `backend.invoke`、`ui.requestSurface` 与 `records.*`。单条消息不超过 64 KiB，单次 Range 不超过 1 MiB。
5. Bridge 参数中不承认 `userId`、`pluginKey`、文件路径、URL、SQL 或 Token 为认证事实；后续服务端必须用宿主签发的会话上下文再次检查安装版本、Grant、Consent 和业务 ACL。

## 4. 威胁与处置

| 威胁 | R11-01 处置 | 后续验收门禁 |
| --- | --- | --- |
| 路径穿越、符号链接、远程 UI | Manifest 与目录校验拒绝不安全路径/链接 | R11-03 对压缩包、摘要、签名和原子安装做负向测试 |
| 插件脚本读取主站状态 | 不准主站动态执行插件源码 | R11-02 必须验证独立 Origin、sandbox、`postMessage` source/origin/challenge 与旧 Port 失效 |
| Bridge 越权读取文件 | 只声明有限方法/大小限制，不提供 owner/路径/SQL | R11-02/06/09 每次 Host 调用重做 ACL、Grant、Consent 和撤权测试 |
| 配置逃逸或执行代码 | 限制 Schema，配置不作为授权凭据 | R11-07 验证用户目录、CAS、预算、崩溃恢复和跨用户隔离 |
| Runtime 获取基础设施能力 | Manifest 不接受命令/环境声明 | R11-05 验证 Wasm/Container 受限身份、网络、挂载、资源和恢复 |

## 5. 后果与非结论

这项决定使下一阶段可以验证隔离 UI，而不会先把 PDF 页面从现有可工作的宿主路径移走。它不表示插件已经安装、
用户目录已经生成、授权界面已经切换、PDF 已动态加载或旧 v1-v3 合同已经删除。

如果 R11-02 无法满足跨 Origin iframe、PDF.js Worker 和受控 Range 的安全/兼容性门槛，必须修订隔离方案并更新本 ADR；
不得退回主站动态执行插件 JS，也不得把原型成功误写为全版完成。
