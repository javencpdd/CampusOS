## 2. 执行摘要

v1.1 聚焦两个可独立验收的用户价值：为图文文章增加受控附件，以及交付可在弹窗、全屏层或 CampusOS
同源新标签页中工作的第一方 PDF 预览插件。User Asset 不再作为本版的大一统改造目标，而是作为附件和 PDF
预览需要的最小公共资产底座；底层字节继续由 Core User Storage 的 `storage_objects` 与 Object Port 管理。

```text
RichText Article
  -> Inline/Cover Image Binding（参与图文排版）
  -> Attachment Binding（只作为附件展示）
     -> User Asset（稳定身份、owner、状态）
        -> Storage Object（字节、哈希、配额、Provider）

Attachment Card
  -> PDF：宿主打开 PDF Viewer Surface
  -> 其他格式：认证下载
```

“Resource”一词在 CampusOS 中已经表示无 Runtime 的 Resource Package，因此用户界面、API 和代码统一使用
`asset`，避免把用户文件与主题/风格等资源包混为同一生命周期。

v1.1 的交付主线是：

```text
图文草稿 -> 上传或选择附件 -> Article-Attachment 显式绑定 -> 发布/下架联动 -> 认证下载
                                                     -> PDF Viewer Plugin
                                                        -> modal/fullscreen/new-tab
```

图片继续用于封面和正文排版；PDF、MP3、MP4、DOC/DOCX、XLS/XLSX、ZIP、RAR 只作为附件。本版只为 PDF
提供在线预览，其他附件提供安全下载。`.exe`、脚本和其他可执行文件默认禁止；“Excel”明确指 `.xls/.xlsx`。

## 3. 当前代码与数据事实

### 3.1 已有能力

| 当前能力 | 代码/数据事实 | v1.1 复用方式 |
| --- | --- | --- |
| Core User Storage | `ObjectPort` 已有 owner、namespace、purpose、流式 Put/Open、SHA-256、状态和配额 Reservation | 继续作为唯一字节边界，不向业务或插件暴露路径 |

| 插件文件 | `plugin_file_metadata`、用户授权、受管文件上传/下载/删除已存在 | 作为插件拥有命名空间的用户资产适配器，不再拥有第二套物理存储模型 |

| 可靠任务 | Outbox、重试、dead-letter、receipt、审计和恢复已存在 | 异步校验、缩略图或未来转换任务复用，不另造队列 |
| 本地 Provider | 当前 Object Provider 只支持 local | v1.1 只要求 Port 兼容，不宣称已经交付 S3/MinIO |

### 3.2 计划制定时的缺口（现已作为 v1.1-dev 实现基线）

1. RichText 当前只有图片资产，没有独立于 HTML 的附件清单、排序、显示名和文章状态联动。
2. 直接把附件 URL 写入 HTML 会造成死链、路径暴露和文章下架后仍可访问等不可接受边界。
3. `storage_objects` 是字节事实，缺少供文章附件引用的稳定、owner-scoped Asset 身份。
4. PDF 当前只有安全下载降级；下载端点也尚未形成统一的 `Range`、`If-Range`、`ETag`、`206/416` 合同。
5. Plugin UI v1 的声明式 Schema 不能承载 PDF.js Canvas/Worker；`trusted-module` 又只能使用编译期白名单。
6. 当前没有宿主控制的插件弹窗、全屏层和同源新标签页，也没有短期 `invocation_id` 上下文。
7. 附件类型、数量、单文件/单文章总量、配额、引用保护和中文错误提示尚未形成统一合同。

## 4. 版本目标与成功标准

### 4.1 核心目标

1. 为图文文章增加独立附件清单，支持上传、选择已有资产、排序、移除、下载及草稿/发布/下架联动。
2. 图片继续承担封面和正文排版；PDF、MP3、MP4、Office、ZIP/RAR 等文件只作为附件，不进入 HTML 排版。
3. 建立满足附件引用所需的最小 User Asset -> Storage Object 模型，不在本版强制迁移头像、Personal Documents 或全部插件文件。
4. 交付第一方 PDF Viewer Plugin，支持宿主弹窗、全屏和同源新标签页，并符合认证 HTTP Range 语义。
5. 将 Plugin UI 升级为向后兼容的 `campusos.ui/v2`：插件声明 Surface，宿主决定 Presentation、上下文和生命周期。
6. 让附件继承文章访问策略；文章草稿、私密、下架或附件隔离后，不得继续通过旧 URL 读取。
7. 建立 active、trashed、quarantined、deleted 生命周期、引用保护、配额和可恢复清理。
8. 提供具体中文限制、失败原因、已用/剩余配额和修复建议，并同步 Schema、ER、UI、Capability 和路由合同。

### 4.2 量化验收标准

| 维度 | v1.1 Final 门槛 |
| --- | --- |
| 附件闭环 | 图文草稿可上传/选择、排序、移除附件；发布后展示；下架后普通用户立即失去访问 |
| 类型边界 | 图片可排版；PDF/MP3/MP4/DOC(X)/XLS(X)/ZIP/RAR 只显示附件卡；可执行文件默认拒绝 |
| 所有权 | 上传、绑定、移除、下载、预览、回收站和插件调用均有跨用户负向测试 |
| Range | PDF 单 Range、开放区间、后缀区间、`If-Range`、无效范围 `416` 和重复跳页请求均有自动测试 |
| PDF | 支持打开、翻页、缩放、页码跳转；不加载外部 URL，不执行 PDF JavaScript，不绕过认证 |
| Plugin UI | UI v1 插件无回归；PDF Surface 可由宿主以 modal/fullscreen/new-tab 打开，停用后不可调用 |
| 调用上下文 | URL 不携带 JWT/路径/永久下载令牌；随机短期 `invocation_id` 绑定用户、第一方 Viewer、Asset 和用途；有效期内可服务 PDF 的多次 Range 请求 |
| 配额 | 附件按实际 Object 字节计量；并发上传不能突破用户配额、单文件和单文章总量限制 |
| 安全 | 不返回宿主路径、storage key、JWT、运行令牌、Secret 或可长期复用的公开 URL |
| 性能 | Range 不把完整 PDF 载入服务端内存；20 路预览基准下 RSS 与延迟不超过 G0 批准阈值 |
| 可恢复 | reset、空库 up、全链 down/up、对象/账本对账、备份恢复和引用保护均有证据 |

## 5. 范围与优先级

### 5.1 P0：v1.1 必须完成

- G0 数据、路由、权限、容量、附件类型和 PDF 样本基线；术语、可见性和威胁模型 ADR。
- 最小 User Asset、Article Attachment Binding、Repository/Service/Port 和 owner-scoped 资产选择器。
- 图文文章上传附件、选择已有附件、排序、移除以及附件卡片；图片继续使用排版流程。
- PDF/MP3/MP4/DOC/DOCX/XLS/XLSX/ZIP/RAR 附件允许列表；`.exe` 和脚本默认拒绝。
- MIME/magic、一致性、文件名、数量、单文件/单文章总量、配额和中文错误合同。
- 附件继承文章访问判定；草稿、私密、下架、隔离、回收和删除状态即时生效。
- 认证 PDF 内容端点、完整 Range/ETag/If-Range 行为和流式响应。
- 向后兼容的 Plugin UI v2、`open-surface`、modal/fullscreen/new-tab 和短期 Invocation Context。
- 第一方受信任 PDF Viewer Plugin；插件停用或不可用时安全降级为认证下载。
- migration、ER、Schema、UI、Capability、Route、Error 和真实浏览器门禁。

### 5.2 P1：v1.1 应完成

- 附件访问的低敏审计、限流、容量指标、对象对账和恢复演练。
- PDF Viewer 的键盘操作、移动端全屏、目录、页内搜索和最近阅读位置。
- Plugin UI v2 SDK/类型、示例 Surface、Conformance 和停用/升级/崩溃恢复测试。
- 从 RichText 旧图片 URL/目录清单到显式 Asset 引用的测试数据 reset/cutover；不保留长期双写。

### 5.3 P2：不阻塞 v1.1 Final

- S3/MinIO/OSS/WebDAV Provider、CDN、分片上传、断点续传和秒传/去重。
- FFmpeg 转码、HLS/DASH、自适应码率、波形、缩略图集和媒体处理集群。
- MP3/MP4 在线播放、DOCX/Office 在线转换、PDF 编辑/OCR、全文或向量检索。
- 匿名分享链接、密码分享、公开外链、协作编辑、评论和多人版本合并。
- 防病毒引擎、DLP、版权指纹和完整内容审核平台。
- 任意第三方 JavaScript Bundle；它必须等待独立的 `sandbox-iframe`、CSP、签名和 Bridge 安全项目。
- 用户之间分享资产、插件批量读取全部用户资产、跨用户访问或插件间转授。

### 5.4 明确非目标

- 把 User Asset 当作现有 Resource Package；二者生命周期、所有权和发布边界不同。
- 新增一套绕过 `storage_objects` 的文件路径服务，或让业务代码直接 `os.Open` 用户路径。
- 用 Resource ACL 替代 v1.0 AuthorizationService，或用 User Consent 覆盖管理员拒绝。
- 把附件 URL 直接写入正文 HTML，或让下架文章继续通过旧地址读取附件。
- 允许插件提交任意 URL、直接 `window.open()`、主动弹窗或在主站动态 `import()` 未受信任代码。
- 宣称“仅允许预览但绝对不能保存”。PDF 预览必须把字节交给浏览器，v1.1 不提供 DRM。
- 因测试数据可删除而静默修改已经冻结的 `000001-000005`；Schema 变化仍从 `000006` 追加。
- 在 API 进程内执行不受限的 Office/PDF/媒体转换器。

## 6. 核心架构与模块职责

```text
RichText Editor / Thread Detail
  -> RichText Attachment Service
     -> Article Access Policy + Attachment Binding
     -> Minimal User Asset Repository
     -> Object Port (Core User Storage)

Attachment Card --open-surface--> Plugin UI v2 Host
  -> modal / fullscreen / CampusOS same-origin new-tab
  -> PDF Viewer trusted-module
  -> short-lived Invocation Context
  -> Authenticated Asset Content Gateway
  -> Object Port
```

| 模块 | 职责 | 禁止承担 |
| --- | --- | --- |
| `core.user-storage` | Storage Object、流式 Provider、Reservation、配额、哈希、对账 | 分享业务、插件授权、文档编辑、公开 URL |
| 最小 `feature.personal-assets` | Asset 身份、owner、状态、选择列表、引用保护 | 本版强制迁移全部个人空间业务或建立第二套字节账本 |
| `feature.controlled-richtext-article` | 图片排版、附件绑定/排序、文章状态联动和展示 | 在 HTML 中保存宿主路径或不受控附件 URL |
| `internal/plugin` / UI Runtime | UI v1/v2 适配、Surface、Presentation、Invocation、插件生命周期 | 接收插件自报用户/Asset、打开任意 URL、注入未受信任脚本 |
| PDF Viewer Plugin | PDF.js 页面、缩放、跳页、错误态和展示模式适配 | 直接读数据库/文件路径、持有 JWT 或永久下载 URL |
| Asset Content Gateway | 文章/owner/插件判定、Range、ETag、安全响应头 | PDF 渲染、Office 转换 |
| Web | 附件编辑器、卡片、宿主弹层和同源新标签页 | 作为最终权限边界或允许后台任务主动弹窗 |
| Admin | 策略、配额、隔离/失败聚合、审计诊断 | 默认浏览用户文件正文 |

Plugin UI v2 必须兼容全部 UI v1 Manifest。`modal`、`drawer`、`fullscreen`、`new-tab` 是宿主选择的
Presentation，不是四种插件权限；后台事件不得主动打开界面，只能产生通知。第一方 PDF Viewer 使用编译期登记的
`trusted-module`。真正运行时安装的第三方 UI Bundle 不属于本版，后续必须使用独立 Origin 或严格
`sandbox-iframe`，不能把上传的 JavaScript 动态导入主站。

## 7. 数据模型与 migration 方案

### 7.1 目标模型

| 表/事实 | 核心字段 | 约束与用途 |
| --- | --- | --- |
| `user_assets` | `id`、`owner_user_id`、`kind`、`original_name`、`status`、`storage_object_id`、`mime_type`、`size_bytes`、时间字段 | 本版最小稳定身份；owner/Object FK；名称非空；状态和大小受 CHECK；不保存路径 |
| `richtext_article_attachments` | `id`、`article_content_id`、`asset_id`、`display_name`、`display_order`、时间字段 | 文章与附件多对多绑定；组合唯一；删除文章只删除绑定，不静默删除 Asset |
| `plugin_ui_invocations` | `id`、`user_id`、`plugin_key`、`surface_id`、`article_content_id`、可空 `asset_id`/`attachment_id`、`presentation`、`purpose`、`expires_at`、`opened_at`、`context_digest` | 短期、服务器端上下文；为 PDF.js 多次 Range 可在有效期内重复读取，但每次重验；不得保存 JWT、路径或原始 Secret |

`storage_objects` 继续保存物理字节事实；它不是文章绑定或业务生命周期表。RichText 正文图片在本版可以通过
前向 migration 关联最小 Asset，但不要求 Personal Documents、头像和插件受管文件同时完成大迁移。
`plugin_ui_invocations` 只有在服务端无状态签名上下文无法满足即时撤销、一次消费和审计时才落表；G0 ADR
应优先比较“服务端记录 + 随机 ID”与“短期签名令牌 + 吊销表”，禁止把敏感上下文放入查询字符串。

### 7.2 索引规划

- `user_assets(owner_user_id,status,updated_at DESC,id DESC)`：用户清单 keyset 分页。
- `user_assets(owner_user_id,kind,updated_at DESC,id DESC)`：附件选择器的类型筛选。
- `user_assets(storage_object_id)` 唯一索引：一个最小 Asset 对应一个 Object；未来版本化需求另立 migration。
- `richtext_article_attachments(article_content_id,display_order,id)`：文章附件稳定排序。
- `richtext_article_attachments(asset_id,article_content_id)`：删除前引用检查；组合唯一防重复绑定。
- `plugin_ui_invocations(expires_at)`：清理；如需恢复查询，再增加 `(user_id,plugin_version_id,expires_at)`。
- 不为低选择性状态单独建窄索引，也不为暂未查询的 JSONB 建 GIN。

### 7.3 migration 序列

| 版本 | 内容 | 回滚原则 |
| --- | --- | --- |
| `000006_v1_1_article_attachments` | 最小 Asset、Article Attachment Binding、类型/状态约束和索引 | 仅在未切流且无 v1.1 附件时允许 down |
| `000007_v1_1_plugin_ui_invocations` | 必要时增加短期 Invocation、吊销/消费和清理索引 | 回滚先停用 UI v2 新入口；不删除 Asset/Object |
| `000008_v1_1_attachment_cutover` | 测试数据 reset 后清理 RichText 新写入对裸 URL/路径的依赖 | destructive down 不作为生产恢复手段；使用 forward-fix |
| `000009_v1_1_asset_governance` | 追加 Asset `purging` 状态、低敏生命周期审计和最小治理权限 | production 不使用 down 擦除审计；对象清除失败采用前向重试/对账 |

项目所有者已确认当前数据均为测试数据，因此 v1.1 不承担旧测试数据保留或批量 backfill：实施前使用 development/test
双确认 reset 重建数据库。migration 必须检测非空旧事实并明确拒绝隐式迁移，避免以后误用于真实实例。即便如此，
`000001-000005` 仍不可改写；新的 Schema 从 `000006` 追加。

### 7.4 删除与配额语义

1. 从文章移除附件只删除 Binding，不删除 Asset/Object；资产继续计入 owner 配额。
2. 删除文章只删除文章绑定；同一个 Asset 被其他文章引用时仍然可用。
3. Asset 移入回收站不删除 Object，仍计入配额；文章附件立即不可读并显示明确状态。
4. 硬删除前必须确认不存在文章附件、正文图片或其他已登记引用。
5. PDF 预览不生成派生文件；原始 Object 只计量一次。以后生成缩略图时必须按真实字节计量。
6. 元数据删除与物理删除使用可靠命令和对账；未知文件只报告/隔离，不自动归属或删除。

## 8. 访问控制与 Capability 设计

### 8.1 普通用户访问公式

```text
允许读取文章附件 = 当前用户满足文章访问策略
                AND Article-Attachment Binding 有效
                AND Asset/Object 状态可读
```

草稿只允许作者访问；私密文章遵循现有私密策略；管理员下架、文章删除、Asset 回收/隔离后，普通读取立即失败。
附件是否允许匿名访问必须在 G0 ADR 中与现有文章可见性冻结；默认安全方案是只允许已登录且有文章读取权的用户。
PDF 预览会获得原始字节，因此不能宣传为强制“只能看、不能保存”。

### 8.2 插件访问公式

```text
允许 PDF 插件读取 = Manifest Declaration
             ∩ Admin Grant
             ∩ User Consent
             ∩ plugin/version/runtime 状态
             ∩ self Scope
             ∩ 宿主签发且未过期/未消费的 Invocation Context
             ∩ 当前用户可读取对应文章附件
             ∩ Asset/Object 可读状态
             ∩ 系统策略与限额
```

候选 Capability 在 G0 评审后进入 `campusos.capability/v1`：

| Capability | 风险 | 用途 |
| --- | --- | --- |
| `article_attachment.self.preview` | medium | 通过宿主签发的 Invocation 读取一个当前有权访问的 PDF 附件 |
| `plugin_ui.surface.open` | low | 声明 Surface 可由明确的用户操作打开；不授予任何数据权限 |

`plugin_ui.surface.open` 不是浏览器弹窗权限：插件不能提交任意 URL、不能从后台事件主动弹窗，也不能因此读取 Asset。
PDF 插件不能获得任意 owner、宿主路径、JWT 或长期下载 URL；每次 Range 请求继续由主业务 API 重新执行文章和 Asset 判定。

### 8.3 平台 RBAC

- 用户上传和绑定附件采用认证身份 + owner + 文章作者规则，不信任请求中的 `owner_user_id` 或 `article_content_id`。
- Admin 新增策略级 Permission Code：资产策略/隔离管理、聚合审计读取；不默认提供用户内容读取权限。
- 调整配额继续复用现有 Personal Space 管理权限；如拆分必须通过 Permission Catalog migration 和路由合同评审。
- 所有拒绝返回稳定错误码、中文修复建议和 request/trace ID，不返回 SQL、路径或底层 Provider 错误。

## 9. API 与前端合同

### 9.1 用户 API 候选

```text
GET    /api/v1/assets
POST   /api/v1/assets/upload
GET    /api/v1/assets/{id}
POST   /api/v1/assets/{id}/trash
POST   /api/v1/assets/{id}/restore
GET    /api/v1/assets/{id}/download
GET    /api/v1/assets/{id}/content

GET    /api/v1/richtext/articles/{thread_id}/attachments
POST   /api/v1/richtext/articles/{thread_id}/attachments
PATCH  /api/v1/richtext/articles/{thread_id}/attachments/order
DELETE /api/v1/richtext/articles/{thread_id}/attachments/{attachment_id}

POST   /api/v1/plugin-ui/invocations
GET    /api/v1/plugin-ui/invocations/{invocation_id}
```

- 列表使用 cursor/keyset，不用不稳定 offset。
- 附件上传和绑定可以是一个可靠命令，也可以先上传到个人资产后绑定；失败时不能留下无法识别的半成品。
- `content` 首版仅为 PDF Viewer 开放，支持 `Range: bytes=`、`If-Range`、`ETag`、`Last-Modified`、`206`、`416`。
- `download` 使用相同访问判定和字节源，只改变安全的 `Content-Disposition`。
- Invocation 只接受宿主已注册的 `surface_id`、Asset 和 Presentation，不接受任意跳转 URL；新标签页 URL 只携带随机 ID。
- 所有内容响应设置 `X-Content-Type-Options: nosniff`、同源策略和私有缓存边界。

### 9.2 Web 页面

- 图文编辑器新增附件区：上传、从自己的 Asset 选择、重命名显示、排序和移除；不把附件链接写进 HTML。
- 图片上传仍提供“设为封面/插入正文”，普通附件只显示附件卡片，不提供排版入口。
- 详情页附件卡显示名称、类型、大小；PDF 显示“预览/下载”，其他允许格式显示“下载”。
- PDF Viewer Surface 支持 modal、fullscreen、new-tab；新标签页必须是 CampusOS 同源 `/extensions/...` 路由。
- 宿主负责 ESC、焦点恢复、移动端全屏、加载/错误态、防重复弹窗和插件停用后的安全降级。
- 只有明确用户点击可以打开 Surface；后台任务和事件只能通知，不能主动弹窗或新开页面。
- “我的资源”本版只需提供附件选择所需的 owner-scoped 最小清单；全面资产管理和跨用户分享顺延。

### 9.3 Admin 页面

- 只显示数量、字节、状态、类型、失败/隔离原因分布和最近任务，不显示文件名或内容作为默认列表。
- 管理员可调整配额、隔离明显异常资产、查看低敏审计；恢复/删除高风险动作要求原因、权限和二次确认。
- 插件管理显示 UI 合同版本、Surface/Presentation、PDF Viewer 健康和最后错误；不得借此读取用户 PDF。
- 架构页展示源代码中的表和关系，不伪称实时数据库浏览器。

## 10. 预览与媒体安全设计

### 10.1 上传校验

1. 请求体先由 `MaxBytesReader` 限制，再进行流式读取；不能先解析完整 multipart。
2. 文件扩展名、声明 MIME 和内容 magic 必须相容；不能只相信浏览器 `Content-Type`。
3. 图片沿用像素/格式检查和压缩，只允许进入封面/正文图片流程；附件流程不对图片进行二次 HTML 拼接。
4. PDF 沿用并加强结构/危险动作限制；PDF.js 固定版本、同源 Worker、禁止外部 URL 和脚本动作。
5. OOXML 是 ZIP 容器，必须识别 DOCX/XLSX 内部结构；DOC/XLS 使用有界 OLE 签名识别。ZIP/RAR 只校验容器签名，不在服务端解压。
6. `.exe`、`.dll`、`.msi`、脚本、HTML/SVG 等可执行或主动内容默认拒绝；双扩展名和 MIME 冲突不以改名绕过。
7. 未知、损坏或超限内容进入拒绝或 quarantined，不以错误 MIME 强制下载或预览。
8. 默认 50 MiB 用户配额保持不变，管理员可调。G0 冻结单文件、单文章数量和附件总量，且单文件上限不能超过剩余配额。

### 10.2 PDF Viewer 与 Plugin UI v2

- PDF.js Viewer 是第一方 `trusted-module`，通过插件 Manifest 注册 Surface，但代码随受信任 Web 构建交付。
- UI v2 新增宿主控制的 `open-surface` 行为和 modal/drawer/fullscreen/new-tab Presentation；UI v1 继续适配。
- 新标签页打开 CampusOS 同源插件路由并使用 `noopener,noreferrer`；不得打开插件后端、任意第三方 URL 或服务器 `127.0.0.1`。
- 宿主生成短期 `invocation_id`，绑定用户、第一方 Viewer、Surface、文章、Asset、用途和到期时间；URL 不携带 JWT、路径或文件令牌。为保障 PDF.js Range，Invocation 不是单次字节令牌，每次读取均重新执行授权。
- PDF.js 通过主业务 API 的认证 Range 读取；每次请求重新验证文章、附件绑定、Asset 和插件状态。
- 插件停用、升级不兼容、Invocation 过期或 Viewer 崩溃时回退为认证下载，并显示可理解的中文原因。
- 本版不运行任意第三方前端 Bundle。未来 `sandbox-iframe` 必须具备独立 Origin/CSP、包签名、严格 `postMessage` Bridge、
  网络/内存/消息限额，并禁止读取主站 DOM、Cookie、JWT 和 localStorage。
- 预览会把原始 PDF 字节传给浏览器，产品文案不得承诺 DRM、防复制或水印防泄漏。

| 风险 | 概率/影响 | 预防与缓解 | 止损/回退 |

## 16. Stop Rules 与回滚原则

- 任何用户或插件能通过猜测 Asset/Object ID 跨 owner 读取：立即关闭相关内容入口。
- 文章进入草稿、私密、下架或删除后，旧附件地址仍可被普通用户读取：立即关闭附件内容路由。
- 任何路由直接返回 storage key、宿主路径、Secret、JWT 或长期 bearer URL：停止发布并轮换受影响凭据。
- UI v2 允许插件提供任意 URL、后台主动弹窗、动态导入未受信任代码或绕过 AuthorizationService：停止发布。
- Range 实现通过把完整 PDF 载入服务端内存工作：不得上线 PDF 预览。
- 删除无法证明引用安全或补偿失败：只允许 trash，禁用 purge。
- migration 目标环境、数据库名或数据性质不明确：不得 reset/down。
- 前端 Viewer 安全证据不足：回退为认证下载，不在 API 进程加入临时转换器。

生产回滚顺序是关闭附件上传/绑定和 PDF Viewer Surface、保留有权用户的认证下载、停用 UI v2 新行为、保留所有 Asset/Object/Binding，
再用前向 migration 修正。不得用 destructive down 删除用户内容。

## 17. 验证与发布门禁

### 17.1 自动化

- Go：Attachment/Asset Repository/Service、文章访问、Range、Invocation、MIME/magic、配额、引用和补偿测试。
- 数据库：`000001-000009` 空库 up、checksum、逐步/全链 down/up、并发绑定、约束/索引/冗余、reset。
- 合同：OpenAPI、Route/Operation、Permission、Capability、UI v1/v2、Error Catalog、ER 和 Admin Architecture drift。
- Web：附件编辑/排序/移除/详情、PDF Viewer、modal/fullscreen/new-tab、UI v1 回归和 PC/移动端浏览器流程。
- 安全：跨用户、文章下架、插件停用/升级、Invocation 过期/重放、伪造 owner、路径穿越、MIME 欺骗、恶意 PDF、Range 滥用。
- 容量：不同 PDF 大小、20 路 Range、慢客户端、取消请求、附件数量/总量和配额并发。
- 恢复：PostgreSQL + Object payload 一致恢复、缺文件/孤儿对象/过期 Reservation dry-run 与受控修复。

### 17.2 Final 条件

以下任一项缺失，不得宣称 `v1.1 Final`：

1. P0 未闭合，或 P1 被保留在计划内但未明确延期。
2. 附件仍通过裸 URL/路径写入 HTML，或文章状态变化不能即时控制附件访问。
3. owner、文章 Access Policy、Invocation、插件授权或 Range 存在已知绕过。
4. migration/ER/Schema/reset/恢复证据不完整。
5. PDF 的 modal/fullscreen/new-tab 真实浏览器矩阵、UI v1 回归和安全下载降级没有证据。
6. 目标 Linux 环境的容量、慢客户端、备份恢复和日志脱敏未通过。
7. 文档把第三方 UI Bundle 沙箱、MP3/MP4 预览、Office 转换、分享、DRM 或病毒扫描写成已交付。

## 18. Definition of Done

每个任务必须同时具备：

1. 代码、必要的前向 migration 和明确模块所有者。
2. 正向、越权、文章状态、插件停用、Invocation 过期、失败、并发、配额和恢复测试。
3. 生成合同、中文错误、Web/Admin、Plugin UI v1/v2、Manifest 和 SDK 类型文档同步。
4. `docs/进度/v1.1-dev/` 中记录更新时间、验证命令、回滚和未决证据。
5. 无宿主路径、跨用户数据、Secret、Token 或隐式长期兼容层泄漏。
