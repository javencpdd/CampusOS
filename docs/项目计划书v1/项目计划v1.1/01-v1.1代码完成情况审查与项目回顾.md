## 1. 审查方法与范围边界

逐项对照计划，沿 Web/Admin → HTTP → 业务服务 → 授权 → PostgreSQL/文件存储追踪实现，
再用单元、组件、生产构建和隔离 PostgreSQL 测试核对。找到代码不等于通过端到端验收；
测试脚本存在不等于演练成功。下表区分“实现”“自动化证据”和“目标环境验收”。

原始“版本计划书思路”中的音视频预览、共享和大一统 Resource 改造，已被正式计划缩小/延期，
不能重新当作本版漏做功能。PDF Viewer 按正式计划采用第一方受管插件：
`builtin.pdf-viewer` 的 Manifest 管理授权与 Surface，PDF.js 可信模块随 Web 编译。
它不是任意第三方可下载、动态执行的前端插件包。

数据库当前仅有 `000001_v1_1_schema_baseline`，此前报告中的 000006～000010 是已收敛的历史编号。
本轮未重写基线、未新增插件私有表、未重置开发库、未删除用户文件；
用户预先存在的 `migrations/er/20260919/` 未修改。

## 3. 本轮实际发现与修复

### 3.1 资产列表截断与数值排序

旧列表固定 LIMIT 200，UI 无下一页。本轮新增 `cursor/limit/next_cursor`，按
`(updated_at DESC, user_assets.id DESC)` keyset 分页；每页 1～200，Web 请求 50。
游标绑定 owner 和状态，但只是翻页位置，不是授权令牌。

真实 PG 测试进一步发现 SELECT 中 `id::text` 的同名投影会让未限定的 ORDER BY id
按字符串排序，与 bigint 游标比较不一致。已显式限定原表 bigint 排序；同时间、多页、240 项测试通过。

### 3.2 通用界面上下文与实时授权

旧声明式 `open-surface` 被 Extension wrapper 拒绝。
现在用户点击 → 宿主选定资源上下文 → POST Invocation → 服务端核验已安装插件、Surface、Presentation、
Action/附加 Permission → 业务 ACL → Capability/Grant/Consent → 短期签发 → 宿主打开。

共享服务属于 `internal/platform/pluginui`；RichText/Personal Documents 仍拥有业务权限和字节读取。
只接受 article_attachment、personal_asset、personal_document；没有开放任意资源类型、URL、路径或 SQL。

既有 `context_digest` 现在绑定不可变插件授权版本/Surface 和对象版本/哈希。
升级、对象版本变化、撤权、停用、跨用户与到期都会阻断后续读取。
读取时直接返回完成对象摘要校验的同一流，不在校验后重新打开最新文档版本；拒绝时关闭流。
旧的空摘要 Invocation 不继续沿用：用户重新点击预览即可，无需 migration 或清库。

### 3.3 下载降级不是预览授权旁路

Viewer 的“下载”原本仍请求 Invocation content，预览过期后也下载不了。
新 `GET /plugin-ui/invocations/:id/download` 是宿主认证下载：只允许该上下文的当前登录用户，
重新执行文章阅读权或资产/文档 owner、状态和绑定检查，不要求插件继续运行或继续获得预览同意。
不恢复预览权限，不生成公开链接。文章下架、附件隔离、跨用户仍被拒绝。

上下文到期后保留 24 小时供此降级定位，之后有界清理；
记录已清理或附件已从文章移除时，应返回来源页面使用其独立下载入口，而不是无限期持有旧 Invocation。

### 3.4 真实外键冲突与清理

真实 PG 复现：已预览附件的 Invocation FK 会阻止 DELETE Attachment。
修复为事务内锁定准确绑定行，删除它对应的短期上下文，再删除绑定。
并发签发的 FK 校验被行锁串行化，不先删文件，也不影响同一 Asset 的其他文章绑定。

模块启动后每分钟清理最多 500 条“过期已超过 24 小时”的 Invocation；
使用 SKIP LOCKED，并在模块关闭时取消后台工作。只删短期元数据，不删用户资产或字节。

### 3.5 内容流保护及管理端诊断

认证附件流新增：每用户 20 路、API 实例总计 64 路并发，每用户每分钟 1200 次，
最多保留 4096 个限流用户窗口；拒绝返回中文 429、具体上限和 Retry-After。
这是单 API 实例内限制，不冒充集群限流。单次内容响应写入期限 2 分钟，结束后清除期限，不修改全局 SSE。

管理端展示 UI 合同版本、Surface/Presentation、原有健康与最近运行错误；
仅返回声明摘要，不为此读取用户 PDF、config Secret 或 schema 内容。

## 4. 当前已实现功能清单

- 图片排版与独立文章附件；上传、选择、重命名、排序、移除、认证下载。

- PostgreSQL 并发准入、预览绑定事务移除、有界上下文清理、内容限流和管理端诊断。
- 环境凭据白名单、插件通用表 API、私有 SQLite/config 边界及相应测试。

## 7. 工程回顾

1. MemoryStore 能证明业务规则，但不能发现 PostgreSQL FK、快照和 bigint 排序问题；关键流程必须保留隔离库测试。
2. Manifest 声明、前端类型与用户按钮执行是不同层，合同存在不能代替动作链路验收。
3. 插件权限与业务下载权限应分开，安全降级不能依赖已经失效的插件能力。
4. 临时 Invocation 也有生命周期与 FK 影响，需要有界回收及原子失效。
5. “实现完成”“自动化通过”“目标环境验收”“版本发布”四种状态必须分开记录。
