## 三、关键缺口与必须保持的安全约定

### 3.1 PDF Viewer 注册与三层授权（已于 2026-09-15 修正）

当前证据：

- `internal/plugin/builtin_pdf_viewer.go` 声明 system/builtin 的 v3 Manifest 与三项最小 Capability；`builtin_runtime.go` 不执行包代码，只管理受信编译模块的生命周期。
- `platform_modules.go` 注册 Manifest、同步不可变插件版本、只补齐缺失的管理员默认 Grant，并启动运行时；现存拒绝/撤销记录不会被覆盖。
- `bootstrap.go` 将 RichText 的窄回调接入 AuthorizationService；`attachments.go` 在创建和每次读取 Invocation 时复核 Declaration、Grant、Consent、插件状态、文章阅读权或资产 owner。
- `article_attachment.self.preview` 的空 owner 上下文不是越权：文章阅读权已先由 RichText 验证。`personal_space_file.self.read` 始终带当前用户 owner，不能读取他人空间。
- 用户只需登录后确认用途授权，不生成 JWT、私钥或长期 Token；撤销同意、管理员 Grant 或插件状态会阻断后续读取，不公开个人空间。

计划明确“第一方 trusted-module 随 Web 编译”，同时要求插件 Manifest；两者已按受管 builtin 方式结合，
不以任意第三方动态 JavaScript/iframe 沙箱替代。

### 3.2 通用 UI Action 与下载降级

`web/src/campus-ui/DeclarativeRenderer.vue` 将 Action 送入 `uiRuntimeApi.extension`，
而 `web/src/modules/plugin-runtime/api.ts` 拒绝 `kind=open-surface`。
目前专用 PDF 入口可以调用宿主，并不代表任意合法声明式按钮能完成签发 Invocation 和打开 Surface。
应补齐宿主业务上下文、用户点击、授权签发、注册 Surface/Presentation 与升级失效的执行链。

Viewer 内的下载依赖 Invocation content；Invocation 过期时该按钮不能实现完整下载降级。
文章/个人资产的独立认证下载入口仍可用，但必须补齐计划规定的 Viewer 错误态交互，不能使用公开永久链接绕过校验。

### 3.3 数据与性能边界

`ListUserAssetsByOwner` 目前按更新时间和 ID 排序并 `LIMIT 200`，没有游标/下一页。
应在保持 owner 过滤的前提下实现稳定 keyset 分页，并同步 DTO、选择器、合同和测试。
并发准入本轮改为独立事务锁语句后再查询预算；还需在隔离 PostgreSQL 上验证数量、总大小、重复绑定和回滚。

## 四、本轮实际修复

旧实现把 advisory lock 和附件预算放在同一个 INSERT CTE。
单条语句的快照不会因为等待锁结束而重新取得，可能同时以旧预算通过准入。

本轮在 `PgStore.CreateAttachment` 使用现有 transaction.Manager 包裹：

1. 独立语句取得文章级事务 advisory lock。
2. 后续语句计算数量、总大小、重复绑定和下一显示顺序，再插入。
3. 提交/回滚释放锁；已有事务上下文继续复用，不另行跨连接执行。

依赖现有 READ COMMITTED 事务使用方式；不能擅自改为保留旧快照的隔离级别后仍宣称成立。
新增 SQL 防回归检查，防止把锁重新合并入预算 CTE；这不是数据库并发集成测试的替代。
未修改 Schema、依赖、配额上限或权限策略。先前工作区的 PDF 生命周期与 Surface 修正保留未覆盖。

## 六、项目回顾与后续实施顺序

已形成的可复用基础：附件与图片分流、Storage Object 字节边界、显式文章绑定、owner 下载、
文章权限继承、认证 Range、随机短期 Invocation、资产状态与引用保护、受信 PDF.js 与宿主 Surface。
这些是本版已有能力清单，不表示各 WBS 的全部验收条件均满足。

本版必须继续完成：通用 Action 的业务上下文签发/降级 → owner 资产分页 → 隔离数据库并发/迁移 →
PC/移动端/无障碍 → 容量与恢复 → 汇总发布证据。
第一项仍是代码实施，不应仅交给管理员“确认”；后面的实际环境验证才需要可运行环境与受控演练安排。

后续版本而非本版缺陷：Office 在线转换、音视频播放/转码、PDF 编辑/OCR、跨用户空间分享、
云存储、AV/DLP、任意第三方前端 Bundle 沙箱。继续保留附件下载安全路径，不为展示效果扩大授权范围。

整体状态：开发中，不能标记全部需求实现、RC 验收完成或 v1.1 Final。
只有上述代码缺口闭合且发布证据齐备后，才能另行编写正式收尾结论。
