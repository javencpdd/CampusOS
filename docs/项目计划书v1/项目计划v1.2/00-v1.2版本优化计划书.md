## 1. 定位和计划审查结论

CampusOS 的主产品仍是校园社区、个人内容和可扩展插件平台。WeKnora 是知识管理与 RAG/Agent 产品；本版借鉴其**资源范围授权、可重建索引、版本治理、Provider 注册和任务可观测**的工程方法，不把 CampusOS 改造成完整 RAG 平台。下述 WeKnora 能力以本机快照为准；其分析报告中的竞品排名、性能和覆盖率数字未由本次审查独立复测，不能作为 CampusOS 的验收目标。

当前 [v1.1 自包含插件计划](../项目计划v1.1/02-v1.1插件自包含与动态加载重构计划书.md)仍是未完成的实施记录；[旧范围回顾](../项目计划v1.1/01-v1.1代码完成情况审查与项目回顾.md)只覆盖早期附件/PDF 范围。`v1.1.36-dev` 主要同步了版本标识，没有替代 R11 的真实环境验收。本计划承接未完成项，不追认 v1.1 Final；开始 v1.2 实施时在 G0 记录范围移交。实施、自动化通过、目标环境验收和发布是四种不同状态。

### 2.1 WeKnora：授权、模型与知识索引

## 3. v1.2 可验收目标与非目标

1. 面向已发布扩展点的新插件独立构建/签名，安装、启用、配置、升级、回退和卸载均**不修改宿主源码、依赖锁文件、构建产物或核心 Schema，不要求重新编译/打包/重启宿主**；支持 UI-only、backend-only 和组合包。插件进程可独立重启；首次部署所需隔离环境由宿主部署者配置，不由安装脚本提权完成。新能力需要宿主版本演进时，应声明最低合同版本并拒绝不支持的宿主，不能自动打补丁。
2. Identity、插件授权、业务资源访问和外部集成凭据有单一判定链；拒绝路径有稳定原因码与低敏审计。
3. 使用可丢弃测试数据重建 P0 Schema 和对应仓储；后续知识/模型结构按阶段追加迁移。表所有权、索引、合同、ER、Admin 架构视图一致；发布后冻结 checksum。
4. 交付“校园知识检索”最小闭环：管理员维护已核验的公开资料，索引按来源版本更新，用户可搜索并打开有效原文；外部客户端只能在授予范围内读取。
5. 平台细粒度授权覆盖后台、版主、作者、个人文件、知识库和机器凭据；角色仅是动作组合，资源状态/所有权必须实时复核。
6. 可选择公开板块或单篇帖子建立集合，用户可逐项选择自己的可解析文档建立私有集合；先搜索与引用，再以可关闭的受管模型提供有据问答。
7. AI Gateway 与 Knowledge/RAG 是可启停的内置功能，不依赖安装外部插件才能运行；外部插件可以消费受控 API，也可提供可选 Provider，两种方向独立授权。
8. 管理员与普通用户分属独立身份域；凭据、会话、角色绑定、恢复和审计主体明确区分，不以给用户追加 admin 角色创建后台身份。
9. 每个阶段均有可复现测试和进度证据；最终须有真实浏览器、隔离运行、备份恢复和目标容量报告。

非目标：完整 Agent Center、自动 Wiki、浏览器/宿主命令执行、全站个人文档自动入库、公共插件市场自动安装、十种向量库或模型厂商矩阵、Kubernetes 微服务化。个人文档仅在本人逐项选择、独立 Scope 和删除传播具备时进入私有知识层；不支持的格式明确提示而非静默解析。

## 4. 目标边界与数据所有权

`Core Identity` 分别管理 User/Admin 身份域、各自凭据/Session/角色绑定、Integration Principal 和凭据摘要；`Core Community` 管帖子/版块与公开性；`Core User Storage` 管字节、owner 和配额；`Plugin Platform` 管不可变包、安装状态、Runtime、Grant/Consent、配置与审计；`AI Gateway` 与 `Knowledge/RAG` 均是可关闭的 Built-in Feature；AI 管受管模型调用、Profile 和费用预算，Knowledge 管自有官方资料的来源/修订、外部公开内容的受限引用、索引投影与检索策略。公开帖子的发布、删除及版块权限仍由 Community 决定，Knowledge 不复制一份可独立放行的授权事实。外部插件/WeKnora 适配器只能走 Host API、Extension Gateway 或受限公开端点。

检索调用链：`Principal/Session → Endpoint Scope → 集合授权 ∩ 原资源 ACL → 当前可读修订（公开来源要求已发布）→ RetrievalProvider → 返回前重新核验引用`。索引是派生数据；来源下架/撤权先修改权威事实并使查询立即不可见，再异步清理索引。v1.2 可用现有 AI Gateway 作可关闭的 Chat Adapter，但模型不能参与检索授权，也不能凭回答放宽来源权限。

设计概念与管理员配置步骤见 [v1.2 权限与知识访问入门](../../help/系统设计相关/v1.2权限与知识访问设计入门.md)、[细粒度授权与资源策略](../../help/系统设计相关/v1.2细粒度授权与资源策略设计.md)、[数据库与索引重建入门](../../help/系统设计相关/v1.2数据库与索引重建设计入门.md)和 [校园知识库与 RAG 接入](../../help/系统设计相关/v1.2校园知识库与RAG接入设计.md)；均为规划说明，不能当作现有 UI/命令。

## 5. 结构与接口决策

### 5.1 数据

- G0 冻结数据所有权与关键不变量，G1 冻结外部合同；目标 DDL 在各阶段迁移前确定。V12-01a 重建 development/test 的最小 P0 Schema 并同步切换仓储；只改同阶段能够闭环的表，其他插件运行/知识/模型结构在所属阶段追加 migration，不提前删除仍被运行代码引用的表。删除旧兼容表/adapter 时保留安全测试意图并更新夹具，不要求维持旧测试数据或协议。
- Identity 使用独立 `integration_principals` / `integration_credentials`：凭据只存盐化或高熵 token 的单向摘要、可辨识前缀、用途、Scope、到期/撤销与审计关联；绝不复用管理员 Session、JWT、插件 Host Token。管理员准入事实仍单独管理。
- Plugin Platform 明确 `plugin_packages`、`plugin_versions`、`plugin_user_installations`、`plugin_operations`、`plugin_admin_grants`、`plugin_user_consents` 与 Secret 引用。包摘要不可变；安装关系不再同时充当能力授予；文件配置通过 operation+Outbox+原子替换和代次收敛。
- Knowledge 保存集合、独立的选择规则、显式成员引用、来源修订、持久索引任务和可重建投影；字节归 User Storage，帖子状态归 Community。候选 `knowledge_source_selections` 与 `knowledge_collection_sources` 分开，`knowledge_index_tasks`、`knowledge_backfill_runs` 承载重试和断点；字段/约束在 V12-09a/09b 确定。v1.2 私人集合仅本人，协作者 ACL 合同保留到后续，不能把尚未交付的分享表写成必需实现。
- 对中文检索先做 PostgreSQL 参数化候选方案和真实样本基准；词法、`pg_trgm`、外部检索 Provider 由评测选定，不能因为 WeKnora 使用向量就强制安装 pgvector。

### 5.2 权限和 API

角色只组合动作，不形成全域管理员等级。作者是资源关系、版主是角色绑定，二者不是新的 Principal 类型；用户、机器、插件实例与 Worker 的身份以及后台会话通道分别表达。路由预筛选不能代替读取实际资源后的最终判定。社区帖子/个人文档的原模块是可见性权威；Knowledge 集合授予只能缩小它。外部模型获取私人片段需要本人对提供方和出站内容的独立同意，不随知识库索引许可自动产生。

管理员是独立 `admin` Principal，普通用户与版主是 `user` Principal；共享策略引擎不共享账号、会话或角色绑定。当前独立准入表仍绑定 user/account，角色授予服务与 SQL 触发器会自动创建准入，必须由 V12-02d 移除，而非宣称已经隔离。

普通用户：`会话有效 ∩ 集合使用权 ∩ 原业务资源可读 ∩ 当前修订有效`；公开来源另要求审核发布，自己的私有文档不必公开发布。外部集成：再交 `凭据有效 ∩ Endpoint/工具/来源 Scope`。插件：再交 `Package Declaration ∩ Admin Grant ∩ User Consent（若要求）∩ 安装/版本/运行状态`。所有资源 ID 由服务端重新加载并确定 owner/版块，不能相信客户端或索引返回的 Scope。

本轮不要求旧 API、Schema、插件包或配置兼容；每阶段同步更新 Web/Admin/SDK/CLI/OpenAPI 和夹具，直接切换到单一目标路径。目标插件合同为 `campusos.plugin/v5`，解除 v4 强制 UI 和 self-only 限制；旧包重建，不继续套 legacy Manager。未变语义的 HTTP 路径无需机械改名。G1 定义新合同版本与协商规则，为以后的扩展保留可判定版本边界。标准 MCP 与管理端 `/api/v1/mcp/tools` 分开。

### 5.3 非侵入式安装合同

安装器只写受管插件包、插件配置/数据空间与平台安装/授权/操作记录。不得执行宿主 shell/npm/go 安装钩子、修改 `go.mod`/锁文件、替换宿主文件或为插件新增核心表。插件依赖随包或隔离镜像交付；自有数据只走命名空间化 KV/对象/记录 API。包校验包括路径穿越、符号链接、大小与摘要，包代码目录运行时只读。

UI 通过已发布的插槽、菜单/路由描述与隔离 UI Host 加载，不要求修改 Web/Admin router 或组件注册表；后端通过固定 Gateway 分发，不动态改写 Gin 路由。卸载只移除插件贡献并按显式保留策略处理其数据，不删除业务模块或原始用户资源。不能承诺“完全没有运行影响”：启用新 UI/Provider 是预期变化，但应受命名空间、预算与故障隔离限制。

V12-08a/08b 在已构建的只读宿主上比对安装前后源码、依赖锁文件、宿主镜像/二进制/前端产物及 Schema 指纹；不变才通过。允许改变的包、配置、授权和日志记录必须列白名单，并执行安装/升级/卸载期间社区与其他插件的回归。

### 5.4 内置功能与插件的双向接口

`AI Gateway` 和 `Knowledge/RAG` 拥有各自业务生命周期、配置和数据，不进入插件安装/卸载流程。它们的默认 Adapter 在主程序中，未安装插件也能完成受管 Chat 和内置检索；Knowledge 检索不强依赖 AI，RAG 问答才依赖可用的 AI Port。停用保留数据、拒绝相应 API/新任务，不影响社区主流程。

消费方向：`插件 → Host API/SDK → 宿主授权与预算 → 内置 AI/Knowledge 应用 Port`。v1.2 首批只开放受限模型调用、公开集合检索和公开集合引用式问答；私人集合对普通用户自身可用，但不顺带开放给插件或 MCP。模块启用、API 已发布、插件获批和用户可读是不同条件。

贡献方向：`可选外部 Provider → 类型化贡献 Adapter → AI/Knowledge Port`。v1.2 外部贡献仅处理公开内容或无宿主私有数据的请求；私人 RAG 走内置 Adapter 和已获本人同意的受管端点，不把私人上下文转交任意外部插件。贡献模型协议不代表可消费全部模型 API，贡献知识源不代表可读取索引。不能把插件 ID/实现导入内置功能；由装配根接入可选 Adapter，缺插件有内置路径，所选 Provider 不可用时明确报错或使用管理员显式配置的同政策降级，禁止偷偷更换出站提供方。

### 5.5 宿主授权与主机资源

“主机权限”分为两层：业务 API 权限与运行环境资源许可。前者控制可调用哪些动作、Profile、集合和对象；后者控制插件自身的文件空间、受管网络目标、CPU、内存、并发、时限和费用。二者都由宿主实施，任何一层允许都不能代替另一层。

目标执行上限：`包声明 ∩ 宿主已公开合同 ∩ 管理员批准 ∩ 所需用户同意/原资源 ACL ∩ 模块/安装状态 ∩ 部署安全上限`；数值预算取更严格上限。管理员审批不能授权 DB 连接、CampusOS Token/JWT 私钥、任意宿主目录、Docker socket、特权容器或宿主命令执行。秘密仅由 Broker 代用，不给插件读取原值；安全上限不可在普通管理 UI 关闭。

管理端分别呈现业务能力和运行资源，按版本/实例限制 Profile、公开集合、网络目标、配额、期限，记录批准人与原因。高风险变更要求管理员专门授予权、MFA 与 required audit；用户只能同意自己的数据使用，不能自行放宽全局限制。撤销停止新调用并回收短期实例权限，缩小沙箱权限不能热应用时重建该插件实例，不重启宿主或保留旧特权。V12-01b 定义资源策略，04 完成管理界面，05/06 验证真实隔离。

### 5.6 管理员与用户身份域

目标 Admin 账号不再外键依赖 `users/accounts` 才能登录；独立凭据、MFA/恢复、角色绑定、Session/Refresh 家族。User/Moderator 权限只属于用户域，Admin 权限只属于管理域；Permission Code 目录可复用，但必须约束允许的主体、audience 和 Scope，不能通过同名角色或相同数字 ID 混用。

用户 Token 不能调用管理 API，管理员 Token 不能冒充用户调用 `/me`、个人文件/私密知识库或发帖操作；两端登录、刷新、登出和恢复各用对应凭据/会话，不能交换或自动升级。一个人需要两种功能时分别使用两种账号，关联联系方式不能传递权限。后台治理动作走管理域专用入口，由服务端加载目标资源并审计，不借用户身份执行。

移除 `PermissionService.AssignRole → EnsureActive`、`sync_identity_admin_account_for_user` 及相关触发器/seed 的自动提升路径；新管理员由受控 bootstrap 或有专门权力的管理员显式开设。保留最后有效安全管理员保护、独立暂停/撤销及离线恢复审计；不能因分表丢失这些规则。后台身份只授权治理和配置，不自动读取用户私有原文。两域的认证函数可复用，但不得跨域查找相同邮箱账号或降级登录；Session、Refresh、MFA challenge、验证码与恢复票据均绑定身份域、用途和目标账号。管理员使用独立签名密钥/issuer/audience 配置及专用验证器，普通用户 Token 即使附带 admin 字符串也不能进入后台。日志、审计、缓存键必须使用主体类型与 ID 组合。

### 5.7 调用、事件和模型执行链

固定调用链为：身份/会话校验 → Operation/Capability 及 Schema 校验 → 模块/安装状态 → 业务授权与资源事实 → 预算预留 → 有界执行 → 返回前权限/修订复核 → 用量结算及审计。SDK 只是客户端门面，安全检查在宿主；禁止提供可绕过链路的原始 handler。回调由受限任务身份执行，不保存触发用户的长期 Token，也不能因异步执行扩大范围。

采用受管生命周期通知与白名单公开元数据事件订阅，不把原始 Outbox、私密帖子、Prompt、会话或审核数据广播给插件。订阅与投递时都验证权限/实例代次，事件有类型、版本、ID、大小与 TTL 上限；外部插件失败由独立投递任务限次重试/隔离，不能阻塞核心事务或核心消费者。插件不得 veto 权限、审计、删除传播或改写系统提示词；暂不开放全局请求/响应拦截器和任意同步 hook。

AI 内部定义有序 `started/usage/completed/failed/cancelled` 事件和统一错误/取消合同，敏感 prompt/原始错误不进入事件。公共流式接口是独立能力，不默认开启；私人 RAG 首版仍缓冲并重验后返回。Provider 模态声明为能力上限，不是授权，缺省为最小支持；不支持的图片/工具输入明确拒绝，不能静默删掉内容。模型返回工具调用只作为不可信数据，v1.2 不执行自动工具循环。

### 5.8 生命周期、配置与供应链

Package、Installation、Grant/Consent、Config、RuntimeInstance、Contribution 各有身份/版本，生命周期通过 Operation 记录与 desired/observed 代次收敛。激活顺序：校验不可变包 → 宿主校验配置及许可 → 创建受限实例 → 健康/合同检查 → 原子发布贡献；失败保留可诊断状态，不影响其他插件或内置模块。升级先隔离准备新代次，再停止旧代次接单并排空/取消，重新核对授权后切换；超时终止旧实例，旧 handle/订阅不能复活。撤权不等清理成功才拒绝新请求。

宿主固定支持的 JSON Schema 子集，同时生成表单、校验默认值与服务端配置；禁远程 `$ref`、任意脚本校验/表单，限制深度/大小。普通配置和 Secret 写入分离、更新带版本前提；占位符不作为真实密钥回写。Profile/集合选择器只显示调用者可用项，保存和实际调用均复核。Schema 只是输入合同，不能替代授权。无需 UI 的插件也能配置和诊断。

签名证明包身份，不证明安全。不可变包/容器镜像固定 digest，更新与权限差异可审核；宿主维护发布者信任与撤销策略。安装不得按浮动 tag 拉取后执行，开发未签名模式只能受限本地启用并明确标记，不能绕过沙箱。插件升级快照只含该插件获准的数据/配置；恢复后仍按当前 Grant/Consent 重新授权，不能把已撤销权限一起恢复。

Secret 存储采用加密封装与独立部署密钥引用，轮换/恢复需要可验证的密钥材料；普通数据库备份与插件导出不夹带解密主密钥。Broker 将 secret_ref 绑定到已批准 Profile、目标和用途，不允许插件改目的地后复用凭据或自行覆盖认证头。v1.2 不提供明文密钥导出。操作系统/root、部署者和数据库超级用户属于可信运维边界，不声称应用 RBAC 能防御他们直接访问物理数据；平台管理员不等于这些运维身份。

## 7. 每阶段共同 Definition of Done

1. 定向 Go/TS/真实 PostgreSQL 测试覆盖成功、越权、撤销、故障和并发路径；`GOCACHE=/tmp/campusos-go-cache go test ./... -count=1`、涉及的 Web/Admin/Docs 构建与浏览器检查通过。
2. `git diff --check`、`python scripts/check-line-endings.py --include-untracked`、`make contracts-check`、`make docs-links`、`make architecture-check` 通过；切换 v5 时同步替换原 v4 检查器/生成物，不保留错误的旧协议门禁；DB 阶段追加 `make database-check`、ER/Admin 架构同步和隔离恢复演练。
3. 每个已改 API、Capability、Manifest、表、持久化目录均列出影响和重置/回退办法；功能停用不以删除授权审计或绕过业务 ACL 换取通过。
4. 进度文档记录**实际命令、环境、退出结果、失败与未执行项**；计划状态分“代码完成/自动化验收/目标环境验收”。未提供证据不得打勾。

### 验收分组与证据责任

| 门禁 | 必交证据 | 阻止验收的条件 |
| --- | --- | --- |
| 身份/数据隔离（P0） | 真 PostgreSQL、Memory、API/浏览器的 User/Admin/Plugin/Integration 矩阵；独立刷新/恢复；同 ID 不串权 | 只有按钮隐藏、仅单元测试通过或角色可自动提升 |

## 8. 重置、回退和停止条件

- 用户已授权重建当前测试数据，无需重复请求一般重构许可。实施工具必须输出并校验目标 DB、Compose Project 和目录清单，仅作用于本项目已识别的 development/test 环境；未知目标先停止定位。本次设计审查不执行删除。
- 代码回退使用 Git 版本与隔离快照；数据库回退采用**重建测试库**或已验证的配套快照，不承诺不兼容版本的无损 downgrade。运行系统若出现非测试数据，立即停止 reset 路线并另拟迁移。
- 插件版本回滚只恢复包/配置/私有数据，不回滚平台授权。整库备份恢复则可能回到旧权限状态，必须在开放流量前生成新的实例认证代次、废止旧会话/机器凭据、暂停插件/出站绑定并由可信运维重新核验；不能仅恢复旧库便承诺此前撤销仍有效。恢复证据必须覆盖这个区别。
- P0 新基线发布后冻结 checksum；隔离测试库可重复重建验证，知识/模型结构按阶段追加 migration。删除旧合同测试时必须保留对应用户行为与安全测试，不能仅降低测试数量。
- Runtime 若不能隔离宿主 DB/Secret/文件系统，禁用对应类型；知识 ACL 或来源删除传播出现漏洞时关闭外部检索/MCP，保持社区基础能力可用。
- 检索质量未达阈值时可以交付已验收搜索，但 V12-14b 保持未验收、整版不能称 Final。不得把模型说辞当作权限事实或官方结论。
