## 2. 产品入口及字段

入口建议：个人设置 → 模型服务 → 新增连接 → 测试连接 → 选择默认模型。普通用户的个人连接与管理员配置的站点模型并存；使用哪一条由用户明确选择，个人连接失败不自动改用站点Key。

| 字段 | 首版行为 |
| --- | --- |
| 连接名称 | 用户自己的显示名称 |
| 协议 | 首版OpenAI兼容Chat Completions；Responses/Anthropic单独适配，不仅修改URL |
| 接口地址 | 明确标为Base URL，按供应商提供的根路径填写；不盲加v1，不重复拼接完整Endpoint |
| API Key | 仅写入；编辑页不回填，返回是否已配置及更新时间，支持显式轮换/撤销 |
| 模型名 | 支持手填；不假定所有服务均支持models列表 |
| 高级设置 | 有界超时、最大输出和并发/请求额度；兼容参数按协议与模型能力发送 |
| 测试连接 | 用户点击才发送固定、有限的测试文本，提示可能消耗API额度；保存本身不出站 |

连接状态区分未测试、可用、认证失败、模型/协议不兼容、限流、超时和结果不确定；不显示原始提供方错误正文或凭据。界面不把套餐剩余次数、tokens和货币账单混为一项。

## 3. 归属与边界

- 站点策略决定是否允许个人模型、哪些协议/出站目标和额度；个人Key不绕过AI停用或恢复围栏。保存配置与测试/使用分开，禁用状态不发请求。下一片须明确现有总开关与新增用户控制面的关系。
- AI内置Feature拥有个人连接、服务端加密凭据、连接版本和选择事实。每次从当前User会话解析owner，创建/修改/使用均重新核对本人；不能相信提交的owner_id。
- 密钥不放localStorage、普通插件配置或日志。复用受管加密/独立密钥保管机制，密文绑定owner、连接、协议、规范化端点和用途；更换目标需重新确认，旧同意及在途请求失效。平台托管不是把原始Key交给贡献插件。
- 用户自定义远端首版只允许受控HTTPS公网目标；复用出站代理的DNS/连接检查、禁止私网/元数据地址、重定向与代理绕行。站点管理员配置的本机模型保留独立路径，普通用户不能把服务器127.0.0.1当成自己的设备访问。
- 非回环网页提交真实Key应要求站点HTTPS。当前LAN部署为HTTP，正式向局域网用户开放Key配置前需补齐TLS部署；不能仅加密数据库而忽略传输。
- 平台负责实际调用、额度、超时与取消。供应商模板和后续协议适配可扩展；任何新的插件扩展点/Host API按正式版本演进，不改写已冻结合同或直接给插件网络权限。
- 私人知识继续核对原业务ACL、当前修订及本次完整内容/目标的明确同意；使用自己的Key不扩大资料范围，也不自动允许第三方插件读取。QQ适配器不会自动使用某个群成员的个人Key或将私人资料发群。

## 5. Coding Plan核验

Coding Plan是套餐，不是统一协议。接口格式可兼容，也仍需确认Key/端点属于同一产品、支持目标模型和当前用途。以下为2026-10-28核对，不承诺后续政策不变：

| 来源 | 对本项目的影响 |
| --- | --- |
| [阿里云Coding Plan官方说明](https://www.alibabacloud.com/help/en/model-studio/coding-plan) | 当前说明限制编程工具交互场景，并明确排除应用后端/自动化脚本；不作为CampusOS通用问答默认预设 |
| [智谱Coding Plan官方概览](https://docs.bigmodel.cn/cn/coding-plan/overview) | 套餐额度限指定工具与产品环境；不承诺任意自定义Web应用可消耗套餐额度 |
| [Kimi Code官方概览](https://www.kimi.com/code/docs/)、[社区倡议](https://www.kimi.com/code/docs/kimi-code/community-guidelines.html) | 提供多种协议并限定交互使用/工具场景，产品集成与开放平台另有定位；须对具体用途核对，不能仅因有兼容端点就判定套餐适用 |
| MiniMax等其他套餐 | 当前没有完成对应官方用途与接口的逐项核验，保留待选，不标成已支持 |

首版基础能力面向允许产品集成的通用API，供应商/套餐选择等待用户反馈。没有请求用户在聊天发送Key，没有调用真实提供方或产生测试费用。
