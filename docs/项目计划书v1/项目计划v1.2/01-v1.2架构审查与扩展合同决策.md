## 2. 重构前提与依赖方向

用户允许重建当前测试数据、不保留旧 API/Schema/包兼容。代码可重新组织；选用模块化单体并保留独立进程的外部插件，因为数据库事务和业务授权仍应在宿主掌控。版本协议用于以后识别支持范围，不等于本轮承担旧版本兼容。

依赖方向必须是：`HTTP/任务入口 → 业务应用服务 → Core Port`；装配根把具体实现传入。Policy Core 只依赖认证、授予仓储和小型事实 DTO；Knowledge 依赖 Community/Personal Documents 的公开读取 Port；AI 与 Knowledge/RAG 为内置功能，AI 依赖 Security/Egress 与配置 Port，不依赖某个外部插件才能运行；Plugin Platform 只登记和调度外部贡献。Core 不反向导入 `features/*`，SDK 不导入 `internal/*`。

不建立任意名称取任意 Service 的通用注册器。Extension Catalog 只能返回声明过类型和版本的贡献描述，业务模块用自己的 Port 消费它。新增一类宿主能力需修改宿主合同和测试；已发布扩展点内增加插件/模型/知识源应只新增包和配置。

### 非侵入式的判定

插件独立打包其依赖，通过只读宿主已发布的 UI Host/固定 Gateway 接入。安装/更新/卸载不修改宿主源码、依赖锁文件、路由文件、核心表或构建物，不重新编译或重启宿主；首次部署可由运维准备隔离环境，不能让插件安装脚本提权。包、受管配置/数据和平台安装/授权记录才是允许变动项。用指纹和真实基础业务回归验证，不承诺插件完全没有运行时资源影响。

需要新宿主能力时正式演进 Host API，低版本宿主明确拒绝；不通过自动打补丁绕过协议。内部共享 Port 与外部 SDK/DTO 分开，外部不能调用裸 handler、获得任意 Service，或绕过应用服务的事实/权限校验。

## 3. 授权合同

每个请求具有不可由客户端自填的 `actor_kind/actor_id`、可选 `effective_subject`、`credential_id`、`audience` 和认证强度。作者是资源关系，版主是角色绑定，同一个用户不因发帖或成为版主产生另一身份。插件代表用户时同时约束插件实例及该用户；后台准入也不能从插件传来的角色列表推断。Admin 是独立主体，不是 User 加一个 admin 角色；账号、凭据、角色绑定、Session/Refresh、MFA/恢复分别建模。同邮箱或相同数字 ID 不合并权限，必须由主体类型和 ID 共同定位。

ResourceFacts 由资源拥有者服务在当前调用/事务中构造，包含带类型的资源 ID、owner、父资源、版块、状态及事实版本。Policy Port 接受这些事实和平台授予，返回允许/拒绝、原因码、策略版本及必要义务；授权结果不是可长期复用的通行证。公开阅读、作者编辑、版块治理分别是命名策略，拒绝使用万能 owner 或 global 分支。

同一层的多个有效角色授予在各自范围内可取并集，与业务 ACL、插件 Grant/Consent、机器 Scope、功能状态的限制取交集；暂停/撤销/过期优先拒绝。授予他人权限必须另有管理动作，并满足被授予的动作、范围、有效期、认证要求是操作者可委托权限的子集。v1.2 不引入通用策略脚本、任意 deny 表或角色继承树；未知条件拒绝，未来扩展需版本化。

普通用户/版主不能由角色分配进入管理域；管理员需独立用户账号才可使用个人 /me 和发帖功能，治理走后台专用动作，不伪造受治理用户。移除用户角色自动创建 Admin 的服务/SQL 触发器时，保留显式 bootstrap、最后有效安全管理员保护、停用与离线恢复审计。管理域有独立签名 key/issuer/audience，刷新、MFA/邮箱挑战和恢复不能跨域消费；普通用户找回密码不触及管理员凭据。

首版每次高风险请求读权威授权；若以后缓存，必须按主体、资源与策略版本隔离。角色修改、撤权、资源移动与写操作通过一致的事务锁/版本验证产生明确提交顺序；撤权提交后的新操作拒绝，已提交的旧操作不会自动撤销。列表的过滤、计数、分页和批量授权使用同一策略，禁止任意 SQL 片段作为公开 Port。

## 4. 插件与 Provider 贡献合同

`campusos.plugin/v5` 必须分别声明以下内容，JSON Schema/SDK/CLI 同阶段生成并校验：

| 字段组 | 责任与限制 |
| --- | --- |
| 包身份 | publisher/key/version、签名、摘要、支持的宿主合同版本；同版本不同摘要拒绝 |
| 交付形态 | UI-only、backend-only、组合包；UI audience 可选但不能与 artifact 不匹配；无任何贡献的空包拒绝 |
| Runtime | none/wasm/container 是 v1.2 必验类型；gRPC/HTTP 是调用传输，不自动成为受支持的部署类型 |
| consumes | 请求的 Host Capability 与类型化 Scope；公开、自用、集合范围和系统配置能力由宿主目录定义，不由包自封 |
| provides | 命名的 extension point、合同版本、贡献 ID、输入/输出 schema、支持能力和配置 schema |
| host_resources | 精确出站目标、插件私有空间和 CPU/内存/时限；包请求、部署上限、管理员批准及 Runner 强制隔离共同决定，不授予 root |
| 状态与数据 | 系统配置/用户配置版本、私有 KV/对象空间、配额、升级规则；不提供核心数据库连接或任意 SQL |

首批扩展点固定为 `preview.renderer/v1`、`ai.chat/v1` 和 `knowledge.source/v1`。后两者首版只接公开数据或无宿主私有数据的最小 DTO；贡献返回的正文、URL、媒体类型和引用均不可信，宿主限制大小/格式、验证来源归属，URL 抓取只能通过 Egress，不直接接收插件自报的 owner/ACL。私人原文、任意网络和用户 Token 不是贡献注册的附带能力。`embedding/rerank/parser` 预留独立合同，只有真实 Adapter 与合同测试通过后才声明可用。风格包仍为 Resource Package，不能借此注册业务 Runtime。

生命周期：验证包 → 全局安装 → 管理员授予 → Runtime 就绪 → 发布贡献目录；用户安装型插件调用还需个人安装/同意；系统绑定的模型 Provider 不强迫每名用户安装，但仍须资源授权和所需数据出站同意，不能借系统绑定绕过用户权限。卸载/撤权首先停止接收新调用，再取消或排空存量调用、回收贡献句柄。安装状态、用户安装、Grant/Consent、observed health 和 desired state 分表/分字段管理。贡献选择由宿主配置确定，冲突显式报错，不让后装插件抢占默认 Provider。

调用携带 request ID、合同版本、贡献 ID、实例代次、授权上下文的受限投影、deadline 和大小预算。宿主保留真正授权事实；插件返回的身份/权限字段不可信。升级后旧代次句柄失效；新增能力重新授予。配置转换在隔离 Runtime 内处理有界快照，失败恢复版本、配置和贡献绑定；插件自有数据变更无法逆转时禁止宣称可一键回退，必须拒绝该升级或先提供可验证快照。

两项强制扩展实验：在已构建宿主安装 PDF UI 包；再安装一个无 UI 的公开文本知识源或 Chat Provider 包。08a 先通过类型化 Dispatcher 和合同测试消费者验证调用、替换及实例隔离；14c 再验证真实知识源或 Chat 接入及插件消费内置 API 的独立授权。没有后一层证据不能记为扩展功能完成。不得修改宿主业务源码，也不能通过放开 DB/Secret 获得通过。另用不支持的合同版本和未授权 Scope 证明拒绝路径。

### 主机权限和生命周期

业务 API Grant、Host Resource Policy、User Consent 分别约束动作/资源、运行环境、本人数据，互不替代。管理员也不能通过 UI 授予核心 DB、宿主目录、Docker socket、特权容器、用户 Token、JWT 私钥或宿主 shell；插件身份仅为可撤销的短期实例凭据，audience 限 Host API，不是用户 Session。Secret 由出站 Broker 代用，不能读取原值。

安装只认可签名不可变 Manifest，实例就绪后才发布贡献；配置 Schema 是受限输入合同，Secret 与普通字段分离。准备新代次、撤销旧接单、排空/取消、原子切换和失败恢复都有 Operation 证据；反复加载不累加订阅。失败插件独立隔离/恢复，不能阻断平台启动。升级快照回滚不恢复已撤销的 Grant/Consent。这里指插件版本/配置快照，不包括整库回退；整库恢复须隔离流量、重建认证代次、废止旧凭据并重新核验授权，具体门禁见主计划第 8 节。

生命周期及公开元数据事件经白名单脱敏和限流投递，不把原始 Outbox/私有正文/Prompt 给插件；投递失败不能反压核心事务。不借鉴全局 stop_event 或任意 Prompt 改写，安全决策不可由插件取消。

## 5. 模型与知识链合同

内置 AI Gateway 与 Knowledge/RAG 管理自身业务启停与配置，零插件时有内置 Adapter/检索路径。外部 Provider 只是可选实现，消费 Host API 与贡献 Provider 分别授权。首版插件/MCP 仅访问指定公开集合；私人知识库仍只供本人使用，不因模型/知识功能启用而开放。Feature 停用必须拒绝已授权插件的新请求。

`ProviderDefinition` 描述协议和能力，`ProviderProfile` 保存受管端点、模型与 Secret 引用，`ProviderInstance` 维护健康和预算，`Binding` 选择集合/用途所用 Profile。Profile 变更有版本；端点、数据处理区域或出站策略变化使相关私人授权失效。模型调用方不能临时提交 BaseURL、任意模型名或 Secret。

Chat、Embedding、Rerank、Parser 分接口和能力；能力未声明按不支持处理，不默认全模态、不静默裁剪输入。借鉴统一响应事件表达 usage/终态/取消，但不输出私密 Prompt 或原始内部错误；v1.2 不执行模型自动工具调用。统一请求预算、deadline/取消、大小上限、用量与结构化错误。Profile 配额先预留再结算，调用超时但远端结果未知时不盲目重试计费操作；无自动切换到更宽数据政策的 Provider。真实 v1.2 必验一个 OpenAI 兼容 Chat Adapter 和受管本地模型路径，测试可使用本地协议服务；实际第三方连通与费用单独留证。

Knowledge 保存 `source_revision`、选择规则版本、parser/chunker 版本和索引 Profile 指纹。以后增加向量时指纹还包含模型版本、维度和归一化方式；改变模型必须新建代次并验证后切换，不把不同模型向量混合查询。私有集合的片段、索引、缓存、任务载荷、临时物和备份采用同一数据分类与清理政策。

索引采用持久任务和修订对账。选择规则先存储；常驻 Outbox 消费者持久化幂等任务后才确认事件；回填用分页断点、来源修订和选择规则代次，另定期从权威源对账处理迟提交、停机、已清理事件与删除。重复投递允许，投影结果幂等；不声称外部副作用 exactly-once，也不将事件生成 ID 当数据库提交顺序。

私人内容在解析、Embedding、Rerank、查询改写、Chat 和遥测的每个外发步骤都要复核本人同意及 Profile 版本。词法检索一样需要私人存储保护；保护不足时私人索引不可启用。首版 RAG 答案先缓冲，返回前重新检查引用与来源；默认不持久化私人回答历史。取消可以阻止后续步骤，无法收回已经发给提供方或客户端的内容。提示注入防护验收的是不能提升权限/执行工具/读取无权数据，不承诺模型永不受文字影响。

## 6. 数据建模与范围控制

G0 冻结数据所有权和关键不变量，G1 冻结外部合同；具体表字段在所属阶段编写 migration 前确定。先完成 P0 Schema 与仓储切换，再以前向迁移加入知识和模型表；无需一次规划未来全部表。当前测试库可重建，已发布的新基线 checksum 不再改写。旧包和测试夹具按新合同重建，不保存旧权限 fallback 或 legacy Manifest 转换链。

用户与管理员分别存储角色绑定、凭据和会话，共享动作目录必须标注允许主体域；不通过 user_id 外键或邮箱关联取得后台身份。用户角色绑定只处理用户域与版块职责，知识集合选择规则与单项成员引用分开存，不能用同一个多态 `source_id` 同时表示板块订阅、帖子和解析片段。作用域 ID 在跨模块合同使用类型化不透明字符串；持久化层按资源类型做 FK/唯一约束或验证流程，不将任意字符串 JSON 当合法授权。共享资源 ACL 的扩展点保留，v1.2 私人集合仅本人，复杂协作者分享留后续。

## 7. 五视角验收与结论边界

| 视角 | 必交证据 |
| --- | --- |
| 产品 | 版主精确版块、用户私人集合、后台选择来源、模型不可用时搜索、插件停用和无插件降级均可操作 |
| 架构 | 导入图无 Core → Feature；SDK 无 internal；两个 Provider 可在同一业务 Port 替换；零插件时内置功能可用；宿主安装指纹不变；没有双重 ACL 权威 |
| 工程 | 新包安装/升级/回退、数据与配置恢复、撤权和实例代次隔离、故障后的索引对账完整 |

## 8. AstrBot 对照结论与适用限制

已读用户参考报告，并抽查本机源码 `69ae35a` 的 `star_manager.py`、`star/context.py`、`provider/register.py`、`provider/func_tool_manager.py`、`agent/tool.py` 与工具循环 Runner。报告建议不是 CampusOS 实施指令，文件行号只对该快照有效。

保留：配置 schema 与自动表单、元数据/注册/绑定分离、失败插件列表、单插件重载、权限代理、类型化 Provider 与有序响应事件。舍弃：同进程全能力 Context（含 DB）、安装时修改宿主依赖、任意注册路由、同名工具覆盖、未知模态全支持、全局 Prompt hook、默认插件优先拦截业务，以及完整 Agent 执行循环。

AstrBot 的权限代理只包装非内置工具，其余依赖各自守卫；CampusOS 借鉴不可绕开调用边界，不照搬这个例外。内置应用服务仍须授权，外部贡献不因进入统一目录而成为可信核心。安全提示词和黑名单不构成沙箱。

WeKnora 用于来源/父资源授权、独立机器入口与模型/索引版本治理；不照搬“Admin 可访问空间所有资料”的等级模型或 RBAC 关闭时放行。两项参考互补，但 CampusOS 的独立 User/Admin 身份域和插件安全上限由自身需求决定。
