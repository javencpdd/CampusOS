## 1. 现状与依赖

主计划的整版 Final 尚未完成；本计划不改变其阶段验收。`.172` 已验证现有 NapCat 登录、947743079 群成员身份和单条发送/读回，但没有插件或人类指令事件证据。

当前 v5 插件运行容器关闭网络，已发布扩展点不包含 IM 入口。因此首版通过现有 NapCat 的 **OneBot 11 正向 WebSocket** 独立运行，源码归入 `integrations/napcat-campusos/`；它不是 NapCat 原生包或 CampusOS Admin 可安装的 `campusos.plugin/v5` 包，不修改平台授权、数据库、运行隔离或既有 AstrBot 连接。新增的 WS 项只监听回环并要求随机 Token，不宣称拥有 CampusOS v5 的沙箱。实际核验发现本机原生加载器强制官方 ID 白名单，自定义原生包被拒；不修改加载器，改用标准协议。

依赖：现有 NapCat OneBot 11 事件及群消息动作、Node.js 20+、仓库中的公开文档。首版使用随包的受控公开文档目录，不依赖已停止的 CampusOS API、模型或私人知识权限。

## 2. 本次唯一切片：Q1 文档助手

1. 明确 `/campus` 前缀：帮助、ping、官网入口、公开文档关键词搜索（最多三条及来源链接）。可在前面 @ 当前机器人。
2. 默认关闭、群白名单、拒绝私聊/自身消息/其他群；限制输入、输出、调用频率；持久化消息回执去重，发送失败不自动重发。
3. 独立运行、配置、停用和重启；只新增本机 WS 项及本适配服务，保持既有账号、网络连接条目及其他插件。
4. 定向测试通过后运行共同门禁；实际安装与指定群验收单独记证据。人类事件未获得时不得用合成调用替代。
5. 编写从需求、代码、测试、打包到安装的教程，更新进度，完成一次聚焦本地提交。
