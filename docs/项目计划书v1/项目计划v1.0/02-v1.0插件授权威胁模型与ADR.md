# CampusOS v1.0 插件授权威胁模型与 ADR

> 状态：Accepted（实现基线）  
> 更新时间：2026-09-11

## 决策

1. 外部插件的有效权限采用 Declaration、Admin Grant、User Consent 三层交集，并叠加版本、Scope、运行状态、Delegation 和系统策略；RBAC 只控制谁能管理 Grant，不代替插件授权。
2. `plugins.id + plugin_versions.id` 是运行授权身份。语义版本、包摘要和权限指纹构成不可变事实；同版本不同内容在覆盖文件前拒绝。
3. v3 只允许 Catalog 中的显式 Capability，禁止通配；未知 Host 方法默认拒绝。
4. `self` Actor 只能来自已验证会话或由宿主验证的短期 Delegation。插件请求体中的 user_id、角色或权限不是可信身份。
5. 管理员/用户撤销采用事务化 revision 和每次入口判定，不使用跨请求正向允许缓存，保证下一次调用拒绝。
6. 用户公开资料与联系信息分离；Secret 使用独立加密表和接口；停用或卸载代码不隐式删除用户数据。
7. 本地进程正式名为 `runtime: process` 和 `campusos.process/v1`。历史 `grpc` 仅为兼容别名，不把 loopback HTTP 伪称标准 gRPC。

## 主要威胁与控制

| 威胁 | 控制与验证 |
| --- | --- |
| 包升级静默扩权 | 五类 diff；Added/Expanded/Purpose Changed 触发重新审批；版本事实不可变 |
| 插件伪造当前用户 | Actor 由 Session/Delegation 注入；self owner 不匹配返回 `DENY_SCOPE_MISMATCH` |
| 撤销后继续使用缓存/令牌 | 无正向跨请求缓存；停用撤销运行令牌；Delegation 独立校验状态和过期时间 |
| 未知方法绕过 | Host 方法目录默认拒绝并有覆盖测试 |
| 获取超量个人信息 | `GetUser` 最小公开投影；email 仅由 `user.contact.read` 提供 |
| Secret 出现在配置/日志 | Secret 字段拒绝进入普通配置；AES-256-GCM + AAD；只返回掩码 |
| 后台任务无限授权 | Delegation 最长 24 小时，绑定用户、插件版本、能力和资源 Scope，可撤销 |
| 进程伪装或外连监听 | health/extension URL 只能 loopback；运行令牌请求头和合同响应头双向握手 |
| 事件订阅绕过授权 | Manifest 事件要求 `event.system.subscribe`；投递前逐次判定并使用稳定 Envelope |
| 卸载造成用户数据丢失 | 保留数据导出/删除通道不依赖插件运行或目录发布状态 |

## 信任边界

可信：登录中间件产生的用户 ID、数据库中的活动版本/Grant/Consent、宿主运行令牌、Catalog。  
不可信：插件 Manifest 的风险描述、插件传入 user_id、进程返回正文、包内路径、普通配置中的 Secret、旧版本令牌。

## 失败策略

授权存储、Catalog、版本解析、运行状态或 Secret Key 不可用时默认拒绝；用户看到中文恢复建议，审计保留稳定英文 ReasonCode、request_id 和 trace_id。授权审计不保存 Secret、Delegation 明文或完整敏感业务载荷。

## 兼容与退出

Manifest v1/v2 经适配器生成版本化声明并继续使用旧用户 Grant 界面；v3 的 Host API、事件和受管数据必须进入统一授权服务。兼容期结束后只能通过新的前向 migration 删除旧运行表，不回写已经冻结的 `000001-000003`。
