## 1. 审查方法

## 3. 当前完整功能清单

- Manifest v1/v2 兼容与 v3 显式能力声明。
- 版本化三层授权、管理员/用户界面、后台委托、Scope 和即时撤销。
- Host API v3 最小 DTO、事件授权、受管数据/文件、Secret 和进程运行合同。
- 插件签名/摘要/预检/五类权限变化/版本回滚同步。
- PostgreSQL 与无数据库测试适配器、低敏授权审计、中文可恢复错误；同版本摘要冲突只隔离插件，不再拖垮 API。
- Capability/Event/Process 合同、Go/TS SDK、CLI、Harness 和三个参考插件。
- clean baseline migration、Schema/ER/路由/合同漂移检查和跨平台 Docker 配置。

## 4. 尚未完成或需要后续开发的事项

代码范围内没有计划 P0/P1 的已知缺口。以下事项依赖目标环境，属于发布验收而不是缺失功能：

1. 在 Linux 发行目标执行 release-check、真实浏览器 Admin/Web 授权与即时撤销场景。
2. 在 Linux 目标环境执行备份恢复和真实并发 Grant/Consent 验证；Windows Docker 的 `000001-000005` clean up、逐步 down/up、checksum drift 与 PostgreSQL 授权/Secret 集成测试已通过。
3. 在目标规模数据上采集授权热路径 p95≤5ms、冷路径 p95≤20ms 或经批准的基线阈值。
4. P2 的 OS 完整沙箱、远程市场和插件间 Provider 继续保留，不影响 v1.0 功能闭环。
5. 继续观察兼容 Manifest v1/v2 的弃用窗口，并在下一主版本通过前向 migration 清理旧 Grant/Permission 表；当前不得修改冻结基线。

## 5. 整体状态与发布判定

本轮完成了计划要求的仓库内实现、合同、示例和说明，P0/P1 源码审查状态为完成，P2 按计划延期。整体状态应标记为“v1.0 代码收尾/Release Candidate”，而不是仅凭文档宣称 Final。管理员收集第 4 节前三项证据并确认无回归后，才可更新应用版本、发布记录和最终基线为 `v1.0 Final`。
