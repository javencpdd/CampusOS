# CampusOS v1-v5 计划审查

> 审查日期：2026-07-10
> 审查口径：对照历史计划、当前代码目录、`v0.1-dev` 至 `v0.5-dev` 进度记录和当前帮助文档。历史计划保留原貌；本文件只记录后续实现后的真实结论。

## 1. 状态定义

| 状态 | 含义 |
| --- | --- |
| 已完成 | 有可运行实现，并在进度文档或测试中有交付记录。 |
| 已完成基础闭环 | 主路径可用，但规模、自动化、标准化或生产保障仍不足。 |
| 部分完成 | 已有数据模型、接口或试验实现，不能作为完整交付宣称。 |
| 未完成/后置 | 仍是规划项，不能出现在 README 的已实现能力列表中。 |

## 2. v1 审查

v1 确立了“社区核心 + 插件生态”的方向，但范围包含了过多生产级目标。实际实现已完成了最重要的基础路径，也留下了应在后续版本单独治理的项目。

| v1 目标 | 结论 | 依据与缺口 |
| --- | --- | --- |
| 注册、登录、JWT、用户和社区对象 | 已完成基础闭环 | `internal/core/identity`、`internal/community`、用户端和管理端均有实现。 |
| PostgreSQL 迁移、Docker 开发依赖、NATS 事件 | 已完成基础闭环 | 迁移已到 `000013`，Compose 管理 PostgreSQL/Redis/NATS；完整应用容器化仍未完成。 |
| RBAC、管理员用户/版块/帖子管理 | 已完成基础闭环 | 角色、权限与后台管理已落地；细粒度 ABAC 不在 v1 完成范围。 |
| gRPC 插件、Manifest、Host API、事件分发 | 已完成基础闭环 | 后续已扩展到 Built-in/Wasm 和 Host API 权限。 |
| OpenAPI 覆盖所有 API | 部分完成 | 只有 `docs/api/openapi-v0.3-pre.yaml` 的历史基线，当前全部路由没有权威完整规范。 |
| MinIO/统一对象存储 | 未完成/后置 | 目前使用本地数据目录和个人空间分类；云盘/对象存储需要独立存储抽象。 |
| 通知、任务队列、邮件 | 未完成/后置 | 不应把事件总线或本地日志等同于可运营通知系统。 |
| 点赞、全文搜索、完整帖子状态机 | 未完成/后置 | 当前内容治理和私密可见已存在，但这些用户功能未形成完整交付。 |
| 70% 核心覆盖率、全量结构化日志 | 未完成/后置 | 有模块测试和平台日志，未建立覆盖率门槛或全链路结构化观测。 |

## 3. v2 审查

v2 通过双前端、RBAC 和插件仓储把原始社区服务转为可管理系统；其“系统级扩展”目标中，真实 IM 和 AI 当时并未完成，后续在 v4/v5 以更小范围补齐。

| v2 目标 | 结论 | 依据与缺口 |
| --- | --- | --- |
| Web/Admin 双前端和后台 UI | 已完成基础闭环 | `web/` 与 `admin/` 分离，覆盖用户、帖子、版块、插件等后台工作流。 |
| RBAC 角色和权限管理 | 已完成基础闭环 | 数据库迁移、服务和管理端授权路径已存在。 |
| PostgreSQL 插件仓储、API Key、缓存层 | 已完成基础闭环 | 插件仓储和 Host API 已有持久化路径；缓存性能策略尚未作为可量化验收。 |
| 帖子审核队列和完整缺失 API | 部分完成 | 管理端内容治理存在，但历史计划中的完整审核状态机和端点清单未全部完成。 |
| NapCat、AstrBot、真实 IM 同步 | 未完成/后置 | 目前只有平台无关 Message 模型和 local adapter。 |
| LLM Gateway、Webhook、MCP | 后续已完成基础闭环 | AI Gateway、Webhook 和内部 MCP-like 只读工具在 v4/v5 才落地；MCP 仍非标准协议。 |
| 搜索、邮件、关注系统 | 未完成/后置 | 不应被当前社区列表或事件能力替代。 |

## 4. v3 审查

v3 的核心插件生态目标已大体达成，但“安全隔离”和“开发者中心”的生产级含义需要更严格地拆开。

| v3 目标 | 结论 | 依据与缺口 |
| --- | --- | --- |
| Wazero Wasm Runtime 与基本 Host API 权限 | 已完成基础闭环 | `internal/plugin/wasm`、Host API 和权限检查已存在。 |
| gRPC/Wasm/Built-in 插件运行与包工具 | 已完成基础闭环 | `campusosctl` 支持 init/inspect/pack/install，管理端支持包预检和导入。 |
| 插件日志、KV、配置与生命周期 | 已完成基础闭环 | 日志/KV/配置已落地；v0.5.29 补充 system/user 生命周期。 |
| Go SDK 与示例插件 | 已完成基础闭环 | Go SDK、hello gRPC/Wasm 示例和开发文档存在。 |
| TypeScript/Rust SDK | 未完成/后置 | 当前没有同等成熟度的 SDK 交付。 |
| 一键沙盒、事件模拟器、完整开发者中心 | 部分完成 | 管理端文档和日志入口已提供，独立沙盒和事件模拟工作台未形成完整交付。 |
| 对象池、资源配额、强隔离证明 | 部分完成 | 运行时已有受控执行与权限边界，但没有完整资源隔离基准、压测和自动恢复体系。 |
| ABAC、字段级和行级数据权限 | 未完成/后置 | 当前以 RBAC 和业务检查为主。 |

## 5. v4 审查

v4 将方向调整到个人主页、AI 和集成，实际落地范围较计划更收敛，符合先做确定性功能的原则。

| v4 目标 | 结论 | 依据与缺口 |
| --- | --- | --- |
| AI Gateway | 已完成基础闭环 | OpenAI-compatible provider、配置、限流和调用日志已实现。 |
| 个人主页、个人空间和风格包 | 已完成基础闭环 | 公开主页、内容同步、头像、受限 HTML/CSS、目录/zip 风格包和回滚均已实现。 |
| 插件包交付闭环 | 已完成基础闭环 | 包检查、导入导出、Checksum、版本比较、风险提示和文档已实现；强签名和自动回滚未完成。 |
| Webhook | 已完成基础闭环 | endpoint、签名、测试投递和投递记录已实现。 |
| MCP Server | 部分完成 | 当前是内部 MCP-like 只读工具层，不是标准 MCP 传输和能力协商实现。 |
| 一个真实 IM 适配器 | 未完成/后置 | Message local adapter 不等同于 Discord、OneBot、NapCat 或 AstrBot 适配器。 |
| AI 内容审核 | 未完成/后置 | 仍缺少样本、人工复核、误伤治理和明确执行策略。 |
| 完整 Docker 产品化、Windows 实机验证 | 未完成/后置 | 当前有开发期 Compose 与 WSL2 路线文档。 |

## 6. v5 审查

v5 的实际工作量超出最初 `v0.5.0` 至 `v0.5.7` 的拆分，主要补齐了用户内容能力、个人空间、风格包标准、课表、平台日志、插件生命周期、管理端数据架构可视化及其同步检查。当前文档基线为 `v0.5.33-dev`；详情见 [v5 第二版计划书](../项目计划v5/01-v5版本计划书第二版.md)。

| v5 目标 | 结论 | 依据与缺口 |
| --- | --- | --- |
| 管理后台集成中心、平台日志和基础指标 | 已完成基础闭环 | 管理端有集成与固定来源日志入口；集中日志、告警和 tracing 未完成。 |
| 个人主页/风格包运营化 | 已完成基础闭环 | 快照、回滚、恢复默认、安全筛查和标准目录均已落地。 |
| 受控富文本与普通文本治理 | 已完成基础闭环 | 图文草稿/发布/治理，以及普通文本编辑、删除、私密可见和离开提醒已实现。 |
| 个人空间与课表 | 已完成基础闭环 | 数据分类、头像、课表、`terms/<year>-<semester>.json` 和日历浏览已实现。 |
| 插件包治理与生命周期 | 已完成基础闭环 | 包预检、导入、配置、scope、重启生效和热加载已实现。 |
| Webhook、MCP-like、Message local adapter | 已完成基础闭环 | 均有可操作基础路径，但对外标准协议和真实平台接入尚未完成。 |
| 备份恢复、Docker 运行说明 | 已完成文档，未完成演练验收 | 恢复步骤可查，但没有被记录为可重复的实际恢复演练。 |
| 完整 v0.5 API 规范、端到端回归门槛 | 部分完成 | 单元测试、构建和 smoke 脚本存在；完整 OpenAPI 和浏览器 E2E 门槛未建立。 |

## 7. 审查结论

1. v1-v5 的核心产品骨架和插件平台基础已经形成，不应重新开新论坛或重做插件运行时。
2. 之后的优先级应从“再增加功能”转为“API 契约、可恢复交付、插件信任与可验证集成”。
3. 标准 MCP、真实 IM、公开插件市场、AI 强制审核、Kubernetes/高可用不应被一次性并入同一版本。
4. v6 应只在通过 v0.5 回归基线后，选择一条受控标准化路线和一条可恢复性交付路线推进。
