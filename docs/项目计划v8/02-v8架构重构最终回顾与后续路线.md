# CampusOS v8 架构重构最终回顾与后续路线

> 状态：二次真实性审查完成，v0.8.0 架构范围已验收  
> 日期：2026-07-13  
> 主计划：[00-v8版本计划书](00-v8版本计划书.md)  
> 纠偏进度：`v0.8.17-dev` 至 `v0.8.19-dev`

## 1. 最终结论

v8 计划冻结的架构重构范围已经完成。这个结论不是沿用首次 A16 的自评，而是在重新检查运行时权威源、状态所有权、路由登记、前端目录和发布脚本后作出的。

二次审查最初判定“尚未完全完成”：Feature Registry 仍与 Plugin Manager 状态耦合，Manager Facade 仍直接操作子服务内部锁，路由 owner 没有来自真实运行时登记，Web/Admin 页面和 Appearance Store 仍在根级目录。以上问题已在 R1-R3 修复，并补充了会在回归时失败的自动门禁。

## 2. 当前已完成的能力

### 2.1 平台与核心模块

- Module Runtime 支持依赖拓扑、Register/Start/Stop、失败回滚、健康状态和 PostgreSQL/Memory Profile。
- Identity、Community、Moderation、User Storage 作为 Core Module 运行，通过公开 Port 协作。
- Moderation 的权限策略、板块作用域、审计和完整性始终启用；置顶、锁定、删回复等动作可配置。
- User Storage 统一管理 `data/personal-space/<user-id>`、安全路径、配额、目录分类和本地 Provider。

### 2.2 内置功能与界面资源

- Personal Space、Controlled RichText、Personal Schedule、Appearance 进入 Built-in Feature Registry。
- Feature Store 是 desired/effective/config 的唯一权威；`restart` 与 `hot-gated` 语义可验证，停用不删除数据。
- RichText 和 Schedule 依赖 User Storage Port，不依赖 Personal Space 是否启用。
- Appearance Application 统一 Homepage、WebTheme 和 Personal Space Style 的筛查、预览、应用和回滚。
- 资源包保存在数据目录，旧 `data/plugin_data/*/style-packs` 作为只读兼容来源继续可用。

### 2.3 外部插件平台

- External Plugin 与 Core/Built-in Feature 在 API 模型和 Admin 页面中分离。
- Catalog、Runtime、Lifecycle、Config、UI、Event、Audit、Package、Snapshot、Host Access 具有明确责任和状态所有权。
- Manager 仅保留旧 Go API 的无状态转发；检查器禁止其重新持有 map/锁或越过子服务公共操作。
- gRPC、Wasm、Remote HTTP/Host API 既有合同、包导入导出、快照回滚、Token 轮换和事件机制保持兼容。

### 2.4 集成、HTTP 与前端

- AI、Webhook、MCP-like、Message、Platform Log、Metrics 和 Integration Overview 作为独立 Module/Port 运行。
- Server 只负责配置、Profile/Module Set、HTTP 启停和 Runtime 停止；具体业务路由由 HTTP Transport 注册。
- 148 条路由由真实 Gin 注册同步写入 Route Registry，每条路由都有 Module owner、Audience、Auth、Permission 和 Feature metadata。
- Web/Admin 的 API、Route、Store 和页面主实现已按功能域组织；根级入口只做聚合或兼容导出。
- Admin 分为“外部插件”和“内置功能”两个管理入口，Core Moderation 不提供停用按钮。

## 3. 硬性退出条件证据

| Appearance/User Storage/Integration 主路径统一 | 通过 | Application/Port/Summary Port 定向测试与 race |
| Web/Admin 按领域组织 | 通过 | 根级页面禁止规则、兼容 Store 行数规则、两端生产构建 |

## 4. 兼容策略与有意保留项

- `/plugins/:name/*` 对历史 builtin 仍存在，但只投影 Feature Store；它不是第二权威源。
- 历史自定义个人存储根通过兼容 Adapter 读取，默认和新配置全部走 User Storage。未自动搬迁是为了避免静默移动用户文件。
- Gin 路由实现保留在 Transport Adapter，领域 Module 不依赖 Gin。Route owner 从实际 Handler 模块产生，并在启动时校验 Gin/Registry 数量一致。
- HTTP 合同文件仍沿用 `v0.6` 名称和 Host API v1，表示协议版本，不表示服务版本回退。
- Web/Admin 主 chunk 暂未追求最小化，但已受机器预算约束且当前通过。

## 6. 接下来需要完成的工作

以下项目不是 v8 未完成项，应在后续版本独立立项和设计威胁模型：

1. Agent Center、审批、任务历史、配额和用户界面。
2. 独立进程或容器 Agent Runner、标准 MCP Server、Knowledge Provider。
3. Prompt、Persona、Skill 和知识资源的管理产品与迁移协议。
4. Discord、OneBot 等第三方 Adapter，以及第三方 Secret 的加密迁移。
5. 云存储 Provider、历史自定义根的显式迁移工具和跨实例资产迁移。
6. 插件/资源市场、签名供应链、灰度升级和生产级高可用。
7. Web/Admin 进一步按需拆包、组件测试扩充和性能基线优化。
