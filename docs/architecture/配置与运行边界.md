## 配置入口与优先级

[pkg/config/config.go](../../pkg/config/config.go) 的 Config.Load 读取进程工作目录的 .env：
非空进程环境变量优先，其次 .env 非空值，最后代码默认值。空字符串不是强制覆盖值。
该文件解析不等于把 .env 全部导出进程环境；直接 os.Getenv 的模块有自己的读取路径。

| 文件/来源 | 职责 |
| --- | --- |
| [.env.example](../../.env.example) | 原生 API 配置示例，不被程序当作实际 .env 自动加载 |
| [开发模板](../../deploy/docker/.env.dev.example) | Docker 开发 setup 输入模板 |
| deploy/docker/.env.dev.local | 本机开发实际配置；由脚本选作 Compose 插值来源，不纳入 Git |
| [部署模板](../../deploy/docker/.env.example) | 部署配置示例，不是开发 local 的别名 |
| modules/*/*/module.yaml | Feature 默认配置与配置 Schema |
| builtin_feature_states | 持久化的功能配置/启停状态，由 Feature Registry 读取 |

查看 Compose 的 environment 映射才能确认某个变量是否真的进入 API 进程。

## 插件 Secret 活跃行换钥边界

内部 `SecretService.RewrapActive` 读取指定插件、owner 和名称对应的活跃密文，先用旧 key 完成认证解密，再用当前 active key 原地重加密。PostgreSQL 在与普通写入、撤销共用的事务锁内按原行 ID 条件更新；若期间值已更换或撤销，拒绝覆盖。记录 ID、owner、名称、状态、元数据与时间戳不变；原值不进入插件 Host API、配置导出或命令输出。宿主本地 `campusosctl secret rewrap` 提供按插件、每次 1–500 条的有界运维入口；默认只读预览，执行必须给出当前候选数量、操作者和原因。密钥组与 `DATABASE_DSN` 只从进程环境读取，不通过命令参数传入。先写 `platform_operation_runs` 操作记录，再逐行重封装；执行失败可能已有部分行完成，应根据审计和重新预览继续，不把部分成功记作全库退钥。操作者不得在原因中填写 Secret 名、原值或凭据。

撤下旧 key 前，必须让所有写入实例改用新 active key，并核实目标数据库所有仍需读取的活跃行都已重加密；单个插件候选数归零不构成全库退役证明。历史 rotated/revoked 行和换钥前生成的备份仍可能需要旧 key；数据库备份本身不包含解密密钥。缺旧 key 或认证失败时拒绝改写，不能以删除 key 替代换钥。该运维命令不发布 HTTP/Host API。自动后台轮换由下面的独立 Worker 承担。

## 自动后台 Secret 重封装

`CAMPUSOS_SECRET_ROTATION_ENABLED=true` 显式启用 Server 装配的 Worker；默认关闭。必须有 PostgreSQL、完整旧读 Keyring 与当前 active ID；无数据库或错误密钥配置时拒绝启用，不回退 Memory。`CAMPUSOS_SECRET_ROTATION_INTERVAL` 默认 5m，允许 1s–24h；第一次处理等待一个周期。每轮最多 25 插件，每插件一批最多 100 条，以 PG 会话 advisory lock 防止两个 Worker 同时扫描，仍以既有行 CAS 防止覆盖 Put/Revoke。

游标在进程内跨轮推进，到库存末尾回绕；坏密文插件写失败 operation 后让后续插件继续。操作只记录插件 ID、key ID、计数和稳定错误码。租约、库存或审计基础设施失败会停止 Worker 并记录通用服务日志，应检查 `platform_operation_runs` 后修复并重启；取消和等待 Worker 结束先于连接池关闭。逐行提交允许部分成功，剩余库存可继续；历史/撤销行不重写。部署前先统一所有写实例的新 active ID，保留备份和历史所需旧 key。

## V12-01b 共享 Port

`PgPluginV5ConfigStore` 从不可变版本 Manifest 读取配置定义，使用 `plugin_configurations` 保存系统/用户普通值及独立 Secret 引用，事务 revision CAS 与值脱敏审计。受限选择器由宿主提供事实验证器，缺验证器时拒绝；UI 入口属于 V12-04。

`SecretUseBroker` 是受信宿主内部代用入口，每次检查活跃版本、当前配置引用、Grant/Consent、资源交集及用途预算；批准绑定必须精确包含 Secret 名、ref、Profile、完整 HTTPS URL 和 purpose。POST/Bearer 固定由宿主构造，禁止重定向，仅返回 HTTP 状态码，响应头/体不传给插件。资源并发以单个宿主 Broker 的版本在途计数收紧；用途预算预留、结算及未知结果按预留全额计费，撤销预算取消在途请求。

共享 Egress 默认拒绝，仅允许明确 HTTPS DNS origin；每次连接重新解析并拒绝任一非公共 IP，连接固定已验证 IP，不用环境代理或连接复用。请求/响应/头和时间均有界。纯资源策略取合同、申请、宿主上限与管理员授予的严格交集；实际 Runner CPU/内存/文件及跨进程预算验收属于 V12-05/06，完整系统恢复属于 V12-08b。

## 插件 Secret 密钥引用快照（只读）

宿主本地 `campusosctl secret inspect-key --key-id ID` 只需 `DATABASE_DSN`，不需 Keyring 环境变量。命令在 PostgreSQL `REPEATABLE READ READ ONLY` 事务中，按 `key_version` 对当前 `plugin_secret_values` 跨所有插件做聚合快照，输出 `snapshot_at`、active/rotated/revoked/other/total 引用数和涉及的插件数；不读取 Secret 名称、密文或明文，不修改数据，也不写操作审计。它与按插件逐批改写的 `secret rewrap` 是不同操作。

快照显示零引用仅表示查询时当前表无该 key ID 的记录：备份、其他存储仍可能引用旧 key，运行中的写入也可能在快照后发生。不能仅凭此输出删除旧 key；退钥仍须核对写入实例、历史数据和恢复需求。

## 文件根与持久化边界

bootstrap 显式以 corestorage.DefaultRoot 构造 User Storage，当前为 data/personal-space。
**Config.Load 没有一个全局 USER_STORAGE_ROOT 配置项**，不能仅在 .env 写入自造变量就搬迁 Object 存储。
历史 Feature 的 file_storage 配置与 Core Object 根也不能混为一谈。

相对路径相对于 API 工作目录。开发脚本 [dev-api.sh](../../deploy/docker/dev-api.sh) 切换到 /workspace，
[Compose](../../compose.dev.yml) 绑定仓库到 /workspace。新附件位于
data/personal-space/<用户ID>/file/objects/<对象ID>.bin；业务名称保存在元数据中。

## 部署限制与健康检查

[部署校验](../../internal/server/deployment.go) 明确拒绝 multi-instance 写模式，
原因是本地 User Storage 与旧 SQLite KV 没有共享多写协调能力。
production 校验 JWT、管理员初始化、安全密钥等配置；这不是自动 TLS、HA 或生产数据库可用性保证。

GET /api/v1/health 的 [实现](../../internal/modules/core/identity/handler/user_handler.go)
返回 status、service、version，不逐一探测数据库、邮件和插件。因此 HTTP 200 不等于所有依赖正常。

## 热加载的实际行为

Docker Go watcher 是 dev-api.sh 内的指纹轮询，不是容器中的 Air：
扫描 Go、migration SQL、module YAML 和 go.mod/go.sum；默认轮询一秒。它会跳过测试夹具或运行数据目录中的 `data/`、`.campusos/`，避免不同容器 UID 留下的文件导致扫描权限错误；入口脚本本身变更仍需 `docker-dev.* rebuild`。
变化后构建候选二进制，执行 migrate.sh up，成功后替换 API 进程；
编译或迁移失败会保留上一成功运行进程，所以页面可访问不一定代表新代码已生效。

Web/Admin/文档站由各自开发进程处理源码更新。依赖、镜像构建文件或容器入口变化使用 rebuild。
CAMPUSOS_DEV_API_HEALTHCHECK_INTERVAL 是 Compose 健康探测间隔；
CAMPUSOS_DEV_POLL_INTERVAL 是 Go 源码轮询间隔，两者都不是浏览器心跳。
