## 使用规则

每项现有运行时能力必须恰有一个业务所有者。拥有者负责领域规则、公开 Port、数据写入和 HTTP Route Contributor；其他领域只能调用其公开 Port 或订阅事件。列表中的现有文件是 A0 时的真实入口，不表示它们已经满足目标目录结构。

## 路由、数据和前端基线

- HTTP 路由数为 148，method、path、认证、权限、审计和稳定性字段由 [`../api/http-routes-v0.6.json`](../api/http-routes-v0.6.json) 冻结；领域归属由本表和后续 Route Descriptor 共同维护。
- 历史 migration 为 `000001` 到 `000018`，均不可改写。A7 Feature State 及之后的持久化变化只能追加 migration，并通过升级和恢复演练验证。
- 当前持久化根目录为 `data/config`、`data/dist`、`data/images`、`data/personal-space`、`data/plugin_data`、`data/plugins`、`data/resources`、`data/skills`。目录和已公开 URL 不得在迁移中改名。
- Web 入口由 [`../../web/src/router/index.ts`](../../web/src/router/index.ts) 冻结；Admin 入口由 [`../../admin/src/router/index.ts`](../../admin/src/router/index.ts) 冻结。A12/A13 只移动模块，不改变 URL、localStorage key 或授权结果。

## A0 已识别债务

1. `internal/server/application.go` 同时创建业务 Repository、Service、Handler 并注册具体 Gin 路由；这是 A2-A11 的渐进迁移对象。
2. PostgreSQL 与 Memory 分支重复组装业务对象；Profile 只能负责 Adapter，不能继续拥有 Service/Handler 构造。
3. [`../../config/architecture-boundary-allowlist.json`](../../config/architecture-boundary-allowlist.json) 有 8 项既有跨 Repository 例外；A1 冻结数量，A14 必须降为 0。
4. Web 和 Admin 的 API、Router、Store 仍分别集中在入口目录；A12/A13 才能做目录移动，A0 不变更前端行为。

## 变更控制

在 A0 之后，任何新增或变更路由、表、迁移、目录、Manifest、页面 URL、权限或错误包络都必须同时更新本矩阵、机器基线（以新增快照而非覆盖本文件）、合同检查和对应阶段进度文档。未归属的代码、表、目录或页面不能进入主分支。
