# ADR-0012：邮箱身份事实与历史账号迁移

> 状态：已接受并在 v0.12 A2 实施  
> 日期：2026-07-17  
> 关联：[v0.12 计划书](../../项目计划v0.12/00-v0.12版本计划书.md)、[账号身份与历史迁移说明](../../help/系统设计相关/v12账号身份与历史迁移说明.md)

## 背景

历史 CampusOS 同时在 `users.email` 与 `accounts.identifier` 保存邮箱，两个唯一索引都按
原始字符串比较。大小写不同的同一邮箱可以绕过唯一性；`accounts.verified` 也不足以表达
“历史账号可以继续登录，但系统没有证明其仍拥有邮箱”的兼容语义。

v0.12 需要增加验证式注册、密码找回和邮箱绑定，但不能把历史 `verified=false` 直接改成
`true`，也不能在迁移时猜测冲突邮箱的归属。

## 决策

1. `accounts(type=email)` 是登录邮箱的权威事实；`users.email` 暂时保留为兼容投影，所有
   写入最终只能由 Identity Service 原子同步。
2. 邮箱规范化固定为 `trim + lowercase`。不实施 QQ、Gmail 或任意供应商特定的点号、别名
   或域名折叠规则。
3. 新增 `identifier_normalized` 并对有效 email account 建立部分唯一索引；`000028` 会在
   任何 DDL 前列出大小写冲突、一个用户多个邮箱、投影不一致、孤儿和空标识，然后中止。
4. `verification_state` 明确区分 `unverified`、`legacy_accepted`、`verified` 与
   `system_managed`。历史普通账号迁移为 `legacy_accepted`，可保持登录兼容，但不等同于
   邮箱已验证，也不能成为密码找回依据。
5. 历史共享邮箱只允许进入 `identity_legacy_email_placeholders` 作为迁移证据，绝不写入
   `accounts.identifier` 或 `users.email`。`identity_reserved_identifiers` 保存不可注册的
   规范化标识；当前注册服务拒绝受保护的历史占位邮箱。
6. 对外仅暴露不含 credential 的 `identity.account-reader` Port。邮件投递、前端、插件和
   管理页面不能读取密码 hash、Token、验证码或数据库 Repository。

## 后果

- v0.12 A3-A7 能以明确验证状态决定注册、重置和绑定流程，而无需猜测旧布尔字段含义。
- 历史用户不需要被强制改密或立即验证，因此迁移不会无故中断已有登录。
- 迁移遇到不一致数据时需要人工选择，而不是静默合并或覆盖邮箱。
- `users.email` 在兼容期仍可被旧读路径使用，但不应再作为独立写入接口；删除投影属于未来
  破坏性版本的单独迁移。

## 被拒绝的方案

- **把所有历史邮箱标记为 verified**：这会把“曾经注册”错误扩大为“仍拥有该邮箱”。
- **以字符串相等保留大小写差异**：会导致登录、找回和唯一约束有不同结果。
- **按邮箱供应商自动归并别名**：会把合法且不同的用户地址错误合并。
- **让邮件模块查询 Identity Repository**：会让投递模块得到不必要的凭据访问能力。

## 验证与回退

`scripts/test-v12-identity-migration.sh` 在隔离数据库中验证冲突预检、正常升级、状态映射和
up/down/up。`make identity-email-check` 同时运行 Identity 单测和迁移演练。生产遇到数据
冲突时采用人工治理与 forward-fix；down migration 仅用于隔离演练，不用于恢复历史原始
邮箱或验证语义。
