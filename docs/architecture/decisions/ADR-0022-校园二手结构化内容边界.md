# ADR-0022：校园二手使用独立 Detail、分价金额和交易状态机

> 状态：已接受并在 v0.12 C3 实施  
> 日期：2026-07-17  
> 关联：[v0.12 二手信息设计](../../项目计划v0.12/07-二手信息子模块设计.md)

## 背景

二手内容有价格、成色、交付方式和交易进度，不能把这些字段放进所有 Thread，也不能从正文中猜测。
若允许浏览器提交任意 JSON Detail，则不能稳定约束币种、金额、状态、作者或索引；若让 External Plugin
取得事务参与能力，则会突破 Community 的数据所有权和可靠命令边界。

## 决策

1. 新增 Built-in Feature `feature.secondhand`；其业务数据只保存到一对一
   `secondhand_details`。
2. 标价采用 `price_minor`，首版只允许 `CNY`；用户界面显示元，写入前转换为分，避免浮点持久化。
3. 交易状态使用 `available`、`reserved`、`sold`、`closed`，只按显式状态机转换；
   `sold` 和 `closed` 为终态。
4. 创建通过 Community `CreateStructuredThread` 在同一可靠事务中写 Thread、Revision、Detail、Audit 和
   Outbox；编辑和状态变更使用版本化可靠命令。
5. 数据库触发器强制 Detail 指向 `secondhand` Thread，且 `created_by` 与 Thread 作者一致；
   Feature 停用只拒绝其入口，不删除 Detail 或削弱 Community 治理。
6. 不实现支付、订单、担保、即时聊天、物流、仲裁或全量联系方式存储。

## 后果

- 二手列表可以稳定按价格和交易状态展示，且不会把数据混入通用 Thread。
- 业务“已售”与 Community 的审核、下架和恢复互不覆盖，审计事实更清晰。
- 金额、币种、状态和作者不只依赖前端校验，数据库也会拒绝不合法记录。
- 未来扩展其他币种、支付或交易流程必须经过独立威胁建模和新合同，不能改变现有 CNY 语义。

## 被拒绝的方案

- **将价格写成浮点数**：货币不应依赖浮点舍入，统一以分保存。
- **把交易进度复用为帖子发布状态**：交易完成与内容治理是不同事实。
- **让通用 Thread 接收二手 Detail JSON**：会破坏固定 schema、状态机和模块所有权。
- **直接接入支付或担保**：这会引入资金、欺诈、隐私和仲裁责任，超出 v0.12 范围。
