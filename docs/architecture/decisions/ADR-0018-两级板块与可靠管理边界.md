# ADR-0018：两级板块与可靠管理边界

> 状态：已接受并在 v0.12 B1-B3 实施  
> 日期：2026-07-17  
> 关联：[v12 计划书](../../项目计划v12/00-v12版本计划书.md)、[两级板块设计](../../项目计划v12/04-两级板块与可靠管理设计.md)

## 背景

既有 `categories` 已有 `parent_id`、`is_closed` 和历史客户端，但没有层级上限、生命周期、并发版本或
可靠写入边界。直接追加前端树形组件会使三级、循环、归档父级、错误发帖和版主越权在不同入口中表现
不一致。另起一张导航表则会引入两份板块事实和不可预测的迁移成本。

## 决策

1. 保留 `categories` 作为唯一板块事实表，追加 `node_kind`、`lifecycle_status`、`version` 和 `color`。
2. 仅支持根级 group、根级 board 或 group 下 board。group 不可发帖，board 不能拥有子节点。
3. 将可发帖资格收敛为 active 且未关闭的 board，并在主题和回复写入前由 Community Service 校验。
4. Category 创建、更新、移动、归档和恢复统一进入 Reliability/TxKernel；Repository 必须从 Context
   获取事务执行器，业务事实、required audit 和 Outbox 一起提交。
5. 层级不是授权继承树。版主 scope 始终是显式 board ID，移动不修改 scope。
6. 公开读取仅返回 active 节点；管理读取使用 `/admin/categories`，避免归档信息意外暴露。旧 DELETE
   仅映射 archive 并保留兼容遥测。
7. 数据库 migration 先预检历史树，再由 CHECK、索引和触发器阻止绕过 Service 的非法写入。

## 后果

- 管理员可安全地调整导航，并通过 version 冲突得到明确的重新读取提示。
- 归档保留历史主题、审计与权限关联，但不再允许新增主题或回复。
- 无法通过给一个 group 授权来批量扩大版主范围；这是有意的最小授权约束。
- 公开 flat 列表继续工作，树形导航是加法接口；旧 DELETE 行为变为非破坏性的 archive。

## 被拒绝的方案

- **无限级树**：当前没有权限继承、迁移治理和 UI 回归所需的完整模型，过早开放会制造无法验证的
  路径。
- **仅靠前端限制**：脚本、旧客户端和直接 SQL 会绕过前端，不能保护数据完整性。
- **物理删除板块**：会破坏主题、回复、版主 scope、审计与历史链接，且难以恢复。
- **移动后继承父 group 权限**：会在不经过授权审计的情况下扩大版主能力。
