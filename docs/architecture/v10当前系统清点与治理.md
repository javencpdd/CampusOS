# CampusOS v0.10 当前系统清点与治理

> 基线：`v0.10-dev`，最后核验：2026-07-16。  
> 用途：记录 v0.10 已确认的所有权、读写边界、兼容对象、生成物政策和未完成清理门槛。它不是删除清单。

## 1. 决策摘要

| 事项 | v0.10 决策 | 依据与限制 |
| --- | --- | --- |
| 帖子可见性事实源 | Community `threads` 与三维状态 | Personal Space 改为通过 `ContentQuery` 查询；旧 `user_space_contents` 暂不删。 |
| 标签事实源 | Community 的 `tags` 与帖子关联 | Personal Space 只接受查询结果/展示筛选，不能单独决定帖子标签或可见性。 |
| 富文本状态 | Community Thread 为治理事实，RichText 保留展示兼容字段 | 不能绕过 Community 直接把下架内容设回公开。 |
| 权限迁移 | 新权限目录与旧 `permissions` 并存 | `000025` 追加回填；未知 Code 默认拒绝，旧表至少保留一个兼容周期。 |
| 模块实现与数据 | 描述符在 `modules`，实现在 `internal/modules`，本地可变数据在 `data/module_data` | 编译期模块不进入插件安装、升级或卸载流程。 |
| 外部插件实现与数据 | 实现在 `data/plugins`；私有运行数据在 `data/plugin_data`，用户附件走受管 User Storage | Plugin Manager 只管理 External Plugin。 |
| 风格/资源包 | `data/resources` 是唯一受管资源仓库 | 已提供布局迁移、资源采用、checksum 校验和逆向回滚工具；资源包不注册业务 Runtime。 |
| Admin 构建产物 | `admin/dist` 为本地生成物，已停止纳入版本控制 | 源码和锁文件是可复现输入；CI/发布流程必须自行构建。 |

## 2. 模块、数据和公开 Port

| 所有者 | 主要目录 | 拥有事实 | 对其他模块公开的边界 |
| --- | --- | --- | --- |
| Identity Core | `internal/modules/core/identity` | 用户、认证、角色、作用域、权限目录、授权审计 | UserReader、Authorization/Moderation Policy、角色管理 Handler。 |
| Community Core | `internal/modules/core/community` | 板块、标签、帖子、回复、内容状态、内容修订与审核案例 | `ContentQuery`、Moderation Gateway、读写应用服务。 |
| Moderation Core | `internal/modules/core/moderation` | 版主范围流程、治理动作配置与 Moderation 审计 | 通过 Identity Policy 和 Community Gateway，不直接拿其他模块 PG Repository。 |
| User Storage Core | `internal/modules/core/userstorage` | 用户目录、安全路径、配额、资产 Provider | `UserFileStore`、`AssetStore`、Quota/SafePath Port。 |
| Personal Space Feature | `internal/modules/features/personalspace` | 个人资料、主页偏好、风格、公开主页装配 | 只读 `ContentQuery`；不拥有帖子可见性事实。 |
| Controlled RichText Feature | `internal/modules/features/richtext` | 富文本正文、编辑器和图片资产关联 | 通过 Community Thread 状态机发布/下架/删除。 |
| Personal Schedule Feature | `internal/modules/features/schedule` | 个人课表 JSON 和导入 | 依赖 Identity 与 User Storage。 |
| Appearance Feature | `internal/modules/features/appearance/runtime`、`internal/modules/features/appearance/homepage`、`internal/modules/features/appearance/webtheme`、`internal/modules/features/appearance/stylepack` | 首页/主题偏好、资源包校验与应用 | Appearance Catalog、Package Validator、Preference Store 的适配边界。 |
| Plugin Platform | `internal/plugin` | External Plugin Catalog、Runtime、Host API、Grant、市场与审计 | Host API、Extension Gateway、公开插件 API；不管理 Built-in Feature 生命周期。 |

外部插件、Agent Runner、Knowledge Provider 和 MCP Adapter 不得导入 `internal/*`、获取 `AppContext`、直连 PostgreSQL 或取得 JWT/用户 Token。它们只能走 Host API、Gateway、MCP 或公开 HTTP 合同。

## 3. PostgreSQL 表所有权与保留策略

| 表/组 | 所有者 | 当前用途 | 保留策略 |
| --- | --- | --- | --- |
| `users`、`accounts`、`sessions`、`api_keys` | Identity | 账号、登录、会话和应用凭据 | 核心数据；只能通过身份策略/合规流程删除。 |
| `roles`、`user_roles`、`permissions` | Identity | 旧角色和 `resource:action` 兼容授权 | 兼容期保留，不能被 v0.10 migration 删除。 |
| `permission_definitions`、`role_permissions`、`route_operations`、`route_permission_bindings`、`authorization_audits` | Identity | v0.10 稳定权限、路由绑定、角色矩阵与授权证据 | 由 `000025` 追加；需备份后才可做 down 演练。 |
| `categories`、`tags`、`threads`、`posts`、`likes`、`notifications` | Community | 社区事实、内容关系和用户通知 | 核心数据；`threads` 同时保存 legacy `status` 和 v0.10 三维状态。 |
| `content_revisions`、`content_moderation_cases`、`content_moderation_actions` | Community | 修订、审核案例和状态转换证据 | 由 `000023` 追加；保留到内容保留策略明确。 |
| `richtext_article_contents`、`richtext_article_assets` | RichText Feature | 富文本正文/图片元数据 | 保留展示字段；治理状态以关联 Thread 为准。 |
| `user_spaces`、`user_space_contents`、`user_space_style_snapshots` | Personal Space Feature | 个人资料、历史内容投影、风格快照 | `user_space_contents` 进入影子/兼容期，禁止未验证删除。 |
| `plugins`、`plugin_permissions`、`plugin_logs` | Plugin Platform | External Plugin 运行时及权限/日志；历史 Built-in 行仅保留审计/回滚证据 | `000026` 将历史 Built-in 活跃行软删除，不物理清理。 |
| `plugin_records`、`plugin_file_metadata`、`plugin_user_grants`、`plugin_catalog_entries`、`plugin_install_requests`、`plugin_releases`、`plugin_market_audits` | Plugin Platform | v2 受管记录、文件元数据、用户 Grant、目录与发布治理 | 保留；数据归属和卸载语义由 Plugin Platform 执行。 |
| `webhook_endpoints`、`webhook_deliveries` | Webhook Feature | Webhook 配置与投递记录 | 受集成功能配置和审计保护。 |
| `mcp_audit_logs` | MCP-like Feature | 内部只读工具调用记录 | MCP-like 不是标准 MCP Server。 |
| `message_bindings`、`message_logs` | Message Feature | Local Adapter 绑定和消息记录 | 不宣称为第三方生产消息适配器。 |
| `ai_call_logs` | AI Gateway Feature | AI 调用审计/追踪 | 不保存敏感 token 明文。 |
| `audit_logs`、`configurations`、`builtin_feature_states` | Platform | 通用审计、配置和 Built-in Feature 状态 | 不因 Feature 停用删除。 |

所有历史 migration `000001` 至 `000022` 只读。v0.10 仅追加 `000023` 至 `000026`。`000026` 把历史 Built-in 状态/配置迁入 Feature Store、合并 Appearance 配置并从 External Plugin 活跃目录软删除历史行。删除表、列、目录或兼容 API 的前置条件是：无活跃读写、至少一个弃用版本、备份、恢复演练、数量/checksum 对账和明确的 forward-fix 方案。

## 4. 内容状态、读路径和兼容对象

`threads` 的 v0.10 可见性由以下谓词统一判定：

```text
publication_status = published
AND moderation_status = clear
AND deletion_status = active
```

| 读取者 | 合同 | 可见范围 |
| --- | --- | --- |
| 访客、帖子列表、公开个人主页、搜索、只读集成 | `ContentQuery.ListPublicThreads` / `GetPublicThread` | 上述公开谓词。 |
| 作者自己的个人主页管理视图 | `ContentQuery.ListAuthorThreads` | 作者自己的非 `purged` 内容及治理摘要。 |
| 管理端 | 管理应用服务和明确权限 | 根据稳定 Code、真实资源范围和状态机执行。 |
| RichText | 关联 Community Thread | 本地 `status` 是兼容显示，不是独立治理事实。 |

`user_space_contents` 仍有旧同步/回填路径，目的是兼容历史数据和回滚；生产装配优先给 Personal Space 注入 Community `ContentQuery`。在没有差异计数、读取统计和恢复证据前，它不能被物理删除。

## 5. 本地目录与 Resource Package

```text
data/
├── plugins/                  External Plugin 实现、manifest、入口与 README
├── plugin_data/              External Plugin 私有运行数据与版本快照
├── module_data/              Built-in Feature 本地可变数据
├── personal-space/<user>/    用户文件、图片、课表和受管插件附件
├── resources/                无 Runtime 的受管资源仓库
│   ├── themes/
│   ├── homepage-packs/
│   ├── space-style-packs/
│   ├── skills/ prompts/ personas/ knowledge-metadata/
├── images/                   非个人空间的全局图片
├── config/ dist/ skills/     本地预留或运行时导入目录
```

资源包允许模板、CSS、经筛查的资源和元数据，但不得包含 `plugin.yaml`、`go.mod`、`Cargo.toml` 等插件实现标识。当前受管风格包统一从以下来源读取：

```text
data/resources/space-style-packs/
data/resources/homepage-packs/
data/resources/themes/
```

每个已纳管目录包含 `resource.json` 并通过入口、路径和 checksum 检查。旧 `data/plugin_data/*/style-packs` 可使用 `scripts/migrate-v10-module-plugin-layout.sh` 冲突安全地迁入，回滚会按 `layout-moves.tsv` 逆序恢复；当前仓库不再把旧目录作为运行时资源源。

## 6. 生成物政策

以下目录是本地构建输出，必须由源码重新生成，而不是提交到 Git：

```text
web/dist/
admin/dist/
docs-site/.vitepress/cache/
docs-site/.vitepress/dist/
docs-site/.vitepress/.temp/
```

检查命令：

```bash
make data-governance-check
make generated-files-check
```

前者验证模块描述符、模块数据、外部插件实现/数据、用户存储和资源包的边界；后者检查 `.gitignore` 规则及上述生成物是否仍被 Git 追踪。它们只检查稳定仓库边界，不扫描用户私有文件内容。

## 7. 运行时与文档事实源

| 事实 | 权威来源 | 检查/生成方式 |
| --- | --- | --- |
| HTTP 路由与模块所有者 | `ownedGroup` 注册和运行时 Route Registry | `make contracts` / `make contracts-check`。 |
| 路由权限绑定 | Route Descriptor + `permission_definitions` / `route_permission_bindings` | 服务启动同步，`make architecture-check`。 |
| 数据库结构 | 顺序 migration | `make migrate-status`、`make database-check`。 |
| 架构图和表说明 | `docs/architecture` + data architecture sync skill | `python3 skills/sources/campusos-data-architecture-sync/scripts/check_architecture_sync.py --root .`。 |
| 文档链接 | Markdown 文档 | `make docs-links`。 |
| Web/Admin/docs 生成物 | 各自构建命令 | `make generated-files-check`。 |

## 8. 仍受控制的后续工作

1. 为 `user_space_contents` 建立实际差异/读取统计后，再决定停止写入和弃用时间。
2. 继续完善通用 Resource Package 在线导入、版本比较和签名分发体验；现有风格包已有校验、采用和布局回滚，不再依赖 Legacy Source。
3. 给高风险业务命令补充与授权审计同一事务的持久化方案；当前审计路径不承诺跨表原子提交。
4. 依据真实数据量和备份演练，制定内容修订、审核记录、插件日志和集成投递记录的保留期。
5. 不把这些待办与“可直接删除历史数据”混为一谈。任何物理清理必须另开阶段并保留恢复证据。
