# CampusOS v10 模块、插件与资源物理隔离

> 状态：v0.10-dev 已实施  
> 最后核验：2026-07-16

## 1. 结论

CampusOS 仍是模块化单体，不是“所有功能都做成插件”的单模块系统。v10
将编译期模块、外部插件、资源包及其数据从目录、生命周期、API 和权限四个
层面分开。

| 类型 | 描述符 | 实现 | 管理入口 | 可卸载 |
| --- | --- | --- | --- | --- |
| Core Module | `modules/core/*/module.yaml` | `internal/modules/core/*` 或明确的平台内核目录 | `/api/v1/features` 只读/策略配置 | 否 |
| Built-in Feature | `modules/features/*/module.yaml` | `internal/modules/features/*` | `/api/v1/features` | 否，可启停且保留数据 |
| External Plugin | `data/plugins/*/plugin.yaml` | Wasm 或受管外部进程 | `/api/v1/plugins` | 是 |
| Resource Package | `data/resources/*/*/resource.json` | HTML/CSS/图片/模板/受限特效等数据 | Appearance/Resource 工具 | 可导入导出，无业务 Runtime |

`runtime: builtin` 仅能被旧清单解析器读取以辅助迁移。Plugin Manager、包导入、
CLI 脚手架和目录扫描均拒绝安装它，也拒绝外部插件占用模块 ID、Feature ID
或 `homepage-customizer` 等兼容别名。

## 2. 目录所有权

```text
CampusOS/
├── modules/
│   ├── core/<module>/module.yaml
│   └── features/<feature>/module.yaml
├── internal/modules/
│   ├── core/
│   └── features/
└── data/
    ├── plugins/<external-plugin>/
    ├── plugin_data/<external-plugin>/
    ├── module_data/<built-in-feature>/
    ├── resources/{themes,homepage-packs,space-style-packs,...}/
    └── personal-space/<user_id>/
```

- `modules/` 是编译期合同，不是可写安装目录。
- `internal/plugin/` 是 Plugin Platform 宿主实现，不是某个 External Plugin。
- `data/plugins/` 只放可独立运行的外部扩展代码与 `plugin.yaml`。
- `data/plugin_data/` 只放外部插件私有 KV、快照和运行数据。
- `data/module_data/` 只放 Built-in Feature 的本地可变数据。
- `data/resources/` 只放无业务生命周期的资源包。
- `data/personal-space/` 由 User Storage Core 管理，课表、头像、富文本图片和
  插件用户附件都通过其安全路径、配额和所有权 Port 写入。

## 3. 运行时与管理面

Feature Registry 从嵌入的 `campusos.module/v1` 描述符注册 Core/Built-in
Feature，Plugin Manager 只扫描 External Plugin。

```text
GET  /api/v1/features
GET  /api/v1/features/:id
PUT  /api/v1/features/:id/config
POST /api/v1/features/:id/enable
POST /api/v1/features/:id/disable

GET  /api/v1/plugins
...  External Plugin install/config/lifecycle/package APIs
```

Core 使用 `always-on`；Built-in Feature 使用 `restart` 或 `hot-gated`。停用功能
只隐藏 UI、拒绝 API 或停止事件处理，不删除数据库行和文件。Gin 路由不会在
运行时动态增删，`hot-gated` 由统一中间件执行。

Web Runtime Manifest 分开返回：

```json
{
  "modules": [],
  "plugins": []
}
```

因此个人课表、个人空间和 Appearance 导航来自 `modules[]`，不会因 `/plugins`
只列外部插件而消失。

## 4. Appearance 与资源包

`homepage-customizer` 和 `web-theme` 是 Appearance Feature 的配置兼容别名，
不是插件。个人主页、首页和系统主题包分别位于：

```text
data/resources/space-style-packs/
data/resources/homepage-packs/
data/resources/themes/
```

每个受管资源目录必须包含 `resource.json`，其 ID 与目录名一致，并通过类型、
入口、安全文件、路径和 checksum 校验。内置 JSON 风格状态位于
`data/module_data/personal-space/styles/`。

## 5. 兼容与迁移

数据库 migration `000026_v10_module_plugin_separation`：

1. 将历史 Built-in 插件配置和目标状态写入 `builtin_feature_states`；已有
   Feature Store 保持权威。
2. 合并 Homepage/Web Theme 配置到 `appearance`。
3. 软删除 `plugins` 表中的历史 Built-in 活跃记录，不删除其审计数据。
4. 新增 `platform.feature.read/configure/lifecycle` 权限。

文件迁移工具：

```bash
./scripts/migrate-v10-module-plugin-layout.sh check
./scripts/migrate-v10-module-plugin-layout.sh apply backups/v10-layout-before
./scripts/migrate-v10-module-plugin-layout.sh rollback backups/v10-layout-before
```

`apply` 在冲突时停止，不覆盖同名目标；每次移动写入 `layout-moves.tsv`；
`rollback` 按记录逆序恢复。迁入的旧风格包会生成并验证 `resource.json`。

旧 `/plugins/<builtin-alias>` 单项接口在一个兼容周期内投影到 Feature Handler，
但 `/plugins` 列表不会重新混入 Built-in Feature。新代码应直接使用 `/features`。

## 6. 备份、回滚和门禁

备份格式 v2 同时包含 PostgreSQL、`modules/`、`data/module_data`、
`data/resources`、外部插件、插件数据和用户文件。恢复工具仍接受 v1 备份。

```bash
make data-governance-check
make architecture-check
make database-check
make restore-drill
```

- Data Governance 验证目录、描述符、保留名称、资源入口和 checksum。
- Architecture Check 阻止跨模块具体 Repository、Feature -> Plugin Manager、
  External Plugin -> `internal/*` 等新依赖。
- Database Check 包含 `000001..25 -> 000026 up/down/up` 隔离库演练。
- Restore Drill 核对模块描述、外部插件、模块数据、资源和用户文件。

任何后续合并目录、删除兼容 API 或清理历史数据库记录，都必须新增阶段、备份、
迁移和回滚证据，不能直接修改历史 migration。
