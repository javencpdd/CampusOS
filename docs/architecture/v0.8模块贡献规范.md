# CampusOS v0.8 模块贡献规范

> 生效阶段：A1  
> 适用范围：所有 `internal/` 后端领域、Web/Admin 领域模块和未来的兼容 Adapter。

## 后端模块

一个有业务职责的领域模块按需要采用以下结构，禁止为了目录形式建立空层：

```text
internal/<domain>/
├── module.go
├── domain/
├── application/
├── port/
├── adapter/
│   ├── postgres/
│   └── memory/
├── transport/http/
└── compatibility/
```

- `module.go` 是 Module Registry 的唯一注册点，声明稳定 ID、依赖、公开 Port 和可选生命周期。
- `domain/` 不依赖 HTTP、Gin、PostgreSQL、文件系统或其他领域的具体实现。
- `application/` 只组合本领域规则和其他领域的公开 Port。
- `port/` 是跨领域的唯一同步依赖面；事件用于异步协作。
- `adapter/` 是 PostgreSQL、Memory、文件、HTTP 客户端等基础设施差异的归属。Profile 只选择 Adapter，不构造业务 Service 或 Handler。
- `transport/http/` 将 HTTP DTO 转为 Application 命令，不持有其他领域 Repository。
- `compatibility/` 仅允许旧入口调用新 Application Service，不得拥有业务状态或新规则。每个 Adapter 必须有删除条件和回归测试。

Module 不得导入另一个领域的 `repository`、`service`、`handler` 或 `adapter`。同一领域内的暂存旧层可继续存在，直到对应 A3-A14 阶段迁移完成。

## Route Contributor

路由的唯一所有者是业务 Module。后续 Module 必须提供 Route Descriptor（稳定 `id`、`owner`、method、path、audience、auth、permission、feature gate 和 audit metadata），并在注册时将 Handler 注册到平台提供的静态 Gin group。

禁止在运行时动态增删 Gin 路由。`hot-gated` Feature 通过统一中间件拒绝请求，`restart` Feature 在下次启动读取有效状态。路由路径、认证和权限变化必须同步更新 HTTP 合同、OpenAPI、路由测试和进度文档。

## Infrastructure Profile

PostgreSQL 与 Memory Profile 只能绑定 Port 的 Adapter、基础设施、缓存和日志。业务 Service、Handler、DTO、Route Descriptor 和 Feature 规则必须由同一 Module 装配一次；不得在两个 Profile 分支复制它们。

## 前端领域模块

Web 与 Admin 的目标目录为：

```text
src/
├── app/
├── shared/
├── modules/<domain>/
│   ├── api/
│   ├── dto/
│   ├── store/
│   ├── routes/
│   ├── views/
│   ├── components/
│   └── internal/
└── pages/
```

一个模块可以从另一个模块的公开入口导入；不得导入 `@/modules/<other>/internal/*`。`app/` 只能组装路由、Provider 和全局壳，不查询领域数据。迁移期间旧 `api/`、`router/`、`stores/` 只可作为单向聚合入口，不能再增加领域逻辑。

## 自动化门禁

`make architecture-check` 同时执行后端检查、前端内部导入检查和检查器正负样例。A0 冻结的后端 allowlist 最多 8 个来源和 23 条具体边；它只能减少。任何新违规、allowlist 扩张、Feature 直接读取 Plugin Manager、Plugin 子服务反向依赖 Manager、External Plugin 导入 `internal/*` 或 Agent Contract 访问敏感 Core 实现都会失败。
