# CampusOS 当前架构概览

> 基线：`v0.6.26-dev`

## 1. 运行拓扑

```text
web（Vue 3，:3000） ----------\
                              -> API（Go + Gin，:8080） -> PostgreSQL
admin（Vue 3，:3001） --------/                       -> Redis / NATS
                                                          -> 本地 data/

docs-site（VitePress，:3002） -> 独立静态文档站
```

`web/` 是普通用户界面，`admin/` 是管理员界面。业务规则和授权必须在 API 层执行；前端只负责调用已授权接口和呈现状态。`docs-site/` 不依赖业务 API，负责面向使用者和插件开发者的项目介绍、部署、接口与插件教程，可以独立构建、部署或迁移到单独仓库。

## 2. 后端模块

v7 迁移采用模块化单体。当前已增加 `internal/platform/module`，由 Registry 在启动前检查依赖和循环，按拓扑顺序启动、失败逆序回滚，并在关闭时逆序停止。首个真实接入链为 `core.event-bus -> core.plugin-platform`；业务 Service、Handler 和 Router 仍通过兼容装配运行，后续按 [v7 计划书](../项目计划v7/00-v7版本计划书.md) 逐模块迁移。

四类能力边界为：不可停用的 Core Module、可停用且保留数据的 Built-in Feature Module、只能走 Host/Gateway/公开 API 的 External Plugin，以及不拥有业务生命周期的 Resource Package。

| 模块 | 职责 |
| --- | --- |
| `internal/core/identity` | 身份、JWT、角色、权限和后台授权。 |
| `internal/community` | 版块、标签、帖子、回复、可见性和事件。 |
| `internal/moderation` | 版块版主授权、作用域判定、治理动作和审计。 |
| `internal/plugin` | manifest、三轴生命周期、UI Contract/Revision/SSE、Extension Gateway、内置/gRPC/Wasm runtime、安装包、Host API 和配置。 |
| `internal/space` | 个人主页、内容同步、头像、个人空间和个人主页风格包。 |
| `internal/stylepack` | `page-style-pack.v1` 与 `campusos.app-style-pack.v2` 的目录/zip 读取、Layout Recipe 和安全筛查。 |
| `internal/webtheme` | 管理员提供的全用户前台主题目录、公开运行包和资源读取边界。 |
| `internal/richtext` | 受控图文文章、草稿、HTML 清洗和图片资产。 |
| `internal/schedule` | 按学期的个人课表 JSON、课程导入和日历计算。 |
| `internal/ai`、`internal/webhook`、`internal/mcp`、`internal/message` | AI Gateway、Webhook、内部 MCP-like 只读工具和 Message local adapter。 |

## 3. 插件边界

| 目录或概念 | 职责 |
| --- | --- |
| `data/plugins/<plugin>/` | 插件实现、manifest、运行入口和插件 README。 |
| `data/plugin_data/<plugin>/` | 插件运行数据、KV 数据和可编辑源码目录风格包。 |
| `scope: system/user` | 只表示管理级别、安装权限和系统重要性，不再决定 Runtime 生效方式。 |
| `lifecycle.backend.activation_mode` | `restart`、`plugin-restart` 或 `hot`；旧 manifest 按 Runtime 推导。 |
| `lifecycle.frontend.activation_mode` | 当前固定为 `hot`；路由、导航、插槽、Surface 和 Action 可注册与完整清理。 |
| `target: web` | 只作用于用户前台应用根节点；Admin 是独立前端，不加载系统主题。 |

“用户级”不表示普通登录用户可自行安装插件。插件安装和配置仍受管理员权限保护。插件状态分为 BackendState、FrontendState 和 Health；后端重启或降级不会自动删除前端页面。

## 3.1 前端运行时

```text
CampusApp -> ThemeRoot -> AppShell
  -> Header / Navigation / Hero / Sidebars / PageOutlet / Floating / Footer / Safety
  -> Runtime Registry
  -> Route / Navigation / Slot / Surface / Action
```

`GET /api/v1/ui/runtime-manifest` 提供当前主体可见贡献，`GET /api/v1/ui/events` 以 SSE 通知 revision。第三方默认 UI 使用白名单声明式 renderer；复杂旧页面只能通过 Core 编译期 trusted module registry 迁移。业务 Action 统一经 `/api/v1/extensions/:plugin/*path` 分发，插件只信任 Core 注入的 caller。

## 4. 本地数据边界

```text
data/
├── plugins/                 插件代码和 manifest
├── plugin_data/             插件运行数据和风格包
├── personal-space/<user>/   用户本地数据
│   ├── file/                通用文件和课表数据
│   ├── img/                 头像和富文本图片
│   ├── excel/ word/ pdf/    按类型归类的上传文档
│   └── file/schedule/
│       ├── index.json
│       └── terms/<year>-<semester>.json
├── images/                  非用户空间的全局图片
├── config/                  本地配置预留
├── dist/                    本地发布/构建产物预留
└── skills/                  本地 runtime/imported skills 预留
```

个人空间数据会计入配额。默认本地配额由 `personal-space` 插件配置；课表和富文本图片遵循相同的用户存储边界。

## 5. 安全与协议约束

- 页面风格包和自定义外观使用经过筛查的 HTML/CSS，不接受任意 JavaScript。
- 风格包可选 JavaScript 仅以 `sandbox-worker.v1` 运行；无同源、DOM、令牌、存储和任意网络权限。TypeScript 只是可选源码，运行前必须编译成受筛查的 JavaScript。
- CampusStyleSDK 只代理 manifest 声明的只读能力；个人主页数据固定到主页所有者，系统主题的私有能力还需当前用户单独授权。
- 插件包导入前检查路径安全、大小、checksum、manifest 和声明权限。
- MCP-like 工具是内部只读 API，不是标准 MCP Server。
- Message 是平台无关模型，只提供 local adapter；Discord、OneBot v11、NapCat 和 AstrBot 应作为适配器工作，而不是核心业务协议。
- 系统级授权和校验由 Go 服务强制执行，不能依赖浏览器侧检查。
- `member` 是有效登录用户的隐式基础角色；`user_roles` 记录管理员全局授权和版主版块授权，`guest` 不会写入用户角色关联。
- 版主请求必须同时满足动作权限和主题所属版块的 `category` scope；客户端传入的版块 ID 不能作为授权依据。

外部适配映射见 [接口协议适配器标准说明](../help/系统设计相关/接口协议适配器标准说明.md)。

## 6. 管理端数据架构页

管理端的 `/architecture` 页面以 `migrations/000001` 至 `000018` 和当前目录约定为来源，提供三个只读标签页：

- 数据库关系：按业务字段和索引归纳的 ER 逻辑关系、表职责、关键字段与迁移来源。
- 数据与文件：PostgreSQL、`data/`、个人空间、插件目录、插件数据和开发期日志之间的职责边界。
- 迁移与维护：迁移文件分组、常用迁移命令和备份边界。

`000016` 已为核心身份、社区、个人空间、富文本和 Webhook 稳定关系增加并验证 25 条 PostgreSQL foreign key；插件名称、多态目标、版主 category scope 和外部平台字符串 ID 等连线仍属于服务层逻辑关系。页面不会读取真实业务数据、密钥或本地文件内容。

该页面不会与运行中的 PostgreSQL 实时同步。后续修改 migration、迁移脚本或持久化目录时，使用 `skills/campusos-data-architecture-sync/` 中的检查器比对 schema 表、架构图表项、关系端点、最新 migration 标记和外键说明：

```bash
python3 skills/campusos-data-architecture-sync/scripts/check_architecture_sync.py --root .
```
