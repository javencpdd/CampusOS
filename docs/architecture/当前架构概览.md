# CampusOS 当前架构概览

> 基线：`v0.6.8-dev`

## 1. 运行拓扑

```text
web（Vue 3，:3000） ----------\
                              -> API（Go + Gin，:8080） -> PostgreSQL
admin（Vue 3，:3001） --------/                       -> Redis / NATS
                                                          -> 本地 data/

docs-site（VitePress，:3002） -> 独立静态文档站
```

`web/` 是普通用户界面，`admin/` 是管理员界面。业务规则和授权必须在 API 层执行；前端只负责调用已授权接口和呈现状态。`docs-site/` 不依赖业务 API，负责面向使用者和插件开发者的项目介绍、部署、接口与插件教程，可以独立构建、部署或迁移到单独仓库。

## 2. 后端模块

| 模块 | 职责 |
| --- | --- |
| `internal/core/identity` | 身份、JWT、角色、权限和后台授权。 |
| `internal/community` | 版块、标签、帖子、回复、可见性和事件。 |
| `internal/moderation` | 版块版主授权、作用域判定、治理动作和审计。 |
| `internal/plugin` | manifest、内置/gRPC/Wasm runtime、安装包、Host API、配置和生命周期。 |
| `internal/space` | 个人主页、内容同步、头像、个人空间和个人主页风格包。 |
| `internal/stylepack` | `page-style-pack.v1` 的目录/zip 读取和安全筛查。 |
| `internal/webtheme` | 管理员提供的全用户前台主题目录、公开运行包和资源读取边界。 |
| `internal/richtext` | 受控图文文章、草稿、HTML 清洗和图片资产。 |
| `internal/schedule` | 按学期的个人课表 JSON、课程导入和日历计算。 |
| `internal/ai`、`internal/webhook`、`internal/mcp`、`internal/message` | AI Gateway、Webhook、内部 MCP-like 只读工具和 Message local adapter。 |

## 3. 插件边界

| 目录或概念 | 职责 |
| --- | --- |
| `data/plugins/<plugin>/` | 插件实现、manifest、运行入口和插件 README。 |
| `data/plugin_data/<plugin>/` | 插件运行数据、KV 数据和可编辑源码目录风格包。 |
| `scope: system` | 随服务部署的核心能力。管理端启停只记录目标状态，重启 API 后才生效。 |
| `scope: user` | 可独立维护的扩展。管理员可加载、重载、停止和覆盖更新。 |
| `target: web` | 只作用于用户前台应用根节点；Admin 是独立前端，不加载系统主题。 |

“用户级”是生命周期分类，不表示普通登录用户可自行安装插件。插件安装和配置仍受管理员权限保护。

## 4. 本地数据边界

```text
data/
├── plugins/                 插件代码和 manifest
├── plugin_data/             插件运行数据和风格包
├── personal-space/<user>/   用户本地数据
│   ├── file/                通用文件和课表数据
│   ├── img/                 头像和富文本图片
│   ├── excel/ word/ pdf/    按类型归类的上传文档
│   └── file/schedule/
│       ├── index.json
│       └── terms/<year>-<semester>.json
├── images/                  非用户空间的全局图片
├── config/                  本地配置预留
├── dist/                    本地发布/构建产物预留
└── skills/                  本地 runtime/imported skills 预留
```

个人空间数据会计入配额。默认本地配额由 `personal-space` 插件配置；课表和富文本图片遵循相同的用户存储边界。

## 5. 安全与协议约束

- 页面风格包和自定义外观使用经过筛查的 HTML/CSS，不接受任意 JavaScript。
- 风格包可选 JavaScript 仅以 `sandbox-worker.v1` 运行；无同源、DOM、令牌、存储和任意网络权限。TypeScript 只是可选源码，运行前必须编译成受筛查的 JavaScript。
- CampusStyleSDK 只代理 manifest 声明的只读能力；个人主页数据固定到主页所有者，系统主题的私有能力还需当前用户单独授权。
- 插件包导入前检查路径安全、大小、checksum、manifest 和声明权限。
- MCP-like 工具是内部只读 API，不是标准 MCP Server。
- Message 是平台无关模型，只提供 local adapter；Discord、OneBot v11、NapCat 和 AstrBot 应作为适配器工作，而不是核心业务协议。
- 系统级授权和校验由 Go 服务强制执行，不能依赖浏览器侧检查。
- `member` 是有效登录用户的隐式基础角色；`user_roles` 记录管理员全局授权和版主版块授权，`guest` 不会写入用户角色关联。
- 版主请求必须同时满足动作权限和主题所属版块的 `category` scope；客户端传入的版块 ID 不能作为授权依据。

外部适配映射见 [接口协议适配器标准说明](../help/系统设计相关/接口协议适配器标准说明.md)。

## 6. 管理端数据架构页

管理端的 `/architecture` 页面以 `migrations/000001` 至 `000017` 和当前目录约定为来源，提供三个只读标签页：

- 数据库关系：按业务字段和索引归纳的 ER 逻辑关系、表职责、关键字段与迁移来源。
- 数据与文件：PostgreSQL、`data/`、个人空间、插件目录、插件数据和开发期日志之间的职责边界。
- 迁移与维护：迁移文件分组、常用迁移命令和备份边界。

当前 migration 没有声明 PostgreSQL foreign key；页面中的连线是 `user_id`、`thread_id`、`plugin_name` 等字段和服务层约束表达的逻辑关系，而不是数据库强制外键。页面不会读取真实业务数据、密钥或本地文件内容。

该页面不会与运行中的 PostgreSQL 实时同步。后续修改 migration、迁移脚本或持久化目录时，使用 `skills/campusos-data-architecture-sync/` 中的检查器比对 schema 表、架构图表项和关系端点：

```bash
python3 skills/campusos-data-architecture-sync/scripts/check_architecture_sync.py --root .
```
