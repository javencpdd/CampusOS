# CampusOS v0.7 模块边界与数据所有权

## 分层

CampusOS 保持模块化单体。`internal/platform/module` 管理 Core 生命周期，`internal/platform/feature` 管理内置功能启停，`internal/plugin` 只为外部扩展提供兼容 Facade，`internal/platform/resource` 管理无运行时的资源包。

| 层级 | 实现入口 | 约束 |
| --- | --- | --- |
| Core | Identity、Community、Moderation、User Storage | always-on，不允许普通卸载 |
| Built-in Feature | Personal Space、RichText、Schedule、Appearance | restart 或 hot-gated，停用不删数据 |
| External Plugin | gRPC、Wasm、Remote HTTP、MCP、Runner | 只走 Host/Gateway/公开 API |
| Resource Package | `data/resources` 与 Legacy Source | 不注册路由、进程、migration |

## 装配

`internal/server/server.go` 只保留 Server 外观和 Run 入口；`bootstrap.go` 装配 Database、EventBus、Plugin Platform、Cache 和 Metrics；`module_assembly.go` 提供 Identity、Community 和公开 Port 装配入口；`application.go` 保留兼容业务编排和静态路由。后续新增业务不得回填到 `server.go`。

## 数据所有权

- Identity：用户、会话、角色和权限表。
- Community：版块、帖子、回复和标签表。
- Moderation Core：板块作用域策略、治理审计和操作完整性。
- User Storage Core：`data/personal-space/<user-id>`、安全路径、标准目录和配额 Port。
- Plugin Platform：插件记录、运行日志、KV 与 `data/plugins` 外部实现。
- Resource Repository：`data/resources`；旧 `data/plugin_data/*/style-packs` 作为 Legacy Source。

跨模块历史依赖记录在 `config/architecture-boundary-allowlist.json`，`make architecture-check` 只允许有责任和移除说明的存量项，拒绝新增违规。Identity、Community、Plugin 和 User Storage 已提供可运行 Adapter，并通过命名 Port 注册到 Module AppContext；External Plugin 不会取得该 Context。
