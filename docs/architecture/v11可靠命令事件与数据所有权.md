# v11 可靠命令、事件与数据所有权

> 基线：`v0.11.0`  
> 权威实现：`internal/platform/transaction/`、`internal/platform/reliability/`、migration `000027`  
> 相关 ADR：[ADR-0011](decisions/ADR-0011-可靠命令与持久事件边界.md)

## 1. 目标链路

```text
已认证请求 / Core 调用
  -> 路由 Operation 与 Permission Code
  -> 服务读取真实资源、角色和 scope
  -> TxKernel
       -> 业务表
       -> required authorization/content audit
       -> platform_command_audits
       -> platform_outbox
  -> COMMIT
  -> Reliable Worker
       -> 具名消费者 receipt / attempt
       -> EventBus 兼容分发、Webhook fan-out 或其他受控消费者
```

`platform_outbox` 只在提交成功后可被 Worker claim。任何外部副作用必须位于 commit
之后；失败通过 retry 或 dead-letter 保留证据，而不是回滚已经发出的 HTTP 请求。

## 2. 所有权表

| 数据/目录 | Owner | 写入边界 | 说明 |
| --- | --- | --- | --- |
| `users`、`accounts`、`user_roles`、`role_permissions` | Identity Core | Identity Repository + TxKernel | 注册和高风险授权动作与 reliable command 一起提交。 |
| `authorization_audits` | Identity Core | Identity 授权服务 | 保留现有允许/拒绝/错误证据；`000027` 追加 command/trace/resource version 链接。 |
| `threads`、内容治理/修订表 | Community Core | Community Repository + TxKernel | 真实板块和版本是治理权限的事实源。 |
| `platform_outbox`、receipt、attempt、lease、command audit、operation、compatibility、retention run | Reliability Core | `internal/platform/reliability` | External Plugin 和 Feature 只能使用窄 Service Port。 |
| `webhook_endpoints`、`webhook_deliveries` | Webhook Built-in Feature | Webhook Service | 投递记录以 `endpoint_id:event_id` 幂等；与 Outbox 通过 `outbox_event_id` 关联。 |
| `data/plugins/`、`data/plugin_data/` | Plugin Platform | Package Manager + operation tracker | 文件操作使用 staging/snapshot/compensation，非数据库原子事务。 |
| `data/resources/` 与 Appearance 状态 | Appearance Feature | Appearance Facade + operation tracker | Legacy source 仍可读并记录兼容遥测。 |

## 3. 已接入命令目录

| Command Code | Owner | 业务事实 | Required evidence / event | 失败策略 |
| --- | --- | --- | --- | --- |
| `identity.user.register` | Identity | `users`、`accounts` | command audit、`user.created` | 任一数据库写失败全部回滚。 |
| `identity.role.assign` / `identity.role.revoke` | Identity | `user_roles` | authorization audit、command audit、`authorization.changed` | 事务内复核权限；最后管理员和自助提权继续拒绝。 |
| `identity.role.scopes.replace` | Identity / Moderation policy | category scoped grants | authorization audit、command audit、`authorization.changed` | 空范围撤销版主能力；失败回滚。 |
| `identity.role.create` / `identity.role.permissions.update` | Identity | role / matrix | authorization audit、command audit、`authorization.changed` | 操作者权限上限仍为服务端事实。 |
| `community.thread.*` 高风险治理 | Community | thread 状态、case、revision、治理 action | content authorization audit、command audit、领域事件 | 乐观版本/真实 category scope；业务或必需证据失败回滚。 |
| `platform.reliability.replay` | Reliability Core | dead-letter status | command audit、operation record | 仅 dead-letter；Idempotency-Key 重复不重置事件。 |
| 插件包和 Appearance 操作 | Plugin / Appearance | 文件系统与 catalog/config | operation run、snapshot、兼容记录 | staging/rename/restore；失败保留 failed 操作供人工处理。 |

## 4. Worker 语义

- PostgreSQL claim 使用 `FOR UPDATE SKIP LOCKED`；过期 worker 的完成写入会因 owner 与
  `lease_generation` 不匹配被拒绝。
- retry 使用指数退避和抖动；达到最大次数或永久错误进入 `dead`。
- 每个消费者有 `(consumer_name, event_id)` receipt。成功消费者不会因另一个消费者
  重试而重复执行。
- 有 exclusive handler 的事件不会走 legacy EventBus fallback；additive consumer 可以
  和 fallback 并存，Webhook fan-out 使用该模式，并以子事件幂等去重。
- 服务停止时 Worker 取消 poll loop；任务并不丢失，lease 过期后可由下一实例处理。

## 5. 兼容路径

| 历史对象 | 当前处理 | 退出条件 |
| --- | --- | --- |
| EventBus 发布/订阅 | 仍由 fallback 分发；新高风险 producer 写 Outbox | 观察 consumer/兼容遥测后另立弃用计划。 |
| `permissions` `resource:action` | 继续用于 legacy catalog fallback，并记录使用 | 连续版本无调用且迁移/回滚证据完整。 |
| `runtime: grpc` | 仍是受管进程 Runtime 的兼容名 | 不等同 protobuf gRPC；协议升级另行完成。 |
| `user_space_contents` | 个人空间 legacy 内容投影可读并记录 | 先完成差异计数、恢复与访问证据。 |
| `data/plugin_data/*/style-packs` | Appearance Legacy Resource Source | 资源迁移和用户回滚确认后再评估。 |

兼容遥测是删除历史路径的必要证据，不是自动删除开关。

## 6. 不变量与审计可见性

1. 高风险允许路径中，业务写、required audit 和 Outbox 任一失败都不得留下部分提交。
2. 拒绝不会因为审计故障而变成允许；事务内拒绝产生的证据必须在回滚后独立记录。
3. 可靠性 API 仅在后台 Permission Code 保护下提供。命令审计列表不返回 raw payload、
   `details`、Webhook Secret 或 Token。
4. Resource Package 没有运行时业务生命周期；External Plugin 也不能直接导入
   `internal/*`、访问数据库、JWT 私钥或宿主完整文件系统。
5. 保留任务 v11 只做 dry-run，不物理删除审计、事件、Webhook 或内容历史。
