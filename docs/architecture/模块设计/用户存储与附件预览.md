# 用户存储与附件预览

> 更新时间：2026-09-21（Asia/Shanghai）
> 实现基线：v1.1-dev
> 返回：[当前架构概览](../当前架构概览.md)

## 三层职责

| 层次               | 负责内容                             | 不负责内容         |
| ------------------ | ------------------------------------ | ------------------ |
| Storage Object     | 原始字节、哈希、配额、对象生命周期   | 文章是否开放       |
| User Asset         | 稳定资产 ID、owner、名称、MIME、状态 | 直接暴露磁盘路径   |
| Article Attachment | 文章绑定、显示名、顺序、访问上下文   | 授予作者空间访问权 |

代码入口：[ObjectService](../../../internal/modules/core/userstorage/object_service.go)、
[附件服务](../../../internal/modules/features/richtext/attachments.go)、
[附件 HTTP 处理](../../../internal/modules/features/richtext/handler.go)。

## 实际落盘与一致性

默认存储根为 data/personal-space，相对于 API 进程工作目录。新附件路径为：

```text
data/personal-space/<用户ID>/file/objects/<对象ID>.bin
```

原始文件名与 MIME 存在数据库，不能按原始文件名查找 .pdf 文件来判断是否落盘。
Docker 开发环境将仓库挂载为 /workspace，因此默认路径映射到宿主仓库的 data/personal-space；
改变启动目录或挂载时先核实路径，不能假定宿主和容器任意同名目录相通。
当前 bootstrap 使用 Core 固定默认根，Config.Load 没有全局 USER_STORAGE_ROOT 配置键；
历史 Feature 配置不等于 Core Object 根配置，详见 [配置边界](../配置与运行边界.md)。

上传先验证文章权限、大小和格式，再经 Object Port 配额预留、临时文件写入、同步与原子重命名保存字节。
RichText 随后保存资产及文章绑定；失败时进行补偿清理。ObjectService 不负责全部业务表，
也不存在文件系统与 PostgreSQL 跨介质的单一 ACID 事务；异常残留需通过对账工具审查。

默认个人空间配额为 50 MiB，管理员可调整。附件当前限制为单文件 20 MiB、每篇 10 个、合计 40 MiB，
并继续受用户剩余配额约束。允许 PDF、MP3、MP4、DOC/DOCX、XLS/XLSX、ZIP、RAR；
扩展名、MIME、文件签名和 Office 容器校验不能替代病毒扫描。

历史头像、正文图片、课表可能仍使用各自兼容目录；“我的文档”不是整个存储根目录的文件浏览器。

## 下载权限与接口

所有路径前缀 /api/v1；以下附件和资产接口要求登录。

| 入口              | 接口                                                           | 服务端边界                                                      |
| ----------------- | -------------------------------------------------------------- | --------------------------------------------------------------- |
| 我的资产列表      | GET /assets?status=active&limit=50&cursor=...                     | 当前用户 keyset 分页；每页 1～200，返回 next_cursor；按更新时间和 bigint ID 降序 |
| 我的资产下载      | GET /assets/:id/download                                       | owner 匹配且资产可用；不能靠换 ID 访问别人                      |
| 文章上传附件      | POST /richtext/articles/:id/attachments/upload                 | 作者写入权限、格式与配额                                        |
| 文章附件下载      | GET /richtext/articles/:id/attachments/:attachment_id/download | 文章可读、绑定属于该文章、资产有效                              |
| 我的 PDF 预览     | POST /assets/:id/pdf-invocations                               | 当前用户拥有 PDF                                                |
| 文章 PDF 预览     | POST /plugin-ui/invocations                                    | 在文章上下文核验附件阅读权限                                    |
| 我的文档 PDF 预览 | POST /documents/:id/pdf-invocations                            | 文档 owner 匹配、仅当前版本为 PDF                               |
| 我的文档下载      | GET /documents/:id/download                                    | 文档 owner 匹配；浏览器必须经认证 API 获取 Blob，不能使用裸链接 |
| 预览内容          | GET /plugin-ui/invocations/:id/content                         | 调用者、期限、上下文和资源重新鉴权                              |
| 预览失败时下载 | GET /plugin-ui/invocations/:id/download | 宿主认证下载；上下文属于当前用户，重新检查业务 ACL，不依赖插件预览授权 |

其他用户只通过开放文章的附件入口下载；当前实现不提供匿名附件下载。
作者查看自己的草稿不意味着其他人也可查看。管理员治理权限不自动等同于下载他人私有文件。

## 双入口预览流程

文章附件列表、个人空间资产面板或“我的文档”的 PDF 行 → 用户确认 PDF 插件的用途授权 → 创建 Invocation
→ 宿主打开已校验 release 的隔离 PDF Surface → PDF.js 通过 Host Bridge 认证读取原始字节。个人空间资产入口位于
[个人主页设置](../../../web/src/modules/space/pages/SpaceSettingsView.vue)；“我的文档”入口位于
[PersonalDocumentsView](../../../web/src/modules/personal-documents/pages/PersonalDocumentsView.vue)，两者是不同业务边界。

`campusos.pdf-viewer` 的 v4 Manifest 声明 `article_attachment.self.preview`、`personal_space_file.self.read`、
`plugin_ui.surface.open` 以及可选的 `plugin_record.self.read/write`。启动时仅为尚无记录的能力建立可撤销的管理员默认 Grant；用户首次预览时
在插件中心或确认框同意对应的 restricted 数据用途。管理员拒绝/撤销、用户撤销同意、插件停用、文章状态变化
或资产状态变化都会使后续创建或读取失败。

Invocation 有效期十分钟，绑定调用用户；`article_attachment`、`personal_asset` 与 `personal_document`
使用互斥上下文约束。个人文档 Invocation 只保存 document ID，不复制对象，也不会暴露 Object ID 或物理路径。
`internal/platform/pluginui` 负责通用签发/读取，业务模块提供固定资源解析器；既有 `context_digest` 绑定插件授权版本、Surface 和对象版本/哈希。
每次读取重新核验 owner、版本、格式和状态，URL 不是绕过授权的永久分享链接。内容支持认证 Range 读取，
并使用私有缓存策略；预览不另存一份转换后的 PDF。PDF Viewer 和 PDF.js Worker 是插件 release 内的内容哈希资源，
由隔离静态网关分发；受保护的 PDF 内容仍走宿主认证 `/api/` 私有响应，绝不写入该持久缓存。
用户同意后，最近阅读页仅存入既有 `plugin_records` 的 `campusos.pdf-viewer/reading_positions` owner=user 命名空间，
按资源类型和当前对象 ID 区分版本；不使用 `localStorage`、IndexedDB 或 PDF 缓存。

**当前 Viewer 是自包含的 v4 UI-only 插件包，渲染模块不是宿主静态 import。** Plugin UI 接入与限制见
[插件平台与授权体系](插件平台与授权体系.md)。它仍未完成用户安装状态机、Admin 动态界面、任意第三方 Runner、病毒扫描和通用 Office 在线预览。

## 治理与验证

回收、隔离、恢复和清除需审查资产状态、文章引用与低敏审计；清除前预览影响，不直接删除整个用户目录。
至少验证 owner 越权、私有草稿、下架、过期 Invocation、Range 边界、格式伪装与上传中断补偿。

移除文章附件时先在同一事务锁定绑定行、删除该绑定的预览上下文，再删除绑定；否则 Invocation FK 会阻止移除。
后台每分钟清理最多 500 条过期超过 24 小时的上下文，不删除资产/字节；24 小时保留期支持预览到期后的宿主下载降级。
旧上下文被清理后回来源页面下载，不能将短期记录当作永久书签。

附件内容流限制为每用户同时 20 路、API 实例总计 64 路、每用户每分钟 1200 次，返回 429、中文上限和 Retry-After；
限流窗口最多 4096 用户，单次内容响应写期限 2 分钟。该机制是单实例限制，不是跨节点全局限流，也不限制普通 SSE。
