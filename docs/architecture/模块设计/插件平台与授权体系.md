# 插件平台与授权体系

> 更新时间：2026-09-20（Asia/Shanghai）
> 实现基线：v1.1-dev
> 返回：[当前架构概览](../当前架构概览.md)

## 职责与信任分类

[插件平台](../../../internal/plugin) 管理 Manifest、安装、授权、运行状态、宿主能力和扩展入口。
Core、内置 Feature、外部 Plugin、无运行时 Resource Package 使用不同生命周期。
停用、撤权、卸载和删除持久数据不是同一个操作。

当前装配注册 grpc、process、wasm、builtin 四个 Runtime 名称；grpc 与 process 共用受管进程适配器，
wasm 使用 wazero。grpc 的兼容名称不能解释为完整标准 protobuf gRPC 服务。
`builtin` 不执行包提供的代码，只为随 CampusOS 编译的第一方受管插件保存生命周期、UI 和授权事实。
宿主 API 不提供核心 JWT、数据库连接串或用户存储根；受管进程本身仍需操作系统权限隔离，不能视为完整沙箱。

这里的“不提供”既包括 Host API 合同，也包括 process/grpc 的明确子进程环境白名单：只保留启动所需的 PATH、
locale/时区（Windows 保留系统启动变量），并显式注入短期 Host Token、专属数据目录和 config 路径。数据库、JWT、
SMTP 和平台 `CAMPUSOS_*` 环境不继承。它仍**不是** OS 沙箱；目标部署必须再以独立身份、受限目录和数据库网络隔离
限制进程，不能据 Host API 没有 SQL 方法宣称外部进程已经无法访问数据库。

## 插件持久数据边界

项目约定：插件只使用平台预先开放的通用表接口、自身 SQLite 和自身文件型 config。禁止插件自行创建平台表、
执行平台 migration 或取得任意 SQL 权限。当前 `plugin_records`、`plugins.config`、受管文件和授权相关表均由平台维护。
SQLite KV 默认位于 `data/plugin_data/<plugin-name>/plugin.db`；`PreparePluginStorage` 同时规定私有 `config.json`，
并以 JSON 校验、256 KiB 上限、原子写入和符号链接拒绝保护它。宿主管理 Config API 仍持久化到 `plugins.config`，
二者不双向同步。完整代码依据、配置方式和待实施项见
[插件存储边界与平台通用数据设计](../../help/系统设计相关/插件存储边界与平台通用数据设计.md)。

当前 `000001_v1_1_schema_baseline` 已包含 `plugin_ui_invocations` 的个人文档 FK 和三类上下文约束；这是平台资源关系，外部插件不执行任何 migration。
通用签发与校验已提取到 `internal/platform/pluginui`；RichText 适配器提供三类业务资源解析，server 装配插件注册与授权检查。
平台复用 `context_digest` 绑定不可变插件版本、Surface 和资源对象版本，不执行插件提供的解析器。
Viewer 的最近页使用其声明的
`plugin_records` user collection，键由资源类型和当前 storage object ID 构成；读/写均需独立 Grant/Consent，失败时
只保留会话状态。浏览器静态 JS/Worker 缓存可继续保留，但不保存 PDF 字节或阅读位置。

## 三层授权流程

1. 插件 Manifest 声明 Capability 和作用域。
2. 管理员批准平台允许的能力范围。
3. 代用户处理数据时，用户明确同意相应范围。

[授权服务](../../../internal/plugin/authorization.go) 对声明、管理授权、用户同意和当前策略进行交集验证。
普通用户通过授权界面确认，不需要自己制作密钥或长期 Token。短期委托凭据由平台管理，
不应把浏览器用户登录令牌转交插件。版本、策略或授权状态变化后不能继续沿用已失效授权。

`plugin_versions` 等授权表使用 64 位 Snowflake `BIGINT` ID。为避免浏览器 JavaScript `number` 超过安全整数范围后
静默舍入，授权 Overview、Grant、Consent 与 Delegation API 均以**十进制字符串**输出和接收这些 ID；前端将其原样拼入
路径参数，服务端再以 `int64` 校验。若把它转换成 number，会请求一个不同版本并表面化为“当前插件版本没有声明该能力”，
不能据此判定 Manifest 或数据库声明丢失。

Host API 的具体能力、参数与权限见 [API 文档入口](../../api/README.md)；
宿主受管文件或插件数据不能被等同于核心业务表访问权。

## 运行接口与依赖

| 接口或代码                       | 职责                       |
| -------------------------------- | -------------------------- |
| GET /api/v1/ui/runtime-manifest  | 输出当前可用界面贡献       |
| GET /api/v1/ui/events            | 运行状态变更通知           |
| /api/v1/extensions/:plugin/*path | 认证后的 Extension Gateway |
| internal/plugin/hostapi          | 受授权限制的宿主接口       |
| internal/plugin/ui_contract.go   | Plugin UI 声明及校验       |

依赖 Identity、插件授权持久化、秘密管理、受管运行目录和运行时适配。
插件秘密不得明文进入日志；错误与监控应保留诊断能力而不泄漏 Token 或用户内容。

## 界面弹窗与新标签页

[Surface Host](../../../web/src/campus-ui/PluginSurfaceHost.vue) 支持 modal、drawer、fullscreen、new-tab 等呈现方式。
宿主决定可打开的 Surface 与受控路径，不接受任意远程 URL、动态 Vue 代码或插件注入脚本。

声明式 `open-surface` 已与 HTTP Extension 动作分流：只有宿主选定的 `resourceContext` 才能用于签发；
服务端验证 Action 的归属、Surface/Presentation、附加 Permission 和数据能力，Schema body 不能替代资源上下文。
上下文只支持平台固定的三类 PDF 资源，不表示已交付任意第三方动态预览代码。
关闭弹窗恢复触发器焦点；插件停止或运行版本变化会卸载已打开的界面，后端仍独立复核每次内容读取。
管理端显示 UI 合同、Surface/Presentation、健康和最近错误摘要，不为诊断读取文件内容。

PDF Viewer 的受管插件 Manifest 位于 [builtin_pdf_viewer.go](../../../internal/plugin/builtin_pdf_viewer.go)，
兼容性 Feature 描述符位于 [PDF Viewer 模块](../../../modules/features/pdf-viewer/module.yaml)，渲染实现位于
[PDF Viewer 页面](../../../web/src/modules/pdf-viewer/pages/PdfViewerView.vue)。描述符不再声明 UI，避免与插件
Manifest 重复注册同一 Surface/Route。`builtin.pdf-viewer` 使用 `builtin` Runtime 和可信白名单
`core.pdf-viewer`，通过 Plugin UI 宿主与短期 Invocation 连接文章附件、个人资产及 owner-only Personal Documents
三种入口。
原 `pdf-viewer` Feature 仍是兼容性总开关：它关闭时 RichText 不签发 Invocation；它不再声明 Surface、
不保存插件授权，也不替代插件的启停与 Grant/Consent 判断。

其访问决策同时要求 Manifest Declaration、管理员 Grant、用户 Consent（仅受限文件读取）、运行状态、
当前文章或 owner 访问判定以及未过期 Invocation。文章入口不会伪造附件 owner：先由 RichText 验证阅读权，
再用 `article_attachment.self.preview` 记录当前用户的用途授权；个人资产和 Personal Documents 入口均额外要求
当前用户是 owner，并使用 `personal_space_file.self.read`。个人文档只传递 document ID，不向插件运行时暴露
对象路径、对象 ID 或长期链接。创建 Invocation 和每次 Range 内容读取均复核上述状态。管理员可在“插件运行管理”调整 Grant，用户可在
“插件中心 → PDF 文档预览 → 查看并授权”撤销 Consent。

Viewer 本体和 PDF.js Worker 是随 Web 构建的内容哈希静态资源，生产 `/assets/` 可长时间缓存；受保护 PDF
字节始终由 API 以私有缓存策略返回，不持久化为插件缓存。它不是可安装的第三方包；动态第三方 Bundle、
sandbox iframe 和 Bridge 仍是后续范围。

## 验证重点

覆盖越权 Capability、过期或撤销委托、版本/策略变化、功能停用、恶意跳转、无效 Surface、
Invocation 跨用户复用及进程退出。文章下架后已有预览也应重新受阅读权限约束。
