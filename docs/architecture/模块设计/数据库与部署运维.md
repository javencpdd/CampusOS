## 数据所有权与迁移

[migrations](../../../migrations/README.md) 是数据库结构事实源。
当前重建基线包含核心业务、插件三层授权与权限种子；后续迁移追加运行时修正、
附件资产、文章绑定、预览 Invocation、资产治理以及个人资产预览上下文。

表由模块拥有，跨模块通过显式服务或 Port 协作；管理端架构页是结构投影，不是实时全库数据浏览器。
已应用迁移的校验值有意义，不能随意改旧 UP 文件消除运行错误。
新增变更追加有序 UP/DOWN，说明外键、索引、默认值、回滚损失和数据修复前置条件。

测试数据可重置并不意味着任何一次任务都应执行删除；重置或 destructive DOWN 前需确认目标库和授权。

## 持久数据边界

| 位置 | 内容与约束 |
| --- | --- |
| PostgreSQL 数据卷 | 业务事实、权限、资产元数据、任务与审计 |
| data/personal-space | 用户对象字节及历史兼容布局 |
| 插件实现目录与 plugin_data | 安装实现与插件运行数据分离 |
| module_data、resources | 内置模块数据与无运行时资源分别管理 |
| .campusos/logs | 开发日志，注意脱敏与保留策略 |

准确的目录解析由运行配置和对应存储服务决定。备份必须关联数据库与用户字节，
仅备份数据库不能恢复附件；仅复制文件不能恢复所有权、引用和权限。

API 当前会在 PostgreSQL 连接失败时选择内存适配器，不按生产环境排除此分支。
本地用户存储与插件 SQLite 限制为单实例写入，multi 模式在启动校验中被拒绝。
这些边界及准确配置键见 [配置与运行边界](../配置与运行边界.md)。

## Docker 开发与配置流程

[开发 Compose](../../../compose.dev.yml) 编排 API、Web、Admin、文档、PostgreSQL、Redis 与 NATS。
开发本地配置由模板生成到 deploy/docker/.env.dev.local；应用根 .env.example、生产 Docker 模板与开发模板
不是四份需要同步手改的同一配置。

Windows 入口为 scripts/docker-dev.ps1，Linux 入口为 scripts/docker-dev.sh。
up 使用现有开发镜像；依赖、Dockerfile、构建配置或容器入口脚本变化需 rebuild。
普通源码由容器内开发进程监听，改源码通常不必重建镜像；配置变化需重新运行 up 让 Compose 按配置重建容器。
单纯 docker restart 不会重新读取新的 Compose 环境变量。

端口绑定 0.0.0.0 只是局域网可达的必要条件之一，还需宿主防火墙、路由和服务监听允许。
API/数据服务默认回环约束与 UI 暴露分开，不能为方便预览顺便公开数据库端口。

## 健康、日志与验证

GET /api/v1/health 返回静态服务状态和版本，不检查各依赖；Docker healthcheck 的间隔不等于浏览器轮询间隔。
容器退出先查日志中的首次实际错误，不能把健康检查访问日志当失败原因。
容器日志与平台日志的采集链需要分别核实，文件权限错误也不等于数据库迁移失败。

按变更范围运行：

```bash
python scripts/check-doc-links.py
python migrations/tools/generate_er.py --check
make architecture-check
make data-governance-check
make database-check
```

数据库演练使用隔离环境；本次纯文档整理不执行迁移、重置或容器重启。
发布还需目标 Linux、浏览器、备份恢复与容量证据，文档更新不替代实际验收。
