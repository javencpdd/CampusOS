# 社区内容与审核治理

> 更新时间：2026-09-23（Asia/Shanghai）
> 实现基线：v1.1-dev
> 返回：[当前架构概览](../当前架构概览.md)

## 模块职责

[Community](../../../internal/modules/core/community) 管理分组与板块、帖子、评论、标签以及社区业务事实；
[Moderation](../../../internal/modules/core/moderation) 管理审核与治理边界。
[RichText](../../../internal/modules/features/richtext) 管理图文内容及附件；
互助与二手由对应内置功能承载结构化详情，而不是任意插件直接扩展核心表。

分组是聚合层，板块是发帖与类型策略的具体归属；分组列表应汇集下属板块中当前访问者可见的帖子，
不能把分组 ID 当作单一叶子板块 ID 使用。

## 数据与关键流程

帖子公共字段由社区持有；互助、二手详情通过一对一业务关系补充类型专属字段。
二手金额使用最小货币单位的整数 price_minor，前端人民币小数输入须精确转换，不能用浮点误差代替金额规则。

发帖过程：认证与板块类型检查 → 清洗内容及校验类型详情 → 写入帖子和详情 → 按审核状态决定是否公开。
图文附件另外绑定 User Asset，不将 PDF、压缩包等嵌入正文排版。

作者的权限与审计以不可变的 `author_id` 为准；列表、详情和评论中的 `author_name` 是创建时写入的昵称展示快照。
用户名仅用于唯一识别、个人主页地址与管理检索，不能替代对外昵称。昵称修改不会改写既有内容的历史展示快照。

评论、回复、下架等事件的通知需要沿业务写入和持久事件链核验；通知消费者重复执行不得造成重复业务效果。
作者可管理自己允许操作的内容，审核人员按平台或板块作用域操作；下架不是继续公开可下载的状态。

## 主要接口

前缀 /api/v1，准确字段与 permission 见 [路由合同](../../api/HTTP路由与授权矩阵-v0.6.md)。

| 方法与路径 | 职责 |
| --- | --- |
| GET /categories/tree | 分组与板块树 |
| GET /categories/:id/thread-types | 板块允许的帖子类型 |
| GET /threads、/threads/:id | 可见帖子列表和详情 |
| POST /threads、PUT /threads/:id | 创建和修改帖子 |
| POST /threads/:id/submit-review | 提交审核 |
| GET、POST /threads/:id/posts | 评论列表与发表评论 |
| POST /mutual-aid/threads | 创建互助帖子 |
| POST /secondhand/threads | 创建二手帖子 |

## 依赖与安全边界

依赖 Identity 权限、Content Editor 内容清洗、可靠事务、用户存储和通知链。
[Content Editor](../../../internal/modules/core/contenteditor) 不负责直接写磁盘或装载插件。

文章阅读、正文图片和附件使用不同接口；不能由“图片有公开 URL”推导所有个人文件都应公开。
附件访问规则详见 [用户存储与附件预览](用户存储与附件预览.md)。

## 回归重点

覆盖分组跨板块聚合、不可见内容过滤、类型切换、金额边界、作者与审核员权限、评论回复通知，
以及文章下架后附件和已创建预览会话的重新鉴权。
