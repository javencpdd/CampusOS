# 身份认证与权限管理

> 更新时间：2026-09-23（Asia/Shanghai）
> 实现基线：v1.1-dev
> 返回：[当前架构概览](../当前架构概览.md)

## 职责与代码入口

[Identity](../../../internal/modules/core/identity) 拥有用户、邮箱身份、会话、角色权限、MFA 与管理员准入事实。
[HTTP Router](../../../internal/transport/httpapi/router.go) 将公开、已登录、管理员路由分组，服务层继续验证资源范围。

不要把“有账号”“具有管理员角色”“通过管理员准入”“允许当前操作”合并成一个布尔值。

## 关键流程

注册请求先创建 Challenge，经邮件验证换取 Ticket，再提交注册；账号创建与票据消费遵循服务端原子性要求。
验证码与身份事实由 Identity 管理，投递模块不自行生成身份凭据。

登录建立受会话验证约束的令牌；刷新、退出全部设备、撤销会话与 MFA 是独立流程。
管理员操作还需有效的管理员准入状态及对应 permission；敏感操作按路由和服务要求执行额外验证。

请求授权依次检查：认证身份 → 操作权限 → 目标对象所有权或作用域 → 对象当前状态。
普通成员、板块范围管理员和平台管理员不是可互换身份。

## 账号标识与对外显示

| 字段 | 作用 | 是否可修改 | 对外展示规则 |
| --- | --- | --- | --- |
| 邮箱 | 登录凭据与邮件验证标识 | 按受控身份流程处理 | 不在公开主页、帖子或评论中展示 |
| 用户名 `username` | 全局唯一、个人主页路径 `/u/:username`、后台检索 | 注册后不可修改 | 不是帖子、评论作者的默认显示名称 |
| 昵称 `nickname` | 面向用户的显示名称 | 用户可在个人资料中修改 | 新建普通帖子、图文文章、互助、二手与评论的 `author_name` 使用此值 |

认证中间件会提供用户 ID、用户名和昵称；受服务端 Session 校验的请求会在每次访问时用 Identity 当前昵称刷新展示上下文。
`author_id` 始终是所有权和权限判断依据，`author_name` 只是发帖时的展示快照。历史测试数据中已经保存的用户名不会被这次代码改动自动改写；需要统一历史展示时，应在可丢弃测试数据中重建或另行执行受控的数据修复。

## 主要接口

以下路径均以 /api/v1 为前缀，详细字段见 [路由合同](../../api/HTTP路由与授权矩阵-v0.6.md)。

| 方法与路径 | 语义 |
| --- | --- |
| POST /auth/registration/challenge | 发起注册验证 |
| POST /auth/registration/verify | 校验验证码 |
| POST /auth/register | 完成注册 |
| POST /auth/login、/auth/admin/login | 普通与管理员登录入口 |
| POST /auth/refresh | 刷新会话凭据 |
| GET /auth/me、/auth/sessions | 当前身份与会话 |
| POST /auth/logout-all | 撤销当前用户全部会话 |
| POST /auth/mfa/step-up | 敏感操作前的加强认证 |

## 数据与外部依赖

PostgreSQL 保存身份、角色、会话与安全状态；可靠邮件模块只接收受控投递任务。
配置密钥、SMTP 授权码属于部署秘密，不写入文档、Git 或面向用户的错误消息。

个人文件采用 owner-only；开放文章仅提供文章上下文的附件访问，不授予作者整个空间权限。
插件代用户访问还受独立的 [三层授权](插件平台与授权体系.md) 约束；普通用户不需要自己生成 API 密钥来完成授权。

## 验证与变更影响

修改身份流程需验证会话撤销、票据重复消费、MFA、管理员停用和越权请求。
改变 permission 时应同步路由合同、迁移及管理端能力展示，不能只改菜单。
身份与恢复实现见 [Identity 模块装配](../../../internal/modules/core/identity/module.go)；旧架构路径只保留导航，不再提供旧实施指令。
