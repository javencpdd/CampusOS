# 身份认证与权限管理

> 更新时间：2026-10-27（Asia/Shanghai）
> 实现基线：当前 v1.2 开发候选，非正式发布
> 返回：[当前架构概览](../当前架构概览.md)

## 职责与代码入口

[Identity](../../../internal/modules/core/identity) 拥有用户、邮箱身份、会话、角色权限、MFA 与管理员准入事实。
[HTTP Router](../../../internal/transport/httpapi/router.go) 将公开、已登录、管理员路由分组，服务层继续验证资源范围。

不要把“有账号”“具有管理员角色”“通过管理员准入”“允许当前操作”合并成一个布尔值。

## 关键流程

注册请求先创建 Challenge，经邮件验证换取 Ticket，再提交注册；账号创建与票据消费遵循服务端原子性要求。
验证码与身份事实由 Identity 管理，投递模块不自行生成身份凭据。

登录建立受会话验证约束的令牌；刷新、退出全部设备、撤销会话与 MFA 是独立流程。
管理端使用独立 `admin_accounts / admin_credentials / admin_sessions / admin_roles / admin_role_bindings`，不外键依赖 `users/accounts`；两域仍位于同一个 PostgreSQL 数据库，而非两个物理库。Token 的 issuer/audience/key id 与验证入口分域，用户角色不自动创建管理域账号。管理员操作还需当前 Admin 会话、有效角色/权限与敏感操作所需 MFA。

新库不播种固定超级用户。第一位安全管理员由显式 `AUTH_ADMIN_BOOTSTRAP_SECRET` 启用受控初始化，并要求请求头 `X-CampusOS-Bootstrap-Secret` 的精确部署证明；该配置默认关闭、不回退到旧用户域 `AUTH_BOOTSTRAP_ADMIN_SECRET`。已有有效安全管理员时拒绝重复初始化，事务内复核、必需审计和角色绑定仍由生命周期服务负责。操作说明见[独立管理员初始化](../../help/系统设计相关/v1.2独立管理员初始化与账号隔离.md)。

请求授权依次检查：认证身份 → 操作权限 → 目标对象所有权或作用域 → 对象当前状态。
普通成员、板块范围管理员和平台管理员不是可互换身份。

## 独立管理员 MFA 的部署策略

`AUTH_ADMIN_MFA_REQUIRED` 默认 true；部署者显式 false 才关闭二次验证要求，空值或非法值不降级。Identity 装配将该策略传入当前 Admin 会话事实和账号生命周期策略；HTTP 参数、请求头、浏览器缓存与插件返回值不能提供这个事实。

关闭要求时，Identity 只在 Go 内存中的当前 Admin 会话/主体事实附加 `AdminMFAOptional`（`json:"-"`）；不参与 JSON、JWT、数据库或 SDK 传输，冻结的 G1 合同、Schema、SDK DTO 和历史摘要均保持不变。JSON 解析不能恢复该标记，客户端提交同名字段会被严格解析器拒绝。实际认证强度仍为 `password` 或真实验证得到的 `mfa`；用户等其他主体不能使用该标记。执行授权会再次读取会话并比较该事实，伪造标记不能跳过默认 MFA。内容治理、个人空间/配额、资产、插件、Integration、Knowledge 和 AI 的管理路径使用同一要求，并继续检查当前角色、资源事实、事务与审计；用户授权中的显式 MFA 要求不会放宽。

`/admin/identity/me` 返回 `mfa_required`、当前绑定状态和验证到期时间，前端据此显示状态、首次绑定提示及分步引导。后台部署状态页不再调用旧用户域 MFA 策略。关闭不删除密钥、因子、会话或账号，也不使密码会话升级成 MFA。更换已有认证器的持有证明和独立离线恢复仍按原安全流程执行。

## 账号标识与对外显示

| 字段 | 作用 | 是否可修改 | 对外展示规则 |
| --- | --- | --- | --- |
| 邮箱 | 登录凭据与邮件验证标识 | 按受控身份流程处理 | 不在公开主页、帖子或评论中展示 |
| 用户名 `username` | 全局唯一、个人主页路径 `/u/:username`、后台检索 | 注册后不可修改 | 不是帖子、评论作者的默认显示名称 |
| 昵称 `nickname` | 面向用户的显示名称 | 用户可在个人资料中修改 | 新建普通帖子、图文文章、互助、二手与评论的 `author_name` 使用此值 |

认证中间件会提供用户 ID、用户名和昵称；受服务端 Session 校验的请求会在每次访问时用 Identity 当前昵称刷新展示上下文。
`author_id` 始终是所有权和权限判断依据，`author_name` 只是发帖时的展示快照。历史测试数据中已经保存的用户名不会被这次代码改动自动改写；需要统一历史展示时，应在可丢弃测试数据中重建或另行执行受控的数据修复。

## 主要接口

以下路径均以 /api/v1 为前缀，详细字段见 [路由合同](../../api/HTTP路由与授权矩阵-v0.6.md)。

| 方法与路径 | 语义 |
| --- | --- |
| POST /auth/registration/challenge | 发起注册验证 |
| POST /auth/registration/verify | 校验验证码 |
| POST /auth/register | 完成注册 |
| POST /auth/login | 用户域登录；旧 /auth/admin/login 不作为当前管理端入口 |
| POST /admin/identity/login、/admin/identity/refresh | 独立管理域登录与刷新 |
| POST /admin/identity/bootstrap | 仅显式启用且持有部署请求证明时初始化首位安全管理员 |
| POST /auth/refresh | 刷新会话凭据 |
| GET /auth/me、/auth/sessions | 当前身份与会话 |
| POST /auth/logout-all | 撤销当前用户全部会话 |
| POST /auth/mfa/step-up | 敏感操作前的加强认证 |

## 数据与外部依赖

PostgreSQL 保存身份、角色、会话与安全状态；可靠邮件模块只接收受控投递任务。
配置密钥、SMTP 授权码属于部署秘密，不写入文档、Git 或面向用户的错误消息。

个人文件采用 owner-only；开放文章仅提供文章上下文的附件访问，不授予作者整个空间权限。
插件代用户访问还受独立的 [三层授权](插件平台与授权体系.md) 约束；普通用户不需要自己生成 API 密钥来完成授权。

## 验证与变更影响

修改身份流程需验证会话撤销、票据重复消费、MFA、管理员停用和越权请求。
改变 permission 时应同步路由合同、迁移及管理端能力展示，不能只改菜单。
身份与恢复实现见 [Identity 模块装配](../../../internal/modules/core/identity/module.go)；旧架构路径只保留导航，不再提供旧实施指令。
