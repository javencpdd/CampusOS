## 1. 风险登记

| 风险 | 影响 | 现有控制 | 剩余证据或后续动作 |
| --- | --- | --- | --- |
| 账号邮箱冲突 | 错误合并账号或错误允许找回 | `000028` 先对账并中止，不自动选择所有者 | 在真实历史副本升级时保存预检输出 |
| 验证码/Token 泄露 | 账号接管 | HMAC Code、Ticket/Refresh 摘要、最小 Outbox payload、日志扫描 | Final 复跑 secret 负向检查 |
| 邮件重复或延迟 | 用户重复收到验证码或无法及时注册 | Outbox、receipt、过期 replay 跳过、at-least-once 文案 | SMTP 故障注入和受控 Provider 验收 |
| 消费者完成但事件无限重新领取 | attempts 越界、队列噪声，错误恢复可能重复外部副作用 | Complete/Retry/Dead 错误显式返回与脱敏日志、Consumer Receipt、Claim 上限、finalize Attempt、lease generation fencing | 部署后让历史耗尽事件收敛到 dead，经 Admin 审查后单条 Replay；不得删除 Receipt |
| 验证码策略误配或并发覆盖 | 邮件轰炸或正常用户无法请求 | 不可关闭的上下界、滑动窗口、版本冲突、required audit、管理员专用权限 | 恢复合理值并核对策略事件/命令审计；不直接清空计数 |
| 限流锁键与数据库文本协议不兼容 | 所有注册/绑定/找回 Challenge 在事务开始后回滚 | advisory lock tuple 先编码为固定 SHA-256 hex；单元测试拒绝 NUL，真实 PostgreSQL Repository 测试覆盖消费和限流 | Final 复跑注册、绑定、找回请求；基础设施失败只返回脱敏 503 与 request ID |
| Session 切换 | 用户强制重登或旧令牌误用 | `typ/session_id/auth_version` 校验、rotation、family revoke | 发布公告和真实浏览器回归 |
| Category 层级破坏 | 不能发帖或权限范围混乱 | 预检、版本、触发器、显式 board scope | 历史副本 migration drill |
| 结构化 Detail 半写 | Thread、Revision、Detail、Audit/Outbox 不一致 | TxKernel、Memory Snapshot、创建与编辑故障注入 | PostgreSQL 事务演练 |
| 回收 Thread 继续变化业务状态 | 删除后产生误导性交易/互助事件 | Feature 状态写入拒绝非 active Thread，且不写可靠证据 | 浏览器/API 负向流程 |
| 内部错误泄露 | 公开表名、查询或用户标识 | Feature Handler 只回显已分类错误，未知错误返回通用 500 与 trace | 统一错误中间件是后续横向治理项 |
| Feature 停用造成数据不可治理 | 历史内容无法审核、恢复或审计 | 专用 API 受 Gate 控制；Community Core 保留基础 Thread 和治理能力 | 停用/恢复后的 Community 流程 smoke |
| C3 migration 演练遗漏 | 二手 Detail 表/触发器无法安全部署 | `make v12-migration-check` 已被 `database-check` 和 `release-check` 调用，隔离 up/down/up 已通过 | Final 候选继续重跑并留存日志 |
| 列表 N+1 Detail 读取 | 数据量增长后延迟和数据库压力上升 | 当前按页上限限制、索引与正确性优先 | v0.13 前做批量查询/join 投影和容量测试 |
| 图文 HTML 或危险图片输入 | XSS、钓鱼式覆盖或恶意文件进入公开详情 | Community Core 白名单清洗；预览与保存同源；User Storage 校验 MIME、路径、随机文件名、请求体与配额 | Final 真实浏览器负向上传，并持续维护清洗器回归语料 |
| 孤立正文图片占用配额 | 上传后未发布造成空间长期占用 | 文件始终归当前用户并计入总配额，不因 Feature 停用删除 | 后续增加引用索引、保留期和有审计的延迟回收，不直接扫描删除 |
| 二级功能分组被当作生命周期依赖 | 关闭图文文章时误停互助/二手或误删数据 | `presentation_parent` 仅供 UI；Feature 状态、Thread Type、Detail 和状态机均独立 | Admin/Feature 回归持续验证父停用、子运行组合 |
| Operation Code 与数据库约束漂移 | 路由权限目录同步事务回滚，新增路由不进入授权目录 | Route Registry 启动前验证同一正则；历史非法 code 改为下划线并保留兼容 alias | 冷启动要求目录同步无警告，contracts-check 校验所有生成 code |
| 管理员角色与准入漂移 | 普通用户误入管理平面，或合法管理员被锁在 Admin 外 | 独立 `identity_admin_accounts`、用户/凭据外键、角色同步触发器、Admin 专用登录、每请求三重门禁和数据库审计 | Final 验证专用登录、暂停准入和最后管理员恢复；禁止直接改表绕过服务 |

## 2. 回滚原则

1. 生产问题优先兼容 forward-fix；不能以删除结构化 Detail 表作为日常回滚。
2. down migration 只用于隔离 up/down/up 演练。真实恢复使用同一时间点备份、维护窗口和恢复后核对。
3. 任何回退到不理解 `thread_type`、Category 层级或 v0.12 Session Claims 的旧二进制前，先关闭相应写入口并
   明确进入只读或认证维护状态。
4. Feature 停用不会清理 `mutual_aid_details`、`secondhand_details` 或基础 Thread；恢复专用
   入口必须通过 Feature Registry 的重启式启用流程。
5. Recovery、密码重置和 Session 事件出现异常时，优先撤销相关 session family 和重新认证，不能恢复旧 refresh
   明文或放宽 Access JWT 校验。
6. `000038` 回滚只删除独立准入投影和触发器，不会删除身份、凭据或 RBAC 数据；旧二进制回退前必须进入
   维护窗口，不能在缺少管理平面门禁时继续对公网开放 Admin API。

## 3. 事故处理顺序

1. 记录 trace ID、时间范围、运行版本、migration 状态和受影响资源 ID；不要把邮箱、验证码、Token 或密码写入工单。
2. 判断是可逆的 API/Feature 问题、数据库 schema 问题还是身份安全事件。
3. 对可逆代码问题发布 forward-fix；对安全事件撤销 Session、轮换相关 Secret，并保留 required audit。
4. 对数据问题从已验证备份恢复到隔离库，先运行 schema/data audit，再决定生产维护窗口。
5. 恢复后执行最小读写验证、`make database-check`、相关 Feature 检查和浏览器关键路径。
6. 更新进度证据和本登记，不将未验证的临时规避措施写成长期兼容行为。

## 4. 发布阻断项

在以下任一项未关闭时，v0.12 不能升级版本：

- C3 的 `000035`、A7.1 的 `000036`、A4.1 的 `000037` 与 A7.2 的 `000038` 隔离 PostgreSQL up/down/up。
- 全量 `make database-check` 与 `make restore-drill`。
- Final 候选的冷启动和受控浏览器 smoke。
- 包含 `make v12-migration-check` 的完整 `make release-check`。
