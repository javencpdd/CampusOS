# CampusOS Help 文档索引与生命周期

> 当前基线：`v0.13.0`
> 最近审查：2026-08-02
> 适用范围：`docs/help/` 的入口、权威性判断、历史文档保留和后续维护

`docs/help/` 保存面向开发者、管理员和运维人员的操作说明。这里既有当前指南，也保留了早期版本的
设计记录和故障复盘。文件存在不等于内容仍是当前操作标准；开始工作前应先按本页判断状态。

## 1. 文档状态怎么判断

| 状态 | 含义 | 使用方式 |
| --- | --- | --- |
| 当前指南 | 已按 `v0.13.0` 代码、迁移或门禁核验 | 可以作为当前操作入口 |
| 专项参考 | 只覆盖一个功能、兼容路径或具体故障 | 先读当前指南，再按场景查阅 |
| 历史快照 | 记录当时真实状态，但版本、表数量、命令或边界已变化 | 只用于理解演进和排查旧实例 |
| 已被替代 | 有更完整的新文档；旧文件只为历史链接保留 | 不再作为新开发的执行依据 |
| 规划参考 | 描述候选协议或未来能力，不代表已经实现 | 必须回到代码、合同和当前计划验证 |

当前事实的优先级是：

```text
可执行代码与 migration
  > 生成的 API/路由/数据库/资源合同与检查器
  > 最新进度验收证据
  > 当前架构和帮助文档
  > 已封版计划与历史设计稿
```

## 6. 本轮发现并补齐的缺口

| 原缺口 | 处理 |
| --- | --- |
| `docs/help` 没有总入口，版本前缀容易被误解为当前/过期 | 新增本页并定义生命周期和替代关系 |
| 没有统一说明 v1-v13 的迭代主线、哪些计划已失效 | 在 `docs/help/计划书总结/` 提供开发者入口，并由 `docs/计划书总结/` 保存详细治理证据 |
| 官方文档站没有版本演进和当前路线 | 新增版本演进、当前规划页面和导航 |
| 项目上手 Skill 仍停留在 v0.5，快照脚本只列 v0.5/v0.6 | 同步到 v0.13，并改为动态列出最新进度 |
| 数据库静态指南容易把旧表数量当成实时架构 | 增加历史警告，明确以 Admin 只读架构、migration 和检查器为准 |
| README、仓库文档门户和官方文档站的规划入口不统一 | 统一指向计划总结与当前路线 |
| 官方文档站看不到旧文档为何失效以及应读哪个替代文档 | 新增“文档状态与历史替代”公开页面 |
| v1-v13 只有一行摘要，无法追溯每版的关键取舍 | 新增逐版本迭代思路详解 |
| 新开发者面对数十份 Help 文档没有固定顺序 | 新增分阶段学习路线和每阶段完成标志 |
| CI 文档引用不存在的 `test.yml` 且与 PR 文档重复 | 合并到当前开发指南并以真实 `ci_test.yml` 为准 |
| 没有完整记录哪些文档可删、应留或后续拆分 | 新增逐类审计与删除标准 |

当前已具备完整入门路径、本机和 Docker 开发、模块边界、权限配置、API、课表插件示例、发布和恢复指南，
没有阻断普通贡献者上手的 P0 文档缺口。版本化公开文档/release notes、真实 Windows 与 arm64 认证、
生产 TLS/供应链和标准 MCP/gRPC/Agent 教程仍待相应实现或运行证据形成后补充；不能提前写成已交付能力。

## 7. 维护规则

1. 新文档先选择唯一权威位置；不要同时在 README、Help 和 docs-site 复制完整正文。
2. 版本封板后，操作指南可以继续维护；进度证据和历史计划不回写成当前事实。
3. 被替代文档默认保留状态说明；只有内容已完整迁入、没有历史证据引用且链接已更新时才删除。
4. 表数量、路由数量、版本、checksum 和权限矩阵优先由代码生成，不在教程中长期硬编码。
5. 文档变更至少运行 `make readme-check`、`make docs-links`、docs-site build 和 `git diff --check`。
