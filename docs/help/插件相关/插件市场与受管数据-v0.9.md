# 插件市场、受管数据与签名（v0.9）

## 目录职责

| 目录 | 内容 |
| --- | --- |
| `data/plugins/<id>/` | 外部插件实现、Manifest、运行时文件和 README。 |
| `data/plugin_data/<id>/` | 插件私有 KV、快照、运行日志等系统管理数据。 |
| `data/personal-space/<user>/plugins/<id>/` | 用户明确授权后由插件保存的个人文件。 |
| `data/resources/` | 主题、样式包、Skills、Prompt、Persona 等资源包，不运行后端业务。 |

不要将用户文件、风格包或用户记录写入 `data/plugins`。插件升级会替换实现目录，受管数据不随安装包覆盖。

## 插件发布流程

1. 编写 `plugin.yaml`，声明 Runtime、Host API 权限、用户权限、集合和文件限额。
2. 在插件目录运行 `campusosctl plugin dev`，通过测试、构建和 Manifest 校验。
3. 可选地用离线 Ed25519 私钥签名，再打包。
4. 管理端导入包时先查看权限、文件清单、版本变化、签名状态和风险提示。
5. 管理员将符合 v2 合同的已安装外部插件发布到目录；用户端只能请求、授权和撤销，不能安装任意二进制包。

导入成功后，v2 External Plugin 会立即同步到本地 Catalog，并生成基于实际摘要与验签结果的发布记录，不需要重启 API。目录默认是草稿，只有管理员发布后用户才可新建授权。

```bash
go run ./cmd/campusosctl plugin sign <plugin-dir> --key-id <key-id> --key-file /secure/private-key.txt
go run ./cmd/campusosctl plugin pack <plugin-dir>
```

私钥只应保存在离线或受控密钥系统中。签名公钥配置在 `data/config/plugin-trust-keys.json`：

```json
{
  "keys": [
    { "id": "organization-key", "algorithm": "ed25519", "public_key": "BASE64_PUBLIC_KEY" }
  ]
}
```

如果 Manifest 设置 `release.signature_required: true`，只有受本实例信任且验签通过的包可以导入。未签名或未受信任的包不会伪装成“已验证”。

## 数据与授权

`permissions.api` 是管理员安装时审核的宿主权限；`permissions.user` 是用户在插件中心决定是否给出的个人数据授权。两者互不替代。

用户可以：查看声明用途和风险、授权部分能力、查看记录/文件占用、撤销授权、导出本插件数据、删除本插件个人记录和文件。搜索使用单独的 `plugin_search:read` 同意，不会因为授予 `managed_data:read` 自动开启。执行“删除数据”后会同步撤销授权；单独撤销不会删除已有数据。插件下架或代码卸载后，已有 Grant 仍只用于用户导出或删除自己的保留数据，不能继续业务读写。

用户可以填写未安装插件的稳定 ID 提交推荐/安装申请。申请只进入管理员审计队列，批准动作不会自动下载或执行代码。

管理端插件中心同时显示 Runtime 健康、系统权限数量、记录/文件占用、发布记录和近期市场治理审计。

参见 [Host API v2 受管数据合同](../../api/Host-API-v2受管数据合同.md)。
