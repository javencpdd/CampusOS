# CampusOS 模块、插件与资源生命周期说明

CampusOS 是模块化单体。管理界面可以把多类扩展放在同一个“扩展总览”中，
但它们的代码位置、生命周期、权限和数据所有权并不相同。

## 1. 四类能力

| 类型 | 描述符与实现 | 生命周期 | 数据位置 |
| --- | --- | --- | --- |
| Core Module | `modules/core/*/module.yaml`、`internal/modules/core/*` | `always-on`，不可停用、安装或卸载 | PostgreSQL 或明确的 Core 存储 |
| Built-in Feature | `modules/features/*/module.yaml`、`internal/modules/features/*` | `restart` 或 `hot-gated`，可启停但不可卸载 | PostgreSQL、`data/module_data`、User Storage |
| External Plugin | `data/plugins/*/plugin.yaml`、Wasm 或受管进程 | `plugin-restart` 或 `hot`，可安装、升级、停用和卸载 | `data/plugin_data`、插件表、授权后的 User Storage |
| Resource Package | `data/resources/*/*/resource.json` | 校验、导入、应用、导出；没有业务 Runtime | `data/resources` |

`runtime: builtin` 只为旧 Manifest 审查和迁移保留解析能力。Plugin Manager、
CLI 和包导入不会安装它；内置能力必须随 CampusOS 编译。

## 2. Built-in Feature 启停

Feature API 使用独立入口：

```text
GET  /api/v1/features
GET  /api/v1/features/:id
PUT  /api/v1/features/:id/config
POST /api/v1/features/:id/enable
POST /api/v1/features/:id/disable
```

| 模式 | 行为 |
| --- | --- |
| `always-on` | Core Module 使用。停用请求被拒绝；只允许在明确边界内调整策略配置。 |
| `restart` | 保存目标状态并标记待重启；API 进程重启后生效。 |
| `hot-gated` | 路由保持静态注册，由统一 Gate 立即隐藏 UI、拒绝 API 或停止事件处理。 |

停用 Built-in Feature 不会删除数据库记录、`data/module_data` 或用户文件。
系统不会在运行时动态增删 Gin 路由。

## 3. External Plugin 生命周期

External Plugin Manifest 可以声明：

```yaml
scope: user
lifecycle:
  backend:
    activation_mode: plugin-restart
  frontend:
    activation_mode: hot
```

`scope` 表示管理级别，不表示普通用户可以安装插件。导入、配置、生命周期、
发布和卸载仍需要对应的管理员 Permission Code。

| Runtime | 后端默认模式 | 说明 |
| --- | --- | --- |
| `wasm` | `hot` | 新实例验证后切换，候选失败时保留旧实例。 |
| `grpc` | `plugin-restart` | 历史兼容名称；当前为 CampusOS 管理的独立进程和 loopback HTTP Extension 合同，不是 protobuf gRPC。 |

外部插件状态分为 BackendState、FrontendState 和 Health。前端贡献通过 Runtime
Manifest 与 SSE revision 热注册或清理；插件停用不会自动删除
`data/plugin_data/<plugin>` 或用户授权数据。

## 4. 管理入口

| 入口 | 管理对象 |
| --- | --- |
| Admin `/features` | Core/Built-in Feature 状态、模式和配置 |
| Admin `/appearance` | Theme、Homepage、Space Style Resource Package |
| Admin `/plugins` | 已安装 External Plugin 的导入、配置、启停、更新、日志和导出 |
| Admin `/plugin-center` | External Plugin Catalog、发布、安装请求和市场审计 |
| Admin `/extensions` | 四类能力的只读聚合与跳转，不合并生命周期 |

Web Runtime Manifest 分开返回 `modules[]` 和 `plugins[]`。个人课表、个人空间和
Appearance 来自 `modules[]`，不会因为 `/plugins` 只列外部插件而消失。

## 5. 安全边界

- External Plugin 不能导入 CampusOS `internal/*`、获取 `AppContext`、直连数据库或取得 JWT/用户 Token。
- 插件只能使用声明并获准的 Host API、Extension Gateway、公开 HTTP 或 MCP 合同。
- Resource Package 不能注册进程、业务路由、migration 或后台任务。
- Feature/Plugin 停用以及 Resource Package 切换都不得隐式删除用户数据。
- 外部插件名称不能占用模块 ID、Feature ID 或历史 Built-in 兼容别名。
