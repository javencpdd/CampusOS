# 插件分级与生命周期说明

CampusOS 将“谁能管理插件”和“插件怎样生效”分开表达。

```yaml
scope: system # 或 user，只表示管理级别
lifecycle:
  backend:
    activation_mode: restart # restart | plugin-restart | hot
  frontend:
    activation_mode: hot
```

## 1. 默认兼容规则

旧 `plugin.yaml` 不需要立即改动：

| Runtime / 范围 | 后端默认 | 前端默认 |
| --- | --- | --- |
| `builtin + system` | `restart` | `hot` |
| `grpc`，不论 scope | `plugin-restart` | `hot` |
| `wasm`，不论 scope | `hot` | `hot` |
| 其他受支持 builtin | `hot` | `hot` |

`scope: system` 代表随服务部署、不能从 Admin 卸载等管理约束；它不再强制所有插件整站重启。`scope: user` 也不代表普通用户能安装插件，安装、配置和生命周期操作仍由 Admin 权限控制。

## 2. 状态

| 维度 | 值 |
| --- | --- |
| BackendState | `installed`、`starting`、`running`、`restarting`、`stopping`、`stopped`、`pending_restart`、`error` |
| FrontendState | `unloaded`、`loading`、`loaded`、`incompatible`、`error` |
| Health | `healthy`、`degraded`、`unavailable`、`unknown` |

旧 `status`、`activation_mode`、`desired_enabled` 和 `pending_restart` 继续返回。新客户端应优先显示三轴状态。后端 restarting 或 degraded 时，已加载前端保持注册并显示统一健康提示；管理员明确停用或卸载后才热卸载前端。

## 3. 管理操作

| activation mode | 启用/停用 | 更新 |
| --- | --- | --- |
| `restart` | 保存目标状态，BackendState 变为 `pending_restart`，重启 API 后应用 | 随 Core 部署；前端 manifest 仍可热同步 |
| `plugin-restart` | 只启动或停止插件进程，不重启 Core | 先验证新插件进程，再切换；失败保留旧版本或使用快照回滚 |
| `hot` | 当前进程内立即生效 | Wasm 新实例验证后原子交换；候选失败时旧实例继续运行 |

Admin 的“重载”按钮由 activation mode 决定，不再由 scope 决定。系统级 gRPC 可以重载，restart 插件不能重载。系统级插件仍不能从网页卸载。

## 4. 前端热加载

所有插件 UI 使用 `lifecycle.frontend.activation_mode: hot`。Core 通过 Runtime Manifest 和 SSE revision 通知 Web 注册或清理 Route、Navigation、Slot、Surface、Action 和主题 override 缓存。业务数据、插件配置、日志和 `data/plugin_data/<plugin>/` 不会因前端卸载而删除。

完整开发方式见 [插件前端运行时与 Extension Gateway](插件前端运行时与Extension%20Gateway.md)。
