# CampusOS 个人主页风格包说明

> 适用阶段：v0.6-dev
> 更新时间：2026-07-11
> 文档状态：旧 Personal Space 风格 API 与兼容包参考。新包必须同时遵守
> [app-style-pack.v2](../系统设计相关/app-style-pack-v2开发说明.md) 和
> [v13 双端交付标准](../系统设计相关/v13风格包双端交付标准.md)。

## 1. 功能定位

个人主页风格包用于在不同用户之间分享、导入和迁移个人主页外观。当前阶段已完成 JSON 风格包 manifest、文件夹/zip 页面拓展风格包、安全校验、导入预览、导出当前风格、一键应用到个人主页，以及受限 HTML/CSS 风格片段检测与应用。

当前支持：

| 能力 | 状态 |
| --- | --- |
| 风格包 manifest JSON 格式 | 已支持 |
| 安全校验 | 已支持 |
| 登录用户校验 API | 已支持 |
| 风格包导入预览 | 已支持 |
| 当前主页风格导出 | 已支持 |
| 风格包一键应用 | 已支持 |
| 用户侧前端入口 | 已支持 |
| 应用前快照和回滚 | 已支持 |
| 受限 HTML/CSS 风格片段 | 已支持 |
| 文件夹/zip 页面拓展风格包 | 已支持，标准为 `page-style-pack.v1` |
| 整页稳定 CSS 作用域 | 已支持，根选择器为 `.public-space[data-campusos-space]` |
| 沙箱 JS/TS 特效 | 已支持；TS 需编译为 JS，运行时为 `sandbox-worker.v1` |
| CampusStyleSDK | 已支持只读白名单能力，主页数据固定到主页所有者 |

风格包可以修改个人主页内部的全部内容，包括资料头部、头像、元信息、自定义模板、帖子列表、标签、空状态、字体、背景和页面间距。它不能修改 CampusOS 顶部导航、其他页面或 Admin。

访问 `/u/:username` 时，后端使用 URL 中用户名对应的主页所有者配置。用户 A 的风格由 A 保存，所有访问 A 主页的人看到同一套 A 风格；访问 B 主页时不会带入 A 风格。

完整权限和沙箱规则见 [风格包能力边界与 CampusStyleSDK 说明](../系统设计相关/风格包能力边界与CampusStyleSDK说明.md)。

## 2. 校验 API

接口：

```text
POST /api/v1/spaces/me/styles/validate
```

该接口需要登录：

```bash
curl -X POST http://localhost:8080/api/v1/spaces/me/styles/validate \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "manifest": {
      "schema_version": "space-style.v1",
      "name": "clean-blog",
      "version": "0.1.0",
      "author": "Alice",
      "description": "Clean blog style for CampusOS personal spaces.",
      "preview_image": "assets/preview.png",
      "compatible_campusos": [">=0.4.0"],
      "layout": "blog",
      "components": [
        {
          "slot": "header",
          "type": "profile-header",
          "props": {
            "show_avatar": true,
            "title_size": "lg"
          }
        },
        {
          "slot": "main",
          "type": "content-list",
          "props": {
            "density": "comfortable"
          }
        }
      ],
      "tokens": {
        "color.primary": "#2563eb",
        "font.body": "system-ui",
        "radius.card": "8px",
        "space.section": "24px"
      },
      "assets": [
        {
          "name": "preview",
          "path": "assets/preview.png",
          "type": "image/png"
        }
      ]
    }
  }'
```

返回示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "valid": true
  }
}
```

如果校验失败，接口仍返回统一成功响应，但 `data.valid=false`，并列出错误：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "valid": false,
    "errors": [
      "manifest.components[0].type \"script\" is not supported"
    ]
  }
}
```

## 3. 导入预览 API

接口：

```text
POST /api/v1/spaces/me/styles/preview
```

该接口需要登录，请求体与校验 API 一致。接口会返回：

| 字段 | 说明 |
| --- | --- |
| `validation` | 校验结果 |
| `owner` | 当前登录用户的公开展示信息 |
| `space` | 当前用户的个人主页配置 |
| `manifest` | 校验通过后的规范化 manifest |
| `layout` | 预览布局 |
| `components` | 可渲染组件列表 |
| `tokens` | 可渲染样式 token |
| `assets` | 包内资源声明 |

如果 `validation.valid=false`，接口不会返回 `manifest`、`layout`、`components`、`tokens` 和 `assets`，前端应只展示错误信息，不能渲染风格包。

示例：

```bash
curl -X POST http://localhost:8080/api/v1/spaces/me/styles/preview \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d @style-package.json
```

返回示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "validation": {
      "valid": true
    },
    "owner": {
      "id": "1001",
      "username": "alice",
      "nickname": "Alice"
    },
    "space": {
      "user_id": "1001",
      "title": "Alice的个人主页",
      "layout": "blog",
      "theme": "default"
    },
    "layout": "blog",
    "components": [
      {
        "slot": "header",
        "type": "profile-header"
      }
    ],
    "tokens": {
      "color.primary": "#2563eb"
    }
  }
}
```

## 4. 风格导出 API

接口：

```text
POST /api/v1/spaces/me/styles/export
```

该接口需要登录。接口会读取当前登录用户的个人主页配置，将 `layout`、`theme` 和受控组件组合导出为标准风格包 JSON。

请求体可以为空对象：

```bash
curl -X POST http://localhost:8080/api/v1/spaces/me/styles/export \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{}'
```

也可以指定导出名称、版本和描述：

```bash
curl -X POST http://localhost:8080/api/v1/spaces/me/styles/export \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "alice clean blog",
    "version": "0.2.0",
    "description": "Alice 的个人主页风格"
  }'
```

返回示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "filename": "alice-clean-blog-0.2.0.space-style.json",
    "validation": {
      "valid": true
    },
    "package": {
      "manifest": {
        "schema_version": "space-style.v1",
        "name": "alice-clean-blog",
        "version": "0.2.0",
        "author": "Alice",
        "description": "Alice 的个人主页风格",
        "compatible_campusos": [">=0.4.0"],
        "layout": "blog",
        "components": [
          {
            "slot": "header",
            "type": "profile-header",
            "props": {
              "align": "center",
              "show_avatar": true,
              "show_cover": false
            }
          },
          {
            "slot": "main",
            "type": "content-list",
            "props": {
              "density": "comfortable",
              "show_excerpt": true,
              "show_meta": true
            }
          }
        ],
        "tokens": {
          "color.primary": "#2563eb",
          "color.background": "#ffffff",
          "color.surface": "#f8fafc",
          "font.body": "system-ui",
          "radius.card": "8px",
          "space.section": "24px"
        }
      }
    }
  }
}
```

导出规则：

| 项目 | 规则 |
| --- | --- |
| `name` | 未传时由用户名生成；传入值会转为小写短横线格式 |
| `version` | 未传时为 `0.1.0`；传入值必须是语义版本 |
| `layout` | 使用当前主页布局；不支持的布局回退为 `blog` |
| `theme` | 转换为受控 token，目前支持 `default`、`ink`、`dark`、`warm` |
| 个人内容 | 不导出帖子、标题正文、同步内容或运行数据 |
| 资源文件 | 当前导出只生成 manifest JSON，不打包图片资源 |

## 5. 风格应用 API

接口：

```text
POST /api/v1/spaces/me/styles/apply
```

该接口需要登录，请求体与校验 API 一致。接口会先执行完整安全校验，只有 `validation.valid=true` 时才会写入当前用户的个人主页配置。

示例：

```bash
curl -X POST http://localhost:8080/api/v1/spaces/me/styles/apply \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d @style-package.json
```

应用成功后会更新：

| 字段 | 写入内容 |
| --- | --- |
| `theme` | 风格包 `manifest.name` |
| `layout` | 风格包 `manifest.layout` |
| `style_name` | 风格包名称 |
| `style_version` | 风格包版本 |
| `style_manifest` | 规范化后的完整 manifest |

如果风格包非法，接口返回 400，且不会写入 `user_spaces`。

返回示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "validation": {
      "valid": true
    },
    "space": {
      "theme": "clean-blog",
      "layout": "blog",
      "style_name": "clean-blog",
      "style_version": "0.1.0"
    },
    "applied": {
      "schema_version": "space-style.v1",
      "name": "clean-blog",
      "version": "0.1.0",
      "layout": "blog"
    }
  }
}
```

## 6. HTML 风格片段 API

风格包 manifest 可包含：

| 字段 | 说明 |
| --- | --- |
| `custom_html_enabled` | 是否在公开个人主页渲染 `custom_html` |
| `custom_html` | 检测通过后渲染到公开个人主页的受限 HTML 片段 |
| `custom_css` | 检测通过后与 `custom_html` 一起注入的受限 CSS |

用户侧设置页提供独立 HTML 编辑器，可先检测、生成基于当前风格的示例，再应用到当前风格 manifest。

检测 HTML：

```text
POST /api/v1/spaces/me/styles/html/validate
```

请求：

```json
{
  "html": "<section><h2>Alice Space</h2></section>"
}
```

生成当前风格示例：

```text
GET /api/v1/spaces/me/styles/html-example
```

返回内容包括生成后的 `html`、可直接导入/应用的 `package` 和 `validation`。

应用 HTML：

```text
POST /api/v1/spaces/me/styles/html/apply
```

应用接口会复用风格包完整校验、应用前快照和持久化流程。只有检测通过的 HTML 才会写入 `user_spaces.style_manifest`；若检测失败，接口返回 400，不会覆盖当前风格。

## 7. 页面拓展风格包

`page-style-pack.v1` 是面向个人主页和首页插件的文件夹/zip 风格包标准。它比旧的 `space-style.v1` JSON manifest 更适合直接在源代码中维护模板和 CSS，也适合从前端上传 zip 后应用。

当前个人主页资源包统一保存在 `data/resources/space-style-packs/<pack>/`，每个受管包还包含 `resource.json`。内置 JSON 风格状态位于 `data/module_data/personal-space/styles/`；`data/plugin_data` 只保存 External Plugin 私有运行数据。

标准目录：

```text
style.yaml
README.md
preview.png
templates/page.html
templates/card.html
assets/cover.webp
assets/avatar-frame.png
styles/theme.css
config.schema.json
```

`style.yaml` 示例：

```yaml
schema_version: page-style-pack.v1
target: personal-space
name: clean-blog
version: 0.1.0
display_name: Clean Blog
author: CampusOS
entry: templates/page.html
templates:
  - name: page
    path: templates/page.html
  - name: card
    path: templates/card.html
styles:
  - styles/theme.css
preview_image: preview.png
config_schema: config.schema.json
tokens:
  color.primary: "#2563eb"
  color.background: "#ffffff"
  color.surface: "#f8fafc"
assets:
  - name: cover
    path: assets/cover.webp
    type: image/webp
  - name: avatar-frame
    path: assets/avatar-frame.png
    type: image/png
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema_version` | 是 | 固定为 `page-style-pack.v1` |
| `target` | 是 | `personal-space` 或 `homepage` |
| `name` | 是 | 小写字母、数字和中划线 |
| `version` | 是 | 语义版本，例如 `0.1.0` |
| `entry` | 是 | HTML 入口文件，必须是包内相对路径 |
| `templates` | 否 | 可复用 HTML 模板列表；当前会对所有 `.html` 文件统一筛查 |
| `styles` | 否 | CSS 文件列表，必须是包内相对路径 |
| `preview_image` | 否 | 包内预览图，推荐使用根目录 `preview.png` |
| `config_schema` | 否 | 推荐指向根目录 `config.schema.json`，用于声明风格包可配置项 |
| `tokens` | 否 | 可被编译到旧风格 manifest 的颜色或布局 token |
| `assets` | 否 | 当前只允许声明 png/jpg/jpeg/webp |

个人主页相关接口：

```text
POST /api/v1/spaces/me/styles/packs/validate
GET  /api/v1/spaces/me/styles/packs/example
GET  /api/v1/spaces/me/styles/packs/example.zip
POST /api/v1/spaces/me/styles/packs/apply
POST /api/v1/spaces/me/styles/packs/apply-source
```

使用方式：

| 方式 | 说明 |
| --- | --- |
| zip 上传 | 在用户侧 `/space/settings` 选择 zip，先筛查，通过后再应用 |
| 源码目录 | 将目录放到 `data/resources/space-style-packs/<name>/`，通过 `apply-source` 应用 |
| 示例生成 | `example.zip` 会根据当前正在应用的风格生成可导入 zip 示例包 |

筛查规则：

| 项目 | 规则 |
| --- | --- |
| 路径 | 只允许安全相对路径，拒绝绝对路径和路径穿越 |
| 文件 | 最多 80 个文件，zip 总大小最多 1MB，单文件最多 256KB |
| 扩展名 | 允许 `yaml`、`yml`、`md`、`html`、`css`、`png`、`jpg`、`jpeg`、`webp`，以及根目录 `config.schema.json` |
| HTML | 复用 `internal/safehtml`，对每个 `.html` 文件筛查，拒绝脚本、事件处理器、不安全 URL 和过复杂片段 |
| CSS | 对每个 `.css` 文件筛查，拒绝 `@import`、`url(`、`expression(`、`javascript:`、`data:`、固定/粘性定位等高风险内容 |
| 配置 Schema | `config_schema` 必须指向 `config.schema.json`，文件必须是可解析 JSON，`type` 如声明则必须为 `object` |

## 9. Manifest 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema_version` | 是 | 当前固定为 `space-style.v1` |
| `name` | 是 | 小写字母、数字和中划线，最长 63 字符 |
| `version` | 是 | 语义版本，例如 `0.1.0` |
| `author` | 否 | 作者 |
| `description` | 否 | 描述 |
| `preview_image` | 否 | 包内相对路径，支持 png/jpg/jpeg/webp |
| `compatible_campusos` | 否 | 兼容版本声明 |
| `layout` | 是 | 支持 `blog`、`grid`、`timeline`、`magazine` |
| `components` | 是 | 受控组件列表，最多 30 个 |
| `tokens` | 否 | CSS 变量式 token，最多 80 个 |
| `assets` | 否 | 包内资源声明，最多 20 个 |
| `custom_html_enabled` | 否 | 是否启用受限 HTML 片段渲染 |
| `custom_html` | 否 | 受限 HTML 片段，启用前必须通过安全校验 |
| `custom_css` | 否 | 受限 CSS 片段，启用前必须通过安全校验 |
| `source_style_pack` | 否 | 由 `page-style-pack.v1` 编译应用时记录来源包 |

## 11. 安全规则

当前阶段不允许任意 JavaScript、未审查 HTML 或未受控外链资源进入风格包。`custom_html` 只开放受限 HTML 子集，且必须在后端检测通过后才会应用和渲染。

校验会拒绝：

| 风险 | 规则 |
| --- | --- |
| 脚本组件 | `type=script`、`iframe`、未在白名单内的组件会被拒绝 |
| 事件处理 props | `onload`、`onclick` 等 `on*` 字段会被拒绝 |
| HTML 注入 | 包含 `html`、`script` 语义的 props 会被拒绝 |
| 危险字符串 | `<script`、`javascript:`、`data:text/html`、`<iframe` 等会被拒绝 |
| 外链资源 | `http://`、`https://`、`//` 资源路径会被拒绝 |
| 路径穿越 | `../`、绝对路径、空路径会被拒绝 |
| CSS 注入 | token 值中的 `url(`、`expression(`、`javascript:` 会被拒绝 |
| SVG | 当前阶段不允许 SVG 资源，避免脚本嵌入风险 |
| HTML 脚本 | `<script>`、事件处理器属性、`srcdoc` 会被拒绝 |
| HTML URL | `javascript:`、`vbscript:`、`data:`、`file:`、`blob:` 和协议相对 URL 会被拒绝 |
| HTML/CSS | `url(`、`expression(`、`@import`、`position:fixed`、`position:sticky` 等危险 CSS 会被拒绝 |
| HTML 复杂度 | 超过长度、节点数或嵌套深度限制的片段会被拒绝 |
