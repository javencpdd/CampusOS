# CampusOS 模块、插件与资源保存位置及作用汇总

> 当前基线：v0.10，最后核验：2026-07-16。

本文回答三个问题：代码放在哪里、数据放在哪里、应该到哪个管理页面操作。
这里的“插件”只指可以独立安装的 External Plugin。

## 1. 一眼区分四类能力

| 类型 | 代码/描述符 | 数据 | 管理入口 |
| --- | --- | --- | --- |
| Core Module | `modules/core/<id>/module.yaml`、`internal/modules/core/` | PostgreSQL 或 Core 明确拥有的存储 | Admin `/features` 只读状态或策略配置 |
| Built-in Feature | `modules/features/<id>/module.yaml`、`internal/modules/features/` | PostgreSQL、`data/module_data/`、User Storage | Admin `/features` |
| External Plugin | `data/plugins/<id>/plugin.yaml`、Wasm/受管进程代码 | `data/plugin_data/<id>/`、插件表、授权后的用户附件 | Admin `/plugins`、`/plugin-center` |
| Resource Package | `data/resources/<type>/<id>/resource.json` 与主题/模板/图片/CSS | 同一资源目录；用户偏好由所属 Feature 保存 | Admin `/appearance` 或对应用户设置页 |

`modules/` 不是插件安装目录，`data/plugins/` 也不允许放 Personal Space、Schedule、
RichText、Appearance 或 Moderation 的编译期实现。

## 2. External Plugin 保存在哪里

默认扫描目录是 `data/plugins`，可以用 `PLUGINS_DIR` 覆盖。每个一级子目录必须
包含合法 `plugin.yaml`：

```text
data/plugins/<plugin-id>/
├── plugin.yaml
├── README.md
├── plugin.wasm                 # Wasm，可选
└── executable/source files     # 受管进程，可选
```

运行数据与代码分开：

```text
data/plugin_data/<plugin-id>/
```

该目录保存 SQLite KV、缓存、版本快照和可恢复运行状态。标准插件包不会自动
包含这些数据；备份、恢复和迁移需要同时处理代码包与运行数据。

当前外部插件示例：

| 目录 | 作用 |
| --- | --- |
| `data/plugins/hello-wasm` | 最小 Wasm 事件插件，含 README 与可运行模块。 |
| `data/plugins/hello-plugin` | 受管进程 Manifest 示例；完善运行端前应以 `examples/plugins` 为主。 |
| `examples/plugins/grpc-example` | 最小受管进程插件。`grpc` 是历史兼容名称，不是 protobuf gRPC。 |
| `examples/plugins/campus-welcome` | 可运行的 UI Surface 与 Extension Gateway 示例。 |
| `examples/plugins/v2-managed-example` | Manifest v2、用户 Grant、受管记录和文件示例。 |
| `examples/plugins/schedule-helper` | 以课表场景讲解可移植插件；不读取内置课表内部 Service。 |

Admin `/plugins` 负责预检、导入、配置、启停、重载、日志、导出和卸载；
`/plugin-center` 负责 Catalog、发布、安装请求、版本和市场审计。

## 3. 编译期模块保存在哪里

模块描述符使用 `campusos.module/v1`：

```text
modules/
├── core/<module>/module.yaml
└── features/<feature>/module.yaml
```

Go 实现统一放在：

```text
internal/modules/core/
internal/modules/features/
```

### Core Module

| 模块 | 作用 |
| --- | --- |
| `core.identity` | 用户、认证、角色、权限目录、作用域和授权审计。 |
| `core.community` | 版块、标签、帖子、回复、内容状态和 `ContentQuery`。 |
| `core.user-storage` | 用户目录、安全路径、配额和资产 Provider。 |
| `core.moderation` | 版主板块作用域、授权策略、治理审计和完整性检查。 |
| `core.plugin-platform` | External Plugin 的宿主安全边界。 |

Core 使用 `always-on`，不能停用或卸载。Moderation 的 `allow_pin`、
`allow_lock`、`allow_delete_post` 只能缩小版主动作范围，不能关闭作用域检查和
审计。

### Built-in Feature

| Feature | 生效方式 | 作用 |
| --- | --- | --- |
| `personal-space` | `restart` | 个人主页、头像、主页设置和公开页面装配。 |
| `controlled-richtext-article` | `restart` | 富文本草稿、编辑、清洗、图片、发布和预览。 |
| `personal-schedule` | `restart` | 学期课表、第一周、周视图、日历和表格导入。 |
| `appearance` | `hot-gated` | 首页、系统主题、个人主页风格与资源包统一 Facade。 |
| AI/Webhook/MCP-like/Message/Platform Log 等 | 以各自描述符为准 | 可配置集成和运维能力。 |

Built-in Feature 可启停但不能普通安装或卸载。停用只隐藏 UI、拒绝 API 或停止
事件处理，不删除数据库行、模块数据或用户文件。

Admin `/features` 使用独立 Feature API：

```text
GET  /api/v1/features
PUT  /api/v1/features/:id/config
POST /api/v1/features/:id/enable
POST /api/v1/features/:id/disable
```

历史 `/plugins/<builtin-alias>` 单项接口在兼容期内投影到 Feature Handler，
但 `/plugins` 列表只返回 External Plugin。

## 4. 模块数据和用户文件

Built-in Feature 的本地可变数据放在：

```text
data/module_data/<feature>/
```

当前个人主页内置 JSON 风格位于：

```text
data/module_data/personal-space/styles/
```

所有用户拥有的文件由 User Storage Core 管理：

```text
data/personal-space/<user-id>/
├── img/avatars/               头像源文件，默认保留最近 3 个
├── img/richtext/              富文本图片
├── file/schedule/             学期课表索引和 JSON
├── plugins/<plugin-id>/       获用户授权的插件附件
├── excel/
├── word/
└── pdf/
```

默认配额为 10 MB，可在 Personal Space Feature 配置中调整；SafePath、所有权和
配额由 User Storage Core 强制执行。Schedule 和 RichText 只依赖 User Storage，
不会因为 Personal Space 页面功能停用而丢失数据。

## 5. Resource Package 保存在哪里

主题和风格包统一放在：

```text
data/resources/themes/<id>/
data/resources/homepage-packs/<id>/
data/resources/space-style-packs/<id>/
data/resources/skills/<id>/
data/resources/prompts/<id>/
data/resources/personas/<id>/
data/resources/knowledge-metadata/<id>/
```

每个受管包必须有 `resource.json`，声明 ID、类型、版本、入口、兼容范围、来源和
checksum。它可以包含模板、图片、CSS、配置 schema 和受限沙箱特效，但不能
包含 `plugin.yaml`、migration、服务端进程或数据库访问。

```bash
go run ./cmd/campusosctl resource adopt data/resources/themes/my-theme --type theme
go run ./cmd/campusosctl resource inspect data/resources/themes/my-theme
```

当前示例：

| 类型 | 示例 |
| --- | --- |
| 首页包 | `data/resources/homepage-packs/campus-hero` |
| 个人主页包 | `data/resources/space-style-packs/clean-blog`、`kinetic-journal` |
| 系统主题 | `data/resources/themes/campus-canvas`、`aurora-campus` |

## 6. v10 迁移和回滚

旧版本可能把 Built-in Manifest 放在 `data/plugins`，把风格包放在
`data/plugin_data/*/style-packs`。使用冲突安全脚本迁移：

```bash
./scripts/migrate-v10-module-plugin-layout.sh check
./scripts/migrate-v10-module-plugin-layout.sh apply backups/v10-layout-before
./scripts/migrate-v10-module-plugin-layout.sh rollback backups/v10-layout-before
```

数据库 migration `000026_v10_module_plugin_separation` 将历史 Built-in 状态和
配置迁入 Feature Store，并软删除 External Plugin Catalog 中的历史 Built-in
活跃行。它不删除用户内容、模块数据或审计记录。
