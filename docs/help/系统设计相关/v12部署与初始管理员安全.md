# v12 部署与初始管理员安全

> 适用阶段：v0.12 A1
>
> 状态：已实施；验证式注册、邮件和 Session 轮换将在后续阶段追加。

## 1. 为什么需要这项改动

早期 CampusOS migration 为本地演示创建过固定管理员。固定凭据不能出现在生产日志，也
不能作为生产启动后的实际密码。v12 将它收敛为一个仅用于识别历史风险的兼容标记：服务
发现旧凭据后，只能使用部署方提供的 Bootstrap Secret 轮换它。

服务不会记录密码、Bootstrap Secret、bcrypt 哈希或恢复值。启动日志只会说明管理员
已经创建、轮换或保留，不能据此登录。

## 2. 配置环境

`CAMPUSOS_ENV` 只接受以下值：

| 值 | 用途 |
| --- | --- |
| `development` | 本地开发。可显式保留兼容管理员，不能用于公开部署。 |
| `test` | 自动化测试和隔离测试。 |
| `staging` | 预发布环境。禁止明文密码和开发兼容管理员。 |
| `production` | 正式部署。必须提供 Bootstrap Secret 和非开发 JWT Secret。 |

本地 `.env` 的最小安全配置：

```dotenv
CAMPUSOS_ENV=development
AUTH_PASSWORD_HASH_ENABLED=true
AUTH_ALLOW_DEVELOPMENT_DEFAULT_ADMIN=true
```

`AUTH_ALLOW_DEVELOPMENT_DEFAULT_ADMIN=true` 只允许在 `development` 使用。它是为现有本地
数据和 smoke 工作流保留的兼容入口，不应复制到共享测试、预发布或生产环境。

## 3. 正式环境首次启动

生产环境必须通过受保护的部署 Secret 注入以下值，而不是提交到仓库、镜像、前端变量或
普通配置导出包：

```dotenv
CAMPUSOS_ENV=production
JWT_SECRET=<至少 32 字节的随机值>
AUTH_BOOTSTRAP_ADMIN_SECRET=<至少 16 个字符的一次性高强度密码>
AUTH_PASSWORD_HASH_ENABLED=true
AUTH_ALLOW_DEVELOPMENT_DEFAULT_ADMIN=false
```

生产启动会拒绝以下状态：

1. 缺少或过短的 `AUTH_BOOTSTRAP_ADMIN_SECRET`。
2. 保留开发默认 `JWT_SECRET` 或空 JWT Secret。
3. 关闭密码哈希。
4. 启用开发兼容管理员。

因此，部署失败时应先补齐 Secret，再重新启动；不要通过修改 migration、写入明文密码或
临时关闭认证来绕过检查。

## 4. Bootstrap 的实际行为

启动时服务在一个数据库事务中检查 `admin@campusos.local` 的凭据：

| 当前状态 | 结果 |
| --- | --- |
| 管理员不存在 | 使用 Bootstrap Secret 创建管理员。 |
| 仍为历史默认凭据 | 使用 Bootstrap Secret 轮换密码。 |
| 已由管理员修改过 | 原样保留，不会被 Bootstrap Secret 覆盖。 |
| 本地 development 且显式允许兼容凭据 | 保持本地兼容入口，日志不输出密码。 |

管理员角色分配和默认板块仍保持幂等。若管理员邮箱指向了非 `admin` 用户，服务会停止，
要求先人工处理数据冲突，而不会猜测应该覆盖哪个账号。

## 5. 轮换与后续操作

- 成功首次生产启动后，应立即在部署 Secret 管理系统中轮换并移除一次性 Bootstrap Secret；
  当前阶段仍要求生产启动配置存在该值，因此使用新的随机值保留为受管 Secret 即可，它不
  会覆盖已经自定义的管理员密码。
- 不要把 Bootstrap Secret 当作 CampusOS API Token、JWT Secret 或邮件发件密码复用。
- A6/A7 将提供 Session 撤销、密码找回和本机恢复 CLI；在这些能力上线前，生产密码恢复
  应遵守现有受控运维流程，不在数据库直接写入明文或 bcrypt 值。

## 6. 验证

```bash
GOCACHE=/tmp/campusos-go-cache go test ./pkg/config ./internal/server -count=1
GOCACHE=/tmp/campusos-go-cache go run ./cmd/campusosctl version
STOP_EXISTING=true make dev-all
```

检查 API 日志时，应该看到管理员初始化状态，但不应该看到 `默认密码`、Bootstrap Secret
或 bcrypt credential。完整 v12 验收还会在最终阶段执行 `make release-check`。
