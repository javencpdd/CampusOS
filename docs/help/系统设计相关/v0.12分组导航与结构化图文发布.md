# v0.12 分组导航与结构化图文发布

> 适用版本：v0.12-dev  
> 面向对象：普通用户、管理员、前端开发者和 Built-in Feature 维护者

## 1. 前台分组导航如何使用

板块分组是导航容器，不是可以发帖的板块。前台顶部只显示一个分组入口，例如“分组测试”；点击后会出现
该分组中仍处于活动状态且未关闭的子板块，例如“测试板块”和“版主测试”。选择子板块后进入帖子列表，
并自动携带对应的 `category_id` 筛选条件。

根级板块仍直接显示为链接。已归档、已关闭的板块和没有可用子板块的空分组不会出现在公开导航中。
PC 端使用点击菜单，移动端使用同一个可触控菜单，不再把“分组标题 + 所有子板块”平铺在一行。

## 2. 互助和二手为何显示在图文文章下面

管理端把“校园互助”和“校园二手”显示为“图文文章”的二级功能，是为了表达它们共用以下内容能力：

- 纯文本与安全图文两种正文格式；
- 图片上传、正文插入和发布前预览；
- HTML 自动清洗、图片自适应和列表纯文本摘要；
- Community 的板块、标签、回复、可见性和治理能力。

这只是展示和能力分组，不是生命周期继承。三个 Built-in Feature 仍有独立开关：停用图文文章不会自动
停用互助或二手，停用互助或二手也不会删除它们的 Thread、Detail 或图片。互助继续拥有互助类型和状态机，
二手继续拥有价格、成色、交易方式和交易状态；它们没有被改成普通 RichText Article。

## 3. 用户如何发布图文内容

1. 打开“校园互助”或“校园二手”，点击发布按钮。
2. 在正文上方选择“图文”或“纯文本”。新建内容默认使用图文模式。
3. 图文模式可插入标题、段落、加粗、引用和列表，也可点击“插入图片”。
4. 图片上传成功后会自动插入正文，并在编辑器下方出现缩略预览；点击缩略图可查看大图。
5. 点击“预览”，服务端会先执行与保存时相同的 HTML 清洗，通过后才展示最终效果。
6. 填完板块、结构化字段和标签后发布。详情页和通用帖子回复页都会按正确格式显示正文。

旧客户端可以继续省略 `content_format`，服务端会按历史 `markdown` 纯文本保存。编辑已有图文内容时，若旧
客户端没有发送格式，服务端保留该 Thread 当前格式，避免把安全 HTML 意外降级为可见标签文本。

## 4. 正文与图片安全边界

图文正文使用 `content_format=safe_html`。服务端只保留标题、段落、列表、引用、代码、表格、链接、图片等
白名单元素；脚本、iframe、表单、事件属性、危险 URL、固定定位和危险 CSS 会被移除。保存和预览使用同一
个 Community Core 清洗器，浏览器预览不能代替服务端检查。

图片上传入口属于始终启用的 User Storage Core，而不是某个可停用功能：

```text
data/personal-space/<user_id>/img/content/<random-name>.<ext>
```

当前只接受 JPEG、PNG、GIF 和 WebP，单文件默认不超过 5 MiB，并计入用户总存储配额。文件名由服务端随机
生成，路径使用安全段检查；公开帖子图片通过只读 URL 提供，不允许调用方指定宿主机路径。当前版本不会自动
删除尚未发布内容留下的孤立图片，管理员不得直接清空用户目录；后续应通过有审计的资产引用和回收策略处理。

## 5. API 合同

| 方法 | 路径 | 认证 | 作用 |
| --- | --- | --- | --- |
| `POST` | `/api/v1/content/preview` | JWT | 清洗并预览一段 `safe_html` 正文。 |
| `POST` | `/api/v1/content/assets/images` | JWT | 上传当前用户的正文图片。 |
| `GET` | `/api/v1/content/assets/images/:user_id/:filename` | 无 | 读取已上传的公开内容图片。 |
| `POST/PUT` | `/api/v1/mutual-aid/threads...` | JWT + 作者 | 保存纯文本或安全图文互助内容。 |
| `POST/PUT` | `/api/v1/secondhand/threads...` | JWT + 作者 | 保存纯文本或安全图文二手内容。 |

图文请求示例：

```json
{
  "title": "毕业台灯转让",
  "content": "<p>成色良好，配件齐全。</p><figure><img src=\"/api/v1/content/assets/images/1001/a.png\" alt=\"台灯实拍\" loading=\"lazy\"></figure>",
  "content_format": "safe_html",
  "category_id": "board-1",
  "tags": ["毕业季", "台灯"]
}
```

接口只接受 `markdown`（含兼容别名 `plain_text`）或 `safe_html`。`richtext_article` 是完整图文文章 Detail 的
格式，不能冒充互助或二手正文格式。完整字段仍以 OpenAPI、互助/二手设计文档和对应 Feature API 为准。

## 6. 管理员检查清单

1. 在“内置功能”确认互助、二手各自的目标状态；二级显示不代表开关联动。
2. 在“版块管理”给目标 board 启用 `mutual_aid` 或 `secondhand` 类型策略。
3. 测试纯文本、图文、图片上传、预览、编辑和通用帖子回复页。
4. 检查移动端图片没有横向溢出，文字与背景对比度由当前系统风格包负责。
5. 排障时先查看 API 错误和用户配额，不要移动 `data/personal-space` 中的文件来规避限制。

[v0.12 校园互助发布与状态管理](v0.12校园互助发布与状态管理.md) 与
