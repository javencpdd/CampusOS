# v0.12 校园二手发布与交易状态管理

> 面向对象：普通用户、管理员和 Built-in Feature 维护者  
> 适用阶段：v0.12 C3

## 1. 这项功能做什么

“校园二手”用于发布校内闲置物品信息。每个条目包含标题、说明、人民币标价、成色、交易方式、粗粒度地点和
当前交易进度。它帮助信息发布和沟通，不替代线下验货、付款或争议处理。

系统不提供支付、担保、订单、物流或仲裁。不要在公开内容中填写银行卡号、支付密码、身份证号、完整住址或
其他敏感个人信息。

## 2. 管理员如何开放

管理员需要同时完成两步：

1. 在管理端“内置功能”确认 **Campus Secondhand** 已启用。该功能是 `restart` 模式，调整启停后重启服务才会
   切换有效状态。
2. 进入“版块管理”，对要开放的 `board` 点击“配置帖子类型”，勾选 `secondhand` 并保存。

只启用 Feature 或只开放 board 都不够。关闭 Feature 或 board 类型只阻止新建，不会删除已有二手条目；
Community 管理员仍可以按正常治理规则查看、下架、恢复和审计基础帖子。

用户端会通过只读 `GET /secondhand/status` 显示当前有效状态。即使 Feature 已停用，该接口仍会返回
`enabled=false`；创建、列表、详情、编辑和状态修改等业务路径仍会被统一 Feature Gate 拒绝。

## 3. 用户如何发布

1. 打开用户端顶部的“校园二手”，选择“发布二手信息”。
2. 选择已经开放二手类型的 board。
3. 填写标题、物品说明、标价、成色和交易方式；地点范围和标签可选。
4. 标价按“元”填写，系统会以“分”保存并固定为人民币 CNY。
5. 发布成功后初始状态为 `available`（在售）。

编辑仅限原作者。保存时要带当前 `version`；出现冲突时重新加载最新内容，再确认要保留的修改。

## 4. 交易状态如何使用

| 当前状态 | 可以变为 | 推荐场景 |
| --- | --- | --- |
| `available` | `reserved`、`sold`、`closed` | 正在出售、暂为他人保留、已线下完成或停止出售。 |
| `reserved` | `available`、`sold`、`closed` | 约定未完成时重新开放、已完成交易或主动关闭。 |
| `sold` | 无 | 已完成交易，保持终态。 |
| `closed` | 无 | 不再继续出售，保持终态。 |

“已售出”不会自动删除帖子，也不会阻止管理员的治理操作。帖子被下架也不表示交易状态发生变化。

## 5. 常见问题

| 现象 | 原因 | 处理方式 |
| --- | --- | --- |
| 找不到发布入口或提交被拒绝 | Feature 未启用，或 board 未允许 `secondhand` | 管理员检查内置功能和板块类型策略。 |
| 标价不能提交 | 标价不是非负人民币金额 | 输入 0 或正数，避免货币符号和其他币种。 |
| 状态不能修改 | 状态转换不允许，或操作者不是作者 | 只选择当前状态允许的下一步；非作者不能改。 |
| 保存时提示冲突 | 已有新版本 Detail | 重新读取内容后再编辑。 |
| 编辑或状态更新返回 409 | 基础 Thread 已进入 Community 回收站，不能继续改变交易业务事实 | 先在 Community 内容流程确认或恢复基础帖子，再重新读取详情；不要重复提交旧版本。 |
| 返回 `internal server error` | 未分类的存储、网络或服务端故障被安全地统一处理 | 稍后重试；维护者应按服务端 trace 和日志排查，客户端不会收到数据库或用户内部信息。 |

## 6. 维护者边界

维护者扩展字段时必须新增固定数据库列、CHECK、索引、migration、可靠命令测试和 migration drill。不能把
支付或任意 Detail JSON 放入 Community Core，不能让 External Plugin 访问 Community Repository、数据库连接或
事务 Participant。编辑和状态修改必须先确认基础 Thread 仍处于 active（未回收）状态；拒绝后不得产生新的交易
状态、可靠审计或 Outbox 事件。未分类底层错误只能记录在服务端，不得直接回显给客户端。新的币种或金融流程
属于新产品边界，必须经过独立安全和合规审查。
