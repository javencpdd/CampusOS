# v12 结构化帖子类型与板块策略

> 适用阶段：v0.12 C1  
> 面向对象：管理员、Built-in Feature 开发者和维护者

## 1. 先理解两个不同的字段

一条帖子现在有两个容易混淆的概念：

| 字段 | 解决的问题 | 例子 |
| --- | --- | --- |
| `thread_type` | 这是什么业务内容，是否需要独立详情和状态机 | `discussion`、`article`、`mutual_aid`、`secondhand` |
| `content_format` | 正文如何渲染 | `markdown`、`richtext_article` |

图文文章的 `thread_type` 是 `article`，而正文格式是 `richtext_article`。以后互助和二手可以使用普通文本
说明，但它们仍分别是 `mutual_aid` 和 `secondhand`。不要再用正文格式猜测业务类型。

## 2. 管理员如何配置一个板块

1. 进入管理端的“版块管理”。
2. 在一个 `board` 行点击“配置帖子类型”图标。
3. 选择这个板块允许新建的类型，至少保留一种。
4. 保存。系统会使用当前 `version` 提交，若其他管理员刚修改过该版块，会要求重新加载后再保存。

历史 board 默认已启用“普通讨论”和“图文文章”。“校园互助”和“二手信息”必须同时满足两件事才可发布：

1. 管理员在这个 board 的类型策略中明确启用它。
2. 相应的 Built-in Feature 处于启用状态。

关闭类型不会删除已有帖子，也不会让管理员失去查看、下架、恢复或审计已有内容的能力；它只阻止新的该类型
创建请求。

## 3. 接口与权限

| 操作 | 接口 | 权限 |
| --- | --- | --- |
| 查看活动 board 的公开类型 | `GET /api/v1/categories/:id/thread-types` | 无 |
| 查看包括归档 board 的策略 | `GET /api/v1/admin/categories/:id/thread-types` | `category:read` |
| 更新策略 | `PUT /api/v1/categories/:id/thread-types` | `community.category.configure_thread_types` |

更新请求需要当前版本：

```json
{
  "allowed_types": ["discussion", "article", "mutual_aid"],
  "version": 4
}
```

请求只接受固定类型。未知类型、group、空数组、过期 `version` 和不具备权限的操作者都会被拒绝。

## 4. Built-in Feature 如何安全创建结构化内容

Built-in Feature 不能直接导入 Community Repository，也不能自己开启第二个数据库事务。它调用 Community
内部 `ContentGateway.CreateStructuredThread`，并提供一个只负责持久化本 Feature Detail 的 Participant：

```text
Feature DTO 校验
-> Community 校验 board、类型策略与 Feature 状态
-> 写 Thread + Revision
-> Participant 写一对一 Detail
-> 写 required audit + Outbox
-> COMMIT
```

Participant 必须是编译进主程序的 Feature 代码。它只能在当前事务内写自己的数据库 Detail，不能上传文件、
调用 HTTP、访问外部服务、启动进程或保存到任意宿主路径。RichText 已按这个规则作为第一个 `article`
Participant 实现。

External Plugin、SDK、MCP、Agent Runner 和浏览器页面没有这个接口。它们只能调用公开 API 或被 Gateway
授权的 Host API，不能接触 Community Repository、TxKernel 或宿主数据库连接。

## 5. 数据迁移与排查

`000033_v12_structured_threads` 做了三件事：

1. 为 `threads` 增加固定 `thread_type` 约束。
2. 将存在 RichText Detail 的历史 Thread 回填为 `article`。
3. 创建 `category_thread_type_policies` 并为历史 board 写入 `discussion/article`。

迁移开始前会检查每个 RichText Detail 是否有对应 Thread；发现孤立数据会直接中止，而不是自动删除。迁移、
策略更新和结构化创建都使用可靠命令或数据库约束，生产问题应优先 forward-fix。down migration 只用于隔离
up/down/up 演练。

维护时可运行：

```bash
make structured-thread-check
./scripts/test-v12-structured-threads-migration.sh
```

更完整的事务边界见 [v12 结构化帖子可靠写入说明](v12结构化帖子可靠写入说明.md)，决策依据见
[ADR-0020](../../architecture/decisions/ADR-0020-结构化帖子类型与内置参与者.md)。
