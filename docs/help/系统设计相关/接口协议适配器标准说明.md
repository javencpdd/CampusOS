# CampusOS 接口协议适配器标准说明

> 日期：2026-07-08
> 适用范围：Discord、OneBot v11、NapCat、AstrBot、飞书等外部消息或机器人协议接入设计

## 1. 核心思路

不要把 CampusOS 核心接口直接改成 Discord 或 OneBot v11 的形状。更稳的做法是把系统拆成三层：

| 层级 | 作用 | 示例 |
| --- | --- | --- |
| CampusOS Core Protocol | 系统内部稳定协议，只表达“用户、会话、消息、事件、动作” | `message.inbound`、`thread.created`、`richtext.article.published` |
| Adapter Contract | 插件必须实现的适配器标准 | `Receive()`、`Send()`、`Normalize()`、`Render()` |
| Platform Mapping | 面向具体平台的字段转换 | Discord gateway event、OneBot v11 message segment |

这样可以做到：核心业务只理解 CampusOS 的统一模型，Discord、OneBot v11 等差异交给插件适配层处理。

## 2. 推荐标准模型

统一消息入口建议使用下面的形状：

```json
{
  "protocol": "campusos.message.v1",
  "platform": "onebot-v11",
  "adapter": "napcat",
  "direction": "inbound",
  "conversation": {
    "id": "group:10001",
    "type": "group"
  },
  "sender": {
    "id": "123456",
    "display_name": "Alice",
    "user_id": "1001"
  },
  "message": {
    "id": "abc",
    "type": "rich",
    "content": "hello",
    "segments": [
      { "type": "text", "data": { "text": "hello" } }
    ]
  },
  "raw_payload": {}
}
```

其中 `raw_payload` 保留平台原始数据，便于排查和补字段，但业务逻辑不要依赖它。

## 3. Discord 和 OneBot v11 的转换方式

| 能力 | CampusOS 标准 | Discord 映射 | OneBot v11 映射 |
| --- | --- | --- | --- |
| 文本 | `segment.type=text` | `message.content` | `{type:"text", data:{text}}` |
| 图片 | `segment.type=image` | attachment / embed image | `{type:"image", data:{file,url}}` |
| 用户 | `sender.id` | `author.id` | `user_id` |
| 群组/频道 | `conversation.id` | `channel_id` / `guild_id` | `group_id` |
| 回复 | `message.reply_to` | `message_reference` | `reply` segment |
| 事件 | `event.type` | Gateway event name | `post_type` + `message_type` |

适配器只做转换，不直接写核心数据库。需要落库时调用 CampusOS 后端已经开放的 Message、Webhook、Thread 或插件 Host API。

## 4. 插件实现建议

每个协议适配器可以作为一个插件：

```text
data/plugins/onebot-v11-adapter/
data/plugins/discord-adapter/
```

插件应声明：

```yaml
permissions:
  api:
    - resource: "message"
      actions: ["read", "write"]
    - resource: "thread"
      actions: ["read"]
```

内部至少实现：

| 函数 | 说明 |
| --- | --- |
| `NormalizeInbound(raw)` | 把平台事件转成 CampusOS 标准模型 |
| `RenderOutbound(message)` | 把 CampusOS 标准消息转成平台发送格式 |
| `Receive(raw)` | 接收平台事件并写入 Message |
| `Send(message)` | 发送 CampusOS 消息到外部平台 |
| `Health()` | 返回连接状态、版本、权限摘要 |

## 5. 与富文本文章插件的关系

`controlled-richtext-article` 插件产生的是社区内容能力，不是外部消息协议。协议适配器可以监听：

```text
richtext.article.published
thread.created
post.created
```

然后把文章摘要、封面和链接渲染成 Discord embed 或 OneBot 图文消息段。反方向也可以把外部平台的图文消息规范化为草稿，再调用富文本文章 API 发布。

## 6. 当前边界

1. 当前 CampusOS 已有 Message local adapter，但还不是 Discord 或 OneBot v11 的完整实现。
2. 后续接入真实平台时，优先做一个协议适配器，不要一次接多个平台。
3. 外部协议字段变化频繁，核心系统只保留稳定标准模型，平台原始字段放在 `raw_payload`。
4. 发送外部消息前需要补权限、限流、审计和失败重试。
