# v14 学期治理与个人文档使用说明

> 更新时间：2026-08-29 20:57（Asia/Shanghai）
> 适用状态：`v0.14-dev`；发布基线仍为 `v0.13.0`，本文不代表 v0.14 Final 已发布。

## 更新数据库并重启 API

v14-dev 新增 `000044` 至 `000049`。其中 `000048` 只无损统一早期开发库的对象账本约束名称；`000049` 为课表保留旧 JSON 兼容读取的同时，增加当前 Object、第一周快照和用户查看偏好。源码与 migration 变更后执行：

```powershell
.\scripts\docker-dev.ps1 rebuild api
```

Linux 或 Git Bash 使用：

```bash
./scripts/docker-dev.sh rebuild api
```

API 启动时会顺序执行新增 migration。不要手工在生产库执行 down migration；如需回退，停用对应 Feature、保留数据并通过新 migration forward-fix。

## 管理员维护学期

后台新增“学期管理”（`/academic-terms`）：管理员创建春季或秋季学期，第一周开始日期必须是星期一；一个开放学期可被设置为默认。关闭学期后，用户既有课表可查看但不能再保存、导入或新建。

删除操作带乐观锁和原因字段；一旦 `user_schedule_terms` 已登记该学期的用户课表引用，数据库 RESTRICT 外键会拒绝删除。

## 用户课表行为

用户在“个人课表”中只能从平台开放学期下拉框选择。旧 `term_year + semester` 请求仍保留兼容形状，但服务端只会解析已有且开放的 AcademicTerm，不能借此创建任意年份学期。每次新保存先写兼容 JSON，再登记不可变的私有 schedule Object；旧 JSON 不会被重命名或删除。

## 历史课表采用与对象对账

两条维护命令默认只读，适用于 Windows Docker Desktop、Linux 和 WSL2。Docker 开发环境中建议在 API 容器运行，以使用容器内的 `DATABASE_DSN` 和挂载的 `data/personal-space`：

```powershell
docker compose --env-file deploy/docker/.env.dev.local -f compose.dev.yml exec api go run ./cmd/campusosctl storage reconcile --dry-run
docker compose --env-file deploy/docker/.env.dev.local -f compose.dev.yml exec api go run ./cmd/campusosctl schedule adopt --dry-run
```

Linux/Git Bash 的命令相同，只需去掉 PowerShell 特有的续行习惯。`storage reconcile` 不沿符号链接遍历，报告过期 pending/Reservation、metadata 缺物理文件、孤儿对象文件、hash/size、账本和未分类旧文件；报告只给相对路径，不泄露宿主绝对路径。

确认报告后才能显式执行修复或采用，必须填写操作者和原因：

```powershell
docker compose --env-file deploy/docker/.env.dev.local -f compose.dev.yml exec api go run ./cmd/campusosctl storage reconcile --apply --actor admin-1001 --reason "核对 v14 对象账本"
docker compose --env-file deploy/docker/.env.dev.local -f compose.dev.yml exec api go run ./cmd/campusosctl schedule adopt --apply --actor admin-1001 --reason "采用已核验的历史课表"
```

对账 apply 只会释放已过期的 Reservation 并把“ready metadata 但物理文件缺失”的对象标为 `missing`；未知文件、账本差异和 quarantine 永远不会自动修改。课表采用只处理 owner、文件名、春/秋学期、星期一第一周和 hash 都有效的 JSON：缺少的历史 AcademicTerm 以 `closed` 创建，原 JSON 复制为不可变对象，`index.json` 有效时写入查看偏好；损坏或不符合要求的文件只报告、保留原位。两种 apply 都写入 `platform_command_audits`，重跑相同 user/term/hash 不重复创建对象。

## 我的文档

用户导航中的“我的文档”（`/documents`）提供：

- 新建 TXT、Markdown 或 CampusDoc v1 文本；每次保存均追加不可变版本。上传文本类也会先执行相同的格式校验，不能绕过编辑器限制。
- 上传 TXT、Markdown、CampusDoc、PDF 或 DOCX；文本类单文件最多 5 MiB，PDF/DOCX 最多 25 MiB，仍受个人总配额限制。
- 下载、版本历史、从历史版本恢复为新版本，以及回收站恢复。
- 已保存的 TXT、Markdown、CampusDoc 可使用“安全预览”。`GET /api/v1/documents/:id/preview` 只返回服务器经共享 `core.content-editor` 清洗后的 `rendered_html`；Markdown 中的原始 HTML 会显示为文本，CampusDoc v1 图片只允许数字 `object_id`，不接受外部 URL。
- PDF/DOCX 在没有满足隔离条件的 Converter 时仅支持认证上传和下载，`GET /api/v1/documents/:id/preview` 明确返回 `converter_unavailable` 与下载下一步；服务器不会回退调用 Office/PDF 外部程序。

新增文档内容通过 User Storage Object Port 保存。接口响应仅含 Object ID、名称、大小、hash、状态和版本，不暴露宿主绝对路径或 provider key；其他用户访问文档 ID 返回统一的“文档不存在或无权访问”。Document Provider 的 `ReadPort` 目前只是受信编译内 Built-in 调用草案，始终带 owner 参数，未注册到 AppContext、External Plugin Host 或插件 Gateway，插件不能读取用户原始文档内容。

当空间不足时，响应使用中文 `user_storage.quota_exceeded`，并包含文件上限等可操作详情；不要依赖旧的英文底层错误文本。运行时会以低基数指标汇总对象、Reservation 和（未来隔离 Runner 的）预览队列状态；Admin 集成中心仅展示固定的运营合计，不展示用户、文件名、Object ID 或路径。

## Converter 和恢复边界

`deploy/docker/compose.converter.example.yml` 是可选的隔离模板，不被 `compose.dev.yml` 自动加载。它强制非 root、只读根文件系统、`cap_drop: ALL`、`no-new-privileges`、无网络、1 CPU、512 MiB、64 个 PID、受限 tmpfs 和 60 秒/50 MiB 任务限制，并且不注入数据库、JWT、SMTP 或个人空间宿主目录。仅设置镜像变量不能启用预览：必须先交付经审查的受限任务协议 Runner，才可改变 `converter_unavailable` 的降级行为。

备份与恢复演练使用。Linux、WSL2 或 Git Bash：

```bash
./scripts/restore-drill.sh
```

Windows PowerShell 可调用 Git Bash：

```powershell
& 'C:\Program Files\Git\bin\bash.exe' -lc './scripts/restore-drill.sh'
```

脚本会优先使用 `POSTGRES_CONTAINER`；未设置时也能识别标准开发容器
`campusos-dev-postgres-1`。该演练在隔离数据库恢复 DB 与 `data/personal-space`，并核验 v14 的对象、账本、
课表绑定、文档表以及绑定列；它不会对运行中的开发数据库执行 down、reset 或删除开发卷。
