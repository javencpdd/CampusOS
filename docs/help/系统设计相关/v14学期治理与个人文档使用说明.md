# v14 学期治理与个人文档使用说明

> 更新时间：2026-08-29 03:08（Asia/Shanghai）
> 适用状态：`v0.14-dev`；发布基线仍为 `v0.13.0`，本文不代表 v0.14 Final 已发布。

## 更新数据库并重启 API

v14-dev 新增 `000044` 至 `000048`。其中 `000048` 只无损统一早期开发库的对象账本约束名称。源码与 migration 变更后执行：

```powershell
.\scripts\docker-dev.ps1 rebuild api
```

Linux 或 Git Bash 使用：

```bash
./scripts/docker-dev.sh rebuild api
```

API 启动时会顺序执行新增 migration。不要手工在生产库执行 down migration；如需回退，停用对应 Feature、保留数据并通过新 migration forward-fix。

## 管理员维护学期

后台新增“学期管理”（`/academic-terms`）：管理员创建春季或秋季学期，第一周开始日期必须是星期一；一个开放学期可被设置为默认。关闭学期后，用户既有课表可查看但不能再保存、导入或新建。

删除操作带乐观锁和原因字段；一旦 `user_schedule_terms` 已登记该学期的用户课表引用，数据库 RESTRICT 外键会拒绝删除。

## 用户课表行为

用户在“个人课表”中只能从平台开放学期下拉框选择。旧 `term_year + semester` 请求仍保留兼容形状，但服务端只会解析已有且开放的 AcademicTerm，不能借此创建任意年份学期。历史 JSON 位于个人空间，v14-dev 暂时保留兼容读取，不会静默移动或删除历史文件。

## 我的文档

用户导航中的“我的文档”（`/documents`）提供：

- 新建 TXT、Markdown 或 CampusDoc 文本；每次保存均追加不可变版本。
- 上传 TXT、Markdown、CampusDoc、PDF 或 DOCX；文本类单文件最多 5 MiB，PDF/DOCX 最多 25 MiB，仍受个人总配额限制。
- 下载、版本历史、从历史版本恢复为新版本，以及回收站恢复。
- PDF/DOCX 在没有满足隔离条件的 Converter 时仅支持认证上传和下载，服务器不会回退调用 Office/PDF 外部程序。

新增文档内容通过 User Storage Object Port 保存。接口响应仅含 Object ID、名称、大小、hash、状态和版本，不暴露宿主绝对路径或 provider key；其他用户访问文档 ID 返回统一的“文档不存在或无权访问”。

当空间不足时，响应使用中文 `user_storage.quota_exceeded`，并包含文件上限等可操作详情；不要依赖旧的英文底层错误文本。
