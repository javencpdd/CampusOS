# v0.12 账号恢复与邮箱绑定说明

> 更新时间：2026-10-26 01:44（Asia/Shanghai）
> 适用范围：普通 User 恢复流程及当前独立 Admin 本机恢复
> 面向对象：普通用户、管理员与部署维护者

## 1. 三种入口不要混用

CampusOS 把“忘记密码”“更换个人邮箱”和“无法证明旧邮箱归属”分成三个流程。这样做是为了让
每个流程只拥有完成它所需的最小权限。

| 场景 | 使用入口 | 谁能完成 | 结果 |
| --- | --- | --- | --- |
| 已验证个人邮箱，忘记密码 | 登录页的“找回密码” | 邮箱持有人 | 更新密码并退出全部设备 |
| 已登录，想换成新的个人邮箱 | 头像菜单的“账号安全” | 当前用户 | 新邮箱验证后替换登录邮箱并退出全部设备 |
| 历史账号没有已验证邮箱且忘记密码 | 管理端“账号恢复” | 管理员线下核验后，用户完成邮件验证 | 绑定新邮箱、更新密码并退出全部设备 |

`legacy_accepted` 历史账号可以用原密码登录，但不能把旧邮箱当作已经证明所有权的找回邮箱。
当前独立系统 Admin 的邮箱为 `admin@campusos.local`，使用独立 Admin 凭据、MFA 和会话。User 的密码、邮箱、角色或恢复 Case 不能恢复独立 Admin；同号或同邮箱也不作跨域回退。独立 Admin 公网恢复票据消费 HTTP 尚未开放，已有 `admin_recovery_tickets` 仓储不代表已有找回入口。

## 2. 普通用户：通过邮箱找回密码

1. 在登录页打开“找回密码”，输入已验证的个人邮箱并请求验证码。
2. 页面在发送成功后会把不透明 Challenge ID 保存在当前页面内存，普通用户只需填写邮件中的六位
   验证码，不需要抄写或输入请求编号。
3. 页面把内部 Challenge ID 和验证码一并提交，服务端只在验证成功后发放一次性 Ticket。
4. 输入新密码完成重置，系统在同一事务内更新密码、增加 `auth_version`、撤销所有 Session 并消费
   Ticket。
5. 页面跳回登录页。此前设备的 Access Token、Refresh Token 和已登录会话全部失效，必须重新登录。

若邮箱不存在、账号为历史未验证账号、账号停用或请求被限流，页面仍显示同一类“已受理”结果。
这不是故障，而是避免攻击者通过页面判断某个邮箱是否注册。

## 3. 已登录用户：绑定或更换邮箱

1. 点击自己的头像，进入“账号安全”。
2. 打开“绑定邮箱”，输入一个未被其他账号使用的新个人邮箱。
3. 输入新邮箱收到的六位验证码，服务端验证后消费一次性 Ticket。
4. 系统原子更新 `accounts.identifier`、规范化邮箱、验证状态和兼容的 `users.email` 投影；随后增加
   `auth_version` 并撤销全部 Session。
5. 用户重新登录后，新邮箱成为唯一的登录和后续找回邮箱。

不要在个人主页资料、插件配置、数据库控制台或前端本地存储里直接修改邮箱。那些写法会绕开账号
唯一性、验证码、审计和令牌撤销边界。

## 4. 管理员：辅助恢复的正确做法

管理员不能查看验证码、Ticket、旧密码、密码 hash 或线下证明材料，也不能直接给用户填写新密码。
管理端只保存“线下核验编号”这一非敏感引用，线下材料应留在组织既有的受控流程中。

操作步骤：

1. 先按组织流程核验用户身份，并记录可追踪但不包含个人敏感内容的核验编号。
2. 在管理端“账号恢复”输入用户 ID、新个人邮箱和核验编号。
3. 系统只允许目标账号处于 `legacy_accepted` 或 `unverified` 状态，且新邮箱未被其他用户占用。
4. 系统创建一个有时限的恢复 Case，并向新邮箱发送验证码。列表只显示脱敏邮箱和状态。
5. 用户自行用“找回密码”页的“辅助恢复”模式输入邮件中的请求编号、验证码和新密码。
6. 完成后系统把该账号迁为 `verified`，原子替换邮箱、更新密码、撤销全部会话、消费 Ticket、完成
   Case，并写入 required audit/outbox。

管理员可取消尚未完成的 Case，也可在获授权的情况下查看用户的脱敏会话投影并撤销全部会话。取消
Case 不会删除审计记录；发生错误时用 forward-fix 处理，而不是手工删除 Challenge、Case 或 Session。

## 5. 权限最小化

| Permission Code | 允许动作 | 不允许动作 |
| --- | --- | --- |
| `identity.account.recovery.override` | 创建、查看和取消辅助恢复 Case | 读取验证码、Ticket、密码或证明原文；直接完成恢复 |
| `identity.session.read` | 查看指定用户的脱敏会话 | 读取 Refresh 摘要、原始 Token、IP 明文 |
| `identity.session.revoke` | 撤销指定用户的全部会话 | 修改密码或邮箱 |
| `platform.email_delivery.read` | 查看邮件投递的脱敏健康状态 | 查看邮件正文、验证码、SMTP Secret |
| `identity.challenge_policy.read` | 查看验证码的邮箱/IP 滑动窗口策略 | 查看邮箱、IP、Code 或 Ticket |
| `identity.challenge_policy.update` | 在安全边界内热更新窗口和次数 | 关闭限流、设置零次数或绕过审计 |

以上是管理员操作普通 User 资源时的业务权限，不表示 User 全局 `admin` 角色可以作为独立 Admin 登录证明。委派前应核对当前独立 Admin 角色中的权限码、资源范围、MFA 和审计责任。

## 6. 独立系统 Admin 本机恢复

部署维护者在可信服务器的真实交互式 TTY 中执行：

```bash
campusosctl identity reset-password --email admin@campusos.local --reason "approved system Admin password recovery"
```

`--email` 只能是固定 `admin@campusos.local`，省略时仍使用该邮箱，目标必须是现有、活跃且有有效本域凭据的独立系统 Admin。命令要求：

1. 部署配置中已有 `AUTH_BOOTSTRAP_ADMIN_SECRET`。
2. 逐字确认 `RESET admin@campusos.local`，再隐藏输入该部署 Secret。
3. 两次隐藏输入一致的新密码；不接受密码、证明的命令行参数或管道输入，CI 不能替代 TTY。

成功后只更新独立 Admin 密码凭据，消费其旧 Admin MFA/恢复票据并撤销全部 Admin 会话及刷新凭据；不改 User 的密码、邮箱、角色或会话，不新增或扩张 Admin 角色，已吊销 Admin 不可恢复。凭据变更、旧票据消费、会话撤销、必需审计与 Outbox 同事务提交，任何一步失败会整体回滚。

暂停账号恢复与丢失 TOTP 使用另外两个命令，均要求实际不透明的独立 Admin `--account-id`；旧 `--user-id` 已退役，不能把旧准入兼容页的关联用户编号用于本机 Admin 恢复。参见[管理员准入与本机恢复](v0.13管理员准入管理与本地恢复.md)及[TOTP 恢复说明](v0.13TOTP多因素认证与恢复说明.md)。

## 7. 部署与排障

- 配置 SMTP 后，邮件是通过可靠 Outbox 异步投递的。请求成功表示工作流已安全提交，不承诺邮件已经
  到达收件箱。
- 检查脱敏健康状态和失败计数，而不是从日志寻找验证码：`GET /api/v1/platform/email-delivery/status`。
- 测试当前实现用 `make identity-recovery-check`；核对当前 clean baseline 用
  `make migrate-status` 和 `make database-check`。旧 v0.12 迁移演练脚本不用于现行库。
- 验证码策略默认是每邮箱 10 分钟 5 次、每 IP 60 分钟 10 次，可在管理端热更新；具体边界见
  [验证码频率策略配置说明](v0.12验证码频率策略配置说明.md)。
- 数据库 down migration 仅用于隔离演练。生产恢复保留 Case、Session、命令审计和 Outbox 证据，使用
  forward-fix 或备份恢复，不直接删除安全记录。

相关接口字段、错误语义与审计边界见 [v0.12 账号恢复与邮箱绑定流程](../../api/v0.12账号恢复与邮箱绑定流程.md)。
