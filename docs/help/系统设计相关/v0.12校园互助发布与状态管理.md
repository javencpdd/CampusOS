# v0.12 校园互助发布与状态管理

> 面向对象：普通用户、管理员和 Built-in Feature 维护者  
> 适用阶段：v0.12 C2

## 1. 这项功能解决什么问题

“校园互助”用于发布明确的求助、提供、志愿协助或资源分享信息。它是一种特殊帖子：除了标题和正文，还会
记录当前进度、可选截止时间、粗粒度地点和联系渠道类别。

它不是交易、支付或即时聊天功能。不要在正文或地点字段中发布身份证号、银行卡号、完整宿舍门牌、密码或
其他敏感信息。

## 2. 管理员先做的两项配置

互助功能默认作为 Built-in Feature 随服务编译，但不是每个板块自动允许发布。管理员需要依次完成：

1. 在管理端“内置功能”确认 **Campus Mutual Aid** 已启用。它的启停模式是 `restart`，修改后重启服务才会
   让新配置生效。
2. 进入“版块管理”，找到要开放的 `board`，点击“配置帖子类型”，勾选 `mutual_aid` 并保存。

只有 Feature 已启用且对应 board 的类型策略允许 `mutual_aid` 时，用户才能创建互助内容。关闭类型或
Feature 不会删除已有帖子；Community 管理员仍可以查看、下架、恢复和审计原基础帖子。

用户端会通过只读 `GET /mutual-aid/status` 显示当前有效状态。即使 Feature 已停用，该接口仍会返回
`enabled=false`；创建、列表、详情、编辑和状态修改等业务路径仍会被统一 Feature Gate 拒绝。

## 3. 用户如何发布和更新

1. 打开用户端顶部的“校园互助”。
2. 选择一个已允许互助类型的 board。
3. 填写标题、正文、互助类型、联系渠道；截止时间和地点范围可选。
4. 发布后，初始状态是“进行中之前的开放状态”（`open`）。
5. 作者可以打开自己的条目编辑正文和 Detail；保存时系统会检查版本，避免覆盖他人刚完成的修改。

公开浏览者只能看到公开 Thread 与其互助 Detail。作者专用编辑读取和修改接口会再次核验本人身份，不能只靠
前端隐藏按钮保护。

## 4. 状态应该如何使用

| 当前状态 | 可改为 | 建议场景 |
| --- | --- | --- |
| `open` | `in_progress`、`resolved`、`closed` | 有人已接手、问题已解决或不再开放。 |
| `in_progress` | `open`、`resolved`、`closed` | 协助中、无人继续时重新开放、已完成或终止。 |
| `resolved` | `closed` | 保留已解决说明后关闭。 |
| `closed` | 无 | 结束后不再重新开放，避免历史状态被误用。 |

“已解决”只表示互助业务完成，不等于帖子从前台消失。管理员的下架、恢复和锁定仍是独立的 Community 治理动作。

## 5. 出现错误时怎么判断

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 无法发布 | Feature 未启用，或 board 未允许 `mutual_aid` | 由管理员检查内置功能和板块类型策略。 |
| 保存时提示冲突 | 另一处编辑已更新 Detail | 重新读取最新内容，再合并并提交。 |
| 无法改变状态 | 状态机不允许该转换，或作者不匹配 | 从当前状态选择允许的下一步；非作者不能修改。 |
| 编辑或状态更新返回 409 | 基础 Thread 已进入 Community 回收站，不能继续改变互助业务事实 | 先在 Community 内容流程确认或恢复基础帖子，再重新读取详情；不要重复提交旧版本。 |
| 功能页面显示不可用 | Feature 已被停用或服务尚未按新配置重启 | 检查启停配置和服务状态，不要尝试绕过 API。 |
| 返回 `internal server error` | 未分类的存储、网络或服务端故障被安全地统一处理 | 稍后重试；维护者应按服务端 trace 和日志排查，客户端不会收到数据库或用户内部信息。 |

## 6. 维护者的边界

维护者扩展互助字段时，应新增固定列、校验、索引、migration 和测试。不能让浏览器提交任意 Detail JSON，
也不能让 External Plugin 接触 Community Repository、数据库连接或事务 Participant。创建、编辑和状态修改
必须保留可靠命令、作者检查、版本检查和 Community 治理独立性。编辑和状态修改还必须先确认基础 Thread
仍处于 active（未回收）状态；拒绝后不得产生新的互助状态、可靠审计或 Outbox 事件。未分类底层错误只能记录在
服务端，不得直接回显给客户端。
