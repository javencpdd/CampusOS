# v0.12 两级板块与可靠管理说明

> 适用阶段：v0.12 B1-B3  
> 面向对象：社区管理员、版主配置人员和开发者

## 1. 先理解两个概念

CampusOS 把板块分成两种节点：

| 节点 | 可以做什么 | 不可以做什么 |
| --- | --- | --- |
| group（分组） | 给多个 board 提供导航分类 | 发布主题、接收回复、获得父级版主权限 |
| board（版块） | 承载主题、回复、默认标签和明确分配的版主 scope | 再包含子节点 |

最常见的结构是“学习交流”这个 group 下放“课程讨论”和“竞赛信息”两个 board。也可以直接建立一个
根级 board，例如“站务公告”。系统最多两级，避免目录层层嵌套后用户和版主都找不到实际治理范围。

## 2. 管理员如何配置

1. 进入管理端的“板块管理”。页面显示所有节点，包括已归档节点。
2. 先建立需要的 group。group 只能在根级，不能选择父级。
3. 建立 board。可以选择一个活动 group，也可以不选，让它成为根级 board。
4. 为 board 设置名称、说明、默认标签、颜色、排序和是否关闭。颜色只能为 `#RRGGBB` 或
   `#RRGGBBAA`；页面颜色选择器会生成正确格式。
5. 需要整理导航时，选择一个 board 后执行移动。系统会要求确认目标 group，并检查当前版本。
6. 不再开放新内容时，先关闭 board；需要从导航中撤下且保留历史内容时，再使用归档。
7. 恢复时使用“恢复”。若它原来位于 group 下，那个 group 必须仍然是活动状态。

关闭和归档不同：关闭后板块仍出现在公开导航，但不能发新内容；归档后只在管理端可见，公开导航、
发帖选择和公开单条读取都不会显示它。

## 3. 归档前为什么要看影响

归档不是删除。系统会保留板块、主题、回复、默认标签、版主分配和审计记录，便于未来恢复和治理。
归档前的影响预览会告诉管理员：

- 是否有活动的 child board；若有，group 不能归档，必须先移动或归档这些 board。
- 该节点关联的主题数量；这些主题不会被删除，但不会再接受新回复。

使用旧的删除 API 或旧客户端的“删除”按钮时，系统也只会执行归档。该兼容用法会被记录，便于后续
安全地移除旧入口。

## 4. 版主权限不会因为移动而变化

管理员分配版主时选的是具体 board，而不是 group。比如用户只被分配给“课程讨论”，将这个 board 从
“学习交流”移动到“新生指南”后，该用户仍只能管理“课程讨论”里的主题；他不会因为新的父 group 获得
“新生指南”下其他 board 的权限。

这也是为什么 group 不提供“给这个分组下所有板块分配版主”的快捷方式。需要扩大治理范围时，应由
管理员明确勾选每个 board，并由现有授权审计记录这次变更。

## 5. 用户侧会看到什么

- 前台导航将 group 显示为分组标题，将其下活动 board 显示为可点击入口。
- 发帖和创建富文本文章时，只会列出活动、未关闭的 board。
- 用户仍然可能从旧链接打开历史主题；能否阅读由原有主题可见性与治理状态决定。新主题和新回复必须
  重新通过板块资格校验。

前端的隐藏只是改善体验。无论请求来自网页、脚本还是旧客户端，后端都会拒绝向 group、closed 或
archived 节点写入内容。

## 6. 开发者调用注意事项

管理读取路径是 `/api/v1/admin/categories`，公开读取路径是 `/api/v1/categories`。不要把这两类
结果混用：公开接口不返回 archived 数据，管理接口需要 `category:read`。

更新、移动、归档和恢复都要携带当前 `version`。收到 `409` 时，不要重试旧请求；先重新读取，再把
新的状态展示给管理员。移动使用专用请求：

```json
{
  "parent_id": null,
  "version": 7
}
```

这里的 `null` 明确表示移动到根级。省略 `parent_id` 会返回参数错误，而不是猜测调用者意图。

完整的路由、权限、错误和迁移规则见 [v0.12 两级板块与可靠管理流程](../../api/v0.12两级板块与可靠管理流程.md)。

## 7. 排障与恢复

- 创建或移动失败：确认父节点是活动 group，且目标不是 board、自身或已经归档的节点。
- 发帖失败：确认目标 board 没有关闭或归档；不要只看前端缓存，重新读取公开板块列表。
- 版本冲突：另一位管理员已更新该节点，重新加载后再处理。
- 迁移失败：查看 `000032` 预检输出的节点 ID，人工确认三级、循环或孤立 parent 后再执行迁移；不要
  用脚本自动重接层级。

验证实现可运行：

```bash
make category-hierarchy-check
./scripts/test-v12-category-hierarchy-migration.sh
```

生产恢复优先使用 forward-fix 或经过验证的备份恢复。down migration 仅用于隔离演练，不能作为删除
归档记录或审计证据的生产操作。
