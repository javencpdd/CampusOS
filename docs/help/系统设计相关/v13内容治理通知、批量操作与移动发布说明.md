# v13 内容治理通知、批量操作与移动发布说明

本文说明管理员删除帖子后用户如何收到消息、管理端如何批量治理帖子，以及手机端如何发布普通、图文、
校园互助和校园二手内容。

## 1. 管理员删除帖子后的通知

管理员或其他治理主体把帖子移入回收站时，系统会给帖子作者创建一条站内通知：

- 通知类型为 `community.thread.trashed`。
- 标题会明确说明帖子已被管理员移入回收站。
- 正文包含帖子标题，点击后可打开作者可见的帖子详情。
- 用户自己删除自己的帖子时不会重复通知自己。
- 管理员删除自己发布的帖子时也不会产生无意义的自我通知。

帖子状态、治理记录、可靠命令和通知在同一个数据库事务中提交。通知无法保存时，删除操作也会失败并回滚，
不会出现“帖子已经不见了，但用户永远收不到通知”的半完成状态。

### 用户在哪里查看

登录用户可在用户端页头点击铃铛图标打开“消息通知”：

1. 未读数量显示在铃铛角标中。
2. 点击消息会先标记已读，再打开站内目标页面。
3. 可以使用“全部已读”一次标记当前账号的全部通知。
4. 页面可见时每 30 秒检查一次新消息；浏览器重新回到前台时也会刷新。

当前交付的是站内通知，不等同于邮件、短信、系统推送或 WebSocket 实时推送。30 秒轮询可能带来短暂延迟，
外部通知渠道应在后续通过受控 Adapter 和用户偏好单独设计。

### 通知 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/notifications?page=1&page_size=20` | 获取当前用户通知、分页和未读总数 |
| `POST` | `/api/v1/notifications/:id/read` | 将当前用户拥有的一条通知标记为已读 |
| `POST` | `/api/v1/notifications/read-all` | 将当前用户全部未读通知标记为已读 |

这些接口都要求登录。服务端始终使用 JWT 中的当前用户 ID 查询和更新；用户不能通过参数读取或修改他人的通知。
不存在或不属于当前用户的通知统一返回 404，避免泄露通知 ID 是否真实存在。

## 2. 管理端批量治理

进入“内容治理 -> 帖子治理”后，表格第一列是选择框。勾选表头选择框会选择当前页的帖子，然后可以从批量
操作菜单执行：

- 内容列表：置顶、取消置顶、锁定、解除锁定、审核通过、审核拒绝、下架、直接恢复、移入回收站。
- 回收站：恢复内容、永久清除。

“全选”只作用于当前已加载页面，不会静默操作其他分页或所有筛选结果。切换列表、筛选条件、页码或刷新时，
当前选择会被清除，防止管理员误把旧选择带入新页面。

批量操作复用已有单项 API，并按选择顺序逐项执行。每一项仍独立经过：

```text
管理员准入 -> Permission Code / 板块作用域 -> 状态机 -> 可靠事务 -> 审计 / Outbox -> 作者通知
```

系统不会因为是批量入口而绕过权限、板块范围、治理原因或审计。部分帖子不满足状态或权限时，界面会汇总成功
和失败数量，并显示首个失败项；已经成功的项目不会被伪装成失败，也不会在客户端进行不可靠的整体回滚。

审核、下架、恢复和永久清除仍要求填写原因，同一批次原因会分别写入每条帖子的治理记录。永久清除不可恢复，
应先确认保留和审计要求。

## 3. 手机端四类发布入口

登录后打开“发布帖子”，手机或窄容器会显示全宽发布类型选择框，桌面宽容器显示分段选择器。两端提供相同的
四类入口：

1. 图文文章
2. 普通文本
3. 校园互助
4. 校园二手

校园互助和校园二手会进入各自的专用编辑器。两个编辑器都支持安全图文正文、图片上传和插入、纯文本模式及
服务端预览，同时保留各自的结构化字段。移动端单选项、数字步进和主要按钮使用不小于 44px 的触控尺寸。

入口可见不代表一定允许发布。服务端仍会检查：

- 对应 Built-in Feature 是否启用。
- 目标节点是否是可发布的活动板块，而不是分组。
- 该板块是否允许 `mutual_aid` 或 `secondhand` 类型。
- 图片类型、个人存储配额、HTML 清洗和内容字段是否合法。

功能被管理员明确停用时，发布类型会禁用；状态接口暂时失败时，客户端不会擅自把整个入口永久隐藏，最终请求
仍由后端权威校验。切换到互助或二手编辑器前如果当前普通/图文内容尚未保存，页面会要求用户确认，避免误丢稿件。

## 4. 常见问题

### 管理员删除后用户没有立即看到通知

先确认用户仍处于登录状态，然后点击铃铛手动打开通知中心。站内通知最多可能等待一个轮询周期。若接口失败，
检查 `/api/v1/notifications` 响应和 API 日志中的 request ID。

### 批量操作只有一部分成功

这是逐项权限或状态校验的预期结果。清除筛选并重新读取列表，检查失败帖子的板块作用域、当前治理状态和治理
记录。不要通过直接改数据库绕过状态机。

### 手机端能看到互助或二手入口，但发布返回不允许

管理员需要同时启用对应功能，并在目标板块的帖子类型策略中允许该类型。前端入口用于导航，后端策略才是最终
权限和业务规则来源。

## 5. 当前限制

- 通知中心首版只消费 CampusOS 站内通知，不包含邮件、短信、浏览器 Push 或第三方平台推送。
- 批量操作是当前页逐项执行，不是服务端异步批处理任务；超大批量治理应另行设计幂等任务、审批和进度审计。
- 当前只为“管理员移入回收站”建立作者通知。审核拒绝、下架、回复删除等事件可在统一通知合同上继续扩展，
  但需要分别定义文案、频率控制和用户偏好。
