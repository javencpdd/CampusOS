# v13 容量基线与回归门禁

> 工具：`cmd/campusos-baseline`、`cmd/campusos-capacity`  
> 候选环境预算：[`docs/项目计划v13/evidence/v13-capacity-budget.json`](../../项目计划v13/evidence/v13-capacity-budget.json)  
> 隔离演练预算：[`docs/项目计划v13/evidence/v13-capacity-drill-budget.json`](../../项目计划v13/evidence/v13-capacity-drill-budget.json)

## 1. 目标

容量门禁不是压测平台，也不会制造账号、发送验证码、登录用户或修改业务数据。它把同一台候选环境上的只读延迟样本与受控运行时快照保存为 JSON，并在发布前比较：

- 健康页、帖子列表、校园互助列表、二手信息列表的 p50/p95/p99；
- 受限管理员准入列表、MFA 策略、指标摘要和 Reliability 摘要的 p50/p95/p99；
- 失败和非 2xx 响应；
- goroutine、堆内存、数据库连接池空闲等待；
- Reliability 队列健康、dead-letter 数和最老待处理事件年龄；
- 已有前端 bundle、查询预算和低基数指标检查。

它只能访问 loopback（`localhost`、`127.0.0.1` 或 `::1`）目标，避免把管理员凭据或观测数据发送到远程地址。

## 2. 先冻结静态基线

静态基线记录路由、迁移、模块、外部插件、资源包和结构化列表查询模式：

```bash
go run ./cmd/campusos-baseline --root . --output docs/项目计划v13/evidence/v0.13-static-baseline.json
```

这不替代真实候选环境采样。比较 p95 时必须使用同一硬件、相近数据量、相同部署参数和相同 samples 数。

## 3. 采集候选环境

先取得一个只具备 `identity.admin_account.read`、`identity.mfa_policy.read`、`platform.metrics.read` 和 `platform.reliability.read` 的短期管理员授权值。不要把值写进 shell history、命令参数、JSON 报告、截图或工单。仅在权限为 `0600` 的临时文件中保存一行完整 `Authorization` Header 值：

```bash
umask 077
printf '%s\n' 'Bearer <short-lived-admin-token>' > /tmp/campusos-capacity.authorization

go run ./cmd/campusos-capacity capture \
  --base-url http://127.0.0.1:8080 \
  --samples 20 \
  --include-admin-observability \
  --authorization-file /tmp/campusos-capacity.authorization \
  --output /tmp/campusos-baseline.json
```

对升级后的同环境候选重复一次并改为 `/tmp/campusos-candidate.json`。工具只发 GET 请求；它不会调用登录、Refresh、Challenge、重放或删除 API。采样结束后按本机安全流程移除临时授权文件。

## 4. 比较与预算

```bash
go run ./cmd/campusos-capacity compare \
  --baseline /tmp/campusos-baseline.json \
  --candidate /tmp/campusos-candidate.json \
  --budget docs/项目计划v13/evidence/v13-capacity-budget.json
```

候选环境默认预算为同环境 p95 不超过基线 20%、goroutine 不超过 20%、堆分配不超过 50%、数据库空池等待不超过 1 秒、最老 Reliability 待处理事件不超过 300 秒且 dead-letter 为 0。它们是 v13 候选门槛，不是未经测量的生产 SLO；项目升级硬件、数据模型或流量模型时应新建、审查并版本化预算文件，而不是临时放宽命令参数。

隔离演练使用单独的 `v13-capacity-drill-budget.json`。它仍保留 20% 比例门槛，但仅对同一空数据库、同一 loopback 进程的微秒计时增加固定 `8ms` 绝对允许值，避免 Go 调度、GC 和宿主负载把 1-10ms 的短请求误判为发布回归。原始 p50/p95/p99 始终保留在报告中；超过比例门槛且绝对增加超过 `8ms` 仍会失败。这个允许值不得用于真实候选环境的基线比较。

## 5. CI 与发布前检查

```bash
make v13-capacity-check
```

该检查验证工具、容量预算、结构化列表查询预算、Identity/Reliability 定向测试和前端 bundle 预算。`make release-check` 也调用它。真实样本比较仍需在具备数据库、候选服务、数据集和受限管理员授权的环境中执行；`--include-admin-observability` 会额外采样固定且有界的管理员读取接口，不接受任意用户 ID 或查询参数。没有这份证据时，不能把 v13 标记为 Final。

仓库发布门禁还提供一个不依赖现有开发数据的隔离演练：

```bash
make v13-capacity-drill
```

它创建临时 PostgreSQL 数据库，按所有 migration 启动仅监听 `127.0.0.1` 的独立 API，使用种子管理员的短期会话采样固定 GET 路由，然后立即删除数据库、进程、二进制和授权文件。它不读取或删除现有 `campusos` 数据库中的 dead-letter、Session 或用户数据。可用 `V13_CAPACITY_API_PORT` 和 `V13_CAPACITY_SAMPLES` 调整隔离端口和 20-50 的样本数量，默认每轮采集 40 个样本；该上限受可靠任务查询真实的 `120 次/分钟/管理员` 限流约束，演练不会为测试关闭或放宽限流。发布检查默认执行该演练。

## 6. 故障处理原则

1. p95 回归先检查数据量、缓存预热、候选配置、查询预算和连接池等待，再定位代码。
2. 不通过提高默认连接数、关闭验证码限流、缩短审计保留、删除安全检查或忽略 dead-letter 来“通过”门禁。
3. metrics 快照不包含环境变量、DSN、Token、命令行参数、用户 ID、邮箱或业务正文；若报告出现这些内容，应停止发布并按安全事件处理。
4. 对登录、Refresh 和 Challenge 的写路径，使用现有 Go 集成测试与受控浏览器测试，不把真实密码或验证码嵌入容量工具。
