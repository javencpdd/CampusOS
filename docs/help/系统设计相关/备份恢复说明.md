# CampusOS 备份恢复说明

> 更新时间：2026-10-21（Asia/Shanghai）；当前格式 v3，整库恢复须认证隔离与可信本地授权复核。

当前完整操作合同见[官方备份恢复手册](../../../docs-site/operations/recovery.md)，Docker入口见[单主机Docker部署](../../../docs-site/deployment/docker.md)。以下入口均要求可信归档、预构建当前CLI与匹配的运行版本/migration，停止API及全部其它写入者；不提供在线跨数据库/文件一致性快照。

| 材料 | 恢复边界 |
| --- | --- |
| PostgreSQL | 用户/管理员域、会话、权限、业务、对象、v5安装/配置/Secret密文等，须与文件同一停写备份 |
| `PLUGIN_DATA_DIR/v5` | packages、prepared、data、checkpoints、restored-data五棵受管目录；插件检查点不恢复Grant/Consent |
| `data/personal-space` | Object字节与owner目录、文档/头像等；DB元数据、配额和物理字节需一同对账 |
| modules/migrations及普通data子目录 | 归档用于核对版本与恢复受管数据，不覆盖宿主源码/模块/迁移代码 |
| `.env`/`.env.docker`、Secret/MFA/JWT材料 | 独立受控保管，不进入普通归档，也不得放入data/config或插件数据树 |
| 宿主/guest镜像、构建产物 | 按固定版本/digest独立准备；恢复不自动拉取、构建或执行安装钩子 |

```bash
go build -o bin/campusosctl ./cmd/campusosctl
make backup
./scripts/restore.sh verify <明确的v3归档.tar.gz>
./scripts/restore.sh extract <明确的v3归档.tar.gz> <新的私有检查目录>
```

备份0700暂存、0600文件、同秒唯一原子发布，dump或严格校验失败不发布。校验拒绝两层链接/特殊文件/路径穿越/重复项、错误清单及超限/追加载荷；SHA并不认证来源。v1/v2与不同运行版本的旧库须走独立隔离迁移方案，不能仅改格式或直接导入后开服。

```bash
# 先核对DB/目录与同版本迁移；新空库须显式初始化当前migration。
./scripts/restore.sh apply <v3归档.tar.gz> --confirm
bin/campusosctl recovery status
# 按独立运维/撤权记录纠正不应保留的账号、角色与绑定，再重新取得盘点SHA。
bin/campusosctl recovery review --data-root data \
  --epoch <本次代次> --inventory-sha256 <实际核对的当前SHA> \
  --operator <可信运维引用> --reason <复核记录引用> --confirm-offline
```

恢复先写持久隔离标记，再恢复文件/SQL；旧User/Admin会话、刷新/恢复票据、机器凭据及委托废止，插件Grant/Consent与待执行操作撤回，出站绑定暂停。新JWT派生绑定随机实例认证代次。DB/文件与当前盘点不一致或未复核时启动拒绝；复核不自动重新批准插件/出站，也不通过bootstrap重建已移除角色。不要将手工执行SQL或健康接口可访问当成完整恢复证据。

Docker `backup`/`restore`停止API/Web/Admin，使用与API同UID的非root只读维护容器；恢复不构建、不拉取、不自动开服。准备匹配镜像、完成本地盘点复核后，维护者再显式启动。

```bash
make restore-drill
```

当前Linux演练使用独占PG16/网络/数据根、原生只读cmd/server及真实Docker，验证当前密钥正负例、签名包/对象对账、两用户与独立Admin浏览器及预先冻结的容量/恢复时限；不触碰当前实例。Windows实机按用户指示延期，不能由Linux或语法检查替代。
