# v13 管理员准入管理与本地恢复

> 适用版本：v0.13-dev（migration `000039_v13_admin_admission_operations`）  
> 面向对象：平台管理员、值班运维和权限设计人员

## 1. 先区分三件事

管理员能力由三个独立层共同决定：

```text
users / accounts                 这个人是谁，以及能否通过密码登录
identity_admin_accounts          这个人现在能否进入管理平面
roles / permission_definitions   进入后能执行哪些管理操作
```

给用户分配全局 `admin` 角色，不等于应该永远允许其进入 Admin。v13 的“管理员准入”页面只管理第二层，
不会复制密码、读取 Token，也不会替代角色与权限配置。

## 2. 管理后台如何操作

登录 `http://localhost:3001` 后，打开“用户与权限 -> 管理员准入”。页面显示的是非敏感投影：账号状态、
关联用户、最近管理员认证时间、变更原因、版本和变更时间。它不会显示密码、Refresh Token、MFA Secret 或
恢复码。

### 暂停一个管理员

1. 在列表中找到目标账号，确认用户名和邮箱。
2. 点击“暂停准入”。
3. 填写具体原因，例如“离职交接，等待权限复核”。原因会进入受保护的授权审计，不能留空。
4. 确认操作。成功后状态变为 `suspended`，目标的所有 Session 同时撤销。

暂停只禁止管理平面准入。该用户的普通资料、帖子、文件和普通用户登录不会被删除；是否还能执行普通用户
能力仍由用户状态、角色和各功能权限决定。

### 恢复一个管理员

只能恢复由本页面暂停的 `suspended` 账号：

1. 筛选“已暂停”。
2. 点击“恢复准入”，填写恢复原因。
3. 重新登录 Admin。旧 Session 保持撤销，避免被盗浏览器自动恢复。

`revoked` 不是“暂停”。它表示全局 `admin` 角色已撤销或不再有效，应先经过正常的角色分配流程重新建立
准入条件，不能用恢复按钮绕过角色治理。

## 3. 后端保护措施

- 每次暂停或恢复都要提交 `expected_version`。页面过期、其他管理员刚修改过状态时，服务返回冲突，绝不
  静默覆盖新状态。
- PostgreSQL 在事务中使用管理平面聚合锁并重新统计有效管理员，两个管理员同时暂停彼此时也不会留下零个
  可用管理员。
- 最后一个有效管理员和自我暂停都会被拒绝。有效管理员要求：活动准入、活动用户、有效邮箱凭据和全局
  `admin` 角色同时存在。
- 暂停、Session 撤销、必需授权审计和 Outbox 事件在同一个 Identity 可靠命令中完成。任一步失败都会回滚。
- 需要的权限分别是 `identity.admin_account.read`、`identity.admin_account.suspend`、
  `identity.admin_account.restore`、`identity.admin_account.read_audit`。默认 `admin` 角色拥有它们；自定义
  角色必须显式授予最小集合。

版主的板块作用域不属于管理员准入，不会因为本功能改变。

## 4. 紧急本地恢复

当所有管理平面准入记录都被暂停、但目标用户仍保有有效全局 `admin` 角色时，只能在可信服务器的交互式
终端使用受控 CLI。它没有 HTTP 入口，也不接受 Bootstrap Secret 的参数或管道输入：

```bash
campusosctl identity restore-admin-admission \
  --user-id 123 \
  --reason "incident INC-2026-0719 approved emergency recovery"
```

命令会要求：

1. 本地 TTY；非交互 shell、CI 和管道会被拒绝。
2. 精确输入 `RESTORE-ADMIN 123`。
3. 隐藏输入部署配置中的 `AUTH_BOOTSTRAP_ADMIN_SECRET`。
4. 连接 PostgreSQL，并写入可靠命令、必需审计和 Outbox 事件。

恢复后旧 Session 仍然撤销。应立即按事故流程重设管理员密码、检查角色和审计记录，并在 MFA 启用后完成
第二因子注册。不要直接 `UPDATE identity_admin_accounts`，也不要把 Bootstrap Secret 写到脚本、聊天记录、
环境导出包或工单正文中。

本地恢复只能恢复 `suspended`。已 `revoked` 的账号必须先恢复合法的全局角色来源，避免把紧急入口变成
绕过授权的后门。

## 5. API 与审计

管理 API 位于 Admin audience：

```text
GET  /api/v1/admin/identity/admin-accounts
GET  /api/v1/admin/identity/admin-accounts/:id
POST /api/v1/admin/identity/admin-accounts/:id/suspend
POST /api/v1/admin/identity/admin-accounts/:id/restore
GET  /api/v1/admin/identity/admin-accounts/audits
```

写请求体：

```json
{
  "expected_version": 3,
  "reason": "离职交接，等待权限复核"
}
```

审计页面和 `audits` API 只显示该生命周期的授权证据。原因属于受保护运营信息，应避免写入身份证号、密码、
Token、邮件验证码或其他敏感材料。

## 6. 升级与回滚

先备份并执行：

```bash
make migrate-up
make migrate-status
make identity-admin-account-check
```

`000039` 仅追加状态原因、操作者、时间、索引和 Permission Code，并替换角色同步函数以保留暂停状态。
旧二进制会忽略新列；新二进制要求 migration 已应用。隔离演练可执行 down/up，但生产故障优先 forward-fix，
不要删除管理员准入数据。

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 暂停按钮不可用 | 当前账号缺少 `identity.admin_account.suspend`，应由更高权限管理员授予或使用默认 admin。 |
| 返回版本冲突 | 刷新列表，查看最新状态和审计后再决定操作。 |
| 返回“最后一个有效管理员” | 先确保至少还有一个有效管理员；不要通过直接改表绕过。 |
| 恢复按钮不可用 | 目标是 `revoked` 或没有有效 admin 角色；先走角色治理流程。 |
| CLI 拒绝读取 Secret | 命令不是给自动化脚本使用的。使用可信本机终端并确认部署 Secret 已配置。 |
