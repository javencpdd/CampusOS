# 数据库管理指南

> 更新时间：2026-09-21 21:22（Asia/Shanghai）
> 适用版本：v1.1-dev

## 1. 数据库与迁移事实

CampusOS 使用 PostgreSQL 16+。当前顺序迁移为 `000001_v1_1_schema_baseline`、`000002_v1_1_ui_only_plugin_runtime` 和
`000003_v1_1_trusted_market_sources`。`000001` 从零建立完整 v1.1 业务结构、系统角色/权限参考数据、附件与 PDF
预览上下文；`000002` 允许 UI-only 外部插件 Runtime；`000003` 增加可信市场白名单及申请来源快照。不建立默认管理员、邮箱、密码或业务测试记录。

旧的 `000001`–`000011` 开发链已在项目所有者授权“测试数据可清空”后整合。已经记录旧名称或旧 checksum 的开发库不能继续 `up`，
而应在确认目标正确后 reset。生产或需保留数据的环境禁止按此路径重置。

## 2. Docker 开发连接

Docker 开发配置位于 `deploy/docker/.env.dev.local`。迁移脚本可使用容器内 `psql`，避免 Windows、Git Bash、WSL2 或 Linux
宿主的 `psql` 指向错误数据库：

```powershell
$env:CAMPUSOS_SKIP_DOTENV = "true"
$env:PSQL_MODE = "docker"
$env:POSTGRES_CONTAINER = "campusos-dev-postgres-1"
$env:DB_NAME = "campusos"
.\scripts\migrate.ps1 status
```

Linux/Git Bash 将最后一行换为 `./scripts/migrate.sh status`。用户名和密码仍从开发 Docker 配置读取；不要将 Secret 复制到命令历史、文档或 Git。

## 3. 日常命令

| 操作 | PowerShell | Linux/Git Bash | 作用 |
| --- | --- | --- | --- |
| 状态 | `.\scripts\migrate.ps1 status` | `./scripts/migrate.sh status` | 列出已应用版本与 checksum |
| 校验 | `.\scripts\migrate.ps1 check` | `./scripts/migrate.sh check` | 检查 UP/DOWN 配对和 checksum |
| 应用 | `.\scripts\migrate.ps1 up` | `./scripts/migrate.sh up` | 应用未执行 migration |
| 回滚 | `.\scripts\migrate.ps1 down` | `./scripts/migrate.sh down` | 回滚最高 migration |

`down` 会回滚当前最高 migration。`000003 down` 在存在市场来源或来源型申请时会明确拒绝，以保护审计证据；`000001 down`
才会删除全部应用表与参考数据。正常开发请优先使用隔离 drill，不要把 `down` 当作修复真实数据的工具。

## 4. 重置旧开发测试库

先用 `status` 确认数据库名与容器。确认数据可删除后：

```powershell
$env:CAMPUSOS_SKIP_DOTENV = "true"
$env:CAMPUSOS_ENV = "development"
$env:CAMPUSOS_RESET_CONFIRM = "campusos"
$env:PSQL_MODE = "docker"
$env:POSTGRES_CONTAINER = "campusos-dev-postgres-1"
$env:DB_NAME = "campusos"
.\scripts\migrate.ps1 reset
Remove-Item Env:CAMPUSOS_SKIP_DOTENV, Env:CAMPUSOS_ENV, Env:CAMPUSOS_RESET_CONFIRM, Env:PSQL_MODE, Env:POSTGRES_CONTAINER, Env:DB_NAME
```

`reset` 对指定库执行 `DROP SCHEMA public CASCADE` 后立即应用 baseline；它仅接受 `development` 或 `test`，且确认值必须与
`DB_NAME` 一致。开发库重建后，启动 API 以执行受控管理员 bootstrap 和内置插件注册。

## 5. 结构与数据验证

```bash
PSQL_MODE=docker POSTGRES_CONTAINER=campusos-dev-postgres-1 make v1-database-baseline-check
CAMPUSOS_SKIP_DOTENV=true PSQL_MODE=docker POSTGRES_CONTAINER=campusos-dev-postgres-1 \
  DB_NAME=campusos ./scripts/database-check.sh all
python migrations/tools/generate_er.py --check
python skills/sources/campusos-data-architecture-sync/scripts/check_architecture_sync.py --root .
```

第一条只使用并清理隔离临时库。第二条对显式的开发库执行审计、Schema 合同和索引卫生检查；不会清空数据，但可能建立临时检查视图。
ER 与管理端架构页都从仓库 Schema 生成或校验，不是实时数据浏览器。

## 6. 未来变更

下一项结构变更从 `000004_<描述>.up.sql` 与对应 `.down.sql` 开始。必须同步 Schema 合同、Admin `/architecture`、ER、架构文档、
进度记录和隔离库回归。不可通过修改已应用基线来让环境“临时通过”。
