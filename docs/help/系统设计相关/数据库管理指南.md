## 1. 当前结构与迁移事实

CampusOS 使用 PostgreSQL 16+。当前顺序迁移为 `000001`–`000036`，共132张表（130张业务/系统受管表及两张迁移执行器表）、143个外键。具体文件与职责以 [migrations/README](../../../migrations/README.md)及可执行SQL为准，不能将旧链最大编号当成新结构版本。

`000001_v1_1_schema_baseline` 是冻结的新基线；后续迁移包括独立Admin身份、v5安装与Operation、知识索引及受管AI。迁移播种角色、权限和策略参考数据，不创建固定密码的超级用户。应用的用户域开发兼容播种与独立管理域初始化是两种流程，见[独立管理员初始化](v1.2独立管理员初始化与账号隔离.md)。

旧v0.14的 `000001`–`000049`，以及其他旧名称/旧checksum的链，不能直接续跑当前 `up`。需保留业务语义的数据应另行设计导出、转换和验证。开发库允许默认数据时，可备份并保留旧库，在独立候选库建立新结构后切换；本机实例记录见下文及 [v1.2.174-dev](../../进度/v1.2-dev/v1.2.174-dev.md)。

## 2. Docker配置与连接

Docker开发配置事实源是被Git忽略的 `deploy/docker/.env.dev.local`。优先使用仓库启动器，它读取该配置、定位实际容器并调用迁移脚本：

```bash
./scripts/docker-dev.sh infra-up
./scripts/docker-dev.sh migrate status
./scripts/docker-dev.sh migrate check
./scripts/docker-dev.sh migrate up
```

PowerShell对应入口和参数见 [Docker开发指南](../../../docs-site/deployment/docker-development.md)。不要让根 `.env` 中的旧端口/DSN替代Docker配置。直接运行 `scripts/migrate.sh` 时须传入正确的容器、库名和凭据环境；实际密码、Token和密钥不进入命令历史、文档或Git。

默认PostgreSQL对宿主发布 `127.0.0.1:55432`，容器内仍是5432；实际用户名、库名和端口以本地配置为准。API、数据库、Redis和NATS保持回环，只有显式开放的UI供局域网访问。

## 3. 日常校验

`status` 列出已应用版本与checksum，`check` 检查UP/DOWN配对和已应用摘要，`up` 只执行未应用文件。不要为了让旧库通过而改写名称、版本、checksum或已应用SQL。

```bash
python3 skills/sources/campusos-data-architecture-sync/scripts/check_architecture_sync.py --root .
python3 migrations/tools/generate_er.py --check
```

实际目标还需运行 `scripts/database-check.sh all` 的数据库审计、Schema合同及索引卫生检查。Docker模式须传入实际 `PSQL_MODE=docker`、`POSTGRES_CONTAINER`、`DB_USER`、`DB_NAME` 等环境，避免误连其他实例；检查器可能建立临时视图，不会清空业务数据。Admin架构页与ER是仓库结构视图，不是实时业务记录浏览器。

## 4. 旧开发库重建边界

1. 确认开发/测试目标及所有者授权，停止连接该库的应用，明确容器、命名卷与文件目录。
2. 备份数据库和受管可变文件，部署密钥单独保管。实际还原到临时库核对表、行及序列，不凭dump文件存在判断可恢复。
3. 在独立候选库应用当前全量迁移，运行摘要、结构、外键和审计检查，启动当前API验证。
4. 切换时保留原库和旧文件。新身份可能复用旧ID，不能把旧个人目录直接暴露给新库；归档旧可变文件，保留仓库跟踪的公共默认资源。
5. 更新运行配置，按新库失效本项目派生缓存，验证登录、退出及浏览器。旧用户/帖子留在归档库，不把默认数据重建称作业务数据迁移。

`reset` 会对精确 `DB_NAME` 执行 `DROP SCHEMA public CASCADE`，只允许development/test且确认值须完全匹配；它不处理旧个人文件，也不替代备份。本机这次采用候选库验证后重命名切换，没有执行reset、删除原库或删除Docker卷。

正式整库恢复须遵循[备份恢复说明](备份恢复说明.md)的离线隔离、当前授权复核及密钥保管合同，不能导回旧会话/插件授权后直接对外服务。

## 后台 Chen ER 图（2026-10-30）

“数据架构 → 数据库关系”使用Chen实体—属性—联系记法，支持主键下划线、无向连接、1/N基数、单双线参与约束及已确认弱实体的双矩形/双菱形。选择实体查看局部关联，跨领域引用继续保留；使用分组、缩放、键盘选择或导出SVG查看细节。全部132个实体均有迁移证明的标识符，独立执行事件作为弱实体示例，帖子tags数组为多值属性示例；没有依据的派生属性或弱实体不自动加入。

结构元数据是公开的编译期Schema事实，不读取数据库行、配置文件、凭据值或物理本机路径。`schema.generated.json`仅包含字段名、标识符、多值标记和外键约束，不复制SQL默认值。更新迁移后执行 `make database-er`，同时刷新物理表结构产物和Admin Chen事实；`make architecture-check`或`make database-er-check`检查漂移。也可只生成/检查Chen事实：

```bash
python3 scripts/generate-architecture-schema.py
python3 scripts/generate-architecture-schema.py --check
python3 -m unittest scripts/test_architecture_schema.py
```

完整Schema的表结构图与后台Chen视图各按自身记法呈现；本次没有变更数据库表、数据或迁移。
