# 插件包治理与回滚说明

本文说明 v0.5 插件包导入治理的当前边界，重点覆盖预检、风险分级、版本比较、导入审计、手动回滚和签名预研。

## 1. 导入前预检

管理端导入插件包前会先调用：

```text
POST /api/v1/plugin-packages/precheck
```

预检会返回：

| 字段 | 说明 |
| --- | --- |
| `checksum` | 插件包 sha256 校验值 |
| `package_size` | 插件包大小 |
| `manifest` | `plugin.yaml` 解析结果 |
| `files` | 包内文件列表 |
| `permissions` | 展平后的 Host API 权限 |
| `risk_level` | `low`、`medium`、`high` 或 `unknown` |
| `risk_score` | 风险分数 |
| `risk_reasons` | 风险原因 |
| `existing_version` | 已安装同名插件版本 |
| `import_version` | 将导入的插件版本 |
| `version_change` | `new`、`upgrade`、`downgrade`、`same` 或 `unknown` |
| `signature_status` | `unsigned` 或 `present_unverified` |

## 2. 风险分级

风险分级不是安全承诺，只是帮助管理员快速判断是否需要更严格审查。

| 风险来源 | 说明 |
| --- | --- |
| gRPC Runtime | 可以启动本地插件进程，风险高于 Wasm |
| Wasm Runtime | 有沙箱边界，但仍要审查 Host API 权限 |
| `*.before` 事件 | 可以阻断宿主流程，需要关注 |
| `*:*` 权限 | 最高风险，导入前必须人工确认 |
| `role/user/config/plugin` 写权限 | 属于敏感资源写权限 |
| PostgreSQL storage | 代表插件希望访问更重的持久化能力 |
| 同名覆盖 | 会替换已有插件目录 |
| 版本降级 | 可能引入旧漏洞或丢失兼容变更 |

## 3. 管理端导入流程

推荐流程：

1. 在 `/plugins` 上传 `.campusos-plugin.tar.gz`。
2. 查看预检弹窗中的风险等级、权限、版本变化和 checksum。
3. 如果存在同名插件，确认是否开启“覆盖”。
4. 对高风险插件，先在本地或测试环境导入。
5. 确认后再点击“确认导入”。

导入成功或失败后，系统会写入插件日志：

```text
GET /api/v1/plugins/:name/logs
```

日志中包含操作者、checksum、包大小、风险等级、版本变化、是否覆盖和结果。

## 4. 手动回滚

当前 v0.5 没有强制保留所有历史插件包，因此回滚策略仍是手动执行。

推荐做法：

1. 导入覆盖前，先在管理端点击旧插件“导出”。
2. 保存旧包文件和 checksum。
3. 如果新插件导入后异常，先禁用新插件。
4. 上传旧包，开启“覆盖”，查看预检确认是预期版本。
5. 导入旧包后启用插件并查看日志。

命令行也可以回滚：

```bash
go run ./cmd/campusosctl plugin install old-plugin.campusos-plugin.tar.gz --dir data/plugins --replace
```

导入后重启后端或在管理端刷新插件列表。

## 5. 签名预研

v0.5 只检测签名文件是否存在，不执行强制验签。

预留签名文件名：

```text
SIGNATURE
signature.sig
plugin.sig
plugin.yaml.sig
.campusos/signature.json
```

后续可演进为：

| 阶段 | 目标 |
| --- | --- |
| v0.6 预研 | 明确签名格式、签名算法和信任根 |
| v0.6 实验 | 对官方内置插件包生成签名 |
| v0.7 候选 | 管理端展示验签结果和签名人 |
| 稳定期 | 对高风险插件强制验签或要求管理员二次确认 |
