> 对应计划：[CampusOS v1.2 版本优化计划](../../项目计划书v1/项目计划v1.2/00-v1.2版本优化计划书.md)

## 1. 先分清“谁在请求”和“请求什么”

现有平台 RBAC 决定用户/管理员能否操作版块、帖子和设置；插件三层授权决定某个插件版本能否代表用户使用宿主能力。v1.2 计划再给外部脚本/MCP 增加**独立的 Integration Principal**，并把资源所有权和状态复核纳入统一策略。三种身份不能因为都带一个 Token 就互换。完整规则见 [细粒度授权与资源策略](v1.2细粒度授权与资源策略设计.md)。

| 身份 | 从哪里来 | 可以获得什么 | 不可以获得什么 |
| --- | --- | --- | --- |
| 普通用户 | 已验证 Session | 自己的资源、允许看的社区内容 | 他人的私有文档、管理员操作 |
| 管理员 | 独立管理准入 + Session/MFA/平台 RBAC | 获批准的后台操作 | 将管理员 Session 交给插件或 MCP |
| 外部插件实例 | 已校验包、运行实例和宿主签发的短期身份 | Declaration、Admin Grant、User Consent 交集内的 Host API | 原始数据库、JWT、任意用户目录 |
| 集成 Principal（v1.2 目标） | 管理员/有权用户显式创建的命名凭据 | 指定端点、工具、来源范围内的只读调用 | 管理员万能权限、插件 Host Token、超出范围的来源 |
| 未登录访客 | 无 | 明确公开的资源 | 私有/未发布内容和受限工具 |

`Principal` 是“谁”，`Capability` 是“能做什么”，`Resource Scope` 是“能对哪些资料做”。一个凭据写着“可搜索”，不代表可以搜索任意人的个人文件。

## 2. 一次查询如何被允许

```text
普通用户查询 =
  Session 有效 ∩ 集合使用权 ∩ 原资源当前可读 ∩ 来源修订有效

外部集成查询 =
  凭据有效 ∩ 端点/工具/集合 Scope ∩ 原资源当前 ACL ∩ 公开发布版本

插件代表用户查询 =
  包声明 ∩ 管理员批准 ∩ 用户同意（需要时）
  ∩ 插件安装/版本/运行状态 ∩ 业务资源 ACL
```

“当前可读”按资源类型定义：公开集合要求发布且审核通过；本人私有集合无需把个人文档发布成公开内容，但仍须本人选择、修订有效和实时可读。

资源所属模块的应用服务读取真实 owner、版块、状态和修订，再将可信事实传给纯 Policy Port。授权核心不反向加载全部业务模块。浏览器传来的 `owner_id`、插件传来的 `user_id`、检索索引里的“公开”标记都不能直接成为授权依据。知识集合的访问范围还须与原帖/文档的当前 ACL 取交集；命中检索结果后，在返回标题、片段和引用链接前再次核验。下架或撤权后，即使旧索引尚未清完，也不能泄露片段。

当前 `internal/modules/features/mcp` 仅注册了管理端只读工具和审计路由，位于 Admin 权限守卫之后；这**不是** v1.2 拟建设的按来源范围发布的标准 MCP 端点。`internal/agentcontract` 也只是安全接口，不是已经运行的 Agent。

## 3. 管理员如何配置（v1.2 目标流程）

以下步骤是实施后的产品流程，不是当前管理台已经存在的菜单：

1. 在“知识来源”中创建一份**官方资料**，指定负责人、来源 URL 或受管文件、发布范围和复核日期；或逐个选择允许索引公开帖子的版块。默认草稿，不扫描全部板块和用户个人文档。
2. 审核内容并发布。服务端产生新修订，可靠事件驱动索引；管理台分别显示“已发布”和“索引就绪/失败”，不能把两者混成一个成功提示。
3. 用户在自己的“我的知识库”中逐项选择可解析的个人文档，默认仅本人可检索；允许外部模型读取还需本人对提供方和发送片段另行同意。
4. 要开放给外部工具时，创建命名 Integration Principal，选择可调用的只读工具、允许的**公开**来源集合、过期时间与限流。密钥只显示一次；数据库只保存摘要和辨识前缀。
5. 查看一次测试请求的授权结果、来源引用与低敏审计。用另一来源、下架内容和已撤销密钥做负向验证。
6. 不再需要时先撤销凭据或缩小 Scope；内容撤回先改权威发布状态，后台再异步清索引。不得仅通过删除向量或页面按钮隐藏完成撤回。

后台给用户分配版主角色时，必须另选具体版块；“能管理帖子”不代表“能给别人授予管理权”。配置保存时还会核对操作者的可委托动作、范围、期限和 MFA 条件。新方案允许重构旧表和旧界面，但这些安全限制不会因测试数据可清理而取消。

插件权限仍在“插件管理”中按**插件版本与 Capability**授予；用户在自己的插件页决定 Consent。创建外部集成凭据不会自动批准插件；给插件授予能力也不会给 MCP 客户端管理员身份。

## 4. 四个常见场景

**查校园办事资料**：普通用户搜索“补办学生证”。结果可以引用已发布的官方资料。草稿、已撤回的版本和无权版块即使存在索引也不显示。

**版主处理本板块内容**：版主角色的 `category` Scope 由服务端根据帖子所属板块核验。知识检索权限不能让版主跨板块治理帖子；这沿用现有平台 RBAC 边界。

**课表提醒插件**：插件声明 `schedule.self.read`，管理员批准，用户同意，宿主只返回当前会话用户的受限 DTO。外部 Integration Principal 不能借同一能力读取课表。

**外部 MCP 客户端**：客户端持命名凭据调用只读搜索工具；服务端同时检查工具和来源 Scope。来源下架或凭据轮换后，下一次调用应立即拒绝并记录不含正文/密钥的审计。

## 5. 模块职责与失败处理

| 模块 | 负责什么 | 失败时做什么 |
| --- | --- | --- |
| Identity Core | Session、平台角色、Integration Principal、凭据摘要、吊销 | 无身份或摘要不匹配直接拒绝 |
| Community / Personal Documents / User Storage | 分别负责社区内容、个人文档业务规则、受管字节/owner/配额 | 下架/回收/跨 owner 立即拒绝 |
| Plugin Platform | 包身份、版本、Grant、Consent、运行状态、Host API | 权限交集缺项时返回稳定拒绝码 |
| Knowledge Feature | 来源、修订、索引代次、检索及引用校验 | 索引失败保留失败状态；不能改写来源 ACL |
| MCP/外部 Adapter | 协议、工具白名单、端点 Scope、限流 | 格式错误、越界或撤销时拒绝，不返回内部错误/Secret |

审计保留 actor、动作、来源 ID、判定、原因码、trace 和时间；默认不保存正文、检索片段、原始请求参数、Token 或用户私有文件名。现有管理端 MCP 审计会保存工具参数，v1.2 实施时必须按字段白名单收口，并添加“敏感参数不落库”的负向测试。

## 6. 开发者验收清单

- 两名用户分别查自己的资源；互相请求私有 ID 返回拒绝，且响应不含标题/片段。
- 外部凭据限一个来源，换来源 ID、猜测资源 ID、伪造 owner 均失败；轮换/撤销立即生效。
- 插件升级扩大 Capability 后，旧 Grant/Consent 不自动批准新增能力。
- 发布内容被撤回时，在索引清理之前也无法被结果列表、引用详情和 MCP 读取。
- 失败日志和管理端审计不显示 Token、原文、宿主路径或数据库连接。

与数据库结构、一次性测试重建及索引状态有关的解释见 [v1.2 数据库与索引重建入门](v1.2数据库与索引重建设计入门.md)；帖子/板块/个人文档的 RAG 流程见 [校园知识库与 RAG 接入](v1.2校园知识库与RAG接入设计.md)。
