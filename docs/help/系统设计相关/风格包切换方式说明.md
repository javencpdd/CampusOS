# CampusOS 风格包切换方式说明

> 适用阶段：v0.13-dev
> 更新时间：2026-07-22

本文集中说明当前 CampusOS 中“个人主页”和“用户前台首页”的风格切换方式、适用场景、操作入口和对应 API。新建或重新应用的 Resource Package 必须满足 [v13 风格包双端交付标准](v13风格包双端交付标准.md)，不能仅靠单端预览通过。

## 1. 当前支持的切换对象

| 对象 | 归属 Feature/资源类型 | 主要页面 | 说明 |
| --- | --- | --- | --- |
| 个人主页 `/u/:username` | Personal Space + Space Style Package | 用户前台 `/space/settings` | 用户自己的公开主页风格、HTML/CSS 片段、拓展风格包、回滚和恢复默认 |
| 用户前台首页 `/` | Appearance + Homepage Package | 管理后台 `/appearance` | 管理员统一配置首页风格、背景、检索标签和拓展风格包 |
| 完整用户前台 | Appearance + Theme Package | 用户头像菜单 `/appearance` | 管理员提供 `target: web` 包；每个用户按自己的本地选择切换，Admin 管理端不受影响 |

注意：

- Personal Space 被停用后，个人主页页面与设置 API 会被 Gate 拒绝，但 User Storage、课表和富文本数据不会删除。
- Appearance 被停用后，页面使用安全默认外观；资源文件和用户偏好不会删除。
- `data/plugins/<plugin>/` 只保存 External Plugin 实现。全部风格包统一保存在 `data/resources/{themes,homepage-packs,space-style-packs}/`。
- Built-in Feature 的本地状态数据使用 `data/module_data/<feature>/`，不能与外部插件数据混放。
- 未筛查 HTML 和同源任意 JavaScript 仍不开放。`v0.6.4-dev` 起可使用 `sandbox-worker.v1` 特效和 CampusStyleSDK 只读能力，详见 [风格包能力边界与 CampusStyleSDK 说明](风格包能力边界与CampusStyleSDK说明.md)。

个人主页包归主页所有者。任何访问者打开用户 A 的主页时，系统都读取并显示 A 自己保存的风格，不会使用访问者或其他用户的主页风格。

## 2. 个人主页风格切换

### 2.1 使用内置 JSON 风格包

适合快速切换个人主页布局和基础样式。

用户入口：

```text
http://localhost:3000/space/settings
```

操作方式：

1. 进入“主页设置”。
2. 在风格包区域选择内置示例风格。
3. 点击“校验”或“预览”确认效果。
4. 点击“应用”写入当前个人主页。

后端示例文件：

```text
data/module_data/personal-space/styles/*.space-style.json
```

相关 API：

```text
POST /api/v1/spaces/me/styles/validate
POST /api/v1/spaces/me/styles/preview
POST /api/v1/spaces/me/styles/apply
POST /api/v1/spaces/me/styles/export
```

### 2.2 使用受限 HTML 风格片段

适合在当前风格基础上增加一段更自由的页面结构。

用户入口：

```text
http://localhost:3000/space/settings
```

操作方式：

1. 在“HTML 风格”区域点击“生成示例”。
2. 修改生成的 HTML。
3. 点击“检测 HTML”。
4. 检测通过后点击“应用 HTML”。

相关 API：

```text
POST /api/v1/spaces/me/styles/html/validate
GET  /api/v1/spaces/me/styles/html-example
POST /api/v1/spaces/me/styles/html/apply
```

该方式会把片段写入当前 `style_manifest.custom_html`。如果同时需要独立 CSS，更推荐使用下面的拓展风格包。

### 2.3 上传 zip 拓展风格包

适合把风格作为文件夹开发，再压缩上传。标准为 `page-style-pack.v1`。

用户入口：

```text
http://localhost:3000/space/settings
```

操作方式：

1. 在“拓展风格包”区域点击“当前风格示例”，下载示例 zip。
2. 解压后修改 `templates/page.html`、`templates/card.html`、`styles/theme.css`、`assets/` 和 `config.schema.json`。
3. 重新压缩为 zip。
4. 在页面中点击“选择 zip”。
5. 点击“筛查”。
6. 筛查通过后点击“应用拓展包”。

标准目录结构：

```text
style.yaml
README.md
preview.png
templates/page.html
templates/card.html
assets/cover.webp
assets/avatar-frame.png
styles/theme.css
config.schema.json
```

`style.yaml` 必须包含：

```yaml
schema_version: page-style-pack.v1
target: personal-space
name: clean-blog
version: 0.1.0
entry: templates/page.html
templates:
  - name: page
    path: templates/page.html
  - name: card
    path: templates/card.html
styles:
  - styles/theme.css
preview_image: preview.png
config_schema: config.schema.json
assets:
  - name: cover
    path: assets/cover.webp
    type: image/webp
  - name: avatar-frame
    path: assets/avatar-frame.png
    type: image/png
```

相关 API：

```text
POST /api/v1/spaces/me/styles/packs/validate
GET  /api/v1/spaces/me/styles/packs/example
GET  /api/v1/spaces/me/styles/packs/example.zip
POST /api/v1/spaces/me/styles/packs/apply
```

### 2.4 应用源码目录拓展风格包

适合开发者直接在项目源码中维护风格文件夹，然后在用户端选择，或用 API 应用到当前登录用户。

源码目录：

```text
data/resources/space-style-packs/<风格包名>/
```

当前内置示例：

```text
data/resources/space-style-packs/clean-blog/
```

用户端操作：

1. 进入 `/space/settings`。
2. 在“拓展风格包”的“源码目录风格包”区域点击“刷新”。
3. 选择筛查通过的风格包，例如 `clean-blog`。
4. 点击“应用源码目录”。

API 示例：

```bash
curl -X POST http://localhost:8080/api/v1/spaces/me/styles/packs/apply-source \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"clean-blog"}'
```

接口：

```text
GET  /api/v1/spaces/me/styles/packs/sources
POST /api/v1/spaces/me/styles/packs/apply-source
```

列表接口会读取源码目录并返回每个包的筛查状态；应用接口会再次执行同一套筛查，通过后再应用。

### 2.5 回滚和恢复默认

每次应用新风格前会保存快照。

用户入口：

```text
http://localhost:3000/space/settings
```

操作方式：

| 操作 | 结果 |
| --- | --- |
| 回滚 | 恢复上一次应用风格前的快照 |
| 恢复默认 | 清空当前风格 manifest，回到系统默认个人主页风格 |

相关 API：

```text
POST /api/v1/spaces/me/styles/rollback
POST /api/v1/spaces/me/styles/default
```

## 3. 用户前台首页风格切换

首页风格由 Appearance Built-in Feature 的 `homepage` 配置区控制，只有管理员可改。`homepage-customizer` 只是旧 API 兼容别名。

管理入口：

```text
http://localhost:3001/appearance
```

进入方式：

1. 登录管理后台。
2. 打开“外观与风格包”。
3. 在“首页风格包”区域调整配置、导入或切换资源包。

### 3.1 修改结构化配置

适合快速调整首页标题、背景图、遮罩、版块检索标签等。

可配置项包括：

| 配置项 | 说明 |
| --- | --- |
| `hero_title` | 首页标题 |
| `hero_subtitle` | 首页副标题 |
| `background_image` | 首页背景图 URL |
| `background_overlay` | 背景遮罩色 |
| `show_category_tags` | 是否显示版块检索标签 |
| `category_tag_limit` | 最多显示多少个版块标签 |
| `custom_html_enabled` | 是否渲染受限 HTML |
| `custom_html` | 受限 HTML 片段 |
| `custom_css` | 受限 CSS 片段 |

保存后，用户前台首页通过：

```text
GET /api/v1/home/config
```

读取最新配置。

### 3.2 上传 zip 首页拓展风格包

适合把首页样式作为文件夹维护，再由管理员上传应用。

管理入口：

```text
http://localhost:3001/appearance -> 首页风格包
```

操作方式：

1. 点击“当前示例”，下载基于当前首页配置生成的示例 zip。
2. 解压后修改 `templates/page.html` 和 `styles/theme.css`。
3. 重新压缩为 zip。
4. 点击“选择 zip”。
5. 点击“筛查”。
6. 筛查通过后点击“应用”。

`style.yaml` 必须包含：

```yaml
schema_version: page-style-pack.v1
target: homepage
name: campus-hero
version: 0.1.0
entry: templates/page.html
templates:
  - name: page
    path: templates/page.html
  - name: card
    path: templates/card.html
styles:
  - styles/theme.css
preview_image: preview.png
config_schema: config.schema.json
assets:
  - name: cover
    path: assets/cover.webp
    type: image/webp
  - name: avatar-frame
    path: assets/avatar-frame.png
    type: image/png
```

相关 API：

```text
POST /api/v1/home/style-packs/validate
GET  /api/v1/home/style-packs/example
GET  /api/v1/home/style-packs/example.zip
POST /api/v1/home/style-packs/apply
```

应用后会写入 Appearance Feature 的 `homepage` 配置区：

```text
custom_html_enabled
custom_html
custom_css
active_style_pack
style_pack_version
```

### 3.3 应用源码目录首页风格包

适合开发者直接修改项目中的首页风格包目录，然后由管理员在后台应用。

源码目录：

```text
data/resources/homepage-packs/<风格包名>/
```

当前内置示例：

```text
data/resources/homepage-packs/campus-hero/
```

管理端操作：

1. 进入 Admin `/appearance` 的首页风格包区域。
2. 在“源码目录风格包”下拉列表中刷新并选择筛查通过的包，例如 `campus-hero`。
3. 点击“应用源码目录”。

API 示例：

```bash
curl -X POST http://localhost:8080/api/v1/home/style-packs/apply-source \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"campus-hero"}'
```

接口：

```text
GET  /api/v1/home/style-packs/sources
POST /api/v1/home/style-packs/apply-source
```

列表接口会返回每个首页源码目录风格包的筛查状态；管理端只允许选择并应用筛查通过的包。

## 4. 风格包筛查规则

`page-style-pack.v1` 的 zip 上传和源码目录应用会共用同一套筛查规则。

| 项目 | 规则 |
| --- | --- |
| target | 个人主页必须是 `personal-space`，首页必须是 `homepage` |
| 路径 | 只允许安全相对路径，拒绝绝对路径和路径穿越 |
| 文件数量 | 最多 80 个文件 |
| zip 总大小 | 最多 1MB |
| 单文件大小 | 最多 256KB |
| CSS 大小 | 合并后最多 20000 字节 |
| 扩展名 | 允许 `yaml`、`yml`、`md`、`html`、`css`、`png`、`jpg`、`jpeg`、`webp`，以及根目录 `config.schema.json` |
| HTML | 对每个 `.html` 文件执行检测，拒绝脚本、事件处理器、不安全 URL、过大和过深片段 |
| CSS | 对每个 `.css` 文件执行检测，拒绝 `@import`、`url(`、`expression(`、`javascript:`、`data:`、固定/粘性定位等 |
| 配置 Schema | `config_schema` 必须指向 `config.schema.json`，文件必须是可解析 JSON，`type` 如声明则必须为 `object` |

筛查失败时不会应用，也不会覆盖当前正在使用的风格。

## 5. 推荐使用方式

| 场景 | 推荐方式 |
| --- | --- |
| 普通用户快速换个人主页外观 | 使用 `/space/settings` 内置 JSON 风格包 |
| 普通用户想轻量增加自定义内容 | 使用 HTML 风格片段，先检测再应用 |
| 用户或开发者要维护完整模板和 CSS | 下载示例 zip，修改后上传筛查并应用 |
| 开发者维护内置个人主页风格 | 修改 `data/resources/space-style-packs/<name>/`，在 `/space/settings` 选择或通过 `apply-source` 应用 |
| 管理员快速调整首页文字和背景 | 修改 Appearance 的 Homepage 结构化配置 |
| 管理员切换首页整体风格 | 上传首页拓展风格包 zip 或应用源码目录 |
| 想撤回个人主页新风格 | 使用回滚 |
| 想回到系统默认个人主页 | 使用恢复默认 |

## 6. 当前边界

- 个人主页有回滚和恢复默认；首页资源包由 Appearance 管理并保留应用快照/回滚入口。
- 源码目录列表只做当前目录实时筛查和选择，不保存审核结论；后续如果做风格包市场，需要增加持久化审核状态和版本索引。
- CSS 筛查当前较保守，不允许 `url()` 和外部资源引用；后续如支持本地图片资源，需要增加资源映射、CSP 和更细粒度 CSS parser。
- 风格包市场、站内分享、管理员审核和版本回滚列表仍是后续任务。
