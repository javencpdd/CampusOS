# v0.13 管理员准入管理与本地恢复

> 更新时间：2026-10-26 01:44（Asia/Shanghai）
> 当前说明：保留旧 User 关联准入的兼容边界，本机恢复采用 v1.2 独立 Admin 域
> 面向对象：平台管理员、值班运维和权限设计人员

## 1. 先区分两个身份域

当前独立 Admin 的数据边界为：

```text
admin_accounts / admin_credentials       独立管理员账号与密码凭据
admin_mfa_totp / admin_mfa_tickets        独立认证器及 MFA 票据
admin_sessions / admin_recovery_tickets  独立会话及恢复票据
admin_roles / admin_role_bindings        独立角色绑定
```

普通 User 仍使用 `users`、`accounts`、User MFA/会话和 User 角色。两域即使碰巧有相同 ID 或邮箱，也不能相互查找或回退认证；给 User 分配全局 `admin` 角色不等于创建独立 Admin。

`/admin-admission` 页面和 `/api/v1/identity/admin-accounts` 系列接口保留的是旧 User 关联准入兼容能力，对应 `identity_admin_accounts`。页面里的 `user_id` 只属于该兼容模型，不能作为独立 Admin 本机恢复的目标 ID。

## 2. 当前独立 Admin 的状态管理

独立 Admin 生命周期写接口使用当前本域身份、权限、MFA 和严格请求体：

```text
POST /api/v1/admin/identity/accounts
POST /api/v1/admin/identity/accounts/:id/suspend
POST /api/v1/admin/identity/accounts/:id/revoke
POST /api/v1/admin/identity/accounts/:id/restore
```

状态变更请求填写非敏感的 `reason`。服务端重新读取当前权限与账号事实并执行版本 CAS，不能根据按钮可见性推定允许。

- `active`：账号可按本域凭据登录，具体管理能力仍取决于当前角色和 MFA。
- `suspended`：可经受控恢复重新激活，不恢复此前会话。
- `revoked`：吊销终态；在线恢复、角色重新分配和本机恢复都不能将其重新激活。

账号创建回执中的不透明 `account_id` 应保留在受控运维记录中。不能把 User ID、旧准入页的关联用户编号或相同邮箱推导成独立 Admin ID。

## 3. 旧准入兼容页的范围

`/admin-admission` 中的暂停/恢复、版本冲突和最后有效管理员保护，仍按旧 User 关联准入合同执行；其 `expected_version`、User 全局角色和准入投影不代表独立 Admin 账号、密码、MFA 或会话已经改变。

维护独立 Admin 时应使用上一节的本域生命周期接口，或下面的受控本机命令。不要把恢复旧 `identity_admin_accounts` 记录当成恢复独立 Admin，也不要直接改表绕过事务与审计。

## 4. 独立 Admin 紧急本机恢复

### 恢复已暂停账号

在可信服务器的真实交互式终端执行：

```bash
campusosctl identity restore-admin-admission \
  --account-id adm.example \
  --reason "incident INC-2026-0719 approved emergency recovery"
```

`adm.example` 仅为示例，应替换为受控记录中的实际独立 Admin ID。旧 `--user-id` 参数已经退役。

命令要求：

1. 目标是现有、`suspended`、拥有有效本域密码凭据的独立 Admin；已 `revoked` 的账号会被拒绝。
2. `--reason` 非空、单行、不超过 500 字符，不包含密码、Token 或线下证明原文。
3. 本地 TTY 中逐字输入 `RESTORE-ADMIN adm.example`。
4. 隐藏输入部署配置中已设置的 `AUTH_BOOTSTRAP_ADMIN_SECRET`。
5. 当前实例数据库与必需事务审计可用。

配置里存在 Secret 不替代操作者的终端证明。命令不接受 Secret 参数、管道、CI 输入或环境值替代隐藏输入。

成功只把本域账号从 `suspended` 恢复为 `active`，保留原有角色绑定；零权限账号不会因此获得管理权限。该账号的全部旧 Admin 会话、刷新凭据、MFA 票据和恢复票据失效，必须重新登录。不会修改 User 的密码、邮箱、准入、角色或会话。

### 恢复系统 Admin 密码或丢失的 TOTP

```bash
campusosctl identity reset-password --email admin@campusos.local --reason "approved system Admin password recovery"
campusosctl identity reset-mfa --account-id adm.example --reason "lost independent Admin authenticator"
```

密码命令只接受固定 `admin@campusos.local`，省略 `--email` 仍是该邮箱；要求确认 `RESET admin@campusos.local`、隐藏输入部署 Bootstrap Secret，再两次隐藏输入一致的新密码。它只恢复已有、活跃的独立系统 Admin，不能重置普通 User 或任意其他邮箱。

MFA 命令要求目标独立 Admin 活跃、具备有效本域凭据和待确认或已启用 TOTP 因子；逐字确认 `RESET-MFA adm.example` 后隐藏输入 Bootstrap Secret。它关闭该 Admin 的 TOTP，使旧 Admin MFA/恢复票据和全部会话失效，保留角色；不清理或修改同号 User 的因子、恢复码或会话。详细流程见 [TOTP 与本机恢复](v0.13TOTP多因素认证与恢复说明.md)。

## 5. 事务、票据与证据

本机服务固定使用独立 Admin 仓储，先锁定账号、凭据和 TOTP 当前事实，再执行状态或凭据 CAS、消费旧票据及撤销会话，最后复核事实。它不新增账号、不授予角色，也不复活已吊销账号。

这些变更与 `identity.admin_local.password_reset`、`identity.admin_local.account_restore` 或 `identity.admin_local.totp_recovery` 必需命令审计及 Outbox 同事务提交。审计或其他步骤失败会整体回滚；旧票据保留为已消费证据，不通过删除安全记录掩盖操作。

当前独立 Admin 公网恢复票据消费 HTTP 尚未开放。`admin_recovery_tickets` 的存在只是仓储能力，不代表已交付远程邮件找回、用户辅助 Case 或插件 Host 恢复入口。普通 User 自助找回及管理员辅助恢复 Case 见[账号恢复与邮箱绑定](v0.12账号恢复与邮箱绑定说明.md)，本域会话/MFA 见[独立管理员 SPA 合同](../../api/v1.2独立管理员SPA当前身份与会话合同.md)。

## 6. 部署与排障

部署执行当前完整迁移链；旧 v0.13 `000039` 已整合进冻结基线，不能把历史 1–3 基线演练当作当前部署迁移集合。恢复前确认连接配置对应目标实例，并保留运维工单及审计证据。

| 现象 | 原因与处理 |
| --- | --- |
| CLI 不接受 `--user-id` | 改用受控记录中的独立 Admin `--account-id`，不能使用旧兼容页的 User ID。 |
| 目标不可恢复 | 确认目标存在、状态符合命令条件且具有本域凭据；已吊销账号是终态。 |
| 恢复后没有管理权限 | 命令不授予角色，须走正常独立 Admin 授权流程。 |
| 旧浏览器不能继续使用 | 这是必需撤销结果，应重新登录并完成 MFA。 |
| 拒绝读取证明或密码 | 使用真实本机 TTY；确认部署 Bootstrap Secret 已配置，不使用管道或 CI。 |
| 事务或审计不可用 | 排查依赖后重试，不直接改凭据、票据、角色或会话表。 |
