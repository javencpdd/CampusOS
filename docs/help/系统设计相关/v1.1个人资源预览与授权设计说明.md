> 正式计划：[CampusOS v1.1 正式项目计划](../../项目计划书v1/项目计划v1.1/00-v1.1版本计划书.md)  
> 创建时间：2026-09-11；更新时间：2026-09-11

## 1. 为什么使用“用户资产”而不是“资源”

CampusOS 已经用 Resource Package 表示主题、风格包等“无 Runtime、由系统安装和发布”的资源包。用户上传的
文档、图片和音视频具有 owner、配额、隐私、回收站和分享语义，不能进入 Resource Package 生命周期。

v1.1 将这类对象称为 **User Asset（用户资产）**，但本版只建设图文附件所需的最小模型：

```text
User Asset：用户看到和管理的稳定对象
Asset Version：该对象的不可变版本
Storage Object：真实字节、哈希、大小和 Provider 位置
Resource Package：系统安装的主题/风格等包，与 User Asset 无关
```

当前代码已经有 `storage_objects`、Personal Documents、图片清单和插件受管文件。v1.1 不再要求一次迁移全部业务，
而是先完成图文文章附件和 PDF Viewer；头像、Personal Documents、MP3/MP4 预览、分享及全部插件文件收敛顺延。

## 2. 模块职责

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| Core User Storage | Object、流式 IO、SHA-256、配额 Reservation、本地 Provider、对账 | 分享、插件 Consent、文档编辑 |
| Minimal Personal Assets | 附件 Asset 身份、owner、状态、选择清单、引用保护 | 本版迁移全部个人空间数据 |
| RichText Feature | 图片排版、附件绑定/排序、文章状态联动 | 把附件路径直接写进 HTML |
| Plugin Platform/UI Runtime | UI v1/v2、Surface、Presentation、Invocation、生命周期 | 任意 URL、主动弹窗、未受信任脚本注入 |
| PDF Viewer Plugin | PDF.js 翻页、缩放、搜索和错误态 | 直接读取数据库、路径、JWT 或永久 URL |
| Web Host | 附件区/卡片、宿主弹窗/全屏/同源新标签页 | 最终授权判断 |
| Admin | 配额、策略、隔离和低敏诊断 | 默认查看用户文件内容 |

## 3. 核心数据关系

```text
users
  1 -> N user_assets
user_assets
  N -> 1 storage_objects
richtext_articles
  N <-> N user_assets (through richtext_article_attachments)
plugin_versions + users + assets
  -> short-lived plugin_ui_invocations
```

- Asset 保存稳定名称、类型、owner 和生命周期；v1.1 附件不引入非必要的版本模型。
- Storage Object 继续承担配额和物理状态，但不承担分享业务。
- Attachment Binding 保存文章、Asset、显示名和顺序；不把附件 URL 写入正文 HTML。
- Invocation 只保存/表达打开 PDF Surface 所需的短期上下文，不是文件访问凭据。
- 文档、头像和其他插件文件的统一模型属于后续版本，不作为 v1.1 Final 前置条件。

## 4. 生命周期与配额

| 状态 | 含义 | 是否可预览 | 是否计入配额 |
| --- | --- | --- | --- |
| `active` | 正常可用 | 是 | 是 |
| `trashed` | owner 已移入回收站 | 仅 owner 可恢复性查看 | 是 |
| `quarantined` | 校验失败或被管理员隔离 | 否 | 是，直至受控删除 |
| `deleted` | 元数据完成删除流程 | 否 | 物理字节删除成功后不计 |

默认用户配额仍为 50 MiB，管理员可调整。附件按实际 Object 字节计量；一份 Asset 绑定多篇文章不复制字节。
回收站仍占用空间，因此“空间不足”的提示必须同时返回已用、剩余、单文件上限和建议操作。

硬删除必须经过引用检查：正在作为当前头像、帖子图片、RichText 资产、文档版本或插件数据使用的对象不能静默删除。

## 5. 在线预览怎样工作

### 5.1 统一过程

```text
用户点击图文文章的 PDF 附件
  -> 宿主验证文章和附件并创建短期 invocation_id
  -> 宿主以 modal/fullscreen/new-tab 打开 PDF Viewer Surface
  -> PDF.js 带当前 Session 发起 Range 请求
  -> 服务端再次验证文章/绑定/Asset/插件状态并流式读取 Storage Object
```

每个 Range 请求都重新检查授权，不生成长期公开 URL。服务端应支持 `ETag`、`If-Range`、`206 Partial Content`
和无效范围的 `416`，并保持常量级缓冲，不能为预览一个 PDF 把整个文件读入服务端内存。

### 5.2 格式边界

| 格式 | v1.1 方式 | 限制 |
| --- | --- | --- |
| PDF | 仓库锁定版本的 PDF.js + 认证 Range | 禁止外部 URL/PDF JavaScript；不支持编辑 |
| MP4 | 认证附件下载 | v1.1 不在线预览；以后可增加独立 Viewer |
| MP3 | 认证附件下载 | v1.1 不在线预览；以后可增加独立 Viewer |
| TXT/Markdown/CampusDoc | 继续使用 Content Editor Core 安全渲染 | 不执行原始 HTML/脚本 |
| DOC/DOCX、XLS/XLSX | 认证附件下载 | v1.1 不在 API 内加入 Office Converter |
| ZIP/RAR | 认证附件下载 | 服务端不解压、不内联渲染 |

预览会把原始内容传给浏览器，因此不能承诺 DRM 或“用户绝对无法保存”。“允许预览但不允许下载”只能是界面意图，
不是可证明的安全边界；v1.1 ACL 统一使用 `read`。

## 6. 上传与内容安全

1. 先限制 HTTP 请求体，再解析 multipart。
2. 同时检查扩展名、声明 MIME 和内容 magic，三者冲突时拒绝。
3. 对 PDF、MP4/MP3、Office/OLE/OOXML、ZIP/RAR 做有界签名检查；损坏或异常文件拒绝或隔离，压缩包不解压。
4. 内容响应设置 `X-Content-Type-Options: nosniff`、同源和私有缓存策略。
5. PDF.js 从本地依赖加载，不从第三方 CDN 动态执行脚本。
6. v1.1 不宣称已经提供病毒扫描、DLP 或版权识别；这类能力进入后续版本。

## 7. 图文附件的访问规则

附件继承文章访问策略，而不是单独创建跨用户分享：

1. 草稿只有作者可以读取附件。
2. 私密文章沿用现有私密访问判定。
3. 已发布文章按 G0 冻结的文章读者策略提供附件；默认安全方案要求登录。
4. 管理员下架、文章删除或 Asset 隔离/回收后，旧地址也必须立即拒绝。
5. 从文章移除附件只删除 Binding，不静默删除用户原文件；硬删除前检查全部引用。

指定用户分享、匿名链接、分享密码、公开外链和多人协作不属于 v1.1。

## 8. 插件如何获得授权

PDF Viewer 不能因为是第一方插件就获得整个个人空间。一次读取需要同时满足：

```text
插件声明 PDF 附件预览 Capability
  AND 管理员批准该插件版本
  AND 用户通过明确点击打开 Surface
  AND 宿主签发未过期/未重放的 Invocation Context
  AND 插件/版本/Runtime 正常
  AND 当前用户可读取文章、附件绑定和 Asset
```

候选能力：

| Capability | 说明 |
| --- | --- |
| `plugin_ui.surface.open` | 声明 Surface 可以由宿主响应用户操作打开；不授予数据权限 |
| `article_attachment.self.preview` | 在短期 Invocation 和文章访问判定下预览一个 PDF 附件 |

Host API 不返回路径、JWT 或永久 URL。每个 PDF Range 请求都回到主业务 API 重新授权；插件升级/停用、文章下架、
Asset 隔离或 Invocation 过期后，下一调用立即失败。v1.1 不向插件开放分享管理、任意资产遍历或删除。

Plugin UI v2 提供宿主管理的 modal、drawer、fullscreen 和 CampusOS 同源 new-tab。后台事件不能主动打开界面；
插件不能提交任意 URL 或直接 `window.open()`。首版 PDF Viewer 是编译期白名单 `trusted-module`。真正第三方前端
Bundle 必须等待独立的 sandbox-iframe、CSP、签名和严格消息 Bridge，不得动态导入主站。

## 9. 配置方式（规划项）

具体变量名在 G0 合同冻结后进入 `.env.example` 和 Docker 示例。建议配置类别如下，当前不要自行添加未实现变量：

| 类别 | 规划用途 | 规则 |
| --- | --- | --- |
| 附件限制 | 单文件、每篇数量、每篇总字节、允许类型 | 必须小于等于用户剩余配额；服务端为最终事实 |
| Range | 单次分块上限、超时和并发 | 防止慢客户端和大范围滥用 |
| Preview | PDF.js 开关、允许格式 | 关闭后安全降级为认证下载 |
| Plugin UI | Invocation TTL、允许 Presentation、单用户并发 Surface | 只能由明确用户操作触发 |
| 插件读取 | Range/调用频率和 Invocation 使用规则 | 绑定插件版本、用户、文章、Asset 和 Capability |
| 清理 | 回收站保留期、purge 批量大小 | 默认 dry-run；引用或对账异常时停止 |

配置修改后的加载方式必须在实现时逐项标明：纯 Web 配置是否热加载、API 环境变量是否需 `docker-dev.* up`，
依赖/Dockerfile 变化是否需 `rebuild`，不能笼统要求每次改源码都重建镜像。

## 10. 常见使用场景

### 场景 A：图文文章加入附件

图片可设为封面或插入正文；PDF、MP3、MP4、Office、ZIP/RAR 进入独立附件区。发布后详情页显示附件卡片，
正文 HTML 中不保存附件路径。

### 场景 B：弹窗预览 PDF

用户点击“预览”，宿主创建短期 Invocation，并在 modal 或移动端 fullscreen 中打开 PDF Viewer。每次 Range 请求
重新检查文章和附件；失败时显示中文原因并提供认证下载降级。

### 场景 C：新标签页阅读 PDF

宿主打开 CampusOS 同源 `/extensions/...` 页面，URL 只携带随机 Invocation ID，并使用 `noopener,noreferrer`；
不跳转插件进程地址，也不暴露 JWT、storage key 或文件路径。

### 场景 D：文章被管理员下架

已有 PDF Viewer 标签页的下一次 Range 请求立即失败；普通下载同样拒绝。作者和管理员只获得受权限约束的诊断信息，
不能依靠旧附件 URL 绕过文章状态。

### 场景 E：用户空间不足

系统返回单文件限制、每篇附件数量/总量、已用/配额/剩余字节和中文建议。回收站仍占空间；管理员可以调整配额，但不能通过删账本
掩盖真实文件。

## 11. 数据库与 reset 边界

当前 migration 已到 `000005`。v1.1 从 `000006` 追加，不改写已经冻结的文件。项目所有者已确认现有数据都是测试数据，
因此可在 development/test 环境执行双确认 reset，不为旧测试文件设计 backfill；但 reset 必须打印精确数据库并在
production/staging 硬拒绝。

计划 migration、最终表和索引以正式计划第 7 节为准。实际实施时还必须同步：

- `migrations/README.md`、ER PNG/SVG/中文说明；
- `scripts/schema-contract.sql`、database audit/hygiene；
- Admin `/architecture`；
- 备份恢复、配额对账和当前架构文档。

## 12. 当前使用者应注意

本文描述 v1.1 目标，不表示当前系统已经支持图文附件、Plugin UI v2 或 PDF Viewer Plugin。MP3/MP4 在线预览、
跨用户分享、全部个人资产统一和第三方 UI Bundle 沙箱也不属于本版交付。当前能力仍以现有 RichText 图片、
v0.14 Personal Documents、Plugin UI v1、v1.0 插件授权代码和生成 API 合同为准。
