## 1. 为什么使用“用户资产”而不是“资源”

CampusOS 已经用 Resource Package 表示主题、风格包等“无 Runtime、由系统安装和发布”的资源包。用户上传的
文档、图片和音视频具有 owner、配额、隐私、回收站和分享语义，不能进入 Resource Package 生命周期。

v1.1 将这类对象称为 **User Asset（用户资产）**，但本版只建设图文附件所需的最小模型：

```text
User Asset：用户看到和管理的稳定对象（本版仅限图文附件）
Storage Object：真实字节、哈希、大小和 Provider 位置
Resource Package：系统安装的主题/风格等包，与 User Asset 无关
```

当前 v1.1 clean baseline 已包含 `user_assets`、`richtext_article_attachments`、`plugin_ui_invocations`、低敏
`asset_lifecycle_audits`，以及 Personal Documents 的 owner-only PDF 预览 `personal_document_id` 上下文；它不导入
或合并用户文档/版本历史数据。头像、MP3/MP4 预览、分享及全部插件文件收敛仍顺延。

## 2. 模块职责

| 模块                       | 负责                                                              | 不负责                                           |
| -------------------------- | ----------------------------------------------------------------- | ------------------------------------------------ |
| Core User Storage          | Object、流式 IO、SHA-256、配额 Reservation、本地 Provider、对账   | 分享、插件 Consent、文档编辑                     |
| Minimal Personal Assets    | 附件 Asset 身份、owner、状态、选择清单、引用保护                  | 本版迁移全部个人空间数据或提供跨用户分享         |
| RichText Feature           | 图片排版、附件绑定/排序、文章状态联动                             | 把附件路径直接写进 HTML                          |
| Plugin Platform/UI Runtime | v4 release、Surface、Presentation、Invocation、生命周期           | 任意 URL、主动弹窗、未受信任脚本注入             |
| PDF Viewer v4 UI-only 包   | PDF.js 翻页、缩放、页码跳转、键盘、目录、搜索和错误态             | 直接读取数据库、路径、JWT 或永久 URL             |
| Web Host                   | 附件区/卡片、宿主弹窗/全屏/新标签壳页、受控 Bridge                | 最终授权判断                                     |
| Admin                      | 配额、策略、隔离/恢复/清除、低敏聚合与审计诊断                    | 默认查看用户文件内容、文件名、对象路径或下载地址 |

## 3. 核心数据关系

```text
users
  1 -> N user_assets
user_assets
  N -> 1 storage_objects
richtext_articles
  N <-> N user_assets (through richtext_article_attachments)
plugin_versions + users + assets
  -> short-lived plugin_ui_invocations
plugin_versions + users + personal_documents
  -> short-lived plugin_ui_invocations（仅当前 owner 的 PDF）
user_assets + users
  -> asset_lifecycle_audits（仅状态、操作者类型、原因和时间）
```

- Asset 保存稳定名称、类型、owner 和生命周期；v1.1 附件不引入非必要的版本模型。
- Storage Object 继续承担配额和物理状态，但不承担分享业务。
- Attachment Binding 保存文章、Asset、显示名和顺序；作者可只改显示名而不改变源 Asset，不把附件 URL 写入正文 HTML。
- Invocation 只保存/表达打开 PDF Surface 所需的短期上下文，不是文件访问凭据。对 Personal Documents，它只保存
  document ID，读取时再由 Personal Documents Service 取得当前版本并复核 owner；不保存或泄露 Object ID、路径。
- 文档、头像和其他插件文件的**统一**模型属于后续版本；本次 owner-only PDF 入口不改变这一边界。

## 4. 生命周期与配额

| 状态          | 含义                                       | 是否可预览            | 是否计入配额           |
| ------------- | ------------------------------------------ | --------------------- | ---------------------- |
| `active`      | 正常可用                                   | 是                    | 是                     |
| `trashed`     | owner 已移入回收站                         | 仅 owner 可恢复性查看 | 是                     |
| `quarantined` | 校验失败或被管理员隔离                     | 否                    | 是，直至受控删除       |
| `purging`     | 已进入两阶段物理清除，等待对象或元数据完成 | 否                    | 是；不能恢复或绑定     |
| `deleted`     | 元数据完成删除流程                         | 否                    | 物理字节删除成功后不计 |

默认用户配额仍为 50 MiB，管理员可调整。附件按实际 Object 字节计量；一份 Asset 绑定多篇文章不复制字节。
回收站仍占用空间，因此“空间不足”的提示必须同时返回已用、剩余、单文件上限和建议操作。

硬删除必须经过引用检查：正在作为当前头像、帖子图片、RichText 资产、文档版本或插件数据使用的对象不能静默删除。
v1.1 管理端只显示按状态/字节、操作类型和过期 Invocation 的聚合；操作者输入的原因限制在 500 字符，审计表不保存
原始文件名、owner、Object Key、绝对路径或内容。清除先将 Asset 置为 `purging`，再删除 Object，最后标记
`deleted`；若对象已经删除而元数据提交未完成，重复确认只会完成元数据收口，不会重建或暴露对象。

普通用户可在图文编辑页“我的附件与回收站”中切换可用附件与回收站：被文章引用的附件会被拒绝回收，移入回收站后
仍计入配额，恢复后才能再次绑定文章。

附件选择器与个人资产面板使用 owner-scoped keyset 分页，每次加载 50 项；还有下一页时点击“加载更多附件”。
服务端接受 1～200 的 limit，返回 next_cursor；游标不是访问凭据，切换用户或回收站状态后必须重新查询。
列表是实时查询而非冻结快照，文件状态变化后应刷新。

## 5. 在线预览怎样工作

### 5.1 已实现过程

通用上下文已提取到 `internal/platform/pluginui`；业务解析只支持文章附件、个人资产、个人文档。
既有 `context_digest` 校验插件与资源对象版本，升级或更换文档版本后重新打开；原来没有摘要的临时上下文同样重新签发。
预览失败时，“下载”调用独立宿主认证接口，仍按文章阅读权或 owner 判断，不绕过下架、隔离或跨用户限制。
到期超过 24 小时的上下文会清理；清理后从来源页面重新下载。移除文章附件会同时使其相关预览上下文失效。

```text
用户点击图文文章的 PDF 附件、个人空间 Asset 或“我的文档”的 PDF
  -> 宿主验证文章和附件并创建短期 invocation_id
  -> 宿主以 modal/fullscreen/new-tab 打开 PDF Viewer Surface
  -> PDF.js 带当前 Session 发起 Range 请求
  -> 服务端再次验证文章/绑定/Asset/插件状态并流式读取 Storage Object
```

每个 Range 请求都会重新检查文章/绑定/Asset，或 Personal Document 的 owner、当前版本格式和状态，不生成长期公开 URL。服务端已通过 `http.ServeContent`
提供 `ETag`、`If-Range`、`206 Partial Content` 和无效范围的 `416`；Object Port 返回可 seek 的流，避免为 Range
响应把整份 PDF 读入 API 内存。PDF.js 使用当前 Session 的 `Authorization` 请求头和 64 KiB Range 分块。

插件版本、授权记录和短期委托使用 PostgreSQL `BIGINT` Snowflake ID。它们在 API JSON 中必须以**十进制字符串**返回和传回路径参数，不能在浏览器中转成 JavaScript `number`；否则超过 `Number.MAX_SAFE_INTEGER` 的版本 ID 会被静默舍入，授权接口会查到一个不存在的版本并错误报告“该版本没有声明能力”。

### 5.2 格式边界

| 格式                   | v1.1 方式                             | 限制                                    |
| ---------------------- | ------------------------------------- | --------------------------------------- |
| PDF                    | 仓库锁定版本的 PDF.js + 认证 Range    | 禁止外部 URL/PDF JavaScript；不支持编辑 |
| MP4                    | 认证附件下载                          | v1.1 不在线预览；以后可增加独立 Viewer  |
| MP3                    | 认证附件下载                          | v1.1 不在线预览；以后可增加独立 Viewer  |
| TXT/Markdown/CampusDoc | 继续使用 Content Editor Core 安全渲染 | 不执行原始 HTML/脚本                    |
| DOC/DOCX、XLS/XLSX     | 认证附件下载                          | v1.1 不在 API 内加入 Office Converter   |
| ZIP/RAR                | 认证附件下载                          | 服务端不解压、不内联渲染                |

预览会把原始内容传给浏览器，因此不能承诺 DRM 或“用户绝对无法保存”。“允许预览但不允许下载”只能是界面意图，
不是可证明的安全边界；v1.1 ACL 统一使用 `read`。

## 6. 上传与内容安全

1. 先限制 HTTP 请求体，再解析 multipart。
2. 同时检查扩展名、声明 MIME 和内容 magic，三者冲突时拒绝。
3. 对 PDF、MP4/MP3、Office/OLE/OOXML、ZIP/RAR 做有界签名检查；DOCX/XLSX 除 ZIP 签名外还检查 `[Content_Types].xml` 与各自的 `word/document.xml`/`xl/workbook.xml` 容器项。压缩包不解压、不执行其内容；损坏或异常文件会被拒绝，且未成为可见 Asset 前会清理临时 Object。
4. 内容响应设置 `X-Content-Type-Options: nosniff`、同源和私有缓存策略。
5. PDF.js 从本地依赖加载，不从第三方 CDN 动态执行脚本。
6. v1.1 不宣称已经提供病毒扫描、DLP 或版权识别；这类能力进入后续版本。

## 7. 图文附件的访问规则

附件继承文章访问策略，而不是单独创建跨用户分享：

1. 草稿只有作者可以读取附件。
2. 私密文章沿用现有私密访问判定。
3. 已发布文章按 G0 冻结的文章读者策略提供附件；默认安全方案要求登录。
4. 管理员下架、文章删除或 Asset 隔离/回收后，旧地址也必须立即拒绝。
5. 从文章移除附件只删除 Binding，不静默删除用户原文件；硬删除前检查全部引用。

指定用户分享、匿名链接、分享密码、公开外链和多人协作不属于 v1.1。

## 8. 自包含 PDF Viewer 的授权边界

PDF Viewer 是受版本控制的 `campusos.pdf-viewer` v4 UI-only 包，运行时只发现其校验后的 `.installed` release，
不接受用户上传源码作为执行入口。它不能因为是插件就获得整个个人空间；一次读取需要同时满足：

```text
用户通过明确点击打开 Surface
  AND 宿主签发未过期的 Invocation Context
  AND `campusos.pdf-viewer` UI-only Runtime 已启用且 release 完整
  AND Manifest Declaration ∩ Admin Grant ∩ User Consent 已允许当前用途
  AND 当前用户可读取文章附件，或作为 owner 读取个人 Asset / Personal Document
```

宿主不会向 Viewer 返回路径、JWT 或永久 URL。每个 PDF Range 请求都回到主业务 API 重新授权；Feature 或插件停用、
管理员 Grant/用户 Consent 撤销、文章下架、Asset 隔离、个人文档变更/删除或 Invocation 过期后，下一调用立即失败。为让 PDF.js 取得多个
字节范围，同一 Invocation 在十分钟有效期内可被同一用户重复用于 Range 读取；它不是一次性下载令牌，每一次读取都会
重新执行文章、Binding、Asset、Feature、插件状态和授权判定。v1.1 不向第三方插件开放分享管理、任意资产遍历或删除。

通用宿主提供 modal、drawer、fullscreen 和新标签壳页。后台事件不能主动打开界面；插件不能提交任意 URL 或直接
`window.open()`。当前 PDF 包通过独立 Origin sandbox iframe、CSP、签名/摘要 release 和严格消息 Bridge 加载，
不会动态导入主站；iframe 只可请求 `resource.describe/readRange`，其余方法一律拒绝。

### 8.1 三层授权的实际执行顺序

1. API 启动时只发现 `campusos.pdf-viewer` 的校验后不可变 release，并将最小授权 adapter 的不可变版本和 Capability 写入 `plugin_versions`、`plugin_capability_declarations`；版本、包摘要或声明变化必须提升版本，不能覆盖旧版本。
2. 管理员在“外部插件运行管理 → 授权”对该**精确版本**逐项写入 `plugin_admin_grants`。这是全站总开关；拒绝或撤销后，后续调用立即失效。
3. 用户在“插件中心 → PDF 文档预览 → 查看并授权”，仅对需要个人同意的 `self` 能力写入自己的 `plugin_user_consents`。用户无需生成 API Key 或长期 Token。
4. 用户点击预览时，宿主先检查登录身份、文章/附件或个人 Asset/文档的业务读取权和插件运行状态；再调用 `AuthorizationService` 计算 `Manifest Declaration ∩ Admin Grant ∩（需要时的 User Consent）∩ Scope ∩ Runtime`。
5. 通过后才签发十分钟、同用户绑定的 Invocation；每次 PDF Range 读取仍重复第 4 步。后台任务才使用短期 Delegation，数据库只存其摘要，不能代替管理员 Grant 或用户 Consent。

## 9. 配置方式与当前限制

单文件 20 MiB、每篇 10 个附件、每篇总计 40 MiB 是当前服务端常量；用户总配额继续复用 Core User Storage
的 50 MiB 默认值及现有管理员调整能力。PDF Viewer 是否可用取决于 `campusos.pdf-viewer` 的已校验 release、运行状态、
Grant/Consent 和业务访问判定；实际文件读取权限永远由宿主服务端决定。
当前不提供将这些附件阈值改写为环境变量的入口，避免配置与数据库/前端提示不一致。

| 类别      | 规划用途                                              | 规则                                                          |
| --------- | ----------------------------------------------------- | ------------------------------------------------------------- |
| 附件限制  | 单文件、每篇数量、每篇总字节、允许类型                | 必须小于等于用户剩余配额；服务端为最终事实                    |
| Range     | 单次分块上限、超时和并发                              | 防止慢客户端和大范围滥用                                      |
| Preview   | PDF.js 开关、允许格式                                 | 关闭后安全降级为认证下载                                      |
| Plugin UI | Invocation TTL、允许 Presentation、单用户并发 Surface | 只能由明确用户操作触发                                        |
| 插件读取  | Range/调用频率和 Invocation 使用规则                  | 绑定第一方 Viewer、用户、文章、Asset 与用途；每次读取重新授权 |
| 清理      | 回收站保留期、purge 批量大小                          | 默认 dry-run；引用或对账异常时停止                            |

配置修改后的加载方式必须在实现时逐项标明：纯 Web 配置是否热加载、API 环境变量是否需 `docker-dev.* up`，
依赖/Dockerfile 变化是否需 `rebuild`，不能笼统要求每次改源码都重建镜像。

## 10. 常见使用场景

### 场景 A：图文文章加入附件

图片可设为封面或插入正文；PDF、MP3、MP4、Office、ZIP/RAR 进入独立附件区。发布后详情页显示附件卡片，
正文 HTML 中不保存附件路径。

### 场景 B：弹窗预览 PDF

用户点击“预览”，宿主创建短期 Invocation，并在 modal 或移动端 fullscreen 中打开 PDF Viewer。每次 Range 请求
重新检查文章和附件；失败时显示中文原因并提供认证下载降级。

### 场景 C：新标签页阅读 PDF

宿主打开 CampusOS 同源 `/extensions/...` 页面，URL 只携带随机 Invocation ID，并使用 `noopener,noreferrer`；
不跳转插件进程地址，也不暴露 JWT、storage key 或文件路径。

### 场景 D：文章被管理员下架

已有 PDF Viewer 标签页的下一次 Range 请求立即失败；普通下载同样拒绝。作者和管理员只获得受权限约束的诊断信息，
不能依靠旧附件 URL 绕过文章状态。

### 场景 E：用户空间不足

系统返回单文件限制、每篇附件数量/总量、已用/配额/剩余字节和中文建议。回收站仍占空间；管理员可以调整配额，但不能通过删账本
掩盖真实文件。

## 11. 数据库与 reset 边界

插件存储以 [插件存储边界与平台通用数据设计](插件存储边界与平台通用数据设计.md) 为最新约束：
只用预先开放的现有平台表、自身 SQLite 和文件型 config。v1.1 基线中的 Invocation 表属于平台结构，插件本身
不能创建表或执行 SQL。通用平台表不足可由平台修改，当前测试数据可按确认目标清空。
子进程环境白名单、文件配置规范与阅读进度受控存储已实现；目标环境 OS/网络隔离和通用预览服务仍待实现。

当前 migration 为单一 `000001_v1_1_schema_baseline`。项目所有者已确认现有数据都是测试数据，
因此旧链必须在 development/test 环境执行双确认 reset 后重建，不为旧测试文件设计 backfill；但 reset 必须打印精确
数据库并在 production/staging 硬拒绝。基线进入共享或不可丢弃环境后，下一项结构变化从 `000002` 追加。

计划 migration、最终表和索引以正式计划第 7 节为准。实际实施时还必须同步：

- `migrations/README.md`、ER PNG/SVG/中文说明；
- `scripts/schema-contract.sql`、database audit/hygiene；
- Admin `/architecture`；
- 备份恢复、配额对账和当前架构文档。

## 12. 当前使用者应注意

当前系统已支持图文文章上传/选择/排序/移除附件、个人回收站恢复、认证下载、图文附件/个人 Asset/Personal Documents
PDF.js 预览、
modal/drawer/fullscreen/new-tab、兼容 UI v1/v2 Contract，以及低敏管理端隔离/恢复/清除操作台。MP3/MP4 在线播放、
跨用户分享、全部个人资产统一、第三方 UI Bundle sandbox 与正式环境容量/恢复/浏览器证据仍不属于已完成交付，
不能宣称 `v1.1 Final`。
