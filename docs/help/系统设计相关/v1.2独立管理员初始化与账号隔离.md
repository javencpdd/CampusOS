# v1.2 独立管理员初始化与账号隔离

> 更新时间：2026-10-29（Asia/Shanghai）
> 适用范围：当前v1.2开发候选；默认账号与本机新增流程按用户确认的易用性要求调整，见[v1.2.181-dev](../../进度/v1.2-dev/v1.2.181-dev.md)。

## 1. 默认超级管理员

正常应用首次启动时，如果整个管理域没有任何账号，会自动创建：

| 项目 | 初始值 |
| --- | --- |
| 用户名 | `admin` |
| 密码 | `admin` |
| 联系邮箱 | `admin@campusos.local` |
| 角色 | 独立管理域 `security_admin` |
| 登录入口 | `http://开发机地址:3001/login` |

直接使用用户名登录即可，不需要先设置初始化凭证或运行脚本。已有任何管理域账号时不再默认播种，包括停用或撤销的账号；已经修改的密码不会因重启、重新构建镜像或新增管理员而恢复为初始值。测试profile由测试夹具管理，恢复审查中的实例不会通过默认播种重新开通管理员。

默认账号由应用服务在事务中创建，迁移 `000009` 仍只创建表与角色参考数据，不写入账号或固定密码。初始化受数据库事务锁、角色绑定、必需审计及Outbox保护；失败时整体回滚。

## 2. 修改管理员密码

1. 登录3001管理端。
2. 点击页面右上角“修改密码”，进入 `/account/security`。
3. 输入当前密码、新密码及确认密码；新密码为6–64字节。
4. 成功后重新登录。

修改仅针对当前登录的独立管理员，不接受指定其他账号。当前密码错误或请求失败不会改动密码；成功时更新哈希并注销该管理员的全部会话及未消费恢复票据，其他账号和系统配置保持原样。已绑定认证器且部署要求MFA时，先通过页面上的“管理员认证”；未绑定的初始账号可先修改密码。不会因此关闭MFA或删除认证器绑定。

## 3. 按需新增超级管理员

默认账号已经可以登录；需要另一个安全管理员时，在部署主机的仓库根目录运行：

```bash
python3 scripts/bootstrap-admin.py
```

默认使用完整Docker开发部署：脚本定位当前项目正在运行的API容器，通过其现有数据库环境执行本机CLI。宿主机只需Python、Docker与Compose；Go命令在已有API开发容器内运行。脚本依次询问新管理员用户名、邮箱和两次不回显密码，**不再询问 `AUTH_ADMIN_BOOTSTRAP_SECRET`**。

- 新增账号独立保存密码哈希，并绑定 `security_admin`；与默认管理员可以同时存在。
- 用户名为2–64位，小写字母/数字开头，允许小写字母、数字、点、下划线和短横线；邮箱与用户名分别唯一。
- 账号已存在时拒绝覆盖。要改已有密码，使用管理端“修改密码”或现行本地恢复流程。
- 密码通过子进程标准输入传给本机CLI，不作为命令参数、环境变量或临时请求文件保存。
- 本机CLI需要部署者现有的Docker/数据库控制权限，不作为HTTP接口或插件能力开放。
- 命令只新增账号、凭据、角色绑定和必需审计，不改 `.env.dev.local`、JWT、SMTP、MFA、主题、业务数据或已有账号，不要求为创建账号重启服务。
- 超时或结果不确定时先核对账号结果，不自动重试。

自定义Docker项目和配置分别沿用 `CAMPUSOS_DOCKER_PROJECT`、`CAMPUSOS_DOCKER_DEV_ENV`，也可显式传 `--env-file 路径`。不要选择另一套项目或数据库。

原生部署使用现有进程环境及本机Go工具链：

```bash
python3 scripts/bootstrap-admin.py --native
```

如果API由私有运行JSON启动，可显式复用它的环境：

```bash
python3 scripts/bootstrap-admin.py --runtime-profile .campusos/private/api-lan.json
```

私有JSON须为普通文件、权限0600，脚本拒绝符号链接；真实值不显示。当前本机已经切换完整Docker，默认使用第一条命令；历史宿主JSON不会自动影响Docker容器。

## 4. 管理员与用户的存储关系

两域共用一个PostgreSQL数据库，身份数据分别存放：

| 项目 | 用户域 | 管理域 |
| --- | --- | --- |
| 账号与密码 | `users / accounts` | `admin_accounts / admin_credentials` |
| 会话 | `sessions` | `admin_sessions` |
| 角色绑定 | `roles / user_roles` | `admin_roles / admin_role_bindings` |
| MFA/恢复 | 用户域安全表和票据 | `admin_mfa_* / admin_recovery_tickets` |
| 登录API | `/api/v1/auth/login` | `/api/v1/admin/identity/login` |

管理域账号没有到 `users/accounts` 的账号外键，Token签发与验证分域。同一邮箱或数字ID不会合并身份；给普通用户赋予旧 `admin` 角色不会自动创建管理域账号。历史用户域 `admin@campusos.local / Admin@123456` 与当前管理端默认 `admin / admin` 是两套凭据。

## 5. 配置的当前作用

| 配置 | 作用 |
| --- | --- |
| `AUTH_BOOTSTRAP_ADMIN_SECRET` | 历史用户域引导及本地恢复的部署凭据；不是当前默认管理员登录密码 |
| `AUTH_ADMIN_BOOTSTRAP_SECRET` | 仅旧回环HTTP首次初始化接口的请求证明；空值关闭该兼容接口，启用时8–4096字节且不得复用前者 |
| `AUTH_ALLOW_DEVELOPMENT_DEFAULT_ADMIN` | 仅development的历史用户域兼容路径，不决定独立管理域默认账号 |
| `AUTH_ADMIN_MFA_REQUIRED` | 默认true；显式false关闭独立管理端敏感操作二次认证要求，其他鉴权保持 |

普通默认登录和新增管理员脚本不依赖 `AUTH_ADMIN_BOOTSTRAP_SECRET`，也不会清空或改写它。该字段是字符串，不能用 `false` 代替空值。实际Docker配置是本机私有 `deploy/docker/.env.dev.local`；[模板及字段说明](../../../deploy/docker/.env.dev.example)只提供参考，已有本地文件不会自动被模板覆盖。

修改部署配置值后执行 `docker-dev.* up`；仅修改注释无需重启，单独 `docker restart` 不会重读env文件。当前本机Docker/宿主运行方式见[数据库管理指南](数据库管理指南.md)。

## 6. 管理员MFA

默认开启TOTP二次认证。部署者可在实际配置设置 `AUTH_ADMIN_MFA_REQUIRED=false` 关闭；只有明确false关闭，未设置、空值或非法值保持开启。变更后执行 `up`。管理端“管理员MFA策略”展示当前生效状态；浏览器页面不能自行降低部署要求。

开启时：登录后点击“管理员认证”或引导按钮 → 开始配置认证器 → 使用添加链接或手动密钥添加TOTP → 输入6位验证码绑定 → 等待下一组验证码确认身份 → 重试敏感操作。当前认证有效期15分钟；绑定时已用过的验证码不可立即复用。

关闭开关不会删除绑定或伪装成已通过MFA，密码、会话、权限、资源范围、CSRF及必需审计仍校验。用户域MFA、明确要求MFA的受托授权，以及已有认证器的持有证明不随该开关改变。

## 7. 兼容HTTP首次初始化与恢复

原来的回环HTTP初始化保留为兼容入口：`POST /api/v1/admin/identity/bootstrap` 仍要求精确的一份 `X-CampusOS-Bootstrap-Secret`，且仅允许没有有效安全管理员时首次创建。已有默认管理员后应使用上面的本机新增命令，不能用兼容接口覆盖它。

需要验证旧HTTP客户端时显式运行 `python3 scripts/bootstrap-admin.py --http`，可搭配 `--runtime-profile` 或 `--port`；它先检查API健康，再隐藏输入证明和密码，禁止代理、重定向与自动重试。该模式沿用首次条件，不是默认新增流程。

遗失已有管理员密码或认证器时使用现行独立Admin本地恢复命令；新增命令不会重置已有账号，也不会修改用户域数据。代码入口：[部署创建服务](../../../internal/modules/core/identity/service/admin_provision_service.go)、[本人改密服务](../../../internal/modules/core/identity/service/admin_password_service.go)、[初始化脚本](../../../scripts/bootstrap-admin.py)。


运行参数可在后台“系统与运维 → 运行配置”编辑并保存重启，使用独立的读取/管理权限，沿用当前MFA策略。默认security_admin具有该权限，配置修改不重建账号、不重设密码。参见[后台运行配置](../../../docs-site/deployment/runtime-config.md)。


2026-10-30：运行配置的保存/重启弹窗可选择“管理员密码”或“MFA验证码”，默认再次输入当前管理员密码。尚未绑定验证器也可使用密码方式，只授权本次配置操作；账号密码、当前会话MFA强度及其他管理操作的验证规则保持。见[后台运行配置](../../../docs-site/deployment/runtime-config.md)。
