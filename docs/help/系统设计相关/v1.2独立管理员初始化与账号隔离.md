# v1.2 独立管理员初始化与账号隔离

> 更新时间：2026-10-27（Asia/Shanghai）
> 适用范围：当前 v1.2 开发候选；初始化必须由部署者自行授权执行。

## 1. 为什么没有默认超级用户

管理端不再复用用户账号或固定开发密码。`000009` 迁移只建立管理域表和 `security_admin` 角色，不播种账号、凭据或会话。第一位安全管理员必须显式创建；启动应用、注册用户或给用户分配旧 `admin` 角色，都不会自动开通管理域。

两域目前位于同一个 PostgreSQL 数据库，**不是两个物理数据库**：

| 项目 | 用户域 | 管理域 |
| --- | --- | --- |
| 账号与密码 | `users / accounts` | `admin_accounts / admin_credentials` |
| 会话 | `sessions` | `admin_sessions` |
| 角色绑定 | `roles / user_roles` | `admin_roles / admin_role_bindings` |
| MFA/恢复 | 用户域自己的安全表和票据 | 独立 `admin_mfa_* / admin_recovery_tickets` |
| 登录 API | `/api/v1/auth/login` | `/api/v1/admin/identity/login` |

管理域账号表没有到 `users/accounts` 的外键。Token 的 issuer、audience、key id 和验证入口分域，用户 Token 不能登录管理端。物理拆库不是当前实现；如未来拆库，还需重新设计连接、事务、必需审计和 Outbox 边界。

## 2. 两个初始化配置不能混用

| 配置 | 当前作用 |
| --- | --- |
| `AUTH_BOOTSTRAP_ADMIN_SECRET` | 历史用户域引导及本地恢复的部署凭据；不会启用独立管理域初始化 |
| `AUTH_ADMIN_BOOTSTRAP_SECRET` | 独立管理域首次初始化的请求证明；默认空、关闭；16–4096 字节，且不得与前者相同 |
| `AUTH_ALLOW_DEVELOPMENT_DEFAULT_ADMIN` | 仅 development 的历史用户域兼容路径；不创建 `admin_accounts` |
| `AUTH_ADMIN_MFA_REQUIRED` | 默认 true；部署者显式 false 可关闭独立管理端敏感操作的二次认证要求，不关闭其他鉴权 |

设置管理域初始化凭证不会自动创建账号，也不会作为新管理员的登录密码。建议使用至少 32 个随机字节，在部署秘密管理中保存；不要将真实值提交到 Git 或写入本文。

生产兼容启动校验仍要求旧 `AUTH_BOOTSTRAP_ADMIN_SECRET` 至少 16 字符；关闭首次管理域初始化只清空新的 `AUTH_ADMIN_BOOTSTRAP_SECRET`，不要误删仍被用户域兼容启动/本地恢复使用的旧配置。

### 2.1 配置字段的中文说明与正确格式

[Docker 开发模板](../../../deploy/docker/.env.dev.example)已为每个字段补充中文说明；本机实际使用的是被 Git 忽略的 `deploy/docker/.env.dev.local`，不要用模板覆盖已有本地配置或公开其真实凭据。

- 字段必须写成 `KEY=value`，使用半角等号；只写 `AUTH_ADMIN_BOOTSTRAP_SECRET` 字段名不会设置初始化凭证。
- `AUTH_ADMIN_BOOTSTRAP_SECRET=` 表示空值，管理域初始化保持关闭；需要首次创建时由部署者填写符合上节要求的独立凭证。
- 管理员的用户名、邮箱、登录密码仍在下面的交互请求中设置，不是 `POSTGRES_USER`、`EMAIL_SMTP_USERNAME` 或任一初始化凭证。
- 仅修改 `#` 注释无需重启；修改配置值后执行 `docker-dev.* up` 重新应用环境，无须因此 `rebuild`，单独 `docker restart` 不会重读 env 文件。
- 遇到 `bootstrap denied`，先核对新字段是否已填写、长度是否合规、是否执行过 `up`，以及请求输入是否与新字段一致；已有有效安全管理员时该入口也会拒绝，不能拿它重置密码。

## 3. Docker 开发环境首次初始化

先在被 Git 忽略的 `deploy/docker/.env.dev.local` 中设置独立 `AUTH_ADMIN_BOOTSTRAP_SECRET`，然后从仓库根目录执行 `./scripts/docker-dev.ps1 up`（PowerShell）或 `./scripts/docker-dev.sh up`。仅重启容器不会重新读取 env 文件。

确认 API 健康后，在开发机本地 PowerShell 执行下面的交互式示例；它不会猜测或显示已有密码：

```powershell
$bootstrapProof = Read-Host '输入配置中的管理域初始化凭证' -AsSecureString
$newPassword = Read-Host '为新管理员设置登录密码' -AsSecureString
$proofText = [System.Net.NetworkCredential]::new('', $bootstrapProof).Password
$passwordText = [System.Net.NetworkCredential]::new('', $newPassword).Password
$adminName = Read-Host '管理员用户名（例如 operator）'
$adminEmail = Read-Host '管理员邮箱'
$body = @{
    username = $adminName
    email = $adminEmail
    password = $passwordText
    reason = '部署者首次初始化独立管理域'
} | ConvertTo-Json
try {
    Invoke-RestMethod -Method Post `
        -Uri 'http://127.0.0.1:8080/api/v1/admin/identity/bootstrap' `
        -Headers @{ 'X-CampusOS-Bootstrap-Secret' = $proofText } `
        -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($body))
} finally {
    Remove-Variable proofText,passwordText,body,bootstrapProof,newPassword -ErrorAction SilentlyContinue
}
```

用户名须符合管理域规则（小写字母/数字开头，允许小写字母、数字、点、下划线、短横线，长度 2–64）；邮箱与密码仍由服务端校验。上例默认 API 端口为 8080，修改过本地端口时使用实际值。

成功后立即清空 `AUTH_ADMIN_BOOTSTRAP_SECRET`，再次执行 `up`；在 3001 使用新账号登录并按要求绑定/验证 MFA。只要已有有效安全管理员，重复初始化就会被拒绝；不能用此入口重置密码或绕过 MFA。

## 4. 管理员 MFA 开关与使用引导

MFA 是密码之外的第二道身份验证，当前采用支持 TOTP 的认证器，不是邮箱验证码或管理员登录密码。默认保持开启；部署者可以按风险选择关闭。

### 开启或关闭

在 Docker 开发配置 `deploy/docker/.env.dev.local` 设置一项：

```dotenv
AUTH_ADMIN_MFA_REQUIRED=true
```

`true` 开启，改成 `false` 关闭。只有明确的 `false`（大小写不敏感、忽略首尾空白）关闭；未配置、空值或其他非法值均保持开启，避免拼写错误意外降级。原生环境在实际 `.env` 或进程环境设置；Docker 部署在实际部署 env 中设置。

修改后在仓库根目录执行 `.\scripts\docker-dev.ps1 up`，Linux 用 `./scripts/docker-dev.sh up`；无需因此 `rebuild`，单独 `docker restart` 不会重读配置。管理端“管理员 MFA 策略”页会显示 `/admin/identity/me` 返回的实际生效状态；刷新状态不会修改策略。本页不再用旧用户域的登录策略控制独立管理域，也不允许浏览器请求直接降低部署认证要求。

关闭后仍须通过正确密码、独立管理域会话、当前账号状态、角色/权限、资源作用域、CSRF 和审计校验。会话仍标为 `password`，不会伪装为 `mfa`，已有认证器绑定及加密资料也不会被删除。用户域 MFA、明确要求 MFA 的受托用户授权，以及更换已绑定认证器自身的持有证明不随该开关放宽。生产或局域网环境建议保持开启；不要通过删除 `AUTH_MFA_*` 密钥或直接改表来关闭。

### 开启后的操作步骤

1. 登录 3001 后，未绑定时会看到引导提示；点击“查看配置引导”，或进入“管理员 MFA 策略”页。
2. 准备支持 TOTP 的认证器，点击“开始配置管理员认证器”。使用添加链接，或手动填写页面显示的密钥并选择基于时间的动态验证码；不限定手机或品牌。
3. 输入认证器显示的 6 位动态验证码，完成绑定。请勿把密钥、添加链接或验证码公开分享。
4. 等待认证器显示下一组验证码，再确认管理员身份；绑定时用过的验证码不能立即复用。
5. 验证通过后重试原操作。当前验证有效期 15 分钟，过期后重新验证；验证码失败时检查设备时间是否自动同步。

认证器丢失时使用现行独立管理员离线恢复流程；初始化接口不能替代恢复。这里的开关是部署设置，不是某个用户自行在请求中声明的权限。

## 5. 常见误区与安全限制

- `admin@campusos.local / Admin@123456` 是旧用户域开发兼容值，并非管理端超级用户；已有密码修改后不会因启动而变回固定默认值。
- 密码只保存哈希，不能从数据库“查出原密码”；需要恢复时使用当前独立 Admin 的离线恢复流程。
- 请求头必须精确携带一份初始化凭证。缺失、错误、重复、超长或配置关闭统一拒绝，不输出秘密；请求正文限制 4096 字节。
- 首次初始化条件在事务内复核，账号、角色绑定、必需审计/Outbox 按现行生命周期原子提交；并发请求不能绕过首次条件。
- 本机回环初始化不等于允许开放 API 8080 到局域网。Windows Docker LAN 只开放 UI 3000–3003，API/数据库保持回环。
- 本文不会授权 Agent 创建账号或重置密码；实际执行仍需项目所有者明确同意。
