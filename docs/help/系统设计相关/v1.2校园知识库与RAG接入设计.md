# v1.2 校园知识库与 RAG 接入设计

> 状态：设计方案，尚未交付知识库、向量检索或 RAG 问答；当前 AI 功能仅有 OpenAI 兼容聊天网关。
> 日期：2026-09-25
> 对应计划：[v1.2 优化计划](../../项目计划书v1/项目计划v1.2/00-v1.2版本优化计划书.md)

## 1. 产品边界与借鉴

CampusOS 的知识库不是 WeKnora 的全量复制。WeKnora 本机快照 `e2433b12` 的 README 与 `internal/models/runtime/registry.go`、`internal/application/service/retriever/registry.go`、`internal/application/service/chunk.go` 展示了模型 Provider、检索引擎、来源修订/索引状态的分离；`internal/mcpserver/scope.go` 在对外读取时重新检查端点范围。CampusOS 借鉴这些**边界**，不移植多租户、Agent、Wiki 或众多向量驱动。

CampusOS 现有 `internal/modules/features/ai` 只有单一 OpenAI 兼容 Chat Provider、内存限流和调用日志，已有 `EmbeddingProvider` 类型声明但没有接入实现，尚无 Rerank、受管密钥、多模型配置或检索；`internal/modules/features/personaldocuments/read_port.go` 是仅本人可读的 Built-in Feature Port，不可直接暴露给外部插件。帖子列表搜索是关键词查询，不是 RAG。下面所有“将”“允许”均是 v1.2 **目标行为**。

## 2. 知识库可以收什么

| 集合类型 | 谁创建/选择 | 进入条件 | 默认读者 |
| --- | --- | --- | --- |
| 校园公开知识库 | 有专门权限的后台内容管理员 | 人工审核的官方资料；发布后入库 | 公开或登录用户，依来源策略 |
| 指定板块知识库 | 管理员逐个选择版块并开启订阅 | 仅该板块当前可公开、已发布、审核通过的帖子及图文文章；排除私密/草稿/下架/删除 | 仍按帖子的实时可见性，不因入库变公开 |
| 单篇帖子精选集合 | 内容管理员逐篇选择 | 同上，帖子移动版块或变更状态时重新计算 | 同原帖 |
| 我的知识库 | 用户本人创建 | 本人逐篇选择个人文档或自己帖子；首版仅可解析的纯文本/Markdown/现有富文本正文，其他文件显示“不支持索引” | 只有本人；管理员和版主不自动获得原文 |

**默认不扫描全站帖子、全部板块或任何人的个人空间。** 板块订阅只对当前合规公开内容建立投影；审核、编辑、移动、私密化、删除立即改变可检索性。用户即使选择私人文档，也只是授权 CampusOS 的 Knowledge Feature 为自己生成索引，不等于允许外部模型、插件、MCP 或其他用户读取。

## 3. 实际架构

```text
Community Read/Visibility Port ----┐
RichText Read Port -----------------+--> Source Catalog/Revision --> Outbox --> durable Index Task --> Worker
Personal Documents Own Read Port ---┘                              |          |
                                                              Parser/Chunker  Lexical Index
                                                                            (Vector optional)
User/Integration query --> Authorizer --> RetrievalProvider --> recheck each source
                                                        |             |
                                                  result + link   opted-in ChatProvider
                                                        \             /
                                                    citation validation
```

Knowledge 是可关闭的 Built-in Feature，拥有集合、来源引用、修订和派生索引，不拥有帖子、附件字节、个人文档或原资源 ACL。社区模块决定帖子当前发布/审核/删除/版块事实；个人文档模块决定 owner/版本/是否仍存在；User Storage 管字节与配额。外部检索插件和模型 Provider 只能经受限 Port/Host API，不能直接访问库表或用户目录。

## 4. 入库与撤权流程

1. 管理员选择允许的板块或用户逐项选择自己的文档。服务端验证操作者、资源真实状态及来源类型，记录显式集合选择；私人资料保留本人同意版本和时间。板块订阅规则与逐篇成员分开建模，先保存选择代次，再分页回填已有资源，并持续与权威来源对账；不能假设当前 Outbox 提供可永久回放的事件游标。
2. 业务内容变更与可靠 Outbox 事件同事务提交。常驻消费者先幂等落地 `knowledge_index_tasks` 再完成事件回执，Worker 从持久任务用 `source_kind/source_id/revision` 读取当前版本，执行可取消的解析、分块与索引。重复投递幂等，旧修订不能覆盖新代次；任务有租约、重试与去重键，索引状态为 `pending/processing/ready/failed`，失败原因只含安全代码。任务再检查集合选择代次，不能因旧任务完成把已取消的订阅恢复。
3. 用户或版块管理员撤回时，**先**在权威来源/集合订阅上使其不可见；查询、缓存命中、引用详情和模型上下文立即拒绝旧内容。之后异步删除块、向量、快照与临时解析物，并监控清理时限和失败队列。
4. 对来源移动版块、撤销分享、个人文档删除/版本替换、停用 Knowledge Feature，均执行同样的失效规则。Feature 停用保留业务原文；索引投影按保留策略清理，不可把失效投影继续提供给外部端点。

事件 ID 在提交前生成，不是数据库提交顺序；不能用 `max(event_id)` 推断已完整处理。事件保留期、功能长期停用、订阅晚于历史事件及事务晚提交都由分页回填与周期对账兜底；对账同时检查新增、变更和移除来源。外部索引调用只保证至少一次尝试加幂等/代次隔离，不声称分布式 exactly-once。

索引存储的 owner/category 等字段只用于**粗过滤和性能**，不是授权依据；查询取候选后由 Knowledge 应用服务通过原模块只读 Port 获取事实，再交给纯 Authorizer 重新判定，再返回标题、片段、文件链接或引用。分页、计数、自动补全和“相关搜索”也需要同一可见性约束，不能泄露私密标题。

## 5. 查询与 RAG 问答

第一层先交付**带原文链接的关键词检索**：用户选集合 → 权限交集 → 词法召回 → 来源实时复核 → 返回摘要/可点击引用。中文召回用固定问题集比较 PostgreSQL 方案；只有相对词法基线有实测收益，再追加可选 Embedding、向量召回、重排。不能把“安装 pgvector”当成功标准。

第二层提供可关闭的**基于检索的问答**：仅将已授权、当前有效的片段构造成上下文，限制条数、长度和 Token；模型输出是草稿，服务器只附上经重新核验的引用。找不到依据时回答“未找到可核实的资料”，不让模型凭常识编造官方答复。来源中的提示词一律视为数据，不执行其中的命令、工具调用、链接抓取或权限要求；输出需做安全渲染。引用校验能证明链接仍可访问，不能自动证明回答语义完全正确，因此仍需人工评测。

v1.2 私有问答默认先缓冲完整答案，再复核来源权限/修订与引用后返回；不先把敏感 Token 流出去再检查。默认不保存私有问答正文历史，浏览器/网关使用受限缓存策略；已向用户返回的合法内容无法被远程收回。未来开放持久历史或流式答案时必须另验收历史读取与撤权边界。

外部模型请求是**数据出站**：公开资料可由管理员为集合启用经批准的 Provider；用户问题、上传内容和查询改写输入也需要数据分类，不能因为召回资料公开就默认问题中没有隐私；个人文档首版默认只允许受管本地模型，若用户选择外部 Provider，须在请求前明确说明将发送哪些片段、发往哪个提供方并逐次/按有期限策略同意。界面必须说明撤销只能阻止后续发送，无法收回提供方此前已收到的数据，保留规则取决于与该提供方的协议。同意绑定 Provider Profile 版本、目的、端点与出站策略；变更端点或扩大用途必须重新确认。解析/OCR、Embedding、Rerank、查询改写、Chat 与遥测都受同一出站政策约束，不是只检查最后一次 Chat。管理员启用模型不替代用户同意。检索功能即使模型不可用也应继续可用。

## 6. 模型接入的最小合同

复用现有 Chat Adapter 作为可替换实现，不把单一 OpenAI 兼容响应格式扩散到业务模块。目标模型有四个独立概念：

| 概念 | 谁负责 | 示例 |
| --- | --- | --- |
| Definition | 内置 Adapter 或 v5 插件声明能力和协议版本 | `ai.chat/v1`，不等于支持 Embedding |
| Profile | 管理员配置的可持久设置 | endpoint、model、secret_ref、出站政策、用途、预算及 revision |
| Instance | 运行时创建的连接与健康代次 | 可停止/取消的运行实例，不直接存数据库连接或用户 JWT |
| Binding | AI/Knowledge 选定的用途与 Profile | 某集合的 Chat Profile；不默认给插件抢占全局默认模型 |

公开 DTO 区分 Chat、Embedding、Rerank 和 Parser，独立版本化；响应声明用量、限制、错误码和取消语义。Registry 只接收已声明的类型化贡献，不接受任意 Go Service。请求按用途和能力发现 Provider，缺少能力应清楚拒绝或按用户可见的非模型路径降级，不把 Chat 实现当通用模型能力。新包标准见 [v1.2 扩展合同决策](../../项目计划书v1/项目计划v1.2/01-v1.2架构审查与扩展合同决策.md)。

V12-01b 先交付共享 Secret/Egress Broker；插件和 AI 都用同一受限出站路径。Secret 仅保存引用，常规 UI/日志/导出不回显原值；宿主代请求注入凭据，不允许运行插件绕过 Broker 任意联网。当前 OpenAI 兼容实现和受管本地模型是 V12-14a 的两种真实验收 Adapter，不预先承诺支持所有厂商协议。

管理员自定义端点必须经 URL 规范化、DNS/重定向与内网/元数据地址限制、TLS/证书策略和显式出站白名单；可信本地部署才可批准精确内网端点，不能通配整个内网。配置连接测试也使用同一 Broker，不能成为 SSRF 旁路。

按主体/集合/Profile 实行并发、速率、Token/费用预算，先预留再结算；超时、流断开、取消、故障和未知用量必须释放或保守结算，防止无限占额。外部已受理但响应丢失的计费请求不得盲目重试，除非 Provider 提供可验证的幂等合同；不得自动切换到出站范围更宽的模型。日志只记录 Profile、模型、集合 ID、用量、延迟与原因码，不记录私密正文、Prompt 或密钥。

索引 fingerprint 至少绑定模型/Profile 修订、Embedding 维度、归一化、Parser/Chunker 版本。变化后构建新代次，验证完成再切换，不混用不同向量空间。取消 Profile、插件更新或权限撤销时停止新请求，并取消尚未发送/可取消的任务；无法撤回已发送字节。

## 7. 最小数据模型（按阶段冻结）

| 表/投影 | 作用与关键约束 |
| --- | --- |
| `knowledge_collections` | owner、类型、可见性、启停和 Provider 策略；个人集合不能由管理员直接设为公开 |
| `knowledge_source_selections` | 显式逐篇选择或板块订阅规则、选择代次和撤回时间；与物化成员分离 |
| `knowledge_collection_sources` | 当前集合成员与来源关联；唯一约束和选择代次，避免重复/旧任务复活 |
| `knowledge_index_tasks` / `knowledge_backfill_runs` | 持久索引任务、租约、幂等键、回填检查点及对账结果；不是复制一套通用队列 |
| `knowledge_sources` / `knowledge_revisions` | 来源快照身份、原模块引用、修订和校验和；不复制授权为最终事实 |
| `knowledge_chunks` / `knowledge_index_generations` | 可重建片段、索引代次和状态；派生数据可按来源撤回清除 |
| `ai_provider_profiles` | 提供方/用途/模型/Secret 引用和预算；无明文 Token |

G0 先定所有权和不变量，G1 冻结公开合同；V12-09a/09b、14a 随仓储实现追加知识/模型 migration，不提前猜测全部 DDL。私人集合首版仅本人使用，协作分享与 grants 表留待后续。

私人文档索引和临时解析物应按 owner 分区或至少强制 owner 键过滤，执行最小保留周期并在撤回后清理。若现有 PostgreSQL 存储/备份策略不能为私人派生数据提供足够保护，则禁用私有资料索引入口，只交付保护条件达标的公开检索。词法块和本地模型缓存同样可能包含完整私密正文，不是安全回退；不能只禁外部向量服务就宣称隐私达标。对同一来源被多个集合引用要做引用计数/投影代次设计，不能撤销一个集合就误删另一个集合仍合法使用的数据。

## 8. 使用场景与管理员配置

- 管理员在后台选择“校园通知”版块作为公开知识来源，预览本次预计入库数量和排除理由，确认后启动带选择代次的分页回填、增量任务和周期对账；关闭订阅后新查询立即不再命中该集合。
- 用户在“我的知识库”中勾选两份自己的 Markdown 文档，查看解析/索引状态，只在本人会话中提问。取消勾选立即撤销查询与后续模型出站许可，后台清理 CampusOS 持有的派生数据。
- 内容被设为私密或下架时，用户刚得到的旧引用再打开也必须经过原资源鉴权；AI 回答不应继续引用该内容。
- 管理员配置模型时先选 Chat/Embedding 用途，再填写受限端点和 Secret；运行连接测试只发送固定测试文本，不发送用户数据。界面区分“搜索可用”和“问答模型可用”。

阶段顺序：V12-09a/09b 建立来源与可靠索引，10 交付检索，13 验收私有来源保护，14a/14b 再交付模型适配与引用问答。纯搜索完成不等于 v1.2 全部完成；14b 未验收不能关闭 Final。

验收需覆盖：两个用户跨 owner、私密/草稿/下架/删除/版块移动、撤销与 Worker 竞态、重复事件、私有片段出站拦截、模型提示词注入、恶意 BaseURL/重定向/元数据地址、缓存泄露、引文失效、无证据拒答、中文黄金问题集和容量/恢复测试。外部 Integration Key 与 MCP 按 [细粒度授权方案](v1.2细粒度授权与资源策略设计.md)逐端点与集合默认拒绝。
