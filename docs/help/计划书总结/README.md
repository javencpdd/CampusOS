# CampusOS v1-v14 计划书总结

> 当前基线：`v0.13.0`
> 审查日期：2026-08-28
> 文档状态：当前 Help 入口

本目录面向刚接触 CampusOS 的开发者，回答三个问题：

1. v1 到 v14 每一版为什么迭代。
2. 哪些旧计划已经失去当前执行作用。
3. 项目现在处于什么状态，下一阶段应优先规划什么。

这里是帮助性总结，不改写历史证据。完整计划保存在 `docs/项目计划v1/` 至 `docs/项目计划v14/`，
实现和验收证据保存在 `docs/进度/`；更详细的计划治理记录见
[版本计划总结与有效性](../../计划书总结/README.md)。

## 1. 三阶段演进结论

```text
v1-v3  平台蓝图、真实实现校准、外部插件隔离
v4-v6  个人空间、集成中心、前端扩展和风格包
v7-v10 模块化单体、四类能力、多端插件生态、权限与物理归属
v11-v13 可靠事务、可信账号、结构化社区、可观测和可移植交付
v14     学期治理、User Storage 对象层和个人文档工作区
```

CampusOS 当前不是单模块项目，也不是微服务集合，而是模块化单体：

- Core Module 负责平台完整性和安全边界。
- Built-in Feature 是编译在主程序中、可启停但不可普通卸载的业务功能。
- External Plugin 只能通过公开 API、Host API 或 Extension Gateway 扩展系统。
- Resource Package 只保存主题、风格、Skill、Prompt 等资源，不拥有业务 Runtime。

## 2. 当前计划有效性

| 范围 | 当前判断 |
| --- | --- |
| v1-v3 | 全目录只作早期蓝图和实现演进参考 |
| v4 | 原计划未全部闭合，以 v4 实现总结为历史结论 |
| v5 | 第一版被第二版替代 |
| v6 | 早期计划被第三版替代 |
| v7-v12 | 已封版，只用于架构和验收追溯 |
| v13 | 当前发布基线，但正式计划也已封版 |
| v14 | 正式计划已建立，当前待实施，不代表功能已经交付 |
| v15 及以后 | 只有候选路线，尚未正式立项 |

“已封版”不等于文件没有价值，而是不能再把它当作当前待办列表。计划中的旧端口、目录、表数量、默认配置
和未来设想也不能覆盖当前代码与生成合同。

## 4. 如何使用历史计划

1. 先从本目录确认版本和文档有效性。
2. 再读取该版本建议的正式计划或最终回顾。
3. 用对应 `docs/进度/` 检查实际完成和测试证据。
4. 用当前代码、migration、OpenAPI、路由矩阵和检查器验证仍然有效的行为。
5. 新需求不能追加到已封版计划，应进入缺陷修复、明确补充阶段或下一版正式计划。
