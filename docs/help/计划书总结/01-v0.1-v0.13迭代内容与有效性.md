## 2. 已失去当前执行作用的计划

### 只作历史参考

- `docs/项目计划v0.1/`、`docs/项目计划v0.2/`、`docs/项目计划v0.3/`：不能用于当前部署、API、数据库和插件开发。
- `docs/项目计划v0.4/00-v0.4版本计划书.md`：不能单独作为 v0.4 完成结论。
- `docs/项目计划v0.5/00-v0.5版本计划书.md`：已被第二版替代。
- `docs/项目计划v0.6/01-v0.6版本计划书.md`：已被第三版替代。

### 已完成但不再接收新任务

- v0.7-v0.13 正式计划均已封版。
- v0.13 是当前发布基线，不表示可以继续把新功能无边界追加到 v0.13。
- 历史计划中的未实现愿景仍然是未实现，不能因为后续封版而自动视为完成。

### 从来不是正式计划

以下类型只保存需求输入和推理过程：

- `计划书创建提示词`、`计划书优化提示词`
- `功能域重构与兼容-v0.8计划.md`
- `多端适配与插件市场-v0.9计划.md`
- v0.10-v0.13 名称带“计划思路”的文件

它们不能覆盖对应版本的 `00-...版本计划书.md` 和最终审计。

## 3. 当前仍有效的跨版本原则

1. 保持模块化单体，不拆分无必要的微服务。
2. Core、Built-in Feature、External Plugin、Resource Package 使用不同生命周期和数据归属。
3. External Plugin 不得直接访问数据库、JWT 私钥、内部 Service 或完整宿主文件系统。
4. Feature 停用、插件卸载和资源切换不得隐式删除用户数据。
5. 高风险写入必须保留权限、作用域、审计、事务、幂等和可靠事件。
6. 风格包必须交付 PC/移动双端适配并通过安全与可读性检查。
7. CampusOS Token、Session、JWT 私钥和数据库凭据永不导出。
