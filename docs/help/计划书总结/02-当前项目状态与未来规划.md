# CampusOS 当前项目状态与未来规划

> 当前发布基线：`v0.13.0`
> 更新日期：2026-09-01
> 状态：项目所有者已确认 v0.14-dev 当前代码验证完成并完成开发收尾；发布基线仍为 `v0.13.0`，Final 门禁尚未满足

## 1. 先区分“已实现”和“已计划”

CampusOS 当前已经交付模块化单体、Identity、Community、User Storage 安全目录、个人空间、个人课表、
RichText、可靠任务、可观测、插件/资源体系和 Windows/Linux Docker 单主机交付。这些能力属于 v0.13 基线。

v0.14 的 AcademicTerm、Storage Object Layer 和 Personal Documents 已完成开发实现：管理员学期治理、受管课表、
对象账本、个人文档版本、安全编辑预览与受限运营摘要已有代码和 `v0.14.5-dev` 证据；`v0.14.9-dev` 记录了
逐项审查、可恢复对账、文档预览安全降级 receipt 与文档同步，`v0.14.11-dev` 记录项目所有者验证后的开发收尾。
开发者仍不能把它们写成
v0.14 Final：真实历史数据 `--apply`、Linux 目标环境 release-check/浏览器证据、受审查 Converter Runner 和正式发布审查尚未完成。

## 2. v0.14 为什么选择这条主线

当前课表允许用户自行输入年份并由服务端按日期推断学期；User Storage 的主要接口仍是 Path/Usage；头像、
内容图片、RichText 资产和课表文件的元数据分散。直接增加文档上传会继续放大配额竞争、孤儿文件、路径耦合和
恢复困难。

因此 v0.14 的执行顺序是：

```text
真实基线
  -> User Storage 对象与配额预留
  -> 管理员 AcademicTerm 与课表约束
  -> 私有文档、版本和安全预览
  -> 对账、恢复和发布门禁
```

## 3. v0.14 将交付什么

### AcademicTerm 与课表

- 学期类型固定为 spring/fall，管理员维护 open/closed/default。
- 用户只能在管理员配置的学期内创建、导入和编辑课表。
- closed 历史课表可读不可写；第一周默认只在首次创建时复制。
- 旧课表 JSON 保留并通过 dry-run、closed 登记和幂等采用迁移。

### User Storage Object Layer

- 新业务以 Object ID 使用文件，不取得绝对路径。
- PostgreSQL 记录对象元数据、持久用量和 Reservation。
- Local Provider 使用 staging、hash 和原子 rename；中间态可对账和恢复。
- 旧头像、图片、RichText 和课表通过兼容 Adapter 渐进迁移。

### Personal Documents

- 提供私有文档的上传、列表、编辑、不可变版本、恢复、下载和回收站。
- TXT/Markdown/CampusDoc 可编辑，PDF 只读。
- DOCX 原文件永久保留；只有 Converter 满足无网络、非特权和资源限制时才启用预览。

完整 migration、API、权限、风险、时间和验收见
[v0.14 正式项目计划](../../项目计划书v0/项目计划v0.14/00-v0.14版本计划书.md)。

## 4. v0.14 不做什么

- 多人实时协作、分享链接、跨用户 ACL、通用个人云盘。
- 完整 Office/PDF 编辑、OCR、全文/向量搜索和 AI 文档能力。
- S3/OSS/WebDAV 生产迁移、多节点高可用。
- 标准 MCP、远程插件市场、Agent Runner。

接口预留、Local Provider 或 Converter 原型不等于这些能力已经实现。

## 5. v1.0 正式规划与后续候选

v1.0 已正式选择“插件生态与三层授权”作为下一主线。它将复用当前 Manifest v2、Host API v1/v2、用户 Grant、
本地目录、签名预检和受管数据，建立声明、管理员授予、用户同意三层授权，补齐稳定插件身份、统一判定、升级
diff、即时撤销、Secret、事件/后台任务和 Process Runtime 合同。完整范围见
[v1.0 正式项目计划](../../项目计划书v1/项目计划v1.0/00-v1.0版本计划书.md)；当前尚未开始实现。

真实 Windows/arm64 发行认证、远程 Storage Provider、Passkey/OIDC、远程公共市场、完整进程沙箱、标准 MCP/gRPC、
Agent Runner 和多节点能力仍需独立威胁模型、迁移和恢复方案，不属于 v1.0 P0/P1。

## 7. 不能回退的边界

- 不把模块化单体无必要地拆成微服务。
- 不让 External Plugin 或 Converter 读取数据库、JWT、用户 Token 或宿主完整文件系统。
- 不因 Feature Disable、学期关闭或文档回收自动删除数据。
- 不为了进度取消权限、审计、配额、清洗、迁移、并发或恢复验证。
