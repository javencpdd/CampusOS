# 插件 v5 包与签名操作说明

> 更新时间：2026-10-18（Asia/Shanghai）
> 范围：V12-03a包构建/验证、03b签名导入与分域安装、03c有界宿主调用与元数据队列；04 的声明式配置/审批与隔离 UI；真实 Runner 仍属05/06。

先在仓库根目录显式构建两个示例：

```bash
bash scripts/build-v5-examples.sh
go run ./cmd/campusos-plugin-v5-check -root plugins
go build -o .cache/campusosctl ./cmd/campusosctl
```

PDF示例提供两个UI audience；Echo示例是无UI的Go/WASI包，使用共享Go SDK DTO。构建只发生在开发者显式运行脚本时，包内没有可触发的安装/构建命令。

打包及只读检查，输出路径必须尚不存在：

```bash
.cache/campusosctl plugin pack plugins/campusos.chat-echo --out /tmp/chat-echo-v5.tar.gz
.cache/campusosctl plugin inspect /tmp/chat-echo-v5.tar.gz
.cache/campusosctl plugin catalog
```

`plugin init <key> --dir <new-directory>`可生成无消费能力的UI-only源码模板。`plugin validate <source-directory>`检查实际产物与当前宿主目录。旧`plugin v4`、build/dev/watch和直接install不再进入旧协议；插件自身构建命令应在明确的源码目录中手工执行。

签名与核对需要操作者已有的Ed25519私钥文件、发布者信任文件。私钥文件内容为标准base64编码的64字节Go Ed25519私钥，不放入包、Git或文档。信任文件结构见[Schema](../api/plugin-v5-trust-v1.schema.json)，必须由可信操作者按publisher和key_id设置公钥及active/revoked状态。

```bash
.cache/campusosctl plugin sign /tmp/chat-echo-v5.tar.gz \
  --key-id <key-id> --key-file /path/to/private-key \
  --out /tmp/chat-echo-v5.release.json
.cache/campusosctl plugin verify /tmp/chat-echo-v5.tar.gz \
  --release /tmp/chat-echo-v5.release.json --trust /path/to/trust.json
```

只有`verify`成功才返回`signature_verified=true`；所有命令都返回`installed=false`。`pack/inspect`检查字节与合同，不将未签名包当作可信发布。签名外封在包外；相同版本改变字节必须提升版本，不能覆盖已知发布摘要。服务器可通过`CAMPUSOS_PLUGIN_V5_TRUST_STORE`加载同格式的宿主信任文件；默认信任集合为空，错误配置使模块启动失败，不退回旧Host Token。

包输入大小、路径、归档格式和签名消息详见[字节与签名合同](../api/v1.2插件v5包字节与签名合同.md)。主CLI只输出稳定错误码和安全元数据，不回显配置、私钥或完整文件路径。旧HTTP包/控制入口返回410；新入口见[安装与操作合同](../api/v1.2插件v5安装与操作合同.md)；v5包通过检查也不会自动安装、恢复旧v4发现或执行插件。

独立声明快照工具仍可用于离线合同测试，见[首片工具说明](插件v5声明离线检查说明.md)。它输出`installable=false`，不能把合成目录快照转换成生产权限。完整03a复验和证据见[阶段进度](../进度/v1.2-dev/v1.2.114-dev.md)。

服务器内部包身份Port已接入000026的PostgreSQL账本，防止跨进程/重启后重用同版本不同摘要。它每次仍核对当前信任；数据库不可用不会回退内存允许。CLI `plugin verify`不连接该账本，离线成功不会登记、安装或授权。升级宿主应按[迁移说明](../../migrations/README.md)前向应用至28；非空账本不能回滚，普通卸载也不能清除已知发布身份。具体边界与证据见[03b首片合同](../api/v1.2插件v5发布身份持久化合同.md)。

## 受管安装与操作状态

当前签名导入使用`POST /api/v1/admin/plugin-v5/packages`的multipart字段`package/release/idempotency_key`。Admin须有当前安装权限与近期MFA；浏览器提供独立Admin CSRF。不要把私钥、宿主路径或User凭据发送给插件。

导入后依次使用版本化`install`、独立`grant`和`enable`命令；安装默认disabled，批准不自动运行。User从`GET /api/v1/plugin-v5`查看当前获批的全局安装，再建立自己的安装/配置与必要同意；owner由当前会话决定。命令返回Operation ID，按对应域`GET .../plugin-v5/operations/:id`查看进度。CAS冲突刷新代次/revision后使用新幂等键；相同键只重放原意图。

未配置后端执行器时启用保持pending/runtime_unavailable；UI-only 在当前安装/授权/配置均满足且已配置独立 UI 网关时可以加载，不能据此认定后端 Runner 已就绪。卸载默认保留；只有显式`purge_data=true`才异步清理自己的配置和数据。包GC须无全局/用户当前或期望版本引用；数据库与`PLUGIN_DATA_DIR/v5`须一同备份。字段、错误、升级限制和后续责任见[完整合同](../api/v1.2插件v5安装与操作合同.md)。

## 宿主调用与事件状态

当前能力合同只包括公开帖子读取和生命周期/公开帖子/公开知识源元数据订阅；声明和管理员Grant均须逐项typed匹配，不能用旧permissions或事件数组替代。资源ACL由Core当前公开读Port复核；公开知识源生产授权尚未绑定时不投递。内置AI/RAG不依赖这些插件能力。

宿主03c提供受管发布/不透明短期实例凭据、三类贡献调用和取消/排空、独立事件工作器，05已提供显式配置的 Linux Wasm 固定 worker；未配置时 `enable`仍等待runtime_unavailable。不要写数据库observed=ready、复用旧代次或传入User/Admin Token冒充插件凭据。Wasm 实际运行见下节05，Container仍属06。

000028独立队列仅保存有限引用/状态/修订及重试证据；来源必须是已提交Core Outbox，不存正文/Prompt/Secret/原始Outbox载荷。最多5次尝试，撤权、过期或重启旧实例终止为死信；不通过清表/回滚删除这些证据。数据库与受管文件仍作为同一备份集合。当前实现/自动化/目标三态与可复跑命令见[.119](../进度/v1.2-dev/v1.2.119-dev.md)和[完整调用合同](../api/v1.2插件双向调用事件与生命周期合同.md)。

## V12-04 配置、审批与界面

更新时间：2026-10-18（Asia/Shanghai）。管理员从“插件管理”进入 `/plugins`，显式导入包和签名，选择具体版本，单独安装、审批和启用。业务能力与运行资源分别呈现；只能从该版本声明选择，资源数值/网络目标只能收紧，填写原因与未来 30 天内的截止时间。审批人由服务器记录。操作编号可查询；仅当前 waiting/failed 操作可用读回的修订号显式重试，不重放旧审批。旧 `/plugin-center` 跳转当前入口。

Admin“插件系统配置”和 User“插件配置”使用宿主生成的文字、整数、小数、开关、枚举及受限选择器。精确数字不丢位，系统/本人配置分开；普通字段与密钥引用为两个独立表单，保存一栏保留另一栏，均用当前修订 CAS。密钥只选择当前可见引用，不提供原值输入。后继 Profile/Knowledge/v5 Secret 目录未绑定时选项为空，不能填写任意 ID。

User `/plugins` 从当前获批版本安装，逐项确认用途后启用；撤权/过期的本人安装仍可停用、卸载。无插件不影响正常下载。Admin 的确认身份入口完成 MFA 后仍由操作者重新读取并决定保存，页面不会自动重试失败命令。

界面必须部署独立租约子域网关及精确父 Origin，配置见[配置与端口](../../docs-site/deployment/configuration.md#v5-插件与隔离界面)。PDF 示例通过受限 Bridge 读取宿主当前选择的 PDF，支持文章附件、个人资源、个人文档的四种展示；iframe 不取得 JWT、API 地址、Secret 或任意路径。实现边界见[UI/Bridge 合同](../api/v1.2插件UI宿主与Bridge合同.md)。前一首片 [.120](../进度/v1.2-dev/v1.2.120-dev.md) 保留原验收；完整阶段状态以主计划当前三态为准。

## V12-05 Wasm 后端

更新时间：2026-10-19（Asia/Shanghai）。Linux 原生 API 显式设置 `CAMPUSOS_PLUGIN_WASM_IMAGE` 为本地固定宿主 worker 的完整 sha256 镜像 ID，构建方法、有限 JSON/Host import ABI、资源上限与失败语义见 [Wasm 合同](../api/v1.2插件Wasm执行沙箱合同.md)。默认空值、错误镜像或缺少真实隔离/PG guard 时保持不可用；不能手工写 ready。不要给 guest/API 容器挂 Docker socket。

仅支持符合有限 ABI 的签名 Wasm；当前 Echo/WASI 示例仍是包合同样例，不能当作已适配的可执行程序。实际 readiness 通过后由协调器发布，普通配置变化准备新代次；当前授权、私密状态、会话撤销和真实到期会拒绝调用，worker 退出撤下贡献，已知失败用当前代次显式 enable/retry。内置 AI/RAG 消费接线仍属14c。三态及原始证据见 [.123](../进度/v1.2-dev/v1.2.123-dev.md)与[完整报告](../项目计划书v1/项目计划v1.2/evidence/v12-05-runtime-exit-linux.json)。


## V12-06 Container 后端

更新时间：2026-10-19（Asia/Shanghai）。原生 API 设 `CAMPUSOS_PLUGIN_CONTAINER_ENABLED=true` 显式启用，默认false。签名包绑定本地精确RepoDigest，镜像必须实现有限 `campusos.container-pipe/v1` 的HTTP/gRPC标准输入/输出协议；任意监听服务不会自动适配。需要Docker Linux/cgroup v2/seccomp、单写PG guard，无pull、宿主目录/socket/DB/凭据暴露。

实际readiness后Observe/发布，普通配置与安全元数据可用，Host调用逐次检查当前声明/Grant/所需Consent及Core ACL；已知失败以当前代次enable/retry。完整资源、取消/回收与证据见 [Container执行合同](../api/v1.2插件Container执行沙箱合同.md)和[.125](../进度/v1.2-dev/v1.2.125-dev.md)。Linux目标已验证；Windows相关工作按用户要求延期、仍未验收，不能将完整跨平台06标完成；后续Linux阶段按主计划Linux依赖推进，最新范围见[.128](../进度/v1.2-dev/v1.2.128-dev.md)。
