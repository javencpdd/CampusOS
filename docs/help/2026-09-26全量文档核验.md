## 核验方法

逐文件检查标题、状态、入口、代码路径、脚本和 Make 命令；对操作性结论以
`Makefile`、`migrations/`、`internal/transport/httpapi/router.go`、
`internal/modules/`、`internal/plugin/`、`pkg/config/`、
`modules/`、`plugins/`、`data/resources/`、`deploy/docker/` 为准。
仓库内链接由 `scripts/check-doc-links.py` 检查。历史进度与设计稿不因文件存在就成为当前操作依据。
本次是仓库静态核验；没有声称 Windows 实机、生产 SMTP、真实外部模型或发布环境已重新验收。

当前可执行数据库迁移仅有 `000001_v1_1_schema_baseline`、
`000002_v1_1_ui_only_plugin_runtime`、`000003_v1_1_trusted_market_sources`。
旧 `0000xx` 只可出现在明确的历史叙述，不得再作为升级指令。
新插件优先使用 `campusos.plugin/v4` 和 `campusos.ui/v3`；v1-v3 说明只供兼容维护。

## 保留文档逐项结论

状态：**操作** = 当前可用的操作或合同入口；**兼容** = 只供旧合同维护；
**历史** = 事实快照/阶段决策，不作为当前命令；**规划** = 尚未实现；**索引** = 导航。
“已修订”表示本轮有实质改动；其余文件通过路径/命令/版本核验，使用时仍应以代码为最终权威。

## 当前阅读路径与限制

第一次贡献从 [开发者递进入门路线](开发者递进入门路线.md) 开始；数据库以
[数据库管理指南](系统设计相关/数据库管理指南.md) 为准；新插件以
[v4 Manifest](../../docs-site/plugins/manifest.md) 为准；权限操作以
[权限配置入门](../../docs-site/guide/permission-configuration.md) 为准。
v1.2 的规划文档不得写成已经上线的 RBAC、知识库或 Agent 能力。

旧进度或计划中的纯文本路径可能仍指向本轮删除的 Help 文件，那是历史变更记录，
不是可执行链接；需要原文时使用 Git 历史。以后再清理文档，应先核对实际实现和引用，
再更新此报告与 Help 索引。
