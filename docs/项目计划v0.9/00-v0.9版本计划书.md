> 编写日期：2026-07-13

## 1. 计划结论

v9 不重写 v8 已建立的模块化单体，也不把插件平台扩张成未经治理的公共应用商店。本轮聚焦两条相互依赖的主线：

1. 让 Web、Admin 和插件动态 UI 在 PC、平板、手机上具备一致、可测试、可回归的使用体验。
2. 在现有 External Plugin 边界上建立 Manifest v2、受管结构化数据、用户文件、授权、目录、搜索、签名和升级治理，形成可演进的本地插件市场基础。

v9 的插件市场首先是“由管理员管理来源和安装、由用户决定启用与授权”的本地治理中心。公开远程仓库、付费交易、云文件 Provider、向量检索和任意数据库能力均不属于 v0.9.0 的完成条件。

## 2. v8 基线与现状问题

### 2.1 可复用的 v8 基础

- Module Runtime 已负责 Core Module、Built-in Feature、External Plugin 和 Resource Package 的分类与装配。
- Identity、Community、Moderation、User Storage 已形成 Core 边界。
- Personal Space、RichText、Schedule、Appearance 已进入 Built-in Feature 生命周期。
- Plugin Manager 已保留为兼容 Facade，路由、生命周期和 Runtime 职责已有独立归属。
- gRPC、Wasm、Remote HTTP、MCP、Agent Runner 等外部运行时具有安全边界。
- Web 与 Admin 已按业务域拆分，具备继续建立响应式布局和测试基线的条件。
- Resource Package 与可执行业务插件已经分离，历史风格包目录仍由兼容源读取。

v9 必须复用这些边界，不得把 Built-in Feature 或 Resource Package 重新包装成普通市场插件。

### 2.2 当前主要缺口

| 缺口 | 当前状态 | v9 目标 |
| --- | --- | --- |
| 前端自动化不足 | Web/Admin 以构建、Lint 和浏览器 smoke 为主，组件级回归不足 | 建立组件测试、响应式测试和五视口浏览器门禁 |
| 多端规则不统一 | 页面各自处理表格、弹窗、导航和密集操作 | 建立共享响应式规则和可复用模式 |
| 插件 Manifest 表达有限 | 当前为 `campusos.plugin/v1`，缺少受管数据、用户授权和响应式 UI 声明 | 新增 v2，并保留 v1 Adapter |
| 插件结构化数据能力过窄 | SQLite KV 仅支持 Get/Set/Delete | 增加宿主管理的记录、分页、有限筛选、配额和审计 |
| 用户文件边界未标准化 | 插件可使用空间文件能力，但缺少统一插件命名空间和治理视图 | 通过 User Storage 建立用户/插件双重隔离 |
| 管理授权与用户授权混合 | 安装、系统权限和用户数据同意缺少完整分层 | 分离管理员批准、用户授权和运行时校验 |
| 市场治理能力不完整 | 已有包和生命周期能力，但无统一目录、风险摘要、安装申请和升级审查 | 建立本地 Catalog 与 Admin/User Plugin Center |
| 搜索边界不明确 | 不能统一发现插件声明可检索的数据 | 只索引声明字段，并在返回结果前执行所有权和权限过滤 |
| 升级与多实例约束不足 | 本地 SQLite/文件在多写实例下存在一致性风险 | 增加签名、兼容预检、回滚和多实例阻断规则 |

## 3. 目标架构

```text
CampusOS v9
├── Frontend Experience Layer
│   ├── Responsive Foundations
│   ├── Web Domain Views
│   ├── Admin Domain Views
│   └── Dynamic Plugin UI Renderer
├── Plugin Platform
│   ├── Manifest v1 Compatibility / Manifest v2
│   ├── Catalog & Package Governance
│   ├── Runtime / Lifecycle / Config / UI / Event / Audit
│   ├── Permission Policy & User Consent
│   ├── Managed Data Service
│   ├── Plugin File Gateway -> User Storage Core
│   ├── Declared Search Service
│   └── Release / Signature / Rollout
├── Existing Core & Built-in Features
│   ├── Identity / Community / Moderation / User Storage
│   └── Space / RichText / Schedule / Appearance
└── Compatibility Sources
    ├── campusos.plugin/v1
    ├── Host API v1 SQLite KV
    ├── Existing plugin_data directories
    └── Legacy Resource Package sources
```

### 3.1 插件数据分层

| 数据类型 | 归属 | 推荐位置/存储 | 规则 |
| --- | --- | --- | --- |
| 插件代码与 Manifest | Plugin Platform | `data/plugins/<plugin-id>/` | 由管理员安装和升级；运行时只读 |
| 系统级结构化业务数据 | Managed Data Service | PostgreSQL 受管表 | 插件仅通过 Host API 访问 |
| 用户级结构化业务数据 | Managed Data Service | PostgreSQL 受管表，宿主注入用户所有权 | 禁止插件提交或伪造其他用户 ID |
| 用户文件 | User Storage Core | `data/personal-space/<user-id>/plugins/<plugin-id>/...` | 复用安全路径、配额、Provider 与审计 |
| 插件配置 | Plugin Config Service | 现有配置存储及后续受管配置 | Secret 与普通配置分离 |
| Resource Package | Resource Repository | `data/resources/` 及 Legacy Resource Source | 无业务 Runtime 和数据库迁移 |
| 历史 SQLite KV | Host API v1 兼容层 | `data/plugin_data/<plugin-id>/plugin.db` | 保留读取和兼容；多写实例下受限 |

## 5. 关键合同

### 5.1 Manifest v2

新增 `campusos.plugin/v2`，至少表达：

- 稳定插件 ID、版本、CampusOS 兼容范围和 Runtime。
- 插件类型、作用域、入口、依赖和生命周期策略。
- 系统权限、用户权限、权限用途说明和升级后的重新授权规则。
- UI 目标、导航位置、响应式能力和不支持视口的降级方式。
- Managed Data collection、字段 schema、所有权、配额、索引和可检索字段。
- 用户文件类型、单文件限制、总配额和保留策略。
- 配置 schema、Secret 字段声明和可导出策略。
- 包摘要、签名、发布渠道和数据迁移版本。

v1 Manifest 继续可加载。未声明 v2 能力的插件不得自动获得受管数据、用户文件、搜索或新增 UI 权限。

### 5.2 Managed Data Host API

首版提供受约束的记录接口：

```text
CreateRecord
GetRecord
UpdateRecord
DeleteRecord
ListRecords
```

合同要求：

- Host 从运行时上下文注入 `plugin_id`、`owner_type` 和 `owner_id`。
- 使用 collection 与 record key，不暴露表名、SQL 或数据库连接。
- List 仅允许 Manifest 声明的等值、标签、时间范围和排序字段。
- 支持稳定分页、乐观锁版本和写入幂等键。
- 执行 schema、大小、数量、速率、配额和权限检查。
- 写入、删除、导出和越权失败进入审计。
- 插件停用、卸载或升级不得默认删除数据。

建议初始模型：

```text
plugin_records
  id, plugin_id, owner_type, owner_id,
  collection, record_key, data_json, search_text,
  created_at, updated_at, version
```

实际表、索引和约束在 A0.5 之后冻结，迁移只能追加。

### 5.3 用户文件合同

- 插件通过 Plugin File Gateway 使用 User Storage Port，不直接拼接宿主路径。
- 实际本地目录保持为 `data/personal-space/<user-id>/plugins/<plugin-id>/`。
- 文件类型、后缀、MIME、单文件大小和总配额由 Host 校验。
- 返回稳定资产 ID 或受控 URL，不向插件暴露宿主绝对路径。
- 用户可查看占用、导出、清理和撤销访问；管理员可查看汇总和审计，不能绕过业务授权读取私密内容。
- Provider 首版仍为 Local；v9 只保证 Provider Port，不承诺交付云 Provider。

### 5.4 权限与授权合同

```text
包来源信任
  -> 管理员安装/升级批准
  -> 系统权限策略检查
  -> 用户对个人数据能力授权
  -> Runtime 每次调用校验
  -> 审计与撤销
```

- 管理员批准插件进入系统，不等于用户同意访问个人数据。
- 用户授权必须绑定插件 ID、版本范围、权限摘要和用途说明。
- 新增高风险权限、扩大文件类型或扩大可检索字段时必须重新授权。
- 撤销后立即拒绝新调用，已生成缓存按声明策略清理或失效。
- CampusOS Session、Access/Refresh Token、JWT 私钥、数据库凭据永不交给插件或进入导出包。

### 5.5 搜索合同

- 只索引 Manifest 显式声明且通过审核的字段。
- 仅索引 Host 托管数据，不扫描插件 SQLite、任意文件或私有配置。
- 查询先限制插件、collection、用户和作用域，再匹配关键词。
- 返回统一标题、摘要、目标 URL、插件来源、时间和权限元数据。
- 所有结果在返回前再次进行资源所有权和权限校验。
- v9 不提供任意 JSONPath、SQL、向量或跨 Provider 查询。

### 5.6 多端合同

固定验收视口：

| 类型 | 视口 |
| --- | --- |
| 小屏手机 | 360 x 800 |
| 标准手机 | 390 x 844 |
| 平板 | 768 x 1024 |
| PC | 1440 x 900 |
| 宽屏 | 1920 x 1080 |

共同规则：

- 页面不得出现非预期横向滚动；文字、图标、按钮和浮层不得相互遮挡。
- 关键触控目标不小于 44 x 44 CSS 像素，并处理移动端安全区域。
- PC 表格在手机端转换为卡片/分组列表；复杂编辑进入全屏页或底部抽屉。
- 导航、面包屑、筛选、批量操作和分页在窄屏下有明确替代交互。
- 支持键盘导航、可见焦点、语义标签和 WCAG AA 级正文对比度。
- 动态插件 UI 必须声明响应式能力；不能适配时显示受控降级，不渲染破损界面。

## 6. 数据库与持久化策略

预计采用以下追加迁移，具体编号和拆分在 A0.5 基线后确认：

| 预计迁移 | 内容 | 所有者 |
| --- | --- | --- |
| `000021_v09_plugin_market` | 受管记录、文件元数据、Grant、Catalog、请求、发布和市场审计 | Plugin Platform / User Storage Adapter |
| `000022_v09_plugin_catalog_permissions` | Catalog 的用户权限用途、风险与可撤销声明 | Plugin Policy |

约束：

1. 不修改 v8 及以前已发布迁移。
2. 新表具备 PostgreSQL 和测试用 Memory Adapter；Repository 不跨模块直接引用。
3. 所有用户数据表必须有所有权、唯一性、时间和必要的级联/限制策略。
4. 停用或卸载默认进入 `retained` 状态，不执行物理删除。
5. 生产回滚优先回退应用并保留新增表；只有空数据或可丢弃环境才执行破坏性 down。
6. 导出与删除必须按插件、用户、collection 和文件范围生成可审计结果。

**交付**：完成现状审查、范围排除、目标架构、数据边界、阶段依赖、验收和回滚规则。

**验收**：计划不把 v8 Built-in Feature 重新变成插件；保留 v1/SQLite/旧目录兼容；每个后续阶段可独立回滚和验证。

### 7.3 A0.5：当前系统基线冻结

**交付**：记录 Go/Web/Admin/docs-site/SDK 构建，全量路由与 OpenAPI 快照，迁移清单，Manifest/Runtime 清单，数据目录，前端体积，五视口现状，smoke/database/architecture/release-check 结果。

**重点目录**：`docs/architecture/`、`tests/`、`scripts/`、`docs/进度/v0.9-dev/`。

**验收**：后续阶段能机器比较 API、路由、迁移、插件包和前端体积；失败项必须登记为基线债务，不能伪装成新回归。

### 7.4 A1：前端测试基础

**交付**：为 Web/Admin 引入与 Vue/Vite 版本匹配的组件测试环境、DOM 测试、网络 Mock、共享测试 fixture 和 CI 命令；覆盖导航、权限门禁、Feature gate、插件动态 UI 的基础状态。

**兼容/回滚**：只增加开发依赖和测试配置，不改变生产路由；可通过移除测试入口回退。

**验收**：测试可重复、无外部网络依赖；Web/Admin 测试和现有 build/lint 同时通过。

### 7.5 A2：响应式设计基础

**交付**：统一断点、容器、间距、字体、焦点、触控尺寸、安全区域；实现响应式 Shell、导航、筛选栏、数据表/卡片、分页、Dialog/Drawer 和空/错/加载状态。

**兼容/回滚**：保留现有 URL、权限和业务组件输入输出；逐页迁移，不一次替换全部 CSS。

**验收**：基础组件在五视口无溢出和遮挡，键盘与触摸可操作，正文对比度满足要求。

### 7.6 A3：现有页面与动态 UI 适配

**交付**：优先验证登录、首页、帖子、个人空间、课表、插件入口以及 Admin 的用户、插件、功能和架构页面；动态 UI 增加视口能力和降级渲染。历史页面保持 v8 布局，后续按业务域继续迁移。

**兼容/回滚**：按业务域分批切换；每批保留旧组件至定向回归通过。

**验收**：关键任务在五视口可完整完成；手机端不依赖 hover；动态 UI 的不支持状态有明确提示。

### 7.7 A4：性能与懒加载

**交付**：保留现有路由级拆包，实施组件库按需引入和入口资源预算；重型编辑器/图表的网络级性能分析、资源缓存和失败重试留给后续性能专项。

**兼容/回滚**：懒加载失败必须显示可重试状态；不得改变鉴权和 Feature gate 时序。

**验收**：以 A0.5 实测值冻结预算，关键入口体积和首屏请求不回归，并达到阶段内明确记录的下降目标；慢网下无空白页。

### 7.8 A5：五视口回归门禁

**交付**：Playwright/Chrome 自动化覆盖五视口、登录与关键业务流；增加 body 溢出、文字遮挡、空白 Canvas/图片、控制台错误、焦点和截图基线检查。

**兼容/回滚**：截图变化需显式审查更新，不能自动覆盖基线。

**验收**：本地和 CI 可执行；关键页面五视口通过，失败报告包含 URL、视口、截图和控制台信息。

### 7.9 A6：Manifest/SDK v2

**交付**：Manifest v2 Go/JSON Schema/SDK 类型、v1 Adapter、CLI inspect、示例插件和迁移指南；增加响应式 UI、Managed Data、用户文件、用户授权和发布字段。

**兼容/回滚**：v1 默认映射到原能力且不获得 v2 新权限；现有插件包无需修改即可继续运行。

**验收**：正反 schema fixture、兼容 fixture、权限升级 diff、SDK 构建和 CLI 检查通过。

### 7.10 A7：受管插件数据

**交付**：Managed Data Port/Service、PostgreSQL/Memory Repository、追加迁移、Host API v2、配额、分页、乐观锁、稳定 record key 幂等语义、审计、导出和保留状态。

**兼容/回滚**：Host API v1 SQLite KV 和原文件不变；回退应用后新增表保留，不丢数据。

**验收**：跨插件/跨用户越权、配额、并发冲突、非法过滤、重复幂等键和停用保留数据的负向测试通过。

### 7.11 A8：用户插件文件

**交付**：Plugin File Gateway、User Storage Adapter、插件文件元数据和配额；使用 `data/personal-space/<user-id>/plugins/<plugin-id>/`，提供上传、读取、列出、删除、导出和受控 URL。

**兼容/回滚**：不移动现有用户文件；旧空间文件接口继续工作；新增文件可由旧 User Storage 读取。

**验收**：路径穿越、MIME 欺骗、超额、跨用户、跨插件、孤儿元数据和停用/卸载保留测试通过。

### 7.12 A9：权限与用户授权

**交付**：系统权限审批、用户授权记录、用途摘要、升级重新授权、撤销和审计；Admin 与 Web 同步展示权限来源和影响。

**兼容/回滚**：历史插件仅保持原批准能力；不得用兼容默认值授予新增个人数据权限。

**验收**：未批准、未授权、已撤销、版本权限扩大和不同用户上下文均有负向测试；Token/DSN/Secret 不可见。

### 7.13 A10：本地 Catalog 与包治理

**交付**：Catalog、包元数据、兼容性、摘要、风险说明、导入导出、安装申请和来源信任；只接入管理员配置的本地/受信来源。

**兼容/回滚**：复用现有插件安装和生命周期 Facade；Catalog 删除不卸载插件，卸载不默认删除数据。

**验收**：Zip Slip、重复 ID、版本倒退、摘要错误、Manifest 不兼容、Resource Package 冒充插件等负向测试通过。

### 7.14 A11：Admin Plugin Center

**交付**：管理员查看 External Plugin、版本、Runtime、健康、权限、用户授权汇总、数据/文件占用、审计、安装申请和发布状态；高风险操作使用分步确认。

**兼容/回滚**：保留现有 Admin 插件页面和 API，先通过 Adapter 接入新 Facade，再迁移入口。

**验收**：PC/手机均可完成安装审查、启停、升级预检和数据保留选择；权限不足时服务端拒绝。

### 7.15 A12：User Plugin Center

**交付**：用户查看可用插件、申请安装、启用个人能力、授权/撤销、数据与文件占用、导出和删除申请。

**兼容/回滚**：用户不能安装宿主代码，只能对管理员已安装/发布的插件操作。

**验收**：用户只能看到自己的授权和数据；撤销、导出、删除流程在移动端可完成且有审计。

### 7.16 A13：声明式基础搜索

**交付**：Host 管理的受管记录搜索文本、关键词查询和插件/collection/当前用户过滤。首版直接查询受管记录，不引入独立索引、同步队列或跨插件全局结果合同。

**兼容/回滚**：索引可重建，关闭搜索不影响源记录；不扫描 v1 SQLite 和任意用户文件。

**验收**：权限过滤、删除同步、重建、停用插件、撤销授权和无权结果不泄露测试通过。

### 7.17 A14：签名、升级与回滚

**交付**：包摘要、签名信任库、导入预检、发布渠道/状态审计记录与既有 snapshot 回滚。远程自动分批启用和健康观察不在 v0.9 范围。

**兼容/回滚**：历史未签名包可按管理员策略标记为 legacy/local，不能伪装为可信签名；升级失败恢复旧代码和配置快照，保留向前写入的数据。

**验收**：篡改、未知签名者、权限扩大、迁移失败、健康失败和回滚演练通过。

### 7.18 A15：多实例与最终验收

**交付**：PostgreSQL 并发一致性验证；检测本地 SQLite/Local File Provider 的多写风险并拒绝或降级为单写；执行恢复演练、五视口回归、完整发布检查和文档收口。

**兼容/回滚**：单机部署继续受支持；不以尚未交付的共享文件 Provider 冒充多实例完全就绪。

**验收**：第 11 节全部条件满足，形成 v9 最终回顾、兼容矩阵和已知限制清单。

### 7.19 实施偏差与验收说明

- 原草案按能力分别预计六个迁移；实现将强关联的受管记录、文件、Grant、Catalog、请求、发布和审计合并在 `000021`，并在 `000022` 单独追加 Catalog 用户权限字段。两者均为追加迁移。
- 搜索采用受管记录的同步搜索文本和强制插件/collection/当前用户范围，不引入独立索引或队列；这避免首版出现异步权限失效窗口。
- 发布治理实现确定性签名、信任预检、管理员发布记录和既有 snapshot 回滚；远程自动灰度/健康观察明确转入后续版本。
- A16 复审发现原验收遗漏了独立搜索授权、插件停用运行门禁、记录总配额、严格 MIME/schema 校验、导入后目录同步、升级权限差异以及插件中心占用/审计展示。上述实现与负向测试已经补齐。
- 用户可以提交任意合法插件 ID 的安装建议，但仍不能下载、安装或执行代码；请求仅进入管理员治理队列。公开远程市场仍属于 P2。
- 组件测试已正式加入 CI；动态声明式 UI 与 Web/Admin 插件中心均有组件级测试。全局响应式基线统一了安全区域、焦点、媒体约束和粗指针触控目标。
- A15 的全局 `git diff --check` 存在用户既有 `docs/Todo/sys` 行尾空白告警。v9 文件不引入该问题，阶段记录保留事实，不修改用户工作内容。

### 7.20 A16：计划符合性复审与收口

**交付**：逐项比较计划合同、实现、测试、前端和文档，修复原“已完成”结论中的证据和行为缺口：

- Catalog 只有 `published` 且插件 Runtime 处于运行状态时，才允许新增授权和普通数据调用；停用/下架后仍允许用户导出或删除本人保留数据。
- 搜索使用独立的 `plugin_search:read` 可撤销授权，不再隐式复用普通记录读取授权。
- 记录严格拒绝未声明字段，并统一校验单记录大小、collection 数量和插件/所有者总字节配额。
- 文件同时校验后缀、声明 MIME、内容嗅探、单文件大小和总配额；元数据写入失败会清理文件，删除采用可恢复的暂存流程。
- v2 包导入成功后立即同步 Catalog，并记录真实 checksum/签名状态；升级预检展示系统/用户权限差异、数据 schema 变化和重新授权要求。
- User Plugin Center 展示个人记录/文件占用、独立搜索授权、导出/删除和安装建议；Admin Plugin Center 展示 Runtime 健康、系统权限、占用汇总和市场审计。
- Web/Admin 组件测试进入 CI，并增加路由鉴权、Built-in Feature 管理入口、动态路由移除、声明式 UI 渲染和共享响应式基础回归。

**兼容/回滚**：不修改 `000021`/`000022`，不移动旧目录，不删除 v1 API。运行门禁只影响 v2 普通调用；停用、下架或卸载后的本人数据控制能力继续保留。应用可回退到 A15 代码，新增记录和审计不需要向下迁移。

**验收**：Go 全量测试、Web/Admin 组件测试、Web lint/format、Web/Admin/docs-site/SDK build、contracts、architecture、docs-links 和 frontend-budget 已通过。当前执行环境无 `psql`、不能访问 Docker Socket，也禁止监听前端端口，因此本轮 `database-check`、migration status 和修改后的五视口浏览器复验未执行；此前 A15 的迁移、恢复和五视口证据保留为历史证据，但不能替代 A16 复验。解除环境限制后必须补跑这些门禁，才能把 A16 标为“已验收”。

## 11. 最终验收标准

## 13. 风险与回滚原则

| 风险 | 控制措施 |
| --- | --- |
| 响应式改造引发大面积视觉回归 | 按业务域迁移，固定五视口，截图需人工确认 |
| Manifest v2 破坏旧插件 | v1 Adapter、fixture 和双版本 SDK 合同测试 |
| 受管数据成为通用数据库后门 | 声明式 collection/filter、Host 注入所有权、禁止 SQL |
| 用户数据被停用/卸载误删 | 默认 retained、删除单独授权、导出和审计 |
| 插件文件绕过空间配额和路径安全 | 只走 User Storage Port，统一配额/MIME/SafePath |
| 搜索泄露私有数据 | 仅声明字段，查询和结果双重权限校验，索引可重建 |
| 升级扩大权限或损坏数据 | 权限 diff、重新授权、快照、健康观察和应用回滚 |
| 本地存储用于多写实例 | 启动检测、明确拒绝/只读/单写模式，不静默运行 |
| 市场范围失控 | v9 限定本地 Catalog；远程公共市场放入 P2 |

回滚遵循“代码可回退、数据不倒退、权限默认收紧”：应用版本可回退；新增用户数据和审计默认保留；新权限在不确定状态下拒绝；迁移不得用破坏性 down 作为常规生产回滚手段。

## 14. 禁止事项

- 禁止一次性重写 Web、Admin 或 Plugin Manager。
- 禁止删除旧 API、路由、迁移、Manifest、SQLite 文件和数据目录。
- 禁止插件直接访问 PostgreSQL、CampusOS `internal/*`、JWT 私钥、用户 Token 或宿主完整文件系统。
- 禁止让调用方自行指定可信 `plugin_id`、`owner_id` 或其他用户身份。
- 禁止提供任意 SQL、任意 JSON 查询、跨插件 Join 或未经声明的搜索索引。
- 禁止停用、卸载、Catalog 下架或授权撤销时自动删除用户数据。
- 禁止将 Theme、Style Pack、Skill、Prompt、Persona 等 Resource Package 当作 External Plugin 安装运行。
- 禁止用户绕过管理员安装、升级或执行宿主代码。
- 禁止默认明文导出任何 Token 或 Secret；CampusOS Token 永不导出。
- 禁止在没有负向测试、兼容证据、回滚验证和进度文档时标记阶段完成。
