# CampusOS 项目计划 v0.6（第三版）

> Priority: **P0-Highest**  
> Status: **已完成并封版（最终审查：v0.6.24-dev）**
> 编写日期：2026-07-12  
> 实现阶段：`v0.6-dev`  
> 历史基线：第二版计划截至 `v0.6.9-dev` 的已完成状态保持不变

## 1. 修订定位

本计划不回写第二版中的历史结论。`v0.6.0-dev` 至 `v0.6.9-dev` 已完成的接口、权限、数据库、插件工具链、恢复与发布门禁仍是基线。本次 P0-Highest 主线解决插件后端生命周期、前端运行时和全屏风格包之间缺少统一合同的问题。第二版明确后置的标准 MCP/真实 Message Adapter、生产多节点编排和公网插件市场不属于本计划完成定义。

目标边界是：Core 拥有身份、授权、Gateway、App Shell、UI Contract、兼容和回退；插件拥有业务和默认可用 UI；风格包拥有受控布局与视觉，但不拥有业务、授权和 API。

## 2. 当前架构审查

### 2.1 可复用能力

| 领域 | 当前能力 | 本次复用方式 |
| --- | --- | --- |
| 插件定义 | `campusos.plugin/v1`、builtin/gRPC/Wasm、权限、事件、配置 schema | 以可选字段扩展，旧 manifest 不迁移也能读取 |
| 插件管理 | 安装、配置、启停、用户级 reload、快照、回滚、日志 | 保留管理 API，内部改用后端/前端/健康三轴状态 |
| Runtime | builtin、外部进程 gRPC、wazero Wasm | 统一增加 Extension Dispatch；Wasm 改为验证后原子替换 |
| 前端 | Vue 3、Pinia、Vue Router、Element Plus、系统主题 store | Core 封装 Campus UI；建立 App Shell 和动态注册器 |
| 风格包 | `page-style-pack.v1`、`target: web`、HTML/CSS/资源/受控 effect 校验 | 原样保留，新增 `campusos.app-style-pack.v2` |
| 契约与发布 | 路由清单、授权矩阵、schema 检查、release-check、浏览器 smoke | 将新 API、migration、动态 UI 和回退流程加入门禁 |

### 2.2 当前问题

1. `scope` 同时承担管理级别与启停策略，导致 system gRPC 不能单独重启、前端也随后端状态消失。
2. 插件状态只有 installed/enabled/running/stopped/error，无法表达启动中、待重启、前端已加载但后端不可用等真实状态。
3. 动态插件缺少稳定业务入口；直接向主 Router 注册 Handler 无法安全卸载，也缺少统一可信调用上下文。
4. `App.vue`、导航和路由为静态硬编码，插件不能声明并热装载 Route、Navigation、Slot、Surface 和 Action。
5. 风格包主要改变受限区域的颜色和 CSS，缺少全视口 App Shell 布局合同；同时不能允许任意同源脚本。
6. Admin 和 SDK 仍按 system/user 二分展示生命周期，无法解释后端、前端和健康状态。

## 3. 架构目标与不做事项

### 3.1 目标

```text
HTTP / SSE
  -> Core Auth + Extension Gateway + UI Runtime Service
  -> Plugin Manager (lifecycle + revision + audit)
  -> builtin | gRPC | Wasm runtime

CampusApp
  -> ThemeProvider -> ThemeRoot -> AppShell
  -> Runtime Registry
  -> Route / Navigation / Slot / Surface / Action
  -> Declarative Renderer | core-side trusted module registry
```

### 3.2 明确不做

- 不允许插件取得 JWT、管理员布尔值、全局 Router/Store 或其他插件 DOM。
- 不允许风格包执行任意同源 JavaScript、改变 API/Method/权限/确认或审计策略。
- 不复制 `aurora-blog` 代码、业务模型或后端，只参考完整页面、封面层次、阅读布局和响应式组织。
- 不在本阶段建设公网插件市场、远程任意 Vue 模块、跨节点 Runtime 编排或零停机 Core 升级。
- 不删除旧路由、旧主题、旧 manifest 字段、历史 migration 或用户数据。

## 4. 兼容与迁移基线

1. Manifest 仍使用 `campusos.plugin/v1`，新增 `lifecycle` 和 `ui` 为可选字段。默认规则为 builtin+system=`restart`、gRPC=`plugin-restart`、Wasm=`hot`、前端=`hot`。
2. 旧 `status` 字段和插件管理接口继续返回；新增状态作为附加字段。后端重启期间，只要插件仍安装且未禁用，前端贡献保持可发现。
3. 新数据库 migration 只追加，不改写 `000001` 至 `000017`；先加可空或有默认值的状态/修订字段，再由启动加载过程回填。
4. `page-style-pack.v1`、`target: web`、首页和个人主页风格包继续走原加载路径；v2 校验失败时回退到 v1 或 Core 默认主题。
5. 现有静态业务路由保留为迁移期 fallback。动态注册成功后优先使用 Runtime Manifest，禁用或卸载时清理注册而不删除业务数据。

## 6. 工作包实施合同

### WP0 现状审查、计划书和兼容基线

- 输入：第二版计划、`v0.6.0-0.6.9` 进度、当前代码、migration、测试与文档索引。
- 后端/Web/Admin/SDK/数据库：只审查，不改变运行行为；形成旧字段、旧路由、旧主题和数据兼容清单。
- 输出：本计划、文档入口、WP0 进度记录。
- 验收：历史状态未改写；版本编号无冲突；`git diff --check`、Go 基线测试和现有构建结果可记录。

### WP1 插件 Manifest 与生命周期模型

- 后端：增加 `lifecycle.backend/frontend`、BackendState、FrontendState、Health；Manager 以 activation mode 而非 scope 决策；frontend 状态独立。
- 数据库：追加运行状态、前端状态、健康与 UI revision 字段，提供 down migration 和 schema contract。
- SDK：同步 Go Manifest 类型和默认推导函数。
- 验收：旧 manifest 三类 Runtime 默认值正确；system gRPC 为 plugin-restart；Wasm 替换失败保留旧实例；旧 `status` 仍兼容。

### WP2 插件 API Gateway 与 Runtime 分发

- 后端：新增 `/api/v1/extensions/:plugin/*path`；统一 JWT、权限、状态/健康、body 上限、timeout、trace、审计和标准错误。
- Runtime：builtin handler registry；gRPC 受控 extension endpoint；Wasm 受限 ABI；调用上下文的 user/roles/permissions 仅由 Core 注入。
- 文档/SDK：Extension Request/Response、错误和安全说明。
- 验收：覆盖未登录、无权限、插件停止、超限、超时、伪造用户字段及三类 dispatch；不能向主 Router 泄漏动态 Handler。

### WP3 CampusOS UI、ThemeRoot 与 App Shell

- Web：建立 CampusApp、ThemeProvider、ThemeRoot 和包含 Header、Primary/Secondary Nav、Hero、左右 Sidebar、PageOutlet、Floating Action、Footer 的 AppShell。
- 兼容：现有页面继续由 PageOutlet 承载；旧系统主题 CSS 仍能应用。
- 验收：桌面和移动端无重叠，必要登录/用户菜单、全局错误和插件健康区域不可被主题删除。

### WP4 UI Contract、Surface、Action 与扩展插槽

- 后端/SDK：Manifest `ui` 声明 route、navigation、slot、surface、action；ID、版本、权限、引用和 route namespace 校验。
- Web：定义 Design Token、Campus UI Primitive、Semantic Component、Layout、Runtime Context 类型。
- 验收：非法 Surface/Action 引用、重复 ID、越界路径和可变 Method 均被拒绝；插件必须有默认 renderer/schema。

### WP5 动态路由、导航和前端热加载

- Web：Runtime Registry 负责 `router.addRoute`、导航/插槽/surface/action 注册，并保存 disposer；插件更新先校验新定义再原子替换。
- 验收：启用、更新、禁用、卸载不会重复注册；清理后路由、菜单、插槽和缓存均消失；后端 restarting 时页面保留并显示 degraded。

### WP6 UI Runtime Manifest 与 SSE 同步

- 后端：`GET /api/v1/ui/runtime-manifest` 返回 contract、theme、revision、当前主体可见插件、生命周期和 UI 贡献；`GET /api/v1/ui/events` 只广播 revision 变化。
- Web：SSE 收到新 revision 后经带 JWT 的普通请求重取 manifest；断线退避重连并定时校准。
- 验收：权限过滤在后端完成；SSE 不泄漏私有 manifest；乱序/重复 revision 不导致重复注册。

### WP7 声明式 UI Renderer 与可信模块约束

- Web：默认 renderer 只支持白名单 Campus UI 组件、有限属性、数据绑定和已声明 Action；错误 surface 有标准回退。
- 可信模块：只允许 Core 编译期 registry 中的 module ID；禁止远程 URL、token 读取、全局 router/store 和跨插件 DOM。
- 验收：危险标签/属性/未知组件/未知 Action 被拒绝；Action 的 Method、path、确认和审计来自服务端合同。

### WP8 全屏 `campusos.app-style-pack.v2`

- 后端：在现有 stylepack 校验器上增加 v2 manifest、Layout Recipe、Surface Override、资源和动画 preset 校验；继续执行路径、CSS scope、HTML 和 effect 沙箱。
- Web：ThemeRoot 将 v2 token、全视口背景、header/nav/hero/footer/sidebar/content 布局和响应式模式映射到 AppShell。
- 示例：提供可直接复制的动态校园阅读风格包，使用自有资源，不复制参考项目代码。
- 验收：v1 与 v2 可切换；非法包不能应用；失败自动回退；主题无法隐藏安全区域或修改业务 Action。

### WP9 示例插件与完整链路验证

- 插件：提供可运行示例，包含 manifest 生命周期、动态 route/nav/surface/action、声明式默认 UI、Gateway endpoint、权限和 README。
- 验收：安装/启用后无需重建 Web 即出现入口；Action 经 Gateway 返回真实结果；停用清理前端，后端重启态保留只读 UI；三类 Runtime dispatch 有测试样例。

### WP10 现有插件渐进迁移

- 范围：优先迁移 personal-space、schedule、richtext、category-moderation 和 web-theme 的 UI 声明；复杂旧页面通过 Core trusted module ID 承载。
- 兼容：保留原路由、API、数据目录和权限；逐项迁移，不一次删除静态路由。
- 验收：帖子、富文本、课表、个人空间、版主管理和主题主要流程回归通过。

### WP11 Admin、SDK、文档与最终发布验收

- Admin：展示 backend/frontend/health、activation mode、pending restart、revision 和兼容错误；操作按钮按 lifecycle 决策。
- SDK：同步 Go/TypeScript UI Contract、Gateway client、Runtime Context 和模板；文档说明系统级与用户级调用权限差异。
- 文档：更新 API 索引、架构、插件、风格包、SDK、项目状态和 docs-site。
- 验收：Go、Web、Admin、docs-site、lint/format、migration/schema、链接、架构同步、release-check、browser smoke 和 diff check 全部有真实结果。

## 7. 风险、回滚与发布门禁

| 风险 | 控制 | 回滚 |
| --- | --- | --- |
| 动态注册导致残留路由 | 每项注册返回 disposer，revision 原子替换 | 关闭 runtime UI，使用保留的静态路由 |
| Runtime 更新中断 | 新实例健康验证后交换；旧实例延迟释放 | 保留旧实例/快照并恢复 desired state |
| v2 主题破坏可用性 | root scope、layout schema、必需 slot、CSS/资源校验 | 回退 v1 或 Core 默认主题 |
| 新状态与旧 API 漂移 | 旧 `status` 由新状态映射，契约测试双写验证 | 继续读旧字段，新增列允许默认值 |
| SSE 断线或乱序 | revision 单调递增、重连、全量 manifest 校准 | 降级为定时拉取，不阻断页面 |

每阶段至少执行定向测试、`GOCACHE=/tmp/campusos-go-cache go test ./... -count=1` 和 `git diff --check`。最终门禁还包括 Web/Admin/docs-site build、仓库 lint/format、migration/schema、文档链接、架构同步、`make release-check` 和真实 Chrome smoke。无法执行的项目必须在对应进度文档中写明原因，不得记为通过。

## 8. 最终完成定义

只有同时满足以下条件才可把本主线标记完成：生命周期不再由 scope 单独决定；Extension Gateway 至少有真实 Runtime 调用；插件前端可动态注册、更新和完整清理；Runtime Manifest 与 SSE 可恢复同步；声明式默认 UI 和可信模块边界可验证；v1 主题兼容且 v2 可覆盖完整 AppShell；示例插件走通安装到 Action；重点旧插件流程回归；Admin、SDK、API、架构和风格包文档一致；全部发布门禁有真实结果；`v0.6.10-dev` 至 `v0.6.22-dev` 记录与代码实际状态一致。
