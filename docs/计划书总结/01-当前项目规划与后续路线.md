# CampusOS 当前项目规划与后续路线

> 当前发布基线：`v0.13.0`
> 规划基线：分支 `djw-window`、提交 `4ce46bd`、migration `000001-000043`
> 更新日期：2026-08-28
> 状态：v14 G0 基线冻结已完成，业务功能仍按阶段实施

## 1. 当前结论

CampusOS 已形成可运行、可验证和可容器化交付的模块化单体。v13 仍是当前发布基线；v14 不改变
Core Module、Built-in Feature、External Plugin、Resource Package 四类能力和单主机 Docker 的现行边界。

此前页面中的 P0/P1/P2 只是版本间候选。根据新的业务输入和当前代码审查，v14 已从候选中选择一条连续主线：

> 以 User Storage Object Layer 为数据基础，建立管理员治理的 AcademicTerm，并以 Personal Documents
> 验证个人工作区的文件、版本、安全和恢复能力。

完整范围以 [v14 正式项目计划](../项目计划v14/00-v14版本计划书.md) 为准，本页只提供当前摘要。

## 2. v14 正式范围

| 主线 | 当前问题 | v14 目标 |
| --- | --- | --- |
| G0 基线 | v13 Final 后又新增修复和 `000043`，部分当前文档仍写 42 个 migration | 已冻结提交、Schema、OpenAPI、Route、Module、文件/课表盘点和隔离 migration down/up 证据 |
| AcademicTerm | 用户可输入任意年份，服务端仍按当前日期推断学期 | 管理员维护 spring/fall、open/closed/default；用户写入必须通过 Term Guard |
| User Storage | 业务可拿绝对路径，用量主要靠目录遍历和进程内互斥 | Object ID、metadata、owner、Reservation、原子本地写、对账和 Provider 边界 |
| Personal Documents | Personal Space 尚无统一私有文档应用 | TXT/Markdown/CampusDoc 编辑、不可变版本、PDF 只读和受门禁的 DOCX 预览 |
| Reliability/Recovery | Outbox 已有，但复杂转换和文件/DB 一致性仍缺闭环 | 隔离 Converter、retry/dead-letter、故障注入、联合备份恢复和 hash 对账 |

计划采用 `shadow -> dual -> enforce` 灰度。旧课表 JSON、头像、内容图片和 RichText 资产先盘点、再登记、
最后切换新写入；v14 不批量删除或静默重命名历史文件。

## 3. v14 非目标

- 多人协作文档、跨用户 ACL、分享链接和通用个人云盘。
- 完整 Office 在线兼容、PDF 编辑、OCR、AI 文档问答和全文/向量检索。
- S3/OSS/WebDAV 生产迁移、Google Drive/OneDrive 同步。
- 标准 MCP、真实 protobuf gRPC、远程插件市场、Agent Runner。
- 多节点 API/Worker、高可用数据库、自动 TLS。

这些方向仍是后续候选，不能从 Object Port、Converter 原型或接口预留推断为已经实现。

## 4. 实施顺序

```text
G0 真实基线
  ├─> AcademicTerm -> Admin/Term Guard -> Schedule 历史迁移
  └─> Storage Object -> Documents/Version -> Preview/Converter
                                          └─> 恢复与 Final
```

标准团队按 8 周执行；只有 1 名后端和 1 名前端时按 10–12 周安排，不通过取消迁移、并发、安全、恢复或
浏览器测试压缩周期。DOCX Preview 是可降级项；Storage 配额/一致性、课表历史数据和文档版本不可降级。

## 5. 当前与后续版本的边界

### v14 Final 前

- 应用版本和 README 继续显示 `v0.13.0`。
- 计划文档只表示承诺范围；每项完成情况必须进入 `docs/进度/v0.14-dev/`。
- migration 从 `000044` 顺序追加；如有并行 migration，合并前整体顺延。
- 未通过 Gate 的功能只能标记实现中、实验性或关闭，不能写成已经交付。

### v15 及以后候选

- 真实 Windows/arm64 发行认证、镜像 SBOM/签名和目标环境长稳。
- S3/OSS/WebDAV Provider、多实例对象/配额一致性。
- OAuth/OIDC、Passkey、SSE/WebSocket 通知。
- 标准 MCP、标准进程扩展协议、远程插件目录。
- 隔离 Agent Runner、多节点/HA 和跨用户协作能力。

后续版本立项仍需单独冻结基线、威胁模型、迁移、回滚和验收，不能提前并入 v14。

## 6. 不应回退的边界

- 不把模块化单体拆成无必要的微服务。
- 不把 Built-in Feature 或 Resource Package 放回普通插件生命周期。
- 不允许 External Plugin、Converter 或 Agent Runner 获取核心数据库、JWT、用户 Token 或完整宿主目录。
- 不在 Feature 停用、Plugin 卸载、资源切换、学期关闭或文档回收时隐式删除用户数据。
- 不为了通过测试移除权限、审计、清洗、配额、事务、路径或数据库约束。
- 不把 Local Provider 接口抽象宣传成已具备生产对象存储。
