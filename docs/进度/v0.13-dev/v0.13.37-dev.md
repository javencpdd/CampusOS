# v0.13.37-dev：修复 Shell 脚本缺失可执行位导致的 CI 迁移演练失败

> 日期：2026-08-03
> 状态：实现并验证
> 范围：scripts/ 与仓库 Skill 脚本的 Git 可执行权限位

## 1. 目标

CI Backend Test 的 `make database-check` 在 `v13-migration-check` 阶段失败：

```text
make[1]: ./scripts/test-v13-schema-index-hygiene-migration.sh: Permission denied
make[1]: *** [Makefile:151: v13-migration-check] Error 127
```

根因：该脚本在 Windows 上创建，提交时 Git 权限位为 `100644`，而 `Makefile` 按仓库惯例以
`./scripts/...` 方式直接执行，Linux CI Runner 上因此拒绝运行。本阶段修复该文件并排查全仓库同类隐患。

## 2. 完成内容

- 排查 `git ls-files -s` 中全部 `100644` 的 `.sh` 文件，共 6 个，统一补齐为 `100755`：
  - `scripts/test-v13-schema-index-hygiene-migration.sh`：CI 失败的直接原因，`Makefile` 以 `./` 直接执行。
  - `scripts/check-v13-reliability-observability.sh`、`scripts/test-docker-dev-setup.sh`：当前经 `bash`
    调用未受影响，但目录内其余脚本均为 `100755`，补齐以保持一致并防御直接执行。
  - `skills/sources/campusos-dev-nocommit/scripts/check_task.sh`、
    `skills/sources/campusos-dev-workflow/scripts/check_task.sh`、
    `skills/sources/campusos-project-onboarding/scripts/context_snapshot.sh`：Skill 文档以直接执行
    方式引用，补齐保证 clone 后直用。
- 不修改任何脚本内容、Makefile 或 CI 工作流；仅变更 Git 文件权限位。
