## 2. 实际完成内容

- 新增 `cmd/campusos-capacity`：仅允许 loopback 目标，采集公开列表和固定有界管理员读取的 p50/p95/p99、2xx 比率、goroutine、heap、DB 空池等待和 Reliability 队列摘要。
- 受保护采样只接受权限为 `0600` 的本地 Authorization 文件，不接受命令行 Token、任意用户 ID、自由查询或写 API。
- 固定管理员读取覆盖准入列表、MFA 策略、指标摘要和 Reliability 摘要，补齐 C0 管理平面覆盖。
- 新增严格候选预算 `v0.13-capacity-budget.json`，对真实同环境比较保持 20% p95 比例门槛。
- 新增隔离演练预算 `v0.13-capacity-drill-budget.json`：仅对空数据库 loopback 的 1-10ms 计时加入固定 8ms 绝对抖动阈值，保留原始分位数，不能用于真实候选性能结论。
- 新增 `scripts/v13-capacity-drill.sh`：创建临时 PostgreSQL 数据库、运行全部 migration、启动 loopback API、签发临时管理员授权、执行公开/受保护 baseline-candidate 比较并清理数据库、进程、二进制和授权文件。
- 演练将样本上限限制在 20-50，每轮默认 40，避免超过 Reliability 的真实 `120 次/分钟/管理员` 查询限流；不关闭或放宽限流。
- 新增 `make v13-capacity-check`、`make v13-capacity-drill`，并将隔离演练接入 `release-check`。

## 4. 架构变化

容量采样是发布/运维工具而不是业务模块。它通过公开 HTTP 合同和最小权限管理员读取观察系统，不能拿到数据库连接、用户 Token、任意文件系统或写能力。Runtime 指标仍归 Observability Core，Reliability 限流仍归 Reliability 边界。

## 5. 兼容和迁移处理

- 无 schema、业务 API 或资源目录迁移。
- 历史开发库中的 dead-letter 和在线 Session 不再被当作候选容量证据；隔离演练使用独立空库并在退出时只清理自己创建的资源。
- 真实候选环境仍使用严格预算；绝对抖动阈值不改变生产 SLO，也不能通过命令行临时放宽。

## 7. 回滚方式

关闭发布脚本中的演练调用只应作为紧急构建基础设施恢复，不能删除容量工具、预算或观测指标。生产容量结论永远可以回退到上一个已版本化 baseline/预算文件；不得通过提升连接池、关闭查询限流或清理 dead-letter 伪造通过。

## 8. 已知限制

- 隔离演练是确定性的发布回归证据，不等价于真实生产负载/长稳压测；长稳数据仍需由部署环境按文档采集。
- 可比较的管理员采样需要临时最小权限授权文件；工具故意不会替操作者创建真实用户或导出 Token。
