# v0.13.28-dev：Windows Git 提交与 PR 脚本文档补全

> 日期：2026-08-02
> 状态：文档实现并验证
> 范围：Windows PowerShell、Git Bash、WSL2 下的 `git_commit.sh` 与 `git_pr.sh` 使用方式

## 1. 问题

原 PR 脚本说明虽然提到 PowerShell 可以显式调用 Git Bash，但绝大多数示例仍只有
`./sh/git_commit.sh` 和 `./sh/git_pr.sh`，缺少 Windows 可直接复制的完整提交、push、PR 和环境变量流程；
也没有解释 `Set-ExecutionPolicy`、裸 `bash`、GitHub CLI PATH 和 `--body-file` Windows 路径等常见问题。

## 2. 完成内容

更新 `docs/help/github使用相关/PR提交脚本使用说明.md`：

- 明确 `.sh` 不能作为 PowerShell 脚本直接运行，`Set-ExecutionPolicy` 对其无效；
- 从当前 `git.exe` 安装目录动态解析 Git for Windows 的 `bin\bash.exe`，避免裸 `bash` 误用 WSL；
- 增加 PowerShell 下查看状态、diff、commit、单独 push、PR dry-run 和正式创建 PR 的完整命令；
- 增加 `$LASTEXITCODE` 错误处理；
- 增加 `$env:CAMPUSOS_GIT_REMOTE` 和 `$env:CAMPUSOS_ALLOW_PROTECTED_PUSH` 的 PowerShell 写法；
- 分别给出 Git Bash `/c/...` 与 WSL2 `/mnt/c/...` 路径；
- 说明 WSL 的 Git 身份、凭据和 `gh` 登录状态可能与 Windows 独立；
- 增加 `.sh` 无法识别、Git Bash 找不到 `gh`、`--body-file` 路径不存在三类故障处理。
- 根据 PowerShell 实际反馈补充 `$gitBash` 不是内置变量、每个新终端必须重新初始化，以及无需变量的完整路径
  自包含命令；同时解释变量未赋值和省略调用运算符 `&` 的两种报错。

官方文档 `docs-site/contributing/workflow.md` 同步使用动态 Git Bash 解析方式，并加入 PowerShell 完整的
commit、PR 预览和 PR 创建示例。根 README 已有 Windows 入口和详细 Help 链接，本轮不重复扩张 README。

## 3. 行为边界

- 没有修改 `sh/git_commit.sh` 或 `sh/git_pr.sh`，脚本仍动态读取当前分支。
- `git_commit.sh` 仍会执行 `git add -A`，运行前必须确认没有混入无关改动。
- `git_pr.sh --dry-run` 不需要 GitHub 登录，不 push、不创建 PR；正式执行仍要求 `gh auth status` 正常。
- 普通贡献流程不应启用 `CAMPUSOS_ALLOW_PROTECTED_PUSH=true`。
- 文档不要求开发者把 GitHub Token 写入脚本、环境示例或仓库。
