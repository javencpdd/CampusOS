# v0.13.22-dev - Docker 开发首次配置向导与 SMTP 透传

> 日期：2026-07-29
> 阶段：v0.13 Final 后开发体验补充
> 实现状态：已完成
> 验收状态：已验收（Windows PowerShell 与实际容器启动限制见第 8 节）

## 1. 阶段目标

让第一次使用 Docker 开发环境的 Windows/Linux 开发者不再直接面对 Compose 细节：先由脚本生成一份
受 Git 忽略的基础配置，填写端口和邮件方式，再由同一脚本完成安全校验和启动。修复原开发 Compose 将
`EMAIL_PROVIDER=fake` 写死、即使填写 SMTP 变量也无法传入 API 的问题。

## 2. 实际完成内容

- `docker-dev.sh` 和 `docker-dev.ps1` 新增 `setup` 命令。
- 第一次执行生成 `deploy/docker/.env.dev.local`，保留模板不变并限制 POSIX 文件权限。
- 第二次执行校验配置；Bash 使用 `setup --start`、PowerShell 使用 `setup -Start` 可直接启动。
- 后续 `up` 自动优先读取已存在的 `.env.dev.local`；显式 `CAMPUSOS_DOCKER_DEV_ENV` 仍具有最高优先级。
- 校验全部开发宿主端口的范围和冲突，拒绝把固定开发凭据绑定到非 `127.0.0.1` 地址。
- 区分 `EMAIL_PROVIDER=fake` 与 `smtp`：fake 明确提示不会发邮件；SMTP 校验 host、port、from、
  username/password 配对、timeout 非空和 STARTTLS 布尔值。
- 配置摘要不输出 SMTP 密码。
- `compose.dev.yml` 改为从环境文件透传全部 `EMAIL_*`，默认值继续是 `fake`，保持原快速启动兼容。
- `config` 只要求 Docker CLI 与 Compose v2，不要求 daemon；真正 build/up 时再检查 Docker daemon。

标准流程：

```bash
./scripts/docker-dev.sh setup
# 编辑 deploy/docker/.env.dev.local
./scripts/docker-dev.sh setup --start
```

```powershell
.\scripts\docker-dev.ps1 setup
# 编辑 deploy/docker/.env.dev.local
.\scripts\docker-dev.ps1 setup -Start
```

## 4. 行为和安全边界

- `fake` 仍是开发默认值，不依赖外部邮件服务，但不会发送、打印或提供验证码收件箱。
- 完整注册、密码找回和邮箱绑定流程必须选择 `smtp`，或者后续接入隔离的测试 SMTP 服务。
- 脚本只验证配置结构和 Compose 透传；不主动拿用户凭据连接 SMTP，避免初始化阶段产生真实邮件或泄露。
- `.env.dev.local` 已由 `.gitignore` 的 `.env.*.local` 规则排除。
- 固定数据库、JWT、Challenge、Session、MFA 和开发管理员值仍只允许 loopback 开发，不允许公网部署。
- 单主机部署继续使用 `.env.docker` 和 `docker-deploy.*`，不读取开发配置。

## 5. 兼容和迁移处理

- 没有 API、数据库、migration、权限、用户数据或插件数据变化。
- 未创建本地配置时，`up` 继续读取原 `.env.dev.example`，行为与此前一致。
- 已创建本地配置后，`up` 自动使用它，不要求每次重复设置环境变量。
- `CAMPUSOS_DOCKER_DEV_ENV` 自定义路径保持兼容，可用于多个隔离开发配置。
- 原 `EMAIL_PROVIDER=fake` 语义未删除，只增加醒目提示；切换 SMTP 后必须重新申请 Challenge，旧 Fake
  事件不会补发。

## 7. 回滚方式

1. 恢复 `compose.dev.yml` 的固定 fake Provider。
2. 恢复两套 `docker-dev` 脚本原命令集合，并删除向导测试。
3. 从 `.env.dev.example` 删除新增 SMTP 字段。
4. 恢复 README、Help 和 docs-site 的首次启动命令。

本地 `.env.dev.local` 是用户配置，回滚代码时不应自动删除；其中可能包含 SMTP Secret。

## 8. 已知限制

- 当前执行环境没有 `pwsh`，PowerShell 路径通过等价实现、静态合同和 CRLF 规则审查，未在本轮实际执行。
- Docker CLI/Compose 可用，但当前沙箱没有 `/var/run/docker.sock` 权限，因此未在本轮重复启动完整容器栈；
  Compose 渲染和既有 Docker 合同检查已通过。
- 向导不会探测 SMTP 网络、认证和最终收件箱投递；这些只能在启动 API 后用新验证码请求验证。
- 当前没有内置 Mailpit 服务；保留 fake 时不能通过浏览器取得验证码。
- 本阶段使用 `campusos-dev-nocommit`，未创建提交或标签。
