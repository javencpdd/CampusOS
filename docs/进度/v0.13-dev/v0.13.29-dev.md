# v0.13.29-dev：TypeScript 7 路径映射兼容

> 日期：2026-08-03
> 状态：实现并验证
> 范围：Web/Admin TypeScript 配置与开发文档

## 1. 问题

Admin `tsconfig.json` 的 `baseUrl: "."` 在 TypeScript 6 中产生弃用错误，并将在 TypeScript 7 中停止工作。
Web 使用相同配置，并额外通过 `ignoreDeprecations: "5.0"` 隐藏旧版本弃用提示。仅把静音版本改成 `6.0`
只能延后问题，不能形成 TypeScript 7 兼容方案。

## 2. 实现

Web 和 Admin 统一调整为：

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

- 删除 `baseUrl`；`paths` 从 TypeScript 4.1 起不再要求同时配置它。
- 将原先依赖 `baseUrl: "."` 前缀的 `src/*` 改为相对 tsconfig 的显式 `./src/*`。
- 删除 Web 的 `ignoreDeprecations: "5.0"`，让后续真实弃用问题进入编辑器和构建反馈。
- 保留 Web/Admin `vite.config.ts` 中指向 `src` 的 `@` alias；TypeScript 负责类型解析，Vite 负责运行时构建解析。

迁移依据为 TypeScript 官方
[6.0 release notes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-6-0.html#deprecated---baseurl)：
官方建议移除 `baseUrl` 并为 `paths` 条目补充显式前缀，而不是依赖 `ignoreDeprecations`。

## 3. 影响与兼容

- `@/...` import 写法不变，不需要批量修改业务源码。
- Vite 开发与 production build 的运行时 alias 不变。
- 当前锁文件仍使用 TypeScript 5.9.3；该配置同时兼容当前版本、TypeScript 6 和计划中的 TypeScript 7 行为。
- 没有 API、数据库、Docker 环境变量或用户数据变化，不需要 migration 或重启后端。

## 5. 回滚

不建议重新加入 `baseUrl` 或用 `ignoreDeprecations: "6.0"` 静音。若 `@` 路径出现问题，应优先检查
`paths` 是否相对对应 tsconfig、Vite alias 是否仍指向同一 `src`，并采用 forward-fix。临时回退只涉及两个
tsconfig，不影响构建产物之外的数据。
