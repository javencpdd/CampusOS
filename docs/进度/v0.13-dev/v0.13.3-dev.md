# CampusOS v0.13.3-dev 结构化列表批量读取说明

> 日期：2026-07-19

> 实现状态：已完成

## 1. 阶段目标

消除 Mutual Aid 和 Secondhand 公开列表按条读取 Feature Detail 的 N+1，同时保持 Community 分页、排序、
总数、可见性、DTO、Feature Gate 和缺失 Detail 的完整性失败语义不变。

## 2. 实际完成内容

- 两个 Feature Store 增加 `GetMany(context.Context, []string)` 合同。
- PostgreSQL Adapter 使用参数化 `WHERE thread_id = ANY($1)` 一次读取，不拼接 SQL；空 ID 列表返回空映射。
- Memory Adapter 在同一读锁内返回克隆对象，调用方不能修改内部事实。
- `ListPublic` 先取得 Community Thread 页，再一次批量读取 Detail，最后严格按 Thread 顺序组装。
- 可见类型化 Thread 缺少 Detail 时仍整页返回 `ErrNotFound` 包装错误，不静默丢项或返回半条记录。
- 计数 Store 测试创建 5 条数据，证明列表只调用一次 `GetMany`、不调用逐项 `Get`，并覆盖缺 Detail 失败。

## 4. 架构变化与查询预算

Community 仍拥有 Thread 页面，Feature 仍拥有 Detail 表；没有跨模块 Join 或 Repository 依赖。列表查询由：

```text
1 次 Community 列表查询 + N 次 Detail Get
```

变为：

```text
1 次 Community 列表查询 + 1 次 Feature Detail GetMany
```

因此 page size 1、20、100 的 Detail Store 调用数均为 1，满足 `Q(max) <= Q(1) + 1`。

## 5. 兼容与回滚

无 API、DTO、路由、权限、migration 或数据变化。`Get` 保留给详情页和作者读取；如批量 Adapter 发生缺陷可
forward-fix，但不得长期恢复 N+1。PostgreSQL 回滚只需恢复旧代码，不执行 down migration。
