# v0.13.7-dev - Appearance 双端交付合同

> 日期：2026-07-22  
> 阶段：A5  
> 实现状态：已完成  
> 验收状态：已验收；严格资源合同、全包双端浏览器矩阵和发布门禁通过

## 阶段目标

让系统主题、首页包和个人主页风格包使用同一个严格的双端交付合同，并保留历史包的只读兼容路径。

## 实际完成内容

- 在 `stylepack` 增加 `campusos.appearance-delivery/v1`、`valid`、`invalid` 和 `legacy-readonly` 状态。
- 新增 `preview_images.desktop/mobile`、安全 `issues` 报告、包内 checksum 和严格/兼容两组加载 API。
- 严格模式检查双端声明、断点响应式规则、两张预览、对比度、配置绑定和动效的 reduced-motion 降级。
- 新 ZIP 导入、源码目录重新选择和主题加载全部使用严格 API；旧读取 API 保持兼容，并明确返回 `legacy-readonly`。
- `campusosctl resource adopt` 与 `resource inspect` 对三类 Appearance Resource Package 复用相同的严格校验和 target 检查。
- 个人主页资源预览仅能读取严格包中声明的图片资源；未声明路径、CSS 和路径穿越均返回 404。
- 新增 `make appearance-delivery-check`，作为 `release-check` 的静态前置门禁。

## 架构变化

Appearance Resource Package 不再由不同入口各自决定是否可用。兼容读取可保留旧页面，严格选择和应用则统一通过 `stylepack.Load*Strict`。该边界不将资源包变成业务插件，也不向资源包暴露数据库、Token 或宿主路径。

## 兼容和迁移处理

- 未声明 v13 合同的旧包在普通读取中标为 `legacy-readonly`，不会被直接删除。
- 严格入口会拒绝旧包，避免把 warning 当作应用许可。
- `preview_image` 仍是旧客户端的缩略图字段；新包需额外声明双端预览。
- `resource.json` 继续使用原有 `campusos.resource/v1`，类型和目录布局不变。

## 回滚方式

关闭或回退严格入口调用即可恢复兼容读取；不需要删除资源目录、用户偏好或已保存的主页样式。生产修复优先采用 forward-fix，不回改历史资源清单。

## 已知限制

真实浏览器矩阵需要受控 API、Web、测试账号和 Chromium 环境。本阶段已交付矩阵脚本和失败证据格式，但当前受限执行环境不启动候选服务；该项保留到 Final 真实环境复核。
