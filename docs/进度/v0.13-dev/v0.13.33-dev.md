> 日期：2026-08-03

> 范围：`sh/` 跨平台代理入口、脚本可读性、README、Help 与官方 Docker 文档

## 1. 完成内容

- 保留 `sh/proxy.sh` 作为 Linux、macOS、WSL2、Git Bash 的 Bash 入口，并明确它必须通过 `source` 调用，
  会管理当前 Shell 环境、Git 全局代理和带标记的 SSH 配置。
- 新增 `sh/proxy.ps1` 作为 Windows PowerShell 入口，默认代理为 `http://127.0.0.1:7897`，支持
  `on`、`off`、`status`、`test`、`-ProxyHost`、`-Port`、`-SkipGit` 和可选 `-SystemProxy`。
- Windows 脚本用 dot-source 让环境变量留在当前 PowerShell；修改 Git/Windows 系统代理前把旧值保存到
  被忽略的 `.campusos/run/proxy-windows-state.json`，关闭时恢复，而不是无条件删除用户原配置。
- `-SystemProxy` 只管理当前用户 WinINET，不修改 WinHTTP 或 Windows OpenSSH；Docker Desktop 已运行时仍需
  `docker desktop restart`。
- `sh/git_commit.sh`、`sh/git_pr.sh`、`sh/proxy.sh`、`sh/stop_docker.sh`、`sh/proxy.ps1` 顶部统一补充中文
  用途、适用平台、基本用法和关键风险。`stop_docker.sh` 明确会停止整个 Engine 的全部容器。
- Windows `curl.exe` 测试失败现在返回诊断警告，不再因 PowerShell 严格错误策略提前终止脚本。
- README、Windows Docker 实操报告、开发运行指南和官方 Docker 文档同步命令。

## 3. 回滚与限制

删除 `sh/proxy.ps1` 和对应文档即可回滚代码。若已经执行 `on -SystemProxy`，应先在同一仓库执行
`. .\sh\proxy.ps1 off` 恢复旧配置。Windows 脚本当前只面向 HTTP/mixed 代理端口；纯 SOCKS 端口需在代理
客户端开启 mixed/HTTP 监听或手工配置对应工具。
