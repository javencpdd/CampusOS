# v0.13.26-dev：数据库迁移与 Schema 冗余治理

> 日期：2026-07-30  
> 状态：实现并验证  
> 范围：`migrations/`、数据库门禁、Admin 架构视图、Help 与官方文档

## 1. 目标

审计当前 40 个 migration 的最终 PostgreSQL 结构和开发数据，区分真正冗余与版本化兼容事实；仅删除具有
系统目录和查询覆盖证据的冗余对象，不合并或改写已发布 migration，不删除业务数据。

## 2. 审计结论

在独立临时数据库完整应用 `000001-000040` 后：

| 项目 | 结果 |
| --- | --- |
| 定义完全相同的重复索引 | 0 |
| 定义完全相同的重复约束 | 0 |
| 严格左前缀冗余 B-tree 普通索引 | 9 |
| 数据一致性审计 | 78 项、0 违规 |
| Schema 表 | 68 张 |

现有开发数据库的 78 项数据审计同样为 0 违规；九个候选索引当前合计占用 96 kB。该体积仅反映本机小数据，
生产收益会随表数据和索引膨胀增长，不能把本机绝对值外推为生产容量结论。

## 4. 持续门禁

新增 `scripts/migration-hygiene.sql`，检查：

- 完全相同的索引定义；
- 同表、同谓词且被同键唯一索引或更长 B-tree 严格左前缀覆盖的非唯一索引；
- 完全相同的约束定义。

`scripts/database-check.sh` 新增 `hygiene` 动作，`all` 自动包含该检查。新增
`scripts/test-v13-schema-index-hygiene-migration.sh`，在独立临时数据库执行 `000001-000040` 基线、
`000041` up/down/up、数据审计、Schema 合同和冗余检查，并接入 `make v13-migration-check`。

## 5. 有意保留的兼容事实

- `accounts(type=email)` 是权威登录邮箱，`users.email` 暂为旧 API 兼容投影。
- `permission_definitions/role_permissions` 是当前权限代码目录，旧 `permissions` 尚在兼容窗口。
- Thread 的单值 `status` 与治理三轴、Plugin 的单值状态与 Runtime 三轴都仍有旧读取路径。
- 后续 migration 的种子 upsert 和历史回填用于升级旧实例，不等同于重复业务行。

这些对象没有在本轮删除。后续若要收敛，必须先完成调用清单、兼容遥测、API 窗口、独立迁移和恢复演练。

## 8. 部署、风险与回滚

1. 升级前完成数据库备份和恢复验证。
2. 使用项目迁移器执行 `make migrate-up`；不要把 `000041` 手工包进事务。
3. 升级后运行 `make migrate-status` 和 `make database-check`。
4. concurrent 模式降低正常写阻塞，但仍需观察锁、I/O、复制延迟和无效索引。
5. 生产优先 forward-fix；`000041.down.sql` 只用于隔离演练，重新创建九个索引会恢复额外写放大。
