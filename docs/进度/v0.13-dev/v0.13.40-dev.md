# v0.13.40-dev：评论治理删除与版主授权变更通知

> 日期：2026-08-03
> 状态：实现并验证
> 范围：Community 通知域、PostService 治理删除、Moderation 版主授权、模块 Port 接线、Help/官方文档

## 1. 目标

既有站内通知只覆盖“评论收到回复、帖子收到直接评论、管理员下架帖子”（另有回收站通知）。用户在自己的
评论被版主或管理员删除、自己被授予或撤销版主权限时没有任何感知。本阶段按统一通知合同补齐这两类事件，
并保持既有的自我抑制与可靠事务语义。

## 2. 完成内容

### 2.1 评论被版主或管理员删除（`community.post.deleted_by_moderator`）

- `PostNotificationWriter` 新增 `NotifyPostDeletedByModerator`；正文说明评论被版主或管理员删除，
  跳转所属帖子详情（评论已删除，不再使用楼层锚点）。
- `PostService.AdminDeletePost` 增加 `actorID` 参数并纳入可靠命令 `community.post.admin_delete`：
  评论删除、回复计数递减和作者通知在同一事务提交；通知写入失败时整个删除回滚。Outbox 事件使用新增的
  `eventbus.EventPostDeleted`（`post.deleted`）。列表缓存失效移到命令提交之后，与
  `executeGovernanceDelete` 语义对齐。
- 自我抑制：版主删除自己的评论（`post.AuthorID == actorID`）不产生通知。
- 调用链透传：`ModerationGateway.DeletePostForModeration(ctx, id, actorID)`，由
  `moderation.Service.DeletePost` 传入治理操作者。

### 2.2 版主授权与撤销（`identity.moderator.granted` / `identity.moderator.revoked`）

- Community 新增公开 Port `community.notification-writer`（`ModerationNotifier` 接口），由
  `moduleNotificationWriter` 惰性解析到 NotificationService；Moderation 模块按既有 Port 模式消费，
  不接触通知仓储。
- 挂点 `moderation.Service.SetModeratorCategories`：利用既有 before/after 赋值对比，仅对新增板块发
  `granted`、仅对移除板块发 `revoked`；赋值未变化（幂等更新）不重复通知；管理员修改自己的授权
  （`actorID == userID`）自我抑制。
- 投递语义：授权先在 Identity 可靠命令 `identity.moderator.scope.replace` 中提交，通知是提交后的
  尽力而为投递，失败只记录日志，不把已生效授权伪报为失败。这与内容类通知的“失败即回滚”不同，已在
  文档中明确。
- 跳转合同：单板块变更跳 `/threads?category_id=<board_id>`，多板块跳 `/threads`；正文板块名截断并
  限制总长度（≤150 runes），超过 3 个板块折叠为“「A」、「B」等 N 个板块”。
- Web 前端零改动：通知标题、正文和跳转全部由服务端渲染，NotificationCenter 继续按 `action_url` 透传。

### 2.3 测试

- `TestAdminDeletePostNotifiesAuthorWithoutSelfNotification`：作者收到删除通知与跳转/元数据合同、
  回复计数递减、版主自删不通知。
- `TestAdminDeletePostRollsBackWhenNotificationCannotBeStored`：通知失败时评论与回复计数整体回滚。
- `TestNotificationServiceModeratorScopeMessages`：授予/撤销类型、单/多板块跳转、正文长度有界、
  空板块集不写入。
- `TestSetModeratorCategoriesNotifiesGrantAndRevoke`：初次授予、差额授予/撤销、幂等更新不重复通知、
  清空授权全量撤销通知。
- `TestSetModeratorCategoriesSkipsSelfNotification`：经可自我授权的策略替身验证自我抑制（真实
  Identity 层本身会拒绝自我越权赋值，服务层抑制为纵深防御）。

## 5. 后续任务

- 治理恢复（下架恢复、回收站恢复）、审核拒绝、置顶/锁定事件仍只有审计无通知，可在同一合同上继续扩展。
- 版主授权通知目前是授权提交后的尽力而为投递；如未来要求“授权成功但通知必达”，需要把通知纳入
  Identity 命令事务或引入 Outbox 驱动的异步投递，届时需重新评估模块依赖方向。
- Web 通知中心如未来需要按类型展示图标或分组，需要新增前端类型映射，目前无需改动。
