# CampusOS v0.13.6-dev Reliability 运营闭环说明

> 日期：2026-07-19
> 阶段：A4 Reliability 运营闭环
> 实现状态：已完成
> 验收状态：已验收；Final 已复核故障注入、规则合同、队列收敛和发布门禁，真实通知链路仍属部署演练

## 1. 阶段目标

让可靠事件、邮件投递、Identity Challenge 和 Session 的异常能够通过统一低基数指标与管理端定位，并提供
可重复的故障注入、告警规则和安全恢复步骤，同时保持 Consumer Receipt、Attempt 和命令审计语义不变。

## 2. 实际完成内容

- Reliability Worker 接入统一 Meter，覆盖 Claim、Complete、Retry、Dead、Finalize、Receipt 和 lease conflict。
- Consumer duration 使用固定 Consumer ID 与结果标签，不写事件 ID、用户数据、payload 或错误文本。
- Summary 增加积压年龄、近 1/24 小时失败 Attempt、健康状态，并同步 queue/age Gauge。
- Email Delivery 记录 Provider 投递结果与耗时，SMTP 暂时失败只输出 `unavailable`，不输出收件人或验证码。
- Challenge 记录 request/verify/consume 的 success、invalid、rate-limited、error。
- Session 记录 issue/verify/refresh 的 success、invalid、reuse、error；Refresh Token Reuse 有独立指标。
- Admin 可靠任务页增加队列健康、积压年龄、失败趋势和诊断入口；诊断入口只应用 dead/retry 筛选。
- 新增 Prometheus recording/alert rules，覆盖 Worker 停止、积压过旧、dead-letter 增长、SMTP 降级和 Refresh Reuse。
- 更新 Prometheus 示例为独立 `127.0.0.1:9091` exporter，不再指向公开业务 API 端口。
- 新增 v0.13 Runbook 和故障注入门禁，并接入 release-check。

## 4. 架构变化

Reliability、Identity 和 Email Delivery 通过 `platform.observability.meter` 使用同一 Observability Core。Module
Registry 声明 Observability 依赖；直接构造的旧测试/嵌入场景仍可在没有 Meter 时运行。领域模块只持有最小
`observability.Meter` 接口，不取得 Collector 或 Prometheus Server。

Summary 的新字段来自原 Store 的有界聚合查询。PostgreSQL 使用单次聚合与两个固定时间窗口子查询；Memory
实现保持同一语义。没有增加明细遥测表或无界日志。

## 5. 兼容和迁移处理

- 无 migration、路由、权限或旧 Summary 字段删除；Admin API 仅增加字段。
- Consumer Receipt、Attempt、lease owner/generation、Replay 和 required audit 流程未改变。
- Prometheus 默认仍关闭；旧部署不新增端口。
- `NewService`、Identity/Email 旧构造入口保持可用，Meter 通过加法 Setter/Module Port 接入。
- 规则撤销或 exporter 关闭不改变 Outbox 数据与 Worker 行为。

## 7. 回滚方式

1. 设置 `OBSERVABILITY_PROMETHEUS_ENABLED=false` 并重启可关闭 exporter，不影响可靠任务。
2. 从 Prometheus 配置中移除 `campusos-v13.rules.yml` 只撤销告警，不改业务数据。
3. 代码回滚时先回退 Admin 加法字段，再移除各 Service 的 Meter 注入和新指标目录。
4. 禁止在任何回滚中删除 Receipt、Attempt、审计或 dead 事件，也禁止批量重置 attempts。

## 8. 已知限制

- 当前环境没有 `promtool`，且受限环境不允许启动 Docker/真实监听，因此本阶段验证了规则 YAML、指标引用、
  故障条件与恢复收敛；由真实 Prometheus alert engine 触发/恢复告警归 Final 候选环境复核。
- 健康阈值首版固定为积压 300 秒或存在 dead 事件；后续可在保持指标合同稳定的前提下把告警阈值留给部署配置。
- 指标是单实例进程内状态，不做多节点聚合。
