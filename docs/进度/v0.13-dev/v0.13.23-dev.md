## 1. 阶段目标

基于一台真实 Windows 开发机完成的 Docker Desktop 安装和 CampusOS 启动过程，补充一份可以从零复现的
实操报告。同步审查切换 Git 分支后的提交/PR 脚本行为，补齐 upstream、主干保护、head/base 冲突和
remote 选择，并在根 README 提供关键使用流程。

## 2. 实际完成内容

- 新增 `docs/help/Windows系统Docker部署实操报告.md`。
- 记录 Windows 上安装 WSL 2 和 Docker Desktop 的推荐顺序。
- 解释 `docker-dev.ps1 setup` 只生成/校验配置，`setup -Start` 或 `up` 才启动服务。
- 解释 PowerShell 中误输入 `sh` 的含义和返回方式。
- 记录 Docker Hub OAuth Token 获取失败的判定，明确它属于 DNS/代理问题而非 CampusOS Dockerfile 错误。
- 给出 `127.0.0.1:7897` 系统代理、`docker desktop restart` 和
  `docker pull hello-world:latest` 的验证流程。
- 解释 `http.docker.internal:3128` 是 Docker Desktop 内部转发代理。
- 记录七服务健康状态、四个 HTTP `200` 入口和开发管理员入口。
- 区分 `down`、`stop-apps`、退出 Docker Desktop 与具有数据删除风险的 `reset -Confirm`。
- 补充 Windows 换行、大小写、编码、本地配置和开发凭据的安全边界。
- 在 `docs/help/README.md` 的开发者入口和当前维护文档中登记新报告。
- 确认两个 GitHub 脚本动态读取当前分支，不需要硬编码 `djw-window`。
- `git_commit.sh` 使用 `git push -u <remote> <当前分支>`，为新分支建立 upstream。
- `git_commit.sh` 拒绝 detached HEAD，默认拒绝直接 push `main`、`master`、`develop`。
- `git_pr.sh` 新增 `--remote`，并拒绝当前 head 与 PR base 相同。
- 两个脚本都校验目标 remote；PR 摘要显示 remote。
- 根 `README.md` 新增 Windows Git Bash/WSL、提交、push、dry-run 和正式 PR 的关键流程。
- 扩充 `PR提交脚本使用说明.md`，统一说明 commit 与 PR 两个脚本。
- 官方 Docker 开发页同步 Windows WSL 2、`7897` 代理、Docker Hub OAuth 故障、关闭和误输入 `sh` 的处理。
- 官方贡献流程和开发者学习路线同步当前分支、upstream、GitHub CLI、dry-run 和正式 PR 流程。

## 7. 已知限制

- 本报告验证的是 Windows Docker Desktop + WSL 2 + Linux Containers 开发栈，不代表
  `compose.deploy.yml` 的生产发布验收。
- `127.0.0.1:7897` 是本次机器的代理端口，不是 CampusOS 固定要求；其他开发者应使用自己的代理配置。
- `EMAIL_PROVIDER=fake` 无法完成真实验证码收件箱测试。
- Docker Hub、Docker Desktop 和 Windows UI 后续可能变化；项目命令仍以仓库脚本和 Compose 为准。
- 本轮没有执行完整 `release-check`，因为修改范围是文档和 Git 辅助脚本，没有 Go、前端、Schema 或镜像合同变化。
