## 3. 系统 Logo 与后台操作台

原始 PNG 经透明背景提取、内容裁剪和缩放后形成 `data/resources/branding/default-logo.png`：RGBA、
`720 × 223`、`104765` 字节。Web App Shell 顶部改为等比图片品牌区，并保留 `CampusOS` 文字回退。

Appearance Homepage 新增：

| 方法 | 路径 | 访问边界 |
| --- | --- | --- |
| `GET` | `/api/v1/home/logo` | 公开读取，ETag + 5 分钟缓存。 |
| `POST` | `/api/v1/home/logo` | 管理员准入 + `appearance.homepage.configure`。 |

生成的路由矩阵、JSON 合同和 OpenAPI 已同步三条路由。

## 4. 中文可操作头像错误

个人空间状态新增 `max_avatar_bytes`，默认值为 2 MB，并保持可由 Personal Space Feature 配置覆盖。Web 页面显示已用/总配额、单头像限制和 FIFO 保留数量，选择文件时先校验 PNG/JPEG/GIF/WebP 与当前服务端上限。

服务端仍执行最终校验，并把内部英文 sentinel 转为用户可执行的中文信息：

- 超过单文件上限：说明具体最大值，并返回 `error.details.max_bytes`、`accepted_types`；
- 格式不支持：列出 PNG、JPEG、GIF、WebP；
- 总空间不足：提示删除文件或联系管理员提高配额；
- 文件名、路径、文件不存在和读取失败不再直接暴露英文内部错误。

请求体使用 `http.MaxBytesReader` 限制 multipart 上传，避免只依赖文件落盘阶段检查。单文件上限与用户总空间配额
是两个独立条件，必须同时满足。

## 5. 仓库 Skill 结构与 clone 后直用

Skill 目录分为：

```text
skills/
├── sources/<skill-name>/        # 唯一规范源文件
├── guides/                      # 面向开发者的使用说明
└── README.md
.agents/skills/<skill-name>/     # Git 可提交的 Codex 仓库发现桥接
```

没有使用 Git 符号链接，因为 Windows clone 对开发者模式、权限和 `core.symlinks` 有额外要求。普通桥接文件在
Windows/Linux/macOS 表现一致，其 frontmatter 与规范源同步，正文要求 Agent 立即完整读取
`skills/sources/<skill-name>/SKILL.md`。用户从仓库目录启动 Codex 即可调用，不需要写入个人 `.codex/skills`
或 `.agents/skills`。

新增 `campusos-skill-repository-sync` Skill 和标准库同步脚本，支持 `--write`/`--check`，不会自动删除意外桥接。
原 7 个 Skill、脚本和说明移动到新结构，修正相对仓库根和命令路径；`docs/skills/` 保留轻量迁移文件，确保历史
链接继续可达。官方贡献文档和根 README 已说明 clone 后使用、同步和会话刷新方式。

## 7. 回滚与限制

- 恢复默认 Logo 可直接在 Admin 操作，不需要源码回滚；回退代码时应同时移除三条路由、品牌配置字段和操作台。
- 自定义 Logo 属于本地可变数据，Git clone 只带默认 Logo；实例迁移必须备份 `data/config/branding/`。
- 头像客户端检查不能替代服务端检查；旧客户端仍会收到中文服务端错误和机器可读详情。
- 仓库桥接是发现入口而非第二份完整 Skill。修改规范源后必须运行同步检查；已打开且未自动刷新 Skill 列表的
  Codex 会话需要重启一次。
- 本阶段没有 commit 或 push，也没有新增 migration。
