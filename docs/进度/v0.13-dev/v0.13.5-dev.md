# CampusOS v0.13.5-dev Observability Core 说明

> 日期：2026-07-19
> 阶段：A3 Observability Core
> 实现状态：已完成
> 验收状态：已验收；Final 已复核 loopback 导出、合同与发布门禁，真实 Prometheus Server 抓取仍属部署演练

## 1. 阶段目标

建立始终启用、指标有界、标签低基数的 Observability Core，保持现有 Admin JSON 摘要兼容，并提供默认关闭、
只允许 loopback 的独立 Prometheus 导出生命周期。

## 2. 实际完成内容

- 新增 `core.observability` Core Module 和模块 manifest，注册明确 Meter/Collector Port。
- 扩展兼容 Collector，新增注册式指标目录、Counter/Gauge/Histogram、标签白名单和每项 series 硬上限。
- HTTP 中间件记录稳定 Route Operation、method、status class、duration、in-flight 和 response size，不记录原始 URL。
- Recovery 接入同一 Collector，记录 panic 总数；panic 文本只进入服务端日志。
- PostgreSQL pool 通过只读 stats provider 投影 acquired/idle/max、acquire duration、取消和空池等待。
- `Snapshot` 保留全部旧字段，只增加 `in_flight`、`database` 和有界 `metrics`。
- Prometheus 使用专用 HTTP Server，默认关闭；开启时只接受 `localhost`、`127.0.0.0/8` 或 `::1`。
- Prometheus Server 具备 Read/Write/Idle timeout、Module Health 和优雅 Shutdown，不注册公开业务路由。
- Webhook/MCP/Message 等旧 `RecordExternal` 调用继续工作，并通过兼容 Adapter 写入新目录。
- 新增生成式指标 JSON/Markdown、部署说明、`.env.example` 和 `make observability-check` 发布门禁。

## 4. 架构变化

`internal/platform/observability` 拥有模块生命周期、安全绑定和导出；`pkg/observability` 保留为共享 Meter/兼容
Collector Adapter。External Plugin 不取得 AppContext、Meter 或 Collector。Admin Integration 只读取有界 Snapshot，
不接触 Prometheus Server 内部状态。

## 5. 兼容和迁移处理

- 无 migration、既有路由、权限或成功 DTO 删除。
- `/api/v1/metrics/summary` 与 `platform.metrics.read` 保持不变，旧 JSON 字段保持原名和语义。
- 默认 `OBSERVABILITY_PROMETHEUS_ENABLED=false`，升级不会新增监听端口。
- 新模块 manifest 是加法；现有模块继续通过 Collector 兼容入口记录指标。

## 7. 回滚方式

运维侧可先设置 `OBSERVABILITY_PROMETHEUS_ENABLED=false` 并重启，立即关闭独立导出而不影响 API。代码回滚时
先移除 runtime registration 和 manifest，再回退中间件/Collector；无数据和 migration 回滚。

## 8. 已知限制

- 当前只提供进程内单实例快照，不做多节点聚合。
- Histogram 使用固定内存桶，不提供运行时自定义桶，避免合同和基数漂移。
- Reliability、Email、Challenge 和 Session 的领域指标在 A4 接入。
