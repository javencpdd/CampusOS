# v0.13.41-dev：引用回复父楼层快照，修复父回复删除后楼层显示为雪花 ID

> 日期：2026-08-03
> 状态：实现并验证
> 范围：Community 回复域（domain/service/repository）、迁移 000043、Web 帖子详情页、Host API、OpenAPI 与架构视图同步

## 1. 目标

用户反馈：回复引用第 4 楼时显示“回复：第 4 楼”，但第 4 楼被删除后，引用处变成
“回复：第 1785717630906569503 楼”（被引用回复的雪花 ID 被当成楼层号渲染）。

根因（已逐层确认）：

1. 列表合同不返回已删除回复：PG 仓储 `ListByThread`/`GetByID` 带 `deleted_at IS NULL` 过滤，
   父回复软删除后不再出现在回复列表；内存仓储则是物理删除，父回复彻底消失。
2. Web 端 `parentFloor(parentID)` 只在当前已加载的一页 `posts` 中查找父回复，找不到时模板回退
   `post.parent_id`：`回复：第 {{ parentFloor(post.parent_id) || post.parent_id }} 楼`，
   于是把雪花 ID 当楼层号显示。
3. 同一根因还有一个伴随症状：父回复未删除但位于其他分页时，同样会显示雪花 ID。

修复思路：创建回复时把父回复楼层号快照到 `posts.parent_floor_number`（迁移 000043 建列并回填存量
数据，软删除的父回复仍参与回填），列表/详情合同直接返回快照；Web 端优先消费快照，永不把 `parent_id`
当楼层号渲染。楼层号创建后不变且删除后不复用，快照语义稳定。

## 2. 完成内容

### 2.1 数据与后端

- 迁移 `000043_v13_post_parent_floor`：`posts` 增加 `parent_floor_number INTEGER NOT NULL DEFAULT 0`，
  并从父回复（含软删除行）回填存量数据；down 迁移删除该列，重新执行 up 可经回填重建，回滚保数据。
- `domain.Post` 新增 `ParentFloorNumber`（`parent_floor_number,omitempty`），创建回复时由
  `PostService.createPost` 在校验父回复后快照 `parent.FloorNumber`。
- PG 仓储 `Create`/`GetByID`/`ListByThread` 写入并返回快照列；内存仓储无需改动（服务层在
  `repo.Create` 前已写入结构体，父回复物理删除不影响子回复快照）。
- Host API `GetReply` 返回 `parent_floor_number`，插件侧合同与 HTTP 合同一致。

### 2.2 Web 前端

- `ThreadDetailView.vue`：`parentFloor(post)` 优先使用 `post.parent_floor_number` 快照，缺失时才回退
  当前页查找（兼容旧合同）；最终兜底由 `post.parent_id`（雪花 ID）改为 `'-'`，与
  `post.floor_number || '-'` 的既有风格一致。
- 行为结果：父回复被删除后引用处仍稳定显示“回复：第 4 楼”；父回复在其他分页时同样修复。

### 2.3 合同与文档同步

- OpenAPI：`internal/projectaudit/openapi_contract.go` 与 `docs/api/openapi-v0.6-current.yaml` 的
  `Post` schema 增加可选属性 `parent_floor_number`（非 required，向后兼容）。
- Admin 架构视图：`posts` 表字段与迁移登记（000001 + 000016 + 000043）、迁移清单新增 000043 条目、
  页头迁移范围更新为 000001–000043。
- `scripts/schema-contract.sql` 列合同增加 `posts.parent_floor_number`。
- `docs/help/系统设计相关/数据库管理指南.md`、`docs-site/api/community.md` 补充快照字段说明。
