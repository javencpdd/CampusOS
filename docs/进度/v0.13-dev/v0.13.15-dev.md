## 1. 阶段目标

补齐管理端侧栏、用户端主导航、课表数字控件和核心帖子列表的响应式缺口，并确保每个仓库风格包都由机器自动纳入 PC/移动端实渲染门禁。

## 2. 实际完成内容

- 管理端桌面侧栏支持收起和展开，使用图标按钮、Tooltip 和中文 `aria-label`，折叠偏好保存在本机；移动端仍使用遮罩抽屉。
- 用户端主导航在紧凑模式切换为独立抽屉，保留首页、全部帖子、板块分组/子板块、动态功能和个人入口；桌面导航行为不变。
- 用户端页头在紧凑模式隐藏重复文字入口，以图标发布按钮和头像菜单保留高频操作。
- 课表年份、每日节数、课程开始/结束节次在紧凑模式使用左右 44px 触控按钮；Element Plus 组件语义统一为中文，不再输出 `decrease number`/`increase number`。
- 低高度横屏设备与窄屏设备共享紧凑 CSS 条件，修复 `852x393` 下按钮仍为 `32x30` 的边界错误。
- 帖子列表按容器能力切换：常规空间继续显示表格，紧凑空间改为标题、标签、作者、浏览、回复和时间组成的条目列表。
- `ThemeRoot` 恢复资源包合同要求的 `app-container` 兼容类，使主题 CSS 的正文表面、遮罩和背景规则真实生效；reduced-motion 下强制关闭内容入场动画。
- 风格包静态检查和 Playwright 矩阵不再维护固定包名数组，而是从 `data/resources/themes`、`homepage-packs`、`space-style-packs` 自动发现并核对 `resource.json`。
- 首页包按资源 ID 在 Admin 中逐个切换；每个包完成全部视口验证后立即回滚，避免多个包连续测试时污染当前首页配置。个人主页测试兼容桌面文字入口和移动导航入口。

## 4. 架构变化

没有新增设备识别或 User-Agent 分支。Web/Admin 继续使用 `useLayoutCapability`，根据可用宽高、方向和容器空间选择 `compact-portrait`、`compact-landscape`、`regular` 或 `wide`。这使平板分屏和横屏手机也能按实际空间切换，不把“移动端”写死为某个设备名称。

风格包仍是 `data/resources` 下的 Resource Package。`data/plugins` 和 Plugin Manager 没有获得主题数据或风格包生命周期；本次只收紧 Appearance 运行时兼容和发布门禁。

## 5. 兼容和迁移处理

- 无数据库 migration、API、路由或持久数据格式变化。
- `campus-theme-root` 类继续保留，同时增加旧合同使用的 `app-container`，属于加法兼容。
- 管理端侧栏偏好只写 `campusos.admin.sidebar-collapsed` 本机键；清除该键即可恢复默认展开。
- Feature、插件动态导航和板块查询合同不变；移动抽屉复用同一导航数据。
- 测试结束通过既有首页回滚 API 恢复配置，不删除资源包或用户主题偏好。

## 7. 回滚方式

- 回退侧栏和移动导航组件即可恢复旧布局，不涉及后端或数据恢复。
- 删除本机 `campusos.admin.sidebar-collapsed` 可单独重置侧栏状态。
- 若主题兼容类产生意外选择器冲突，可先回退 `app-container` 加法并恢复默认主题；不能删除资源包、用户偏好或静态安全检查。
- 矩阵脚本可以回退执行实现，但不应恢复固定包名清单，否则新增包可能漏测。

## 8. 已知限制

- 动态上传的第三方风格包仍只有严格静态门，没有独立进程/容器渲染 Runner；不能将其描述为已获得可信浏览器认证。
- 响应式能力按页面/容器逐步采用，本阶段优先封闭 App Shell、帖子列表和课表主流程，不宣称所有未来插件 UI 自动获得专用移动模板。
- 完整门禁首轮在隔离容量比较中因单次 Go `HeapAlloc` 快照增长超预算而失败；未修改预算或关闭检查，第二次同命令通过。后续版本应把 GC 时点抖动与真实持续堆增长区分为更稳定的采样合同。
- 本阶段使用 `nocommit` 流程，未创建 Git 提交或发布标签。
