# v0.13.32-dev：Docker 日常启动与镜像重建分流

> 日期：2026-08-03
> 状态：实现并验证
> 范围：Windows/Linux Docker 开发入口、脚本合同、README 与官方/Help 文档

## 1. 故障与根因

开发者在普通源码变更后执行 `.\scripts\docker-dev.ps1 up`，Compose 仍因脚本固定携带 `--build` 而解析
`# syntax=docker/dockerfile:1`，并访问 `auth.docker.io` 获取 Dockerfile frontend 的 OAuth Token。代理或网络
暂时不可用时，四个应用镜像在真正编译源码前全部失败。该错误与 Go/Vue 源码、SMTP、LAN 映射和容器健康
无关，根因是日常启动与镜像重建共用了同一条强制构建路径。

## 2. 实现

- Windows `docker-dev.ps1 up` 与 Linux `docker-dev.sh up` 改用 `docker compose up -d --no-build --wait`，
  从已有开发镜像启动或按配置更新容器，不再因普通源码变化进入 Docker Hub 构建流程。
- 新增跨平台 `rebuild`：仅在前端 package/lockfile、开发 Dockerfile、Compose 构建项或容器入口脚本变化时，
  对 API/Web/Admin/Docs 使用 `--build --force-recreate` 重建镜像并启动，基础设施容器与数据卷不被强制重建。
- 首次 `setup -Start`/`setup --start` 仍执行构建，因为本机尚无应用镜像；真实首次安装仍需镜像源可用。
- `build` 保持“只构建、不启动”；`.env.dev.local` 与 Compose 运行参数变化只需 `up`。
- Makefile 增加 `docker-dev-rebuild`，Bash 模拟回归分别断言 `up --no-build` 与 `rebuild --build`。
- README、官方 Docker 文档、Windows 实操报告、开发指南和跨平台治理文档同步新命令边界。

## 3. 当前使用方法

普通 Go/Vue/Docs 源码在容器运行时自动热更新，无需执行命令。容器已停止或只修改环境/端口/挂载时：

```powershell
.\scripts\docker-dev.ps1 up
```

镜像构建输入变化时：

```powershell
.\scripts\docker-dev.ps1 rebuild
```

Linux、WSL2、Git Bash 分别使用 `./scripts/docker-dev.sh up` 与 `./scripts/docker-dev.sh rebuild`。两种模式都
无需先 `down`。数据库和命名卷不会因本轮命令分流被删除。

## 5. 回滚与限制

如果回退到旧脚本，`up` 会再次强制访问镜像源，不建议回滚。`--no-build` 不会生成缺失的应用镜像；首次
启动、手工删除镜像或真实构建输入变化时必须使用 `setup -Start`/`setup --start` 或 `rebuild`，并保证
Docker Hub、Go module 与 npm/pnpm 依赖源可访问。分支切换仍不会自动回滚已执行的数据库 migration。
