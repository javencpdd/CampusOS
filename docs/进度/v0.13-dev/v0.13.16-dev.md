## 1. 阶段目标

补齐管理员删除帖子后的作者提示、管理端当前页批量治理，以及手机端校园互助和校园二手发布入口，同时保持

## 2. 实际完成内容

- 复用 `000001` 已存在的 `notifications` 表，实现 Community Notification Domain、Memory/PostgreSQL
  Repository、Service、Handler 和生成 API 合同；未新增 migration。
- 管理员或其他治理主体把他人帖子移入回收站时，原子创建
  `community.thread.trashed` 作者站内通知。作者自删或治理者删除自己的帖子不产生重复通知。
- 通知写入与帖子状态、Revision、治理记录、可靠命令处于同一事务；通知保存失败会使回收操作回滚。
- 新增当前用户通知列表、单条已读和全部已读 API。读取和更新始终按 JWT 当前用户隔离，跨用户更新按不存在处理。
- 用户端页头新增通知铃铛、未读角标、消息抽屉、单条/全部已读和内部路径跳转；页面可见时每 30 秒轮询，
  浏览器回到前台时刷新并提示新通知。
- 管理端帖子表格新增选择列、表头当前页全选、批量动作工具栏、原因复用、确认和部分失败汇总。
- 批量置顶、锁定、审核、下架、恢复、回收和清除逐项复用现有 API，不绕过 Permission Code、板块作用域、
  内容状态机、可靠事务、审计或作者通知。
- 统一发布页按实际容器能力在分段选择器和全宽选择框之间切换，PC/移动端均提供图文、普通文本、校园互助和
  校园二手四类入口；功能明确停用时对应入口禁用。
- 校园互助和二手专用编辑器继续复用安全图文/纯文本编辑器，并补齐移动端 44px 单选、数字步进和主要按钮。
- 响应式脚本增加通知、四类发布、专用编辑器和管理端批量选择断言，并修复课表异步渲染及 768px
  内容容器模式判定造成的测试竞态。
- 同步生成 OpenAPI、路由与授权矩阵，补充仓库帮助文档、官方 docs-site 和 v13 最终审计。

## 4. 架构变化

通知属于 `core.community`，没有新增 External Plugin 或 Built-in Feature，也没有让浏览器直接写数据库。Thread
Service 只依赖窄接口 `ThreadNotificationWriter`；Community Module 负责将 Notification Service 适配进去。
PostgreSQL Repository 使用当前 TxKernel Executor，因此管理员回收和通知拥有同一提交/回滚边界。

管理端批量能力是前端编排，不是新的绕权批量 API。每个项目仍调用原单项应用服务和可靠命令，以保留现有权限、
作用域、审计、Outbox 和错误合同。超大批量异步任务仍是后续独立能力。

移动发布继续遵守四类能力边界：普通帖子由 Community Core 管理，图文、互助和二手是编译内 Built-in
Feature；客户端入口不改变服务端 Feature Gate 与板块帖子类型策略。

## 5. 兼容和迁移处理

- 没有数据库 migration、表移动或历史数据重写；直接复用已有 `notifications` 表及索引。
- 只增加 3 条认证 API，原帖子、富文本、互助和二手 API 不变。
- 现有 PC 发布编辑器仍可使用；只把发布类型从两项扩展为四项，并按内容容器选择控件。
- Feature 停用、板块类型策略、图片白名单、User Storage 配额和 HTML 清洗继续由后端权威校验。
- 通知中心只接受 `/` 开头且非 `//` 的站内路径，避免通知元数据造成开放重定向。
- 回滚前端通知中心不会删除通知数据；回滚批量 UI 不影响单项治理 API；回滚移动入口不影响专用编辑器路由。

## 7. 回滚方式

- 后端可回退 Notification Handler/Service 绑定和 3 条路由；`notifications` 历史表及已有数据不删除。
- 若通知投递需要临时降级，应先 forward-fix 通知 Repository，不能通过允许帖子删除半提交来绕过一致性。
- 管理端可回退选择列和批量编排，单项治理接口、权限、审计和帖子数据保持不变。
- Web 可回退统一入口和通知组件；互助、二手专用路由及已发布内容保持可用。
- 响应式测试竞态修复只增加等待和实际控件识别，不降低原有控件数量、尺寸或溢出断言。

## 8. 已知限制

- 当前是 30 秒轮询的站内通知，不是 WebSocket/SSE、邮件、短信、浏览器 Push 或第三方平台实时通知。
- 首版只为管理员回收主题通知作者；审核拒绝、下架、回复删除等通知需要独立文案、频率和偏好策略。
- 批量操作只选择当前页并逐项执行，不适用于数万条筛选结果的异步治理。
- 容量门禁默认 40 样本的两次演练分别受到单次 HeapAlloc 和 p95 时点抖动影响；没有放宽预算，使用脚本允许
  的 50 样本后通过。后续应把采样稳定性作为容量工具改进，而不是隐藏真实持续增长。
- 本阶段使用 `campusos-dev-nocommit`，未创建 Git 提交或发布标签。
