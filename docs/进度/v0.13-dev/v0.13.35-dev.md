# v0.13.35-dev：项目 Skill 适用性审计与专项能力补全

> 日期：2026-08-03
> 状态：实现并验证
> 范围：`skills/`、`docs/skills/`、官方贡献文档、Skill 触发/验证合同

## 1. 审计结论

原有 5 个标准 Skill 的业务方向仍适用，但存在以下过期或冲突：

- 多个 Skill 硬编码 `/home/jack/...`，没有覆盖当前 Windows 工作区。
- 开发流程仍以 v0.3–v0.5 为主要示例；项目上手快照记录 migration 到 `000041`，而仓库已有 `000042`。
- 数据架构 Skill 描述仍引用已迁移的 `admin/src/views/SystemArchitectureView.vue`。
- `campusos-dev-nocommit` 的 description 和 `agents/openai.yaml` 错写成 commit 工作流，可能在未授权时触发提交。
- 没有专项入口固化近期反复出现的 Docker 开发链路和 WebUI 跨层回归诊断。

根目录 `skills/gpt-5.5-base-instructions.md` 不是标准 Skill 包，没有登记为可发现 Skill。

## 2. 现有 Skill 修订

- 7 个项目 `SKILL.md` 正文和所有 `docs/skills/` 使用说明统一写明 `2026-08-03` 更新时间；frontmatter
  继续只保留 `name`、`description`。
- `campusos-project-onboarding` 改为动态工作区根、migration `000042`、当前 Windows/Linux Docker 开发证据和
  `up/rebuild` 边界，并路由到专项 Skill。
- `campusos-dev-nocommit` 成为普通任务默认入口，明确不 commit、不 push；`campusos-dev-workflow` 仅在用户
  显式点名或要求 commit 时使用，仍不自动 push。
- 两个开发助手根据平台处理 Go 全量测试：Linux 默认执行；Windows Git Bash 因现有 managed-process 测试的
  Unix 可执行文件假设而明确跳过并提示 Docker/WSL2/Linux，不能把跳过写成通过。可用
  `CAMPUSOS_SKILL_RUN_GO=true|false` 覆盖。
- `campusos-readme-update` 增加官方 `docs-site` 同步和 Windows workspace Go cache 说明。
- `campusos-data-architecture-sync` 修正 Admin 模块路径，新增 migration 不可变、冗余分类、回滚和数据库 drill
  合同，不另建重叠 migration Skill。

## 6. 回滚与限制

删除两个新增 Skill 并回退现有 Skill/使用说明可恢复旧状态，但会重新引入未授权 commit 触发风险和跨平台过期
信息，不建议回滚。仓库 Skill 尚未自动复制到用户级 Codex 目录；这属于独立安装行为，需要用户明确授权。

本轮没有修复 `internal/plugin/grpc` 的 Windows managed-process 测试本身；后续应单独处理 `.exe` 路径或在 CI
明确只将该套件放入 Linux runner。生产发布、安全供应链、arm64、正式 MCP/gRPC 等仍以计划总结中的候选边界为准。
