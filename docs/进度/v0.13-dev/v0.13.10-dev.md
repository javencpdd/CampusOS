> 日期：2026-07-22

> 验收状态：已验收；v0.13.13 Final 发布门禁通过

## 1. 阶段目标

在 Identity Core 内提供可选 TOTP、一次性恢复码、短期单用途登录 Ticket 与 Session MFA 强度，确保第二因子材料不会进入普通账号字段、日志、资源包、插件配置或客户端持久化存储。

## 2. 实际完成内容

- 新增 `000040_v13_identity_mfa`：TOTP 方法加密信封、Ticket 摘要、恢复码摘要、管理员 MFA 策略和 Session MFA 强度字段。
- 实现带 key ID 的 AES-GCM Secret Protector，支持新旧 key 轮换读取；缺少材料或解密失败时 MFA fail closed。
- 实现 enrollment、confirm、TOTP 登录完成、Step-up、恢复码轮换/消费、关闭 MFA 与本机 `reset-mfa` 恢复。
- 登录 Ticket 仅保存摘要，受有效期、用途、Audience、失败次数和单次消费约束；并发竞争只能成功一次。
- TOTP 支持有限时钟漂移，服务端持久化最后接受时间步，拒绝同一步重放。
- 恢复码仅在生成时返回一次，数据库仅保存摘要和 `used_at`；关闭 MFA 或本机恢复会撤销全部 Session。
- Session 记录 `authentication_strength` 与 `mfa_verified_at`，管理员策略或高风险命令可要求最近 Step-up。
- 新增 MFA 权限、稳定 machine error、低基数 MFA 指标和脱敏错误处理；不把 Secret、验证码、Ticket 或恢复码写入指标/日志。

## 4. 架构变化

MFA 仍归 Identity Core。外部插件、Resource Package、Agent、MCP 和普通 Feature 只能看到最终的授权结果，不能读取 MFA Repository、加密信封、恢复码摘要或 Session 内部状态。管理员准入中间件在要求 MFA 的策略下额外检查服务器端 Session 强度，普通用户 Token 不可绕过。

## 5. 兼容和迁移处理

- MFA 策略默认 `off`，旧用户和旧 Session 在未强制时继续使用原有密码登录路径。
- 旧 Session/Access Token 不需要新增前端字段；服务端仅在需要时读取 MFA 强度。
- 迁移只增加表、字段、权限和策略；不改写历史 migration，也不把 MFA 数据塞入 `accounts`。
- 回滚策略为先把管理员策略回退为 `off` 或 grace，再在维护窗口处理已强制会话；不得恢复明文材料。

## 7. 回滚方式

关闭管理员策略只影响后续门禁；已加密的 MFA 数据和审计保留。丢失全部认证器与恢复码时，只能使用本机交互式 `campusosctl identity reset-mfa`，该命令要求部署 Bootstrap Secret、记录审计并撤销会话。

## 8. 已知限制

- v0.13 不实现 Passkey、OAuth/OIDC 或把邮箱验证码当作第二因子。
- 恢复码用于已认证会话内的轮换和关闭；完全失去认证器时使用受控本机恢复，不提供匿名远程重置入口。
