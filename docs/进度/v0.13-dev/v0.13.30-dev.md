# v0.13.30-dev：后台用户邮箱管理投影

> 日期：2026-08-03
> 状态：实现并验证
> 范围：Identity Core、Admin 用户管理、HTTP/OpenAPI 合同与开发文档

## 1. 问题与根因

Admin 用户管理表已经声明“邮箱”列，但列表请求复用了公开 `GET /api/v1/users`。该公开接口有意使用
`PublicUser` 投影，不包含邮箱，以避免任意访问者枚举用户登录地址；因此页面只能得到空单元格。不能为了
修复后台显示而把邮箱重新加入公开响应。

## 2. 实现

- Identity Core 增加 `AdminUser` 管理投影，包含规范化后的兼容邮箱、状态和基础资料。
- 增加 `GET /api/v1/admin/users`，沿用严格分页，并要求管理员准入及 `identity.user.read` 权限。
- Admin 用户列表改为调用管理接口；空邮箱显示“未绑定邮箱”。
- 历史共享占位邮箱不会作为个人邮箱返回，避免把迁移证据误显示成真实绑定关系。
- 公开 `/users` 与 `/users/:id` 仍使用 `PublicUser`，邮箱隐私边界保持不变。
- OpenAPI、机器路由清单和 HTTP 授权矩阵已从真实路由重新生成，路由归属为 `core.identity`，Operation 为`http.identity.user.admin_list`。

## 3. 数据与兼容

本轮没有 migration，也没有修改邮箱权威事实：`accounts(type=email)` 仍是登录邮箱事实，`users.email` 是现有账号流程同步维护的兼容投影。旧客户端继续使用公开用户接口；只有 Admin 列表切换到新管理接口。

源码由 Docker 开发栈热更新时不需要清空数据库。若 API 容器尚未加载新二进制，执行
`docker-dev.* up` 让开发服务重建后刷新 Admin 页面即可。

> 后续命令变更：v0.13.32 起普通源码由现有热更新进程加载，`up` 不再强制构建或重启应用。当前应先查看
> API 日志中的自动构建结果；镜像构建输入变化才执行 `rebuild`。详见 [v0.13.32](v0.13.32-dev.md)。

## 5. 回滚与安全边界

回滚时可以让 Admin 临时恢复公开列表，但邮箱列会再次为空；不能把邮箱字段加入 `PublicUser`。若后续完全移除
`users.email` 兼容投影，应让管理查询从 Identity 账号读端批量取得权威邮箱，不能逐行发起查询，也不能降低
管理员准入或权限要求。
