# CampusOS v0.13.4-dev 统一错误合同说明

> 日期：2026-07-19
> 阶段：A2 统一错误合同
> 实现状态：已完成
> 验收状态：已验收；隔离 PostgreSQL migration 复测与完整发布门禁通过

## 1. 阶段目标

建立可机器读取、可生成、可审计且不泄漏内部 cause 的统一错误合同，迁移 Identity Challenge/Session、
Mutual Aid、Secondhand 和 Reliability Admin 首批高风险路径，同时保持旧顶层响应字段可用。

## 2. 实际完成内容

- 新增 `pkg/apperror`，定义注册式 `Descriptor`、`AppError`、模块 `Translator`、未知错误 fallback 和目录唯一性校验。
- `pkg/response` 新增 `WriteError` 与 `ErrorDescriptor`，继续返回旧 `code`、`msg`、`data`、`request_id`，并提供
  `error.code`、`message`、`details`、`request_id`、`retryable`。
- 未登记错误和未知 cause 统一脱敏为 `internal.error`；服务端日志记录 request ID 和 cause，响应不返回原始错误。
- Recovery 记录 request ID、方法、路径和服务端堆栈，未提交响应时统一返回结构化 `internal.error`。
- Identity Challenge/Registration/Session、Mutual Aid、Secondhand 和 Reliability Admin 改用模块 Translator。
- 保留已发布的 Identity machine code；历史 `internal.error` 的 HTTP 503 用显式 transport-status 兼容桥处理。
- Reliability Replay 不再通过错误字符串判断身份缺失，改为 `ErrReplayActorRequired` 哨兵错误。
- Web 与 Admin 使用同一 `CampusOSError` 解析语义，并由静态检查确保两个解析器不漂移。
- Go SDK 和 TypeScript SDK 优先读取结构化错误，兼容旧顶层字段；Go SDK 的 `Error()` 不再拼接完整响应体。
- 合同生成器新增错误目录 JSON 和 Markdown，发布门禁新增 `make error-contract-check` 与 raw-error 扫描。

## 4. 架构变化

Domain/Service 继续返回原错误或哨兵错误；每个模块在 HTTP 边界通过 Translator 映射为登记描述符。`response`
只负责传输，未知错误无法自行变成公开 machine code。客户端统一解析结构化扩展，旧客户端仍可读取顶层字段。

## 5. 兼容、迁移与回滚

- 无 migration、路由、权限或成功 DTO 变化。
- 旧数字码和顶层包络保留；已发布的 Identity machine code 保留。
- 新增具体 machine code 只作用于此前由 `campusos.<数字码>` 推导的首批模块错误。
- 回滚可移除 Translator 调用并恢复原 Handler 映射，不涉及数据回滚；错误目录应与代码同批回滚。
- `HostAPIError.Body` 字段仍保留给兼容调用方，但默认 `Error()` 不输出原始 Body。

## 7. 回滚方式

代码回滚不需要 down migration。先回退前端/SDK 解析器和发布门禁，再回退模块 Translator，最后回退
`pkg/apperror` 与生成目录；任何时刻旧顶层字段仍可供现有客户端使用。

## 8. 已知限制

- 本阶段只迁移计划指定的高风险 Handler，其他低风险 Handler 仍使用兼容 `response.Error`。
- `internal.error` 的 503 是历史兼容覆盖；新错误不得复制这种多状态用法。
- Docker 隔离 PostgreSQL 的 Identity Challenge/Registration/Session、Mutual Aid、Secondhand 脚本尚未完整复测，
  因而本阶段不能标记完全验收。
