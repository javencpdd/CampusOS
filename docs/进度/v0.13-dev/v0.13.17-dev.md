# v0.13.17-dev - Docker 跨平台开发、部署与主机迁移

> 日期：2026-07-29

## 1. 阶段目标

让 CampusOS 不再依赖 Ubuntu 22.04 宿主工具链：Windows 10/11 可通过 Docker Desktop Linux Containers，
现代 Linux 可通过 Docker Engine + Compose v2 运行同一套开发和部署合同；同时提供源码热更新、测试、
随机密钥初始化、自动 migration、备份、显式恢复和新主机迁移教程。

## 2. 实际完成内容

- 新增 `compose.dev.yml` 与 `deploy/docker/Dockerfile.dev`，容器化 Go、Node/pnpm、PostgreSQL、Redis、
  NATS、Web、Admin 和 Docs 开发环境。
- API 开发容器轮询 Go、migration 和 module descriptor；先构建候选、再执行 migration，成功后才替换
  上一次可用进程。容器内关闭 VCS stamping，避免 Windows/Linux 宿主 Git UID 不同造成构建拒绝。
- Web/Admin/Docs 使用绑定源码、轮询 HMR、锁定依赖种子和独立 `node_modules` 卷。依赖在镜像构建阶段
  安装，冷启动不再与容器健康超时耦合。
- 开发容器在初始化缓存后按宿主 UID/GID 降权运行；Corepack 使用镜像内共享缓存并锁定 pnpm
  `8.15.9`，避免 Vite/VitePress 生成 root 文件，或非 root 启动时等待下载最新 pnpm。
- 新增 Bash 与 PowerShell 开发入口，支持 config/build/up/ps/logs/test/shell/down 和显式 reset。
- 完善 `compose.deploy.yml` 和多阶段生产 Dockerfile，交付 API/Web/Admin/Docs 镜像、PostgreSQL/Redis/NATS
  依赖、健康检查、非 root API、内部 backend 网络和可选维护 profile。
- 新增 Bash 与 PowerShell 部署入口，支持随机密钥 init、构建、启动、日志、备份、恢复和停止。
- 将生产交付拆为 `infra/api/web/admin/docs` 五份独立 Compose 和独立 env 覆盖；四个 CampusOS 镜像可分别
  构建、启动、升级和停止。根 `compose.deploy.yml` 通过 `extends` 复用相同定义并保留一键整栈。
- 新增 Bash 与 PowerShell 分组件入口；`.env.docker` 保存共享 Secret，`.env.components/` 保存各组件端口、
  网络、卷和公开地址，避免复制数据库/MFA/JWT 密钥。
- 一键和分组件脚本幂等创建同名外部卷及网络；backend 强制创建为 Docker internal 网络，已有同名非
  internal 网络时拒绝降级启动，edge 网络只承载前端代理和 API 对外通信。
- 新增受控 maintenance 恢复容器：归档目录只读、无 Docker socket/privileged/edge 网络，仅保留文件恢复
  所需能力；恢复要求 checksum、安全路径、受控 `backups/` 目录和显式确认。
- `.dockerignore` 排除个人空间、插件/模块可变数据、图片、配置、日志和前端产物；版本化插件实现、资源包
  与兼容所需的已跟踪 Personal Space 默认样式仅作为首次启动缺失文件种子，不覆盖命名卷。
- API 运行镜像锁定 PostgreSQL 16 客户端，与数据库主版本一致；备份把容器绝对路径归一化为固定
  `modules/` 与 `data/*` 布局，并在 Unix 宿主将归档权限收紧为 `0600`。
- `.gitattributes` 固定 shell/Docker/YAML 的 LF 与 PowerShell 的 CRLF，减少 Windows checkout 差异。
- Web/Admin Vite API proxy 支持 `CAMPUSOS_API_PROXY_TARGET`，容器内正确访问 `http://api:8080`，本地
  非 Docker 开发继续默认 `localhost:8080`。
- `make docker-deploy-check` 与 `release-check` 同步检查开发/部署 Compose、必需文件、服务/target、数据卷、
  shell 语法和危险 Docker 能力。
- 新增官方文档站 Docker 开发与部署教程、仓库完整指南、README/文档门户入口，并在 Admin 相关资料页增加
  Docker 教程链接。

## 4. 架构变化

本阶段没有把模块化单体拆成微服务。API 仍是一个模块化单体进程；PostgreSQL、Redis、NATS 和三个前端是
部署依赖。`compose.dev.yml` 只改变开发装配，`compose.deploy.yml` 只改变交付装配，不改变 Core、
Built-in Feature、External Plugin 和 Resource Package 的运行边界。

生产 API 使用 UID/GID `10001`、`cap_drop: ALL` 和 `no-new-privileges`。PostgreSQL、Redis 与 NATS
只连接 internal backend；API 同时连接 backend 与 edge。maintenance 只在显式恢复命令中启动，使用最小
文件恢复能力读取受控归档并修正卷所有权；它不连接 edge 网络，也不能访问 Docker daemon。

## 5. 兼容和迁移处理

- 原生 `STOP_EXISTING=true make dev-all`、本地 Go/Node 开发和现有 `docker-compose.yml` 基础设施流程保留。
- 没有新增数据库 migration、API 或业务表变化；部署 API 启动时运行当前 40 个 migration。
- 部署数据继续使用既有 `data/` 目录语义；镜像只播种缺失版本化文件。
- `.env.docker` 不进入普通备份。跨主机迁移时必须单独加密转移原密钥，否则既有 MFA envelope 和受保护配置
  无法解密；CampusOS 用户 Token 不作为导出内容。
- Redis/NATS 被定义为可重建运行状态，跨主机权威恢复内容是 PostgreSQL 与 `data/`。
- Windows 只支持 Docker Desktop Linux Containers，不宣称支持原生 Windows Containers。

## 7. 回滚方式

- 删除 `compose.dev.yml`、开发 Dockerfile/脚本和 Vite proxy env 适配即可回到原生开发；默认
  `localhost:8080` 行为保留。
- 部署层可回到旧二进制/静态构建方式，PostgreSQL 和 `data/` 不随容器删除。
- `docker-deploy.* down` 不删除命名卷；不提供无确认的部署 `down -v` 包装。
- 恢复失败时使用自动生成的恢复前归档或源主机重新执行受控恢复；不能只恢复数据库或只恢复文件后开放流量。
- `.env.docker` 必须保留到登录、MFA、插件和集成验收完成。

## 8. 已知限制

- 这是单主机、单 API 实例交付，不包含自动 TLS、高可用、容器编排集群、异地复制或自动扩缩容。
- Windows 需要受支持的 Docker Desktop/WSL2 和 Linux Containers；不是“任意历史 Windows”。
- 首次镜像构建仍需要访问 Go module、npm 和基础镜像仓库；离线镜像仓库和供应链签名属于后续能力。
- 外部 SMTP、Prometheus 告警通知和真实生产长稳仍要在目标环境验收。
- Redis/NATS 卷用于重启连续性，但不进入跨主机权威归档。
- 本轮真实容器运行环境是 Linux `amd64`；PowerShell 脚本和 Windows/arm64 路径完成静态/Compose
  合同检查，但仍需在真实 Windows Docker Desktop 与 arm64 发布 Runner 上做发行认证。
- 本阶段使用 `campusos-dev-nocommit`，不创建提交或标签。
