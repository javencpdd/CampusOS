## 1. 阶段目标

为独立的管理平面账号建立可审计、可并发保护的暂停和恢复流程，确保角色授权、准入状态、会话和审计四层不能被前端显示或直接改表绕过。

## 2. 实际完成内容

- 新增 `000039_v13_admin_admission_operations`，为 `identity_admin_accounts` 追加变更原因、操作者、时间、版本和必要索引，并追加管理员准入权限目录。
- 新增 Admin Admission Repository/Service/Handler：支持有界列表、状态筛选、详情投影、暂停、恢复和准入变更审计读取。
- 暂停和恢复均要求 `expected_version` 与非空原因；并发版本冲突返回稳定错误，禁止静默覆盖。
- 暂停命令在同一可靠命令/事务中撤销目标用户全部 Session，记录 required authorization audit、command audit 和 Outbox 事件。
- 数据库行锁和服务端检查共同保护最后一个可用管理员；自我暂停与跨管理员暂停使用同一策略。
- 新增 `campusosctl identity restore-admin-admission` 本机交互恢复路径，要求部署 Bootstrap Secret、显式确认、审计和恢复后重新认证提示。
- Admin 新增“管理员准入”独立页面，提供状态筛选、原因输入、版本化暂停/恢复和变更审计抽屉；不显示密码、Token、MFA Secret 或恢复码。

## 4. 架构变化

管理员准入继续是 Identity Core 的独立边界：`users/accounts` 负责身份凭据，`identity_admin_accounts` 决定是否可进入管理平面，角色与权限决定可执行操作。暂停不会删除角色或用户数据，只停止管理平面准入并撤销会话。

## 5. 兼容和迁移处理

- 仅追加 migration；历史管理员账号由现有角色同步和兼容读取维持。
- 旧管理端 API、角色、版主 scope 和用户端版主管理流程不变。
- `revoked` 仍由管理员角色撤销驱动，恢复 API 只允许 `suspended -> active`，避免越过角色授予。
- 回滚只用于隔离演练；生产修复保留状态、会话撤销和审计，采用 forward-fix。

## 7. 回滚方式

停用新页面和路由前必须保留数据库状态、Session 撤销记录和审计。隔离环境可执行 down/up 演练；生产环境只能通过受权恢复命令或新版本修复，不允许直接更新 `identity_admin_accounts`。

## 8. 已知限制

- 本机恢复是 break-glass 路径，刻意不提供 HTTP 等价接口，且不能从 CI、管道或命令行参数接受 Bootstrap Secret。
- 管理员准入状态不是角色分配 UI 的替代品；先恢复准入不会自动授予已撤销的 admin 角色。
