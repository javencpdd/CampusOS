# v0.13.11-dev - MFA 产品闭环与管理端策略

> 日期：2026-07-22  
> 阶段：B3 MFA 产品闭环  
> 实现状态：已完成  
> 验收状态：已验收；v0.13.13 Final 发布门禁通过

## 1. 阶段目标

让用户可以安全管理自己的认证器，让管理员以分阶段、可恢复的方式配置 MFA 策略，并使 Web/Admin 的 PC、移动端与登录状态转换都遵循 Core 合同。

## 2. 实际完成内容

- 用户端新增“账号安全”页：登录设备、启用 TOTP、二维码与手工密钥确认、恢复码一次显示、恢复码轮换、关闭认证器和会话撤销。
- 用户与管理员登录页支持密码成功后的 MFA 第二步；Ticket 仅保存在当前组件内存，未写入 URL、Local Storage 或 Session Storage。
- Admin 新增“管理员 MFA 策略”页：显示聚合覆盖率、本机恢复可用性、`off/enrollment_grace/required` 策略和版本化保存。
- 服务端在 `required` 前重新核查有效管理员覆盖率和本机恢复能力；已启用 MFA 的策略变更需要最近 Step-up。
- 管理端路由门禁统一拒绝已停用或强制 MFA 未完成的管理员会话，普通用户端 Session 不能绕过。
- 增加 MFA 不可用、Step-up、Ticket 无效、重放和策略冲突的统一错误显示；页面不展示 Secret、恢复码历史、完整账号安全材料或内部异常。
- 新增显式受控的浏览器演练，仅接受指定的可变更测试账号；演练执行启用、Web/Admin 第二步登录、恢复码轮换、关闭 MFA、Session 撤销和关闭后的密码直登，结束后验证测试账号恢复未启用状态。

## 4. 架构变化

前端只消费 MFA HTTP 合同和内存态登录 Ticket；Core 继续拥有策略、认证器、Ticket、Session 强度和审计。管理端页面不替代后端防锁死、版本冲突或 Step-up 判断，所有状态转换仍由 Identity Core 的事务和授权边界执行。

## 5. 兼容和迁移处理

- 未启用/未强制 MFA 的用户继续使用原密码登录；新增页面不会要求历史用户立即注册。
- MFA 页面与策略页面为加法路由，旧用户端和旧管理端的登录 API 包络不变。
- 受控浏览器演练默认关闭，避免默认发布检查改动真实管理员账号；必须显式提供隔离测试账号和状态变更确认。

## 7. 回滚方式

将策略降为 `off` 或 grace 可停止新的 MFA 强制；不要删 MFA 表、恢复码摘要或 required audit。用户丢失设备时按本机恢复 Runbook 处理；显式浏览器演练若清理失败，立即停止测试并使用 `reset-mfa` 恢复测试账号。

## 8. 已知限制

- 完整状态变更浏览器演练只适用于隔离/可重置账号，不能拿生产管理员或真实用户运行。
- v0.13 的恢复码不提供匿名登录旁路；这是为了避免把恢复码变成公开的远程高权限重置通道。
