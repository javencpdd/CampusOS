## 4. 架构变化

业务运行时、HTTP API、数据库表和四类能力边界没有变化。文档层新增唯一生命周期入口和版本规划入口；
容量演练仍是发布工具，不进入业务模块。其 baseline/candidate 现在使用独立 API 进程，比较同一工作负载的
进程状态，不再比较同一进程两个不同 GC 阶段。

## 5. 兼容和迁移处理

- 未删除或移动历史 Help/计划文件，只增加状态横幅、权威入口和替代关系。
- 未新增 migration、路由、权限、配置或数据目录。
- README、仓库 Help 和 docs-site 不复制同一长文：README 保留核心入口，Help 保存仓库专项说明，
  docs-site 提供面向使用者的可导航教程。
- 容量演练继续使用原预算、loopback、`0600` 授权文件、固定只读 API、临时数据库和退出清理；没有放宽
  权限、限流或性能阈值。

## 7. 回滚方式

- 文档导航和状态标记可按文件独立回滚，不影响运行时与数据。
- 容量演练可回滚脚本而不涉及数据库迁移，但旧的同进程采样存在已复现的 GC 偏差，不应作为发布证据恢复。
- docs-site/Admin 资料入口回滚只影响导航；原仓库文档仍保留。

## 8. 已知限制

- 本轮没有创建正式 v0.14 计划；当前路线只表示候选优先级，不是版本承诺。
- 历史文档不会自动随代码更新，新增或替代指南时仍需维护 `docs/help/README.md`。
- Docker 真实运行证据来自 Linux amd64；Windows PowerShell 与 arm64 仍需发行 Runner 认证。
- 仓库隔离容量演练不等价于目标环境持续负载、真实 SMTP、Prometheus 通知或生产 SLO。
- 本阶段使用 `campusos-dev-nocommit`，未创建提交或标签。
