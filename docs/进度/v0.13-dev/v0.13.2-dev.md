> 日期：2026-07-19

## 1. 阶段目标

以 `v0.12.0` Final 为不可变对照，冻结应用版本、路由、migration、Module、External Plugin、Resource
Package、运行环境和结构化列表查询模式，并提供可重复执行的采集工具，供 A1 与 C0 判断真实回归。

## 2. 实际完成内容

- 新增 `campusos-baseline` 命令，使用 JSON/YAML 解析器读取生成路由合同、Module/Plugin Manifest 和资源包。
- 记录 256 条路由及 audience 分布、38 个 migration、9 Core、12 Built-in Feature、2 External Plugin 和
  5 个 Resource Package，并对合同、migration、描述符和每个资源目录生成 SHA-256。
- 记录 Linux/amd64、Go 版本、逻辑 CPU、内存、Git 提交和工作树状态；dirty 状态如实保留，不伪装成 tag。
- 自动识别 Mutual Aid、Secondhand 在优化前均为 `per-item Store.Get`，N 个列表项需要 N 次 Detail 读取，
  明确标记为违反常量查询目标。
- Live 模式只接受 loopback 地址，样本数量限制为 3-100，带响应大小、列表总数与 p50/p95/p99；远程 URL
  有负向测试并默认拒绝。
- 静态基线保存为 `docs/项目计划v0.13/evidence/v0.12.0-baseline.json`，Makefile 增加
  `v13-baseline-check`。

## 5. 兼容与安全处理

采集器只读仓库和 loopback HTTP，不连接数据库、不修改数据、不读取 `.env`、Token、邮箱或用户正文。输出不含
绝对宿主路径和 Secret。基线 JSON 是证据，不作为运行时配置；A1 后不得覆盖该文件来隐藏优化前状态。

## 7. 回滚与已知限制

删除采集命令、Makefile target 和证据 JSON 即可回滚，不影响运行时和数据库。当前快照没有 HTTP 延迟分位数，
所以 A0.5 不能标记完全验收；取得可访问同一冷启动栈的执行授权后，应运行：

```bash
GOCACHE=/tmp/campusos-go-cache go run ./cmd/campusos-baseline \
  --root . --live --samples 20 \
  --output docs/项目计划v0.13/evidence/v0.12.0-baseline.json
```

后续 A1 可以基于已冻结的查询模式独立实施；C0 和 Final 前必须补齐实时分位数并在同环境复测。
