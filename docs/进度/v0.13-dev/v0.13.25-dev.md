# v0.13.25-dev - Docker 开发 UI 可信局域网访问

> 日期：2026-07-30  
> 分支：`djw-window`  
> 状态：代码、容器和本机 HTTP 验证完成；Windows 防火墙等待可信网络确认  
> 范围：仅 Web/Admin/Docs 开发 UI，不开放 API 和数据服务

## 1. 目标

允许同一可信局域网中的测试设备访问 Docker 开发环境：

- Web：`3000`
- Admin：`3001`
- Docs：`3002`

同时保持以下敏感入口仅本机可访问：

- API：`127.0.0.1:8080`
- PostgreSQL：`127.0.0.1:55432`
- Redis：`127.0.0.1:56379`
- NATS Client/Monitor：`127.0.0.1:54222`、`127.0.0.1:58222`
- pgAdmin：`127.0.0.1:5050`

## 2. 为什么不直接修改 `CAMPUSOS_DEV_BIND`

原有 `CAMPUSOS_DEV_BIND` 同时控制 UI、API、数据库、Redis、NATS 和 pgAdmin。如果直接改为
`0.0.0.0`，会把固定开发凭据、数据库和消息基础设施一起暴露到局域网。

本轮为三个 UI 服务新增独立 bind：

```dotenv
CAMPUSOS_DEV_BIND=127.0.0.1
CAMPUSOS_DEV_ALLOW_LAN=true
CAMPUSOS_DEV_WEB_BIND=0.0.0.0
CAMPUSOS_DEV_ADMIN_BIND=0.0.0.0
CAMPUSOS_DEV_DOCS_BIND=0.0.0.0
```

仓库模板继续采用 `ALLOW_LAN=false` 和三个 `127.0.0.1` 安全默认值；只有本机受 Git 忽略的
`deploy/docker/.env.dev.local` 显式启用 LAN。

## 3. 实现

| 文件 | 变化 |
| --- | --- |
| `compose.dev.yml` | Web/Admin/Docs 分别读取独立 bind，敏感服务继续读取 loopback bind |
| `deploy/docker/.env.dev.example` | 增加安全默认值和显式 LAN opt-in |
| `scripts/docker-dev.sh` | 校验 bind 值、拒绝隐式 LAN 开放并输出风险提示 |
| `scripts/docker-dev.ps1` | 与 Bash 入口保持相同的安全合同 |
| `scripts/test-docker-dev-setup.sh` | 增加缺少 opt-in 的负向测试和三 UI 开放的正向测试 |
| `scripts/check-docker-deployment.sh` | 渲染并校验恰好三个 `0.0.0.0` LAN 端口 |
| `admin/src/shared/runtime/companionUrl.ts` | LAN 浏览器访问时把配置中的 loopback companion host 换成当前浏览器主机 |
| `admin/tests/companion-url.spec.ts` | 增加 `localhost` 到 LAN host 的替换测试 |

Web/Admin 内部仍通过容器网络上的 Vite Proxy 请求 `api:8080`，因此局域网浏览器无需直接访问宿主
8080。Admin 中跳转 Web/Docs 时会保留端口并使用当前开发机的 LAN 主机名。

## 4. 本机应用结果

本机 `deploy/docker/.env.dev.local` 已启用三个 UI bind。为避免 Docker Hub 代理问题，本轮复用已有镜像，
仅重建 Web、Admin、Docs：

```powershell
docker compose `
  --env-file deploy/docker/.env.dev.local `
  -f compose.dev.yml `
  up -d --no-build --no-deps --force-recreate --wait web admin docs
```

实际发布结果：

| 服务 | 宿主发布 |
| --- | --- |
| Web | `0.0.0.0:3000 -> 3000/tcp` |
| Admin | `0.0.0.0:3001 -> 3001/tcp` |
| Docs | `0.0.0.0:3002 -> 3002/tcp` |
| API | `127.0.0.1:8080 -> 8080/tcp` |
| PostgreSQL/Redis/NATS | 全部 `127.0.0.1` |

开发机当前 LAN IPv4 为 `192.168.5.3`；本机通过该地址访问三个 UI 均返回 HTTP 200。

## 5. Windows 防火墙边界

当前连接“中兴巡天AX3000”被 Windows 标记为 `Public`。本轮没有为 Public Profile 添加入站规则，也没有
擅自把网络改为 Private。只有确认这是可信家庭/实验室网络后，才应把网络类别改为 Private，并添加：

```powershell
New-NetFirewallRule `
  -DisplayName "CampusOS Dev UI (Private LAN)" `
  -Direction Inbound `
  -Action Allow `
  -Protocol TCP `
  -LocalPort 3000-3002 `
  -Profile Private `
  -RemoteAddress LocalSubnet
```

如果路由器开启 AP/客户端隔离，即使端口和防火墙正确，设备之间仍无法互访。不得配置公网端口转发。

## 8. 风险和回滚

- Admin 3001 包含管理能力，只能在可信测试网络短期开放。
- 开发凭据、SMTP、JWT 和默认管理员配置不能用于生产。
- Windows 防火墙规则只允许 Private Profile 和 LocalSubnet。
- 不删除数据卷、不开放 8080/5050/数据库/NATS/Redis，也不修改路由器公网转发。

关闭 LAN 访问：

1. 将三个 `CAMPUSOS_DEV_*_BIND` 恢复为 `127.0.0.1`。
2. 将 `CAMPUSOS_DEV_ALLOW_LAN` 恢复为 `false`。
3. 重新创建 Web/Admin/Docs 容器。
4. 删除 `CampusOS Dev UI (Private LAN)` 防火墙规则（如果之后创建）。
