# CampusOS 进度证据索引

`docs/进度/` 保存每个版本阶段实际完成的内容、测试结果、兼容处理和回滚方式。它是验收证据，不是当前
操作教程。

## 如何阅读

1. 从 [版本计划总结](../计划书总结/README.md) 判断目标版本和计划是否仍有效。
2. 进入对应 `v0.X-dev/`，按文件名版本号排序。
3. 优先读取该阶段最后一份 Final、审计或回顾记录。
4. 用当前代码和检查器复验，不要把历史的一次成功结果当作当前工作树结果。

当前发布基线仍是 `v0.13.0`；项目所有者已确认 `v0.14-dev` 当前代码验证完成，开发阶段已收尾。
规划、实施与收尾证据位于 [v0.14-dev](v0.14-dev/)；`v0.14.0 Final` 仍须由 Release Owner 单独归档
真实数据和目标环境的发布证据。

## 进度文档必须包含

- 本阶段目标和实际完成内容。
- 主要修改目录和架构变化。
- API、数据、配置和兼容处理。
- 实际执行的测试与构建命令。
- 回滚方式、已知限制和下一阶段。

没有测试证据时不能写“已验收”。纯文档任务也至少执行链接、README、docs-site build 和差异检查。

## 与其他目录的区别

| 目录 | 作用 |
| --- | --- |
| `项目计划v*/` | 当时准备做什么 |
| `进度/v0.*-dev/` | 实际做了什么、如何验证 |
| `help/` | 当前如何使用和维护 |
| `architecture/`、`api/` | 当前边界和合同 |

## 维护约束

1. 新记录使用对应阶段的下一个可用编号，不覆盖或重命名旧证据。
2. 实现状态和验收状态分开；环境阻断时如实记录“部分验收”。
3. 命令结果必须来自当前工作树，不复制上一份进度文档的数字。
4. 进度记录可以引用当前 Help，但不能回写历史证据以伪造当时已经完成。
5. 纯文档阶段也应记录链接检查、文档站构建、差异检查和基础 Go 回归。
