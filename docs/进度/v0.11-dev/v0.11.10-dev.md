# CampusOS v0.11.10-dev：A9 保留预演与兼容遥测

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

先建立可审计的 retention inventory/dry-run 和旧路径使用证据，再讨论任何物理清理。

## 实际完成内容

- `platform_retention_runs` 只记录 dry-run 的目标、截止时间、候选数和状态；服务端
  `CanDelete=false`，没有通用删除入口。
- 预演覆盖 Outbox、授权审计、Webhook 投递、内容修订、内容治理、插件日志等已有
  Owner 表。
- `platform_compatibility_usage` 汇总 legacy permission catalog、legacy builtin API、
  legacy runtime 名称、个人空间内容投影和 Legacy Resource Source 的实际调用量。
- 管理员可读取预演历史和兼容量，但不能借此删除历史表、目录或审计。

## 主要修改目录和文件

- `internal/platform/reliability/{types,store,pg_store,service,handler}.go`
- `migrations/000027_v11_reliable_commands_and_outbox.*.sql`
- `internal/modules/features/personalspace/`、`internal/plugin/`、`internal/modules/features/appearance/`

## 架构变化

Retention 与兼容证据属于 Reliability Core；业务 Owner 继续拥有自己的数据和删除策略。
Resource Package 不获得新的业务生命周期。

## 兼容和迁移处理

旧路径保持可读和可观测。连续版本的实际使用量、备份、恢复、checksum/数量对账和
明确弃用计划是删除前提，v0.11 不做物理清理。

## 测试与构建结果

- `TestRetentionPreviewRecordsDryRunOnly` 通过，验证预演不改变 Outbox 状态。
- `GOCACHE=/tmp/campusos-go-cache go test ./internal/platform/reliability -count=1` 通过。

## 回滚方式

停用预演 UI/API 不会删除历史 retention run；不执行实际数据回滚或删除。

## 已知限制

保留策略尚未包含审批、分批执行、取消、法定保留规则或集群容量策略，后续版本另行
设计。
