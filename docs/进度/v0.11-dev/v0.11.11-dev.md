# CampusOS v0.11.11-dev：A10 可观测性与 Admin

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

把可靠运行状态以受权限保护、不会泄露 payload/Secret 的方式交给后台管理员，并让
路由、Permission Code、文档和架构页同步。

## 实际完成内容

- 新增 `/reliability` 管理页：队列摘要、事件筛选、消费尝试、Worker 心跳、可恢复
  operation、可靠命令关联、兼容遥测和 retention dry-run。
- 新增 `/platform/reliability/*` HTTP 合同，分离 read、replay、retention preview 的
  Permission Code 与 Operation Code；项目路由审计识别 `core.reliability` Owner。
- dead-letter 重放带二次确认和客户端生成的 `Idempotency-Key`；没有“手动 ProcessOnce”
  或任意状态改写接口。
- Admin 数据架构页显示 `000027` 表及关系；Integration Webhook 表单暴露安全范围内的
  endpoint 并发/速率设置。
- 新增仓库/文档站运维教程、API 合同、权限设计补充和 Webhook 安全模型。

## 主要修改目录和文件

- `admin/src/modules/operations/pages/ReliabilityView.vue`
- `admin/src/modules/operations/{api,routes}.ts`
- `internal/transport/httpapi/router.go`、`internal/projectaudit/routes.go`
- `docs/api/`、`docs/help/系统设计相关/`、`docs-site/operations/`

## 架构变化

后台通过 HTTP Handler 读取 Reliability Service，不读取 Store/数据库。command audit API
返回最小安全投影，避免把运维页面变成 payload 或 secret 浏览器。

## 兼容和迁移处理

所有新 API 是加法；既有 Admin/Integration 页面和 Webhook API 保持兼容。`metrics` 继续
提供进程内计数，可靠性页以持久队列/尝试/operation 数据为主。

## 测试与构建结果

- API handler、路由 Owner、replay rollback 和 Admin TypeScript build 在 Final 通过。
- 完整 API 变化由 `make contracts` 生成并由 `make contracts-check` 验证。

## 回滚方式

可撤回 Admin route/UI 而不删除 Outbox、command audit 或 operation 数据；生产回退仍
先停止 producer 和 Worker，而不是清空队列。

## 已知限制

v0.11 没有 Prometheus/集中告警/SLO 系统；当前是持久状态页面与进程内基础计数，告警
阈值和多实例指标聚合属于后续工作。

## 下一阶段任务

执行故障注入、恢复、前后端、数据库、浏览器与发布门禁，并形成最终回顾（Final）。
