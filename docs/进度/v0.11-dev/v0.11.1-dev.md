## 阶段目标

在可靠性改造前固定 v0.10 的代码、迁移、路由、模块和数据目录事实，避免将历史
兼容问题误判为 v0.11 回归。

- 冻结起点为分支 `djw-update` 的 `0c22ee48452029470985884c997cce8db620486f`，
  运行时版本 `v0.10.0`，migration `000001` 至 `000026`。
- 把 v0.10 最终发布、恢复、浏览器和七视口证据引用到 v0.11 计划；基线不重写历史证据。
- 记录兼容文件名 `openapi-v0.6-current.yaml`、`http-routes-v0.6.json`，它们的内容
  由路由生成器而非文件名决定。
- 明确现有 `data/plugins`、`data/plugin_data`、`data/module_data`、`data/resources`
  与 `data/personal-space` 的物理边界；本阶段没有移动用户数据。

## 架构变化

无运行时代码变化。此阶段确认 v0.11 只能以追加 migration、适配层和兼容 API 进入，
不允许重写 Identity、Community、Plugin Platform 或 EventBus。

## 兼容和迁移处理

`000001` 至 `000026` 保持不可改写；旧权限表、EventBus、Webhook API、Manifest 与
资源目录继续可读。后续 migration 从 `000027` 顺序追加。

## 测试与构建结果

- 基线采用 v0.10 已归档的 `v0.10.27-dev` 完整发布门禁证据。
- v0.11 最终再次执行全量 Go、合同、架构、数据库、前端和恢复门禁，结果见
  `v0.11.12-dev.md`。

## 回滚方式

本阶段只建立证据。回滚只需撤回 v0.11 基线说明，不影响数据库、路由或用户数据。

该快照是版本起点，不是生产备份替代物；生产恢复仍须使用受控备份和隔离恢复演练。
