# CampusOS v0.11.3-dev：A2 TxKernel

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

提供不泄露 `pgx.Tx` 的事务 Port，使高风险命令、审计和事件可以共享同一提交边界，
同时让 Memory Profile 验证回滚行为。

## 实际完成内容

- 新增 `internal/platform/transaction` 的 `Manager.Within`、PostgreSQL executor 上下文
  和 Memory snapshot/restore Adapter。
- 支持 error 与 panic 触发 Memory snapshot 恢复；Repository 使用
  `transaction.ExecutorFor` 接入当前事务。
- Identity、Community 和 Reliability Memory Repository 注册 snapshotter，避免本地
  profile 在 required audit 失败时留下半成品。
- 可靠性边界检查阻止业务 Service 新增散落的 `pool.Begin`。

## 主要修改目录和文件

- `internal/platform/transaction/`
- `internal/modules/core/identity/repository/`
- `internal/modules/core/community/repository/`
- `scripts/check-reliability-boundaries.py`

## 架构变化

事务从各模块临时拼接改为平台 Port。事务上下文仅对 Repository Adapter 可见，
不是全局 Service Locator，External Plugin 无法访问。

## 兼容和迁移处理

这是纯代码适配层，无 schema 变更。未迁移的低风险读写继续使用既有 Repository
方法，API 和用户数据不变。

## 测试与构建结果

- `GOCACHE=/tmp/campusos-go-cache go test ./internal/platform/transaction -count=1` 通过。
- panic 回滚、required audit 失败回滚由故障注入脚本和 Final 回归覆盖。

## 回滚方式

先停止新 reliable command producer，再切回旧构造路径；不删除后续 Outbox migration。

## 已知限制

TxKernel 只覆盖同一 PostgreSQL 数据库；它不覆盖 HTTP、NATS、文件或插件进程。
