- 事件、重放、操作、兼容遥测和命令审计使用安全响应 DTO，不再返回 payload、
  headers、幂等键或 raw details。
- Admin 可靠任务中的七类列表均增加独立分页，筛选和事件切换会正确重置页码。
- 新增 `000027` 隔离 up/down/up 脚本并接入 `make database-check`，验证历史 Webhook
  endpoint 在回滚和再次升级后保留。

## 架构变化

Store 分页合同由“条数上限”升级为“页请求 + 真实总数”，PG 和 Memory 行为一致；旧
Service 方法没有删除。HTTP 边界使用显式投影，不把内部持久事件结构作为公开合同。
查询限流位于可靠性 Handler 边界，不进入 Core Store，也不被宣称为集群协调能力。

## 兼容和迁移处理

- 旧 `limit` 继续等价于第一页页大小，响应保留 `data.total` 并新增
  `data.pagination`。
- 路由、Permission Code、数据库表名和历史 migration 未改名或删除。
- `000027` down/up 只在脚本创建的隔离数据库执行；生产继续 forward-fix。
- Admin 只消费新增分页元数据，旧后端响应类型仍保留兼容字段。

## 回滚方式

1. 回退 HTTP 分页时可继续调用保留的旧 Service 列表方法；不要删除新增测试。
2. 查询限流器是无持久状态的进程内保护，回退代码或重启不会修改业务数据。
3. Admin 分页可独立回退，不影响 API、事件状态或用户数据。
4. migration 脚本只新增测试门禁；生产 migration 仍遵循备份和 forward-fix。

## 已知限制

- 查询与 Webhook endpoint 限流均是单进程，不是多实例共享配额。
- Outbox 和外部投递仍为至少一次，不提供 exactly-once。
- retention 仍只有 inventory/dry-run；Prometheus、SLO 和自动修复不属于 v11。
