# CampusOS v0.11.4-dev：A3 持久 Outbox 与命令审计

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

建立能与业务事务同提交的持久事件、命令审计、消费者回执和可恢复操作数据模型。

## 实际完成内容

- 追加 `000027_v11_reliable_commands_and_outbox`，新增 Outbox、receipt、attempt、
  command audit、worker lease、operation、compatibility 与 retention run 表。
- 实现 PostgreSQL/Memory Store 的 enqueue、幂等键、读取、claim、command audit、
  operation 和 dry-run 接口。
- `reliability.Service.Execute` 原子执行业务 action、事件、`platform_command_audits`。
- 命令审计列表仅投影安全关联字段，不把 `details`、payload 或 Secret 暴露给后台。

## 主要修改目录和文件

- `migrations/000027_v11_reliable_commands_and_outbox.*.sql`
- `internal/platform/reliability/{store,pg_store,service,handler}.go`
- `scripts/schema-contract.sql`、`scripts/check-outbox.sh`

## 架构变化

`core.reliability` 成为 `core.event-bus` 之后启动的始终启用 Core Module，提供受限 Port
给 Core 与 Built-in Feature，替代“提交后立即 goroutine 发布”的高风险路径。

## 兼容和迁移处理

旧 EventBus 和审计表仍保留。migration 只追加结构；生产回退采用 forward-fix，down
只用于有备份的隔离演练。

## 测试与构建结果

- `GOCACHE=/tmp/campusos-go-cache go test ./internal/platform/reliability -count=1` 通过。
- `make outbox-check` 与数据库/schema contract 在 Final 通过。

## 回滚方式

停止新 producer 后保留 Outbox 行和 command audit，不删 `000027` 表；必要时修复并
重新部署消费者。

## 已知限制

Outbox 只保证持久事件进入队列，不让 HTTP/Webhook 获得 exactly-once 语义。
