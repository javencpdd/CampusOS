# CampusOS v0.11.9-dev：A8 Webhook 可靠安全投递

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

把 Webhook 从进程内重试改为提交后持久投递，并收紧 SSRF、重定向、DNS、签名和
流量边界。

## 实际完成内容

- 根领域事件经 `webhook.fanout` consumer 创建 `webhook.delivery` 子事件；endpoint 与
  event 的 delivery key 去重，投递记录与 Outbox 关联。
- Worker 处理网络/429/5xx retry、`Retry-After`、最大尝试和 dead-letter；普通 4xx
  作为永久失败。
- URL、redirect、DNS 与实际 dial 均执行受控验证；默认拒绝私网、loopback、
  link-local、multicast 等目标，transport 不继承代理。
- endpoint 增加并发/速率/超时边界，响应头限 32 KiB、体限 64 KiB；Admin 可配置
  合法范围并显示限制。
- v1 HMAC 覆盖 timestamp 与 raw body，携带 event ID；测试按钮是经同样 egress 防护的
  直接探测，不是 durable job。

## 架构变化

Webhook 是 Built-in Feature 的具名 Reliable consumer；它不会直接访问 Outbox 表，也不
把 HTTP 调用放进数据库事务。

## 兼容和迁移处理

既有 `/webhooks/*` endpoint/delivery API 保留并追加可选字段。旧 EventBus 订阅通过
同一幂等 enqueue 兼容；接收方仍必须处理至少一次投递。

## 测试与构建结果

- 私网 URL、delivery key、fan-out、签名、响应限制、Retry-After 和 rate limiter 单元
  测试通过。
- `GOCACHE=/tmp/campusos-go-cache go test ./internal/modules/features/webhook -count=1` 通过。

## 回滚方式

不得以回退为由重新打开不安全私网 URL；保留 dead-letter 和投递历史，停止新 fan-out
后按 operation/event 状态 forward-fix。

## 已知限制

每 endpoint 限流是单进程防护，不是多实例共享 quota；集群 limiter 属于后续版本。
