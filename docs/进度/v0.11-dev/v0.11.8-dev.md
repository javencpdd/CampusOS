# CampusOS v0.11.8-dev：A7 Plugin 与 Resource 补偿流程

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

使跨数据库和文件系统的 External Plugin 导入、升级和 Appearance 资源操作可识别、
可补偿、可恢复，而不假装是单个数据库事务。

## 实际完成内容

- Plugin Package 导入使用 staging、版本 snapshot、原子 rename 与失败恢复；Catalog
  写入失败时还原旧版本而非损坏正式目录。
- Plugin Manager 与 Appearance Facade 通过 Reliability `TrackOperation` 记录 intent、
  running、succeeded/failed 和恢复信息。
- 服务启动时将 `pending`、`running`、`compensating` 的历史 operation 标记 failed，
  要求人工依照 snapshot 重试。
- Legacy builtin API、legacy runtime 名称和 Legacy Resource Source 都写兼容遥测。

## 主要修改目录和文件

- `internal/plugin/{manager,package,platform_services,service_operations}.go`
- `internal/modules/features/appearance/runtime/`
- `internal/platform/reliability/{service,store,pg_store}.go`

## 架构变化

Plugin Platform 继续管理 External Plugin；Appearance 继续管理 Resource Package。两者
只共享可靠 operation Port，不共享内部 Repository 或数据库事务。

## 兼容和迁移处理

历史 `runtime: builtin`、`grpc` 名称和 `data/plugin_data/*/style-packs` 可继续读取，
同时记录实际使用，为未来弃用提供数据。

## 测试与构建结果

- `TestManagerImportPackageRestoresPriorVersionAfterCatalogFailure` 通过。
- `GOCACHE=/tmp/campusos-go-cache go test ./internal/plugin ./internal/modules/features/appearance/runtime -count=1` 通过。

## 回滚方式

按 operation snapshot/版本快照恢复；冲突或 checksum 不匹配时停止，而不是覆盖用户
目录。生产环境不对 `000027` 做破坏性 down。

## 已知限制

跨文件系统/进程流程是 Saga/补偿，不是 PostgreSQL 原子事务；自动化修复不会猜测
用户文件意图。
