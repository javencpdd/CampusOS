# CampusOS v0.11.7-dev：A6 Community 高风险治理

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

让下架、审核、恢复、回收站和永久清除等 Community 治理动作与真实板块 scope、
状态版本、审计和 Outbox 一致提交。

## 实际完成内容

- Community Repository 切换到 transaction executor，并对 thread 写入使用 revision
  防止静默覆盖。
- 高风险治理命令在可靠事务中写内容状态、revision/case/action、required evidence 和
  领域事件；提交后再失效列表缓存。
- 事务内权限拒绝会回滚业务工作，并在回滚后独立写 deny/error authorization evidence，
  防止拒绝证据随失败事务消失。
- 内容授权继续从数据库真实 `category_id` 和 scope 判断，不信任客户端传入板块。

## 主要修改目录和文件

- `internal/modules/core/community/{module.go,service,repository}/`
- `internal/modules/core/community/service/thread_service_test.go`
- `internal/platform/reliability/`

## 架构变化

Community Core 使用 Reliability Port，不读取 Identity PostgreSQL Repository。Identity
继续通过窄授权 Port 提供 scope 判断和审计。

## 兼容和迁移处理

公开/作者/Admin 查询、普通文本/RichText 关联和旧状态字段保持兼容；缓存只在事务提交
后失效，避免回滚路径污染读模型。

## 测试与构建结果

- 治理 required evidence 回滚、deny audit 保留、真实 scope 与 revision 回归测试通过。
- `GOCACHE=/tmp/campusos-go-cache go test ./internal/modules/core/community/service -count=1` 通过。

## 回滚方式

回退前停止新治理 producer，保留已经提交的内容/审计/Outbox 证据；冲突不通过手工
覆盖修复。

## 已知限制

v0.11 不增加多级板块或自动继承版主范围，`self/subtree` scope 仍属于 v0.12。
