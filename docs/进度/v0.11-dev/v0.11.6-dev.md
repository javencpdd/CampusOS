# CampusOS v0.11.6-dev：A5 Identity 与权限原子命令

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

将注册、角色授予/撤销、自定义角色矩阵和版主板块范围纳入可靠命令，同时保留 v10
的 anti-escalation、最后管理员和 scope 规则。

## 实际完成内容

- 注册将 `users`、`accounts`、required command audit 与 `user.created` Outbox 事件
  纳入同一事务，账号或审计失败不会留下孤立用户。
- 角色授予/撤销、范围替换、创建自定义角色和更新权限矩阵通过可靠命令写入
  authorization audit、command audit 与 `authorization.changed`。
- PostgreSQL Identity Repository 使用当前 transaction executor；Memory Repository 注册
  snapshotter，覆盖 required audit 失败回滚。
- `permissions` 兼容目录 fallback 记录可靠性遥测，不改变既有授权判定。

## 主要修改目录和文件

- `internal/modules/core/identity/{module.go,service,repository,permissioncode}/`
- `migrations/000027_v11_reliable_commands_and_outbox.up.sql`
- `docs/help/系统设计相关/v11权限管理与可靠审计设计入门.md`

## 架构变化

Identity Core 通过 Reliability Port 提交高风险命令；路由 Operation、Permission Code、
真实 scope 与业务不变量仍由 Identity 服务端最终判断。

## 兼容和迁移处理

注册响应、登录 API 和 `accounts.verified` 语义不变。`member`/`guest`、系统角色保护、
禁止自助提权和最后管理员保护均保留。

## 测试与构建结果

- 注册 required audit/account 失败回滚、权限目录 fallback 遥测、角色约束单元测试通过。
- `GOCACHE=/tmp/campusos-go-cache go test ./internal/modules/core/identity/service -count=1` 通过。

## 回滚方式

保留 `000027` 与 command audit；如需回退 producer，先停止高风险新写入并以
forward-fix 处理已提交事件，不回滚已生效的角色事实。

## 已知限制

邮箱验证和旧用户验证迁移仍是 v12 工作，v11 不突然改变登录可用性。
