## 架构变化

高风险数据库事实、required audit、command audit 和 Outbox 通过 TxKernel 同提交；
提交后由 fenced Worker 至少一次处理。文件/插件/资源操作使用持久 operation、staging
和补偿，Webhook 使用持久 child event、endpoint 级限制和严格 egress 检查。

## 兼容和迁移处理

- API、旧权限目录、EventBus、Webhook endpoint/delivery、`runtime: grpc`、legacy
  builtin 和 Legacy Resource Source 保持兼容，并记录使用证据。
- `000027` 仅追加。生产回滚使用 forward-fix；不会删除 Outbox、审计、用户文件或
  Feature 数据。
- 版本同步为 `v0.11.0`：应用、模块描述符、Go/TypeScript SDK、docs-site、模板和
  生成 OpenAPI/路由矩阵一致。

## 回滚方式

1. 停止新 reliable command producer 和 Worker poll，不清空队列。
2. 等待/释放有效 lease，保留 dead-letter、attempt、command audit 和 operation evidence。
3. 回退代码后通过 forward-fix 处理 `000027`；down 仅在有备份的隔离环境演练。
4. 插件/资源按 snapshot 和 operation 状态恢复，冲突时停止人工处理。

## 已知限制

- Webhook、Worker 和外部副作用是至少一次，不是 exactly-once。
- endpoint rate/concurrency 是单进程保护；没有多实例共享 limiter。
- 保留策略只 dry-run；没有物理清理、审批、集中告警或 Prometheus/SLO。
- 邮箱验证、多级板块、产品交易/互助、容量与集群性能仍不属于 v0.11。
