# CampusOS v0.11.14-dev：可靠任务页面与模块启动时序修复

> 日期：2026-07-17
>
> 实现状态：完成
>
> 验收状态：已验收

## 阶段目标

修复 Admin 点击“可靠任务”后提示加载失败的问题，确认当前代码能够从零启动完整模块
图，并防止 Reliability、Appearance 和 Plugin Platform 再次因生命周期时序失配而
启动失败。

## 根因

API 日志显示：

```text
register module "feature.appearance": appearance reliability port is unavailable
```

Module Registry 先按拓扑顺序完成所有 `Register`，再执行所有 `Start`。Reliability
原先在 `Start` 才构造并发布 Service/Handler；Appearance 与 Plugin Platform 已在
`Register` 查询它，因此 API 退出。Vite Admin 仍可提供页面，最终只显示通用加载失败。

## 实际完成内容

- Reliability 在 `Register` 校验 Profile Adapter、构造 Service/Handler 并发布稳定
  Port。
- Reliability `Start` 只绑定已经启动的 EventBus、恢复中断操作并启动 Worker，保持
  注册阶段无后台执行。
- 新增生命周期测试，验证依赖模块可在注册阶段取得 Port，缺失 Profile Adapter 时
  明确失败。
- Identity、Community、Plugin Platform、Appearance、Personal Space 与 Webhook 的
  Module Manifest 同步声明 `core.reliability` 依赖。
- 运维文档补充“前端可打开但 API 未启动”的排查步骤。
- 修正七视口脚本在窄屏点击遮罩中心时被侧栏拦截的问题，改为点击实际可见的遮罩
  右侧区域。

## 架构变化

稳定、可依赖的编译内 Port 在 `Register` 发布；产生 goroutine、恢复扫描或外部连接的
运行行为留在 `Start`。该规则符合现有 Registry 两阶段生命周期，也避免把 AppContext
改造成可变全局 Service Locator。

## 兼容和迁移处理

- HTTP 路由、Permission Code、响应结构和数据库 schema 均未改变。
- Outbox、Worker、Webhook、插件 operation 与 Appearance 数据不迁移、不删除。
- Manifest 只补齐实际依赖，不改变模块 ID、Feature ID 或启停模式。

## 回滚方式

代码可回退，但旧实现会重新引入 API 无法冷启动的问题，因此只建议 forward-fix。
回滚不需要数据库 down，也不得删除 Outbox、审计或用户数据。

## 已知限制

- Browser smoke 依赖已运行服务，不能单独证明当前代码可冷启动；本阶段使用生命周期
  单元测试和真实 `make dev-all` 补足证据。
- 查询限流仍为单进程，集群共享配额不属于本修复。
