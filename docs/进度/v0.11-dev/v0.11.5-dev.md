# CampusOS v0.11.5-dev：A4 Reliable Worker Runtime

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收（最终回归见 `v0.11.12-dev.md`）

## 阶段目标

让已提交事件可在重启、重复消费和多 Worker 竞争下被恢复处理，并保留每次尝试证据。

## 实际完成内容

- Worker 用 `FOR UPDATE SKIP LOCKED`、lease owner 和 generation 领取事件；旧 worker
  不能在 lease 被接管后完成事件。
- 实现指数退避、抖动、最大尝试次数、永久失败、dead-letter 和手动受控重放。
- 一个事件可注册多个具名 consumer；每个 receipt 独立保存，成功 consumer 不会因其他
  consumer retry 重复执行。
- Runtime 以 context 驱动启动/停止并写 heartbeat，启动时将中断的文件/资源操作标为
  failed，保留人工恢复说明。

## 主要修改目录和文件

- `internal/platform/reliability/{worker,module,reliability_test}.go`
- `modules/core/reliability/module.yaml`
- `internal/server/{bootstrap,platform_modules}.go`

## 架构变化

Worker 是 Reliability Core 的生命周期能力，而不是 Webhook 或 EventBus 中的无跟踪
goroutine。EventBus 只作为兼容 fallback consumer。

## 兼容和迁移处理

没有移除旧 EventBus。exclusive handler 抑制 fallback；additive consumer 可保留旧
订阅，并通过子事件幂等处理重复 fan-out。

## 测试与构建结果

- lease fencing、retry、dead-letter、receipt、fan-out 和 interrupted operation recovery
  单元测试通过。
- `make outbox-check`、`make failure-injection-check` 在 Final 通过。

## 回滚方式

停止 Worker 时取消 poll loop，但不改事件状态；等待 lease 过期后再由回退/新版本
Worker 接管，禁止手工把 processing 改成功。

## 已知限制

吞吐与跨实例容量目标不属于 v11；Worker 语义为至少一次。
