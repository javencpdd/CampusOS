# v0.8.9-dev：A9 Plugin Platform 主路径收敛

> 阶段状态：已完成，已验收
> 更新日期：2026-07-13
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划v8/00-v8版本计划书.md)

## 阶段目标

保留 Plugin Manager 的公开兼容 API，但将 Catalog、Lifecycle、Config、UI、Event 和 Audit 子服务从对 Manager 的结构性反向依赖中移出；明确 legacy builtin 仅为 Built-in Feature 的投影，真正的外部插件继续由 Plugin Platform 管理。

## 实际完成内容

- `LifecycleService`、`ConfigService`、`UIRegistry`、`EventRegistry` 和 `AuditLogService` 改为注入最小回调，不再保存 `*Manager`。
- `PluginCatalog` 改为回调式查询入口；运行时 Registry 保持独立所有权。
- Plugin Manager 保留原有方法作为兼容 Facade，并继续集中维护内部插件记录、持久化和旧 API 行为，避免破坏 SDK、CLI 与 Admin 调用。
- 审计仓储和 UI revision/listener 状态从子服务回收为 Manager 内部状态，消除子服务反向访问 Manager 的路径。
- Admin 旧插件响应新增 `capability_class`、`lifecycle_owner` 和已映射 builtin 的 `feature_state`，使前端可以区分 External Plugin 与 Built-in Feature。
- Host API v1 已改为使用 Identity/Community 公共 Port，不再允许插件 Host API 直接依赖核心 Repository；架构 allowlist 已缩减到 `0`。

## 主要修改目录和文件

- `internal/plugin/hostapi/{hostapi.go,permissions_test.go}`

## 架构变化

Plugin Platform 的公开 Manager 已成为兼容入口，而各子服务通过明确回调合同协作。legacy builtin 的启停状态、配置和 UI 状态由 Feature Registry 投影；External Plugin 继续只能经 Host API、Extension Gateway 或公开接口访问核心能力。

## 兼容和迁移处理

- `Manager`、现有插件 manifest、gRPC/Wasm/builtin runtime、Host API v1 与 Admin API 均保留。
- Host API `GetUser` 保留既有公开字段；实现改为 Identity User Reader Port。
- 旧 builtin 插件记录未删除，仍用于首次 Feature Store 初始化和旧管理入口展示。

## 回滚方式

回滚代码即可恢复旧 Manager 子服务实现；数据库、manifest、外部插件包与 Host API 合同未发生破坏性变化。不要通过回滚重新扩大架构 allowlist。

## 已知限制

- Manager 仍保存插件目录的内部运行状态，作为兼容 Facade 的实现细节；后续不得重新将其暴露为跨领域依赖。
- Built-in Feature 与 External Plugin 的独立 Admin 页面属于 A13；本阶段只提供响应元数据以保持旧页面兼容。
