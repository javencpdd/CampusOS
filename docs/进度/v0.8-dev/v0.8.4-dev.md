# v0.8.4-dev：A4 Community Core 完整迁移

> 阶段状态：已验收  
> 完成日期：2026-07-13  
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划v0.8/00-v0.8版本计划书.md)

## 阶段目标

将 Category、Thread、Post、标签、可见性、回复楼层、缓存和社区事件的实际组装归入 Community Core Module，并让 Server 只消费公开组件，不再导入 Community 具体实现。

## 实际完成内容

- 新增 `internal/community/profile.go`，PG/Memory Profile 分别绑定 Thread、Category、Post Repository Adapter。
- 新增 `internal/community/module.go`，实现 `core.community`。它依赖 EventBus 和 Identity Core，在启动时组装 Thread/Category/Post Service、缓存、HTTP Handler 和 Event Handler。
- Community Module 在注册时发布 `community.category-reader`、`community.thread-port`、`community.post-port`；服务端其他领域已有 Port 名称不变。
- EventBus Module 额外发布 `platform.memory-event-bus`，由 Community Module 构造原有 `/events` 兼容 Handler；Server 不再直接创建该 Handler。
- Cache 在 Infrastructure Profile 中先创建并发布 `platform.cache`，让 Community 的 PG/Memory 业务装配共用一套 Service、Handler 和缓存规则。
- `application.go` 删除 Community Repository、Service 和 Handler 的具体导入、构造和 `assembleCommunity` 调用；它只使用 Community Module 暴露的 Repository 接口、Services 与 Handler 组。
- 删除 `module_assembly.go` 中的 Community 业务装配和公开 Port 重复注册。
- 删除 Server 相关 allowlist 来源，历史集合从 8 个来源/23 条边下降到 6 个来源/12 条边。

## 架构变化

Community 的 Profile Adapter、缓存依赖、事件总线、内容应用服务、HTTP Handler 和公开 Port 都由同一 Module 管理。PostgreSQL 与 Memory 不再分别在 Server 中构造 Community 业务对象。Server 保留的工作仅是读取 Module 公开组件以维持现有路由注册顺序。

## 兼容和迁移处理

- 版块、默认标签、帖子可见性、私密帖子、回复楼层、缓存失效、事件和管理端操作保持原有 Service 实现与 API 语义。
- 未修改路由、OpenAPI、权限、migration、数据表、数据目录或前端 URL。
- `platform.cache` 仍按原有 Redis 可用性回退到 MemoryCache；只改变其注入位置。
- `setupRoutes` 仍是 A11 前的静态兼容注册器，Community HTTP Handler 组不改变其 148 条路由合同。

## 回滚方式

在 A14 前，可以恢复原 Server Community Repository/Service/Handler 构造和 `assembleCommunity` 兼容实现；无需数据迁移或目录恢复。不得同时保留两套 Community Service 对同一事件/缓存的主路径。

## 已知限制

- Moderation、RichText、MCP-like 和 Host API 仍使用 Community 的具体实现，均在当前 allowlist 中；A5、A7、A9、A10 将逐项改为公开 Port。
- Community 路由仍未成为 Route Registry Contributor，A11 统一处理合同源迁移。
- Storage、Space、Schedule 和 Appearance 的业务构造还在 Server 兼容入口中。
