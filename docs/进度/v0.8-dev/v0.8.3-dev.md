# v0.8.3-dev：A3 Identity Core 完整迁移

> 阶段状态：已验收  
> 完成日期：2026-07-13  
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划书v0/项目计划v0.8/00-v0.8版本计划书.md)

## 阶段目标

使 Identity 成为实际运行的 Core Module：PG/Memory Profile 绑定 Adapter，Module 自己拥有用户、认证、角色、权限 Service/Handler 和公开 Port，Server 不再构造 Identity 具体实现。

## 实际完成内容

- 新增 `internal/core/identity/profile.go`，由 Profile 绑定 PostgreSQL 或 Memory 用户/角色 Repository Adapter 到明确的 Identity Adapter Port。
- 新增 `internal/core/identity/module.go`，实现 `core.identity` 生命周期。它依赖 `core.event-bus`，在启动时构造 UserService、PermissionService 和 HTTP Handlers，并发布 `identity.user-reader` 与 `identity.authorization` Port。
- 新增 Module 测试，覆盖 Memory Adapter、EventBus、JWT、公开 UserReader/Authorization Port 和 Handler 构造。
- EventBus Module 在启动后发布 `platform.event-bus` Port，使 Identity 通过 Module Context 获取事件总线，而不依赖 Server 传入具体对象。
- `bootstrap.go` 用 Identity Module 替代 `core.identity` marker；Server Profile 根据实际数据库状态绑定相同的 Identity Adapter 集合。
- `application.go` 不再导入或创建 Identity Repository、Service、Handler，也不再调用 `assembleIdentity`。它只消费 `s.identity` 暴露的 JWT、Repository 接口、PermissionService 与 Handler 组。
- 将 HTTP 权限中间件的参数从具体 `*identity/service.PermissionService` 收窄为 `middleware.PermissionChecker` 接口。
- 删除 Server 对 Identity 的 6 条跨具体实现 allowlist 边；冻结集合从 23 条降为 17 条。

## 架构变化

Identity 的 Adapter 选择、应用服务组装和 HTTP Handler 所有权均已离开 Server。Infrastructure Profile 只选择 PostgreSQL/Memory Repository Adapter，Identity Module 只依赖 Profile Port 和 EventBus Port。HTTP middleware 只认识授权协议，避免从 Transport 反向依赖 Identity 的具体 Service。

## 兼容和迁移处理

- 登录、注册、JWT claim/TTL、默认管理员、角色、权限和现有路由没有变化。
- PostgreSQL 模式继续使用 `accounts` 中的凭据，Memory 模式继续保持简化登录行为。
- 没有新增 migration、没有修改 `000001` 至 `000018`、没有移动用户数据或改变错误包络。
- 旧 `assembleIdentity` 已删除，不保留双业务组装路径；Server 获取的对象均来自同一个已启动 Identity Module。

## 回滚方式

在 A14 前，可恢复旧的 Server Identity 构造和 `assembleIdentity` 兼容实现，并撤回 Identity Profile/Module 注册；没有数据迁移需要回滚。不得同时保留两套 Identity Service 写入路径。

## 已知限制

- Community、Moderation、Storage 和其他 Feature 仍在 Server 兼容组装中；下一阶段将采用同样的 Profile + Module 模式迁移 Community。
- Identity 的 HTTP 路由仍由 `setupRoutes` 集中注册，Route Contributor 接入属于 A11，未提前改变 148 条合同。
- 部分领域仍以具体 `*PermissionService` 作为构造参数；A5 将通过 Moderation 的公开 Authorization/Scope Port 消除这些跨域具体依赖。

## 下一阶段任务

A4 将迁移 Community 的 PG/Memory Adapter、内容 Service/Handler、公开读写 Port 和事件所有权，随后删除 Server 与 `module_assembly.go` 的 Community 具体依赖。
