# v0.8.8-dev：A8 Appearance Module

> 阶段状态：已完成，已验收
> 更新日期：2026-07-13
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划v8/00-v8版本计划书.md)

## 阶段目标

将 Homepage Customizer、Web Theme 和既有 Resource Package Facade 收敛为一个 Built-in Appearance Module，Feature Store 成为页面外观配置的运行时读取来源，并保持旧插件配置接口、风格包目录和 HTTP API 兼容。

## 实际完成内容

- 新增 `feature.appearance` Module，统一装配 `AppearanceFacade`、Homepage Handler 和 Web Theme Handler。
- Homepage 与 Web Theme 服务改为依赖最小 `ConfigSource`，不再把 Plugin Manager 或 plugin lifecycle 注入新主路径。
- Appearance Module 通过 Community `CategoryCatalog` Port 读取板块显示信息，不导入 Community Repository。
- Appearance Feature 的 Store 配置按 `homepage`、`web_theme` 两个区段保存；旧 `homepage-customizer`、`web-theme` 配置在首次启动时导入对应区段。
- 旧插件更新接口在 schema/HTML/CSS 校验成功后同步更新 Appearance Feature Store；历史 `PluginLookup` 构造入口保留在各领域的 `compatibility.go`。
- Server 不再创建 Homepage/Web Theme Service 或 Handler，公开与后台现有路由继续使用相同 URL、权限和响应格式。

## 架构变化

Appearance 是唯一的 Built-in Feature 装配边界。首页和系统主题的运行时配置来自 Feature Store，`data/resources` 和 `data/plugin_data/*/style-packs` 仍由 `AppearanceFacade` 的兼容 Catalog 读取。旧 Plugin Manager 不再是 Appearance Feature 的运行时依赖。

## 兼容和迁移处理

- `/api/v1/home/*`、`/api/v1/web-themes/*`、后台风格包接口不改路径或权限。
- `homepage-customizer` 和 `web-theme` manifest/config 仍可被旧管理页读取和写入；写入后投影到 `appearance` Feature 配置。
- 旧风格包目录、资源 URL、导入导出格式不移动；Resource Package 的物理迁移继续由后续资源治理阶段单独处理。
