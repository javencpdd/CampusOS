# v0.8.2-dev：A2 Application Runtime 与 Infrastructure Profile 骨架

> 阶段状态：已验收  
> 完成日期：2026-07-13  
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划v8/00-v8版本计划书.md)

## 阶段目标

以不改变业务 API 和数据的方式，为后续领域迁移建立统一的 Application Runtime、PostgreSQL/Memory Profile 选择和静态 Route Registry。未迁移的业务仍由兼容 Composition Root 承载。

## 实际完成内容

- 新增 `internal/platform/runtime`：Runtime 先绑定 Infrastructure Profile，再按 Module Registry 规则注册/启动模块；停止时逆序停止模块后关闭 Profile。Profile 绑定失败和模块启动失败都会执行关闭回滚。
- 新增 `ProfilePostgreSQL` 与 `ProfileMemory` 的统一 Profile 名称和 `StaticProfile` Adapter。该 Adapter 在 `AppContext` 中发布 `platform.infrastructure-profile`，使实际 PG/Memory 选择可观察，同时不在 Server 中创建业务 Service 或 Handler。
- `internal/server/bootstrap.go` 改为先检测数据库并选择 Profile，再将 EventBus、Core Boundary 和 Plugin Platform Registration 交给 Application Runtime。`infrastructureBootstrap.Stop` 改由 Runtime 统一处理模块生命周期，数据库连接仍在其后关闭。
- 新增 `internal/platform/route`：Route Descriptor 校验稳定 ID、owner、method、path、audience、admin permission metadata；Registry 拒绝重复 ID 和重复 method/path，并按确定顺序输出合同。它不支持动态 Gin 路由。
- 为 Runtime 的绑定/启动/停止顺序、失败关闭和缺失 Profile，以及 Route Registry 的冲突、权限和排序行为补充单元测试。

## 架构变化

`Server` 不再自行创建和启动 Module Registry；基础设施生命周期收敛到 `platform/runtime`。PG 与 Memory 的选择现在显式存在于同一 Runtime/Profile 合同中。Route Registry 已成为后续模块路由的唯一目标合同，但 A11 前不替换 `application.go` 中的 148 条兼容路由注册。

## 兼容和迁移处理

- 未修改 HTTP/OpenAPI/权限合同、数据库 migration、Manifest、Feature 状态或持久化目录。
- 当 PostgreSQL 不可用时，Server 仍按原有行为进入 Memory 分支；Runtime 只改变基础设施生命周期的承载位置。
- `internal/server/application.go` 和 `module_assembly.go` 仍在 A1 allowlist 中，是 A3-A11 的临时兼容 Composition Root，不被误标为已清空。

## 测试与构建结果

已通过：

```bash
GOCACHE=/tmp/campusos-go-cache go test ./internal/platform/... ./internal/server/... -count=1

```

Runtime 和 Route Registry 均有独立正负单元测试；合同检查确认旧路由源尚未漂移。

## 回滚方式

可将 `bootstrap.go` 恢复为直接创建 Registry/调用 `StartAll` 的旧实现；没有 migration、配置格式或数据目录变化。Runtime/Profile 和 Route Registry 都是纯加法，可以独立移除。

## 已知限制

- Profile 当前只负责基础设施选择和 Profile Port；领域 Repository Adapter 的绑定将在 A3-A10 分别迁入各 Module，避免一次性移动业务对象。
- Route Registry 已可验证但尚未收集 148 条路由。A11 才会将 Route Contributor 作为 HTTP 合同源。
- `application.go` 的 PG/Memory 业务重复装配仍保留，防止在领域 Adapter 尚未迁移前出现双写或路由漂移。
