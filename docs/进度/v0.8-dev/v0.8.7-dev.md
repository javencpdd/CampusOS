# v0.8.7-dev：A7 Built-in Feature 迁移（进行中）

> 阶段状态：实现中，尚未验收  
> 更新日期：2026-07-13  
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划v8/00-v8版本计划书.md)

## 阶段目标

将 Personal Space、Controlled RichText Article 和 Personal Schedule 收敛为完整 Built-in Feature Module，Feature Store 成为启停状态唯一权威，三个功能只依赖 User Storage 与公开 Core Port，停用时保留用户数据。

## 当前完成内容

- 新增 `builtin_feature_states` 追加 migration（`000019`）和 PostgreSQL/Memory Feature Store。
- Feature Registry 会优先读取持久化 Feature 状态；只有没有状态记录的历史功能才从 legacy builtin plugin 读取一次并写入 Store。
- Feature 请求会持久化 desired/effective/pending-restart；重启型 Feature 不会被之后的 legacy Plugin 状态重新覆盖。
- Admin 旧 Plugin enable/disable 路由对 Personal Space、RichText、Schedule、Web Theme/Homepage 自动写入对应 Feature Store，保留旧 API 的兼容入口。
- 迁移已在本地 PostgreSQL 应用，`builtin_feature_states` 已从四个 builtin 记录初始化；Admin 数据架构视图同步增加该表和 `000019` 说明。
- Space、RichText、Schedule 为默认 `data/personal-space` 根目录新增 User Storage 注入构造。旧自定义根目录仍走 legacy constructor，避免移动用户文件。

## 架构变化

Feature 的状态存储已从 Plugin Manager 分离，旧 Plugin API 正在成为兼容投影。默认本地用户文件使用 Core User Storage 提供的根目录和配额，减少了 Space、RichText、Schedule 重复创建 LocalAdapter 的路径。

## 兼容和迁移处理

- 历史 builtin plugin 记录只在缺少 Feature State 时初始化，不覆盖管理员后续选择。
- `000019` 只新增表和一次性 `INSERT ... ON CONFLICT DO NOTHING`，不修改历史 migration、不删除插件或 Feature 用户数据。
- 自定义旧根目录、URL、头像、文章资源与课表 JSON 不移动，仍保留现有 constructor 作为单向 compatibility path。

## 回滚方式

回滚应用可通过 `000019_builtin_feature_state.down.sql` 删除新增表；生产回滚前必须备份该表。Feature 文件数据和旧 Plugin 记录不删除。代码可回退到 legacy Store/constructor，但不得在两个状态源之间双写。

## 已知限制

- Personal Space、RichText、Schedule 还没有各自的运行 Module/Application/Transport 组装，Server 仍创建这些 Feature Service/Handler。
- 自定义 legacy `file_root` 仍允许 Feature 创建本地 Adapter；下一切片将把它转换为 Storage compatibility adapter，而不是 Feature 自建 Provider。
- Feature 的配置 schema 和 Feature 管理 UI 尚未从 External Plugin 管理模型分离，属于 A7 后续和 A13。
