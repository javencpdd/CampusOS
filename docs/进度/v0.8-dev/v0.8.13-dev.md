# v0.8.13-dev：A13 Admin 前端领域化

> 阶段状态：已完成，已验收
> 更新日期：2026-07-13
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划书v0/项目计划v0.8/00-v0.8版本计划书.md)

## 阶段目标

按管理领域拆开 Admin 的请求和导航，明确 Identity/Moderation、Community、Plugins、Appearance、Integrations、Operations 的边界，并保留全部管理深链接与权限结果。

## 实际完成内容

- Admin API 拆分为 `identity`、`community`、`plugins`、`appearance`、`integrations` 与 `operations` 模块，共用一个认证 HTTP Client。
- 根 API 仅作为历史导入兼容 Facade；所有现有管理页面和 Admin Store 已改为直接导入所属领域 API/Store。
- Root Router 只聚合领域 Route 集合、管理布局和鉴权守卫；`/admin/*` 深链接继续重定向至原页面。
- Admin Store 移至 Identity 模块；旧 `@/stores/admin` 仍保留无状态兼容出口。
- Built-in Appearance 管理与 External Plugin 管理保持在不同领域 API/页面入口，不恢复普通插件卸载语义。

## 主要修改

- `admin/src/shared/api/client.ts`
- `admin/src/modules/*/{api,routes,store}.ts`
- `admin/src/api/index.ts`
- `admin/src/router/index.ts`
- `admin/src/stores/admin.ts`

## 兼容与回滚

未修改 Admin URL、`admin_token`、`admin_user`、角色校验或后端请求。旧 API/Store 的兼容导出可支撑已构建的内部扩展，回滚不需要数据迁移。
