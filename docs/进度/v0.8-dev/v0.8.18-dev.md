# v0.8.18-dev：Plugin、Route 与 Appearance 边界闭合

> 阶段状态：已完成，已验收  
> 更新日期：2026-07-13  
> 性质：A16 后真实性审查 R2

## 阶段目标

消除 Plugin Manager 对子服务内部状态的直接访问，使路由所有权来自真实运行时注册，并让 Homepage、WebTheme 和 Personal Space Style 通过同一个 Appearance Application 主路径运行。

## 实际完成内容

- Plugin Catalog、Runtime、Lifecycle、Config、UI、Event、Audit 各自拥有锁和状态。
- 新增 Package、Snapshot、Host Access 服务；安装、替换、导出、快照回滚、Host Token 校验和 Extension Dispatch 不再由 Manager 直接操作内部状态。
- `Manager` 仅保留兼容方法转发和子服务访问器；架构检查器禁止 Manager 持有 map/锁或越过子服务公共操作。
- 新增运行时 HTTP Route Registry；真实 Gin 注册和 Route Descriptor 由同一次调用生成，148 条路由逐条具有 Module owner，Admin 路由必须显式声明权限。
- 合同生成增加 `module_owner` 与 OpenAPI `x-campusos-module-owner`，并保持 method/path/auth/permission 集合不变。
- Appearance Application 成为 Homepage、WebTheme 和 Space Style 的校验、预览、应用、回滚入口；旧 Handler 仅作 Transport/Compatibility Adapter。

## 架构变化

Plugin Platform 的状态所有权由具体子服务承担，Manager 是无状态 Facade。HTTP 路由属于 Transport Adapter，但 Descriptor owner 对应实际业务 Module，Server 不注册业务路由。Appearance 的目标实现可通过 Adapter 接入，调用者不再绕过统一应用服务。

## 兼容与迁移

Plugin Manager 的公开 Go 方法、HTTP API、Host API v1、9 个 Manifest、插件目录、快照目录和风格包目录保持不变。Appearance 不搬迁资源文件；旧 `data/plugin_data/*/style-packs` 继续作为 Legacy Resource Source。

## 测试与构建结果

- `go test ./internal/plugin ./internal/server ./internal/transport/httpapi ./internal/platform/route ./internal/appearance ./internal/space -count=1`：通过。
- 关键 Plugin/Route/Appearance/Space `go test -race`：通过。
- `make architecture-check`：通过，后端 allowlist 为 0。
- `make contracts-check`：通过，运行时启动确认 148 条路由。

## 回滚方式

Manager Facade 保持原方法签名，可回滚单个服务委托实现；禁止把锁和插件状态重新放回 Manager。Appearance 保留原服务和目录，回滚 Facade 不需要迁移资源数据。

## 已知限制

Gin 注册继续集中在 HTTP Transport Adapter，而不是让领域 Module 直接依赖 Gin。这是有意的边界选择；Route Registry 通过真实 Handler 所属模块记录 owner，并在启动时检查 Gin/Registry 数量一致。
