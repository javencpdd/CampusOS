# v0.8.5-dev：A5 Moderation Core 完整迁移

> 阶段状态：已验收  
> 完成日期：2026-07-13  
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划v8/00-v8版本计划书.md)

## 阶段目标

将版主的权限策略、板块作用域、服务端数据完整性校验和审计迁入始终启用的 Moderation Core；Moderation 不再直接引用 Identity 或 Community 的具体 Repository、Service 或 Handler。

## 实际完成内容

- Identity 新增公开 `ModerationPolicy` Port 和 DTO，封装 scoped authorization、版主范围读取与分类范围替换；不泄露 Identity Repository 或角色模型。
- Community 新增 `ModerationGateway` Port，封装板块/帖子/回复读取、置顶、锁定和管理员删除操作，并把底层未找到错误映射为公开错误。
- Moderation Service 改为只依赖上述两个公开 Port 与 `AuditStore`，不再导入 Community Repository/Service 或 Identity Service。
- 新增 Moderation Profile Adapter，PG 使用原有 `audit_logs`，Memory 使用同一内存审计实现。
- 新增 `core.moderation` Module，在 Profile Adapter、Identity Policy 和 Community Gateway 都就绪后组装 Service/Handler；Server 不再创建 Moderation Service、Handler 或 AuditStore。
- EventBus、Identity、Community 和 Moderation 的 Module Register/Start 顺序均由依赖图保证，Community Gateway 在 Register 阶段发布、在 Community Start 后才执行实际命令。
- Handler 改用公开 Identity/Community 错误，保持用户不存在、板块/帖子/回复不存在、范围无效、操作关闭和跨区拒绝的 HTTP 语义。
- 删除 Moderation 的 6 条跨具体实现 allowlist 边，遗留集合降为 4 个来源、6 条边。

## 架构变化

Moderation 已从可卸载业务插件的运行时实现转为 Core Module。治理范围、权限校验和审计始终装配；`allow_pin`、`allow_lock`、`allow_delete_post` 只是动作开关，不能移除服务端范围或审计检查。Identity 与 Community 分别通过显式 Port 提供必要的最小能力。

## 兼容和迁移处理

- 原有 `/moderation/*`、`/moderation/admin/*`、版主角色范围、审计记录、置顶/锁定/删除行为保持兼容。
- `category-moderation` Manifest 的旧配置目前通过 `LegacySettings` 作为只读兼容输入注入 Module；它不再决定 Moderation Core 是否存在。
- A7 的 Feature Config Store 将把动作开关迁移为唯一写入权威，并让旧 Plugin API 成为投影。A5 不修改现有表、migration、角色数据或审计数据。
- 未更改普通管理员权限、跨区拒绝、安全范围校验或错误包络。

## 回滚方式

在 A14 前可恢复旧 Server 构造与旧 Moderation Service 入参；没有 migration 或用户数据变化。回滚不能移除现有服务端范围、权限或审计检查。

## 已知限制

- 动作开关尚通过旧插件配置兼容读入，A7 Feature Store 完成前不应将它描述为新的系统配置表。
- Moderation 路由仍由 `setupRoutes` 静态注册，Route Registry 迁移属于 A11。
- RichText、MCP-like、Host API 和 Space 的其余 6 条具体依赖仍在 allowlist 中，各自有后续迁移阶段。
