# v0.8.17-dev：Feature 与 Moderation 权威源纠偏

> 阶段状态：已完成，已验收  
> 更新日期：2026-07-13  
> 性质：A16 后真实性审查 R1

## 阶段目标

重新核验 Built-in Feature 和 Moderation 的实际运行路径，确保 Feature Store 是唯一可写权威源，Moderation 安全核心不会随旧 builtin plugin 生命周期被关闭。

## 实际完成内容

- 新增权威 Feature Registry 构造方式；旧 builtin 状态只允许在首次启动时幂等播种，不能持续覆盖 Feature Store。
- 修复 `restart` Feature 的启动语义：进程启动时将已保存的 desired 状态应用为 effective 状态并清除 pending。
- 建立 `core.feature-registry` Module，统一登记 `moderation`、Personal Space、RichText、Schedule 和 Appearance。
- Moderation 改为 `always-on` Core，安全策略、板块作用域、审计和完整性始终生效；`allow_pin`、`allow_lock`、`allow_delete_post` 继续可配置。
- 旧 `/plugins` builtin 接口只投影 Feature 状态和配置；Core/Built-in 禁止普通卸载与重载。
- Admin 分离“外部插件”和“内置功能”，版主管理不再显示插件启停语义。

## 主要修改目录和文件

- `internal/platform/feature/registry.go`
- `internal/server/platform_modules.go`
- `internal/moderation/`
- `internal/plugin/handler.go`
- `internal/plugin/runtime_http.go`
- `admin/src/modules/features/`
- `admin/src/modules/moderation/`

## 架构变化

权威写入方向固定为：Admin/旧 Plugin compatibility API -> Feature Registry -> Feature Store。Plugin Manager 不再决定 Built-in Feature 的 effective 状态。Moderation Core 始终启动，配置只控制允许的治理动作。

## 兼容与迁移

保留旧 builtin Manifest、插件名称和 `/plugins/:name/*` URL。首次遇到空 Feature Store 时可从旧插件状态播种；已有 Feature 状态和配置不会被覆盖。停用 Feature 不删除表、文件或用户数据。

## 测试与构建结果

- `go test ./internal/platform/feature ./internal/moderation ./internal/plugin ./internal/server -count=1`：通过。
- `go test -race ./internal/platform/feature ./internal/plugin -count=1`：通过。
- Admin TypeScript 与生产构建：通过。
- 全量 Go 测试与架构检查：通过。

## 回滚方式

代码可回滚到旧兼容投影，但不得回滚数据库中的 Feature 状态表或恢复 Plugin Manager 持续覆盖 Feature Store。旧 Manifest 和 API 未删除，无需数据回滚。

## 已知限制

独立的 `/features` 公共管理 API 尚未引入；v0.8 继续通过旧 `/plugins` URL 提供单向兼容投影，以保持 Admin 和第三方调用兼容。
