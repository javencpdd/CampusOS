# v0.8.6-dev：A6 User Storage Core 完整迁移

> 阶段状态：已验收  
> 完成日期：2026-07-13  
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划v0.8/00-v0.8版本计划书.md)

## 阶段目标

将用户目录、默认 10 MiB 配额、安全路径、标准文件分类和本地 Provider 的所有权收敛到 User Storage Core，并使 Server 不再构造 User Storage 或 Plugin Catalog 业务 Port。

## 实际完成内容

- 新增 `core.user-storage` Module，负责初始化 Local Provider 并发布 `storage.user`、`storage.quota`、`storage.safe-path`、`storage.provider` 四个稳定 Port。
- 复用既有 `LocalAdapter` 的安全路径、配额、分类目录和 legacy root 归一化逻辑，保持 `data/personal-space/<user-id>/{file,img,excel,word,pdf}` 以及默认 10 MiB 的行为。
- 新增 User Storage Module 测试，覆盖 Port 发布、布局创建和 Provider 初始化。
- Plugin Platform Module 在自身 Register 阶段发布 `plugin.catalog`；删除 Server 的 `registerBusinessPorts` 和 `module_assembly.go`，不再由 Server 创建 LocalAdapter、Storage Port 或 Plugin Catalog Adapter。
- `bootstrap.go` 以真实 User Storage Module 替换 `core.user-storage` marker。

## 架构变化

User Storage 现在是实际运行的 Core Module，Local Provider 与安全路径不再属于 Server 兼容组装。Plugin Catalog 同样由其所有者 Plugin Platform 发布。Space、RichText 和 Schedule 仍保留各自的旧配置兼容 Adapter，但下一阶段会改为注入这些统一 Storage Port，而不是重复新建 LocalAdapter。

## 兼容和迁移处理

- 未改变文件根目录、URL、头像保留策略、富文本图片目录、课表 JSON 目录、配额默认值或既有用户文件。
- 没有文件搬迁、migration、配置删除或双写；`NormalizeRoot` 与各 Feature 旧配置兼容逻辑继续存在。
- 自定义旧 `file_root` 仍由 Space/RichText/Schedule compatibility adapter 读取，直到 A7 统一注入完成。

## 回滚方式

在 A14 前可恢复 `registerBusinessPorts` 与旧 `module_assembly.go` 的 Port 组装。没有数据库迁移或文件移动，回滚不需要恢复用户数据。

## 已知限制

- Feature 级 LocalFileStore、LocalAssetStore 和 Schedule Service 仍有 legacy config constructor；A7 将改为通过 `storage.user`/`storage.quota`/`storage.safe-path` 注入，避免重复 Provider。
- 云存储 Provider、远程对象存储和跨用户迁移不属于 v0.8 新产品范围。
- Storage 路由仍由 Space/RichText Handler 公开，A11 之前不改变路径。

## 下一阶段任务

A7 将迁移 Personal Space、Controlled RichText 与 Personal Schedule：建立 Feature Store，保持数据保留和启停语义，并把三个 Feature 的文件访问切换到 User Storage Port。
