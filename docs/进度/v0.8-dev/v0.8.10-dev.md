# v0.8.10-dev：A10 Integration Module 迁移

> 阶段状态：已完成，已验收
> 更新日期：2026-07-13
> 对应计划：[v0.8 现有功能架构收敛计划书](../../项目计划v0.8/00-v0.8版本计划书.md)

## 阶段目标

将既有 AI、Webhook、MCP-like、Message、平台日志与 Integration Overview 从 Server 业务装配迁入 Module Registry；让 PostgreSQL/Memory 差异只存在于 Profile Adapter，Overview 在运行时只读取 Summary Port。

## 实际完成内容

- 新增 `integration.ai`、`integration.webhook`、`integration.mcp`、`integration.message`、`integration.platform-log` 与 `integration.overview` Module。
- AI、Webhook、MCP、Message 分别拥有 PostgreSQL/Memory Profile Adapter；Webhook 在 Module Start 中注册事件订阅。
- MCP Module 只读取 Community `CategoryCatalog` 和 `ContentGateway` Port，不访问 Community Repository。
- Personal Space Module 显式发布只读服务 Port，Integration Overview 在依赖就绪后读取各集成 Port。
- Integration Overview 新增 `SummaryPort`；生产路径由 Module 建立 Summary Port 聚合，旧 Handler 直连字段只保留为兼容构造路径。
- `internal/server/application.go` 不再创建 AI、Webhook、MCP、Message、Platform Log 或 Integration Overview 的 Service/Handler；PG/Memory 分支不再重复构造这些对象。
- Plugin Platform Module 现在拥有 Host API Server 和 Plugin HTTP Handler 的启动、停止与依赖装配；Server 不再创建 Host API Server。

## 主要修改目录和文件

- `internal/{ai,webhook,mcp,message,platformlog}/module.go`
- `internal/{ai,webhook,mcp,message}/profile.go`
- `internal/integration/{module.go,handler.go}`
- `internal/space/module.go`
- `internal/server/{bootstrap.go,platform_modules.go,application.go,server.go}`

## 架构变化

模块启动顺序由 Registry 的依赖图决定，Profile 负责绑定数据库或内存 Adapter，业务 Module 负责 Service、Handler、事件订阅与 Health。Integration Overview 只通过 `SummaryPort` 获取状态卡片，避免 Server 聚合跨领域 Service。

## 兼容和迁移处理

- AI、Webhook、MCP、Message、日志、Metrics、Integration Overview 的 API 路径、响应格式和权限没有变化。
- PostgreSQL 不可用时，同一组 Module 使用 Memory Adapter，不再进入单独的业务装配分支。
- Host API v1 的地址、认证、权限和 SQLite KV 存储保持兼容；生命周期归 Plugin Platform Module 管理。

## 回滚方式

应用代码可回退到 A9；Profile Adapter、数据表、消息、Webhook 投递记录、MCP 审计和日志文件不删除。回滚不得恢复 MCP 对 Community Repository 的直接依赖。

## 已知限制

- HTTP 路由的实际 Gin 注册仍由迁移期 `application.go` 聚合，A11 将把它收敛到 Route Registry 与模块 Route Contributor。
- Integration Handler 的直连构造器仅保留兼容测试用途；新 Module 路径使用 Summary Port。
