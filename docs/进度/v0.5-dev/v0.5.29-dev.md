# CampusOS v0.5.29-dev 进度说明

> 日期：2026-07-10
> 状态：已完成

## 1. 本次目标

为插件建立系统级和用户级生命周期模型：系统级插件启用或停用后只在 API 服务重启时生效；用户级插件可由管理员手动加载、重载和覆盖更新，无需重启 API 服务，并在管理端明确展示差异。

## 2. 完成内容

| 项目 | 说明 |
| --- | --- |
| Manifest 分级 | `plugin.yaml` 新增 `scope: system|user`。`runtime: builtin` 未声明时兼容为系统级，Wasm/gRPC 未声明时兼容为用户级。 |
| 系统级生命周期 | 管理端启用或禁用系统级插件仅保存目标状态；当前进程继续保留原状态，API 重启后才真正加载或停止。接口返回 `pending_restart`。 |
| 用户级生命周期 | 用户级插件的启用、禁用即时调用 Runtime；新增重载接口，可停止并重新启动当前用户级插件。 |
| 热更新 | 覆盖导入已加载的用户级插件时，Manager 停止旧 Runtime、重新安装新包并自动加载新 Runtime。 |
| 系统级保护 | 网页预检和导入拒绝 `scope: system` 的插件包；系统级插件不能通过运行中的管理接口重载或卸载。 |
| 管理端适配 | 插件列表新增级别、生效方式和待重启状态；用户级插件提供“加载/重载”，系统级插件显示“随服务部署”。 |
| 默认分类 | `personal-space`、`homepage-customizer`、`controlled-richtext-article`、`personal-schedule` 标记为系统级；`hello-plugin`、`hello-wasm` 标记为用户级示例。 |

## 5. 后续任务

1. “用户级”当前表示可热加载的扩展级别，尚未实现普通用户可安装的个人插件市场、每用户权限隔离和每用户插件数据目录。
2. 用户级插件覆盖更新目前不保留旧包的可回滚副本；后续可在插件包治理中增加版本快照、健康检查和自动回滚。
3. 系统级插件的配置字段是否也需要按重启生效，应逐个 Runtime 和内置服务评估，当前本次只约束启用/禁用生命周期。
