# CampusOS v0.5.32-dev 进度说明

> 日期：2026-07-10
> 状态：已完成

## 1. 本次目标

在管理后台提供一个能直观说明当前数据结构的页面：用 ER 风格的逻辑关系图展示 PostgreSQL 数据表、关键字段和职责；同时说明个人空间、插件、风格包、配置和日志等不在数据库中的数据或文件位置。

## 2. 完成内容

| 项目 | 说明 |
| --- | --- |
| 管理端入口 | 新增 `/architecture` 路由、左侧“数据架构”菜单和仪表盘快捷入口。 |
| 数据库关系标签页 | 提供按领域筛选的 ER 逻辑关系图、表目录和可点击表详情，覆盖身份、社区、个人空间/内容、插件和集成表。 |
| 表职责说明 | 每张表展示用途、关键字段、对应 migration 和关联提示，便于了解其业务责任。 |
| 关系边界 | 明确当前 migration 没有定义 PostgreSQL foreign key；图中连线依据 `user_id`、`thread_id`、`plugin_name` 等字段和服务层约束归纳。 |
| 数据与文件标签页 | 以架构流和目录卡片展示 PostgreSQL、`data/personal-space`、`data/plugins`、`data/plugin_data`、全局本地数据与 `.campusos/logs` 的职责。 |
| 迁移与维护标签页 | 汇总 `000001` 至 `000013` 的关键 schema/种子变更，并列出迁移状态、应用迁移和备份边界。 |
| 隐私与安全 | 页面只使用版本控制中的 migration 和目录约定，不读取真实表记录、本地文件内容、密钥或 `.env`。 |

## 5. 后续任务

1. 当前页面是由仓库 migration 和目录约定生成的静态架构视图；如果后续要显示真实表行数、索引大小或 migration 执行状态，应增加受管理员权限保护的只读运维 API。
2. 若数据库开始引入 PostgreSQL foreign key，应同步更新关系图中的“逻辑关联”标识，并加入 schema 解析或契约测试，避免人工维护漂移。
3. v0.6 的完整 OpenAPI 与部署恢复演练可继续沿用该页面作为开发者可视化入口。
