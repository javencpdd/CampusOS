# CampusOS v0.7.2-dev 进度说明

> 日期：2026-07-12
>
> 阶段：A1 Module Kernel
>
> 状态：已验收

## 1. 阶段目标

按修订后的 v0.7 合同核验并完善 Module Kernel，使简单模块不必实现无意义的 Start、Stop 和 Health 空方法。

## 2. 实际完成内容

- `Module` 只保留稳定 ID、依赖声明和 `Register`。
- 新增可选 `Starter`、`Stopper`、`HealthReporter` 接口。
- Registry 对实现 `Starter` 的模块调用启动；无 Starter 的模块注册后直接进入 running。
- 逆序停止和启动失败回滚只调用实际实现的 Stopper；无 Stopper 模块仍正确结束状态。
- 无 HealthReporter 模块统一报告 `unknown`，不需要伪造健康实现。
- 保留缺失依赖、禁用依赖、循环依赖、确定拓扑顺序、Core 禁用拒绝和重复 Port 拒绝规则。

## 3. 主要修改目录和文件

- `internal/platform/module/module.go`
- `internal/platform/module/module_test.go`
- `docs/architecture/当前架构概览.md`
- `README.md`、`docs/README.md`、`docs-site/`、onboarding 状态文档

## 4. 架构变化

生命周期由 Module 强制方法改为能力接口。现有 EventBus 与 Plugin Platform Adapter 继续实现完整生命周期，不改变实际启动和停止顺序。External Plugin 仍不进入 Module Registry，也不会获得 AppContext。

## 5. 兼容和迁移处理

Registry 的 Add/RegisterAll/StartAll/StopAll/Snapshots 调用方式不变；已有完整 Module 无需修改。HTTP 路由、OpenAPI、migration、Manifest 和持久化目录均未变化。

## 7. 回滚方式

可将可选接口重新并回 Module，并保留现有 Adapter 的 Start/Stop/Health 方法。该回滚不涉及 API、数据库和数据文件；但会重新要求所有新模块实现空生命周期方法，因此只作为代码级应急回滚。
