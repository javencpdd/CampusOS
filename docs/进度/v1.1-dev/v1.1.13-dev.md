# CampusOS v1.1.13-dev：PDF Viewer 授权恢复与个人文档预览

> 更新时间：2026-09-15（Asia/Shanghai）
> 状态：实现、Docker 热加载与主要自动化回归已完成；未提交、未推送；不是 v1.1 Final 发布声明。

## 问题与根因

管理员和用户端对 `builtin.pdf-viewer` 授权时出现“当前插件版本没有声明该能力”，根因是旧运行库曾在同一
语义版本下记录了另一份 Manifest 摘要/能力指纹。插件版本表将该变化视为不可变版本冲突并隔离，因此不能再把
旧记录当成当前声明。

“我的文档”原下载入口使用浏览器直接打开 API URL，无法附带 Bearer Token，故服务端正确返回
`missing authorization header`。该入口也未接入 PDF Viewer 的受控 UI Invocation，所以 PDF 被误判为不可编辑。

## 实现

1. 将第一方受管 PDF Viewer 的 Manifest 明确升级为 `1.1.2-dev`，声明文章附件预览、个人文件读取和受控 UI
   Surface 三项能力。只对已知的“同版本声明变化”自动隔离记录执行窄范围恢复；不会覆盖管理员主动停用、拒绝或
   其他运行错误。
2. 新增 `000011_v1_1_personal_document_pdf_preview`：在短期 `plugin_ui_invocations` 中加入
   `personal_document_id`、外键、三类上下文互斥检查及部分索引。它不迁移或重写个人文档历史数据；DOWN 只删除
   到期前的文档预览上下文，不删除文档、版本或对象字节。
3. 将个人文档 PDF 预览接入既有第一方受管插件：服务端每次读取都重新执行 owner-only 文档读取与
   `personal_space_file.self.read`、`plugin_ui.surface.open` 授权；上下文只保存文档 ID，绝不向前端交付
   文件系统路径、对象 ID、长期 URL 或其他人的资产引用。
4. “我的文档”中的 PDF 改为“预览”入口；下载改为带登录凭据的 API Blob 请求，再由浏览器创建临时下载链接，
   因而保留服务端个人空间所有权校验。非 PDF 不被伪装为可在线编辑。
5. `database-check.sh` 新增与 migration 执行器一致的 `PSQL_MODE=auto|host|docker`；Docker/Git Bash/WSL
   可显式在 Compose PostgreSQL 容器内执行检查，避免误连宿主 `psql`。

## 仍需人工验收

本次没有伪造管理员登录态下的浏览器点击证据。请在现有 Docker 开发环境中刷新 3000 与 3001 页面（必要时
`Ctrl+F5`）：

1. 管理端打开 PDF Viewer 授权页，应显示 `1.1.2-dev` 和三项已声明能力，不再出现“没有声明该能力”。
2. 用户端在“我的文档”点击 PDF 的“预览”；因版本已升级，首次预览会按安全模型重新征求该用户的 Consent。
3. 确认后应打开受控 PDF Viewer；点击“下载”应下载文件，而非跳到缺少 Authorization Header 的原始 API 页面。
4. 使用另一用户登录验证：不能访问任一他人的个人文档；公开图文文章附件仍仅能按文章可见性预览/下载。

本次均为容器内源码热加载，已运行的开发栈无需 `rebuild`。只有以后重新启动整套服务时才使用
`./scripts/docker-dev.sh up` 或 `./scripts/docker-dev.ps1 up`；修改 Dockerfile、依赖、Compose build 配置或
容器入口脚本时才使用 `rebuild`。
