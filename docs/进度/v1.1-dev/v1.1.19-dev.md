## 2. 完成内容

1. 个人资产列表增加 owner/status 绑定的 keyset 游标，Web 附件选择器和个人空间支持加载下一页；
   修复 PostgreSQL `id::text` 投影导致 ORDER BY 按字符串排序、翻页重复的问题。
2. 提取 `internal/platform/pluginui` 通用宿主上下文服务，接通文章附件、个人资产、个人文档三类资源；
   校验已安装插件、Surface/Presentation、Action/Permission、业务 ACL、Capability/Grant/Consent。
   复用既有 `context_digest` 绑定插件授权版本及对象版本/哈希，未新增表或 migration。
3. 声明式 `open-surface` 使用宿主解析的资源上下文，不信任插件 action body 自行指定资源；
   插件停止或观察到版本变化时卸载界面，关闭后恢复焦点。
4. Viewer 新增认证下载降级接口。预览过期/插件停用不阻断普通业务下载；
   仍检查 Invocation 用户与文章阅读权限、owner、附件绑定和资产状态，不建立公开下载旁路。
5. 实际 PostgreSQL 测试发现预览上下文 FK 阻止附件移除；改为锁定绑定行、删除对应短期上下文、删除绑定的原子事务。
6. Invocation 过期超过 24 小时后每分钟最多清理 500 条，保留短期下载定位窗口；只删除上下文元数据，不删除资产或文件。
7. 内容流增加每用户 20 路/全实例 64 路并发、每用户每分钟 1200 次及 2 分钟写期限，返回中文 429 和具体限制。
   此限制为单 API 实例内实现，不宣称分布式限流。
8. 管理端显示 UI 合同版本、Surface/Presentation、最近运行错误；只返回声明摘要，不返回 schema 或 Secret。
9. 防止摘要校验后再次打开资源导致读取未经校验的新文档版本：直接交付已校验流，拒绝时关闭流；
   补充 MemoryStore 事务快照对内部摘要的保存，避免回滚丢失摘要。
10. 同步正式计划、架构、系统设计 Help、官方 UI v2 文档、生成 API 合同与文档入口；
    文档链接检查纳入 v1 计划和 v1.1 进度目录。

## 4. 验证结果

下列 Docker 命令均从仓库根运行。没有输出 `.env.dev.local` 内容或数据库密码。

### 4.1 Go 与真实数据库

- Windows：设置工作区 `GOCACHE` 后 `go test ./... -count=1` 通过；最后的同一流修复后相关 richtext/pluginui/server 包再次通过。
- 最终 Docker 全量：`docker compose --env-file deploy/docker/.env.dev.local -f compose.dev.yml exec -T api go test ./... -count=1` 通过。
- Docker 竞态检测：同一命令前缀后执行 `api go test -race ./internal/modules/features/richtext ./internal/platform/pluginui -count=1`，两包通过。
- `go run ./cmd/campusos-contracts --write` 后 `go run ./cmd/campusos-contracts --check` 通过全部 10 项产物。
- 实际 PostgreSQL 集成命令：

```powershell
docker compose --env-file deploy/docker/.env.dev.local -f compose.dev.yml exec -T -e CAMPUSOS_V11_PG_TEST=1 api go test ./internal/modules/features/richtext -run TestPostgresV11AttachmentContracts -count=1 -v
```

最终通过（2.32 秒）：25 路并发最多绑定 10 项；4 个 20 MiB 附件最多绑定 2 项；同资产并发只绑定一次；
摘要持久化；预览后可移除绑定且上下文失效；240 项多页无重复/漏项；过期清理保留最近下载窗口。
测试通过显式 opt-in 创建随机隔离库，结束仅删除该测试库；普通 `go test` 会跳过此项，不能冒充已跑数据库。

基线演练也已通过：设置 `POSTGRES_CONTAINER=campusos-dev-postgres-1`、
`CAMPUSOS_V1_DRILL_DB=campusos_v11_audit_<随机值>`，使用 Git Bash 执行
`scripts/test-v1-database-baseline.sh`；覆盖 reset/checksum/up-down-up，90 张表、78 个 Permission。
仅清理演练数据库，开发库未重置。这不等于生产备份恢复成功。

Range 测试使用 20 个并发请求与各 20 MiB 的逻辑流，每个只读取指定的 64 KiB；
写失败、拒绝、失效时关闭流并释放槽位；未测量真实目标主机的 RSS/p95 或真实慢客户端。
