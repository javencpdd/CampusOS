# CampusOS v1.1.15-dev 插件存储边界实施记录

> 日期：2026-09-15  
> 更新时间：2026-09-15（Asia/Shanghai）  
> 状态：STORE-01、STORE-03、STORE-05 已完成；STORE-02、STORE-04 保留为明确后续项；未提交、未推送。

## 1. 本次目标

落实 v1.1 插件存储约束中可由当前平台代码闭合的边界：外部 process/grpc 插件不继承 API 进程机密环境；
SQLite/config 使用固定私有布局；PDF Viewer 的最近阅读页不再写入浏览器持久存储，而通过既有平台通用记录保存。

## 2. 完成内容

1. `GRPCRuntime` 使用环境变量白名单启动子进程，仅保留必要启动变量和显式传入的短期 Host Token、私有数据目录、
   config 路径；阻断 `DATABASE_URL`、PostgreSQL、JWT、SMTP、平台 `CAMPUSOS_*` 等宿主敏感变量继承。
2. 新增 `internal/plugin.StorageLayout`：安全生成 `data/plugin_data/<plugin-name>/`、`plugin.db`、`config.json`，
   支持带点的合法插件名称，拒绝目录穿越与 config 符号链接；JSON config 限制 256 KiB 并原子替换。
3. `SQLiteKVStore` 复用同一布局并以私有目录/文件权限创建 SQLite；这不是平台 PostgreSQL，也不向插件暴露 SQL。
4. `builtin.pdf-viewer` 升级为 `1.1.3-dev`，声明 `reading_positions` owner=user 的受管集合和阅读记录读/写 Capability。
   管理员默认 Grant 仍可撤销，用户须单独 Consent。
5. PDF Viewer 用资源类型与当前 storage object ID 生成受限 record key；阅读页通过既有 `/plugin-market/.../records/...`
   受控接口读写 `plugin_records`。拒绝、撤销、冲突或网络失败时仅保留当前会话，不回退到 `localStorage`、IndexedDB
   或持久化 PDF 缓存。
6. 没有新增或执行 migration。`000011` 仍是平台对 `plugin_ui_invocations` 的既有表扩展，不属于插件私有表。
