# CampusOS v1.1.12-dev：PDF Viewer 受管插件与双入口预览修正

> 更新时间：2026-09-15（Asia/Shanghai）
> 状态：实现与本地回归完成；未提交、未推送；不是 v1.1 Final 发布声明。

## 本次问题与结论

针对“插件中心/管理端看不到 PDF Viewer、个人空间 PDF 不能预览、公开文章读者不能预览附件 PDF”的问题，
将 PDF Viewer 落实为 `builtin.pdf-viewer` 第一方受管插件。渲染仍由 Web 客户端内的 PDF.js 执行，插件平台只负责
Manifest、生命周期、授权决策与受控 UI 上下文；不会下载或执行第三方动态前端包。

## 实现内容

1. 新增 `builtin` Runtime 及第一方 PDF Viewer v3 Manifest。该 Manifest 是 `builtin.pdf-viewer.preview` 的唯一
   UI Surface/Route 来源；旧 Feature 描述符仅保留兼容性总开关身份，不再重复声明 UI。
2. 将 `article_attachment.self.preview`、`personal_space_file.self.read` 和 `plugin_ui.surface.open` 纳入 Manifest。
   启动时只为没有既存策略记录的能力写入可撤销管理员 Grant，不覆盖管理员的拒绝或撤销决定。
3. 在 RichText 创建与读取 PDF Invocation 两处接入 AuthorizationService。文章附件先按文章可见性验证，随后要求
   当前读者的 Consent；个人空间附件始终要求当前用户是 Asset owner。停用插件、撤销 Grant/Consent、文章下架、
   资产隔离或 Invocation 过期都会阻断后续读取。
4. 用户端首次点击预览会说明用途并请求相应 Consent；用户可以在“插件中心 → PDF 文档预览 → 查看并授权”查看或撤销。
   个人空间和文章附件使用同一受控 Surface，支持 modal、drawer、fullscreen、new-tab。
5. 用户插件中心、管理员插件运行管理和管理员插件中心均显示“第一方受管”标识。第一方插件不可导入、导出、卸载；
   管理员可查看授权并启停它。
6. PDF Viewer 和 PDF.js Worker 继续随 Web 构建为内容哈希静态资源；生产 Nginx 对 `/assets/` 使用一年 immutable 缓存，
   但受保护 PDF 内容保持 `/api/` 私有响应，未写入持久插件缓存。
