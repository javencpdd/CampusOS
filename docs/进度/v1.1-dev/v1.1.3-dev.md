## 2. 已完成实现

### 2.1 附件生命周期与恢复

- 新增 `000009_v1_1_asset_governance`：为 `user_assets` 增加 `purging` 状态，建立追加式
  `asset_lifecycle_audits`，并新增 `personal_space.asset.read_audit` 与
  `personal_space.asset.manage` 两个全局管理员权限。
- 用户图文编辑页的“我的附件与回收站”可切换可用附件/回收站；已被文章引用的附件不能移入回收站，恢复后才可
  再次绑定。
- 管理端 `/asset-governance` 只显示状态/字节/操作计数和过期 Invocation 汇总，不枚举文件名、用户、Object Key、
  路径或内容；管理员必须知道附件 ID、填写原因，才能隔离、恢复、预检或永久清除。
- 清除使用 `trashed|quarantined -> purging -> deleted` 两阶段状态机，先使对象不可读，再删除 Object Port 字节并
  收口元数据。对象已经删除但元数据尚未完成时可安全重试；对象删除失败且由本次动作发起时恢复到先前不可读状态。
- 引用保护同时计算 `richtext_article_attachments` 与已切换的 `richtext_article_assets`，避免正文图片或附件仍被
  引用时误清除。

## 4. 仍是 Final 发布门禁的事项

下列事项不属于可由当前工作树伪造的仓库实现，完成前不得把版本标为 `v1.1 Final`：

1. 目标 Linux 环境的真实浏览器矩阵：PC/移动端、modal/drawer/fullscreen/new-tab、UI v1 回归、停用/撤销/过期
   与安全下载降级。
2. 目标容量环境的 20 路 PDF Range、慢客户端、取消请求、RSS/延迟和告警阈值报告。
3. PostgreSQL 与 Object payload 成套备份恢复演练，以及 reconcile 报告后的管理员审批 `--apply` 记录。
4. 产品明确排期之外的 P2：MP3/MP4 在线播放、Office 在线转换、跨用户分享、全文/OCR、病毒扫描/DLP、全部个人资产
   统一，以及第三方 UI Bundle 的独立 Origin/sandbox iframe/CSP/签名/Bridge。

## 5. 运行与回滚边界

- 生产故障优先停用 `pdf-viewer` 或附件入口、保留有权用户的认证下载，并使用前向修复；不得执行 `000006`–`000009`
  的 destructive down 删除真实用户内容或生命周期审计。
- 管理端清除只能在明确附件 ID、原因和二次确认一致时执行。清除失败会保持不可访问或恢复先前不可读状态；先运行
  Core User Storage 的只读 reconcile，再根据正式 Runbook 处理差异。
- 变更 Go、migration、Vue、PDF.js、Dockerfile 或 Compose 入口后，Docker 开发环境执行
  `./scripts/docker-dev.sh rebuild && ./scripts/docker-dev.sh up`；Windows 为
  `.\scripts\docker-dev.ps1 rebuild` 再 `.\scripts\docker-dev.ps1 up`。仅改 Vue 页面时可使用已有开发容器热加载。
