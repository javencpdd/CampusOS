## 本阶段完成

### R11-03（包构建、签名、安装）

- `internal/plugin/v4/package.go` 现在可以把已构建的 `dist/user`、`dist/admin`、Manifest、配置定义、许可证与说明复制为干净 release 目录，并生成确定性 `tar.gz`、`checksums.json`。
- Ed25519 detached signature 可生成和校验；要求签名时拒绝无签名或不受信任密钥。
- 解包始终在 `.staging` 内进行，检查相对路径、符号链接、普通文件、数量和总大小，再原子移动到 `.installed/<key>/<version>-<digest>`；同一产物重复安装是幂等的。
- `campusosctl plugin v4 validate|stage|pack|sign|install` 提供开发与 CI 的显式流程，不会执行包内脚本，也不会把源码或 `node_modules` 带进发布包。

### R11-02（隔离界面原型，已完成插件侧）

- `web/src/campus-ui/IsolatedPluginFrame.vue` 和 `isolatedPluginBridge.ts` 提供跨 Origin iframe、精确 `origin/source`、随机 challenge、MessageChannel、请求大小与 Range 上限校验。
- `plugins/campusos.pdf-viewer/frontend` 已独立于 `web/src` 构建，真实接入 `pdfjs-dist` 的 Worker 与 `PDFDataRangeTransport`；PDF 字节只通过宿主 `resource.readRange`，不使用 URL、Cookie、JWT 或 `fetch`。
- 插件包自身的 `pnpm-lock.yaml` 使用 Docker 开发镜像中的 pnpm 8.15.9；独立 `vite build` 已通过。

## 尚未完成与边界

- 隔离 iframe 还没有接入 Web/Admin 的动态运行时清单；当前宿主仍使用旧 `trusted-module` PDF 入口。
- API 尚未提供通用 Bridge Broker、插件静态 Origin 网关、`resource.describe/readRange` 的 v4 会话处理，因此本阶段不宣称浏览器端到端预览完成。
- 用户配置 CAS/快照/恢复实现已落在 `internal/plugin/v4/user_config.go`，但尚未接入“用户添加插件”HTTP 生命周期；R11-07 仍为部分完成。
- Docker 的真实容器验证需先启动 Docker Desktop，并修复 Docker Hub 认证链路；本地编译与临时发布包验证不能替代该证据。
