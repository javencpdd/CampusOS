## 1. 问题与根因

1. 用户端 `GET /plugin-market` 只返回 `published` 目录；`campusos.pdf-viewer` 是系统已校验的 v4 外部 release，但旧同步逻辑将其首次目录行保留为 `draft`，所以管理端能看到而 3000 用户端看不到。
2. 旧的用户“申请安装”接口只接收任意格式正确的插件名，既没有可信市场来源，也没有对市场 ID、目录签名、插件链接或来源主机进行校验。这不满足“仅允许系统白名单市场”的安全边界。

## 2. 完成内容

### 用户目录与个人添加

- 系统安装、已校验且隔离 UI 的外部 release 会同步为 `published`；已有的 `draft` PDF 投影会在下一次 API 启动同步时修复。管理员明确设为 `hidden` 仍会被保留，作为唯一的下架手段。
- 用户端插件中心明确区分“已安装插件”和“从可信市场申请”。已发布的 `campusos.pdf-viewer` 会显示在已安装目录，用户可点击“添加到我的插件”，再从精细授权逐项同意个人数据能力。
- 用户添加声明 `configuration.user` 的 v4 插件时，宿主幂等创建 `data/personal-space/<decimal-user-id>/plugins/<key>/config/{user.json,meta.json}`；该路径不交给 iframe、插件或用户输入决定。

### 可信市场白名单与申请

- 增加平台拥有的 `plugin_market_sources` 与 `000003_v1_1_trusted_market_sources`。管理员在 3001 的“用户目录与授权”维护市场 ID、显示名称、HTTPS 目录地址、Ed25519 公钥及启用状态。
- 用户端只会列出 `enabled` 来源。没有来源时会明确提示不能申请，且不提供任意 URL/包地址输入入口。
- 检索时仅请求管理员配置的 HTTPS URL，拒绝跳转，限制 2 MiB 响应，并要求 `X-CampusOS-Market-Signature` 对 `campusos.plugin-market/v1` JSON 做 Ed25519 验签。市场条目的详情/包 URL 必须是 HTTPS 且与市场目录同 Host。
- 用户申请只提交 `source_id + plugin_id + message`。服务端重新从已验签目录解析条目，再把来源、市场插件 ID、版本、发布者与链接快照保存到 `plugin_install_requests`。用户提交的任意链接不会被存储或请求。
- 管理端请求表显示来源与市场条目快照；批准的含义仅是同意进入安装评估。它不会下载、安装或启动包；管理员仍需在“外部插件运行管理”执行预检查、验签和导入。
- 有来源型申请时外键限制删除市场来源；管理员应停用来源以保留审计证据。

### 文档、数据模型与合同

- 更新 Admin `/architecture` 的 000003、`plugin_market_sources`、申请快照字段与 FK 连线；当前投影为 91 张 public 表。
- 更新 `migrations/README.md`、数据库操作 Help、当前架构、插件架构、存储边界与官方插件文档；同步说明白名单、验签、无来源时的行为和不自动安装边界。
- 重新生成 `migrations/er/current/` 下的 PNG、SVG 与中文 ER 说明，当前解析 89 张业务表和 106 条物理外键。
- 更新 HTTP 路由/OpenAPI 合同：用户来源检索/申请接口，以及管理员来源管理接口；移除用户可调用的旧 `POST /plugin-market/:name/request` 路由。

## 3. 关键接口

| 受众 | 接口 | 作用 |
| --- | --- | --- |
| 已登录用户 | `GET /api/v1/plugin-market` | 查看已发布、当前已安装的外部插件目录 |
| 已登录用户 | `GET /api/v1/plugin-market/sources` | 查看已启用可信市场 |
| 已登录用户 | `GET /api/v1/plugin-market/sources/:source_id/plugins?q=` | 检索已验签目录 |
| 已登录用户 | `POST /api/v1/plugin-market/requests` | 以来源 ID 和插件 ID 提交审核申请 |
| 管理员 | `GET/PUT/DELETE /api/v1/plugin-market/admin/sources...` | 查看、配置、停用或删除可信市场来源 |
