# CampusOS v1.1.4-dev 附件持久化与 PDF 预览入口修复

> 状态：已修复本机 Docker 运行时附件 API 错误；v1.1-dev 仍未宣称 `v1.1 Final`
> 更新时间：2026-09-12

## 1. 本次运行时问题

在真实 PostgreSQL Docker 环境中创建图文文章草稿并上传 PDF 附件时，`POST
/api/v1/richtext/articles/:id/attachments/upload` 曾返回 HTTP 500。API 日志给出了实际原因：
`article_content_id` 是 `bigint`，但 SQL 的参数推断将其视为 `text`。

根因位于 `PgStore.CreateAttachment`：同一参数 `$2` 既被用于 advisory lock 的文本 key，又被用于
`richtext_article_attachments.article_content_id`。PostgreSQL 因 `$2::text` 推断了参数类型；插入投影未显式
转换时，数据库拒绝将该文本参数写入 `bigint` 字段。该问题只会出现在 PostgreSQL Store，Memory Store 单测无法暴露。

## 2. 修复内容

- 将附件准入 SQL 提取为 `createAttachmentSQL`，在插入投影中明确使用
  `$1::bigint`、`$2::bigint`、`$3::bigint`，并保留查询条件中的显式类型。
- 新增 `TestCreateAttachmentSQLCastsStringIDsForBigintColumns`，防止未来修改 advisory lock 或插入 SQL 时重新
  遗失 string-ID 到 PostgreSQL `bigint` 的边界转换。
- 管理端 `builtinFeatureDefinitions` 补入 `pdf-viewer`。此前后端 `/features` 已正确注册且启用该 Built-in
  Feature，但管理端使用显式目录投影，未定义的条目不会显示；现在会以“PDF 文档预览”显示在“图文文章”下。
- `modules/features/pdf-viewer/module.yaml` 改用中文显示名称和说明；Plugin UI v2 指南补充其入口、启停行为与
  External Plugin 的区别。

## 4. 使用说明

- “PDF 文档预览”是随主程序发布的**内置功能**，不在“外部插件”安装清单中。管理员可在“扩展中心 → 内置功能”
  或“内置功能”中查看和启停。
- 普通用户须登录并打开一篇已发布、自己有权访问的图文文章；文章附件区的 PDF 卡片会提供“预览”菜单，可选弹窗、
  抽屉、全屏或新标签页。
- 图文文章编辑页的“上传附件”和“从我的附件添加”用于绑定附件。PDF、MP3/MP4、Office 和压缩包均可作为附件；
  当前仅 PDF 提供在线预览，其余类型使用受权限保护的下载。
