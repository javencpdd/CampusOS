## 1. 本次目标

修复 Docker 开发栈中 `plugin-ui` 已健康、但 API 因插件 v4 注册失败而变为 unhealthy 的问题；同时将当前架构、迁移、
Docker 和 PDF 自包含实现的说明同步到代码事实，清理已删除的宿主 PDF 前端依赖与测试。

## 2. 完成内容

1. 定位到 API 的首次错误是 PostgreSQL `chk_plugins_runtime` 拒绝 `runtime=none`。`campusos.pdf-viewer` 是无后端进程的
   UI-only v4 release，而 clean baseline 当时只允许 `builtin/grpc/process/wasm`。
2. 新增前向迁移 `000002_v1_1_ui_only_plugin_runtime`：只将受限 runtime 枚举增加 `none`。`000001` 的 checksum 保持不变；
   DOWN 会在仍有 `runtime=none` 插件时明确拒绝回滚，避免约束与记录不一致。
3. v4 Runtime、用户端动态清单、隔离 iframe、Host Bridge、PDF.js Worker 与 `plugin-ui` 静态网关继续采用 host-owned
   `resource.describe/readRange` 路径；iframe 不接收 JWT、Cookie、对象路径或数据库凭据。
4. 开发 API 的源文件扫描跳过测试夹具/运行数据中的 `data/`、`.campusos/`，避免被不同容器 UID 创建的目录反复输出
   `find: Permission denied`。这是入口脚本变更，下一次 `docker-dev.* rebuild` 才会进入运行容器。
5. 删除已经迁出的 Web PDF Viewer 旧单测，移除 Web 对 `pdfjs-dist` 的依赖；PDF.js 仅保留在
   `plugins/campusos.pdf-viewer/frontend`。保留的 Host Bridge 单测覆盖跨 Origin 握手和有界 Range 合同。
6. 更新 Admin 架构视图、ER 投影、当前架构专题、Docker 说明、插件存储/预览说明、README 与计划状态：明确
   `plugins/.installed`、3003 静态网关、`000002` 和未完成的 Admin Host/用户安装状态机等边界。
