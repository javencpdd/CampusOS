# CampusOS v1.1.2-dev 图文附件、PDF Viewer 与 Plugin UI v2 实施记录

> 状态：v1.1-dev 主功能已完成，未宣称 `v1.1 Final`  
> 更新时间：2026-09-12

## 本次完成内容

- 新增 `000006`–`000008`：最小 `user_assets`、`richtext_article_attachments`、`plugin_ui_invocations` 与 RichText 图片 Asset 关联护栏；87 张业务表、102 条物理外键的 ER 投影已重新生成到 `migrations/er/current/`，日期目录只保留审查快照。
- 图文文章支持附件上传、从自己的附件选择、显示名、稳定排序、移除和认证下载。图片仍只走封面/正文排版流程；PDF、MP3、MP4、DOC/DOCX、XLS/XLSX、ZIP/RAR 仅作为附件。
- 上传端实施单文件 20 MiB、每篇 10 个、每篇 40 MiB 总量、owner 配额、文件名、扩展名、声明 MIME 与内容签名校验；DOCX/XLSX 会继续核验 ZIP 内的 Office 必要条目，失败对象在成为可见 Asset 前清理；空间不足时返回已用/配额/剩余字节与中文修复建议。
- PostgreSQL Attachment Binding 以每篇文章的短事务 advisory lock 原子计算数量、总字节和排序位置；Memory Store 采用同一 admission 语义，避免并发上传绕过数量/总量或产生重复顺序。
- 附件读取每次复用文章可见性、Binding 和 Asset 状态：草稿仅作者、下架/删除/回收后拒绝；不会返回存储路径、key、JWT 或永久下载 URL。
- 新增受控 PDF content/download 路径、`ETag`/`If-Range`/`206`/`416` 支持，以及绑定当前用户、文章、附件、展示方式和十分钟到期时间的随机 Invocation。
- 增加第一方 `pdf-viewer` Built-in Feature 与 `trusted-module`，PDF.js 从同源打包依赖加载，带当前 Session Header 进行 Range 读取；支持翻页、页码跳转、缩放、键盘翻页、目录、文本搜索、按附件保存的最近阅读页、下载与错误降级。
- Plugin UI Contract 升至可兼容 `campusos.ui/v1` 与 `campusos.ui/v2`：v2 Surface 声明 Presentation，外部 Manifest 可声明 `open-surface` Action；宿主控制 modal/drawer/fullscreen/new-tab，且新标签页只使用同源随机 Invocation URL。
- Web 图文编辑页和详情页已增加附件区、附件卡和 PDF 预览入口；管理端数据架构、migration README、ER、Schema、路由/OpenAPI 合同和系统设计文档已同步。

## 尚未构成 Final 的证据与后续项

1. Linux 目标环境的 20 路 PDF Range、慢客户端、RSS/延迟容量结果和真实浏览器 PC/移动端矩阵尚未在目标环境留档。
2. PostgreSQL 与 Object payload 的成套备份恢复、孤儿对象/过期 Invocation 清理演练尚未完成；本版仅有引用保护和 trash-first 行为，未交付可配置 purge/隔离管理台。
3. 本版 Viewer 是编译期第一方 trusted-module；第三方 UI Bundle 的独立 Origin、sandbox iframe、CSP、签名与 Bridge 不在范围内。
4. MP3/MP4 在线播放、Office 在线转换、跨用户分享、全文/OCR、病毒扫描/DLP 和全面个人资产统一均仍是后续版本能力。

## 回滚与运行提示

- 生产问题时先停用 Built-in Feature `pdf-viewer`，PDF 预览会安全拒绝；有访问权用户仍可走认证下载。
- 不得通过 `000006`–`000008` 的 destructive down 删除真实附件；保留 Asset/Object/Binding，采用前向修复。
- 变更 Go、migration、Vue 或 PDF.js 依赖后，Docker 开发环境需要执行 `./scripts/docker-dev.sh rebuild` 或 Windows `./scripts/docker-dev.ps1 rebuild`，再执行 `up`；仅改 Vue 页面可利用当前开发容器热加载。
