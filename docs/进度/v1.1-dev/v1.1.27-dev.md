## 1. 问题与根因

用户在 PDF 预览弹窗中持续看到“正在连接 CampusOS…”。排查发现有两层独立问题：

1. PDF 插件构建产物使用根路径 `/assets/...`。插件网关仅允许访问 `/plugins/<key>/<version-digest>/...`，因此浏览器拿到的入口脚本是 404，页面只能停留在 HTML 的初始提示。
2. 修复构建路径并提升插件版本后，v4 隔离插件重新登记时，持久化记录错误地覆盖了新发布包的 checksum。授权版本表因此把新版本误判为携带旧摘要，触发唯一约束冲突并自动隔离插件，运行时清单不再下发 PDF Viewer。

授权并非第一层故障的原因：前端桥接脚本没有加载时，宿主和插件之间根本不会发起受限连接。

## 2. 完成内容

- PDF Viewer 构建改用相对静态资源路径，并把共享 `dist/assets` 一并发布到 `ui/assets`；用户端与管理端入口均能在隔离发布目录下加载代码和 PDF.js Worker。
- 开发源插件重新打包前只清理自身旧派生发布目录，避免同一插件残留多个开发构建版本。
- PDF Viewer 版本升级至 `2.0.0-dev.2`，使新发布包具有新的、可审计的版本身份。
- 插件持久化同步逻辑把 v4 隔离 UI 发布包与内置模块一样视为不可变发布物：不再用旧记录覆盖当前发布包摘要。
- 只对“版本已升级且此前因声明变更被系统自动隔离”的记录恢复运行；同版本内容变更、管理员停用和其他失败状态仍保持隔离或原状态，避免降低完整性保护。
- 补充发布静态资源、版本身份与开发重建行为的插件 README、开发验收文档、官方站点说明和架构文档。
