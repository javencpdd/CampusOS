## 1. 准绳与冲突

已完整读取 [正式计划](../../项目计划书v1/项目计划v1.1/00-v1.1版本计划书.md)。
第 6、10.2、15 节明确使用随受信 Web 编译交付的第一方 trusted-module，第三方动态 Bundle 属于 P2。
此前建议直接把 Viewer 改为独立第三方 UI 的说法不符合本次指定范围，本轮不实施该扩展。

但第 3.1、8.2、10.2 节同时要求 Plugin Manifest 注册、Declaration/Admin Grant/User Consent 和插件生命周期判断。
当前仅有 modules/features/pdf-viewer 描述符、Feature 开关及业务 owner/文章/Invocation 校验，
没有 PDF Capability 到 AuthorizationService 的完整调用链。不能将“编译期可信”当成已满足插件授权要求。
现有 Manifest 校验仅允许 builtin/system 的可信模块，而插件启动装配注册 process/grpc/wasm，
并跳过 builtin 的授权事实同步；这不是挪目录或重命名即可闭合的缺口。

另有未闭合差异：通用声明式 open-surface Action 仍被当作 Extension 请求入口调用并拒绝，
尚没有从 Action 到宿主签发业务 Invocation 的通用链路；计划候选 Capability 也尚未进入目录。
本轮不新增临时豁免、自动同意、模拟 Grant、第三方 Bundle 或新依赖来掩盖差异。

## 2. 已修正的实际错误

| 计划约定 | 原问题 | 本轮修正 |
| --- | --- | --- |
| 首次预览可用、失败可控 | PDF.js 对象被深度 ref 代理，私有字段访问可能失败；Canvas 未必已挂载 | shallowRef 保持原对象，首帧前等待 DOM 刷新 |
| 切换/关闭销毁上下文 | 旧请求可覆盖新附件；卸载后加载任务继续运行 | 加载代次校验、取消加载任务、停止过时渲染与目录写入 |
| 最近阅读位置为辅助体验 | localStorage 被禁用会中断预览 | 捕获可选存储失败，保留正常阅读 |
| PDF 安全 | 未显式关闭 PDF.js eval 优化 | isEvalSupported=false，不增加依赖 |
| 已注册 Surface 与 Presentation | 入口只验证非空，弹层硬编码 PDF；新标签页固定 PDF 路由 | 查询当前 Runtime Surface、启用与加载状态、展示白名单；使用注册的同源扩展路由；按已有 schema/trusted 渲染器展示 |
| 停用后的界面生命周期 | 已打开弹层未跟随 Surface 消失 | Runtime 清单移除或停用时关闭弹层 |
| 随机短期 Invocation ID | URL 使用时间序列 ID | 标准库 crypto/rand 生成正 BIGINT 随机 ID；保持原 SQL/DTO 类型和每次鉴权 |

随机 ID 不是下载凭据；未更改 owner、文章状态、配额、Range 和有效期规则。
预览不可用时仍从文章或个人附件入口进行认证下载；Viewer 内的 content 按钮仍受 Invocation 有效期限制，
不能描述为完整的“过期后原按钮仍可下载”闭环。
