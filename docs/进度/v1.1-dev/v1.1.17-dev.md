## 1. 本次目标

修复 Admin 与 Web 在对 `builtin.pdf-viewer` 执行管理员 Grant、用户 Consent 或短期 Delegation 时，界面显示能力已经声明但接口提示“当前插件版本没有声明该能力”的问题，并记录真实三层授权执行路径。

## 2. 完成内容

1. 只读核对 Docker 开发库：`builtin.pdf-viewer` 的当前 `plugin_versions.id` 为 `1789489244156976761`，五项 `plugin_capability_declarations` 均存在，五项 `plugin_admin_grants` 均为 `granted`；因此不是 Manifest、Grant 或 migration 缺失。
2. 定位根因：该 19 位 PostgreSQL `BIGINT` Snowflake ID 超过 JavaScript `Number.MAX_SAFE_INTEGER`。旧 API 把它作为 JSON number 返回，浏览器在拼接 `/versions/:version_id/...` 路径前静默舍入到另一个数字；服务端据此查询到空声明集合，才返回误导性的“没有声明能力”。
3. 将插件授权域的版本、声明、Grant、Consent、Delegation 与判定记录 ID 统一序列化为十进制 JSON 字符串；Admin/Web API 包及 PDF Viewer Consent 不再把版本 ID 转为 `number`。短期 Delegation 的撤销 ID 同样保留字符串，防止后续越界。
4. 新增后端回归测试，固定验证超过 JS 安全整数范围的 ID 在授权 Overview 中仍以完整字符串输出；更新 v1.1 授权设计说明的三层实际流程和浏览器 ID 边界。
5. 已重启 API 开发容器使 Go 改动生效；未重建镜像、未执行 migration、未重置数据库。
