## 1. 问题与根因

在 3000 用户端预览 PDF 时，浏览器报“找不到 `api` 的服务器 IP 地址”。这不是三层授权拒绝：Web Vite 代理把原始请求 `Host` 改为 Docker 内部服务名 `api:8080`；v4 Plugin UI 的 `http://{host}:3003` 模板随后产生 `http://api:3003/...`。`api` 只在 Docker 网络内可解析，用户浏览器无法解析它。

## 2. 完成内容

- Web 与 Admin 的 `/api` Vite 代理均改为 `changeOrigin: false`，保留浏览器实际访问的 Host；API 将因此生成 `http://localhost:3003/...` 或 `http://<开发机IP>:3003/...`，而不再暴露 Docker 服务名。
- 新增 v4 Runtime Manifest 回归测试：请求 Host 为 `192.0.2.42:3000` 时，PDF iframe 地址必须使用 `192.0.2.42:3003`。
- 更新架构配置说明与官方 Docker 指南，明确 `api:8080` 只能是容器内部代理目标，绝不能成为浏览器加载的插件地址。

## 3. 修改文件

## 5. 使用说明与后续

本次只改 Vite 配置，已运行容器会自动重启 Web/Admin Vite 服务；不需要 `rebuild`。在浏览器按 `Ctrl+F5` 后重新登录并点击 PDF 预览即可。局域网预览还必须按 Docker 指南开放可信 LAN 的 3003 端口；授权仍由宿主按资源 ACL、管理员 Grant 和用户 Consent 独立判定。
