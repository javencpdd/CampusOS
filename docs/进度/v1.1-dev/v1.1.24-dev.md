## 1. 本次目标

消除管理端同时显示旧内置 `builtin.pdf-viewer` 与当前自包含外部插件 `campusos.pdf-viewer` 的歧义；明确“外部插件运行管理”与“用户目录与授权”的职责边界，并确保旧目录投影不会在服务重启后再次出现。

## 2. 完成内容

1. 定位根因：旧 `modules/features/pdf-viewer/module.yaml` 和 Admin 内置功能目录仍声明了 PDF；同时，`plugin_catalog_entries` 中已发布的旧条目不会被原 `MarketService.SyncCatalog` 删除，因此新 v4 release 出现后仍保留第二行。
2. 删除旧 PDF 内置功能描述和 Admin Feature Catalog 项；服务端 PDF 可用性改为只检查当前 `campusos.pdf-viewer` 外部 release 的运行状态，不再依赖已删除的 `pdf-viewer` Feature 开关。
3. 为插件目录存储增加删除接口；目录同步先写入当前 Manager 发现的外部插件，再删除未发现的旧投影。被清理的仅是可再生目录行，不会删除文章附件、用户文件、授权审计或插件记录。
4. 增加回归测试：预置旧 `builtin.pdf-viewer` 目录行后，只同步当前插件时，验证旧行被移除。
5. 将管理端边界改为：`/plugins` 是“外部插件运行管理”（导入、启停、管理员 Grant、系统配置/Secret、日志）；`/plugin-center` 是“用户目录与授权”（发布可见性、用户请求/Consent、聚合使用数据和审计），后者是前者的受控目录投影，不是第二套安装登记。`/extensions` 保持只读汇总。
6. 同步当前架构、系统设计 Help、官方文档与重构计划，明确 PDF Viewer 的唯一有效身份是 `campusos.pdf-viewer`；`runtime: none` 只表示 UI-only 隔离发布包，不表示内置功能或绕过授权。
