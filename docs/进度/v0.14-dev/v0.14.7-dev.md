## 1. 目标

复查 v0.14 P0/P1 落地后的剩余工程边界：确保 AcademicTerm、User Storage Object 和 Personal Documents 的
PostgreSQL 多语句写入不会绕开 TxKernel；消除 Windows/Linux Docker 回归测试在源码包内生成被忽略运行数据、
进而让 API 热重载重复报告权限错误的问题；以当前 Docker Desktop 环境补充可复验证据。

## 2. 实际完成

| 范围 | 完成内容 | 保持的边界 |
| --- | --- | --- |
| AcademicTerm | `PgRepository` 通过 `transaction.ExecutorFor` 取得当前执行器；创建默认学期和切换默认学期改由 `transaction.Manager.Within` 管理。 | 乐观锁、唯一冲突、open/closed 语义和既有 API 不变；外层已有 TxKernel 时复用同一事务。 |
| User Storage Object | Object、Reservation 与用量账本的 Reserve/Commit/Abort/FinalizeDelete 多语句操作改由 TxKernel 管理；读写均从上下文取得执行器。 | staging、hash、原子 rename、默认只读 reconcile 和显式 apply 授权不变。 |
| Personal Documents | 创建文档、追加不可变版本及其读写路径接入同一事务上下文。 | owner scope、版本恢复、预览安全降级和 External Plugin 隔离不扩大。 |
| Docker 热重载 | `dev-api.sh` 对 `cmd`、`internal`、`pkg`、`sdk` 的源码指纹明确剪枝被忽略的 `.campusos` 目录。 | 不删除历史忽略文件；该目录不属于 Go 源码或热重载输入。 |
| Docker 测试 | PowerShell 与 Bash 的 `docker-dev.* test` 在一次性 API 容器中使用 `/tmp/campusos-go-test`，并在容器 shell 内设置路径。 | 不把容器绝对路径经 Docker `-e` 暴露给 Git Bash/MSYS 改写，也不在工作区包目录生成测试数据。 |
| 文档与 Skill | 架构、v0.14 操作说明、官方 Docker 文档、Help/计划入口和无提交开发参考同步到本记录。 | 保持 `v0.13.0` 为发布基线；历史进度记录不改写。 |
