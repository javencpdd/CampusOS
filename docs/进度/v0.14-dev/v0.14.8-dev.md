# v0.14.8-dev：学期创建、资源可见性与图片上传可操作错误

> 阶段：`v0.14-dev`

> 发布基线：`v0.13.0`；本文记录开发工作树中的修复与验证，不代表 `v0.14.0 Final` 已发布。
> Git：使用 `campusos-dev-nocommit`；本次仅修改工作树，未执行 commit 或 push。

## 1. 目标

修复管理端创建“默认开放学期”时的 500，明确 Docker 开发环境中 `/api/v1/health` 的检查频率，并让用户能在
“我的文档”中看见自己已上传的图片资源。针对头像、普通正文图片和图文文章图片上传，返回带准确限制和下一步的
中文错误，而不是英文底层错误或无说明的 500。

## 2. 实际完成

| 范围 | 实现 | 保持的边界 |
| --- | --- | --- |
| 学期创建 | `academic_terms` INSERT 的状态参数在列写入和 `closed_at` 的 `CASE` 中均显式按 `varchar` 处理，消除 PostgreSQL 对同一占位符推断出 `text`/`varchar` 冲突的 `42P08`。 | 创建默认学期仍和撤销旧默认在同一 TxKernel 事务中完成；无 migration、无历史数据修改。 |
| 开发健康探针 | API Docker healthcheck 新增 `CAMPUSOS_DEV_API_HEALTHCHECK_INTERVAL`，默认 `5s`；PowerShell 与 Bash 都校验 Compose 时长。 | 它只调节容器对 `127.0.0.1:8080/api/v1/health` 的探针，不是 3001 管理端轮询，也不改变 `CAMPUSOS_DEV_POLL_INTERVAL` 的源码热重载扫描。 |
| 我的文档资源库存 | `我的文档 → 已上传资源` 只读汇总当前用户的头像历史、`img/content` 普通正文图片和 RichText 图片；新增 owner-scoped `GET /content/assets/images/me`、`GET /richtext/assets/me`。 | 不把兼容图片伪造为 `personal_documents` 版本，不移动、不删除文件，不暴露宿主路径；每种来源最多 200 条。 |
| 上传错误 | 三条图片链路均返回中文、支持格式、单文件上限和机器可读详情；超过 4000 万源像素时还返回实际宽高与安全上限。JPEG/PNG 超过 1920px 会自动压缩。 | GIF/WebP 保持原样以避免破坏动画或重复有损编码；WebP 仍先解析 RIFF 尺寸以执行同一 4000 万像素上限，未知异常不泄露文件系统、解码器或 SQL 细节。 |
| 通用安全错误 | 注册的 `internal.error` 公共文案改为中文且给出“稍后重试/联系管理员”的下一步。 | 原始 cause 继续只保存在服务端日志；本次不声称已逐一翻译仓库全部历史业务错误。 |

## 3. 用户可见行为

1. 管理员在 `/academic-terms` 创建学期并勾选“设为默认开放学期”不会再因 SQL 参数类型冲突显示
   `internal server error`。
2. 若开发日志每 5 秒出现 `/api/v1/health`，在 `deploy/docker/.env.dev.local` 设置
   `CAMPUSOS_DEV_API_HEALTHCHECK_INTERVAL=30s` 后执行 `docker-dev.* up` 即可生效；无需 `rebuild` 或重启 Docker Desktop。
3. 已上传资源页只显示当前账户上传的图片。头像仍在“个人空间设置”切换；帖子和图文图片仅可预览，以免删除后使
   已发布内容失效。
4. 图片被拒绝时，接口会说明 PNG/JPEG/GIF/WebP、当前单文件上限、已知的实际文件大小；超像素图片还会说明实际
   `宽 × 高`、4000 万像素上限和自动压缩规则。个人空间不足会提示清理文件或联系管理员扩容。
