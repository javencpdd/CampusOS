## 本阶段完成内容

| 范围 | 已实现结果 |
| --- | --- |
| 对象存储对账 | 新增 `campusosctl storage reconcile`。默认只读，报告过期 pending/Reservation、元数据与物理文件缺失、孤儿文件、hash/大小、账本、非法路径和未分类旧文件；扫描不跟随符号链接，报告仅使用相对路径和根目录标签。 |
| 受审计修复 | `storage reconcile --apply` 必须提供 `--actor` 与 `--reason`，仅处理已过期 pending/Reservation 和“ready 元数据缺物理文件”；未知、孤儿、账本不一致及旧文件一律不自动删除或篡改，并写入平台命令审计。 |
| 历史课表采用 | 新增 `campusosctl schedule adopt`。它先只读校验旧 JSON、文件名、用户目录、学期、周一第一周、hash 和 `index.json`；显式 `--apply` 时只复制已校验内容到不可变 Object，建立关闭的历史学期、引用和偏好，保留原 JSON。 |
| 课表 Object 绑定 | `000049` 为 `user_schedule_terms` 补充 `current_object_id`、`first_week_start`、`version`，新增 `user_schedule_preferences`；新保存的课表仍写兼容 JSON，同时登记不可变 Object 和受管学期引用。 |
| 个人文档降级 | PDF/DOCX 预览接口稳定返回 `converter_unavailable` 的中文安全提示并允许下载；不在 API 内执行外部转换。增加非自动启用的 Converter Compose 隔离模板，规定非 root、只读根、无网络、去能力和资源上限。 |
| 配额反馈 | 文件大小/空间不足的中文错误补充单文件上限、请求大小、已用、总配额和剩余字节，让用户能够按提示调整文件。 |
| 恢复与架构 | 备份恢复演练增加 v0.14 表、课表 Object 引用和偏好校验；Admin 数据架构、schema contract、HTTP/OpenAPI/错误合同及使用文档均已同步到 migration `000049`。 |

## 历史数据边界与真实扫描证据

- 实际开发卷的只读扫描发现 16 个未分类旧文件和 1 份可采用的历史课表；没有执行 `--apply`，没有移动、删除或改写任何用户文件。
- `.gitkeep` 等非用户目录现在会被明确标记为 `invalid_owner_directory`，不会被伪装成某个用户的旧文件。
- 采用与修复是需要管理员业务确认的操作：必须先审阅 dry-run，再由有权操作者带原因执行。代码不会把“完成开发”误解为“有权处理现有用户数据”。

1. `scripts/test-v14-*.sh` 与 `make v14-migration-check` 已更新为覆盖 `000049` 及依赖回退顺序；本次末尾未能再次运行统一 Docker 演练，因为执行环境的外部工具额度拒绝了该调用。发布前须在可用 Docker 环境重跑，并运行 `scripts/restore-drill.sh` 和 `scripts/release-check.sh`。
