## 2. 实际完成

| 范围 | 实现 | 保持的边界 |
| --- | --- | --- |
| G0 采集器 | `campusos-baseline` 升级为 v2，分开记录 Schema、OpenAPI、Route/Operation、Permission、Module manifest hash 和 bundle 状态/预算。 | 原 2026-08-28 的 G0 v1 快照保持原样，不把当前 v0.14 工作树事实伪装成历史基线。 |
| 对象对账与分页 | `storage reconcile` 改为 keyset 批次、分 owner 文件扫描、可选原子 checkpoint、聚合计数与有界差异样本；Object List 改为数值 cursor 和索引可用的 `id < cursor` 查询；样本截断时拒绝 `--apply`。 | `--apply` 仍只做窄修复，需 actor/reason/audit；未知文件、账本差异和 quarantine 不自动改写。 |
| 历史迁移 | 新增从 `000043` 历史数据库和旧课表 JSON 开始的隔离 fixture；升级到 `000049` 后验证采用、引用、偏好、Object 和 JSON hash，再运行对账。 | 脚本仅创建/清理临时数据库和目录，不能替代真实历史数据的管理员授权采用。 |
| 文档预览可靠性 | 文档版本创建、保存、恢复在同一 Reliability 事务写入最小化 `document.preview.requested.v1`；内置安全降级消费者严格校验允许字段、写入可靠 receipt；PDF/DOCX 没有 Runner 时持久记录 `unsupported/converter_unavailable`。 | 没有受审查隔离 Runner 时不读取私有内容、不执行 Office/PDF 外部命令；合法预览事件不会因缺少消费者进入 retry/dead-letter，仍仅支持认证上传/下载。 |
| 学期管理可解释性 | AcademicTerm 管理列表批量附带课表引用数；Admin 显示引用数并禁用有引用项的删除按钮。 | 数据库 RESTRICT FK 是并发下的最终保护，前端按钮不能替代服务端约束。 |
| 数据架构图 | 补充个人文档版本到预览状态、预览 Object 的关系线。 | 页面只展示 Schema/逻辑关系，不读取用户文档内容。 |
| 中文可操作错误 | 课表导入的空文件、读取失败、学期/版本参数和超限统一输出中文安全原因；超限附带 `max_bytes`、`actual_bytes`、下一步。 | 不向客户端泄露解析器、文件系统、SQL 或内部错误。 |
| 文档同步 | 更新 Help、API 索引、官方架构/迁移/路线页面，并新增完整审查回顾；官方入门路径改为管理员先建受管学期，并补充用户“我的文档”指引。 | README 仍保持 `v0.13.0` 发布说明，不提前更新为 v0.14 Final。 |

## 5. 审查结论与未决门禁

可由当前仓库实现的 v0.14-dev 范围已经完成；详细矩阵、功能清单、后续项和整体状态见
[v0.14 计划逐项审查与项目回顾](../../项目计划书v0/项目计划v0.14/01-v0.14计划逐项审查与项目回顾.md)。

仍不得宣称 v0.14 Final，原因不是遗留代码 TODO，而是以下发布级证据尚未由对应责任方产生：

1. 有权管理员审阅 dry-run 后执行真实 `schedule adopt --apply` 和 `storage reconcile --apply`，并归档对账结果；
2. 在 Linux amd64 目标环境完成 `release-check`、恢复演练和认证 Web/Admin 浏览器矩阵；
3. 在受控发布工作树归档 v2 G0 基线；
4. 以脱敏/隔离规模 fixture 给出 10 万对象与真实数据量性能证据；
5. 若要启用 DOCX/PDF 在线预览，单独交付并审查真正的隔离 Converter Runner；
6. Release Owner 完成正式发布审查、版本和发布说明决策。

## 6. 回滚

- 本次没有修改既有 migration、执行真实数据 apply、删除真实用户文件或 commit/push。
