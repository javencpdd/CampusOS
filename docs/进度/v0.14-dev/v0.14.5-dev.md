# v0.14.5-dev：共享内容编辑核心与受限运营摘要

> 发布基线：`v0.13.0`；本文记录开发阶段实现，不代表 `v0.14.0 Final` 已发布。

## 1. 目标

完成 v0.14 计划中剩余的 P1 工程项：抽离可复用的内容安全核心，给个人文档提供不越权的只读草案和安全预览，并以低基数聚合指标补足对象、预览与运维摘要。不得因此扩大 External Plugin、Converter 或文件系统权限。

## 2. 实际完成

| 范围 | 实现结果 | 边界与兼容 |
| --- | --- | --- |
| `core.content-editor` | 新增纯 Go Core Module，统一受控 HTML 清洗、TXT/Markdown/CampusDoc 校验和渲染；Markdown 原始 HTML 转义，CampusDoc v1 图片仅接受数字 `object_id`。 | 不依赖 Community、文档仓储、文件系统或 Plugin；旧非空 CampusDoc JSON 仍按转义文本安全可读，避免开发期草稿丢失。 |
| RichText / Community | 原 Community `contentbody` 保留兼容 API，改为委托共享核心；RichText 直接使用共享 Sanitizer。 | 帖子生命周期、Thread、Revision 和资产所有权没有移入 Core。 |
| Personal Documents | 新建/保存/上传的可编辑内容使用同一校验；保存后的可编辑文档可通过 `GET /api/v1/documents/:id/preview` 获得服务端清洗后的 `rendered_html`。前端复用 `web/src/modules/content-editor/` 的编辑组件和格式定义。 | PDF/DOCX 仍明确返回 `converter_unavailable`；不在 API 进程启动 Office/PDF 转换器。 |
| Document ReadPort | 新增 owner-scoped、只读的受信进程内草案，支持仅对所有者列出、读取和打开当前文档。 | 未注册进 AppContext、External Plugin Host 或 Gateway；不会向插件泄露原始文档字节。 |
| 运营指标 | 对象/Reservation 在启动和成功写删后刷新聚合 Gauge；预览队列以数据库聚合刷新，预览调用记录有界耗时 Histogram；对账报告可显式投影为固定差异种类 Gauge。 | 没有 owner、Object ID、文件名、路径或任意标签。对账仍是显式维护命令，当前不会在 API 启动时扫描或修复文件。 |
| Admin 摘要 | 集成中心“基础观测”卡从 Collector 只投影固定对象、Reservation、预览队列和对账差异合计。 | 不复制原始 metric labels，避免 Admin 摘要成为高基数或隐私数据通道。 |

## 5. 回滚、限制与 Final 门禁

- 此 P1 变更没有 migration；回退代码时应同时回退 `core.content-editor` 模块登记、依赖描述和前端安全预览调用，既有文档对象和版本不会被迁移或删除。
- CampusDoc v1 是受限编辑格式，不是通用 HTML 或 Office 文档格式；历史开发草稿只保证安全显示，不承诺自动升级语义。
- `RecordReconcileMetrics` 只接收已完成的只读报告，绝不触发扫描或 `--apply`；真实历史数据 apply 仍必须由授权管理员先审阅 dry-run 并提供原因。
- Converter Runner、真实历史数据 apply、Linux 目标环境 release-check/浏览器证据与正式发布审查仍是 v0.14 Final 人工/目标环境门禁，不能由本地开发实现替代。
