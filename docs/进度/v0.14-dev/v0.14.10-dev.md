# v0.14.10-dev：CI 前端格式与 v14 迁移脚本可执行性修复

> 阶段：`v0.14-dev`
> 日期：2026-08-31
> 更新时间：2026-08-31 10:38（Asia/Shanghai）
> 发布基线：`v0.13.0`；本文仅记录 CI 修复，不代表 `v0.14.0 Final` 已发布。
> Git：使用 `campusos-dev-nocommit`；本次未执行 commit 或 push。

## 1. 问题与根因

GitHub Actions 出现两项独立失败：

1. Web 的 `pnpm format:check` 报出五个 v0.14 相关文件不符合仓库 Prettier 规则；
2. Linux Runner 执行 `make v14-migration-check` 时，首个 `test-v14-g0-baseline-migration.sh` 因 Git 文件模式为
   `100644` 而无法通过 `./脚本` 直接运行。

v13 migration 日志中的 PostgreSQL `NOTICE ... does not exist, skipping` 是幂等迁移演练的正常输出，且两个
v13 脚本均已输出 `passed`；它们不是本次失败原因。真正停止 CI 的是 v14 脚本缺少可执行位。

## 2. 实际完成

| 范围 | 完成内容 |
| --- | --- |
| Web 格式 | 用仓库锁定的 Prettier 格式化 `trustedModules.ts`、`SafeContentEditor.vue`、`DocumentContentEditor.vue`、`personal-documents/api.ts` 和 `PersonalDocumentsView.vue`；变更仅为代码排版。 |
| CI 执行方式 | `Makefile` 的 `v14-migration-check` 对全部七个 v14 演练脚本显式使用 `bash scripts/…` 调用，不再依赖工作区是否保留 Unix 可执行位。 |
| Git 元数据 | 同时为全部七个 `scripts/test-v14-*.sh` 设置 Git `100755` 文件模式，使 Linux clone 后直接运行脚本、文档示例和其他调用方也保持正确。 |

双重处理的目的在于：Makefile 在跨平台工作区中稳定运行，脚本本身也具备应有的可执行元数据；Windows 不会因
可执行位差异受到影响，Linux CI 则不会再出现 `Permission denied`。

## 4. 回滚与边界

- Prettier 变更可按文件回退，不改变前端运行语义。
- 即使不依赖 Git `100755`，Makefile 已通过显式 `bash` 保持 CI 可执行；因此回滚文件模式前应保留该调用方式。
- 本次未改动 migration SQL、未运行真实数据 `--apply`、未声明 v0.14 Final，也未执行 commit 或 push。
