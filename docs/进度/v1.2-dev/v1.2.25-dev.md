范围限定为**一个插件的活跃、未撤销、尚未使用当前 active key 的 Secret 行**。本地 `campusosctl` 默认只读预览；一次显式执行最多处理 500 行。它不提供 HTTP、Host API 或 SDK 明文读取，不自动后台轮换，不声明全库旧 key 可退役。

## 2. 实现与逐路径定向验收

| 路径 | 实现与验证 |
| --- | --- |
| 行级条件更新 | [Secret Service](../../../internal/plugin/secret.go)和[PostgreSQL 仓储](../../../internal/plugin/secret_pg.go)将原行重封装的 CAS 前提收紧为完整旧加密信封（key version、algorithm、nonce、ciphertext），并复核 ID、scope、活跃状态。即使两个操作者都针对同一行换到不同 key，后提交者也不能覆盖先提交者。只更新四个加密字段，保留 ID、owner、名称、状态、元数据及时间戳。[内存测试](../../../internal/plugin/secret_test.go)与[真 PG 测试](../../../internal/plugin/secret_rewrap_pg_integration_test.go)覆盖冲突和旧信封拒绝。 |
| 有界库存与批处理 | [批量服务](../../../internal/plugin/secret_rewrap_batch.go)、[PG 库存](../../../internal/plugin/secret_rewrap_inventory_pg.go)及[内存库存](../../../internal/plugin/secret_rewrap_inventory_memory.go)只按插件和 active key 统计、按 ID 顺序选取 1–500 个候选；逐行调用受 CAS 保护的服务，错误时停止，结果仅给选中、完成与剩余数量。[批量单测](../../../internal/plugin/secret_rewrap_batch_test.go)覆盖分页、幂等、其他插件/历史行隔离、缺旧 key、篡改和库存失败。 |
| 本地操作入口与审计 | [命令](../../../cmd/campusosctl/secret_commands.go) `campusosctl secret rewrap --plugin-id N` 默认只读；`--apply` 需匹配当前 `--expected-count` 并提供 `--actor`、`--reason`，每次只执行一个批次。数据库连接与 Keyring 仅取本地环境变量，操作前写 `platform_operation_runs`，之后写成功/失败和汇总计数；失败可能已有前序行提交，审计保留部分进度。输出和系统生成的错误不包含 Secret 名、值或 DSN；审计理由为操作者输入，操作者应避免填写敏感信息。[命令测试](../../../cmd/campusosctl/secret_commands_test.go)覆盖参数、安全输出和审计行为。[真 PG 命令测试](../../../cmd/campusosctl/secret_batch_pg_integration_test.go)覆盖预览、数量前提、三次单行批次、成功/失败审计和恢复后复读。 |
| 运行文档 | [配置边界](../../architecture/配置与运行边界.md)、[Secret 分流合同](../../api/v1.2插件配置Schema与Secret分流合同.md)和[插件指南](../../help/系统设计相关/插件三层授权与v3开发指南.md)同步本地操作步骤、旧 key 保留条件及无新增插件明文权限。 |

## 3. 目标环境与原始证据

```bash
bash scripts/v12-01b-secret-batch-drill.sh \
  --report docs/项目计划书v1/项目计划v1.2/evidence/v12-01b-secret-batch-linux.json
```

[可复跑演练](../../../scripts/v12-01b-secret-batch-drill.sh)使用独占的 Linux loopback 端口、512 MiB tmpfs PostgreSQL 16 容器，完成 000001–000006 迁移与 checksum、现行和历史数据库门禁、真实命令调用与单行三次分页、成功/失败审计、缺旧 key/坏密文/旧信封冲突拒绝；随后 `pg_dump/pg_restore` 到同容器新库，用**仅新 key**读取正向夹具并确认预览候选为零。演练结束清理容器，没有 reset 共享数据库。[原始 JSON](../../项目计划书v1/项目计划v1.2/evidence/v12-01b-secret-batch-linux.json)记录 implementation、automation、target_environment 均为 `passed`，9/9 检查和 15/15 当次源码/文档 SHA-256 摘要匹配，`stage_status=partial`。

该恢复证据只覆盖本次正向夹具的活跃行；历史 rotated/revoked 行和换钥前备份仍可能需要旧 key。撤下旧 key 前，所有写入实例须切换到同一新 active key，并复核实际数据库全部需要读取的活跃行。本轮没有全库退钥证明或完整系统恢复验收。
