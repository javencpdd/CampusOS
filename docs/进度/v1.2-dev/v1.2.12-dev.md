### 2.1 本次发现并修复的问题

1. **TXT 回收/恢复 SQL 类型冲突**：跨 owner 回收预期 404，真 PostgreSQL 返回 500；安全诊断再次复现 SQLSTATE `42P08`。`SetStatus` 中 `$4` 在 varchar 赋值和 text CASE 比较间推断冲突。两处显式 `$4::text` 后恢复正确的 200/404/409，owner 与版本条件保持原样。Memory 包测试原本通过，不能代替 SQL 实测。
2. **公开列表旧缓存泄露**：容量夹具填充后列表仍显示先前的两条，进而发现缓存键为 `threads:list:1:20:published::`，旧失效键不一致。新增回归通过另一服务实例将公开帖改为私密，修复前仍返回私密正文，测试明确失败。列表正文与总数现统一查询权威仓储，避免把可失效的 DTO 缓存当作可见性事实，也避免并发旧查询在清理后回填。修复后 Memory 回归、真实 HTTP 状态切换及 8 并发容量均通过。当前列表不使用该整页缓存；额外数据库负载已纳入本轮测量。
3. **Docker 兼容门禁夹具过时**：`test-dev-mode-compat.sh` 的 mock 对所有 `-tAc` 查询返回 `1`，新迁移校验需要布尔 `t`、checksum 查询及锁 owner，导致假报 legacy schema。按协议修复 mock 后定向和完整门禁通过；该失败来自 mock，没有实际连接或 reset 既有数据库，未改生产迁移逻辑。
4. **隔离插件静态服务**：新增可选 `CAMPUSOS_PLUGIN_UI_HOST`，本机演练设 `127.0.0.1`；容器内默认绑定保持原合同，端口发布规则不变。浏览器实际验证独立 origin、sandbox、URL 无凭据以及成功 PDF canvas。
