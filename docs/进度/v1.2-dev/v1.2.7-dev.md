## 实际完成与环境边界

1. 用 `env -i` 和 `docker compose --env-file /dev/null -p campusos-v12-g0 -f compose.dev.yml` 排除仓库根 `.env`/会话秘密，只启动独立项目的 PostgreSQL 16、Redis 7、NATS 2。初次 NATS 启动因默认监控端口 `58222` 被占而失败；仅把本项目 NATS 端口改为回环 `18323`、监控端口 `18322` 后启动成功，未停止或改变其他容器。
2. 将 `cmd/`、`internal/`、`pkg/`、`sdk/go/`、`modules/`、`migrations/`、`scripts/`、`plugins/`、`deploy/docker/`、`data/resources/` 与 Go module 文件复制到被忽略的 `.cache/v12-g0-target/`。没有复制 `.env`、现有个人文件、插件数据或数据库卷。API 从此副本编译并以 `CAMPUSOS_ENV=test`、假邮件、禁用 AI/Host API/v4 开发源码安装运行在 `127.0.0.1:18082`；PostgreSQL/Redis/NATS 连接均成功。第一次 API 启动因测试模式要求显式 bootstrap secret 而失败；生成一次性随机 secret 后正常启动，值未归档。
3. 只在隔离库运行现有三条 migration，`scripts/migrate.sh check` 通过，实测 `schema_migrations=3`、`public` 基础表 91 张。隔离 API `/api/v1/health` 返回 200。
4. 使用现有 `cmd/campusos-baseline --live --samples 100` 对四个只读端点各采集 100 个成功样本，原始汇总存于 [v12-g0-live-linux.json](../../项目计划书v1/项目计划v1.2/evidence/v12-g0-live-linux.json)。静态字段读取**主工作树**，HTTP 字段读取**隔离 API**；JSON 中的 `user_storage` 聚合计数不是隔离空库的文件数，不能混作同一实例的数据规模。
5. 发现运行时启动日志为 349 条路由，仓库生成合同仅 348 条；`GET /api/v1` 在隔离 API 返回 200，但合同 JSON 中没有该路径。已有 `make contracts-check` 通过只能说明生成文件与当前生成器一致，**不能证明运行时与合同完整一致**。本次未修改路由或权限合同，以待下一条最小闭环核对。
6. 停止 API 后执行仅针对 `campusos-v12-g0` 项目的 `docker compose down -v`，删除本次创建的容器/卷/网络；复查该项目无容器且 `18082` 无监听。现有数据库、仓库 `data/` 与其他容器未重置。`.cache/` 下只保留被忽略的临时副本和采集缓存。
