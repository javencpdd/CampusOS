## 阶段选择与边界

开工重新核对[主计划](../../项目计划书v1/项目计划v1.2/00-v1.2版本优化计划书.md)的 G0→G1→01a→01b 依赖顺序、最新 [.21](v1.2.21-dev.md) 与[01a 原始退出报告](../../项目计划书v1/项目计划v1.2/evidence/v12-01a-exit-linux.json)、当前 Secret/Host API 代码。G0、G1 和 01a 的退出报告均记录实现、自动化、目标环境 `passed`；01a 的 13/13 检查通过，17/17 源码 SHA-256 与开工代码一致。01a 限定数据基线的目标环境验收已具备，所以选择最前面依赖满足且未完成的 01b。开工工作区无未提交修改；本轮未提交、未推送。

01b 首条可独立验收路径是关闭旧 Host API 的明文 Secret 读取。原 `internal/plugin/hostapi/grpc_server.go` 的 `GetSystemSecret`/`GetUserSecret` 在插件获权后调用 `SecretService.Resolve`，把 `value` 序列化给插件，与 G1“Secret 只由 Broker 代用”合同冲突。本切片仅消除这一实际泄露入口，不宣称共享 Security/Secret/Egress Port、Broker、配置仓储、密钥轮换/恢复、DNS/重定向检查或资源预算已实现。
