## 1. 本次目标与范围调整

承接 [.169](v1.2.169-dev.md)，用户要求管理端二次认证可通过配置关闭，开启时给出实际可用的操作引导。本次明确调整主计划中默认强制 MFA 的范围：默认继续开启，但允许部署者显式选择关闭，而不是只隐藏前端弹窗。

本轮不创建或重置真实账号、不绑定/删除真实认证器、不将当前本地配置改为关闭，不替代 [.168](v1.2.168-dev.md) 尚待的局域网与 Linux Final 联合验收。

## 2. 实现内容与安全边界

### 2.1 配置到服务端判定的完整路径

- 增加 `AUTH_ADMIN_MFA_REQUIRED=true`。只有有效配置中明确的 false（大小写不敏感、忽略首尾空白）关闭；未提供、空值或其他值保持默认开启，仍遵循现有环境/.env 配置优先级。
- 根配置模板、Docker 开发/部署模板以及开发/组件 Compose API 环境映射同步；本机忽略的 `.env.dev.local` 增加中文说明，保留 true 和其他现有值。
- Config → Server → Identity 装配 → 当前 Admin 会话事实/账号生命周期/委托判定形成单一部署事实。修改配置需要 `up` 应用环境；不因该开关要求 rebuild。
- 账号生命周期、内容治理、个人空间/配额、资产、插件、Integration、Knowledge 与 AI 的现有管理判定按同一要求执行；默认开启时保留当前 MFA 及 15 分钟窗口。

### 2.2 不伪造认证强度，不放宽其他权限

- 关闭仅取消独立 Admin 的二次验证码门槛。会话真实强度仍为 password，不生成假的 MFA 时间或修改数据库凭据/因子。
- `AdminMFAOptional` 只存在于可信 Go 会话/主体事实，标记 `json:"-"`；不参与 JSON、JWT、数据库或 SDK 传输。解析/重放 JSON 无法恢复该标记，客户端提交同名字段被严格解析拒绝。
- 当前执行授权重新读取会话并比较部署事实，客户端伪造内存判定输入也不能替代真实读取。账号状态、会话有效性、角色、资源范围、原有事务/审计与 CSRF 检查保持。
- 用户域 MFA、受托用户明确要求的 MFA、最后安全管理员保护、重复初始化拒绝与更换既有认证器的持有证明不放宽。关闭不会删除认证器、历史密文或旧解密密钥。

### 2.3 管理端状态与操作引导

- `/admin/identity/me` 增加 `mfa_required`；前端读取实际生效值，不靠浏览器自报配置。旧响应缺少此字段时按默认开启处理，非法类型不作为关闭依据。
- 后台 MFA 页面不再用旧用户域登录策略控制独立 Admin，改为当前生效状态、部署配置说明、刷新入口及认证器引导；不提供由浏览器直接降低部署认证要求的写入口。
- 未绑定时显示提示与分步说明：准备 TOTP → 开始配置 → 添加链接/手动密钥 → 6 位码完成绑定 → 下一组码确认身份 → 重试操作；说明 15 分钟时效、校时、不可复用验证码和秘密保护。
- 关闭时不再主动要求绑定/验证；已有标签页若缓存了关闭状态，而服务端重新开启，会先刷新当前身份事实再打开引导。关闭弹窗、换账号/Token 或要求变化会清除临时绑定秘密并拒绝迟到响应。

## 5. 使用与后续

需要关闭时，部署者自行将开发 local 的 `AUTH_ADMIN_MFA_REQUIRED` 改为 false，在仓库根目录执行 `.\scripts\docker-dev.ps1 up`（Linux：`./scripts/docker-dev.sh up`），刷新管理端 MFA 页面核对“已关闭二次验证”。需要开启时改回 true，再 up，按页面引导操作。生产和局域网建议保持开启。

本轮未执行共享栈 up/rebuild、未重启 Docker Desktop、未修改账号/认证器或共享数据卷。保留日志后，逐一核实已退出并清理本轮 11 个独占测试容器和 2 个独占缓存卷；没有删除借用的镜像或共享卷。清理后 8 个开发容器仍健康，API 健康请求返回 200。实际账号/局域网 PDF 和 Linux Final 仍按原计划等待相应目标反馈；本次功能自动化通过不等于整版 Final。
