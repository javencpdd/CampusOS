# CampusOS v1.2.1-dev 进度说明：细粒度授权与校园知识库设计

> 日期：2026-09-25
> 状态：设计文档已完成；本阶段没有实现 RBAC/RAG 运行时代码

## 1. 本次目标

在 v1.2 初版计划基础上，参考本机 WeKnora 平台 RBAC、机器凭据白名单、模型 Provider 和知识检索架构，为 CampusOS 设计更细颗粒度的授权，以及从指定板块、帖子和用户主动选择的个人文档建立知识库的安全路径。

## 2. 实际完成内容

- 审查 WeKnora 快照 `e2433b12` 的角色/所有权路由守卫、KB 共享范围、API Key 路由白名单、模型和检索 Registry；明确只借鉴分层，不照搬多租户或 RBAC 关闭时放行的规则。
- 对照 CampusOS 的 Permission Code、`global/category` 作用域、独立管理员准入、版主/帖子服务端复核、Personal Documents Own Read Port、现有聊天网关和可靠 Outbox。
- 新增细粒度授权方案：Principal 类型、动作/资源事实/状态交集、模块 Fact Port、路由预筛选与事务内最终授权、机器默认拒绝、后台有效权限预览和负向测试矩阵。
- 新增校园知识库与 RAG 方案：管理员逐个选择公开板块/帖子，用户逐项选择自己的文档/帖子，来源修订、异步索引、撤权立即不可检索、先搜索后引用式问答，以及私人片段外发前单独同意。
- 将 V12-02 拆成策略 Core、资源级接入与 Integration Principal 阶段，新增个人私有集合和受管模型问答阶段；更新 v1.2 权限/数据库入门和文档入口。

## 4. 架构、兼容和数据

本次只修订设计，不创建迁移、API、模型连接或检索索引，也未触碰测试数据。设计保留既有模块数据所有权：Community/Personal Documents 控制原资源可见性，Knowledge 只拥有集合与派生索引，Identity/Authorization 统一决策接口，外部插件/MCP/模型不得因集合授权获得更大原资源权限。用户已允许之后对测试数据执行不兼容重构，但实施前仍按 v1.2 G0 校验目标环境。
