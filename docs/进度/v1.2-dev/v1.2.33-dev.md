## 2. 完成内容

- **读取路径**：`CheckScoped`/`CheckCodeScoped`/`HasAnyScopedPermissionCode` 对两个治理码改走"全局目录授予 ∪ 当前委托 grant"（同层并集）；其余权限码不变。委托评估的强度事实来自入口证明（`delegation.ActorProof` 上下文载体）；缺失证明时 MFA 级 grants 失败关闭、password 级不受影响（与现有认证基线一致）。
- **授予路径**：`ReplaceCategoryRoleScopesByActor`（moderator）在一条命令事务内完成：user_roles 范围替换（承载 read/lock/pin/user.read 五个非委托码）+ 治理 grants 差集（新增经 `BoardDelegationPolicy` 批量原子判定、移除即终态撤销）。管理员证明由 admin 准入 + MFA 路由门禁后的会话强度供给：identity 新增 `SessionStrengthReader` 端口（`SessionService.AuthenticationStrengthForSession`，TOTP→mfa），moderation handler 从已验证 Session 构造证明，缺失即失败关闭。
- **依赖方向**：`port` 包不再依赖具体 service——适配器移入新子包 `portadapt`（`ErrInvalidRoleAssignment` 提升为 repository 层共享 sentinel，错误身份不变）；版块事实由 moderation 经 community `ModerationGateway` 以 `BoardFactsProvider` 闭包供给（每次调用重载，含事务内复核），Identity 不反向依赖 Community。
- **Memory 目录对齐**：Memory 角色目录与迁移一致移除 moderator 的两个治理码。
- 委托拒绝在 moderation 端映射为 403 + 稳定原因码。
