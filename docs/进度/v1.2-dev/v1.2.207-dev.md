## 2. 完成内容

- 新增离线 `campusosctl plugin backup --inventory ... --data-dir ...`。输入仅含当前发布记录的 releases 数组，备份到受管 v5/repository 下；保留原压缩包、签名外封、清单及版本索引，核对摘要/尺寸/元数据，拒绝覆盖不同内容，不解压或执行包。
- 复用原 Admin purge_release 的权限、MFA策略、CSRF、幂等及操作租约。当前全局 current/desired 不能清理；其他版本在完整备份核验成功后可移出运行仓，即使个人旧安装或恢复记录仍引用该版本。
- 清理分为两次受管审计事务：先将备份及目录链接同步落盘、提交 storage=purged 和恢复标记，再复核修订/租约、移除运行包。第一阶段审计失败保留原包；第二阶段失败可重试；同坐标重新导入会废止旧清理，不删除重新导入的包。失败不修改当前版本安装状态。
- 已归档来源的数据检查点只读临时仓，继续核对账本、尺寸、清单、签名外封和受管私有数据边界。原执行/界面资源准入仍只读取运行仓及当前授权，不从备份自动恢复。恢复执行须正常重新导入、验签、审批及所需本人同意。
- Admin 运行列表不再显示 purged 的旧包，发布身份和审计记录仍按精确坐标保留。没有新增DDL、表、HTTP路由或插件专用宿主例外。
- 同步包操作说明、安装合同、插件及数据目录 README、当前计划及最新更新时间。
