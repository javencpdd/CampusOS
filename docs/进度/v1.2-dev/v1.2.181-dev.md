## 2. 完成内容

- 正常应用已连接PostgreSQL时，在整个管理域完全为空的条件下，事务化创建 `admin / admin`，联系邮箱沿用系统管理员地址 `admin@campusos.local`。使用现有 `security_admin` 角色、bcrypt哈希、必需审计及Outbox；PostgreSQL事务级部署锁和事务内复核防止并发重复。已有任何管理域账号（含停用/撤销）不再默认播种，不覆盖修改后的密码。测试profile使用显式夹具，数据库不可用的Memory回退及恢复审查实例不经默认播种重新开通管理员。
- 新增受当前独立Admin会话及CSRF保护的 `POST /api/v1/admin/identity/password`。仅修改本人，验证当前密码；新密码6–64字节，更新凭据CAS、注销本人全部管理域会话及未消费恢复票据，与必需审计/Outbox同事务。已绑定认证器且部署要求MFA时须近期MFA，未绑定的初始管理员可先改密；其他用户、管理员及配置保持。
- 管理端登录页说明初始账号，右上角新增“修改密码”和 `/account/security` 表单，成功清理本地会话并返回登录。
- `scripts/bootstrap-admin.py` 默认使用当前Docker开发API容器的现有环境，经本机 `campusosctl identity create-admin --stdin` 创建额外安全管理员；原生部署支持 `--native` 或私有运行JSON。脚本不再索要HTTP部署证明，密码仅经隐藏终端与子进程stdin传递，不写入命令参数、环境变量或临时请求文件。重复用户名/邮箱失败，不覆盖原账号、角色或密码，不改任何运行配置，不重启服务。
- 原回环HTTP首次初始化及其冻结策略保留，显式 `--http` 才使用旧模式；本机部署CLI不开放给HTTP/插件，授权来自部署者已有Docker/数据库控制能力。
- 同步README、部署/管理员帮助、身份与配置边界、新HTTP路由授权矩阵及OpenAPI。Docker模板的兼容HTTP凭证恢复为空值，避免此前 `false` 字符串导致启动失败；真实 `.env.dev.local` 没有修改。
