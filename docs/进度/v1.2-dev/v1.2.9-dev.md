## 1. 本次目标与阶段选择

[主计划](../../项目计划书v1/项目计划v1.2/00-v1.2版本优化计划书.md)规定 G1 依赖 G0。[v1.2.8-dev](v1.2.8-dev.md)已闭合路由合同，但双 owner 的真实数据、完整身份场景、容量和跨端证据仍缺。本轮选最前的 G0，以“公开帖子状态事实 → 列表/详情 HTTP → 隔离 PostgreSQL 负向样本”为一个切片。开工时工作树已有上轮未提交的合同、计划及进度改动，均保留。

不变边界：公开可见性仍由 Community 的发布、审核和删除事实决定，`author_id` 仍为 owner 事实；请求参数不能授予读取权。只在本轮脚本创建的 tmpfs PostgreSQL 容器内写测试数据，不连接或重置现有库、个人文件或插件数据。

## 2. 完成内容和分项状态

- 代码：公开 `GET /api/v1/threads` 固定 `status=published` 及当前 `publication_status=published`、`moderation_status=clear`、`deletion_status=active`，覆盖客户端提供的状态筛选。保留管理端独立列表合同。根因是原 handler 只固定旧 `status`，当旧状态与当前事实不一致时，仓储查询可把详情接口拒绝的内容放进公开列表。
- 自动化：新增定向 handler 回归，先证实不安全筛选会传给服务层，修复后通过；新增可重跑的 `scripts/v12-g0-public-visibility-drill.sh`，以隔离 PostgreSQL、真实迁移和 loopback API 验证列表/详情。同步 `docs/api/API索引.md` 与 `docs-site/api/community.md` 的用户可见合同。
- Linux 目标环境：PostgreSQL 16 Alpine 容器使用 tmpfs 数据目录，API 在隔离工作目录以清空环境和一次性凭据启动，禁用 Redis、Host API、AI、插件开发源码安装；应用 3 条迁移并校验 checksum。两个合成 owner、7 条帖子覆盖公开、私密、下架、回收及两条旧 `status` 与当前事实不一致的记录。公开列表及伪造状态参数请求均只返回 2 条且总数为 2；公开详情 200，另外 5 条详情均 404。原始汇总见 [JSON](../../项目计划书v1/项目计划v1.2/evidence/v12-g0-public-visibility-linux.json)。测试容器退出后由 `--rm` 清理，复查无本轮容器。
- 尚未验收：本轮合成用户未登录，未测独立管理员、跨 owner 凭据与撤权；7 条样本不构成目标容量或 p95 对照，Windows/浏览器亦未测。因此 G0 继续为“部分完成”，G1 依赖未满足。
