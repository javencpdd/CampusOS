## 1. 本次目标

修复管理员点击插件“启用”后详情突然消失的交互，清晰表达安装、审批、启用顺序及当前运行状态。

## 2. 完成内容

- 根因是Admin `write`异常分支对任何错误直接清空`selected`：未审批的启用被现有服务端拒绝403，页面因此丢失当前详情。实际共享数据为五个已安装版本，只有ai-knowledge具有有效审批，且该版本仍在等待执行器；其余四个没有审批。
- 列表及详情增加审批/运行状态、操作顺序和下一步提示。当前服务器审批未保存、过期、缺少必需能力或运行资源时禁用启用；本地勾选草稿不当作有效授权。已提交启用时避免重复点击，待执行器明确显示为尚未运行。审批能力比较使用与对象键顺序无关的结构比较。
- 命令403/409或连接异常保留所选版本与审批草稿，仅重读一次当前事实，不重放写请求。当前事实无法确认时保留上下文、暂停操作并提供“刷新当前状态”；命令已接受但读回失败也保留上下文。详情读取失权/消失及身份变化仍清理旧内容、关闭隔离界面，防止迟到结果恢复旧状态。
- 成功读回同步列表和详情；错误信息放在所选插件内。提示保存审批会停用当前安装，保存后需单独启用；实际服务端CAS、Grant、MFA、CSRF和审计合同不变。
- 更新v5帮助和官网说明。普通Admin源码已由现有Vite热更新应用，无API重启、镜像重建、Schema或部署配置变更；保留已有未提交工作。
