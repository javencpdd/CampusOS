# CampusOS v1.2.193-dev 进度说明

> 日期：2026-10-31（Asia/Shanghai）
> 状态：已完成

## 1. 本次目标

修复管理端与用户端插件状态难判断、勾选与保存混淆、启用缺少引导和技术信息过多的问题，完成两端可操作的使用路径。

## 2. 完成内容

- 两端重排为三步进度和“下一步”。管理端显示“安装 → 审批 → 启用”，用户端显示“本人安装 → 用途确认 → 启用并使用”；已保存、未完成和已提交请求分别呈现，不把勾选或启用意图当作实际可用。
- 管理端权限逐项显示“已保存：批准/未批准”和“待保存”；审批草稿修改后先保存或恢复已保存设置，不能直接启用。保存后仍需单独启用；新版本未准备切换前不会开放启用。执行器未部署时说明下一步需要部署者处理。
- 用户端用途勾选显示“尚未提交”，只有本人Consent同时匹配当前purpose_hash和Grant修订才计为已完成；审批变化会要求重新同意。本站未启用或未就绪时阻止无效个人安装/启用并说明管理员应处理；保留原个人停用、撤回和卸载路径。
- 补充用户`site_state`显示摘要，限定当前可见版本的本站安装/启用/就绪/观测/错误码，不含系统配置、代次和恢复指针；列表包含本人Consent元数据，普通配置仍在所属域详情返回。继续分页前筛选，服务端权限、Grant、Consent、CAS和主体隔离不变。类型及OpenAPI同步。
- 将插件名和能力说明展示为易读中文，标识、修订、摘要和原始错误移入技术详情；导入、额度、已完成的审批/同意和撤回/卸载默认折叠。必要用途和当前阻塞原因保持可见，折叠支持鼠标、键盘及窄屏。
- 正在启动时最多自动读当前详情10次、每次间隔1.2秒；就绪或明确报错后停止，身份/选择/页面变化取消，失权时清理旧内容。只读状态确认不整页刷新、不重放写入，保留手动刷新。失败仍保留可读取的详情及草稿，无法确认时暂停继续写入。
- 用户RSS就绪后在“下一步”直接打开当前宿主注册的对应版本入口，继续由原RuntimeRegistry、隔离frame和当前proof控制。PDF指引从附件/文件预览使用，headless说明由宿主入口调用；不猜测或信任插件提交的路由。卸载清理勾选成功后重置，避免带入后续操作。
- 同步帮助、官网、API合同、主计划及本进度。保留既有未提交工作，没有替真实用户审批、安装、同意、启用或部署执行器。
