## 2. 完成内容

- `ScopeDelegationPolicy` 仅按宿主提供的当前事实求值，按冻结次序判定：admin 主体且 MFA；管理动作按收件域精确映射（plugin→`plugin.grant.manage`、integration→`integration.grant.manage`、user→`identity.role.assign`）且当前有效未到期；任一侧 `personal.document.read` 即 `non_delegable`；user 收件人移交版块治理合同（`recipient_mismatch`）；bound 必须 active、可委托且窗口覆盖当前；最后单条 bound 完整覆盖动作、Scope 类型、ID 精确子集、期限包含与认证强度（password 上限可收紧为 MFA，不可反向）。endpoint 候选逐个校验精确 HTTPS 形状，禁通配、`localhost` 与 IP 字面量。接受只表示提案成立，不是已提交授予。
- host JSON codec 限制 32 KiB/64 层，拒绝重复键（含转义同名）、未知/缺失/null 字段、尾随值、非法 UTF-8 与孤立 surrogate。时间以精确整数毫秒处理，拒绝小数、负数与溢出。ID 按 Schema 的 UTF-16 单元 1–128 计数（与 Ajv 一致），不借用 Principal 的 ASCII 限制；本合同无独立不支持版本码，合同字符串不符即 `scope.input_invalid`，错误不回显输入。
- 本合同没有决策对象或 witness；事务内重读事实即重新求值，`scope.facts_changed` 由后续写入路径在事实版本不同时使用。

## 4. 验证结果

Go 使用 `TMPDIR=$PWD/.cache/v12-02a-scope/tmp` 与 `GOCACHE=$PWD/.cache/v12-g0/go-cache`。

每条路径完成即执行定向：

```bash
go test -race ./internal/modules/core/identity/port ./internal/modules/core/identity/policy -run '^TestScopeDelegation' -count=1 -v
node scripts/check-v12-02a-scope-delegation-output.mjs --verify .cache/v12-02a-scope/cases.json .cache/v12-02a-scope/go-output.json
```

结果：严格 codec 3 组（round-trip 含 UTF-16 边界/歧义拒绝/时间精度）、三个 Scope 类型正例、全部 7 个 deny 码与判定次序、12 个端点形态、窗口/强度组合、类型化非法输入与 64 并发路径通过；70 份 Go 实际输出与冻结 G1 oracle 一致（17 accepted、49 deny、4 输入拒绝）。

完整 Linux 目标环境和共同门禁：

```bash
bash scripts/v12-02a-scope-delegation-drill.sh
```

该命令先运行原 G1 Node/Ajv/TypeScript 合同（23 夹具、4 复核、TS 编译用例），再生成 70 个独立 oracle 输入；构建两份 race Go 测试二进制，以 `env -i` 执行，复核真实 Go 输出，最后运行全量 Go、合同、架构、Docs 构建、文档链接、行尾和 diff 共 7 项共同门禁。所有命令通过；[原始报告](../../项目计划书v1/项目计划v1.2/evidence/v12-02a-scope-delegation-linux.json)记录 9/9 必需原生测试、8 份目标日志、18 份源摘要、6 份前置报告、原生二进制、oracle 输入和实际 Go 输出摘要。生成语料数值保持 JS 安全整数范围，更大 int64 值仅由 codec 单测覆盖。

没有迁移、UI、Docker 或生产 API 改动，因此没有将数据库、浏览器、Admin/Docker 门禁伪报为本切片验收。
