## 1. 本次目标

使用 software-company 的产品、架构、工程、测试、交付五个视角，审查 v1.2 权限、大模型接入和插件扩展设计，按用户允许不兼容重构的前提补齐可执行阶段与验收条件。未创建或声称额外 Agent 参与评审。

## 2. 实际完成内容

- 对照 v4 Manifest、Plugin Runtime、Identity Port、AI Provider 和可靠事件 Store，确认强制 UI/self-only、模型配置缺口和 Outbox 无回放游标等实际限制；修正“Embedding 完全没有接口”的表述。
- 权限采用业务服务提供可信资源事实、纯 Policy Core 判定，避免 Core 反向加载 Feature；明确角色、actor、委托主体、动作/范围/期限/认证强度及转授权边界。
- 目标插件包改为 `campusos.plugin/v5`，区分 UI-only、headless 和组合包，规范 typed consumes/provides、配置/授权/运行实例和贡献代次；不用旧兼容 Manager 承接所有职责。
- 将共享 Secret/Egress 放到插件和模型之前交付；模型区分 Definition、Profile、Instance、Binding，补预算结算、取消、出站同意、索引指纹和错误合同。
- 知识索引改为持久任务、分页回填与权威对账，覆盖晚提交、事件过期和删除；私人词法片段同样必须受保护，不能作为隐私保护不足时的回退。
- 拆分 G0/G1、01a/01b、03a/03b/03c、09a/09b、14a/14b。独立插件合同实验与后续真实业务接入分别验收；搜索交付不替代 RAG 或整版 Final。
- 同步权限/数据库/RAG 四份帮助文档和计划索引。全部新增目标均标为设计，不宣称当前后台已能配置。
