## 1. 本次目标

修复RSS“读取最新内容”偶发失败后再次点击成功、但错误统一显示“当前操作未获授权或资源已不可用”造成的误导；在原授权和资源边界内改善短暂网络故障的读取体验。

## 2. 完成内容

- 实际API访问记录显示，服务端时间13:33:16一次RSS读取在8.0276秒后返回503，13:33:21再次读取在1.1105秒后返回200，期间UI授权读取正常。8秒与原出站超时一致；该次现象属于读取暂时不可用，不是实际403审批拒绝。原Bridge将任意执行异常都改成`bridge.denied`，所以网络失败也显示成“未获授权”。不推断所有失败均为同一个源站原因。
- RSS源读取区分暂时性传输失败/超时和源站502/503/504，与安全策略、取消及其他状态拒绝。仅action=feed最多重试一次，等待200毫秒，继续使用原20秒总预算、单次8秒和4并发槽；重试前重新核对主体、UI证明、Grant/Consent及目标配置，成功后保留最终复核。
- 不重试地址/DNS/跳转/大小等出站拒绝、取消、无效XML和审批失败；媒体、图文导入和配置命令不自动重放。继续使用原Egress Broker、HTTPS/TLS、全部DNS答案及实际拨号IP检查，不扩大可达目标或转发用户凭据。
- SDK增加宿主显式选择的公开错误类型：固定`bridge.unavailable`、`bridge.invalid_source`、`bridge.context_changed`文字；RSS Host将网络、429/5xx、400、409映射为对应安全提示。401/403/404及其他未知异常保留原拒绝路径，原错误消息/URL/网络细节不透传；公开类型即使被改写message也只从固定表取文字。
- HTTP状态码、路由和响应DTO保持；更新SDK声明、帮助、官网及RSS合同。既有1.0.0包不重签名或替换，可能仍附通用“检查批准/同意/地址”建议，以首条具体提示判断。
