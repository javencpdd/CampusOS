## 2. 实现和逐路径定向验收

| 路径 | 实现与验证 |
| --- | --- |
| Keyring → Service | [Keyring](../../../internal/platform/security/keyring.go)只增加不暴露材料的 active ID 查询。[SecretService](../../../internal/plugin/secret.go)的 `RewrapActive` 先按既有 AAD 解密，随后用 active key 重新封装；active key 已匹配时先验真再无操作。只返回遮盖元数据，明文临时字节用后清除。[内存测试](../../../internal/plugin/secret_test.go)覆盖旧 key 退役、ID/元数据不变、空操作、缺旧 key、篡改、owner 隔离及失效 CAS；定向测试通过。 |
| PostgreSQL 原行 CAS | [仓储](../../../internal/plugin/secret_pg.go)让 Put、Revoke 和条件重封装共用同一身份 advisory lock；重封装事务只更新 `key_version`、`algorithm`、`ciphertext`、`nonce`，原行 ID/status/owner/metadata/时间戳不变。读取后发生 Put 或 Revoke 时，旧 ID 条件更新失败，不覆盖新值。[隔离 PG 测试](../../../internal/plugin/secret_rewrap_pg_integration_test.go)覆盖系统/个人值、历史行不变、失效与跨 owner 拒绝、坏密文及缺 key 不改写。 |
| 运行边界 | [配置架构](../../architecture/配置与运行边界.md)、[Secret 分流合同](../../api/v1.2插件配置Schema与Secret分流合同.md)和[插件指南](../../help/系统设计相关/插件三层授权与v3开发指南.md)写明内部单行换钥、尚无自动批量入口及历史/旧备份所需旧 key。普通配置、Secret 引用和插件权限没有因此获得新授权。 |

首次本机定向编译因 `/tmp` 的 100 MiB tmpfs 空间不足而中断，改用仓库 `.cache/v12-01b/tmp` 后原命令通过。首次隔离 PG 演练的就绪探测碰到镜像初始化的临时 Unix socket 服务；脚本改为等待正式 TCP 服务与成功查询后，原演练重新执行通过。这两次中断均未改动共享数据库，也未被计作验收通过。

## 3. 目标环境与原始证据

```bash
bash scripts/v12-01b-secret-rewrap-drill.sh --report docs/项目计划书v1/项目计划v1.2/evidence/v12-01b-secret-rewrap-linux.json
```

[演练脚本](../../../scripts/v12-01b-secret-rewrap-drill.sh)创建独占、loopback 端口、512 MiB tmpfs 的 PostgreSQL 16 容器；执行 000001–000006 迁移/checksum 与 `make database-check`，真实 PG seed 测试后 `pg_dump`、恢复到同容器新库，再以仅含新 key 的服务复读，退出清理容器。正向夹具插件的活跃旧 key 行为零；负向夹具故意保留坏密文与缺旧 key 的旧行，以验证失败关闭。PG 测试无 SKIP。[原始 JSON](../../项目计划书v1/项目计划v1.2/evidence/v12-01b-secret-rewrap-linux.json)记录本切片 implementation/automation/target_environment=`passed`，8/8 检查与 8 个源码/文档摘要匹配。

这是**活跃行**的密钥可读性与隔离备份恢复验收。历史 rotated/revoked 行和换钥前备份仍可能需要旧 key；本轮既不证明全库旧 key 可移除，也不等于 08b 的完整系统恢复。撤下旧 key 前还须使全部写入实例使用新 active key，并对实际数据库所有需读取的活跃行复核；当前无自动批量/运维入口。
