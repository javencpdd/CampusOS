## 1. 本次目标

[主计划](../../项目计划书v1/项目计划v1.2/00-v1.2版本优化计划书.md)规定 G1 依赖 G0。[上次隔离实测](v1.2.7-dev.md)证实运行时 349 条路由，而生成合同只有 348 条；`GET /api/v1` 在隔离 API 返回 200，却未列入合同。本次只闭合这条先决路径，不把上一轮的空库样本当作代表性容量验收。开工时 `git status -sb` 为干净的 `djw-update` 分支；未覆盖用户改动。

不变边界：`GET /api/v1` 仍为公开发现端点；不改变业务授权、数据库、插件安装或真实实例的数据。

## 2. 完成内容与分项状态

- 根因：`ParseServerRoutes` 的正则排除了空相对路径，并且只识别带选择器的 handler，漏掉 `public.GET("", APIIndex)`。解析器现在识别此注册形式，生成的 JSON、授权矩阵与 OpenAPI 均包含 `GET /api/v1`，所有权为 `core.platform-api`，受众为 `public`。
- 新增运行时路由集合与源码解析合同的定向测试，直接构建真实 Gin Router 比较 method/path 集合；再由 `make contracts-check` 校验落盘生成物。当前两侧均为 349 条路由，防止生成器再次遗漏运行时路径而仍自检通过。
- 实现状态：本切片代码与生成合同完成；G0 只读基线沿用 [v1.2.6-dev](v1.2.6-dev.md)。
- 自动化验收：定向 Go、全量 Go、合同、文档链接、架构、换行和差异检查均通过。
- 目标环境验收：沿用 [v1.2.7-dev](v1.2.7-dev.md) 的隔离 Linux 空库迁移、`GET /api/v1` HTTP 200 和四个只读端点各 100 次样本；本次未重新启动目标 API。两名用户与独立管理员的代表性场景、容量对照及 Windows/跨端实测仍缺，G0 未整体验收，G1 依赖仍不满足。
