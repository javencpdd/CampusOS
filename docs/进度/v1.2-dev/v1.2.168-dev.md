### 2.4 独立管理员初始化缺口与文档纠正

用户询问默认管理员时，仅查询登录标识/账号数量，没有读取密码哈希。该时点管理域为 0 账号；用户域默认 `admin` 并不是管理域账号。当前设计是同一个 PostgreSQL 数据库内两套独立身份表、凭据、会话、角色与 Token 域，不是两个物理数据库；没有新 DDL。

核查复现了初始化入口缺口：原实现只凭部署开关启用，在隔离内存测试中无请求证明也返回 200。现已修复：

- 独立 `AUTH_ADMIN_BOOTSTRAP_SECRET` 默认空/关闭，不回退到旧用户域 `AUTH_BOOTSTRAP_ADMIN_SECRET`；启用时为 16–4096 字节，部署校验拒绝复用旧值。
- HTTP 必须携带精确的一份 `X-CampusOS-Bootstrap-Secret`；Handler 仅保存其 SHA-256 摘要，恒时比较，不向正文/日志输出秘密。缺失、错误、重复、超长、未配置均拒绝；正文限制 4096 字节，响应 `private, no-store`。
- 既有生命周期仍在事务内复核有效安全管理员数量、角色绑定与必需审计/Outbox；没有绕过首次条件或 MFA，也不自动创建账号。
- 定向 race 覆盖合法首次初始化/重复拒绝、跨域登录、5 组非法证明、缺失证明、正文上限，以及配置不回退/不复用的部署测试，全部通过。
- 当前容量发布 Runner 改用独立随机管理域证明并增加缺失/错误证明拒绝路径；Python 编译通过，真实 Linux 容量目标仍待目标机复跑，旧证据不追认新源码。

当前操作说明为[独立管理员初始化与账号隔离](../../help/系统设计相关/v1.2独立管理员初始化与账号隔离.md)；文档站初始化、Docker/原生开发说明及身份架构已纠正。旧直接改 `accounts` 的管理端排障说明明确标为历史参考。当前实例新初始化配置仍默认关闭，未代用户创建账号。
