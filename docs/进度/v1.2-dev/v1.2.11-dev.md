### 路径验收结果

- **准入**：匿名后台请求 401；普通账号后台登录 401、后台读取/暂停 403。Bootstrap 登录和后台读取成功，角色 API 授予 A 后，A 的管理登录及读取成功，B 仍被拒绝。
- **暂停**：A 准入版本从 2 到 3、状态 suspended；旧管理/用户 JWT 和 Refresh 均 401，新的管理登录 401。A 可重新用户登录并读取本人私密帖子，但后台访问 403；B 不受影响。这也记录了当前用户域与管理准入的实际关系。
- **版本与最后管理员**：旧版本暂停/恢复返回 409；只剩 bootstrap 时暂停自身返回 `identity.admin_admission.last_active`，状态和版本未变。
- **恢复**：A 准入版本从 3 到 4，旧 JWT/Refresh 仍 401，重新管理登录后可进入后台。暂停和恢复各有一条带目标资源及操作者的服务审计；路由层 allow 记录不作为成功变更证据，失败命令未增加成功变更审计。
- **并发**：两名管理员由屏障同时发起互相暂停。本次实测 bootstrap 请求 200，A 请求 409/last_active；持久状态为 1 active、1 suspended，暂停主体旧会话 401。幸存管理员恢复另一方后有 2 active；最终服务审计恰有 4 次成功状态变更。脚本也允许请求在会话/准入门禁提前返回 401/403，但必须仅有一个暂停提交，不能出现零有效管理员。

这一次并发交错不构成长时间压力证明。服务层 Memory 定向测试还验证了会话撤销失败时准入回滚；未做 PostgreSQL 故障注入、跨进程恢复或强制 MFA/浏览器验收。
