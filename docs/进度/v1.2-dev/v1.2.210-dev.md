# CampusOS v1.2.210-dev 进度说明

> 日期及最新更新时间：2026-11-15（Asia/Shanghai）
> 状态：个人插件重复版本入口已修复，当前开发实例已应用；验证结果见下表。

## 1. 本次目标

解决管理端只显示RSS 2.1.0、个人插件中心却同时显示1.0.0和2.1.0的问题，使个人旧安装通过同一入口更新，准确区分安装意图、用途同意和实际可用状态。

## 2. 完成内容

- 原用户目录将“本站当前获批版本”和“本人保留的安装”按完整版本坐标合并，因此同一插件出现两张卡片。内存与PostgreSQL仓储均改为在分页前按publisher/plugin_key选择一个条目，优先本站当前可见版本；本站撤回、授权过期等不可见时，仍保留本人旧安装的清理入口，不暴露其他owner。
- 用户分页游标按插件族生成，避免版本切换造成重复；接收旧的带@version游标并转换。Admin继续按发布版本读取。没有新增DDL、改写包身份或开放授权。
- Web补充分页合并保护，优先site_state.installed所指的本站版本。实际个人版本仍在详情中显示，新版用途未同意时提示“更新前需确认用途”，确认后显式更新原安装记录。
- 更新意图已提交但current尚未切换时显示“正在更新”，不重复提供更新操作，也不开放插件页面；失败后保留显式重试入口。原enabled意图不再将旧安装标为已启用或请求已提交。永久授权显示“永久”。
- 合并后的停用、卸载使用本人实际安装版本及当前generation，读回仍使用本站目标版本；冲突仍只重读，不重放写操作。配置、用途同意、数据保留和卸载清理边界沿用现有合同。

当前开发库只读核对：RSS全局版本为2.1.0，个人唯一安装仍为1.0.0，二者observed均为stopped；本插件为runtime=none的UI-only包，不能据desired=enabled断言有两版进程在运行。旧1.0.0运行包此前已归档，本次没有恢复旧代码、代用户确认用途或改动个人业务状态。
