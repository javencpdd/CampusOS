| PostgreSQL/恢复 | [真实仓储测试](../../../internal/plugin/secret_keyring_pg_integration_test.go)用旧单密钥写系统/个人 Secret，再以新 active+旧 read key 读取和轮换；无旧 key 时旧行拒绝、新行可读。隔离库 `pg_dump/pg_restore` 后再次执行同一读写矩阵。 |

真实 PG 测试首次编译因夹具 `userID` 写成常量却取地址失败；改为变量后同一定向测试通过。测试只在脚本设置 `CAMPUSOS_SECRET_TEST_ISOLATED=1` 且数据库名是专用前缀时执行，普通全量 Go 测试会明确 SKIP 该 PG 用例。

## 3. Linux 目标环境、恢复与证据

```bash
bash scripts/v12-01b-keyring-drill.sh --report docs/项目计划书v1/项目计划v1.2/evidence/v12-01b-keyring-linux.json
```

[演练脚本](../../../scripts/v12-01b-keyring-drill.sh)在独占、loopback、tmpfs PostgreSQL 16 容器内执行 000001–000006 迁移、checksum 与 `make database-check`（含冻结 v1.1 历史门禁），真实 PG 仓储 seed 测试，`pg_dump` 至容器内快照，恢复到同容器新库，再运行恢复测试；退出自动清理容器。旧系统值、新个人值、旧行退役、跨 owner、数据库中无明文及缺旧 key 负例均实际执行，无 PG 用例 SKIP。[原始 JSON](../../项目计划书v1/项目计划v1.2/evidence/v12-01b-keyring-linux.json)记录本切片 implementation/automation/target_environment=`passed`、7/7 检查及 18 个源码/配置/文档 SHA-256。

这是 **Secret 行与密钥可用性** 的隔离恢复，不等于整系统恢复。没有重放真实生产凭据、插件实例代次、授权撤销或文件对象；这部分仍按主计划 08b 验收。当前 Docker dev 栈未运行，本轮只执行临时测试容器、静态 Compose 配置和脚本门禁，没有修改 `.env.dev.local`，没有执行 `up`/`rebuild` 或扩大端口暴露。
