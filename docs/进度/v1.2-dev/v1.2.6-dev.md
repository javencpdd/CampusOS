## 目标环境、样本与阈值

目标验证环境定义为本项目 `compose.dev.yml` 声明的 `campusos-dev` 开发栈（默认 PostgreSQL 16、DB `campusos`）上的 Linux/amd64；Windows Docker Desktop/WSL2 是后续跨端验收目标。`docker compose -f compose.dev.yml ps --status running` 本次返回空列表，故**未取得真实 PostgreSQL 状态、HTTP p95、浏览器或 Windows 证据**。配置文件默认值不代表已连接的数据库或已授权的重置目标。

- 本阶段可运行样本：`cmd/campusos-baseline/v4_test.go` 在临时目录构造 1 个 v4 源码、1 个暂存目录、1 个受校验 release、1 个损坏 release 与 1 个无效源码；所有通过/拒绝路径均由定向测试覆盖。
- 后续 HTTP 样本固定为采集器的健康、帖子、互助、二手 4 个只读 GET；目标环境启动后每端点取 100 次样本（工具上限 100，当前实现另有 1 次预热），记录状态码和 p50/p95/p99，不把未运行的样本填为 0。
- 后续权限/质量样本至少含 2 个不同 owner 的普通用户、1 个独立管理员身份、1 个外部插件、公开/私密/下架/删除帖子及个人文件；跨 owner、跨身份域和撤权后的越权成功数目标为 **0**。这些是真实环境待建夹具，不宣称已执行。
- 容量候选门禁沿用现有 [v0.13 容量预算](../../项目计划书v0/项目计划v0.13/evidence/v0.13-capacity-budget.json)：同硬件/数据量/并发下 p95 回归不超过 20%、goroutine 增长不超过 20%、heap alloc 增长不超过 50%、DB empty wait 不超过 1 秒、队列最老年龄不超过 300 秒，且请求成功。新 v1.2 参考测量尚无，因此这些是**预先声明的阈值，不是已通过的性能结果**；在 V12-08b 前须冻结硬件、并发、数据量和原始样本。
- 未来知识检索质量需另冻结中文问题集与标注答案；本阶段没有语料或召回原始结果，不能设定已达成的 Recall/引用正确率。安全质量先采用可验证的零容忍门禁：私密内容、用户/管理员 Token、宿主 Secret 越权外泄为 0。

## 受控 reset 与兼容/回退

本阶段没有执行 reset、删除、迁移或文件搬迁。现有 `scripts/migrate.sh reset` 仅校验 `CAMPUSOS_ENV=development|test` 与 `CAMPUSOS_RESET_CONFIRM=DB_NAME`，然后重建目标 DB 的 `public` schema；**尚未校验 DB Host、Compose Project 或实际数据目录归属**。因此在 V12-01a 增加目标核验/隔离演练前，不以这两个变量单独证明可安全重置。允许的未来范围只限明确识别的本项目 disposable development/test 库；`data/personal-space`、`data/plugin_data`、`data/resources` 与 `.installed` 不随数据库 reset 自动删除，文件测试继续使用临时目录。生产/未知目标一律停止。

本次 JSON 变化为加法字段和 schema 版本提升；原 `external_plugins` 保留，但语义明确为旧目录清单。回退只需撤销采集器与测试改动，既无 DB rollback 也无用户数据恢复步骤；CRLF 修复无需反向恢复到违规换行。未提交或推送。
