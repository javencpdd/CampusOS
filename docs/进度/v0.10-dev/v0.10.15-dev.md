# CampusOS v0.10.15-dev：A10b 授权决策、作用域与安全约束

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已在 A15 的统一门禁复验

## 阶段目标

让管理员 RBAC 的 global/category scope 和资源真实上下文都由服务端判定，并留下结构化授权证据。

## 实际完成内容

- Permission Service 支持稳定 Code、权限目录、角色权限绑定和 `AuthorizationRepository` 审计。
- 分配/撤销角色拒绝自我授权、权限升级、非法版主全局分配和删除最后一个 global admin。
- `Scoped("category")` 中间件只允许候选范围进入 Service；Service 再根据数据库中 Thread 的真实 `CategoryID` 做最终判断。
- 新增 `authorization_audits`，记录路由决定、角色分配/撤销和版主范围更新的最小上下文。

## 主要修改目录和文件

- `internal/core/identity/service/permission_service.go`
- `internal/core/identity/repository/pg_role_repository.go`
- `internal/core/identity/repository/authorization_repository.go`

## 架构、兼容与迁移

- 管理员 RBAC、External Plugin Host 权限和用户对插件的数据 Grant 继续独立。
- 中间件只是第一道门禁，业务 Service 不会信任客户端传来的 `category_id`、操作者或状态。

## 测试与构建结果

- 角色分配、版主 scope、未知角色、权限升级和服务层绕过的负向测试通过。
- 内容治理的跨版块授权测试通过。

## 回滚方式

可保守回退到旧 `Check/CheckScoped` 兼容路径；新授权记录不会因回滚被删除。

## 已知限制

授权审计采用可用 Repository 尽力写入，尚未与所有高风险业务写操作形成一个跨表原子事务。
