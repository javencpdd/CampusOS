# CampusOS v0.10.25-dev：编译期模块与外部插件物理隔离

> 日期：2026-07-16
> 实现状态：已完成
> 验收状态：已验收（统一门禁证据在 `v0.10.27-dev.md` 汇总）

## 阶段目标

解决 Built-in Feature 与 External Plugin 虽有逻辑分类、但实现和生命周期仍混在
Plugin Manager 与 `data/plugins` 的问题，建立可机器识别的模块目录、独立 Feature
管理面和外部插件边界，同时保留旧 API 兼容。

## 实际完成内容

- 将 Core 实现整理到 `internal/modules/core/{identity,community,moderation,userstorage}`，Built-in Feature 整理到 `internal/modules/features/*`。
- 新增 `modules/{core,features}/*/module.yaml` 和 `campusos.module/v1` Catalog，校验稳定 ID、依赖、生命周期、配置、UI 和兼容别名。
- Feature Registry 从 Module Catalog 独立注册 Core/Built-in Feature；新增 `/api/v1/features` 列表、详情、配置和启停 API。
- Plugin Manager 删除 Built-in Runtime 注册，只管理 Wasm 与受管进程 External Plugin。
- `/plugins` 只返回 External Plugin；旧 `/plugins/<builtin-alias>` 单项读取/配置/启停在兼容期内投影到 Feature Handler。
- Runtime Manifest 分开返回 `modules[]` 与 `plugins[]`，Web 注册器继续发现个人空间、课表和 Appearance。
- 包导入、CLI、市场和目录扫描拒绝 `runtime: builtin`，并拒绝模块 ID、Feature ID 或历史别名名称冲突。
- Admin `/features`、`/appearance`、`/plugins` 使用各自管理面；修复规范 Feature DTO 与旧别名投影的状态映射。

## 架构变化

编译期模块使用 Module Catalog 和 Feature Registry，External Plugin 使用 Plugin
Platform。External Plugin 不获取 `AppContext`，不能注册 Core Module，也不能
导入 `internal/*`。统一扩展总览只聚合展示，不合并生命周期。

## 兼容和迁移处理

- `runtime: builtin` 继续可解析，但不能安装或启动。
- 旧 Built-in 单项插件 URL 保留一个迁移周期；新客户端必须使用 `/features`。
- 旧数据库行本阶段不物理删除，由 `000026` 在下一阶段迁移状态并软删除活跃投影。
- Feature 停用只 Gate UI/API/事件，不删除数据库和用户文件。

## 回滚方式

按代码版本整体回退目录和 import；旧 Built-in 单项兼容 API 可支持过渡前端。不得
只回退 Plugin Manager 而保留新的 Runtime Manifest 或 Feature API，否则会产生
生命周期双重所有权。

## 已知限制

- 旧 Built-in 兼容单项 API 尚未删除，需要在后续大版本按使用统计弃用。
- `runtime: grpc` 仍是受管进程兼容名称，不是标准 protobuf gRPC。
