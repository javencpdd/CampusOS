# CampusOS v0.10.26-dev：模块数据、插件数据与资源包迁移治理

> 日期：2026-07-16
> 实现状态：已完成
> 验收状态：已验收（统一门禁证据在 `v0.10.27-dev.md` 汇总）

## 阶段目标

把 External Plugin 实现/数据、Built-in Feature 数据、Resource Package 和用户
文件落实到独立目录，并为旧布局和数据库 Built-in 记录提供可检查、可备份、可
回滚的迁移路径。

## 实际完成内容

- `data/plugins` 只保留 External Plugin；`data/plugin_data` 只保留其私有运行数据。
- 新增 `data/module_data`，个人主页内置 JSON 风格迁入 `personal-space/styles`。
- 首页包、个人主页风格和系统主题迁入 `data/resources/{homepage-packs,space-style-packs,themes}`。
- 每个受管示例包新增 `resource.json`，记录 ID、类型、版本、入口、兼容范围、来源和目录 checksum。
- CLI 新增 `resource adopt` 与 `resource inspect`，支持目录优先参数、纳管和完整性检查。
- 新增 `migrate-v10-module-plugin-layout.sh` 的 check/apply/rollback；冲突停止、不覆盖目标，并以 `layout-moves.tsv` 记录和逆序恢复。
- 新增 migration `000026_v10_module_plugin_separation`，迁移历史 Feature 状态/配置、合并 Appearance、软删除历史 Built-in 活跃插件行并增加 `platform.feature.*` 权限。
- 备份格式升级为 v2，包含 `modules`、External Plugin、插件数据、模块数据、资源包和用户文件；恢复继续接受 v1。
- Data Governance 和 Architecture Check 增加目录所有权、保留名称、资源 checksum、External Plugin 禁止导入 `internal/*` 等规则。

## 架构变化

目录所有权现在与生命周期一致：模块描述符/实现随程序编译，模块本地数据由
Feature 拥有，External Plugin 代码与运行数据独立，Resource Package 无业务
Runtime，用户文件始终通过 User Storage Core。

## 兼容和迁移处理

- 旧布局迁移不覆盖同名目标，失败时保留源目录；回滚按实际移动记录逆序执行。
- `000026` 保持已存在 Feature Store 为权威，只用旧插件行填充空配置；默认状态在旧状态迁移后插入，避免覆盖已停用功能。
- 历史 Built-in 插件行仅软删除，审计和回滚证据保留。
- 文件路径和用户公开 URL 不变；没有搬迁 `data/personal-space` 用户内容。

## 回滚方式

数据库在有备份的隔离/开发环境执行 `000026` down；生产优先 forward-fix。文件
布局执行 `migrate-v10-module-plugin-layout.sh rollback <backup-dir>`，脚本按状态
记录逆序恢复并在冲突时停止。完整恢复可使用 v2 联合备份。

## 已知限制

- 通用 Resource Package 远程签名分发与跨实例版本市场仍未实现。
- 历史 Built-in 单项 API 和软删除数据库行仍处于兼容期，不能无统计直接清理。
