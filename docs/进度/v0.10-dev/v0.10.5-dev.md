# CampusOS v0.10.5-dev：A3b 内容应用服务、审核与审计

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已在 A15 的统一门禁复验

## 阶段目标

在服务端封住“下架后编辑并直接重新公开”的绕过，并提供可恢复删除和高风险治理命令。

## 实际完成内容

- Thread Service 增加重提审核、下架、审核通过/拒绝、直接恢复、移入回收站、恢复和永久清除命令。
- RichText 发布适配 Community 状态机；下架或拒绝内容编辑后只会进入 `pending`，不能由作者直接写回公开状态。
- 新增内容治理 API，并为高风险路由声明独立 Permission Code、Operation Code 和必要的 category scope。
- 每次内容治理动作记录操作者、原因、变更前后状态及关联案例。

## 主要修改目录和文件

- `internal/community/service/thread_service.go`
- `internal/community/handler/thread_handler.go`
- `internal/richtext/service.go`、`internal/richtext/handler.go`
- `internal/transport/httpapi/router.go`
- `pkg/middleware/permission.go`

## 架构、兼容与迁移

- 旧发布、编辑和删除端点保留，内部适配到新的状态判断。
- category scope 的最终判断读取持久化帖子所属版块，不信任请求中的板块 ID。

## 测试与构建结果

- `TestTakenDownThreadCannotBeRepublishedWithoutReview` 通过。
- `TestTakenDownRichTextArticleReturnsToReviewInsteadOfPublic` 通过。
- `TestTrashAndRestorePreserveModerationState` 和跨版块授权测试通过。

## 回滚方式

可回退前端入口或关闭新命令的暴露；已有 revision、审核案例和审计记录保留，不能通过回滚删除。

## 已知限制

永久清除是高风险动作；生产保留期和异步资产清理的长期策略仍需基于实际数据量单独制定。
