# CampusOS v0.10.10-dev：A6 插件中心空态与用户语义

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已在 A15 的统一门禁复验

## 阶段目标

即使目录中没有已发布的 External Plugin，普通用户也能理解原因、申请路径和数据边界。

## 实际完成内容

- Manifest 增加可选 `experience` 元数据：用途、数据使用、风险、停用后的数据行为、维护者和文档入口。
- `000024` 为 `plugin_catalog_entries` 增加体验元数据，旧 manifest 使用安全默认文案。
- 用户插件中心展示用途、授权、数据用量、风险、关闭后行为及“推荐或申请安装插件”入口。
- 管理端保留目录发布治理，不会把已安装、draft 或 Built-in 功能误显示为普通用户可安装项。

## 主要修改目录和文件

- `internal/plugin/manifest.go`
- `internal/plugin/market.go`、`internal/plugin/market_pg.go`
- `migrations/000024_v10_plugin_catalog_experience.{up,down}.sql`
- `web/src/modules/plugin-center/pages/PluginCenterView.vue`
- `web/tests/plugin-center.spec.ts`

## 架构、兼容与迁移

- Catalog 仍只展示管理员发布的 v2 External Plugin；不会在生产启动时自动导入示例代码。
- 用户授权、管理员 RBAC 和插件 Host API 权限继续是三套独立授权合同。

## 测试与构建结果

- `web/tests/plugin-center.spec.ts` 通过。
- `pnpm --dir web test:component` 与 Web build 通过。
- `make database-check` 通过 `000024` schema contract。

## 回滚方式

旧 manifest 忽略可选体验字段仍可解析；撤回展示层不影响 Runtime、Grant 或受管数据。

## 已知限制

本地目录不是公共插件市场；发布、审核和安装仍需要管理员显式操作。

## 下一阶段任务
