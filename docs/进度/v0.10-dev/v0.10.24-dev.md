# CampusOS v0.10.24-dev：权限配置入门文档

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已验收

## 阶段目标

为 `localhost:3002` 增加一条面向首次使用者的权限配置路径，以通俗、逐步递进的方式说明角色、Permission Code、作用域、版主动作上限和审计，并确保教程与当前 Admin 页面、后端授权规则及 v0.10 安全边界一致。

## 实际完成内容

- 新增 `/guide/permission-configuration`，从权限心智模型开始，依次讲解部署前置检查、权限矩阵、自定义角色创建、权限调整、用户角色分配、板块版主、允许/拒绝验证、撤销和授权审计。
- 使用 `content_reviewer` 作为最小权限示例，明确高风险权限不能默认全选，操作者不能授予自己未拥有的权限。
- 说明系统角色只读、普通自定义角色按全局范围分配、`moderator` 必须配置板块范围、最后管理员保护和系统基础角色保护。
- 明确 Admin 前端当前只允许 `admin/super_admin` 登录，自定义角色拥有后端 Permission Code 不等于获得 Admin 页面准入。
- 区分管理员 RBAC、External Plugin Host 权限和用户插件数据授权，避免管理员审批与用户授权混用。
- 将教程加入文档站顶部导航、侧栏、首页、完整入门路径、docs-site README、仓库文档门户和 Admin“相关资料”。
- 将新页面加入 Chrome 文档深链接回归。

删除新教程，并回退 VitePress 导航、首页、入门路径、Admin 资料入口、浏览器断言和文档门户链接即可。无数据库回滚和数据清理步骤。

## 已知限制

- 当前 Admin 前端仍按 `admin/super_admin` 角色准入，尚未提供按自定义 Permission Code 动态生成的委派式管理工作台。
- 通用自定义角色当前按全局范围分配；板块范围使用专门的 `moderator` 配置。
- 授权审计与业务写入尚不是同一跨表原子事务，设计级限制继续以 v0.10 权限文档为准。
