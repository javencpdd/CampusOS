# CampusOS v0.10.4-dev：A3a 内容状态合同与追加迁移

## 阶段目标

让发布意图、审核结论和删除状态彼此独立，先用兼容映射保留旧 `threads.status`。

## 实际完成内容

- 新增 `internal/community/domain/content_state.go`，定义 `publication_status`、`moderation_status`、`deletion_status` 和公开可见谓词。
- 新增 `000023_v10_content_governance`：给 `threads` 追加状态列、回填历史数据、索引、修订表、审核案例表和治理动作表。
- RichText 本地状态扩展为可表达待审核和回收站，但 Community Thread 是治理事实。
- Repository 在读写时规范化新状态并维护 legacy `status` 投影，避免旧客户端立即失效。

## 主要修改目录和文件

- `internal/community/domain/content_state.go`
- `internal/community/domain/thread.go`
- `internal/community/repository/*thread*`
- `internal/community/repository/content_governance_repository.go`

## 架构、兼容与迁移

- 公开读取统一要求 `published + clear + active`。
- 旧 `status` 仍作为兼容投影；未删除列、旧查询或历史数据。

## 测试与构建结果

- Community 与 RichText 状态转换合同测试通过。
- `make migrate-status`、`make database-check` 通过。

## 回滚方式

开发/演练环境可使用对应 down migration；生产优先保留新增列和审计数据，以前向修复回退行为。

## 已知限制

修订和审计记录目前是应用层写入路径，尚不承诺与所有业务表更新形成单一跨表原子事务。
