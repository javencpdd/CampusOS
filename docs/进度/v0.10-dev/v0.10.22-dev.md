## 架构与安全变化

- HTTP 授权写路径默认拒绝，受信任内部兼容方法不再被传输层隐式使用。
- 最后管理员不变量由 Service 的普通计数检查提升为 Repository 原子命令；PostgreSQL 使用事务和角色级 advisory lock。
- 受管进程 Runtime 仍保留历史 `grpc` 类型名，但事件和 Extension 都只允许显式 loopback HTTP 端点；没有标准 protobuf gRPC 的虚假承诺。
- 文档入口版本成为 release-check 可执行合同，避免 README、docs-site 和服务版本再次漂移。
- 应用版本由 `internal/platform/version` 统一提供；在线健康接口和 API Index 已分别验证为 `0.10.0`、`v0.10.0`。

## 兼容与迁移处理

- 无新增数据库 migration，不移动或删除现有表、目录、API 和用户数据。
- 未声明 `event_url` 的历史进程插件继续运行，事件仅记录；不会再探测随机本机端口。
- 旧 Role Repository Adapter 保留非原子兼容分支，生产 PostgreSQL 与 Memory Adapter 使用新原子接口。
- `openapi-v0.6-current.yaml` 等文件名继续保留，内容由 v0.10 路由重新生成。

## 回滚方式

按本阶段文件回退 Handler、Repository 可选接口、Runtime 和文档门禁；不执行 migration down 或删除用户数据。回退最后管理员原子接口时，Service 与两个 Adapter 必须作为一个原子变更回退。

## 已知限制

- 授权审计尚未与所有高风险业务写入共享同一数据库事务。
- 标准 protobuf gRPC、标准 MCP、生产第三方消息 Adapter 和远程公共插件市场仍未实现。
- 记录保留期、Legacy Resource Source 和 `user_space_contents` 的物理迁移需要真实统计和独立回滚工具。
