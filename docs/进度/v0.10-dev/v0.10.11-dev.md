# CampusOS v0.10.11-dev：A7 可运行官方示例插件

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已在 A15 的统一门禁复验

## 阶段目标

提供一个不会自动进入生产目录、但开发者可以真实编译、验证、打包并理解其数据边界的 v2 External Plugin 示例。

## 实际完成内容

- 新增 `examples/plugins/v2-managed-example`，以“校园个人便签”演示 system/user 受管集合、用户 txt 附件、Grant、导出和卸载后数据保留语义。
- 示例包含独立 `go.mod`、Runtime、HTTP 健康/扩展入口、单元测试、中文 README 和 v2 manifest。
- README 明确禁止数据库直连、JWT 私钥、用户 Token 和原始宿主路径；业务数据只能走 Host API 或用户受管接口。
- 发布门禁新增 `campusosctl plugin dev examples/plugins/v2-managed-example --json`，并清理生成的本地二进制。

## 主要修改目录和文件

- `examples/plugins/v2-managed-example/`
- `scripts/release-check.sh`
- `.gitignore`

## 架构、兼容与迁移

- 示例只在显式开发命令中构建，不会由服务启动、目录扫描或市场同步自动安装/发布。
- 当前 `runtime: grpc` 是现有进程 Runtime 的兼容名称；示例的 Extension Gateway 使用受限 loopback HTTP 合同，不把它宣称为稳定 protobuf gRPC 协议。

## 测试与构建结果

- 示例自身 `go test ./...` 通过。
- `go run ./cmd/campusosctl plugin dev examples/plugins/v2-managed-example --json` 通过，并被 `make release-check` 覆盖。

## 回滚方式

删除示例目录和相应门禁行即可；它没有自动写入用户数据、数据库或生产 Catalog。

## 已知限制

该示例验证当前进程 Runtime 与 Host/Gateway 边界，不是标准 protobuf gRPC SDK 示例。标准化远程 gRPC 合同应作为独立协议版本任务实现，不能把现有 Runtime 名称误当成协议承诺。
