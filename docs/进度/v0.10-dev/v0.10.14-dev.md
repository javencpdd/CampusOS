# CampusOS v0.10.14-dev：A10a 权限目录、稳定 Code 与路由操作

> 日期：2026-07-16  
> 实现状态：已完成  
> 验收状态：已在 A15 的统一门禁复验

## 阶段目标

把业务权限、传输层操作和数据库数字 ID 分开，且让路由合同、OpenAPI 和运行时目录使用同一来源。

## 实际完成内容

- 新增 `permissioncode`，统一 `<domain>.<resource>.<action>` 的稳定命名和 legacy 映射。
- `000025` 建立 `permission_definitions`、`role_permissions`、`route_operations` 与 `route_permission_bindings`，从旧 `permissions` 追加回填。
- Owned Router 支持显式 `PermissionCode`、`Operation`、`Scoped` 和 legacy aliases。
- Identity Module 在启动时同步 Route Descriptor，Server 不直接依赖 Identity 的 PostgreSQL Repository。
- 合同生成物更新路由矩阵、OpenAPI 与权限目录。

## 主要修改目录和文件

- `internal/core/identity/permissioncode/`
- `internal/core/identity/repository/authorization_repository.go`
- `internal/platform/route/registry.go`
- `internal/transport/httpapi/owned_router.go`
- `internal/projectaudit/routes.go`
- `migrations/000025_v10_authorization_catalog.{up,down}.sql`
- `docs/api/`

## 架构、兼容与迁移

- 旧 `permissions(resource, action)` 和 `http.*`/`httpapi.*` alias 继续存在；未知 Code 默认拒绝，不会因兼容放宽权限。
- 路由的 `module_owner` 在合同生成时检查，包级处理器也有明确 Core owner。

## 测试与构建结果

- `make contracts-check` 通过，生成的 OpenAPI 和路由授权矩阵已同步。
- `make architecture-check` 通过，未出现无主 Admin 路由或新增具体 Repository 跨模块边界。
- `make database-check` 通过 `000025` 的 schema contract。

## 回滚方式

授权服务可对可映射旧权限保守回退；新目录表保留，生产不依赖 down migration 删除证据。

## 已知限制

Operation Code 已是目录化合同，但没有承诺外部 API 的永久稳定版本；未来稳定化仍需版本与弃用策略。
