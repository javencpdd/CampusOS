## 4. 架构变化

Feature 路由保持静态注册。Feature 关闭时不会运行时增删 Gin 路由；统一 Path Gate 拒绝业务请求。仅经过
`AllowedPath` 白名单声明的只读状态接口能越过 Gate，用于客户端可靠显示停用状态。该例外不暴露写入、
详情、列表、配置、数据库或内部 Service。

校园二手继续遵循 Community Core 与 Built-in Feature 的边界：Community 拥有基础 Thread、Revision、板块策略、
回复和治理；Secondhand 只拥有 Detail 与交易状态。外部插件、SDK、MCP、Agent Runner 与浏览器均不能获得
Repository、数据库事务或 AppContext。

## 5. 兼容和迁移处理

- v12 migrations 继续只追加，历史表、URL 和普通 `POST /threads` 合同未删除。
- `000035` 的隔离 up/down/up 脚本补充了价格、币种、Thread Type 和 Detail 作者守卫，但尚未在当前受限
  环境执行。
- 生产回滚继续采用兼容 forward-fix 或可验证备份恢复。down migration 仅用于隔离演练，不是生产数据删除方案。
- v12 未取得 Final 验收前，版本与 README 保持现有发布基线，避免向用户或开发者错误宣称已发布。

## 7. 回滚方式

当前尚未发布 v0.12，因此不进行版本回滚。继续使用现有 `0.11.0` 发布基线；v12 代码问题优先以兼容
forward-fix 修复。数据库演练完成后，生产恢复只能使用备份、维护窗口和恢复后核对，不能依赖 down migration
删除用户或业务数据。

## 8. 已知限制

- v0.12 不能声明完成：C3 的真实 PostgreSQL up/down/up、全量 database-check、restore drill 和浏览器 Smoke
  尚无可复现实证。
- 当前资源包 compatibility 元数据仍是既有 `>=0.10.0 <0.11.0` 范围；应在 Final 版本升级时按实际
  兼容范围统一修订并重新 inspect，不能在未验收时单独声称支持 `0.12.0`。
- 运行本地浏览器 workflow 会创建测试账号和内容，必须在专用测试数据库和可控制的前端/API 栈运行。

## 9. 下一阶段任务

在具备 Docker/PostgreSQL 权限的隔离环境依次执行：

1. `./scripts/test-v12-secondhand-migration.sh`，随后执行 `make database-check`。
2. `make restore-drill`，核对备份恢复后的 migration、表、约束和数据数量。
3. 启动专用测试栈，执行浏览器 Smoke、认证 workflow、互助和二手 PC/移动端流程。
4. 完整执行 `make release-check`。全部通过后，才更新版本、SDK、OpenAPI、README，并将 C3 和 Final
   标记为已验收。
