# CampusOS v0.12.20-dev 分组导航与结构化图文加固说明

> 日期：2026-07-18
> 阶段：C3.6 分组导航与结构化图文加固
> 实现状态：完成
> 验收状态：已验收（含 PC/手机分组点击；真实图文发布全流程仍归 Final）

## 1. 本阶段目标

修正前台把板块分组和所有子板块平铺展示的问题，使用户点击分组后再选择子板块；让校园互助和校园二手
同时支持兼容纯文本与安全图文正文、图片上传插入和发布前预览，并在管理端作为图文文章的二级功能展示，
但不把三个 Built-in Feature 的启停和数据生命周期耦合。

## 2. 实际完成内容

- 前台公开导航把活动 group 渲染为点击菜单，只在菜单中列出活动且未关闭的直接子 board；根级 board
  保持直接链接，空分组、关闭和归档节点不显示。选择子板块后进入携带 `category_id` 的帖子列表。
- 新增 Community Core `contentbody` 合同，统一处理 `markdown` 兼容纯文本和 `safe_html` 图文正文。
  白名单清洗会移除脚本、iframe、表单、事件属性、危险 URL/CSS，并限制正文大小、节点数和嵌套深度。
- RichText 的既有清洗入口改为调用 Community Core Adapter，原 `richtext_article` API、错误类型和 Article
  Detail 保持不变，避免形成第二套清洗规则。
- User Storage Core 新增正文图片能力。图片保存到
  `data/personal-space/<user_id>/img/content/<random-name>.<ext>`，只接受 JPEG、PNG、GIF、WebP；在
  multipart 解析前限制请求体，随后检查单文件大小、MIME、安全路径和用户总配额。
- 新增 `POST /api/v1/content/preview`、`POST /api/v1/content/assets/images` 和公开只读图片路由；路由
  所有权、OpenAPI、授权矩阵和机器合同已同步。
- 互助、二手创建和编辑接受 `content_format=safe_html`，保存前执行同一清洗器；旧请求省略格式时继续
  保存为 `markdown`，编辑已有图文而省略字段时保留原格式。列表只显示纯文本摘要，详情和通用 Thread
  页面以响应式样式显示已清洗图文。
- 新增共享 Web 编辑器，提供图文/纯文本分段切换、受控排版命令、图片上传并自动插入、缩略图大图预览和
  服务端最终正文预览。移动端工具栏换行，图片宽度不超过正文容器。
- Module Descriptor 增加 `presentation_parent`，互助和二手在 Admin 中显示为“图文子功能”；该字段仅
  用于展示，Feature Registry 继续分别保存三个功能的目标状态。互助和二手显式依赖始终启用的
  `core.user-storage`，不依赖 RichText Feature 是否启用。
- 首次当前工作树冷启动发现三个既有 Category 路由的 operation code 使用连字符，与数据库
  `chk_route_operation_code` 不一致，导致路由权限目录同步事务回滚。现已改为下划线稳定 code，旧值进入
  `legacy_aliases`；Platform Route Registry 同步数据库格式规则，非法 code 会在注册/合同测试阶段失败，
  不再等到 PostgreSQL 冷启动才暴露。

## 4. 架构变化

安全正文清洗属于 Community Core，因为它约束写入基础 Thread 的内容；通用正文图片属于 User Storage
Core，因为互助、二手和未来的编译内内容功能都需要稳定的用户所有权、配额和安全路径。校园互助、校园
二手和完整图文文章仍是三个独立 Built-in Feature：互助拥有 `mutual_aid` Detail/状态机，二手拥有
`secondhand` 价格和交易状态，图文文章拥有 Article Detail、草稿和发布生命周期。

`presentation_parent` 是管理端能力分组元数据，不是 Module `Dependencies()`，也不建立父子级联启停。
因此停用完整图文文章不会使互助或二手失效，停用任一子功能也不会删除其 Thread、Detail 或图片。

Route Registry 现在在进程装配阶段验证和 PostgreSQL 相同的 operation code 格式。Category 三个旧 code
从连字符迁移为下划线时不改 HTTP 路径、Permission Code 或审计要求，旧 code 仅作为查询兼容别名保留。

## 5. 兼容与迁移处理

- 本阶段不新增数据库 migration，不移动历史 Thread、RichText 资产或个人空间文件。
- 原 `markdown` 值及省略 `content_format` 的客户端继续可用；`plain_text` 只作为输入别名，持久化仍使用
  `markdown`，避免旧前端出现未知格式。
- 新 API、DTO 字段和 Module Descriptor 字段均为加法；现有 RichText、互助和二手路径不删除。
- 现有 Feature 开关、板块类型策略和数据保留规则不变；二级展示不会扩大权限或板块作用域。
- 回退前端时新 `safe_html` Thread 仍可由后端安全读取，但旧页面可能显示原始标签文本，因此生产回退应
  优先 forward-fix，或在维护窗口暂时停止新的图文写入。

## 7. 回滚方式

前端导航和编辑器可以独立回退，但回退前必须停止创建新的 `safe_html` 互助/二手内容，或确认旧页面不会把
标签作为普通文本错误展示。后端回退优先保留 Community 清洗器和 User Storage 图片只读路由，以保证已发布
正文可继续显示。图片文件属于用户数据，不得在回滚中批量删除；Feature 状态回滚也不得清理 Thread、Detail
或个人目录。本阶段没有数据库 down 操作。

## 8. 已知限制

- 上传后放弃发布会留下归属明确但未被正文引用的图片；当前仍计入用户配额，后续需要引用索引、保留期和
  有审计的延迟回收，不能直接扫描删除。
- 当前编辑器提供受控 HTML 模板和源内容编辑，不是完整所见即所得编辑器；更复杂的 Editor Provider 仍按
  RichText 的扩展边界演进。
- 当前开发库的 group 点击已在 PC/手机真实浏览器验证；真实图片上传、互助/二手发布编辑、回收恢复和
  最终候选数据库上的完整 PC/移动端截图仍属于 v0.12 Final，不能由本次导航检查替代。
- 当前开发数据库的四端冷启动已通过，但这不替代隔离最终候选库、恢复后数据核对和完整发布门禁。
- 图片公开读取依赖随机文件名；首版没有独立 CDN、缩略图派生和图片内容审核流水线。
