## 1. 本阶段目标

在不重建 Category 数据模型的前提下，让既有板块写入参与 TxKernel/Reliability，补齐颜色、节点状态和
乐观版本合同，并使每次成功状态转换都生成独立的审计和 Outbox 证据。

## 2. 实际完成内容

- 新增 `000032_v12_category_hierarchy`，为既有 `categories` 表追加 `node_kind`、`lifecycle_status`、
  `version` 和 `color`，以及细粒度 `community.category.*` Permission Code。
- PostgreSQL Category Repository 改为从 Context 取得 `transaction.ExecutorFor`；创建、更新、移动、归档
  和恢复不再绕开可靠命令事务直接使用 pool。
- `CategoryService` 增加 actor-aware 可靠命令、版本冲突检测、required command audit、Outbox 事件与
  Memory Profile 快照回滚支持。
- 创建和更新正式支持严格颜色格式，管理端颜色选择器与后端 DTO/数据库约束使用相同的
  `#RRGGBB` / `#RRGGBBAA` 合同。
- 修复可靠事件键的实际缺陷：不再按 `command + category ID` 复用固定 Outbox 幂等键，连续更新同一
  board 现在各自产生正确的事件负载和命令审计。

## 4. 架构变化

Category 继续由 `core.community` 独占。Service 负责业务不变量和可靠命令编排，Repository 只经显式
事务 Port 读写，Outbox 只在业务事实成功后入队。External Plugin 和 Built-in Feature 没有获得直接
写入 `categories` 或 Reliability 内部 Store 的能力。

## 5. 兼容和迁移处理

- 历史 Category 仍在原表和原 ID 下读取；平面公开列表不改变。
- 旧 `category:write/delete` 通过兼容映射保留，新的管理调用改用 `community.category.*` Code。
- `000032` 不自动修复历史三级、循环或孤立 parent；预检失败会中止并给出节点 ID。
- down migration 仅供隔离演练，生产使用 forward-fix 或备份恢复。

## 7. 回滚方式

临时回退旧二进制前，先把 Category 写入口切为只读，防止旧代码绕过 version、颜色和可靠命令边界。
生产保留新列、审计和 Outbox，使用 forward-fix；不直接执行 down migration 或删除可靠证据。

## 8. 已知限制

  幂等合同不属于 B1。
- 节点层级、归档影响和前端树形操作在 B2/B3 完成。
