## 1. 本阶段目标

将 A3 Challenge/Ticket 与 A4 邮件投递接入公开注册流程。新账号必须证明邮箱拥有权；旧的一步式
注册请求不能再创建状态为 `unverified` 的账号。

## 2. 实际完成内容

- 新增公开端点：
  - `POST /api/v1/auth/registration/challenge`
  - `POST /api/v1/auth/registration/verify`
  - 已保留的 `POST /api/v1/auth/register` 现在要求 `challenge_id` 和 `ticket`。
- 注册 Challenge 固定使用 `registration` Purpose，客户端不能从请求中选择其他 Identity 用途。
  Challenge 请求不会判断或披露邮箱是否已注册；唯一性仍在最终注册命令处理。
- 旧一步式注册稳定返回 `400 identity.verification_required`，不会写入 `users`、`accounts`、audit
  或 Outbox。
- Code 校验成功后返回短生命周期 Ticket；最终注册在同一个 Reliability/TxKernel 命令中锁定并消费
  Ticket、创建 User、创建 `verified` Email Account、写命令审计和只含 `PublicUser` 的创建事件。
- 任一步失败会整体回滚。新增测试覆盖 Account 写失败时用户不残留、Ticket 未消费；同一 Ticket
  重放返回稳定 `identity.registration_verification_invalid`。
- Memory Profile 现在也保存受控 Email Account 和凭据，不能再通过无凭据的内存登录路径绕过
  `verification_state` 检查。
- 用户前台注册页增加验证码发送、邮箱锁定/更换、六位 Code、内存 Ticket、60 秒发送冷却和手机
  单列布局。Ticket 不写入 localStorage、URL 或日志。
- OpenAPI、路由/授权矩阵、API/帮助文档、官方 docs-site、ADR 和 `make identity-registration-check`
  同步更新。当前 External Plugin SDK 不是身份注册 SDK，明确不暴露 Identity 内部写接口。

## 4. 架构变化

`UserService.Register` 保留为 fail-closed 兼容入口，所有实际公开注册只经
`RegisterVerified`。该服务只依赖窄的 `RegistrationTicketConsumer`，不读取 Challenge Repository
或 HMAC key；Challenge Service 则通过 `ConsumeTicketForCommand` 加入外层注册事务，不启动嵌套
可靠命令。

新增 Account 写入只创建 `verified` 状态，移除了 Identity Repository 中无人调用的 unverified
Account 创建路径。登录读取 Account verification state，仅允许 `verified`、`legacy_accepted` 和
`system_managed`，为 A6 Session 切换保留一致的身份判断。

## 5. 兼容和迁移处理

- 没有新增 migration；A5 使用 A2 的 `000028` Account 状态列和 A3 的 `000029` Challenge/Ticket 表。
- 历史 `legacy_accepted` 与 `system_managed` 账号继续登录；A5 只收紧新注册。
- `/auth/register` 路径和成功 `201 User` 响应保留，但请求合同增加两个必填字段。这是明确安全不兼容：
  旧客户端应升级为三步流程，不提供绕过开关。
- API 回退时必须先关闭公开注册或进入受控维护，不能恢复会产生未验证账号的旧二进制。生产故障采用
  forward-fix；Challenge、Ticket digest、audit 和 Outbox 保留用于诊断。

## 7. 已知限制

- Fake 邮件 Provider 不展示验证码；本地人工注册应使用隔离 SMTP，自动流程使用 Challenge/HTTP
  handler 测试。真实 SMTP delivery 的 at-least-once 语义和脱敏边界保持 A4 设计。
- 尚未实现 Session、Refresh Token、Cookie/CSRF、logout 或密码重置。登录响应仍使用 A5 之前的
  Token 形态，A6 会进行明确的强制重新登录切换。
- Challenge 对重复请求的旧 Challenge 失效策略、模板国际化和多 Provider 主备仍属于后续安全/运维
  优化，不改变本阶段 Ticket 一次性消费保证。
