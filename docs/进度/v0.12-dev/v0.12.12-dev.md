# CampusOS v0.12.12-dev 进度说明

> 日期：2026-07-17  
> 阶段：C0 作者内容写入原子化  
> 实现状态：完成

## 1. 本阶段目标

将普通 Thread 创建、作者编辑、作者回收以及 RichText 的 Thread、Revision、Article Detail、required
command audit 和 Outbox 收敛到单一可靠事务，移除 RichText 创建失败后的补偿式回收。

## 2. 实际完成内容

- `ThreadService` 新增作者可靠命令边界；普通创建、更新、作者回收和 Built-in Feature 基础 Thread 更新在
  成功提交前不刷新缓存、不发布内存事件。
- `RichText Service` 新增外层可靠命令。Create/Update/Publish/Offline/Delete 和管理员下线、恢复、删除都
  在同一命令内协调 Community Gateway 与 Article Store。
- `PgStore` 改为通过 `transaction.ExecutorFor` 参与当前 TxKernel；`MemoryStore` 新增 Snapshot/Restore。
- 删除 `richtext_create_rollback` 补偿调用，创建 Article Detail 失败时直接回滚 Thread 与 Revision。
- 新增故障注入单元测试和 `make v12-failure-injection-check`，验证 Revision 或 Article Detail 失败不会留下
  Thread、Article、Audit 或 Outbox。

## 4. 架构变化

RichText 继续只消费 Community `ContentGateway`，没有获得 Repository 或数据库连接。它在外层 Reliability
命令中调用 Gateway；内层 Community 写入识别 active transaction，只参与同一事务，避免重复 Audit/Outbox。
External Plugin、MCP 和 Agent Runner 没有该事务能力。

## 5. 兼容和迁移处理

- 既有 HTTP 路由、ID、Article 状态、资产 URL 和回收站数据不变；本阶段无 migration。
- 正式 Module Graph 将 RichText 声明为依赖 `core.reliability`。旧的隔离构造仍可直接运行，生产装配不使用
  该回退路径。
- 文件上传仍在事务外，并由 User Storage 管理路径和配额；不伪造跨文件系统事务。

## 7. 回滚方式

本阶段无 schema 变化。若出现运行问题，优先用 forward-fix 修正命令逻辑；不得恢复 RichText 创建失败后将
Thread 移入回收站的补偿行为。已存在的历史回收站内容保持不变，按正常治理流程处理。

## 8. 已知限制

- `thread_type`、板块类型策略和正式 Participant 合同尚未实现，当前 RichText 仍以兼容的
  `content_format=richtext_article` 识别。
- 图片上传与文章绑定之间仍是受控的跨存储流程，不会在数据库事务中调用文件系统。
