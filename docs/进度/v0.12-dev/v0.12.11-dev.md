# CampusOS v0.12.11-dev 进度说明

> 日期：2026-07-17  
> 阶段：B3 Category 前端闭环  
> 实现状态：完成  
> 验收状态：已验收

## 1. 本阶段目标

将 B1/B2 的两级 Category 合同完整接入管理端和用户端，避免公开与管理读取冲突，保证桌面和移动端
均能扫描、编辑和使用可发帖 board。

## 2. 实际完成内容

- 管理读取改为 `/api/v1/admin/categories`、`/tree`、`/:id`，避免同一路径组下与公开 `GET /categories`
  发生 Gin 路由冲突或将归档数据暴露给普通访问者。
- 管理端 `CategoryManageView` 提供 group/board 树、颜色色块与输入、版本显示、创建、编辑、board 移动、
  归档影响确认和恢复。固定工具按钮使用图标与 tooltip，窄屏会重排并隐藏非关键列。
- 用户端导航读取公开 tree，将 group 作为分组标识，将可用 board 作为筛选入口；发帖和富文本创建表单只
  列出 active、未关闭的 board。
- 管理端数据库架构页同步 `000032`、Category 新字段和 group-to-board 自关联；API 索引、docs-site、
  架构 ADR、管理员说明与正式计划同步。

## 4. 架构变化

前端按公开/管理的 API 边界读取数据，不把前端过滤当作权限校验。Admin 的树形管理只调用 Core Community
管理路由，Web 只消费公开活动节点；最终写入资格仍由后端 Service 校验。数据架构页仍是 migration 驱动的
只读可视化，不读取真实业务记录或 Secret。

## 5. 兼容和迁移处理

- 平面公开读取、原 Category 写路径和旧 DELETE 路径保持可用；新 Admin 读取路径是加法命名空间。
- 已归档 Category 不会出现在用户导航或创建选择，但管理端仍可恢复，用户数据不被删除。
- 生成的路由清单、OpenAPI 与授权矩阵已经包含新路径和 Permission Code。

## 7. 回滚方式

前端回退可临时恢复旧平面列表视图，但 API 仍保持 `000032` 的安全写入边界。若必须回退服务端，先停止
Category 管理写操作并使用 forward-fix；不得让旧二进制重新对已迁移数据执行物理 DELETE。
