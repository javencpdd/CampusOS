## 1. 本阶段目标

将校园二手落实为独立的 Built-in Feature：以固定 Thread Type 和一对一 Detail 保存结构化物品信息，
提供人民币分价、成色、交付方式、交易状态、作者编辑和前台浏览，同时继续由 Community Core 管理基础
帖子、回复、可见性、审核、回收和审计。

## 2. 实际完成内容

- 新增 `feature.secondhand` 模块描述符和 `internal/modules/features/secondhand`。它只依赖 Community
  `ContentGateway`、`ContentQuery` 与 Reliability Port，不导入 Community PostgreSQL Repository。
- 新增 `secondhand_details` 和 migration `000035_v12_secondhand`。Detail 固定保存金额（分）、仅
  `CNY`、成色、交付方式、交易状态、粗粒度地点、作者和乐观并发版本。
- 数据库 CHECK、外键、索引和触发器共同保证 Detail 一对一指向 `secondhand` Thread、金额不为负、币种/
  枚举/版本/地点合法，且 Detail 作者始终等于 Thread 作者。
- 创建经 Community Structured Thread Command，在同一可靠命令内写入 Thread、Revision、Detail、command
  audit 和 Outbox；Detail 持久化失败时不会留下半写基础帖子、审计或事件。
- 交易状态机固定为 `available -> reserved/sold/closed`、`reserved -> available/sold/closed`；`sold`
  和 `closed` 为终态。业务状态不改写 Community 的发布或审核事实。
- 新增公开状态、列表、详情和认证作者的创建、编辑、状态更新 API；编辑和状态更新均使用 `version`，拒绝
  陈旧版本、非作者和错误 Thread Type。
- 新增 Web 端校园二手列表、关键词/板块筛选、发布、详情、编辑和状态操作页面，并注册用户前台路由。发布页
  会检查目标 board 是否显式允许 `secondhand` 类型。
- 二手路由已接入 Feature Path Gate、服务器 Module Graph、HTTP owner 映射、生成路由/授权合同、schema
  contract、数据库审计和管理端数据架构图。Path Gate 只显式放行只读 `GET /secondhand/status`，使停用
  时仍可返回 `enabled=false`；Feature 停用不会影响普通讨论或历史基础 Thread 的治理。

## 4. 架构变化

Community Core 继续拥有 Thread、Revision、板块类型策略、回复和全部内容治理状态。Secondhand Feature
只拥有 `secondhand_details` 与交易状态机，并通过编译内 Structured Participant 参与当前事务。External
Plugin、SDK、MCP、Agent Runner 和浏览器均不能获得数据库、Repository、AppContext 或 Participant 能力。

Feature 处于停用状态时，统一 Path Gate 和 Service 会拒绝二手 Feature API；普通讨论、历史基础 Thread
以及 Community 的审核、下架、恢复和审计保持可用。activation mode 为 `restart`，修改启停状态后需要
重新启动服务。

## 5. 兼容和迁移处理

- `000035` 只追加 Detail 表、约束、索引和触发器，不移动既有 Thread、URL、用户数据或普通
  `POST /threads` 合同；后者仍只创建 `discussion`。
- 管理员必须同时启用 Feature 并在目标 board 显式允许 `secondhand`；启用 Feature 不会自动开放所有
  板块。
- 生产问题优先采用兼容 forward-fix 或经过验证的备份恢复。down migration 仅用于隔离 up/down/up 演练，
  不作为生产数据删除方式。

## 7. 回滚方式

先关闭二手入口并发布兼容 forward-fix；基础 Thread 仍可由 Community 读取和治理。隔离环境可以使用
`000035` 做 up/down/up 演练。生产恢复必须使用同一时间点备份、受控维护窗口和恢复后数量/约束核对，
不能以删除 Detail 表作为常规回滚。

## 8. 已知限制

- 不提供支付、订单、聊天、担保、物流、地址托管或争议仲裁；用户只能通过帖子回复自行约定。
- 首版只支持 `CNY`，不处理汇率和其他币种。
- 列表当前逐条读取一对一 Detail；数据量显著增长前，应在保持 API 不变的前提下增加受测的批量查询。
- C3 与 Final 的 Docker 迁移、恢复和浏览器 Smoke 需要在具备授权的环境中继续执行。
