# CampusOS v0.12.25-dev Final 发布验收说明

> 日期：2026-07-19
> 阶段：Final 全链路验收

## 1. 阶段目标

封闭 v12 遗留的环境级证据：在最终候选上完成全量测试、数据库审计、完整迁移演练、备份恢复、冷启动、
前后端构建、真实浏览器流程和版本同步，不以静态检查替代恢复或 PC/移动端验收。

## 2. 实际完成内容

- 将应用、Go/TypeScript SDK、OpenAPI、路由矩阵、docs-site 和 README 同步为 `0.12.0`/`v0.12`。
- 路由合同版本改为从统一应用版本派生，避免下个版本再次遗漏硬编码的 `v0.11`。
- 修复浏览器门禁与 v12 Session 安全模型不一致：Access Token 继续只驻留内存，测试从登录响应取得临时值，
  并断言 Local/Session Storage 不保存 Token。
- 整页导航会通过 HttpOnly Refresh Cookie 轮换 Session；越权 API 测试改用独立且最终注销的测试会话，
  不再错误复用已被轮换撤销的初始令牌。
- 响应式门禁只忽略登录页无 Cookie 时预期的匿名 Refresh 401；登录后的 Web/Admin 控制台错误仍会失败。
- 冷启动 API、Web、Admin、docs-site，完整发布脚本最终输出 `CampusOS v0.12.0 release check passed`。

## 4. 架构与兼容处理

本阶段没有新增表或改变业务 API。Cookie/Session 安全边界保持不变：Refresh Token 只在 HttpOnly Cookie，
Access Token 不写浏览器持久存储。旧生成文件名继续保留以兼容链接，但文件内版本由统一常量生成。组件模块
可以保留自身版本，不被应用发布号机械覆盖。

## 6. 回滚方式

版本和文档可一起回退到 `0.11.0`，但数据库 `000028-000038` 与用户数据不得删除。若旧二进制不理解新身份、
Session 或管理员准入合同，必须进入维护窗口并优先 forward-fix。浏览器测试修复不应回退，因为回退会重新要求
把 Access Token 写入持久存储，违背 v12 安全设计。
