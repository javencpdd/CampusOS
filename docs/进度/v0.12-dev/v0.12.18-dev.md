## 1. 本阶段目标

普通邮箱密码找回不再要求用户抄写或输入请求编号；验证码发送限制从写死的固定时间桶收敛为可审计、
可热配置的 Identity Core 安全策略。默认同一邮箱任意连续 10 分钟最多请求 5 次，同时保留来源 IP
限制，并允许管理员将策略调整为例如 5 分钟最多 2 次。

## 2. 实际完成内容

- 普通密码找回页隐藏“请求编号”，发送验证码后只在页面内存中保存 `challenge_id`，用户输入验证码即可继续；
  修改邮箱会清空旧 Challenge，辅助恢复流程仍保留跨设备所需的请求编号输入。
- 新增始终启用的 Identity Challenge Policy 子模块。默认邮箱策略为 `10 分钟 / 5 次`，IP 策略为
  `60 分钟 / 10 次`；所有验证码用途共享邮箱与 IP 防刷窗口，不能把次数配置为零或关闭保护。
- 原固定分钟、天、小时计数改为真正的滑动窗口。PostgreSQL 使用按主体排序的事务级 advisory lock，
  并发请求不会绕过上限；内存实现用于开发与测试，并保持事务快照回滚能力。
- 新增 `identity_challenge_policies` 单例策略表、乐观版本、更新人、更新时间和数据库边界约束；旧限流
  Scope 保留兼容，新 Scope 为 `email_window`、`ip_window`，升级时保守承接近期旧计数。
- 新增管理端“身份与权限 > 验证码策略”页面。管理员可分别配置邮箱/IP 的窗口和次数，保存后下一次
  请求立即读取新策略，无需重启服务；冲突更新返回 `409` 并重新载入当前版本。
- 新增 `identity.challenge_policy.read`、`identity.challenge_policy.update` 权限、路由操作合同、required
  command audit 和 `identity.challenge.policy.updated.v1` Outbox 事件。
- 更新 OpenAPI、HTTP 路由与授权矩阵、数据库审计、schema contract、管理端实时架构图、API 文档、
  帮助文档和 docs-site，并新增面向管理员的策略配置教程。
- 将 `000036` up/down/up 演练加入 `make v12-migration-check`；完整 v10/v11 兼容迁移和 v12
  `000028-000036` 迁移门禁已实际通过。

## 4. 架构变化

验证码频率策略是 Identity Core 的独立安全子模块，不是可卸载 External Plugin，也不是可以停用的
Built-in Feature。管理员只能在有界范围内热更新数值，不能关闭限流。Challenge Service 通过只读
Policy Port 获取当前策略；HTTP、Admin 和其他模块不能直接访问策略 Repository。

密码找回的 `challenge_id` 继续作为 API 内部关联键，以保持 Ticket、旧客户端和辅助恢复兼容，但普通
Web 流程不再把协议细节变成用户输入项。邮件发送仍由 Email Delivery Core 消费可靠 Outbox，策略模块
不直接连接 SMTP。

## 5. 兼容和迁移处理

- 既有 Challenge 请求、校验、Ticket 和密码重置 API 路径及字段不删除；旧客户端仍可提交
  `challenge_id`。
- `email_minute`、`email_day`、`ip_hour` 旧数据和 Scope 约束在升级期保留；新请求写入滑动窗口 Scope。
- migration 只新增策略表、权限和 Scope，不删除 Challenge、Ticket、用户或邮件数据；停机回滚仅在隔离
  演练中使用 down，生产优先使用兼容 forward-fix。
- 策略更新立即生效，窗口内已有计数继续参与新策略判断，避免管理员调整后产生瞬时绕过。

## 7. 回滚方式

前端可回退普通找回交互而不改变 API；后端可在维护窗口回退到旧固定限流实现，但必须继续保留防刷保护。
`000036` down 只用于隔离演练，会删除新策略表、新 Scope 和新增权限；生产出现问题时优先修复或恢复默认
`10/5`、`60/10` 策略，不执行会丢失策略审计信息的 down。

## 8. 已知限制

- 真实验证码邮件仍要求正确配置 SMTP Provider；Fake Provider 只验证投递链路，不会把邮件发送到外部邮箱。
- 策略当前按规范化邮箱和来源 IP 全局作用于注册、密码找回、邮箱绑定等用途，暂不支持按用途分别配置。
- 普通找回只在当前页面内存保存请求编号；刷新页面后需要重新发送验证码。辅助恢复因为跨设备交接仍显示编号。
- 本阶段已解除全部 migration drill 阻塞，但 v12 Final 的数据库审计、备份恢复、候选冷启动、真实浏览器
  流程和完整 `make release-check` 仍未验收，因此版本号不升级为 `0.12.0`。
