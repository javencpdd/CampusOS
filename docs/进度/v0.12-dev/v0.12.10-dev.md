> 日期：2026-07-17

## 1. 本阶段目标

把 Category 的 `parent_id` 从未受限的历史字段收敛为可验证的两级导航，并提供不会物理删除内容的
移动、归档、恢复和影响预览流程。

## 2. 实际完成内容

- migration 预检递归检测三级、循环与孤立 parent，拒绝不确定的历史树而非静默拍平。
- 以 CHECK、索引和 `campusos_guard_category_hierarchy` 触发器约束 group 根级、board 无子节点、
  child 只能位于 active group、group 不能在仍有 active child board 时归档。
- 增加专用 `MoveCategoryRequest`，严格区分省略 `parent_id` 和 JSON `null`；所有更新、移动、归档和
  恢复均要求正版本号，冲突返回 `409`。
- 增加 `/categories/tree`、移动、归档影响、archive、restore 路由；公开读取过滤 archived，管理读取保留
  全部状态。
- Thread 和 Post 创建前复用 Community 的板块资格校验，group、closed、archived 或父 group 不活动时都
  拒绝新主题和新回复。
- 保留历史 `DELETE /categories/:id`，但映射为 archive 并写兼容使用记录；不再物理删除板块。

## 4. 架构变化

层级只服务 Community 导航和发帖策略，不是 Identity/Moderation 的授权树。版主 scope 仍以明确 board ID
为事实，Category 移动不会调用、修改或推导角色分配。归档只改变 Category 生命周期，不删除主题、回复、
scope 或审计记录。

## 5. 兼容和迁移处理

- 公开 flat `GET /categories` 与单节点读取继续存在；tree 是加法读取接口。
- archived 数据只从管理员读取路径可见，旧公开调用不会看到它。
- 旧 DELETE 的语义已安全收紧为 archive，兼容使用会被遥测记录。
- 生产数据库以 forward-fix 为原则；migration 演练验证 down/up，不授权生产直接降级。
