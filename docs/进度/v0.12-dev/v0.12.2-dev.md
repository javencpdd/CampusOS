# CampusOS v0.12.2-dev 进度说明

> 日期：2026-07-17
> 阶段：A1 部署 Bootstrap 安全
> 实现状态：完成
> 验收状态：已验收

## 1. 本阶段目标

移除启动日志中的默认管理员密码，区分开发兼容与生产部署凭据，并让发布门禁从统一的
应用版本常量读取显示版本。

## 2. 实际完成内容

- 新增 `CAMPUSOS_ENV`：只接受 `development`、`test`、`staging`、`production`。
- 新增 `AUTH_BOOTSTRAP_ADMIN_SECRET` 与
  `AUTH_ALLOW_DEVELOPMENT_DEFAULT_ADMIN`；生产启动要求至少 16 字符的 Bootstrap Secret、
  非开发 JWT Secret、bcrypt 密码哈希，并拒绝开发兼容管理员。
- 重写管理员初始化：数据库事务内锁定管理员账户；仅在账号缺失或仍为历史默认凭据时
  创建/轮换；已修改的管理员密码保持不变。
- 删除邮箱、密码和哈希的启动输出。日志只报告管理员已经创建、轮换或保留，且明确说明
  凭据未写入日志。
- 保留本地开发兼容路径，但必须处于 `development` 且显式启用；既有本地默认凭据不再每次
  启动重写。
- 增加 `campusosctl version [--short]`，`release-check` 通过该命令读取统一版本常量，
  不再硬编码 `v0.11` 文本。
- 更新 `.env.example`、官方 docs-site 与仓库帮助文档，说明生产 Secret 注入和安全恢复
  边界。

## 3. 主要修改目录和文件

- `pkg/config/`：环境和 Bootstrap 配置。
- `internal/server/`：部署校验、管理员初始化与启动日志。
- `cmd/campusosctl/`、`scripts/release-check.sh`：统一版本输出。
- `.env.example`、`docs/help/系统设计相关/v12部署与初始管理员安全.md`、
  `docs-site/deployment/bootstrap-security.md`。
- `docs/项目计划v0.12/00-v0.12版本计划书.md`、本进度文档。

## 4. 架构变化

管理员 Bootstrap 仍属于服务启动装配，不进入 Identity 的公开业务 API。它只接收进程环境中
的 Secret 并只写 bcrypt credential；其事务不会把 Secret、默认密码或哈希写入审计、
Outbox、日志或前端配置。后续 A2-A7 仍由 `core.identity` 负责账号事实、验证与 Session。

## 5. 兼容和迁移处理

- 未修改 `000001-000027` 的历史 migration；历史默认 hash 只作为检测对象。
- 本地 `CAMPUSOS_ENV=development` 与
  `AUTH_ALLOW_DEVELOPMENT_DEFAULT_ADMIN=true` 继续支持已有开发账号和 smoke 流程。
- 在 production 中，旧默认凭据会在有 Bootstrap Secret 时被轮换；缺少 Secret 时服务拒绝
  启动，而不会带着已知密码继续运行。
- 该阶段没有表结构和 API 变化，因此不需要 database down；代码回退会恢复旧日志风险，
  生产环境应使用 forward-fix。

## 7. 回滚方式

本阶段无数据库迁移。若必须回退二进制，保留当前生产 Bootstrap/JWT Secret，关闭公开
部署窗口并优先 forward-fix；不得重新启用默认密码日志或将 Secret 写入 `.env.example`。

## 8. 已知限制

- 历史 migration 中的固定 hash 不能修改，必须依赖运行时检测和生产轮换处理。
- 当前没有公开密码重置、邮箱绑定或 Session 撤销入口；这些功能在 A3-A7 实施。
- Bootstrap Secret 目前是启动安全边界，不是可导出配置，也不是用户 API Token。
