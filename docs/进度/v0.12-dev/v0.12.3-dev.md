> 日期：2026-07-17

> 实现状态：完成

## 1. 本阶段目标

为验证式注册、找回密码和会话撤销建立安全的账号事实基础：以规范化的 email account 作为
登录邮箱权威来源，保留历史用户兼容语义，并在任何不可安全自动处理的数据冲突前停止迁移。

## 2. 实际完成内容

- 新增 `000028_v12_identity_account_state`：`accounts` 增加规范化邮箱、验证状态、验证来源、
  凭据版本和密码变更时间；`users` 增加 `auth_version` 与 `must_change_password`。
- 新增有效邮箱的规范化部分唯一索引，规范化规则固定为 `trim + lowercase`；不实施供应商
  特定的别名合并。
- 在 DDL 前检查大小写冲突、一个用户多个邮箱、用户投影不一致、孤儿/空账户；检测到任一
  问题会输出相关 ID 并中止，不合并、不覆盖也不猜测所有者。
- 历史普通账户迁移为 `legacy_accepted`，系统管理员迁移为 `system_managed`。前者保持登录
  兼容，但不被声明为已验证，也不成为未来密码找回邮箱。
- 新增历史共享邮箱占位记录表和保留标识表；`1904650862@qq.com` 不可作为新个人邮箱注册。
- 新增无凭据 `identity.account-reader` Port 和 PostgreSQL/Memory Adapter。调用方只能读取
  账号 ID、用户 ID、规范化标识、验证状态和时间，不能读取 password hash、JWT、验证码或 Ticket。
- 更新数据库架构可视化，使 Admin 架构页、schema contract 和迁移时间线同步到 `000028`。
- 新增账号迁移说明、ADR 和 docs-site 升级文档，明确升级、回退和开发者依赖边界。

## 4. 架构变化

Identity 现在拥有明确的 email-account 事实和状态机前置模型。`users.email` 是兼容投影，
不再是独立写入边界；邮件投递与后续认证功能只能依赖公开的最小 Port。共享历史邮箱被隔离
成迁移元数据，不能变成多用户凭据或验证目的地。

## 5. 兼容和迁移处理

- 未修改 `000001-000027`；新 migration 只追加列、约束、索引和表。
- 正常历史账号映射为 `legacy_accepted`，原邮箱密码登录暂时保持；A5 之前未改变公开注册
  路径，A6 之前未要求新的 Session claims。
- 冲突或不一致数据不自动修复。部署方需先备份并人工治理，再重试 migration。
- `000028` down 只用于隔离 up/down/up 演练；生产回退采用暂停新写入和 forward-fix，不能
  利用 down 恢复旧验证语义或原始邮箱大小写。

## 7. 回滚方式

生产故障先停止新的 email-account 写入并保留数据库备份、预检输出和审计证据，再采用
forward-fix。隔离测试可运行 `000028` down/up；不得在生产直接删除身份状态列或保留标识表。

## 8. 已知限制

- A2 只建立数据和 Port，不发送验证码、不启用验证式注册，也不支持密码找回或邮箱绑定。
- `legacy_accepted` 继续允许历史登录，但后续找回流程必须拒绝把它当作已验证邮箱。
- 保留标识表当前由迁移提供初始策略；后续受控写入口仍需通过 Identity Service，而非直接 SQL。
