## 1. 本阶段目标

将登录从不可撤销的长期 Refresh JWT 切换为服务器权威 Session：短期 Access JWT、Opaque
Refresh Token 摘要、原子轮换、重放家族撤销、Cookie/CSRF 保护和设备级会话管理。

## 2. 实际完成内容

- 新增 `000030_v12_identity_sessions`：历史 Session 的原始 Refresh Token 全部清除并显式撤销；
  新行只保存 SHA-256 摘要、family、rotation 链、撤销原因和 HMAC 化 IP 信息。
- Access JWT 现在必须声明 `typ=access`、`session_id` 和 `auth_version`。生产 Router 将 JWT
  Middleware 连接到 Session Verifier，同时校验签名、Session、用户状态和认证版本；旧 v0.11 JWT
  与 Refresh 凭据不能再访问受保护 API。
- 新增 Login、Refresh、logout、logout-all、列出设备和撤销设备的 Session API。Refresh 在一个
  Reliability/TxKernel 命令中锁定旧摘要、创建新摘要并写 rotation；已轮换 Token 重放会提交撤销
  整个 family，而不是只拒绝该请求。
- 浏览器使用 `HttpOnly` / `SameSite=Lax` Refresh Cookie 与双提交 CSRF Cookie。Web/Admin 移除
  localStorage 身份持久化，Access Token 仅保存在进程内存，并通过 Cookie 恢复会话。
- JSON `refresh_token` body 仅由默认关闭的 `AUTH_REFRESH_BODY_COMPAT` 临时接收，并记录兼容
  遥测；正常响应不再返回 Refresh Token。
- schema contract、数据库审计、OpenAPI、路由/授权矩阵、官方 docs-site、ADR 和会话 API 文档
  同步更新。

## 4. 架构变化

Identity 的 `SessionService` 是唯一的 Access/Refresh 发放和校验入口；Middleware 只依赖窄的
`AccessSessionVerifier`，不导入 Identity Repository。Session Repository 只暴露摘要查询和安全
投影，原始 Refresh Token 不进入数据库、日志、Outbox、Admin API 或 External Plugin 边界。

`auth_version` 是账户级立即失效版本。`logout-all` 已通过原子递增版本和撤销 Session 实施；A7
密码重置与邮箱绑定会复用相同的可靠撤销 Port。

## 5. 兼容和迁移处理

- 已有 Session 一律撤销并删除原始 refresh 值；无法也不会将历史 JWT 伪装成可轮换 Session。
- Access Token 字段仍保留在登录响应；Refresh body 为明确、短期、默认关闭的兼容窗口。Web/Admin
  已迁移 Cookie 流程。
- 生产回退采用 forward-fix。down migration 仅用于隔离演练，使用无效占位值满足旧列约束，不会
  恢复任何凭据。
- 非 development 环境必须提供 `AUTH_SESSION_IP_HASH_SECRET`，并使用 Secure Cookie。

## 7. 回滚方式与已知限制

生产不得通过 down migration 恢复 Refresh Token；采用关闭公开认证写入口、轮换 JWT Secret、受控
重新登录和 forward-fix。Cookie 兼容要求浏览器可保存第一方 Cookie；跨站嵌入认证不在本阶段支持。
`AUTH_REFRESH_BODY_COMPAT` 仍是短期桥接，后续版本应根据兼容遥测删除。
