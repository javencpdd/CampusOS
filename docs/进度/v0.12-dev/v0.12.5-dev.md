## 1. 本阶段目标

将 A3 已提交的 `identity.email.challenge.requested.v1` 可靠事件接入始终启用的邮件 Core，提供
SMTP/Fake Provider、过期 replay 跳过、脱敏运维状态和管理端可见性，但不改变公开注册流程。

## 2. 实际完成内容

- 新增 `core.email-delivery` 与 `modules/core/email-delivery/module.yaml`。模块固定依赖
  `core.identity`、`core.reliability`，不能按 Feature 或 External Plugin 停用、安装或卸载。
- Consumer 只接收严格的 `{"challenge_id":"..."}` payload。未知字段、Code、Ticket、邮箱或
  正文进入 payload 时会被永久拒绝，不会传给 Provider。
- Identity Dispatch Adapter 将不存在、过期、已失效或已消费 Challenge 收敛为
  `ErrChallengeNotDeliverable`；邮件 Consumer 安全确认 receipt 并跳过 SMTP，避免 replay 发送
  旧验证码。
- 增加 SMTP Sender，使用可配置的连接超时、STARTTLS、认证和稳定 `X-CampusOS-Delivery-ID`；
  Provider 原始错误永不写入可靠任务、日志或 HTTP 响应。
- 增加仅限 `development`/`test` 的 Fake Sender。它只保存在进程内的幂等计数，不打印 Code，
  production/staging 配置 Fake 会被部署校验拒绝。
- 新增受 `platform.reliability.read` 保护的
  `GET /api/v1/platform/email-delivery/status`，仅返回 Provider、健康、通用错误、投递/跳过计数和
  时间；管理端“可靠任务”页面同步展示该状态。
- 新增 `make email-delivery-check`、SMTP 环境样例、ADR、部署说明和官方文档入口。

## 4. 架构变化

Identity 保留 Challenge、Code 重建和 Ticket 消费事实；Email Delivery 只消费最小 Dispatch Port，
不读取 Identity Repository、HMAC key、数据库连接或 SMTP Secret。Outbox 仍只包含不透明 ID。
SMTP 发送在提交后由 Worker 执行，属于 at-least-once 语义；consumer receipt、进程内键和 SMTP
header 仅降低重复，不能保证 exactly-once。

## 5. 兼容和迁移处理

- 本阶段没有新 migration，也不改写 `000001-000029`；A3 的未处理事件在升级后由新 Consumer
  继续投递。
- 旧 `/auth/register`、`/auth/login` 和历史账号行为不变；A5 才要求注册 Ticket。
- `EMAIL_PROVIDER=fake` 保持本地开发可启动；staging/production 必须切换到 SMTP，错误配置会在
  进程初始化前拒绝。
- 回退以停止新的 Challenge 请求、保留 Outbox/Challenge/receipt 并 forward-fix SMTP 为准；不能
  删除可靠事件或通过日志找回验证码。

## 7. 已知限制

- Fake Provider 不提供可浏览的本地邮箱；需要人工验收真实邮件时须配置隔离 SMTP 测试服务。
- SMTP 仅支持显式 STARTTLS 或非 TLS 配置；隐式 TLS/465、多 Provider 主备和模板国际化属于 P2。
- A4 还没有公开 Challenge API 或注册 UI，用户无法通过当前前台自行走完验证流程。
