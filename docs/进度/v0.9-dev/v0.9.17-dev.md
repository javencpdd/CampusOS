## 架构变化

Market Service 通过最小的 `PluginActiveResolver` 感知 External Plugin 是否正在运行，不直接依赖 Manager 或 Runtime 实现。Catalog、Runtime、管理员批准和用户 Grant 形成四层门禁；保留数据控制走独立路径，避免插件下架后用户失去数据处置权。

Managed Data 继续由 Host 持有 PostgreSQL/Memory Store，External Plugin 只使用声明式合同。User Storage 继续持有物理路径，插件只得到受控文件 ID/下载入口。

## 兼容和迁移处理

- 未新增或修改数据库 migration，`000021`、`000022` 保持不变。
- Manifest v1、Host API v1 SQLite KV、旧 API 和数据目录继续兼容。
- 新增搜索权限只适用于 v2；未声明权限时默认拒绝，不通过兼容值自动授予。
- 插件停用或下架不会删除 Grant、记录或文件；用户可继续导出或显式删除本人数据。
- 应用可回退到 A15 代码；A16 写入的受管数据和审计记录无需向下迁移。

## 回滚方式

本阶段无 schema 和目录迁移。回滚应用代码即可恢复 A15 行为；不要删除 `plugin_records`、插件文件、Grant、Catalog、Release 或审计数据。若只回滚前端，新 API 的加法字段不会破坏旧页面。

## 已知限制

- 当前只提供本地 Catalog 和管理员治理队列，不包含远程下载或公共市场。
- 发布状态是治理记录，不包含自动灰度编排和健康观察。
- 搜索限定单插件、单 collection 和当前用户，不是全局或向量搜索。
- v9 仍是单写友好的 Local Provider 实现，不宣称真正多实例读写。
