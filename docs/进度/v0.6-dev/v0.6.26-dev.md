# CampusOS v0.6.26-dev Module Kernel 基础设施

> 日期：2026-07-12  
> 状态：已完成（v0.7 A1）

## 1. 本阶段目标

建立不依赖复杂 DI 框架的模块注册和生命周期内核，并以兼容方式接入现有 EventBus 与 Plugin Platform 初始化，证明新机制存在真实运行路径。

## 2. 实际完成内容

- 新增 Core/Built-in Feature 两类主程序模块；External Plugin 和 Resource Package 明确不进入 Module Registry。
- 支持唯一 ID、依赖声明、缺失/禁用依赖检查、循环检测和确定性拓扑顺序。
- 支持 Register、Start、Health、Stop 状态，启动失败时逆序回滚，正常关闭时逆序停止。
- Core Module 禁止以 disabled 注册；停用 Feature 不进入注册和启动回调。
- AppContext 只允许显式命名 Port，并拒绝覆盖，避免成为无约束全局容器。
- 将 EventBus 和 Plugin Platform Runtime 初始化移出 `server.go` 到 `platform_modules.go`，通过 Registry 启动；保留 NATS 失败的 Memory fallback、现有插件目录、三 Runtime 和 Gateway 示例。
- HTTP Server 改为接收 SIGINT/SIGTERM 后先停止接入、最多等待 10 秒，再让 Registry 逆序关闭插件与事件总线；移除旧的重复 `PluginManager.StopAll`。

## 4. 架构变化

启动链首个切片由直接顺序调用变为：`core.event-bus -> core.plugin-platform`。Plugin Manager 仍保留兼容 Facade 和现有仓储设置，业务 Service/Handler/Router 装配尚未迁移。

## 5. 兼容和迁移处理

- 没有新增 migration、修改表或移动用户数据。
- API、插件 manifest、Host API、Extension Gateway、Memory fallback 和前端合同不变。
- `runtime: builtin` 仍由 Plugin Platform 兼容处理；系统功能分类迁移在后续阶段完成。
