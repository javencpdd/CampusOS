> 完成日期：2026-07-10
> 对应计划：[v0.6 版本计划书](../../项目计划v0.6/01-v0.6版本计划书.md)

## 本次目标

修复后台“分配角色失败”的实际写入错误，明确后台角色管理的最小权限边界，并为全局/版块版主能力确定后续实现路径。

## 已完成

| 项目 | 结果 |
| --- | --- |
| 角色分配写入 | `user_roles` 改用 `idgen.New()` 生成 BIGINT ID，不再调用不存在的 `user_roles_id_seq`。 |
| 全局角色唯一性 | `000014_role_assignment_permissions` 清理重复的有效全局关联，并增加 `scope_id IS NULL` 的部分唯一索引。重复分配现在成功且返回 `assigned: false`。 |
| 目标校验与错误 | 分配、读取和撤销前验证用户 ID、目标用户和角色；接口区分参数错误、用户不存在、角色不存在和未分配角色。 |
| 权限拆分 | 新增 `role:read`、`role:assign`、`role:revoke`；三个角色接口不再使用过宽的 `role:manage`。 |
| 基础角色语义 | `member` 成为每个有效登录用户的隐式基础角色，`guest` 只表示匿名主体。两者不能从角色管理接口分配或撤销，给用户添加版主/管理员角色不会丢失普通用户权限。 |
| 撤销边界 | 撤销 API 只处理显式全局关联；禁止操作人撤销自己的角色。 |
| 管理端 | 管理端按全部角色判断管理员身份；仅管理员加载角色管理 UI；基础角色不能选择或撤销；接口错误显示后端消息。 |
| 文档与架构 | 新增 RBAC/版主设计帮助文档，更新 API 索引、数据库说明、架构概览、文档门户、README、v0.6 计划和项目 onboarding 快照。 |

## 版主插件决定

不在本次把 `moderator` 授权逻辑做成可替代插件。`global/category` 作用域、跨版块拒绝和审计属于核心 RBAC，必须由后端强制执行。

v0.6 后续会在核心作用域授权稳定后实现系统级内置 `category-moderation` 插件。该插件负责独立配置窗口、版主授权工作流、用户端治理入口和后续审核能力；启停不应删除或绕过核心授权与审计记录。

当前 `scope_type` / `scope_id` 仍只完整支持 `global`，版块级版主尚未实现，不能将其描述为已可用功能。
