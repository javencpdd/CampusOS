# v0.6.1-dev 进度：版块版主作用域与治理插件

> 完成日期：2026-07-10
> 对应计划：[v6 版本计划书](../../项目计划v6/01-v6版本计划书.md)
> 使用说明：[RBAC 权限与版主管理说明](../../help/系统设计相关/RBAC权限与版主管理说明.md)

## 本次目标

修复“给用户分配版主后无法选择版块”的授权缺口，将版主从历史全局角色收口为按版块分配的治理角色，并交付管理员配置、用户端操作、系统级插件生命周期和审计闭环。

## 已完成

| 项目 | 结果 |
| --- | --- |
| 版主作用域 | `user_roles` 的 `category + scope_id` 成为版主唯一有效授权形态；一个用户可负责多个版块。 |
| 防止全局版主 | 通用角色分配接口拒绝 `moderator`，历史有效全局版主关联由 migration 软删除，不能把旧版主自动升级为全站版主。 |
| 权限判定 | 新增 scoped permission 检查；普通全局权限检查只接受 global 关联，版主不能借历史管理路由跨越版块。 |
| 当前权限 | 版主仅可在已分配版块置顶/取消置顶、锁定/解锁主题和删除回复；用户封禁、主题写入/删除等过宽权限已移除。 |
| 后端防越权 | 主题操作从主题记录读取 `category_id`；回复操作从所属主题读取版块，不信任客户端传入的作用域。 |
| 管理端用户页 | 分配“版主”后必须选择一个或多个版块；已有版主可再次编辑范围，撤销时清空全部版块关联。 |
| 独立管理页 | 新增 `/moderators`，集中展示插件当前/目标状态、待重启状态、动作开关和每个版主的版块范围。 |
| 后台访问边界 | Admin 前端只允许管理员角色登录和访问；版主在用户端治理已分配版块。 |
| 用户端 | 帖子详情根据后端返回的 `actions` 显示置顶、锁定和删除回复操作，并在执行后刷新页面状态。 |
| 内置插件 | 新增 `data/plugins/category-moderation/` 系统级 builtin 插件和 README，可配置置顶、锁定和删除回复；治理审计强制开启。 |
| 插件生命周期 | 启停和配置按系统级插件规则在 API 重启后生效；停用时用户治理 API 不可用，但版块授权和审计保留。 |
| 审计 | 版主范围变更和治理动作写入既有 `audit_logs`。 |
| 版块管理保护 | 版块创建和修改路由从普通登录保护调整为管理员 `category:write` 权限保护。 |

## 数据库变更

- 新增 `migrations/000015_category_moderation_scope.up.sql` 和回滚脚本。
- 软删除历史全局版主授权及不再允许的版主权限。
- 为管理员、版主补充 `thread:lock`。
- 对有效 `user_roles` 增加 scope 形态约束，并在数据库层禁止版主使用 global 作用域。
- 增加用户、角色、scope 查询索引。
- 本地数据库已应用 `000001` 至 `000015`。

## 接口与界面

新增的主要接口：

- `GET /api/v1/moderation/status`
- `GET /api/v1/moderation/me?thread_id=<id>`
- `GET /api/v1/moderation/admin/moderators`
- `GET /api/v1/moderation/admin/moderators/:user_id`
- `PUT /api/v1/moderation/admin/moderators/:user_id`
- `POST /api/v1/moderation/threads/:id/pin|unpin|lock|unlock`
- `DELETE /api/v1/moderation/threads/:thread_id/posts/:post_id`

管理端新增“版主管理”菜单和页面；用户管理的角色弹窗增加版块多选；用户端帖子详情增加经后端授权的治理按钮。

## 当前边界与后续

1. 当前版主治理动作只包含置顶、锁定和删除回复；主题下架、审核队列、操作原因等继续按权限目录逐项增加。
2. 版块作用域首版不自动继承子版块，管理员需要明确选择每个版块。
3. `category-moderation` 关闭后会停止插件提供的治理能力，但核心 RBAC 数据和审计仍保留。
4. v6 仍需完成全路由授权矩阵、统一错误/OpenAPI、服务身份、数据库完整性和插件 SDK/权限目录，不因本次 MVP 视为全部完成。
