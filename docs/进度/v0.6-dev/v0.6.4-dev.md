# CampusOS v0.6.4-dev 进度说明

> 日期：2026-07-11
> 状态：已完成

## 1. 本次目标

1. 明确个人主页、单独首页和完整用户前台三类风格包的作用边界。
2. 保证访问用户 A 的主页时始终显示 A 自己保存的风格，个人包能够设计主页内的全部内容。
3. 允许风格包修改字体、背景、页面间距、布局和动态效果，但不在主页面执行任意同源脚本。
4. 建立系统级与用户级风格包不同的 CampusStyleSDK 权限，支持受控读取公开帖子和本人课表。
5. 提供管理员系统主题、用户本地切换界面和精美动态个人主页示例。

## 2. 完成内容

### 2.1 风格包目标与整页作用域

- `page-style-pack.v1` 新增 `target: web`，与 `personal-space`、`homepage` 形成三个明确目标。
- CSS 强制使用目标根选择器：
  - 个人主页：`.public-space[data-campusos-space]`
  - 用户前台首页：`.home[data-campusos-home]`
  - 完整用户前台：`.app-container[data-campusos-web]`
- 校验器递归检查普通规则和 `@media`、`@supports`、`@container`、`@layer` 内选择器，允许目标内 `@keyframes` 动画。
- 个人主页根节点增加所有者与当前风格标记；服务测试证明用户 A 与用户 B 的风格不会串用。
- 主页包现在可以覆盖资料头部、头像、元信息、模板、帖子卡片、标签和空状态，而不能逃出主页修改应用导航。

### 2.2 沙箱 JS/TS 特效

- manifest 新增可选 `effect`：运行时固定为 `sandbox-worker.v1`，执行入口为筛查后的 `.js`，可保留不直接执行的 `.ts` 开发源码。
- 新增 `StyleEffectLayer`，在无 `allow-same-origin` 的 iframe 内创建 Worker 和 OffscreenCanvas。
- CSP 禁止任意网络，静态筛查拒绝 DOM、Cookie、存储、父窗口、动态代码、WebAssembly 等能力。
- 特效层不接收点击，只获得 Canvas、尺寸、时间、像素比和归一化指针坐标。
- 单入口上限 32 KiB，Worker 具备心跳超时终止，系统减少动态效果模式下不运行特效。

### 2.3 CampusStyleSDK 权限桥

- manifest 新增 `capabilities`，脚本通过 `CampusEffect.request(method, params)` 发起只读请求。
- 宿主检查 manifest 声明、目标允许列表、当前登录状态、对象归属和用户授权后代为调用 API；风格包不获得 JWT、Axios 或任意路径。
- 个人主页包：
  - `space.profile.read` 固定返回当前路由主页所有者公开资料。
  - `space.posts.read` 固定返回主页所有者公开同步帖子，最多 20 条。
  - `schedule.me.read` 只有主页所有者本人访问自己的主页时允许。
- 管理员系统包：
  - 可声明 `community.threads.read` 和 `categories.read` 公共能力。
  - `schedule.me.read` 必须由当前用户在选择主题时单独授权。
- 所有目标都禁止通过风格包 SDK 执行写操作。

### 2.4 系统主题插件与用户切换

- 新增系统级内置插件 `web-theme`，公开管理员提供且通过筛查的完整用户前台主题目录。
- 新增 `/api/v1/web-themes`、`/web-themes/:name` 和声明图片资源接口。
- 系统主题源码保存在 `data/plugin_data/web-theme/style-packs/`；用户端不能安装系统包。
- 新增用户端 `/appearance` 页面和头像菜单入口，展示预览、颜色 token、能力和私有能力提示。
- 主题选择按用户 ID 保存在浏览器本地，切换立即生效；插件整体启停仍按系统插件规则重启 API 后生效。
- 系统主题只加载到 Web，不进入独立 Admin 前端。

### 2.5 示例包

- `campus-canvas`：完整用户前台系统主题，统一字体、页面背景、页边距、按钮、卡片和响应式布局，并通过 `community.threads.read` 调整低干扰活动背景。
- `kinetic-journal`：完整个人主页和同步帖子动态示例，设计资料头部、头像、元信息、介绍模板、帖子卡片、标签和空状态，并通过 `space.posts.read` 驱动沙箱节点效果。
- 两个示例都包含真实 PNG 预览、CSS、JS 入口、TS 源码、模板、图片资产和配置 Schema。

## 5. 后续任务

1. 为系统主题增加管理员 Web 上传、覆盖、删除和版本快照界面；当前管理员通过部署系统插件或维护 `data/plugin_data/web-theme/style-packs/` 提供包。
2. 将 CampusStyleSDK 能力目录改为机器可读单一来源，并生成管理端和官方文档权限表。
3. 在明确公开课表模型前，不向他人主页开放课表数据；当前仅支持本人读取。
4. 为沙箱增加更完整的 CPU/内存遥测、异常审计和自动停用策略。
5. 后续如需可交互业务组件，应设计受尺寸限制的 sandbox widget 插槽，不应放开主页面 DOM 或同源任意脚本。
