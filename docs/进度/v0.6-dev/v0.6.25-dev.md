基于实际代码、插件 manifest、migration、Web/Admin 运行时和 v0.6 文档，制定分阶段、可验证、兼容优先的 v0.7 模块化单体计划，不直接进行全系统重写。

- 记录 `server.go` 集中装配、builtin 与外部插件混用、Storage/Appearance 归属和跨模块具体依赖问题。
- 定义 Identity、Community、Moderation、User Storage、Plugin、Space、RichText、Schedule、Appearance 的表/目录所有权与 Port 方向。
- 将实施拆为 A0-A7、B1-B4 和 Final，每阶段有独立编号、目录、兼容和验收标准。
- 增加 Agent Core/Center/Runner/Knowledge/MCP/资源包边界，以及 CampusOS Token 禁止导出、第三方 Secret 显式加密迁移的策略。

## 4. 架构变化

本阶段只建立目标合同和执行顺序，不修改 API、数据库、运行时或持久化目录。确定先建设 Module Kernel 和兼容装配，再迁移 Moderation、Storage、Feature、Appearance 和 Plugin Platform。

## 5. 兼容和迁移处理

- 保留 `runtime: builtin` 兼容读取，不立即删除既有 manifest。
- 既有表和 `000001-000018` migration 不改写。
- Built-in Feature 停用只隐藏 API/UI/事件订阅，不删除表或文件。
- Resource Package 不获得业务生命周期、数据库或宿主权限。
