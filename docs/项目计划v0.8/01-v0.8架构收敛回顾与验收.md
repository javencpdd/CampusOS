## 结论

v0.8 已完成既有功能的架构收敛。CampusOS 保持模块化单体：业务对象由 Module 拥有，PostgreSQL/Memory 差异由 Profile Adapter 绑定，HTTP 路由由 Transport 管理，Built-in Feature 由 Feature Store 管理，外部插件由 Plugin Platform 管理，主题/风格等资源保持为 Resource Package。

## 已完成范围

- Core：Identity、Community、Moderation、User Storage 均通过公开 Port 协作。
- Built-in Feature：Personal Space、RichText、Schedule、Appearance 保留数据且可按定义启停。
- Integration：AI、Webhook、MCP-like、Message、Platform Log 与 Overview 通过 Module/Port/Summary Port 运行。
- Transport：Server 不再注册具体业务路由；148 条 HTTP 路由由 `internal/transport/httpapi` 作为合同源，并经 Route Registry 验证。
- Plugin：Manager 保留兼容 Facade，Host API 和 Plugin Handler 由 Plugin Platform Module 管理；系统 Feature 不进入普通卸载生命周期。
- 前端：Web/Admin 的共享 Client、领域 API、Route 集合和关键身份/插件运行时 Store 已模块化；旧入口为无状态兼容导出。
- 质量：后端和前端边界检查为零例外，构建体积预算、数据库同步、恢复演练和浏览器流程进入发布门禁。

## 兼容矩阵

| --- | --- |

## 后续工作

v0.8 不实现 Agent Center/Runner、标准 MCP Server、Knowledge Provider、第三方消息 Adapter、插件市场、跨实例 Secret 迁移或高可用部署。这些能力必须在后续版本以最小权限、独立威胁模型和可验证隔离方案重新立项。
