# CampusOS v0.9 计划验收审查与后续规划

> 审查日期：2026-07-13
> 审查基线：`00-v0.9版本计划书.md`、A0-A15 进度文档及当前工作树
> 审查阶段：A16 计划符合性复审

## 1. 审查结论

审查开始时，v0.9 **不能严谨认定为全部完成**。A0-A15 已建立主要能力，但原验收遗漏了若干会影响权限和数据安全的行为，也没有把 Web/Admin 组件测试接入 CI。

A16 已补齐审查发现的功能缺口。当前结论分为两部分：

- **功能实现：已完成。** v0.9 计划内 P0/P1 的代码、合同、界面和文档已有对应实现。
- **最终复验：未完全完成。** 本轮全量测试、组件测试、构建和静态门禁均通过；数据库动态检查和修改后的五视口浏览器回归受当前执行环境限制，仍需补跑。

因此，计划书的正确状态是“实现完成、A16 部分验收”，而不是无条件的“全部验收完成”。

## 2. 主要审查发现与处理

| 级别 | 原缺口 | 风险 | A16 处理结果 |
| --- | --- | --- | --- |

## 3. 当前已完成能力

### 3.1 多端与前端工程

- Web、Admin 共享全局响应式基础：安全区域、可见焦点、媒体宽度、粗指针 44px 触控目标和移动端弹窗约束。
- 路由级拆包、Element Plus 按需引入和入口 JS/CSS 预算门禁已建立。
- Web 插件中心、动态声明式 UI、路由鉴权、动态入口移除、Admin Feature 管理入口和 Admin 插件中心具有组件测试，Web/Admin 测试已进入 CI。
- A15 已留存五固定视口真实 Chrome 回归证据；A16 前端修改仍需补跑同一回归。

### 3.2 插件合同与兼容

- `campusos.plugin/v2`、JSON Schema、Go/TypeScript SDK、CLI inspect 和示例插件可用。
- v1 Manifest、Host API v1 SQLite KV、旧数据目录和既有 External Plugin 继续兼容，不自动获得 v2 权限。
- Built-in Feature 和 Resource Package 仍由 v0.8 的 Registry/Repository 管理，不会重新进入普通市场插件生命周期。

### 3.3 受管数据与用户文件

- Host 注入插件和所有者身份，插件不能指定其他用户、取得表名或数据库连接。
- Record API 支持严格 schema、稳定 key、分页、声明式过滤、乐观锁、数量/大小/总量配额和审计。
- 搜索仅覆盖 Manifest 声明字段，并要求独立、可撤销的用户搜索授权。
- Plugin File Gateway 复用 User Storage，按用户和插件隔离目录，执行路径、后缀、MIME、大小及配额校验。
- 停用、下架和卸载不默认删除数据；用户仍可导出或显式删除本人保留数据。

### 3.4 市场与发布治理

- 本地 Catalog 区分 draft/published/hidden；管理员发布和用户授权相互独立。
- 用户可授权、撤销、查看占用、导出、删除本人数据和提交插件安装建议，但不能安装或执行宿主代码。
- 管理员可查看 Runtime 健康、系统/用户权限、占用、申请、发布记录和治理审计。
- 包导入具备路径安全、摘要、Ed25519 签名信任、版本/权限/schema 预检、重新授权提示和 snapshot 回滚。
- v2 包导入后立即同步本地 Catalog/Release，不依赖进程重启。

### 3.5 部署与多实例边界

- PostgreSQL 采用追加迁移 `000021`、`000022`，旧表和旧目录未被重写。
- Local User Storage 或 v1 SQLite KV 组合不会被静默声明为多写安全；不安全的 `multi` 配置会在启动前失败。
- A15 已完成迁移、数据库契约和隔离恢复演练；A16 没有新增迁移。

## 4. 兼容与数据结论

| 对象 | 当前结论 |
| --- | --- |
| Manifest/Host API v1 | 继续运行；不获得 v2 Managed Data/File/Search 权限 |
| Manifest/Host API v2 | 使用 Catalog、Runtime、管理员批准和用户 Grant 四层门禁 |
| Built-in Feature | 不进入市场安装/卸载流程 |
| Resource Package | 仍是无 Runtime 的资源数据 |
| 旧 SQLite 与 `plugin_data` | 不移动、不删除；仅受多实例限制 |
| 用户插件文件 | 新增到 User Storage 的插件命名空间，旧空间文件保持原位 |
| PostgreSQL | 仅追加迁移；应用回退时保留新表和用户数据 |
| 停用/下架/卸载 | 拒绝普通运行调用，保留本人数据导出和显式删除能力 |

## 6. 后续必须补做的验收

在可访问 Docker/PostgreSQL 且允许监听本地端口的环境中执行：

```bash
make migrate-status
make database-check
STOP_EXISTING=true make dev-all
RUN_RESTORE_DRILL=true RUN_BROWSER_SMOKE=true make release-check
```

上述检查通过后，将 A16 验收状态改为“已验收”，v0.9.0 才满足计划定义的最终出口。

## 7. 未来功能

以下是明确未纳入 v0.9 的后续工作，不应被描述为 v0.9 遗漏：

- 远程公共插件市场、在线下载、评分、支付、来源联合和社区审核。
- 自动灰度编排、健康观察、失败自动回退和多节点发布状态聚合。
- S3/OSS/WebDAV 等共享 User Storage Provider、分布式锁和真正多实例读写。
- 独立搜索索引、跨插件统一搜索、向量检索和 Knowledge Provider。
- 第三方 Secret 的加密跨实例迁移和密钥协商。
- 历史页面逐页移动端精修、持久化视觉差异基线、慢网和大数据性能专项。
- 市场治理的远程包拉取、恶意包沙箱扫描、签名吊销和供应链透明日志。

## 8. 最终判断

v0.9 的**计划范围内功能已经完成**，审查发现的剩余实现缺口已在 A16 修复。当前唯一未闭合的是受执行环境限制的最终动态复验。因此不能把“代码完成”扩大表述为“所有验收已完成”；待第 6 节门禁补跑通过后，才能正式关闭 v0.9。
