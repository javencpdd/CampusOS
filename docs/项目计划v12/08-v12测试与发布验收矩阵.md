## 3. 已执行顺序

1. 准备隔离 PostgreSQL 与专用测试数据库，确认不会写入日常开发或生产数据。
2. 执行 `make v12-migration-check`。C3 的脚本失败时先修 migration，不进入恢复或浏览器阶段。
3. 执行 `make database-check`、`make restore-drill`，记录 schema、约束、数据数量和恢复结果。
4. 从候选工作树执行 `STOP_EXISTING=true make dev-all`，保存四个服务就绪证据。
5. 在该测试栈运行浏览器 smoke，以及 group 点击子菜单、互助/二手图片上传预览、桌面/窄屏写入与停用
   Feature 流程。
6. 停止测试栈后运行 `make release-check`。只有该步骤完整通过才更新版本、SDK、OpenAPI 和 README。

## 4. C3 最小迁移验收

`000035_v12_secondhand` 必须证明：

- Detail 只能关联 `thread_type=secondhand` 的基础 Thread，且 `created_by` 与作者一致。
- 负价格、非 CNY、非法枚举、无效版本和超长地点被约束拒绝。
- down 后表、触发器和约束消失；再次 up 后表、触发器和关键约束恢复。
- 正常数据的创建、读取和索引存在性可验证。

`000036_v12_identity_challenge_policy` 必须证明：

- 默认策略为每邮箱 10 分钟 5 次、每 IP 60 分钟 10 次。
- 次数为零或窗口越界被数据库约束拒绝。
- down 后旧 Scope 约束恢复，re-up 后策略表和约束重新建立。
- 新权限只默认授予 admin，策略更新有版本冲突和 required audit。

`000037_v12_outbox_worker_convergence` 必须证明：

- `system:outbox-finalize` 可记录 `failed`，down 前安全映射为旧约束允许的 `retry`。
- attempts 等于 max 的 pending/retry/过期 processing 不再领取并进入 dead；历史 `103/8` 保留 103。
- `7/8` 的过期 processing 可由新 Worker 领取为 `8/8`，旧 generation Complete 被 fencing 拒绝。
- PostgreSQL Complete、Retry 和 DeadLetter 使用相同 owner/generation 条件并能实际提交。

`000038_v12_admin_accounts` 必须证明：

- 升级前每个全局 admin 都有且仅有一个活动邮箱凭据，否则迁移在建表前失败。
- 管理员密码不复制，准入表只引用 Identity 用户和凭据；非法状态和不一致外键被数据库拒绝。
- admin 角色分配、撤销和重新分配会同步 `active/revoked`，独立 `suspended` 不被普通角色刷新覆盖。
- down 只删除准入表和同步触发器，不删除用户、账号或角色；re-up 能从现有全局角色重新回填。
