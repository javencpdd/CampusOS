# v12 二手信息子模块设计

> 状态：C3 已实施，等待隔离 PostgreSQL migration drill 后完成阶段验收  
> 日期：2026-07-17  
> 关联：[v12 版本计划书](00-v12版本计划书.md)、[结构化帖子事务内核](05-结构化帖子事务内核设计.md)

## 1. 目标和范围

`feature.secondhand` 是编译进 CampusOS 的 Built-in Feature，用于发布校内闲置物品信息。它提供结构化的
人民币分价、成色、交付方式、交易进度和粗粒度地点，但不提供支付、担保、订单、即时聊天、物流或争议仲裁。

一条二手信息分为两层事实：

```text
Community Core
  threads / revisions / visibility / moderation / replies
          1 : 1
feature.secondhand
  secondhand_details / listing and trade progress
```

基础 Thread、回复、可见性和治理由 Community Core 所有；二手 Feature 只拥有 Detail 和交易状态机。因此
“已售出”不等于帖子被下架，管理员下架也不等于交易完成。

## 2. 详情字段和状态机

`secondhand_details` 以 `thread_id` 为一对一主键：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `price_minor` | 标价，单位为分 | 非负整数；浏览器以元输入后转成分 |
| `currency` | 币种 | 首版固定 `CNY` |
| `item_condition` | 成色 | `new`、`like_new`、`good`、`fair` |
| `trade_method` | 交付方式 | `in_person`、`campus_dropoff`、`other` |
| `trade_status` | 交易进度 | `available`、`reserved`、`sold`、`closed` |
| `location_scope` | 粗粒度地点 | 最长 160 个字符，不保存完整住址 |
| `version` | 乐观并发版本 | 每次 Detail 修改递增 |
| `created_by` | 作者事实 | 必须匹配基础 Thread 作者 |

状态只能按以下规则更新：

```text
available -> reserved / sold / closed
reserved -> available / sold / closed
sold -> （不可再次转换）
closed -> （不可再次转换）
```

保留 `reserved -> available` 是为了处理未完成的线下约定。`sold` 和 `closed` 为终态，不能被重新打开。

## 3. 可靠写入与 API

创建固定为 `thread_type=secondhand`，通过 Community `CreateStructuredThread` 在同一可靠事务内写
Thread、Revision、Detail、command audit 和 Outbox。编辑或状态变更使用 Feature 自己的可靠命令；版本陈旧时
返回冲突，避免静默覆盖。编辑或状态写入前必须确认基础 Thread 仍处于 active（未回收）状态；已进入回收站的内容
返回稳定冲突，不更新 Detail，也不产生新的审计或 Outbox。

| 方法 | 路径 | 认证 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/secondhand/status` | 无 | 查询 Feature 是否启用。 |
| `GET` | `/secondhand/threads` | 无 | 分页读取公开二手信息。 |
| `GET` | `/secondhand/threads/:id` | 无 | 读取公开 Thread 与 Detail。 |
| `POST` | `/secondhand/threads` | JWT | 创建本人二手信息。 |
| `GET` | `/secondhand/threads/:id/me` | JWT + 作者 | 读取编辑投影。 |
| `PUT` | `/secondhand/threads/:id` | JWT + 作者 | 更新完整正文与 Detail，需 `version`。 |
| `POST` | `/secondhand/threads/:id/status` | JWT + 作者 | 更新交易状态，需 `version`。 |

管理员必须先启用 Feature，并在目标 board 的类型策略中允许 `secondhand`。Feature Path Gate、Community
类型检查、board policy、作者检查、状态机、版本和数据库约束会一起拒绝越权或非法写入。
Feature 停用时，只有只读 `GET /secondhand/status` 会继续返回 `enabled=false`；其余二手业务路径仍由
Path Gate 拒绝。
未分类的 Repository、数据库和网络错误只返回通用 `500 / 10006`，具体原因仅供服务端 trace 和日志使用。

## 4. 数据库守卫和兼容性

`000035_v12_secondhand` 新增 Detail 表、CHECK、外键、查询索引和触发器。触发器要求 Detail 指向
`secondhand` Thread，且 `created_by` 与 Thread 作者相同。迁移不移动既有 Thread、URL、用户数据或
普通 `POST /threads` 合同；后者仍只创建 `discussion`。

Feature activation mode 是 `restart`。停用时统一 Path Gate 和 Service 拒绝 Feature API，运行中不会动态
删除 Gin 路由。历史基础 Thread 仍可由 Community 读取、下架、恢复和审计，Detail 不会删除。

生产问题优先使用兼容 forward-fix 或经过验证的备份恢复。`down` migration 仅用于隔离 up/down/up 演练，
不能当作生产数据删除方式。
