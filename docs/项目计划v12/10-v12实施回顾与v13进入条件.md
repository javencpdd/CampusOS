# CampusOS v12 实施回顾与 v13 进入条件

> 状态：草案，v12 尚未封版  
> 最近更新：2026-07-19
> 权威验收状态：[v12 计划书](00-v12版本计划书.md) 与 [测试矩阵](08-v12测试与发布验收矩阵.md)

## 1. 已实现的能力

- 可信账号链路：安全 Bootstrap、规范化 email account、历史账号兼容状态、Challenge/Ticket、邮件投递、
  验证式注册、可撤销 Session、密码找回、邮箱绑定和管理员恢复。
- 分层社区：两级 Category、board 类型策略、可靠的移动/归档/恢复命令，以及公开与管理读取边界。
- 内容一致性：普通 Thread、RichText 和编译内结构化 Thread 在同一可靠命令中协调 Revision、Detail、
  Audit 和 Outbox。
- 校园互助与二手：独立 Built-in Feature、明确 Detail 所有权、状态机、乐观并发、Feature Gate 与前台页面。
- C3.5 健壮性：结构化编辑失败回滚、回收内容状态写保护、未知内部错误脱敏，以及发布门禁执行所有 v12
  migration drill。
- A7.1 身份安全加固：普通密码找回不再要求用户抄写 Challenge ID；验证码限制收敛为 Identity Core
  的有界滑动窗口策略，并提供管理端热配置、版本冲突、细粒度权限和 required audit。
- A7.2 管理平面隔离：管理员准入独立保存在 `identity_admin_accounts`，Admin 专用登录及每请求门禁要求
  有效 Session、活动准入和 Permission Code；凭据仍只保存在 `accounts`，版主的 category scope 不被扩大。
- 可靠事件收敛：Worker 不再吞掉 Complete/Retry/Dead/Attempt/Receipt 错误，Consumer Receipt 崩溃窗口
  可最终进入 published，最大次数严格生效，历史越界事件进入 dead，管理端能安全识别最终化异常。
- 完整迁移门禁：v10/v11 兼容迁移和 v12 `000028-000038` 均已通过完整串行 PostgreSQL
  up/down/up；C3、A7.1 与 A7.2 的迁移验收阻塞已解除，Final 仍需重跑完整门禁并留存日志。

## 2. 尚未完成的 v12 验收

这不是“实现缺失”的清单，而是不可省略的真实环境证据：

1. 全量数据库审计、备份恢复和最终候选冷启动。
2. 专用测试栈上的注册、会话、Category、RichText、互助和二手 PC/移动端浏览器流程。
3. 完整 `make release-check`，其中必须在最终候选上重跑 `make v12-migration-check`。
4. 只有全部通过后才将应用、SDK、OpenAPI、docs-site 和 README 升级为 `0.12.0`。

## 3. 进入 v13 的前置条件

- v12 Final 已有可复验日志、恢复证据和发布说明，不再处于“待验收”。
- 不存在 P0 身份、迁移、内容事务或权限回归；遗留限制已明确分配到后续版本。
- 互助/二手的数据量、响应时间和失败率有最小基线；若 N+1 Detail 读取接近容量边界，先完成批量读取优化。
- 后续功能不直接改写 Identity、Community、Reliability 或 Feature Registry 的内部 Repository。
- 任何新 External Plugin/Agent 能力继续通过公开 Host API、Gateway 或受限 Runtime，不取得事务参与、数据库或
  宿主机完整权限。

## 4. v13 候选，而非当前承诺

- MFA/Passkey、OAuth、更多邮件 Provider 与分布式 Session/限流。
- 结构化帖子列表的批量 Detail 读取、容量压测、Prometheus/SLO，以及可靠 Worker 状态转换指标。
- 更严格的全站错误响应统一治理，避免各 Handler 重复实现错误翻译。
- 更多受约束的 Built-in 内容类型；External Plugin 仍不参与宿主事务。

在 v12 Final 之前，不得将上述候选混入 v12 版本声明或发布范围。
