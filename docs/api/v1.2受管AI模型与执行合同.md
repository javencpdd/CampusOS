# v1.2 受管 AI 模型与执行合同

> 更新时间：2026-10-24（Asia/Shanghai）
> 范围：V12-14a，当前 Linux；Windows 沿用用户延期。14b RAG、14c 插件 AI 能力另行验收。

## 1. 能力、配置与实例

当前14b新增组合专用 `ai.local-checked-chat/v1`，接入[公开集合本机引用问答](v1.2公开集合本机引用问答合同.md)；它强制本机Profile和当前来源回调，原有普通文本调用不授予来源读取权。以下保留14a受管执行基础合同。

`integration.ai` 是内置 Feature 的实现模块，不依赖外部插件。只发布宿主内部 `ai.managed-chat/v1` Port；旧 `integration.ai.service` 不再发布，生产 Module 的旧 `ChatCompletion` 拒绝执行。直接构造的旧 Service 只保留协议单元测试用途，不是发布给业务或插件的调用能力。

编译内置 Definition 使用 `campusos.ai-text/v1`：`builtin.openai-compatible.text` 和 `builtin.local-openai.text` 都只支持 text 输入/输出，不支持 tools、function call、streaming、音频或图像。未知能力、非法角色、未知/重复/null JSON 字段、非法 Unicode、超限文本与输出拒绝；不执行模型返回内容。

部署配置形成两个持久 Profile：`remote-chat` 与 `local-chat`。各自固定模型、精确 `/chat/completions` 端点、超时、最大输出 token、最大并发、Secret 和请求单位配额。唯一 `chat` Binding 选其一，使用非循环序列推进的十进制字符串修订做 CAS。重启保留当前绑定、启停和预算，不从默认配置覆盖；部署配置改变时推进 Profile 修订，已停用状态仍保留。

Instance 是进程内随机身份，绑定当前 Profile/Binding 修订。当前 User、会话、Feature desired/effective 状态、绑定和 Profile 在调用前、执行中与返回前重新核对；变更取消旧实例和在途请求，拒绝迟到答案。Stop 取消并等待活动调用完成必要结算，重启创建新实例。

## 2. 身份与 HTTP

内部 `ManagedChat.Invoke(ctx, currentUserResolver, runID, bindingRevision, request)` 必须由可信宿主提供当前 PostgreSQL User 会话解析器。独立 Admin、机器身份和同号另一身份域不成为 User。`runID` 为新生成的 `ar_` 加32位小写十六进制随机值；持久唯一，重复拒绝，不重放模型。调用方不能覆盖 Model、Source 或 Metadata，不能传 Knowledge/Collection/私人来源 ID。Prompt 仅是调用方明确提供的文字，不携带读取原始内容或外发私人知识的权利。`Run` 元数据只由当前原 owner 读取。

实际管理 HTTP 路径均为 `/api/v1/ai/*`，没有 `/admin` 路径段；audience 仍是独立 Admin，不能拿 User JWT 调用。

| 方法与路径 | 权限/请求 | 行为 |
| --- | --- | --- |
| GET `/api/v1/ai/status` | `ai.ai.read` | 当前选定 Definition 与有界保护就绪状态；不是一次模型调用授权 |
| GET `/api/v1/ai/logs?limit=100` | `ai.ai.read`，limit 1–100 | 从新执行元数据投影安全日志，无 Prompt/答案/提供方原始错误 |
| GET `/api/v1/ai/profiles` | `ai.ai.read` | 两个 Profile、当前 Binding、预算；无端点、SecretRef、密文或配置指纹 |
| POST `/api/v1/ai/bindings/chat` | `ai.ai.manage`；`profile_id,binding_version,profile_version` | 精确双 CAS，选定已启用且能解密的内置 Profile |
| POST `/api/v1/ai/profiles/:profile_id/state` | `ai.ai.manage`；`version,enabled` | 单 Profile CAS 启停；启用重新检查保护条件 |

所有写操作要求当前独立 Admin 权限、近期 MFA、浏览器 CSRF 和必需事务审计/Outbox；管理者不能改任意 URL、模型或明文密钥。JSON 封闭、最多4096字节、禁止查询串和版本别名。所有管理路径在鉴权前设置 `Cache-Control: private, no-store`；错误只返回稳定安全描述，不回显 SQL、端点、Key、Prompt 或提供方错误正文。没有新增 User Chat HTTP 或聊天页面。

## 3. Egress 与 Secret

远程端点必须是部署固定 HTTPS origin，使用共享 `security.EgressBroker` 检查 URL、public DNS 全部地址、固定拨号与 TLS，禁用代理和重定向，限制请求/响应字节、头部和时间。混入私网 DNS 也拒绝。没有自动重试或远程失败后改用本地 Profile 的隐式 fallback。

本地路径是显式 HTTP literal loopback IP 加端口，仅当前服务网络命名空间内预先运行的 OpenAI 兼容模型守护进程。网关不安装模型、不启动命令、不执行 shell、不接受主机名/任意局域网地址/重定向或代理。运维须选定实际部署网络中的 loopback 端点；容器内 loopback 指向容器自身。

独立 `AI_ENCRYPTION_KEYS`（`keyID:64hex`，多个以逗号分隔）和 `AI_ACTIVE_KEY_ID` 构造共享 AES-256-GCM Keyring。凭据按随机 opaque Ref 加密写入 PostgreSQL，AAD 绑定合同、Profile、Definition、精确 endpoint、chat 用途和 Ref；跨 Profile/端点复制密文或修改 Ref 不能解密。仅在受管执行边界短时解密并清理字节，不在 Admin、事件、错误或日志导出。密钥/明文凭据来自部署环境，主密钥不得存入普通备份数据目录。

缺配置、缺钥、同 ID 错误密钥或解密失败均关闭执行。已知密钥保护失败在 dispatch 前释放预算。正常轮换使用新 key ID，保留旧解密材料以恢复历史密文；原地替换同 ID 密钥不会把旧密文当可用。更换部署模型/端点/Secret 需重启并重新核对当前修订。

## 4. 预算、审计、未知结果与事件

配额单位是 **一次受管请求**，不是 token 或货币。调用前持久预留1，数据库同时限制 `charged + reserved <= quota` 和每 Profile 当前 reservation 数；多个实例/进程共享。未能标记分发的失败结算0；提交分发标记后的成功结算1，取消、超时、网络/提供方错误及提交结果不确定也保守结算1。token 用量只作描述；失败和未知结果 `usage_known=false`，不伪造0费用。预算不足拒绝新连接，配置变更/重启/恢复不清零 spent/reserved。

Profile 供应、Binding/启停、reserve、dispatch、settle 都通过既有 required Command，在同一 PostgreSQL 事务写业务事实、平台审计和元数据 Outbox。外部 HTTP 无法与数据库组成原子事务：先提交 dispatch 意图，再执行一次；不确定状态不据此重试。reserve/dispatch 审计失败不发送；settle 审计失败不释放已缓冲答案，保留未决预算。常驻有界租约扫描只结算过期元数据，已分发按未知1、未分发0，不重放模型。失败分配的版本/nonce 不复用。

执行 DTO 合同 `campusos.ai-managed/v1`，事件合同 `campusos.ai-events/v1`。每个 run 最多三项、按 ordinal 顺序：`started` → `usage` → `completed|failed|cancelled`；事件携带 run ID 与版本，usage 含 known/charged，仅确知时给用量。事件不是网络流，不提前发布提供方正文；答案只能在成功结算及当前权限复核后返回。表内事件禁止更新、删除和清空；没有 Prompt、答案、原始错误或复用会话凭据。

## 5. 数据、回退与恢复

000035 新增 `ai_model_profiles/secrets/bindings/budgets/runs/run_events` 六表、5 FK；当前35/next36，130业务/系统受管+2执行器表、143FK。owner/instance/SecretRef 的逻辑关系不冒充跨身份域 FK。Admin 静态架构、ER 和 Schema 合同同步。

任一新表非空或权限存在非播种引用，down 原子拒绝；不能删 Secret、预算或事件强制降级。空域 down/up 保留 `ai_gateway_epoch_seq` 高水位；历史1–34不可改写。数据库备份包含密文、绑定、预算和历史；部署主密钥单独托管，普通 v3 备份不含 `.env`。

官方完整恢复先隔离，停用所有 Profile、推进 Profile/Binding 修订、到期未决租约，废止旧 User/Admin 会话。可信本地授权盘点包含模型元数据/配置指纹、Binding 和预算；复核后保留出站暂停，AI 不自动重新授权，不能靠配置重启复活。历史租约仅结算，不重放；预算不清零。本文不新增全局恢复出站解禁入口。

## 6. 验收范围

验收入口：[完整 runner](../../scripts/v12-14a-managed-gateway-drill.py)。真实 PostgreSQL、正常 Server/Router/Identity、共享 Egress 与本机 TLS/HTTP 协议提供方用于验证实际调用链、撤权、预算、故障回滚、重启和官方备份恢复。验收专用 DNS/dial/TLS 固定入口受 `campusos_acceptance` build tag 限定，生产构建不存在此入口。

协议提供方不是真实 LLM，不宣称模型权重、质量或外部服务认证；令牌配额/货币价格、私人 RAG 逐步同意和 AI 插件消费/贡献仍是各自后续合同。Windows 依用户决定延期，不记作通过。历史[文本首片](v1.2AI文本能力与错误边界合同.md)及 .152 报告保留为当时快照，当前生产执行语义以本文为准。

V12-14b私人本机切片通过 `PlanLocalDisclosure` 披露当前User可核对的确切本机模型/端点/参数，不返回Secret或其引用；独立逐次同意及受管guard合同见[私人本机问答与逐次同意](v1.2私人本机问答与逐次同意合同.md)。它不改变本合同的既有管理HTTP或开放远程私人模型调用。
