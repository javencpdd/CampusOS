# v1.2 内联图片授权读取合同

> 更新时间：2026-10-12 18:04（Asia/Shanghai）
> 责任阶段：V12-02b；仅内联图片和本人上传库存切片，不代表整阶段退出。

公开图片请求必须带不可信选择器 `thread_id`。Core `/content/assets/images/:user_id/:filename` 从 Community 的受检查读取 Port 加载当前帖子；要求真实 author 等于图片目录 owner、合法事实版本、active，以及存储的 safe_html 中存在精确 `img[src]` 引用。字符串、链接或 URL 前缀不构成引用。匿名读取仍使用 published/clear/active 的公开 Policy。

RichText `/richtext/assets/:user_id/:filename` 从本模块的受检查文章投影加载原帖 Policy 与文章事实。`store=content` 选择 Core 上传目录，缺省选择 RichText 目录；只接受这两个值。父文章必须实际引用精确图片 URL，或明确以它作为封面，author 与 uploader 必须一致。RichText 图片另需唯一的持久化资产元数据，校验 owner/name/URL/size/MIME。文章不能用其 Core 摘要代替完整正文事实。

没有父帖选择器的图片是独立的本人上传库存，只接受当前完整 User Session 对该 owner 的证明。知道文件名不授予公开访问，Admin 不能冒充同 ID 的用户。请求带 Authorization 时，即使公开资源也须验证该用户会话；失效 Token 不回退匿名。库存列表也在整批返回前复核当前会话和元数据。

授权后只读取有界普通图片文件，拒绝符号链接和非图片 MIME，绑定实际字节与修改时间。投影后重读父资源、文件字节、完整 Principal；正文、owner、生命周期、防 ABA 版本、资产元数据、字节或会话改变均不返回旧字节。HTTP 返回 private/no-store、nosniff，不暴露宿主路径，也不交出稍后由 `c.File` 打开的未检查路径。此兼容文件格式没有持久化 Object 版本，不宣称可撤回已经交付的字节或跨模块原子读取。

Web 的受检查 HTML/图片组件先移除平台图片的裸 src，向同源白名单图片端点发送当前 Bearer Token，成功后展示 Blob URL。公开正文绑定实际父帖，文章中的 Core 图片转到 RichText 的父文章检查入口。凭据不进入 URL，也不发给外站；组件更新、卸载或身份会话变化时中止旧请求并释放 Blob。保留上传库存放大预览。使用方涵盖帖子、文章封面、互助/二手详情、正文预览和个人文档媒体库存。

实现与自动化证据见 [.53](../进度/v1.2-dev/v1.2.53-dev.md)、[Linux 原始报告](../项目计划书v1/项目计划v1.2/evidence/v12-02b-inline-image-linux.json) 和 [隔离演练](../../scripts/v12-02b-inline-image-drill.sh)。实际 JWT/SessionService HTTP 组件使用 Memory Identity，资源另在真实 PostgreSQL16 和实际本地图片上验收。Web 组件测试和构建不替代浏览器验收。
