> 责任阶段：V12-02b；实现、自动化及Linux目标三态通过，其余治理接入继续。

`TakeDownForPrincipal` 从实际Thread加载版块/owner/raw状态/非复用版本，使用.65当前User/Admin与单条执行见证及冻结 `community.thread.take_down` Policy。owner身份不自动授权下架；management/bound不替代执行grant，当前Admin须独立角色执行权限与15分钟MFA。进入可靠事务后锁实际凭据/授权见证及Thread，重验完整私有snapshot和资源Policy，以facts_version+revision CAS写入；最终再次复核完整身份/见证/实际资源。

Thread状态只改moderation为taken_down，保留作者publication与原正文。修订/案例/治理动作/平台必需审计/outbox同事务；任何必需失败回滚。使用.66明确actor域/opaque ID，Admin数值与User相同或opaque时，旧User BIGINT均空；新User保留旧User字段。Memory与PG对应actor适配，旧可信User案例关闭时也同步resolved actor。

新增 User `POST /api/v1/threads/:id/take-down` 使用已验证UserJWT及当前Session，实际版块执行grant在服务内检查；既有 Admin `POST /api/v1/admin/threads/:id/take-down` 使用独立Admin JWT/currentSession、角色权限及资源服务复核。Identity/Community生产窄Port装配，不以客户端body/query/header的actor、board或MFA字段认证，严格JSON拒绝未知事实字段。不存在裸ID鉴权回退。

操作只返回 `id` 和 `moderation_status`，outbox事件也只有这两字段，不回传私有标题/正文/owner或Policy绑定快照。执行权不推出读取权。Space收到当前Core的taken_down事件直接清除既有投影，不要求在事件中带私有owner/body；旧作者事件流程保持其原合同。
