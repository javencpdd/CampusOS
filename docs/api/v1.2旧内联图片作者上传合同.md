# v1.2 旧内联图片作者上传合同

> 更新时间：2026-10-14 23:00（Asia/Shanghai）
> 状态：本切片实现、自动化与 Linux PG 目标三态通过

`POST /content/assets/images` 与 `POST /richtext/assets` 每次从已验证当前 User Session 构造 Principal。前者仅接受一个 file；后者额外接受一个 thread_id/article_content_id。客户端 actor、owner、scope、路径或文章 ID 均不能构造权限事实；未知和重复表单字段拒绝。

未绑定图片使用固定 `inline-image-owner-upload-1` 本人库存 Policy；绑定图文图片使用执行相同的 Core 作者编辑 Policy，并核对实际完整 Thread/Article20。文章资源变化、完整 Principal/凭据/强度变化及当前 Feature 关闭均拒绝旧证明。上传返回现有编辑器图片元数据，不自动公开未绑定图片；既有受检查读取合同继续适用。

在实际必需 audit/outbox 命令中，按优化后字节和持久化当前 quota 分配账本；缺 override 使用配置默认值。PG owner admission/account/quota 行锁保护配额；当前降额关闭超额写入，升额按实际预算执行。照片仍保存到兼容目录，但精确字节加入与 Object 相同的容量账本。

新文件私有回执包括 inode、size、mtime、digest；SDK 或最终证明失败时补偿仅删除匹配文件。替换/修改文件保留，返回 503 清理待完成；当前事实冲突 409、无当前凭据 401、无作者范围 403、尺寸过大 413。失败 PG 元数据/账本/必需审计/outbox 同事务回滚。Memory 仅撤销该容量增量，允许保留无字节的账本 bootstrap；不恢复独立 Object 物理删除。

旧图片表没有资产 nonce；命令比较本次新记录的完整元数据直到提交。已有 Core/Article 非复用版本保护绑定资源 ABA；不宣称覆盖任意外部文件系统更换与删除之间的竞态。无需 DDL，current22/next23。

证据与具体测试：[.95 进度](../进度/v1.2-dev/v1.2.95-dev.md)。全部 V12-02b 仍需空间/其他管理路径与退出验收。

旧内联图片三入口作者上传三态通过：当前完整User与固定本人库存Policy/实际Core作者edit及完整Article20，current quota账本/实际locks与必需audit/outbox；新文件私有inode/size/mtime/digest回执、精确失败清理或pending，strict multipart/兼容URL与编辑器metadata。123必需/42真实PG、11新增含实际JWT三入口与真实路由/OpenAPI检查，十四PG执行（3成功/11真实必需SQL拒绝）及十二current/ABA/实际额外SQL变化，原112回归与共同门禁通过。
