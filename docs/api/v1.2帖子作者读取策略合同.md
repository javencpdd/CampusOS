# v1.2 帖子作者详情读取策略合同

> 更新时间：2026-10-12（Asia/Shanghai）
> 范围：V12-02b 的 `/api/v1/threads/:id/me` 作者详情读取切片。独立命名合同、HTTP 接入与消费链已完成实现、自动化、Linux 目标环境验收；证据见第 6 节。V12-02b 整阶段仍 partial。
> 合同：`campusos.policy.thread-owner-read/v1`；命名策略：`community.thread.owner_read/v1`。

## 1. 目的与边界

作者详情读取允许当前帖子作者查看草稿、私密、待审、拒绝、下架以及可恢复的回收内容，
以便编辑或恢复。它不授予编辑、发布、恢复、治理、委托或插件读取权。

这是一份独立命名合同。冻结的 `campusos.resource-policy/v1` 只有帖子编辑/下架、回复删除、
个人文档读取与知识来源读取五个动作，没有作者帖子读取动作。本切片不改其动作枚举、
事实形状、Schema 或 SDK Registry，也不借 `community.thread.edit` 的写决策读取正文。
`community.thread.public_read/v1` 仍只接受 published/clear/active，不增加作者或管理员例外。

本轮入口限定为用户域 JWT 与当前有效 Session 的 `/threads/:id/me`。Community 的
`ContentQuery` 没有作者详情方法；旧字符串 `GetThreadForViewer`、作者列表、RichText、
MutualAid/Secondhand 私有详情及附件、版块生命周期与治理/MFA Principal 接入留在后续切片。
本策略允许不代表这些路径已完成验收，也不替代入口认证或其他外层限制。

## 2. 请求与可信事实

[请求/决策 Schema](policy-thread-owner-read-v1.schema.json)的 `definitions.request` 和
`definitions.decision` 固定全部字段；[独立决策 Schema](policy-thread-owner-read-decision-v1.schema.json)
引用同一决策定义。所有对象拒绝额外属性，Principal 复用
[主体上下文](v1.2主体上下文合同.md)，Schema 仅作为离线合同，不提供公网授权入口。

| 字段 | 精确要求 | 构造责任 |
| --- | --- | --- |
| `contract` | `campusos.policy.thread-owner-read/v1` | 宿主支持版本 |
| `request_id` | 每次求值的新不透明 ID | 宿主生成，不接受客户端请求 ID 作绑定 |
| `policy` | `community.thread.owner_read/v1` | 服务选择命名策略 |
| `principal` | 完整 `campusos.principal/v1` | 用户域入口完成签名、用途、Session 活性、账号状态/AuthVersion 与真实认证强度验证后构造 |
| `facts.resource` | `{kind:"community.thread",id}` | Community 实际读取的帖子，与目标 ID 核对 |
| `facts.owner` | `{kind:"user",id}` | 当前权威 `Thread.AuthorID` |
| `facts.board` | `{kind:"community.board",id}` | 当前权威 `Thread.CategoryID` |
| `facts.facts_version` | 非空不透明版本 | 与事实及正文来自同一行；覆盖 owner、版块、三种状态及内容修订，包括 ABA |
| `facts.publication_status` | `draft` / `published` / `private` | 原始发布事实 |
| `facts.moderation_status` | `clear` / `pending` / `rejected` / `taken_down` | 原始审核事实 |
| `facts.deletion_status` | `active` / `trashed` / `purged` | 原始删除事实 |

Go 的 `ThreadOwnerReadFacts` 是 `ThreadPublicReadFacts` 的类型别名，**仅共享原始事实形状和
校验**，不复用公开策略的允许条件。ID/版本继续使用 Principal 的 1～128 字符不透明 ID
规则；缺失、空白、路径、未知状态或缺版本均拒绝，不能从 legacy `status` 填充。
正文、owner、版块、事实版本和状态不能由客户端或插件提交。

`credential_id` 必须引用已验证的当前活跃 Session，不能由 `user_id` 伪造。认证适配器
需提供真实 `password` 或 `mfa` 强度，不允许默认升级。Principal DTO 的结构合法不证明
认证成功；本内核不验证 JWT、不读取凭据，也不提供 JSON 请求解析器。外部 JSON 即使
通过 Schema，也不能作为可信 Principal 或事实传入本入口。

## 3. 允许条件

输入先通过严格 DTO 校验；合法输入只有以下合取允许：

1. `principal.actor.kind=user`，`audience=user`，强度为 password/mfa，具有有效凭据引用。
2. `principal.actor.id` 等于当前 `facts.owner.id`。
3. 发布与审核状态属于上表合法集合，删除状态为 `active` 或 `trashed`。

因此 36 个合法三维组合中，当前作者允许 24 个、purged 拒绝 12 个；非作者用户及其余
五个主体域全部拒绝。同数字 ID 的 Admin、Integration、Plugin/Worker，以及指向作者的
`effective_subject` 都不能代替当前 user actor。作者被下架或回收内容可读的既有语义保留，
但不因此取得重新发布或恢复权。

结果必须携带 contract、request_id、policy、完整 principal、类型化 resource 和事实版本。
principal 是内部绑定，含 Session 引用；决策不得作为 HTTP 正文、Token 或跨请求通行证暴露。
纯内核复制代理主体引用，避免请求对象的可变指针改变已经返回的决策。

| effect | reason | obligations |
| --- | --- | --- |
| `allow` | `policy.owner_read` | 必须且仅为 `["recheck_current_facts"]` |
| `deny` | `policy.owner_read_denied` | 必须为 `[]` |

没有 required audit 写义务。未知 effect/reason、矛盾组合、缺失/重复/未知义务均拒绝。
deny 不回显未匹配的主体域、owner、审核/删除状态或正文。

## 4. 消费与返回顺序

`CheckThreadOwnerReadDecision(request, decision, currentFacts, currentPrincipal)` 必须在宿主
可信同次调用内使用：

1. 检查决策结构及 contract/request ID/策略/类型化资源/版本/完整 Principal 与请求绑定。
   有效 deny 结束读取；即使伪造为 allow，非作者、错误主体域或 purged 原事实仍不能消费。
2. 比较全部当前事实与初始事实；比较完整当前 Principal，包括凭据、用途、认证强度和代理
   字段。任何变化或当前结构无效都失效，不只比较版本字符串或 user ID。
3. Community 以 owner、期望版本、合法原始状态及未物理删除条件，从权威源原子读取同行
   正文。Memory 使用同一锁；PostgreSQL 使用同一语句快照。`000016` 版本须对相关变更与
   ABA 推进，读取不能回退或复用缓存/索引里的权限事实。
4. 竞争后重新读取、构造事实并生成新 request ID/决策，最多三次。持续竞争拒绝，不盲目
   重试旧 allow。入口还须复核当前 Session；该纯函数不负责读取 Session 或跨模块事务。

最终受条件保护的同行读取是资源事实与正文的有效时点。该时点之后已返回的字节无法通过
后续撤权收回。作者详情读取不增加浏览量。`/me` 已选择的公开分支继续遵守公开策略；
公开分支遇到撤私密/下架不得在旧公开 allow 之后追加作者例外。

## 5. 错误与当前实现

[错误目录](policy-thread-owner-read-v1.errors.json)固定内部合同错误的入口映射建议：

| 错误 | HTTP 行为 |
| --- | --- |
| `policy.input_invalid` / `policy.contract_unsupported` | 宿主构造输入/版本错误，安全 `internal.error` / 500；不暴露事实 |
| `policy.owner_read_denied` | 通用 `thread.not_found` / 404，不区分错误主体域、非作者或已清除 |
| `policy.decision_mismatch` | 安全 `internal.error` / 500 |
| `policy.facts_changed` | 先重新读取授权；持续竞争使用 `resource.conflict` / 409 |

未认证或当前 Session 无效由入口返回 401。没有接受 Policy DTO 的外部参数，因此内部事实
错误不映射为客户端可修复的 400。上述错误不直接回显 Go 内部错误原文；现有 HTTP 包络保留。

[Port](../../internal/modules/core/identity/port/thread_owner_read_policy.go)与
[纯内核](../../internal/modules/core/identity/policy/thread_owner_read.go)使用当前事实 DTO，零值
可用，没有缓存、事实加载器或仓储依赖。[策略测试](../../internal/modules/core/identity/policy/thread_owner_read_test.go)
覆盖六个主体域×36 状态共 216 个组合、非作者、真实强度形状、非法输入、64 并发调用和
代理主体复制；[消费测试](../../internal/modules/core/identity/port/thread_owner_read_policy_test.go)
覆盖决策绑定、完整事实/Principal 变化及伪造 allow。定向 Go/race 检查与离线 Schema 检查不
替代该入口的真实 JWT、PostgreSQL 并发、读取故障及共同门禁验收。

## 6. V12-02b 作者详情切片验收

[HTTP](../../internal/modules/core/community/handler/thread_handler.go)从已经通过用户域 JWT
中间件的 `user_id`、`session_id`、`auth_version` 构造验证请求；经当前
`SessionVerifier` → `SessionAuthenticationStrengthReader` → `SessionVerifier` 复核后才构造
Principal，`credential_id` 使用真实 Session ID。查询和请求体不能填入可信 facts/Principal。
Community 模块绑定 Identity 两个 Port；缺失 Port 的独立装配可以启动，但此入口返回 401。

[服务](../../internal/modules/core/community/service/thread_owner_read.go)的 `GetThreadForPrincipal`
首先解析当前可信身份并读取原始事实。已选择公开状态时进入原公开链，公开撤权不回退作者例外；
其他状态进入独立 owner Policy。最终 `RecheckOwnerThread` 在
[PG](../../internal/modules/core/community/repository/pg_thread_repository.go)同一语句或
[Memory](../../internal/modules/core/community/repository/thread_repository.go)同一读锁内限制
owner、期望版本、合法原始状态与未物理删除，并返回同行正文。服务在该读取前后再次解析当前
身份并复核完整 Principal/事实；变化重新生成决策，最多三次，持续竞争安全 409。
非作者或 purged 返回通用 404，当前会话无效返回 401，内部故障安全 500。
