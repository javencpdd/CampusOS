# v1.2 帖子作者编辑接入合同

> 更新时间：2026-10-12 19:33（Asia/Shanghai）
> 责任阶段：V12-02b；此切片只覆盖Community discussion作者编辑，不代表全部作者生命周期或治理写入。

HTTP PUT `/threads/:id` 仅处理discussion；typed Feature必须经各自正文/Detail命令，以免撕裂投影。该入口 从实际当前User Session构造完整Principal，调用 `UpdateThreadForPrincipal`；客户端不能提供author、Principal、grant或事实版本。服务端加载真实帖子raw三态、owner、board及非复用facts_version，使用冻结 `community.thread.edit` 纯Policy判定。独立Admin、其他用户、回收/清除状态、缺失证明或不可用事实均不获得编辑权。

允许后必须有真实可靠命令、事务、治理仓储与事实CAS Port。事务内按用户账号→会话顺序锁定当前凭据行，再锁定原帖并复核同一个Policy决策/完整Principal/原始事实。按实际保存的格式执行Core正文安全规范化，拒绝未知发布状态；写入同时比较facts_version与修订号，防止owner、board、状态或正文ABA在修订号不变时绕过；保留即时浏览/回复/点赞计数。提交前复核会话与结果资源的author、board、active及新版本。

内容修订、平台必需审计、outbox与帖子写入同事务提交；审计或投影失败回滚实际数据。之后才失效外部缓存。裸actor字符串的旧服务方法保留为可信进程内原语，不作为HTTP缺少证明时的回退。Memory使用同一个TxKernel串行化命令与登记的回滚快照；不假称跨进程行锁。PostgreSQL通过当前事务执行器保留账号/会话/资源锁。

作者编辑不授予读取，不把owner_read用于写入。本人恢复回收、删除、提交审核、创建与Feature写入仍需各自路径接入，不将deleted映射成active骗过编辑Policy。治理/Admin/MFA及域审计、批量与有效权限预览继续由02b责任清单跟踪。

实现与验收执行状态见[.55](../进度/v1.2-dev/v1.2.55-dev.md)和[隔离演练](../../scripts/v12-02b-author-write-drill.sh)。实现/自动化/Linux目标与共同门禁通过：28必需顶层含3真实PG、实际JWT HTTP，详见[原始报告](../项目计划书v1/项目计划v1.2/evidence/v12-02b-author-write-linux.json)。
