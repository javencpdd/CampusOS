# v1.2 回复作者写入接入合同

> 更新时间：2026-10-13 10:43（Asia/Shanghai）
> 责任阶段：V12-02b；回复作者三路径实现、自动化及Linux目标三态通过，治理/列表后继继续。

当前User的回复创建/编辑/本人删除使用独立 `community.post.owner_write/v1` 纯规则。创建不虚构尚不存在的Post：实际父帖active、未锁定，当前用户为父帖owner或父帖published/clear，同时实际版块/group/type配置允许。编辑/删除只允许当前User拥有的active/published Post与active父帖；这不授予版块治理执行权，也不调用冻结 `community.post.delete` 将owner替代grant。Admin不能冒充同数值User。

Core从自己的实际ParentThread/Post及引用回复构造事实，初始与事务内命名规则绑定完整Principal/Parent/实际Post版本。当前User/Session先复核并锁，再锁创建版块/type配置、父帖和实际Post或引用回复；父帖锁使分配楼层及reply_count写入串行。引用Floor来自当前实际父回复，并在提交前再次验证完整引用快照。

正文经Core editor按实际存储格式规范化；000019 content/delete CAS拒绝旧版本，删除记录typed User域而保留正文。Post、reply_count、创建通知、必需审计和outbox原子；最终重新验证当前Session、创建配置、完整父帖事实/计数及Post/引用快照。操作事件只带post_id/thread_id，不广播私有父帖或回复正文。创建/编辑响应只返回当前本人回复，删除204；内部包含deleted的仓储不新增HTTP入口。

三个现有User HTTP写入口全部使用已验证JWT的subject/session/auth_version，经当前User Session verifier/strength重建完整Principal，缺适配器不回退裸ID；未知body事实字段被拒绝，query/header不定义actor/owner/MFA。Community生产装配传递实际Thread命令源与User proof。列表/治理删除后继单独接入。
