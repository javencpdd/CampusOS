# v1.2 事件元数据与管理执行事实接入合同

> 更新时间：2026-10-13 19:39（Asia/Shanghai）
> 责任阶段：V12-02b；本切片实现、自动化及Linux目标三态通过；其他02b责任继续。

Identity提供独立Admin命名执行事实源 `identity.admin-execution-authority`。仅接受明确动作及scope：Thread read/pin/lock/review/trash/direct_restore/restore/purge绑定实际版块，事件元数据read绑定 `platform.event_metadata/recent`。当前账号/会话及完整角色、绑定、权限事实两次加载，精确权限码决定Allowed；写动作还要求15分钟内MFA，读取允许当前password会话。调用者必须从实际业务加载scope并执行自己的资源规则；此源不授予私有原文读权，不扩展冻结五动作Policy或User版块grant，不接纳管理边界作为执行凭据。

执行见证绑定完整Principal、查询、账号/会话版本、有效期和所有实际角色/权限元数据及非复用版本。事务锁模式只能在真实事务内使用；按现有凭据/角色/绑定/权限锁顺序锁实际行。返回结构全部字段禁止JSON序列化，非客户端能力。其他命名治理命令尚未接入，不将事实源验收等同业务命令完成。

`GET /api/v1/events`改为独立Admin当前Session和精确 `platform.reliability.read`。签名subject/session必须对应实际Admin，User角色或同编号User不能替代。初始和最终反复检查完整见证，期间获取两次同一过滤条件的整页和total；撤权、成员/count变化或空页期间变化失败，不输出旧页/部分total。

EventBus在同一锁内先按标准类型过滤再计算total和limit（1–100），只投影规范UUID ID、允许类型、由类型派生的固定来源、有效时间。未知类型归为other；非法ID/时间不输出。完全不访问或序列化原始Data、Subject、Source、Extensions，恶意Data序列化器不会被调用。Admin事件页面只显示四列元数据，服务器筛选，失败清空旧数据，迟到响应不能覆盖新的筛选结果。

验证分层：真实JWT HTTP使用实际Memory Identity仓储；真实PG验证当前Admin权限见证、行锁、提交变化和scope重放；浏览器使用已构建Admin和仅loopback模拟API，检查渲染/筛选/失败清空，不能等同真实后端浏览器登录验收。
