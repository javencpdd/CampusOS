# v1.2 G1：插件 v5 包形态与宿主合同版本协商

> 状态：目标合同的包形态投影、发布外封、SDK DTO 与 Linux 离线验收已交付；完整 Manifest、安装与运行时仍未交付。  
> 当前生产路径仍使用 v4；本文不能作为 v5 包已可安装的说明。

## 1. 本切片边界

本切片冻结 campusos.plugin/v5 包的身份、三种交付形态、受支持宿主合同版本、首批贡献点的最小标识，以及不可变发布外封。它是**完整 v5 Manifest 的形态投影**，不是完整安装器输入。后续 G1 切片须补齐 consumes 的宿主能力与 Scope、provides 的输入/输出与配置 Schema、host_resources、状态/配额和旧机制删除清单；V12-03a 再将这些合同组合成唯一完整 Manifest 并替换 v4 校验器及示例。不得用本投影直接批准或安装插件。

机器合同：[包形态 Schema](plugin-v5-package-shape-v1.schema.json)、[发布外封 Schema](plugin-v5-release-v1.schema.json)、[错误目录](plugin-v5-package-shape-v1.errors.json)、[SDK 类型](../../sdk/typescript/src/plugin-v5-package-shape.ts)、[离线验收脚本](../../scripts/check-v12-plugin-v5-shape-contract.mjs)。

## 2. 包形态

publisher/key/version 是发布身份；api_version 必须为 campusos.plugin/v5。host_contracts 是明确列出的可接受版本，宿主仅在自身**已发布且支持**的版本与该列表有交集时继续；插件不能凭声明使宿主升级或修改源码。当前生产 Host API 及 v4 安装路径不因此变成 v5 支持方。离线夹具里的 campusos.host/v1 仅为合成协商环境。

runtime=none 要求至少一个 UI audience，无后端且不得提供后端贡献；这是 UI-only 包。runtime=wasm/container 要求相应类型的后端产物，至少一个具名 Provider 贡献；可有 UI（组合包）或无 UI（headless）。http/grpc/host-call 是传输，不是第四种 Runtime。首批具名贡献点只允许 preview.renderer/v1、ai.chat/v1、knowledge.source/v1。同一包内 UI audience 和贡献 ID 不能重复；未发布的点或版本须拒绝。这里仅冻结最小标识，输入/输出 Schema 与能力校验仍待 G1。

UI 与 Wasm 文件定位符只能是相对包路径；容器镜像必须固定为 @sha256 摘要，不能用浮动 tag。Schema 是形状检查；V12-03a 的真实包校验还必须检查规范化路径、符号链接、文件字节、大小与摘要。封闭字段拒绝宿主安装脚本、目录或数据库连接等临时扩权字段；不能因为本投影没有 consumes 就推断插件可调用任何 Host API。

## 3. 发布外封与拒绝规则

发布外封携带与 Manifest 相同的 publisher/key/version、包摘要与签名字段。摘要放在外封，避免 Manifest 自含自身摘要的循环。相同发布身份及版本一旦登记，另一个摘要必须拒绝；相同摘要可幂等再查。错误映射见机器目录。签名字段存在性与长度在本切片可自动校验，但**签名真实性、发布者信任、撤销、真实包字节摘要、容器拉取与安装事务**都归 V12-03a/03b；签名不意味着插件安全。

离线验收脚本用固定合成宿主合同集、内存发布索引、Ajv 与 TypeScript 检查正反例和形态矩阵；不连接生产服务。它记录每个输入摘要与 Linux 离线报告。错误先按形状、再按宿主版本、产物、贡献、发布身份/摘要顺序判断；实际安装器必须同样失败关闭，不能凭 DTO 成功替代真实验证。
