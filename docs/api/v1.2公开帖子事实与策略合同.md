# v1.2 公开帖子 ResourceFacts 与 Policy 决策合同

> 状态：V12-G1 合同切片已冻结并通过 Linux 离线验收；运行时接入待 V12-02a/02b。
> 合同：`campusos.policy.thread-public-read/v1`；命名策略：`community.thread.public_read/v1`。

## 1. 责任与范围

本合同固定“当前帖子是否满足公开状态条件”的输入、决策和消费义务，衔接已冻结的
[主体上下文](v1.2主体上下文合同.md)。它是完整授权链中的一个谓词，不承担身份、路由用途、
版块 ACL、Integration Scope、插件 Declaration/Grant/Consent、功能/实例状态或出站许可检查。
外层任一条件拒绝，最终仍拒绝；public-read 的 allow 不能授予别的动作。

[Schema](policy-thread-public-read-v1.schema.json) 的 `definitions.request` 和 `definitions.decision`
分别定义输入/输出，根 Schema 接受其中一种；依赖本地注册的 Principal Schema，不加载远程引用。
[SDK DTO](../../sdk/typescript/src/thread-public-read-policy.ts) 用于宿主/测试适配器描述类型；
没有提供远程授权客户端、可由插件填写的事实入口或新的 HTTP 路由。

依赖方向仍为 `业务服务读取当前事实 → 纯 Policy Port → 业务服务执行并复核`。Core 不查找
Feature Service、索引、数据库全局资源加载器或任意 SQL。Schema 验证只检查结构；任何来源的
同形 JSON 都不能自行成为可信事实。测试脚本里的 referenceDecision/consume 是可执行规范，
不属于线上 Authorizer，也没有被宿主导入。

## 2. Request 与可信事实

| 字段 | 约束 | 构造责任 |
| --- | --- | --- |
| `contract` | 精确 `campusos.policy.thread-public-read/v1` | 宿主支持版本 |
| `request_id` | 不透明 ID，同次决策的唯一关联值 | 宿主每次 Policy 调用生成，绑定调用上下文；不可复用客户端自报 ID 作授权绑定 |
| `policy` | 精确 `community.thread.public_read/v1` | 服务选择的命名策略，不能改成 global/owner 分支 |
| `principal` | 完整 `campusos.principal/v1` | 对应域认证适配器已验证的主体；本策略不重新解析 Token |
| `facts.resource` | `{kind:"community.thread",id}` | Community 实际读取的目标帖子；与业务请求目标核对 |
| `facts.owner` | `{kind:"user",id}` | 权威 Thread.AuthorID；只记录关系，不给予公开读取例外 |
| `facts.board` | `{kind:"community.board",id}` | 权威 Thread.CategoryID；版块也是本资源的父引用，不再复制另一份 parent_id |
| `facts.facts_version` | 非空不透明版本 | Community 对当前事实快照给出的版本标识；见下文 |
| `facts.publication_status` | `draft` / `published` / `private` | 作者发布事实 |
| `facts.moderation_status` | `clear` / `pending` / `rejected` / `taken_down` | 审核事实 |
| `facts.deletion_status` | `active` / `trashed` / `purged` | 回收/删除事实 |

所有字段必填，所有对象拒绝额外属性。ID/版本沿用 Principal 的 1～128 字符不透明字符串规则；
不接受数值 ID、null、空字符串、空白或路径。禁止将 status、roles、SQL、正文或 allowed 布尔值
塞入 facts。缺失/未知状态必须拒绝，不能默认 published/clear/active。

`facts_version` 必须覆盖资源/owner/版块、三种状态与当前内容修订的变化；不能只拿正文修订号
冒充全部授权事实版本。02b 的适配器需在同一一致性读取中构造事实和内容，并证明版本随相关
变更推进（包括改变后恢复的 ABA）。本合同不提前规定迁移字段或摘要算法。版本不是秘密或签名，
不能仅凭客户端提供的相等字符串通过复核。资源已经不存在/无法读取时，业务入口返回不可见，
不伪造 active 事实；purged 夹具仅用于验证拒绝，不意味着常规查询能读取已物理删除记录。

## 3. 命名策略与 Decision

唯一允许组合：`published ∩ clear ∩ active`。其余 35 种合法状态组合均拒绝。主体类型、是否
作者、管理员认证强度或代理用户关系不会放宽这个谓词。作者查看私有草稿、后台治理分别属于
其他尚待冻结的命名策略，不能复用本策略增加 owner/admin 例外。

输出必须带回 `contract`、`request_id`、`policy`、`resource`（kind 与 ID）、`facts_version`。
策略标识中的 `/v1` 即策略版本，输入与结果必须精确匹配。

| effect | reason | obligations |
| --- | --- | --- |
| `allow` | `policy.public_read` | 必须且仅为 `["recheck_current_facts"]` |
| `deny` | `policy.resource_not_public` | 必须为 `[]` |

unknown effect/reason、相互矛盾的 effect/reason、缺义务、重复/未知义务都拒绝。deny 不泄露具体
私密、审核或回收状态；返回不含 owner、正文、角色或任何 Token。

消费决策时必须：

1. 验证结果结构和 request_id、命名策略、类型化资源、事实版本与本次请求一致。只在宿主已验证
   的同次调用上下文里使用，不保存为跨请求通行证；不接受插件或模型伪造的 Policy 结果。
2. deny 立即结束。本公开谓词允许时仍需满足外层所有授权限制；机器/插件不因资源公开就跳过
   入口 Scope、Grant/Consent 或实例状态。匿名公开路由与机器专用入口分别处理。
3. 在返回内容前从权威源复核事实与内容修订；版本变化或资源/owner/版块/状态变化均停止返回，
   重新读取并重新授权。不能等待缓存失效或异步删除索引；旧决策不能让已下架数据继续可读。
4. 02b 实现时在一致性快照/事务或等价版本验证中确定复核与返回的顺序；本轮离线“前后事实”
   用例不证明并发安全或数据库隔离。已返回的内容无法靠后续撤权收回。

列表过滤、计数和分页必须由同一公开谓词约束，不能先分页再删无权行，更不能让旧总数泄露
不可见记录。该要求已记录为 02b 接入门禁；本次没有发布查询 Port 或任意 SQL 输入。

## 4. 版本与错误

精确版本匹配、未知字段拒绝，不转换旧 status，不自动降级。结构改变或增添状态/义务需新版本。
[目标错误目录](policy-thread-public-read-v1.errors.json) 不修改当前 HTTP 错误目录：

| 代码 | 目标 HTTP 映射 | 行为 |
| --- | ---: | --- |
| `policy.input_invalid` | 400 | 缺字段、未知策略/状态、非法主体或事实；拒绝求值 |
| `policy.contract_unsupported` | 400 | contract 为未知字符串；在其他字段检查前拒绝 |
| `policy.resource_not_public` | 404 | 公开读取不可见，通用 Resource not found |
| `policy.decision_mismatch` | 500 | 宿主得到结构错误或不属于本次调用的决策，拒绝返回内容并记录低敏内部诊断 |
| `policy.facts_changed` | 409 | 复核发现事实变化；先重新读取再重新授权，禁止盲目重试原结果 |

以上均 `retryable=false`，不回显事实。后续适配器须保持当前响应包络要求；本切片未新增路由。
JSON 重复键/尾随值、认证失败和权威事实读取故障仍由具体 ingress/业务适配器处理，不能据此
宣称字节解析、数据库故障或实际 401/403 路径已验收。
