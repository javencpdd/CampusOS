# v1.2 G1：插件配置 Schema 与 Secret 分流目标合同

> 状态：G1 有界输入合同与 SDK 已验收；V12-01b 已实现共享 Keyring、v5 PostgreSQL 配置仓储、Secret 代用 Broker、Egress、资源策略/用途预算及显式启用的后台换钥；表单/Dispatcher/Runtime 接入分别归 V12-04、03c、05/06。阶段三态和退出证据见主计划及 .26。

[配置决定输入](plugin-v5-config-v1.schema.json)把系统/用户配置定义为版本化、封闭对象 Schema。v1.2 首批仅支持最多 32 个扁平 string/integer/number/boolean 字段、标题、枚举及类型相符的长度/数值约束；配置 Schema 字节长度不超过 16 KiB。拒绝远程或本地 $ref、嵌套数组/对象、脚本关键字、未知关键字、无效默认值和未知字段。默认值必须由相同 Schema 校验。真实安装器必须以宿主固定的同一子集验证包内配置定义；不运行插件提供的校验脚本或表单代码。

Profile/公开集合选择器只指向已声明的 string 字段，选项来自宿主对当前操作者可见的事实。保存时以及调用时都要复核；离线验收覆盖选项移除。普通配置与 Secret 引用分别提交；普通字段不得与 secret_names 重名，更新只接受 secret-ref 标识，不接收明文或遮盖占位符作为密钥写回。Secret Broker 在 V12-01b 按已批准 Profile、目标和用途验证引用，当前合同不声称任何 secret-ref 已获批准。 内部活跃行重加密只更新密钥封装，既不授权 secret-ref，也不改变普通配置与 Secret 引用的分流规则；本地运维分批重封装不授予插件新能力；旧备份和历史密文所需的旧 key 仍须独立保留。

本地 `campusosctl secret inspect-key --key-id ID` 仅凭 `DATABASE_DSN` 对现行 `plugin_secret_values` 建立 PostgreSQL `REPEATABLE READ READ ONLY` 快照，跨插件聚合指定 key ID 的 active/rotated/revoked/other、总引用数与插件数；不要求 Keyring，不读取名称或密文/明文，不写审计，也不授予插件任何新能力。零引用不覆盖备份、其他存储或快照后的写入，不能单独作为旧 key 退役依据。

更新携带 expected_revision，版本冲突明确拒绝；`PgPluginV5ConfigStore` 在事务中比较并递增 revision，配置定义来自 immutable Manifest；000007 仅新增宿主配置表，不重复定义表。01b独立仓储首次默认快照 revision=1，成功写入从2开始；当前03b/04受管命令使用独立的非复用字符串计数，未持久化默认值可返回revision=0，客户端始终使用实际读取值而不自行加一；跨 owner/版本引用拒绝，受限选择器在保存/读取/代用前复核。数字、整数边界与枚举用精确十进制比较。无 UI 的包同样通过受管配置入口配置和诊断。Schema 是输入合同，不授予 Profile、集合、业务 API 或网络资源权限。[目标错误目录](plugin-v5-config-v1.errors.json)、[SDK 类型](../../sdk/typescript/src/plugin-v5-config.ts)和[离线检查器](../../scripts/check-v12-plugin-v5-config-contract.mjs)固定拒绝语义。V12-04 负责管理端表单与 Secret 分栏，V12-07 负责版本升级配置快照/恢复；旧 v4 路径已按阶段退役，不能回退授权。

执行：node scripts/check-v12-plugin-v5-config-contract.mjs。

## V12-01b 实现验收边界

普通 `values` 与 `secret_refs` 分列保存，ref 在一个配置快照内唯一；ref 本身不授权 Secret。Broker 每次将 Secret 名、ref、Profile、完整 HTTPS URL、purpose 与当前 Grant/Consent 的 `secret_bindings` 精确比对，同 ref 跨名重绑定须重新批准。仅受信宿主 dispatch 可调用；旧明文 Host API 和 SDK 方法持续关闭。宿主固定 POST/Bearer、禁止重定向、响应只含状态码，避免任意响应回显凭据。

Egress 对 URL、DNS 解析结果、实际拨号、重定向及字节/时间预算逐层收紧，资源策略四方交集与每次当前授权复核分别执行。用途预算为单进程宿主组件；未知网络结果全额计费，禁止盲重试。Server 后台 Worker 默认关闭，显式启用参数和故障恢复见[配置边界](../architecture/配置与运行边界.md)。隔离 PostgreSQL dump/restore 验证配置、Secret 和审计，整库认证代次/对象/包恢复仍由 V12-08b 验收。

## V12-04 当前表单与分流

更新时间：2026-10-18（Asia/Shanghai）。Admin 与 User `/plugin-config` 从不可变 Manifest 生成四类扁平字段、同类型枚举、可选缺省及受限选择器；按 system/user/both 控制当前 owner，数据不写浏览器持久存储。数值使用文本输入和精确 JSON 数字词法解析/序列化，BIGINT、相邻高精度小数及数字枚举不会经过 JavaScript 浮点取整；服务端继续精确比较。

普通值使用 `configuration_part: "values"`，仅提交 `values`；独立密钥表单使用 `configuration_part: "secret_refs"`，仅提交 `secret_refs`。两者共享当前字符串 `expected_revision`，服务端锁定并原子合并当前另一半、校验、写配置和审计；混合 payload 拒绝，普通保存不清空引用。分别保存可移除已撤销的选择/引用，不因另一半已失效而阻止修复；Runtime 使用时仍必须同时验证完整快照。

`GET /[admin/]plugin-v5/:publisher/:key/:version/config-options` 从当前操作者可见的编译宿主 Port 提供每类最多 128 个选项，仅接受这些当前事实；保存和运行前再核对。生产 Profile/Knowledge/v5 Secret 目录尚未绑定时返回空选项并拒绝虚构引用，不借旧插件表 ID 外键映射，也不提前创建后继业务。已有绑定可保留/明确移除；没有明文或任意 ref 输入，`config.read` Bridge 只返回普通值。

保存继续要求当前两域身份、Admin 权限/MFA、浏览器 CSRF、精确 CAS 和 required audit。成功后重新读取，未知结果/冲突不自动重试；身份、选择、权限变化时丢弃旧响应。配置成功与 Runner observed 独立。UI Host 与 PDF 资源边界见[Bridge 合同](v1.2插件UI宿主与Bridge合同.md)。最初仅文字/开关的 [.120](../进度/v1.2-dev/v1.2.120-dev.md) 及其原报告保留为历史切片证据。
