# v1.2 G1：插件配置 Schema 与 Secret 分流目标合同

> 状态：有界输入子集、SDK DTO、默认值/版本/选择器/Secret 引用离线验收已交付；真实表单和持久化尚未接入。

[配置决定输入](plugin-v5-config-v1.schema.json)把系统/用户配置定义为版本化、封闭对象 Schema。v1.2 首批仅支持最多 32 个扁平 string/integer/number/boolean 字段、标题、枚举及类型相符的长度/数值约束；配置 Schema 字节长度不超过 16 KiB。拒绝远程或本地 $ref、嵌套数组/对象、脚本关键字、未知关键字、无效默认值和未知字段。默认值必须由相同 Schema 校验。真实安装器必须以宿主固定的同一子集验证包内配置定义；不运行插件提供的校验脚本或表单代码。

Profile/公开集合选择器只指向已声明的 string 字段，选项来自宿主对当前操作者可见的事实。保存时以及调用时都要复核；离线验收覆盖选项移除。普通配置与 Secret 引用分别提交；普通字段不得与 secret_names 重名，更新只接受 secret-ref 标识，不接收明文或遮盖占位符作为密钥写回。Secret Broker 在 V12-01b 按已批准 Profile、目标和用途验证引用，当前合同不声称任何 secret-ref 已获批准。

更新携带 expected_revision，版本冲突明确拒绝；真实仓储须在事务中比较并递增版本。无 UI 的包同样通过受管配置入口配置和诊断。Schema 是输入合同，不授予 Profile、集合、业务 API 或网络资源权限。[目标错误目录](plugin-v5-config-v1.errors.json)、[SDK 类型](../../sdk/typescript/src/plugin-v5-config.ts)和[离线检查器](../../scripts/check-v12-plugin-v5-config-contract.mjs)固定拒绝语义。V12-04 负责管理端表单与 Secret 分栏，V12-07 负责版本升级配置快照/恢复；当前生产 v4 行为不变。

执行：node scripts/check-v12-plugin-v5-config-contract.mjs。
