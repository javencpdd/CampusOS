# v1.2 公开知识词法检索 Port 合同

> 更新时间：2026-10-22 11:15（Asia/Shanghai）

## 范围和入口

正常Knowledge模块Start提供`knowledge.public-retrieval`，接口`PublicRetrieval.SearchPublic`。采用内置`builtin.lexical/v1`，无外部插件安装即可运行。此Port只接受匿名公开来源，与09a公开来源Port语义相同；没有Principal、Admin override、客户端ACL或出站许可参数，不能扩大来源权。首片.143只发布内部Port；后续.144通过公开搜索HTTP适配器接通同一匿名公开语义及精确引用重开，见[HTTP合同](v1.2公开知识搜索HTTP合同.md)。Web/Admin UI、Host API/SDK/MCP/Integration入口仍待所属阶段分别接通其认证/端点Scope，不可把内部Port当作外部能力注册。

请求为一个规范kc_集合ID、query、page和page_size：query≤1024 UTF8字节，拒绝控制字符及空关键词；Unicode字母/数字分词，转小写去重，最多16项；page为1–100000，page_size为1–50。标点是分隔符，不支持SQL通配符、查询语言、自然语言改写、中文语义切词或模型调用。例如“图书馆 开放”要求两个字面子串同时出现在同一来源标题/正文中；“OR”只是普通字面词。

## 当前事实、排名和计数

Feature默认关闭。单次查询最多5秒；集合必须active，索引必须有与当前集合版本一致的完整ready_generation且run_generation为0。缺失、构建中、禁用和超限分别按现有错误返回，不回退旧代次。按集合→job→规则/成员→文档顺序在CheckedRead事务中锁定，阻止与后台执行器反向锁序或混合代次。

检索只读文档按128项页枚举（持久执行器仍32项），至多1000行，当前可读文本（标题+分块）合计≤4MiB。每个文档先经09b当前G1、来源/集合/规则/成员/板块证明、parser/chunker/Profile及完整投影复核，才送入Provider。私密、撤回、已删除、移板块或旧修订不参与排名、计数或片段；超限整个请求失败，不截断后返回部分总数。Provider只得到分离复制的公开标题/分块/ID，无仓储、ACL、凭据、来源URL或模型网络能力。

内置词法策略对每个查询词做Unicode小写后的字面子串匹配，多个词为AND，可跨正文分块出现。标题命中的不同词各4分，最佳分块命中的不同词各1分，重复堆词不加分；同分按文档ID稳定排序。同一来源出现在板块/单篇等重叠规则时只返回一次。关键词跨1024码点分块边界时，以足够的后续文本上下文匹配，不能丢失边界词。

Provider输出只是候选ID/最佳块/分数，宿主拒绝未知/重复ID、错误块或不符合固定词法合同的分值，并从自己的已核验文档构造片段/解释/URL。Provider不能通过修改输入切片伪造宿主输出。全部可能影响总数的候选在排名后再次复核当前关系和G1，任何中途撤回、规则/板块代次变化、Feature关闭、Stop或取消均失败关闭，不返回先前算出的总数或部分页面。

去重和当前可见性过滤完成后才计算total和切页。每次请求独立核对当前事实；不承诺跨多个分页请求的静态快照。当前策略使用单集合有界扫描及下述候选优化；性能验收范围限定于已冻结规模，不推断更大规模。

## 片段、解释和引用

返回title、≤240 Unicode码点的原文连续snippet（纯文本数据）、整数score和查询词/标题词/最佳块词及固定4/1权重解释。片段可包含原Markdown字面文本；调用方必须作为非可信纯文本处理，不能当HTML、指令或工具调用执行。

引用含collection_id、member_id、visibility_revision、原来源kind/id/revision、完成generation、块起点索引和当前G1的URL；边界片段可带后续块的必要上下文。标题/片段/URL均来自宿主复核的原文，不接受Provider自报来源。调用者可用09a Source Port携带member_id与visibility_revision打开精确当前来源，已变更则拒绝旧证明；普通原文URL在后续访问时也依其原域授权。输出不包含原库owner/审核字段、私密来源ID/标题/片段、原始Provider错误或凭据。

Module.Stop拒绝新Port请求并在返回前复核停止状态；同模块恢复复用已发布Port，完整Server重启重建正常模块图。索引是派生数据，查询不会重建/删除索引来掩盖失效；来源撤回立即过滤，不等待周期清理。

## V12-10 满额检索后端与复用边界

阶段退出工作先冻结[中文黄金集与容量规范](v1.2公开知识检索评测规范.md)，再测旧实现；满额1000投影时选择性、广泛命中与空结果均触及5秒预算。参数化PostgreSQL字面候选提示单独约38ms，仅是未授权提示，不当作端到端性能或来源许可。

当前实现为同一CheckedRead的只读回调使用Community内部可选SourceReadSnapshot：由所属仓储按既有顺序锁定板块/父级，再按数字ID排序共享锁定候选帖子；锁定的原始事实只在Community内部复用，公共读取仍逐次经过G1和版本条件。不同仓储、事务、回调结束后的上下文均不能复用这些事实，返回对象深拷贝。无快照能力的适配器保留原有实时读取与全部复核。Feature热停用/取消仍即时检查；Collection/规则/成员、完整代次、全部计数候选的最终复核及4MiB预算未改变，Provider依旧只能接收已核验的公开文本。没有跨请求结果、正文或allow缓存，也没有新增外部入口/Schema/扩展。

完整评测结果、原始样本与源码/ELF/命令摘要见[完整退出报告](../项目计划书v1/项目计划v1.2/evidence/v12-10-exit-linux.json)。

满额优化的候选过滤：先在宿主用固定词法规则筛选不可信投影提示，不把匹配当作授权。如果扫描投影总文本≤4MiB，则任何当前有效子集必然不超该预算，只需对可能贡献结果/总数的提示逐项执行当前G1；正文变更而未追平的旧索引仍不能返回新或旧片段。若扫描跨过4MiB，切回有界流式当前G1计量，隐藏/旧正文不占当前公开文本预算，不保留整个1000×64KiB投影、不静默截断结果。Provider只收经过复核的匹配文本，返回前复核全部计数候选和所有集合关系。

RichText由自己的Store在同一只读回调内按帖子顺序共享锁定正文，官方资料由Knowledge自己的仓储共享锁定；两者只复用锁定原行的分离副本，所属Feature检查和原文修订校验仍执行。回调/事务/仓储身份绑定及结束失效与Community相同，未产生可跨请求使用的正文或授权缓存。Knowledge DTO解码改为单次解析，Version仍由仓储facts_version覆盖，损坏字段失败关闭；不是从客户端Version或时间戳推断权限。

只读扫描采用原生JSONB传输与单次严格DTO解码，Version仍由仓储epoch覆盖，所属触发器仍删除payload Version；非字符串分块/标题及集合版本错型失败关闭，实际PG负例已验证，不把布尔值等转换成可搜索文本。内置词法策略复用对精确相同投影字节的纯匹配计算；独立策略仍走分离输入与宿主校验。全部贡献计数的候选先经当前原文完整投影复核，再参与排名，返回前再次打开G1。纯摘要复用按小ID定位后仍比较全部绑定字节/epoch/关系，不能只靠ID或版本缓存；回调结束失效，大小/条数有界。

关系终检在PG中核对集合/规则/成员的完整ID集合与非复用facts_version（包括新增项），不重复解码第二份正文；现有行共享锁不释放。Community的行pin只用于删除同一只读回调内的重复来源读取，实际G1与ResourcePolicy仍在Provider前和最终输出阶段分别执行；无pin的适配器保留重复实时比较。关闭Feature或取消时pin快捷返回也必须为空数据，定向回归与真实并发撤回边界通过。

同样的来源事实快照与纯摘要用于常驻索引的32项原子页；回调只读Community/RichText来源，可写Knowledge自己的成员/投影，来源不在回调内修改，租约/断点/回滚与当前G1保留。purge不读取正文。对无大小写关系的Unicode查询词直接匹配原文；含大小写关系时保留原有Go小写语义，没有扩大为Unicode完整case-fold或语义检索。

板块/父级快速路径只返回所属域的不可变事实值，Knowledge仍逐次检查ID、层级、active状态和非复用epoch；不是eligibility缓存。边界词排名与引用窗口保持等价，但只在词未出现在当前块且可能跨块时构造短窗口。全部候选的完整投影头先验证一次；最终阶段再次执行当前G1并逐字检查正文分块、标题/URL、来源/可见性修订及parser/chunker/Profile，不重复序列化同一已验证头部。
