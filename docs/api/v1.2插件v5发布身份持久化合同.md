> 更新时间：2026-10-16 21:26（Asia/Shanghai）

## 唯一事实与输入路径

宿主内部`PluginV5PackageCatalog.VerifyAndRecordContext`先验证[真实包字节、外封与当前发布者信任](v1.2插件v5包字节与签名合同.md)，然后调用`PluginV5IdentityStore`提交不可变坐标。只有提交成功才返回已验证包；当前信任、验签、目录或数据库失败均不返回包，也不写入成功缓存。该Port不对插件开放，尚无新的HTTP/管理CLI入口。

服务器装配始终提供PostgreSQL身份存储。其他业务进入Memory profile时，此Port仍不使用内存回退；nil/关闭连接、缺表、取消、写入/读取或提交失败返回`plugin.package_identity_unavailable`，不回显SQL、DSN或内部错误。显式Memory适配器和旧无参数存储构造路径仅用于独立组件，不能承担重启保证。CLI `plugin verify`仍是离线验签，不写宿主账本。

## 数据与并发

`000026_plugin_package_identities`新增一张宿主管理表：`plugin_package_identities`。复合主键为区分大小写的publisher、plugin_key、version；值为完整压缩包的`sha256:<hex>`及首次登记时间。字段与03a同形校验；不保存包字节、私钥、可信公钥、用户身份、Grant、安装或运行状态。

事务以显式READ COMMITTED执行`INSERT ... ON CONFLICT DO NOTHING`，再用后续语句快照读取已提交赢家。同坐标同摘要幂等，不同摘要返回`plugin.release_digest_conflict`；两个独立Catalog即使不共享进程锁，也不能保存不同赢家。UPDATE、DELETE和TRUNCATE均由数据库守卫拒绝，避免删除/重建导致历史发布身份失忆。信任仍在每次包核对时重新检查；账本存在不代表当前签名有效。

Catalog锁将本实例的当前信任复核与持久提交串行化。信任配置由各宿主实例显式管理；本切片不新增跨实例信任分发或把数据库账本当作信任目录。

## 旧表、回滚与保留

旧`plugins`/`plugin_versions`依赖Manager插件ID、旧生命周期和级联删除；它们不是publisher/key/version全域、独立于安装的永久身份账本。新表不转换或猜测旧记录，不把User/Admin ID或旧签名字段当作v5信任。未来安装版本可引用账本；本切片不重新设计旧授权存储。

迁移不修改000001–000025，不播种包或默认凭据。空账本允许down/up；非空账本在持有排他表锁后拒绝down，整笔事务回滚并保留行及迁移元数据。未来卸载或包文件清理应保留发布身份；允许擦除该账本需要另行明确的数据重置/迁移策略，不能随普通卸载删除。

当前结构为26条迁移、103张业务表及2张执行器表，下一条27。Admin `/architecture`和ER只展示源码Schema，不查询真实记录或秘密。
