# v1.2 知识索引任务请求合同

> 状态：V12-09b当前Linux范围实现/自动化/目标验收通过；早期请求合同保留，完整执行/投影/权威对账见第6节及.142。Windows用户延期。

## 1. 已接通的路径

Knowledge管理命令沿用[09a合同](v1.2知识集合与来源管理合同.md)：当前独立Admin/MFA/CSRF/CAS、业务变更、必需审计和`knowledge.selection.changed` Outbox同事务。新增消费者`knowledge:index-request:v1`由正常Core常驻worker调用，不依赖测试回调、手动ProcessOnce、HTTP请求或外部插件。

消费者在Knowledge模块Register阶段注册，早于Core模块Start时启动worker，避免积压事件先被fallback确认。停止时保留拒绝工作的回调，直到Core停止worker；不能提前注销后让fallback确认停止窗口事件。相同模块Start/Stop/Start复用已发布Port并恢复回调，不重复注册集合Port。普通完整Server重启则使用新模块图读取持久状态。

早期请求消费者只消费Knowledge自有集合/官方资料变更：`collection.save`、`official.save`、`selection.save`、`selection.refresh`、`member.remove`。早期切片尚未包含Community/RichText自身变更订阅及来源修订（本轮追加见第6节）；旧published/已清理事件对应的现存Knowledge集合/官方资料行由下述周期补扫覆盖，不能据此声称跨域来源/消失目标已全量收敛。

## 2. 输入和事务

事件Type固定`knowledge.selection.changed`、SchemaVersion为`v1`、AggregateType为`knowledge`。Payload≤1024字节且恰含`resource_id`和`operation`两个非null字段，重复/未知键、无效Unicode、未知操作或AggregateID不一致拒绝；ID必须与操作对应的`kc_`/`ko_`规范不透明ID一致。无效事件按Core永久失败规则进入死信，不伪造成功回执。

消费者不相信事件携带的来源版本或权限：实际事务内只共享锁定读取所属集合/官方资料的`facts_version`，不读取官方`data`/正文。目标缺失时使用版本0记录后续清理意图。任务键是域分离SHA-256(kind, id, 当前version)，数据库另有三元唯一约束。重复、乱序和迟提交事件每次重新取得当时当前版本，不把event_id当作回放游标；不同当前代次的请求分别保留。

`knowledge_index_tasks`提交成功后消费者才返回，Core随后记录独立回执。任务插入失败不确认事件；任务已提交但回执失败/进程中断时，重试按相同当前代次幂等。目标在重试前再次变化，会产生新的当前代次请求，而非恢复旧正文。回执、租约、有限重试和死信沿用Core Outbox，不新增另一个消息确认协议。

Feature关闭仍可记录已提交变更/撤回的元数据清理意图；这不启用Knowledge、不访问原来源、不调用Provider或模型，也不授予任何读取或出站权限。后续执行器必须重新核对当前目标、来源/规则/ACL和代次，任务不是授权快照。

## 3. 数据和运维边界

000031只新增`knowledge_index_tasks`六列：`id`、`target_kind`、`target_id`、`target_version`、`status`、`created_at`。kind为collection/official，版本≥0，当前status只能pending。无正文、标题、Prompt、Principal/ACL、Header/凭据、event_id或游标。目标是允许缺失的逻辑引用，不建立会阻止清理意图的FK。

当前请求不可UPDATE/DELETE/TRUNCATE。非空down先取得排他锁再原子拒绝；空域down/up不改旧118业务表、任何权限、回执或序列。表随整库备份；无新字节目录、第三方依赖、HTTP/SDK/MCP接口或任务管理页面。Admin `/architecture`只展示静态Schema。

早期.140/.141切片不执行索引，不创建ready投影，不提供执行租约/状态迁移、跨域来源分页回填、来源修订投影、权威全量对账或索引保留策略；pending任务数量或已完成枚举轮数不表示已收敛。已经published或被清理的Outbox事件不会因新消费者而自动复活。这两片验收时09b仍进行中、10依赖未满足；私有资料、AI/RAG、外部出站和12阶段页面不在本片。

## 4. 自有元数据周期补扫（.141）

正常Knowledge模块Start/Stop持有补扫器的取消和完成句柄，完整Server图重启重载持久断点，同模块重启也恢复补扫；没有远端扫描接口或插件回调。Feature关闭仍维护元数据请求，不授予来源读取/出站权。固定每秒每域至多一页32个目标，每页5秒事务期限；失败保留断点、有限间隔重试并令模块健康降级，恢复后解除降级。

000032追加`knowledge_index_backfill_checkpoints`，仅target_kind、after_id、completed_passes、next_scan_at、updated_at五列。集合和官方资料独立进度；按相同ID排序谓词读取至多33个ID以判断下一页，不调用会读取data的旧Repository.list。每项只重新锁读当前facts_version，经既有幂等请求表入队；全部请求和断点同事务提交。多实例对同域断点`FOR UPDATE SKIP LOCKED`，不能由后完成的页覆盖先完成的页。任何插入/断点写入/取消失败整页回滚，另一域仍可继续。

一轮结束后after_id回到空值、完成轮数加一，持久next_scan_at等待60秒再从头扫。它不是数据库快照或提交顺序水位；扫描过程中游标前方新增/更新的行会由下一轮重新发现。不存在简单max(event_id)保证，不重放published/已清理事件、不制造消费者回执。只枚举现存Knowledge自有行；已完全消失而且无事件的目标、Community/RichText源内容/权限、规则/来源修订和真正索引投影仍须后续权威对账，不在本片宣称完成。非法非规范目标ID失败关闭且不推进该页，应修复权威事实后重试，不能跳过坏行伪报成功。

表无种子/正文/ACL/凭据/新目录，断点是允许源行缺失的逻辑边界，不建FK。非空down持排他锁后拒绝；空域up/down/up保留旧119业务表、请求、回执、权限和序列。随整库备份恢复，当前32/next33、120业务/系统受管+2执行器。

## 6. 完整执行与权威对账（.142）

000033追加两张独立表：`knowledge_index_jobs`保存每集合可变执行状态，`knowledge_index_documents`保存公开文本投影。000031六列不可变pending请求原样保留；请求数量、扫描轮数、处理中页数均不是ready。新表不外键到可消失的集合/规则/成员，以便目标已物理删除而且没有事件时，已存在的任务仍能清理残留正文。表有数据时down原子拒绝；空域down/up保留非循环epoch序列高水位与旧120业务表/权限。当前33/next34，122业务/系统受管表与2执行器表。

正常模块Register预先注册`knowledge:source-invalidation:v1`，接受thread.created/updated/deleted与category.created/updated/moved/archived/restored的v1规范数值聚合ID。RichText编辑、发布、下架和删除沿用其所属thread.updated/deleted事件，不另造第二事实源。消费者完全忽略Payload正文、标题与权限，只在有界集合任务域推进requested代次，持久提交后Core才写独立回执。重复/乱序可以再次唤醒，不能把事件当版本或授权。官方资料先提交自身版本请求并释放来源锁，再提交依赖任务失效，两个成功提交均早于回执，避免与执行器反向锁序；中途失败按原请求幂等重试。

正常Start持有执行器，固定100ms至多一页，单页10秒事务期限。领取使用FOR UPDATE SKIP LOCKED，每次分配不可复用租约token，租约30秒；写入检查当前token、processing状态和到期时间，旧执行者不能覆盖新租约。pending→processing→pending（下一页）或idle（完成）；失败进入retry，2–32秒退避，每轮最多8次，随后dead等待60秒再进行新一轮有限尝试。成功页重置失败次数。页提交取消/超时/断点失败时，成员变化、正文投影和断点全部回滚；崩溃后保留的租约到期再领取。最近执行失败的健康降级在退避空轮询期间保留，实际成功页才解除；各任务的retry/dead详情仍以持久状态为准。不输出SQL、正文、凭据或任意错误。

每次构建绑定当前集合代次与独立run_generation，持久记录成员ID、规则ID、规则内数值来源ID和文档ID的分页边界。每页至多32项，额外1项只判断下一页。成员阶段清理已不可读/规则过期的引用；来源阶段逐规则处理单篇、官方及公开板块。Community拥有的`SourceReferenceInventory`只分页枚举板块当前线程ID（可含私密/已删/不支持类型元数据），Knowledge不直接查Community表，也不能用枚举结果读取正文。每个候选仍经原域匿名G1、RichText当前全文清洗与Knowledge当前规则复核，才更新派生成员和投影。板块/父级生命期与版本在页间、页内复核；集合变化重开代次。当前上限仍为每集合64规则/1000成员、全域1000集合/官方资料，溢出失败关闭，不能截断后伪称完成。

投影绑定来源kind/id/revision、集合/规则代次、成员ID、包含成员及板块/父级版本的visibility_revision、构建代次、固定`public-text/v1`解析器、`unicode-1024/v1`分块器和内置词法Profile的SHA256指纹。只接受原有≤64KiB的公开纯文本/Markdown或清洗后文章文本，每块至多1024 Unicode码点、总计≤64块；保留非可信文本，不执行其中指令，不获取任意URL。外部解析器/模型/Profile尚未接入，切换时必须建立新指纹与完整重建，不能混用旧代次。

文档阶段分页删除未被本轮权威来源枚举观察到的旧代次，当前文档再复核一次。全部成员/来源/文档页成功后才推进ready_generation。每轮完成后持久等待60秒再从头查当前事实；游标不是快照/提交顺序水位，游标前方迟出现/改变的行下一轮补齐。即使事件published后被清理、来源撤回/移动/物理删除、规则失效、集合完全消失，也通过现存任务域与当前原域事实收敛；不制造历史事件或回执。Feature关闭/集合disabled/集合缺失走正文purge分页，不调用来源正文Port，ready归零；重新启用需按当前事实重新构建。显式成员移除延续09a Refresh语义：板块规则仍active时，自动派生可在下轮重新物化；永久排除须停用对应选择规则。

内部`CurrentDocument`在返回任何正文前按集合→job→成员/规则→document顺序锁读，复核当前Feature、完成代次、集合/规则/成员关系和当前G1来源修订，并重新计算正文分块/标题/URL/Profile一致性。来源撤回/变私密、移板块、父级归档、规则ABA或Feature关闭立即拒绝旧投影，不等待异步清理。重建时部分新代次不对外释放；可能短暂不可用，不能用旧ready绕过当前授权。此接口没有新增HTTP、检索排序、引用页面、MCP或AI/RAG/插件/Integration出站，V12-10和14c仍需独立开发与验收。
