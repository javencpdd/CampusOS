# v1.2 知识索引任务请求合同

> 更新时间：2026-10-21（Asia/Shanghai）
> 状态：V12-09b 切片；Outbox持久请求及Knowledge自有行的持久分页周期补扫已实现。索引执行、跨域来源回填和权威对账未交付，不表示09b完成。

## 1. 已接通的路径

Knowledge管理命令沿用[09a合同](v1.2知识集合与来源管理合同.md)：当前独立Admin/MFA/CSRF/CAS、业务变更、必需审计和`knowledge.selection.changed` Outbox同事务。新增消费者`knowledge:index-request:v1`由正常Core常驻worker调用，不依赖测试回调、手动ProcessOnce、HTTP请求或外部插件。

消费者在Knowledge模块Register阶段注册，早于Core模块Start时启动worker，避免积压事件先被fallback确认。停止时保留拒绝工作的回调，直到Core停止worker；不能提前注销后让fallback确认停止窗口事件。相同模块Start/Stop/Start复用已发布Port并恢复回调，不重复注册集合Port。普通完整Server重启则使用新模块图读取持久状态。

本片只消费Knowledge自有集合/官方资料变更：`collection.save`、`official.save`、`selection.save`、`selection.refresh`、`member.remove`。Community/RichText自身变更订阅及来源修订仍属后续09b；旧published/已清理事件对应的现存Knowledge集合/官方资料行由下述周期补扫覆盖，不能据此声称跨域来源/消失目标已全量收敛。

## 2. 输入和事务

事件Type固定`knowledge.selection.changed`、SchemaVersion为`v1`、AggregateType为`knowledge`。Payload≤1024字节且恰含`resource_id`和`operation`两个非null字段，重复/未知键、无效Unicode、未知操作或AggregateID不一致拒绝；ID必须与操作对应的`kc_`/`ko_`规范不透明ID一致。无效事件按Core永久失败规则进入死信，不伪造成功回执。

消费者不相信事件携带的来源版本或权限：实际事务内只共享锁定读取所属集合/官方资料的`facts_version`，不读取官方`data`/正文。目标缺失时使用版本0记录后续清理意图。任务键是域分离SHA-256(kind, id, 当前version)，数据库另有三元唯一约束。重复、乱序和迟提交事件每次重新取得当时当前版本，不把event_id当作回放游标；不同当前代次的请求分别保留。

`knowledge_index_tasks`提交成功后消费者才返回，Core随后记录独立回执。任务插入失败不确认事件；任务已提交但回执失败/进程中断时，重试按相同当前代次幂等。目标在重试前再次变化，会产生新的当前代次请求，而非恢复旧正文。回执、租约、有限重试和死信沿用Core Outbox，不新增另一个消息确认协议。

Feature关闭仍可记录已提交变更/撤回的元数据清理意图；这不启用Knowledge、不访问原来源、不调用Provider或模型，也不授予任何读取或出站权限。后续执行器必须重新核对当前目标、来源/规则/ACL和代次，任务不是授权快照。

## 3. 数据和运维边界

000031只新增`knowledge_index_tasks`六列：`id`、`target_kind`、`target_id`、`target_version`、`status`、`created_at`。kind为collection/official，版本≥0，当前status只能pending。无正文、标题、Prompt、Principal/ACL、Header/凭据、event_id或游标。目标是允许缺失的逻辑引用，不建立会阻止清理意图的FK。

当前请求不可UPDATE/DELETE/TRUNCATE。非空down先取得排他锁再原子拒绝；空域down/up不改旧118业务表、任何权限、回执或序列。表随整库备份；无新字节目录、第三方依赖、HTTP/SDK/MCP接口或任务管理页面。Admin `/architecture`只展示静态Schema。

本片不执行索引，不创建ready投影，不提供执行租约/状态迁移、跨域来源分页回填、来源修订投影、权威全量对账或索引保留策略；pending任务数量或已完成枚举轮数不表示已收敛。已经published或被清理的Outbox事件不会因新消费者而自动复活。09b仍进行中，10阶段检索依赖未满足；私有资料、AI/RAG、外部出站和12阶段页面不在本片。

## 4. 自有元数据周期补扫（.141）

正常Knowledge模块Start/Stop持有补扫器的取消和完成句柄，完整Server图重启重载持久断点，同模块重启也恢复补扫；没有远端扫描接口或插件回调。Feature关闭仍维护元数据请求，不授予来源读取/出站权。固定每秒每域至多一页32个目标，每页5秒事务期限；失败保留断点、有限间隔重试并令模块健康降级，恢复后解除降级。

000032追加`knowledge_index_backfill_checkpoints`，仅target_kind、after_id、completed_passes、next_scan_at、updated_at五列。集合和官方资料独立进度；按相同ID排序谓词读取至多33个ID以判断下一页，不调用会读取data的旧Repository.list。每项只重新锁读当前facts_version，经既有幂等请求表入队；全部请求和断点同事务提交。多实例对同域断点`FOR UPDATE SKIP LOCKED`，不能由后完成的页覆盖先完成的页。任何插入/断点写入/取消失败整页回滚，另一域仍可继续。

一轮结束后after_id回到空值、完成轮数加一，持久next_scan_at等待60秒再从头扫。它不是数据库快照或提交顺序水位；扫描过程中游标前方新增/更新的行会由下一轮重新发现。不存在简单max(event_id)保证，不重放published/已清理事件、不制造消费者回执。只枚举现存Knowledge自有行；已完全消失而且无事件的目标、Community/RichText源内容/权限、规则/来源修订和真正索引投影仍须后续权威对账，不在本片宣称完成。非法非规范目标ID失败关闭且不推进该页，应修复权威事实后重试，不能跳过坏行伪报成功。

表无种子/正文/ACL/凭据/新目录，断点是允许源行缺失的逻辑边界，不建FK。非空down持排他锁后拒绝；空域up/down/up保留旧119业务表、请求、回执、权限和序列。随整库备份恢复，当前32/next33、120业务/系统受管+2执行器。
