既有 `POST /admin/threads/:id/review/approve|reject` 接独立命名 `community.thread.admin_review/v1`。实际Core Thread必须active、pending；签名Admin/current Session和精确review角色权限、15分钟内MFA经完整执行见证复核。路由只选ID和固定操作、body只接受审核原因；版块/owner/状态/nonce由实际Core行构造，客户端facts/actor不给权限。审批只改moderation，private/draft发布意图保持。

事务按真实Admin凭据/权限、Thread、既有审核Case行锁顺序执行，修订/非复用facts双CAS。Case是Thread锁后选择的实际历史依赖，不是客户端授权事实；新增transaction-only Case command port。驳回无现行case则创建typed Admin opener；通过现行case写typed Admin resolver，保留原User opener/FK及历史，不将Admin写入旧User列。按既有语义仅解析最新现行case，较旧现行case保留并绑定最终检查。

Thread、typed修订/动作/Case及必需平台审计/outbox同事务；创建case、解析case、写history或audit任一失败整体回滚。返回前完整复核当前见证、写后Thread、实际Case和最新现行case（含空）。变化409或稳定不可用错误；nonce未前进拒绝。显示counter由CAS保留。

回执/事件只含 `id,moderation_status`，不输出原正文、标题、owner或内部事实。HTTP401/403/409/503和输入400稳定；原内部裸ID审核方法不作为新HTTP认证入口。其他Admin生命周期和Feature/User治理命令仍待接入。
