# v1.2 G1：插件 v5 消费能力与类型化 Scope 合同

> 状态：consumes 投影、宿主目录快照结构、SDK DTO、拒绝规则及 Linux 离线合同验收已交付。现行生产 v4 Host API 未切换到 v5，本文不授予插件任何能力。

## 1. 本切片边界与事实源

本合同接续[包形态与版本协商投影](v1.2插件v5包形态与版本协商合同.md)。完整 v5 Manifest 尚未交付；V12-03a 须把包形态、consumes、provides、资源和配置合同组合为单一安装输入。此处的 consumes JSON Schema 校验完整 Manifest 中同名数组的**投影**；它不能单独用于安装或授权。

插件只能声明其请求的 Host Capability、类型化 Scope、用途和是否必需。能力代码、允许的 Scope、公开集合 ID 和可读配置键由**宿主提供的目录快照**决定，包内声明不能自封能力或把数据改称公开。目录快照必须标明与包相交的宿主合同版本；目录缺失、损坏或重复代码时失败关闭。当前[生成的 v1 能力目录](plugin-capabilities-v1.json)仍服务现行协议，含 self/system 旧语义，不能直接当作 v5 的公开、集合或配置目录。测试中的[合成目录](../../sdk/typescript/tests/plugin-v5-host-catalog.fixture.json)只验证合同，不表示四个示例代码或集合现已在生产发布。

## 2. 四种 Scope

| kind | 声明形状 | 宿主必须保持的边界 |
| --- | --- | --- |
| public | 只有 kind | 仅返回当前审核发布且可公开的稳定投影；不能扩大到私密、下架或原始正文之外的字段 |
| self | 只有 kind | 当前已授权用户自身；声明不接受 user_id/owner_id，真实身份由宿主会话构造，并要求用户同意 |
| collection | kind 与非空 collection_ids | 每个 ID 必须属于宿主当前公布的公开集合；不能混入私有集合、通配符或未公布 ID |
| system_config | kind 与非空 keys | 只能读取当前插件的非敏感、已公布配置键；不能读取原始 Secret、全局配置或任意键 |

每个能力代码只能声明一次。数组、目标 ID 和键有显式大小、格式与去重约束；未知 kind、额外字段、空用途、非布尔 required 均拒绝。required=false 仅表达插件对该**已发布**能力的依赖强度，不允许忽略未知代码、错误 Scope 或无权目标。Host Capability 的业务授权与 host_resources 的 CPU、内存、私有空间、受管网络分开计算。

目录快照的分类与同意规则也受 Schema 约束：public/collection 必须是公开数据且不要求用户同意；self 必须标记用户同意；system_config 仅限内部非 Secret 配置。目录在安装后变更或来源撤权时，宿主不得复用旧的接受结果；测试覆盖能力删除、公开集合移除和配置键移除。真实运行时仍须执行 Package Declaration ∩ Host Catalog ∩ Admin Grant ∩ User Consent（若要求）∩ 原资源 ACL ∩ 功能/安装状态 ∩ 部署资源上限，并在调用及返回前复核。目录匹配不是授予记录，也不提供 DB、JWT、宿主 shell/路径或 Docker socket。
