# v1.2 业务治理主体域存储合同

> 更新时间：2026-10-13 09:04（Asia/Shanghai）
> 责任阶段：V12-02b；actor域数据前置实现、自动化及Linux目标三态通过，资源命令接入继续。

八张现有表增加九组 `kind` 与128字符opaque ID：Thread的moderation_actor、Revision的created_actor、ModerationCase的opened/resolved_actor、ModerationAction和AssetLifecycleAudit的actor_kind/actor_ref_id、RichText的updated_actor、Space的disabled_actor、StorageQuota的updated_actor。原User数值列、外键、资产actor_type和旧历史全部保留；Admin只可与空的旧User列同时存储，不把opaque或同数值Admin写成User ID。

旧数值来源与合法ID形状回填为User；NULL及无身份凭据的旧system记为legacy_unknown。旧Space文本保留原值并记unknown，不按前缀、数值形状或旧admin标签推断独立管理域。旧资产admin标签配User FK仍保留User来源及原标签。受管legacy同步触发器维持旧可信User原语兼容；FK SET NULL保留已知历史User的域和ID，避免用户删除使审计主体消失。这些存储列和触发器不认证、不授权任何调用者。

CHECK拒绝无效域/ID或Admin与非空旧User列混合；新opaque字段为逻辑主体关联，没有虚构多态外键。Thread新actor事实变化纳入000016非复用版本函数，actor ABA推进版本，计数不推进。冻结Principal、ResourcePolicyGrant及G1五动作不变。

000018 down先检查全部九组：任何Admin或与旧列不能精确匹配的typed历史（含User删除后保存的ID）都原子拒绝；只有可无损表达的旧数据才允许移除新增列/guard并恢复000016函数。原表行、原User字段和外键不移除。停止依赖typed actor的写入后才降级；不能为降级清空主体历史。
