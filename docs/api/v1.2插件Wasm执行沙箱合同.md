# v1.2 插件 Wasm 执行沙箱合同

> 更新时间：2026-10-19（Asia/Shanghai）
> 状态：V12-05 完整实现；当前验收结果以 [.123](../进度/v1.2-dev/v1.2.123-dev.md) 与[完整报告](../项目计划书v1/项目计划v1.2/evidence/v12-05-runtime-exit-linux.json)为准

## 1. 捕获、授权与实际装配

`PluginV5PackageCatalog.CaptureWasmProgram` 按当前信任、签名、不可变发布身份、归档路径及 artifact digest 重新验证，只捕获 `runtime: wasm`、`artifact.kind: wasm`、`transport: host-call` 的包内字节。程序内部字段不导出，字节、资源和 consumes 返回副本。执行不读取插件源目录，不接受插件提供的宿主路径。

捕获是快照，不能代替当前授权。生产 `V5RuntimeCoordinator` 从 durable waiting operation 读取已校验的 preparation，事务内重核当前安装/owner/代次/配置/Grant/Consent；事务外启动实际 worker、编译和初始化，再以当前 operation lease/CAS 提交 `Observe ready`，之后 `V5ManagedRuntime.Publish` 才发布贡献和短期凭据。审计回滚、租约过期、readiness 或 Publish 失败均关闭 worker，不伪造 ready。凭据只存于宿主内存，不发送给 worker/guest。

Server 在配置 `CAMPUSOS_PLUGIN_WASM_IMAGE` 后绑定协调器。空值、非法/缺失镜像、无 Docker/实际 cgroup 限制或 PostgreSQL 独占锁不可用时关闭执行入口；启用意图不等于 ready。默认没有镜像，继续 `pending/runtime_unavailable`。平台没有批准 arbitrary container 插件，V12-06 仍独立。

受管调用遵循[双向调用与生命周期合同](v1.2插件双向调用事件与生命周期合同.md)：准入和输出前核对当前事实，变化后丢弃迟到输出；普通配置变化重新准备新代次，Secret refs 不进入 guest。取消/撤销先关闭准入、贡献和凭据，再终止实际 worker。运行丢失落为 failed，需显式 enable/retry。重启使旧 ready 失效，重新准备与发布；owner 等待同版本全局真实 ready，不提前终态失败。

## 2. `campusos.wasm-json/v1` ABI

| 项目 | 合同 |
| --- | --- |
| 内存 | 导出 `memory`，初始至少一页；首个 64KiB 是请求区域，常量应放在其他页 |
| 主调用 | `campusos_invoke(i32 ptr, i32 len) -> i64`，输入 ptr=0；返回高32位响应指针、低32位长度 |
| 普通配置 | 有普通配置快照时须导出 `campusos_configure(i32 ptr, i32 len) -> i32`；输入是 `{system?,user?}`，返回0才成功；无 Secret refs |
| 元数据事件 | 声明订阅时须导出 `campusos_event(i32 ptr, i32 len) -> i32`；0为 ACK；仅接独立队列的脱敏元数据，不接 Core 原始事件体 |
| 输入/输出 | 单个完整有效 UTF-8 JSON，最大64KiB；先限制长度、检查内存边界，后复制；业务请求/响应继续由上层 typed codec 验证 |
| 状态 | 每次调用创建新 guest，先配置再执行，结束关闭；不共享 guest 内存、全局变量或函数对象 |
| 初始化 | 不自动调用 `_start`；二进制 start section 仍执行并受期限/取消限制；readiness 不允许业务 Host IO |

内部 stdio 使用宿主固定的长度帧，初始化最多48MiB（Wasm 上限32MiB的 Base64 编码），后续帧最多256KiB；未知字段、畸形帧和额外 JSON 拒绝。guest 不直接拥有 stdio，只能调用下面的有限 import。

## 3. 唯一有限 Host import

允许单个精确签名的 `campusos.host_call(i32 request_ptr, i32 request_len, i32 response_ptr, i32 response_capacity) -> i32`。请求严格为 `{capability,payload}`，payload 是对象；重复键、额外身份/owner/envelope 字段拒绝。每次调用最多32次 Host 请求，请求/响应容量最多64KiB；失败返回 -1，不返回内部 stack/路径。能力须在当前捕获 consumes 中声明。

父进程接到请求后，用宿主内短期实例凭据生成受限 `host_api` envelope，经过当前声明∩Grant∩所需 Consent∩Feature∩资源 ACL 与 typed Host endpoint；前后再次复核。相同可信在途调用复用原并发名额，不能由 guest 指定身份或绕过授权。目前 v5 发布目录的正向业务读取是 `community.thread.public.read`，经真实 Core 公开读 Port；私密状态、当前撤权和未发布能力拒绝。Secret/Egress 业务能力尚未发布到 v5，不恢复旧授权接口，也不把原值、JWT、DB 环境或宿主凭据送进 guest。已有共享 Broker 的合同继续保留，未来只能经正式目录和 typed endpoint 接入。

`NewV5Sandbox` 默认拒绝所有 imports；带编译宿主回调的内核入口只允许上述函数。所有其他 function/memory/table/global imports 均拒绝，没有 WASI、`env.*`、目录、网络、环境、argv 或直接文件/数据库/Secret 入口。

## 4. Linux 真实隔离与资源预算

生产 `V5IsolatedFactory` 使用**宿主构建的固定 scratch worker 镜像**执行已验证 Wasm，拒绝插件提供的镜像、命令和挂载。镜像配置仅 `/runner` 固定可执行文件；输入必须为本地完整小写 `sha256:<64hex>`，经 Docker inspect 解析为本机不可变 image ID 后启动，不拉取标签。API 为原生 Linux 宿主进程，需 `/usr/bin/docker`；不得给 guest 挂载 Docker socket，也不通过给开发 API 容器挂 socket 来启用。

| 限制 | 实际执行 |
| --- | --- |
| 资源交集 | Manifest、批准值、宿主和部署上限取交集；单 worker 最多256MiB、1000 millicores、并发1、单次5000ms；更小值生效 |
| 原生 RSS/编译/内存 | Docker memory.max，swap=0；覆盖 guest 线性内存外的引擎/编译分配；Go GOMEMLIMIT 仅辅助，不代替内核限制 |
| CPU/PID | CPU quota 与 pids.max=64；readiness 既检查 Docker 配置，也读取 worker 实际 cgroup v2 文件，缺任一控制拒绝发布 |
| 隔离 | network=none、无卷/宿主目录/socket、read-only root、uid65534、cap-drop ALL、no-new-privileges、IPC none；环境仅 PATH=/ 和 GOMEMLIMIT；log-driver=none |
| 总预算 | 单个独占宿主先预留，最多16 workers、1024MiB、4000 millicores；超限立即拒绝，不排队创建 |
| 单写围栏 | PostgreSQL 会话 advisory lock 独占协调器；丢锁关闭准入并回收；Host IO 也检查锁；不支持多写/跨主机集群配额 |
| 回收 | 取消/期限强制终止真实 worker，捕获实际 OOMKilled 后移除；健康 ping 不执行 guest 业务；部分 init 最多5秒，失联空闲 worker 最长30秒自行退出 |
| 重启 | 新宿主取得独占锁后，先清理相同数据库部署命名空间、保留标签 `campusos.wasm.worker=v5` 且名字匹配 `campusos-wasm-<32hex>` 的旧 worker，再准备新代次，避免孤儿与新预算重叠 |

配置/worker 缺失返回不可用；协议、trap、非法 JSON、超限或取消不释放部分结果。单个 guest trap 可继续后续调用；真实 OOM、进程退出或取消使对应 worker 失效，协调器撤下贡献并持久记录 runtime_lost，其他实例继续可用。进程级隔离不承诺多宿主 HA。Windows/插件 Container adapter 属于 V12-06，作者 SDK 适配属 V12-08a，内建 AI/RAG 消费接线属 V12-14c。

## 5. 构建与可复跑验收

在 Linux 宿主仓库根目录构建，不发送整个工作区给 Docker：

```bash
set -e
mkdir -p .cache/wasm-worker-image
CGO_ENABLED=0 go build -o .cache/wasm-worker-image/campusos-wasm-worker ./cmd/campusos-wasm-worker
cp deploy/docker/Dockerfile.wasm-worker .cache/wasm-worker-image/Dockerfile
docker build --network=none --iidfile .cache/wasm-worker-image/id .cache/wasm-worker-image
export CAMPUSOS_PLUGIN_WASM_IMAGE="$(cat .cache/wasm-worker-image/id)"
```

完整验收使用 [runtime drill](../../scripts/v12-05-runtime-drill.sh)，依次 `target`、`common`、`documents`、`final`。每次 target 在 `.cache/v12-05-runtime/acceptance.*` 新建独占目录并设置绝对路径 `CAMPUSOS_V5_RUNTIME_DIR`。脚本冻结 HEAD/源码/四份历史依赖，构建固定静态 worker、两份实际 race ELF 与 race cmd/server，使用 `env -i`，独占 PG16临时库迁移1–28，运行当前身份/公开 Core Host/元数据 ACK/配置围栏/会话撤销/Grant 真实到期/审计回滚/leader 丢失/实际 Server 强杀重启和 OOM/取消/邻居隔离/总预算测试。必需测试不得 FAIL/SKIP/race；数据库、11项共同门禁与5项最终文档门禁通过后才能封存完整报告。
