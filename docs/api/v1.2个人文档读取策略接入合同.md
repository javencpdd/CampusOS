# v1.2 个人文档读取策略接入合同

> 更新时间：2026-10-12 09:29（Asia/Shanghai）
> 范围：V12-02b 个人文档读取独立切片；实现、自动化、Linux 目标环境 passed；02b 全阶段仍 partial。

`/documents`、`/:id`、`/:id/content`、`/:id/preview`、`/:id/download`、`/:id/versions` 与 PDF invocation 从已认证 user Session 重新加载 owner/实际认证强度。相同 ID Admin、插件/Worker 代理主体、客户端身份字段都不能代替本人会话。缺 verifier、strength 或 fresh resolver 即失败关闭。

active 原文读取执行冻结的 `personal.document.read`，由 Personal Documents 构造当前 Document、selected immutable version 和 Object 事实；Core 只做纯求值，不查 Feature。当前 document version/完整元数据、所选版本、Object owner/ready/版本/摘要/大小逐一绑定；返回前重新查询并复核完整 Principal。历史版本不得把回收文档放行，正文或版本竞争拒绝，且错误不携带内部路径或字节。文本/原生预览核对实际字节摘要；download 返回 Reader 前核对，任何失败关闭已打开 Reader。有效身份/事实变更 409，撤销/无效会话 401，跨 owner/回收原文不泄露存在性。

回收站元数据是独立的本人生命周期投影：只返回自己的 active/trashed 描述；trashed 移除 CurrentVersion 与版本引用，仅用于查看和恢复，不授权原文/预览/版本枚举。未知/矛盾状态失败关闭，不将 trashed 伪造为 active。列表保持同一 owner/status 集合，整页及顺序重读一致，空列表也重验会话；Memory/PG 的同时间 ID 排序一致。

`ReadPort` 只接受可信入口提供的 fresh resolver；服务器→RichText 文档桥也使用该 Port。Context 携带的是请求内的真实 verifier 函数，不是缓存 Principal 或前端 DTO；每次消费仍核对 user 域与完整身份。旧 service 裸 ID 方法只作内部实现原语，不能由 HTTP、插件或新 ReadPort 当作认证证明。

[.50 进度](../进度/v1.2-dev/v1.2.50-dev.md)、[原始报告](../项目计划书v1/项目计划v1.2/evidence/v12-02b-document-read-linux.json)与[Linux 演练](../../scripts/v12-02b-document-read-drill.sh)：9 必需顶层 PASS，3 真实 PG，5 格式/30 组合/9 提交竞争；真实域 JWT + SessionService HTTP 用 Memory Identity，资源另用 PG Document/Object + 本地字节验收。无新迁移，不宣称全浏览器、PG Identity 联合服务器、Windows 或整阶段通过。

RichText HTTP/附件与其他 Feature 私有读取、治理/MFA、批量授权和权限预览随后分别验收。原文流开始后撤销无法收回已输出字节；不声称跨 Document/Object/Session 有一项跨模块原子事务。
