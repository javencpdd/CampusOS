# v1.2 版块治理委托上限合同

> 合同：`campusos.board-delegation/v1`；状态：G1 合同切片与 Linux 离线验收完成，运行时待 02a/02d/02b。

## 1. 范围和信任边界

本切片冻结“管理员向普通用户授予有限版块治理执行权”提案的判定合同。
首批动作限 `community.thread.take_down`、`community.post.delete`，Scope 为**精确版块 ID**。
授予管理员角色、系统级权限、作者编辑权、私人文件权、机器 Scope 和多级转授不在本切片。
新增动作/Scope 需另有合同，不按通配符、角色名或父级 group 自动扩展。

[JSON Schema](board-delegation-v1.schema.json)、[SDK DTO](../../sdk/typescript/src/board-delegation.ts)、
[目标错误目录](board-delegation-v1.errors.json)是可执行的字段合同。
Schema 顶层接受 request 或 decision，适配器应选择对应 definition；显式注册本地
[Principal Schema](principal-context-v1.schema.json)，不加载远程 Schema。

所有管理授权、可委托上限、收件人、版块与时间事实由宿主在当前调用中构造。浏览器只可提交候选
意图，不能提交可信 bounds、management、evaluated_at 或 facts_version。合法 JSON 不能认证主体，
`delegable:true` 不能由客户端自封。SDK 没有开放授权执行端点；脚本的 evaluate/consume 仅是离线
可执行规范，未被运行时导入。Core 不加载 Feature 服务，业务事实仍由对应模块提供。

## 2. 输入合同

| 字段 | 语义与限制 |
| --- | --- |
| `contract` / `request_id` | 精确版本；宿主每次调用生成唯一关联 ID，绑定完整候选和调用主体，不信任客户端关联 ID |
| `facts_version` | 宿主当前授权事实快照的不可复用版本；覆盖管理权、bounds、收件人和版块变化，含 ABA；具体持久化机制在 02a/02b 实现 |
| `evaluated_at` | 宿主 UTC Unix 秒整数，0～253402300799；不是客户端时钟，不接受毫秒、字符串或小数 |
| `principal` | `campusos.principal/v1`；结构合法的非 admin 仍在语义层拒绝；admin 必须 MFA |
| `management` | 绑定实际 admin 的 `identity.role.assign` 授予动作，含 active/suspended/revoked 与有效区间；与治理执行权分开 |
| `recipient` | 当前 user 主体与 active/suspended/deleted 状态；必须匹配 candidate.recipient，只有 active 可接受 |
| `boards` | 1～64 个 `{kind:"community.board",id,status}`，status 为 active/archived；ID 不重复，候选所用版块必须存在且 active |
| `bounds` | 0～64 项可委托上限，独立 ID、admin actor、状态、delegable 及下述 grant atom；空集合法但不能允许授予 |
| `candidate` | 仅 user recipient；1～32 项执行权 atom，批量原子判定；不包含 delegable 字段，不赋予收件人转授权权 |

Grant atom 为 `{action,board_id,not_before,expires_at,required_strength}`。动作仅限首批两项，
认证要求为 password/mfa。时间是有限半开区间 `[not_before, expires_at)`，起点必须小于终点，
不接受无期限或隐式默认值。每个候选 `(action,board_id)` 只能出现一次；不同权限窗口应拆成
后续明确操作，不在同次请求混合重复项。所有 ID 沿用 Principal 的不透明字符串规则。

bounds 的 ID 唯一；重复 ID、重复版块、候选重复 action/board 或逆序/空时间窗都作为 input_invalid，
不能由“最后一项覆盖”悄悄改变权限。Schema 验证形状与范围，跨字段时间/唯一键规则由语义校验执行。

## 3. 判定次序与子集规则

1. 版本/结构及上述语义输入校验；未知版本字符串优先返回 contract_unsupported。
2. 验证 actor 为 admin 且 authentication_strength=mfa。凭据有效性、MFA 新鲜度仍由宿主认证适配器
   复核，不能相信 DTO 自报。user 即使同 ID、持有 admin 字符串角色也不能进入这条授予路径。
3. management 必须属于同一 `(kind,id)` 且当前 active、`not_before ≤ evaluated_at < expires_at`。
   有治理执行权不意味着有 `identity.role.assign`；反之只有管理动作也不能绕过 bounds。
4. 当前收件人匹配且 active；候选版块全部存在且 active。Admin ID 与 User ID 相同不等于同一主体，
   可向不同域的同 ID user 提案；这不授予其任何后台身份。
5. 每个候选 atom 必须由**同一条** bounds 完整覆盖：同一调用者、active、delegable=true、上限
   当前生效、动作相同、版块 ID 精确相同；候选起点不早于当前时刻或该上限起点，终点不晚于上限
   终点；上限要求 MFA 时候选也必须 MFA。password 上限可收紧为 MFA，不能反向降级。

不同有效 bounds 可以分别覆盖不同候选 atom，但不能把 A 动作+B 版块拼成 A/B 权限，也不能
把短期 password 上限与长期 MFA 上限拼成长期 password。不能用相邻窗口拼接出没有完整证据的
单项授予。v1 采用单条完整 witness，未来若需要复杂区间并集必须显式升级合同并新增验收。

任意一项不满足，整批 deny、witnesses 为空；不写入一部分、不在同次请求返回部分成功。
若多个 bounds 完整覆盖同一 atom，按不透明 bounds ID 的 ASCII 字典序选第一项，确保结果稳定。

## 4. Decision 与提交义务

结果包含 contract、request_id、facts_version、effect、reason、witnesses 和 obligations。
allow 的 reason 固定 `delegation.allowed`；witnesses 按候选索引顺序为每项提供
`{candidate_index,bound_id}`，不得遗漏、重复或指向未覆盖的上限；义务必须精确为
`["recheck_authority_in_transaction","required_audit"]`。deny 无 witness、无义务。

allow 只是提案判定，不是已提交权限。应用服务在写入同一事务中重载认证/管理权/bounds/收件人/
版块和时钟事实，核对版本和候选绑定，再求值；暂停、撤权、到期、认证降级或事实变化后不得提交
旧决定。时钟倒退也拒绝。required audit 与授权写入同事务成功，否则整体失败；需 Outbox 的通知
与该事务一致提交。禁止先授予再异步补必需审计。02a/02b 必须实测锁/版本、撤权竞争和审计失败。

离线检查使用前后输入模拟复核，并重算 witness；不是实际 PostgreSQL 事务，也不证明旧 Session
已撤销或 MFA 新鲜度已经验证。实际凭据/审计仓储故障应失败关闭，不能回退旧角色路径。

## 5. 目标错误与现有代码映射

所有目标错误均 retryable=false，不回显实际授权范围、凭据或候选正文。当前 HTTP 目录尚未接入。

| 类别 | 错误码 | 目标 HTTP |
| --- | --- | ---: |
| 输入 | delegation.input_invalid / delegation.contract_unsupported | 400 |
| 主体/认证 | delegation.actor_denied / delegation.mfa_required | 403 |
| 管理权/收件人/版块 | delegation.management_denied / delegation.recipient_denied / delegation.board_denied | 403 |
| 越过可委托上限 | delegation.outside_bounds | 403 |
| 错误结果/绑定 | delegation.decision_mismatch | 500 |
| 提交前事实已变 | delegation.facts_changed | 409 |

当前 [PermissionService](../../internal/modules/core/identity/service/permission_service.go) 的
`assertActorMayGrantCodes` 只比较实际执行动作码，`ReplaceCategoryRoleScopesByActor` 检查角色和
`identity.role.assign` 后替换 category 范围；这些测试通过不证明新的可委托 Scope/期限/MFA 子集
已经实现。[PermissionDefinition](../../internal/modules/core/identity/repository/authorization_repository.go)
仍为现有动作目录；[Permission Code 映射](../../internal/modules/core/identity/permissioncode/permissioncode.go)
确认首批代码来源。02a 引入执行权/委托权分离，02d 切换独立管理域，02b 接入应用服务及事务复核。
旧 user 角色自动创建后台准入的移除责任仍按[主体合同](v1.2主体上下文合同.md)执行。
