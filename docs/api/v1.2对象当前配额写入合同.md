# v1.2 Object 当前配额写入合同

> 更新时间：2026-10-14 13:01（Asia/Shanghai）
> 状态：本切片实现、自动化和 Linux PostgreSQL 目标三态通过

ObjectService.Put 在预留和提交两个账本事务内读取当前持久化 quota，不使用 LocalAdapter 的启动缓存作为写入容量权威。已有 override 使用实际正数值；缺失 override 使用配置默认值，来源缺失或不可用返回 ErrObjectUnavailable。容量不足返回既有 ErrObjectQuota，不返回 Object 成功回执。

提交条件为已用量 + 其他 pending 预留 + 本次实际字节不超过当前配额；不把本次预留重复计算。即使配额在 byte I/O 期间被另一进程降低，提交也重新检查。

PostgreSQL Reserve/Commit 先持有 owner admission advisory lock，再持有账本和实际 quota 行锁。支持的 PgQuotaRepository.Upsert 使用同一 admission lock，加入当前事务；FOR SHARE 阻止已有 quota 行的直接冲突更新。缺失行由受支持 updater 的 owner admission 串行化，直接 SQL 插入缺失 override 不在该锁合同内。Memory 持有实际 quota 仓储读锁至本次账本操作结束。

提交失败保留并使用最初 reserved Object ID 与 reservation receipt 释放容量。实测覆盖配额变化、来源不可用、SQL 拒绝、取消和其他实际 Object 占用，核对原 Object deleted、reservation released、账本和文件字节，不删除其他已提交 Object。

这是 provider 内部容量前置，不认证调用者、不推出任何资源读写权限、不改变 ObjectPort DTO。附件及其他业务仍需当前 Principal/资源 Policy、必需审计与明确补偿。无 schema 变更，详见[进度 .87](../进度/v1.2-dev/v1.2.87-dev.md)。

Object 当前配额写入前置三态通过：reserve/commit 在实际账本事务内读取持久化 quota，缺 override 使用配置默认值，来源不可用关闭；实际 quota 行锁及 owner admission 串行化受支持 updater；失败保留原 receipt 并释放容量。54 必需/19 真实 PG、当前升降额/默认值/实际锁与外层事务回滚、五种 byte I/O 失败和原 50 回归及共同门禁通过。
