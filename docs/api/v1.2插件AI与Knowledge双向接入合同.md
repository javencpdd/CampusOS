# v1.2 插件 AI 与 Knowledge 双向接入合同

> 实施阶段：V12-14c；最终实现、自动化与 Linux 目标状态见 [进度 .158](../进度/v1.2-dev/v1.2.158-dev.md)。Windows 沿用用户延期。

## 消费宿主能力

| 能力 | Scope 与独立许可 | 输入与执行范围 |
| --- | --- | --- |
| `ai.chat.local.invoke` | `self`；声明、管理员批准及当前用户独立同意 | 固定 `local-chat`，当前 Binding/Profile 修订；仅显式文本 |
| `ai.chat.remote.invoke` | `self`；独立于本机能力批准及当前用户同意 | 固定 `remote-chat`，共享 HTTPS/DNS 固定 Egress 与 Secret 代用 |
| `knowledge.public.answer` | `collection`，确切 collection_ids；另要求对应模型能力的独立许可与同意 | 仅当前公开集合；内置索引/模型、缓冲答案与宿主创建的当前引用 |

沿用 v5 四种 Scope，不新增可自报 owner、Profile 集合或任意网络目标的通用 Scope。当前宿主只有两个编译内置 Profile，因此用各自能力码精确绑定 Profile ID；批准一个能力不授权另一个 Profile。模型与公开问答共用字段：`profile_id`、正十进制字符串 `profile_revision/binding_revision`、`ar_` 加32位小写hex的 `run_id`、`prompt`；公开问答另要求 `collection_id`。封闭 JSON 拒绝重复键、未知字段、零/负/溢出修订、客户端 owner/Token/端点/来源/工具或 Profile 覆盖。输入文本最多12000 UTF-8字符，并受64KiB总信封上限及内置模型文本上限；没有流式、工具、重试或隐式 fallback。

插件只持有受管实例短期凭据。模型调用还须处于宿主当前 User 的已认证调用链：Runtime 将完整会话 resolver 绑定于精确实例的进程内 Context；Host callback 才获得当前检查函数，用户凭据不进入管道。单独的后台实例凭据、其他实例、其他 owner、同号 Admin 或新会话不能借用该上下文。每次调用和返回都重查会话、Feature、声明/Grant/Consent、安装/版本/配置/实例代次、Profile/Binding；长调用持续检查并取消实际模型 HTTP。私人来源没有新增 Host/MCP/SDK 通道；私人索引同意与模型逐次同意不传递给插件。

模型分发前要求低敏 `plugin.ai.authorize` 审计/Outbox，记录发布身份、代次、Profile与RunID；不记录Prompt/答案/私有正文/秘密。之后仍执行既有 AI 持久请求预算预留、分发和必需结算。文本贡献Port绝对期限上限30秒；只有Container的精确模型声明与独立Grant匹配时部署上限才由原5秒扩为30秒，其他插件及Wasm仍为5秒。实际执行取请求、Grant和部署的最小值；普通公开读取Host仍至多5秒，模型/问答Host至多30秒，模型自身Profile期限继续独立约束。请求DTO持续时间即使绝对信封较短也不能超过Grant。重复RunID、预算/并发/期限超额被拒绝；分发后结算失败不返回答案，常驻租约只结算未知计费，不重放模型。插件只能获得文本、RunID与Profile ID，不能读取Secret、密文、原始错误或费用管理接口。

公开问答在预留事务内加入插件许可检查，保留原来源与索引修订、来源发布状态和最终引用重核。插件收到的引用可以经已独立授权的 `knowledge.public.source.read` 重开；模型返回的 URL、工具或引用 ID 不具备授权意义。没有证据直接拒答，不调用模型；未知/伪造引用、撤权、来源私密化或必需审计失败均无答案。

## 贡献给内置功能

`ai.plugin-text/v1` 保留 [首片合同](v1.2可选插件文本贡献接入合同.md) 的精确选择和显式文本边界。新增编译内部 `knowledge.plugin-public-source/v1`：当前 User 选择确切发布者/key/版本/`knowledge.source/v1/public_text` 贡献和一个当前公开集合，宿主用集合 ID 构造 binding_id，以有界 cursor/limit 通过受管 Runtime 调用。Knowledge 不导入 Plugin 实现，装配根负责适配；没有插件时内置检索/问答继续独立运行。

Provider 输出不建立新的可放行授权事实。v1.2 适配器限定为现有公开集合的来源引用：external_id 对应当前 member_id，revision 对应当前原来源修订，title/text 必须逐字匹配原域当前公开来源；可选HTTPS URL若存在也必须匹配当前来源。未知/重复成员、旧修订、伪造正文/URL、跨集合和畸形分页全量拒绝。通过后仍重新打开每项原来源，返回宿主创建的来源与URL，不抓取插件给出的URL、不把插件正文落库。仅声明贡献不会取得检索、引用、模型、网络或秘密消费权限。

每页1–20项、查询最多64 UTF-8字节、页码1–100000、1–5000ms，cursor最多128字符；受管实例/部署的字节、时间和并发上限继续取更严格值。模块 Stop 取消并等待活动调用，停机拒绝接单；重启重新选择当前受管发布，不保存 allow/正文缓存。外部网站采集或 WeKnora 适配仍按主计划 P2，不属于本版本的来源权威。

## SDK、作者包与验收

公共 Go SDK 提供 `ModelChat`、`KnowledgeAnswer` 与双贡献点的 `ServeV5ContainerExtensionsWithHost`；TypeScript提供同名模型/问答 DTO 与 helper。传输仍为独占有界 HTTP/1.1 stdin/stdout，Host yield最多32次；Secret、数据库、网络和宿主目录不交给作者程序。

独立示例 `plugins/campusos.ai-knowledge/` 同时提供文本贡献和当前公开来源贡献，消费能力逐项声明/批准；`scripts/build-v5-ai-knowledge.sh` 只在独立目录离线编译 SDK 和标准库，零镜像摘要模板必须替换为真实RepoDigest后签名。安装器不编译作者代码、不改变宿主源码/锁文件/二进制/Schema。目标验收使用正常生产模块、独占PG16、真实User/Admin、独立签名镜像/实际Container、本机HTTP与共享Egress的真实TLS协议端，详见最终报告；协议端不代表LLM质量评测。

本阶段没有新增DDL、迁移、产品依赖或持久正文目录。回退先撤销Grant/Consent或停用插件/Feature；保留既有审计和计费，移除新能力绑定使调用失败关闭，不删除原来源。整版Final仍须独立验收。
