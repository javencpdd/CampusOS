# V12-02b 图文管理员治理接入合同

> 更新时间：2026-10-14 04:10（Asia/Shanghai）
> 状态：本切片实现、自动化及Linux目标三态通过；其他02b责任继续

| 生产路径 | 当前精确执行权限 | 实际结果 |
| --- | --- | --- |
| POST `/richtext/articles/:id/admin/offline` | community.thread.take_down | Thread taken_down，Article offline；thread_id/status回执 |
| POST `/richtext/articles/:id/admin/restore` | community.thread.direct_restore | actual active/taken_down Thread恢复clear，Article依据真实发表意图投影；thread_id/status回执 |
| DELETE `/richtext/articles/:id/admin` | community.thread.trash | actual active Thread回收，Article trashed；204 |

所有路径要求签名管理域JWT、当前独立账号/会话和15分钟实际MFA，以及当前实际角色/绑定/非复用权限见证。相同ID的User不是Admin，也不能靠owner执行这些动作。可选JSON只接收非空reason；动作和scope由业务入口及实际Thread构造。

Core持有Thread及授权，RichText持有Article完整快照/000020版本。在同一平台事务中依次锁定凭据/权限、实际Thread和Article，比较完整事实，分别CAS更新；typed修订/案例/动作、必需平台审计和outbox原子提交，必需失败全部回滚。Feature最终快照和状态投影复核后，Core再次核对完整主体/授权与资源。

参与者只收到深拷贝的Core字段。旧Article显示状态允许滞后Core直接治理，但不能据此改变授权或假造active；最终投影必须匹配真实Core三态。Admin actor明确admin域/opaque ID，legacy User字段空，保留创建者、原正文/JSON/摘要/封面和发表意图；直接恢复继续使用原清洗规则。

治理执行不授予Article原文、元数据、附件或图片读取权；回执及事件不含这些字段。旧裸ID内部兼容方法不作为生产HTTP授权入口。
