当前 `POST /spaces/me/avatar` 在上传字节/资料/必需审计已提交后清理真正超额的旧头像；上传失败不裁剪旧库存，不把预计清理所得容量用于本次上传。`POST /spaces/me/avatars/cleanup` 是当前本人重试入口，严格无正文，不接受 owner、文件名、任务 ID 或回执。返回 `{owner_id, cleanup_pending}`；上传回执仍为 `{space_id, owner_id, cleanup_pending?}`。Web 通过“清理历史头像”重试，并回读当前资料、存储和历史，容量已满时可先清理再上传。

固定 owner/avatar_retention 规则只允许当前启用的本人空间；每步重新检查完整当前 User Session、空间23或默认无行、Owner、库存与配置。保留最新 keep_limit 条记录，并保护当前 User.Avatar 与 Space.Avatar；受保护的旧记录可使实际总数高于保留数，不能为了凑数删除正在使用的头像。进程文件锁先于 SDK，受支持命令使用实际 User/Session/Space、owner admission 和任务行锁。

已有 `platform_operation_runs` 保存私有固定详情：filename/size/hash/mtime/mode/稳定文件 identity，绝不保存物理路径，也不从任务详情授予权限。Unix 使用 device/inode，Windows 使用文件 handle 的 volume/file index/creation identity。JSON 严格解码，未知字段关闭；同字节/mtime 的 inode 替换也不删除。内建 scoped reader 在分页前按 kind/subject/owner 过滤，当前读取与真实行锁、完整任务结果重验；Memory Start/Update/List/Snapshot/Restore/Recover 的详情去别名。

1. prepare：当前同源事实与文件回执重验，初始化尚未接管的既有文件账本，持久任务及必需 audit/outbox 先提交；失败不删字节。
2. bytes：实际权限/空间/任务锁与完整回执复核后，只删除精确目标；必需审计失败不假装字节回滚，任务仍 pending，容量继续保守占用。
3. finalize：取消独立且最多五秒，重新当前授权、文件确实不存在和同任务，负账本增量、任务终态及必需 audit/outbox 原子。Memory 失败只补回本次释放；重复/新服务重试不重复释放。请求取消导致 byte-phase SQL 提交失败时，仅有界重验一次已缺失文件，继续当前安全 finalize。

任务已被当前资料保护或不再超额时，保留文件、终态 retained、不释放容量。后续真正超额按当前完整事实与库存生成新幂等键。单次最多处理100任务；超出或回执变化诚实 pending。不会宣称任意外部文件写受数据库锁保护，也不会自动删除变化后的文件或越权完成失效会话任务。Operations HTTP 投影原本已隐藏 Details，本路径只持久固定安全状态，不写底层 err.Error()。
