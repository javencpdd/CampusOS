# v1.2 个人空间文件读取接入合同

> 更新时间：2026-10-12 18:30（Asia/Shanghai）
> 责任阶段：V12-02b；头像、本人头像库存及容量元数据切片。

当前个人空间没有通用裸文件原文 HTTP 入口。个人文件原文由已验收的 Personal Documents、UserAsset、文章附件和 Invocation 入口管理；Core Object Port 是可信进程内存储原语，不是任意 owner/object_id 的公开下载 API。此次核对实际路由后，补齐剩余头像路径和库存/容量读取，不新建无需求的通用文件 API。

`GET /spaces/files/:user_id/avatars/:filename` 的匿名例外仅为精确匹配当前活跃用户资料头像，或当前 public、未停用空间的头像。私密空间头像和保留的历史头像仅当前本人 User Session 可读；知道历史 URL 不授予访问。User 与 Space 事实必须从其所属模块加载；跨模块公开资料适配器保留实际用户状态。Admin 或客户端 owner/认证强度字段不能替代本人证明。Authorization 存在但无效时失败关闭，不回退匿名。

`GET /spaces/me/avatars` 与 `/spaces/me/storage` 从实际完整 User Session 导出 owner，核对当前活跃用户及拥有者资料，返回前重读整份头像库存、容量/配额元数据及完整 Principal；空库存同样验证。头像库存不纳入符号链接、非普通文件或非图片后缀。字节读取使用有界实际图片快照并重读资料与字节，不返回物理路径。新的 HTTP 路径用安全通用错误，不泄漏文件系统原因。

容量字段通过 User Storage 的窄 `CurrentQuotaReader` 读取当前持久化 owner 配额。启动缓存不构成当前元数据授权事实；Memory/PG 提供直接 owner 读取，缺 Port 不回退缓存。头像库存附带的容量字段也使用同一路径。该端口不授予更改配额权限，不改变旧上传配额算法。

Web 的受检查图片白名单包含头像路径；本人媒体库存用当前会话请求历史头像并显示 Blob，保留放大预览。当前公开头像仍可匿名加载；认证头只发送至同源白名单。组件与会话变化的字节清理延续[内联图片合同](v1.2内联图片授权读取合同.md)。

兼容资料/头像目录没有持久化非复用事实版本，绑定的是当前值、生命周期、字节和修改时间，不宣称跨介质事务或撤回已交付内容。管理端配额修改、空间停用、作者生命周期和治理写入仍由后续写入责任验收。

实施与证据：[.54](../进度/v1.2-dev/v1.2.54-dev.md)、[Linux 报告](../项目计划书v1/项目计划v1.2/evidence/v12-02b-space-files-linux.json)、[演练](../../scripts/v12-02b-space-files-drill.sh)。实际域 JWT/SessionService 的 HTTP 组件使用 Memory Identity；用户/空间/配额和生产资料适配器在真实 PostgreSQL16 与本地头像文件上单独验收。组件测试与构建不代替浏览器验收。
