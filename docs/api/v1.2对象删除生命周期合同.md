# v1.2 对象删除生命周期合同

> 更新时间：2026-10-14 18:47（Asia/Shanghai）
> 状态：本切片实现、自动化与 Linux PG 目标三态通过

OwnedObjectLifecycleCommands 是内建模块使用的存储 seam，不是 HTTP 或外部插件 capability。读取 owned ready/deleting/deleted 元数据并返回由存储模块持有的 opaque receipt；JSON 为 {}、无路径或私有 key。公开 Object 是去别名投影，改写公开字段或伪造 receipt 不形成有效证明。认证和资源权限由实际业务模块完成。

DeleteOwnedObjectForCommand 在存储真实锁内核对完整内部 receipt（包括私有 storage key）、owner/version；准备、restore、finalize 使用同一完整 deleting receipt。正常 ready→deleting→deleted；pending 用当前 receipt 重试，当前 deleted 幂等，无重复账本释放。终态不可 restore，变化或过期 receipt 拒绝。支持的生命周期变更推进 version，不宣称任意直接 SQL ABA 的通用 nonce。

外层业务事务拒绝 physical I/O。删除 bytes 后 finalize 使用取消独立的最长5秒 context，失败明确 pending；provider/path 失败的 restore 错误也明确 pending。保留真实 row/账本，不以 not-found 或普通失败伪报删除成功，不误删其他对象。物理不可回滚，后继 Asset purge 仍须当前授权、必要阶段审计与诚实 purging/pending 状态。

无 DDL，current22/next23。见[进度 .93](../进度/v1.2-dev/v1.2.93-dev.md)。

Object 删除生命周期前置三态通过：存储持有完整私有 owned receipt/去别名与JSON空对象、实际 prepare/restore/finalize 全回执与行锁、pending/终态安全重试和一次容量释放；取消独立5秒 finalize、restore/finalize 失败明确 pending，拒绝外层业务事务物理IO及终态恢复/过期回执。105 必需/38 真实 PG、四Native/八并发恰一成功、真实 ledger SQL 拒绝/回滚/重试与另一对象保留、七 metadata/private key/alias/outer txn/prepare后变化/restore SQL 场景和actual行锁、原99回归及共同门禁通过。
