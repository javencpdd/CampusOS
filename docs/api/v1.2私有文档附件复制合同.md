# v1.2 私有文档附件复制合同

> 更新时间：2026-10-14 13:56（Asia/Shanghai）
> 状态：本切片实现、自动化与 Linux PG 目标三态通过

POST `/richtext/articles/:id/attachments/from-personal-document` 使用固定 `http.feature.richtext.attachment.copy_document`。strict JSON 只有 document_id 和可选 display_name；当前完整 User 必须是目标实际作者和私有源 owner，独立 Admin 不可代理。沿用实际 Core edit Policy，并独立执行 Personal Documents 当前 source read Policy。

先加载并证明目标 Core/Article20/Asset-Binding22，再通过当前 Session 的可信 bridge 打开 active PDF/DOCX。来源模块持有完整 Document、current immutable version、source Object 预期快照及 CheckCurrent callback；返回元数据不能改写预期证明，callback 不属于网络接口或外部插件能力。复制期间前后复核当前主体和完整源，业务事务内锁定实际 source document/version/Object，最终结果再次检查。

新 RichText Object 的 size/SHA/MIME 必须与完整源相同；截短流不能成功。业务表仅引用新对象，不保存私有 source ID。复制成功后私有源回收不改变附件 bytes。目标新增 Asset/Binding、必需 audit/outbox 原子，失败使用 .88 receipt 补偿与明确 pending 边界。

201 回执与事件只有 thread_id/attachment_id；当前 Web 刷新附件列表。读取和写入各自使用当前 Policy，不能把成功回执或 preview 当作后续权限。支持的 source mutations 递增 version；任意 direct SQL ABA 重写不在本切片保证内。无 schema 变更，详见[进度 .89](../进度/v1.2-dev/v1.2.89-dev.md)。
