# v1.2 其他 Scope 与委托边界目标合同

状态：V12-G1 冻结非版块 Scope 的目标结构、拒绝码与离线验收；02a/02c/03b 才实施仓储、机器/插件主体与真实出站限制。[版块治理](v1.2版块治理委托上限合同.md)继续使用其独立合同。

机器合同：[Schema](scope-delegation-v1.schema.json)、[错误目录](scope-delegation-v1.errors.json)、[SDK DTO](../../sdk/typescript/src/scope-delegation.ts)、[定向检查](../../scripts/check-v12-scope-delegation-contract.mjs)。

首批非版块授予只允许公开知识集合 ID、系统配置键与精确 HTTPS 端点三个 Scope，分别绑定 knowledge.source.read、plugin.config.system.read、integration.webhook.invoke。个人文档首版仅本人，明确不可委托；未知动作、通配符端点和空范围均拒绝。插件、Integration 不是用户或管理员 Session，不能凭借一个 grant 获得另一个能力。

授权者必须是已通过 MFA 的独立 Admin，且拥有与收件域相应的管理动作。每个候选动作必须由同一条当前有效、可委托的上限完整覆盖：动作与 Scope 类型相同，ID 是精确子集，起点不早于当前或上限起点，终点不晚于上限终点，认证要求不可降级。不能跨不同上限拼接动作、ID、期限或 MFA。User 收件人的版块治理另走专用合同，不通过此合同扩大能力。

输入中的 actor、管理权、上限、时钟和 facts_version 由宿主构造；浏览器/插件只能提出有限候选意图。允许的离线结果仍须在同一事务内重读事实、版本与时钟，写入授予与必需审计；撤权提交后的新调用必须拒绝。离线 23 夹具、4 次变更复核只证明合同规则，不证明持久化与出站 Broker 已接入。
