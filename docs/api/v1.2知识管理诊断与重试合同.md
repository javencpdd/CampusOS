# v1.2 知识管理诊断与重试合同

> 更新时间：2026-10-23（Asia/Shanghai）
> 阶段：V12-12；当前实现与 Linux 验收见[.149](../进度/v1.2-dev/v1.2.149-dev.md)

Web `/knowledge` 使用既有[匿名公开搜索和当前引用 HTTP](v1.2公开知识搜索HTTP合同.md)。
独立 Admin `/knowledge` 管理公开集合、官方资料、选择规则、成员引用和索引执行诊断。
两者是不同的前端入口，不能互借 User/Admin 凭据或扩大当前原来源读取范围。

## 管理路径

集合启用/停用、官方资料草稿/发布/撤回及不可变修订、单篇/板块/官方选择、显式成员移除，继续使用[来源管理合同](v1.2知识集合与来源管理合同.md)。
所有修订与版本均按十进制字符串传递；库存中的官方正文已剔除，编辑从授权的当前修订历史读取。
页面按纯文本展示历史正文，不执行内容中的 HTML，也不抓取内容 URL。

选择规则和实际成员分开显示。板块通过正常常驻索引器分页同步；手动“刷新来源”每次至多 50 条，明确展示是否还有后续页。
移除一个成员引用不等于取消规则：规则保持启用时，后续权威对账可重新物化该来源。
持续排除应取消对应来源选择。

## 执行诊断和指标

GET `/api/v1/admin/knowledge/collections/:id/index` 不接受查询参数或正文。
要求当前独立 Admin 会话和精确 `knowledge.collection.read` 权限；Feature 关闭时失败。
返回 `KnowledgeIndexDiagnostics`，见当前 OpenAPI：

- 集合/任务版本、执行状态、阶段、尝试次数和白名单安全原因码；
- 运行/已完成代次、下次调度时间、观察时间；
- 选择规则数、启用规则数、成员引用数及存储投影数；
- 仅在任务为 `retry` 或 `dead` 时标记可手动重试。

这些是一次当前管理事务中的执行观察，供 Admin 面板诊断使用，也不记录查询或正文。
`idle` 只表示一轮结束，投影数可能含待清理旧修订，已完成代次和投影数量都不是原来源可读性的证明。
公开检索仍在计数、分页与输出前复核当前 G1/来源修订；精确引用失效不得自动打开新修订。
DTO 不包含原文、片段、租约 token、内部游标、连接信息或原始异常。

## 平台执行与延迟指标

正常模块接入既有平台 Meter；沿用受保护的 GET `/api/v1/metrics/summary`，Prometheus 展示仍由既有配置控制。
指标目录由当前代码生成，见[可观测性指标目录](v0.13可观测性指标目录.md)：

| 指标 | 标签 | 精确定义 |
| --- | --- | --- |
| `campusos_knowledge_index_pages_total` | `result=success/failure` | 实际非空执行轮次计数，包含领取存储失败；空闲轮询不计数，不等同 ready 代次 |
| `campusos_knowledge_index_page_duration_seconds` | `result=success/failure` | 领取及一页执行的实际耗时；不含等待下一轮的睡眠 |
| `campusos_knowledge_index_schedule_lag_seconds` | `state=pending/processing/retry/idle/dead` | 成功领取时相对原正数调度时间的延迟；过期执行相对旧 lease 到期时间，零时间立即任务没有年龄样本 |

指标标签不含集合、成员、来源、查询、正文、错误文本或凭据；最多2/2/5个series。
执行计数和直方图遵循既有进程 Collector 生命周期，不替代耐久任务记录。调度延迟是调度点到领取的观察，不声明完整排队年龄或SLA。单集合当前状态和计数使用上方诊断；直方图标签表示领取前状态，不冒充全局当前队列长度。
遥测失败不扩大读取权限或改变任务事务结果；未装外部插件也可采集。

## 手动重试

POST `/api/v1/admin/knowledge/collections/:id/index/retry` 只接受：

```json
{"collection_version":"当前集合版本","version":"当前任务版本"}
```

两字段必须是规范正十进制字符串。要求当前 `knowledge.collection.manage`、当前 MFA 和浏览器 CSRF；不接受客户端身份、Scope、正文或任务游标。
在集合→任务锁顺序下同时校验版本与 `retry/dead` 状态，陈旧版本或运行中任务返回 409。
成功的必需审计/Outbox 命令为 `knowledge.index.retry`，typed Admin 归因继承现有管理边界；失败时整个任务重置回滚。

受理只把执行恢复到 `pending`，清除旧执行/ready 代次和租约，重置有限尝试并增加请求代次。
下一轮由既有常驻索引器取得新非复用 lease，重新按当前来源与规则执行；页面显示“已受理”，不伪造 ready。
客户端不自动重放写命令。409 后刷新工作区，核对当前数据再提交；503 后检查诊断，确认恢复再手动重试。
原执行器的租约、断点、重试上限与权威对账策略见[耐久索引合同](v1.2知识索引任务请求合同.md)。

## 状态、操作和验证

禁用、未配置、加载、空结果、请求失败、权限或 MFA 不足都提供中文说明和实际可用动作。
Web 修改查询、切换集合、开始检索、隐藏或离开页面时清空旧结果/原文并取消旧请求；旧请求晚到不会恢复结果。
404/409 清空旧片段和原文并要求重新搜索。Admin 失败清空详细状态，保留刷新入口，不直接重放写请求。

操作教程见[公开知识检索与管理](../../docs-site/guide/public-knowledge-search.md)。
原生入口为[联合 drill](../../scripts/v12-12-public-search-drill.py)，报告为[当前 Linux 退出](../项目计划书v1/项目计划v1.2/evidence/v12-12-exit-linux.json)。
它用当前 race ELF 的正常生产 Server 模块/router、真实 PostgreSQL、两端构建产物和真实 Chrome，验证独立登录/MFA、CAS、当前权限、Feature、实际审计故障回滚和常驻重试。
原生测试宿主不冒充独立 cmd/server 部署；Windows 实机沿用用户延期。本阶段没有私人索引、外部 Provider 或 AI/RAG 接入。
