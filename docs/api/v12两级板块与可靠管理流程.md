# v0.12 两级板块与可靠管理流程

> 基础地址：`http://localhost:8080/api/v1`  
> 适用阶段：v0.12 B1-B3

## 1. 读取边界

| 场景 | 路径 | 返回范围 |
| --- | --- | --- |
| 公开 flat 列表 | `GET /categories` | 仅 active 节点，保持旧列表合同。 |
| 公开树 | `GET /categories/tree` | 仅 active 节点；group 的 `children` 是活动 board。 |
| 公开详情 | `GET /categories/:id` | 仅 active 节点。 |
| 管理 flat/树/详情 | `GET /admin/categories`、`/tree`、`/:id` | 包含 archived 节点；需要 `category:read`。 |

所有 ID 使用字符串，避免 JavaScript 对 BIGINT 的精度损失。公开树不应被用于管理归档或恢复操作。

## 2. 创建与更新

创建 root group：

```http
POST /api/v1/categories
Authorization: Bearer <access-token>
Content-Type: application/json
```

```json
{
  "name": "学习交流",
  "slug": "study",
  "node_kind": "group",
  "color": "#166534",
  "sort_order": 10
}
```

创建 group 下 board：

```json
{
  "name": "课程讨论",
  "slug": "courses",
  "node_kind": "board",
  "parent_id": "1000000000000000001",
  "default_tags": ["课程", "答疑"],
  "color": "#0F766E"
}
```

创建需要 `community.category.create`。group 不能携带非空 `parent_id`。`color` 只能是空字符串、
`#RRGGBB` 或 `#RRGGBBAA`。

更新不允许通过 `parent_id` 改变层级。使用 `PUT /categories/:id`，并携带当前版本：

```json
{
  "name": "课程与答疑",
  "is_closed": false,
  "version": 3
}
```

这需要 `community.category.update`。版本过期返回 `409` 和 `category version conflict; reload and retry`。

## 3. 移动、归档与恢复

移动 board 到一个 group：

```http
PUT /api/v1/categories/1000000000000000002/parent
Authorization: Bearer <access-token>
Content-Type: application/json
```

```json
{
  "parent_id": "1000000000000000001",
  "version": 3
}
```

移动到根级必须显式传入 `null`：

```json
{
  "parent_id": null,
  "version": 3
}
```

省略 `parent_id`、指定 board/archived group、自身或非法层级都会被拒绝。移动需要
`community.category.move`，且不会改变任何版主 scope。

归档前先读取影响：

```http
GET /api/v1/categories/1000000000000000002/archive-impact
Authorization: Bearer <access-token>
```

响应包括 `active_child_boards`、`associated_threads` 与 `will_block_new_posting`。随后调用：

```http
POST /api/v1/categories/1000000000000000002/archive?version=3
Authorization: Bearer <access-token>
```

归档需要 `community.category.archive`。有活动 child board 的 group 不能归档。恢复使用：

```http
POST /api/v1/categories/1000000000000000002/restore?version=4
Authorization: Bearer <access-token>
```

恢复需要 `community.category.restore`，且若该 board 有父级，父 group 必须仍为 active。

## 4. 旧 DELETE 兼容与可靠性

历史客户端可继续调用：

```http
DELETE /api/v1/categories/1000000000000000002?version=3
```

它需要 `community.category.archive`，不会删除记录，只调用 archive 并记录
`community.category.delete.archive` 兼容遥测。新客户端应改用 archive 路由。

所有管理写入在同一可靠命令事务内写入 Category、required command audit 和 Outbox。若数据库写入、
审计或 Outbox 任一环节失败，命令整体回滚。事件处理发生在提交之后，调用方不能把 HTTP 成功解释为
前端缓存已经刷新。

## 5. 发帖规则和错误

主题和回复写入都会重新读取 Category。以下目标会被拒绝：

- `group`；
- `archived` 节点；
- `is_closed=true` 的 board；
- 父节点不是 active group 的 board。

公开读取 archived 节点返回未找到；管理读取可以看到并恢复。客户端应处理 `400`、`409` 与 `404`，不应
把导航缓存或本地的 parent ID 当作授权或发帖资格的事实源。
