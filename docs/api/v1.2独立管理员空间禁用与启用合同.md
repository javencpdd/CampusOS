# V12-02b 独立管理员空间禁用与启用合同

> 更新时间：2026-10-16 01:34（Asia/Shanghai）
> 状态：本切片实现、自动化与 Linux PostgreSQL 目标三态通过

| 入口 | 请求 | 成功响应 |
| --- | --- | --- |
| `POST /api/v1/spaces/:user_id/disable` | 可选严格 JSON，仅 `reason`；正文至多 8192 bytes，trim 后最多 500 字 | `{owner_id, space_id, disabled:true}` |
| `POST /api/v1/spaces/:user_id/enable` | 无正文 | `{owner_id, space_id?, disabled:false}` |

`space_id` 在默认无行启用时省略。两条路径均返回 `Cache-Control: private, no-store`，不返回原始 Space、私密正文、同步错误、文件地址或管理员身份记录。Admin API 类型按安全 ACK 更新；当前页面不存在这两个 API 的实际 UI 消费者，不虚报浏览器验收。

管理权限为基线已存在的 `personal_space.space.manage`。服务端构造固定 `personal_space.space` scope，ID 是实际目标 User ID；当前独立 Admin 会话、完整角色/绑定/权限事实与 MFA 十五分钟窗口每次重新加载。命名 `PersonalSpaceAdminPolicy` 允许管理 active/suspended/deactivated 的真实目标 User；User Token、User 角色和同号 User 不产生管理权限。

事务保留当前 Admin 账号/会话/角色/绑定/权限、目标 User、完整 Space23 与空行 owner admission；执行前后及最后一次证明完整比较。Identity `UserCommandReader` 仅在已有事务可读目标 User 的七字段投影，不提供身份写入或 SQL。

禁用只更新禁用时间/原因、`disabled_actor_kind=admin` 与真实 opaque Admin ID、更新时间，旧 `disabled_by=''`；启用清除上述归属。必要的默认行创建与所有字段独立预期比较。仓储返回精确写入版本，额外写入/ABA 拒绝；启用默认空间不创建行，成功无操作仍写必需 audit/outbox。正文、样式、同步数据、文件、使用量和配额均不在命令修改范围内。

响应与 outbox 使用同一安全 ACK；必需审计的 `actor_type=admin`，任何写入/审计/事件错误使整体回滚。401 当前会话无效，403 当前授权/MFA 不满足，404 目标不存在，409 当前事实变化，503 缺少适配器或事实不可验证；无内部路径或原始数据库错误。

无新 DDL，current23/next24；使用 actor18 已有约束。进度见 [.105](../进度/v1.2-dev/v1.2.105-dev.md)，目标结果以最终报告与源摘要为准；配额/管理读取及阶段其余路径继续独立验收。

独立Admin空间禁用/启用三态通过：固定当前Admin/MFA/permission17与命名Policy，完整目标User/Space23/default，真实账号/会话/角色/绑定/权限/User/Space/admission锁；actor18管理员归属、精确版本回执及必需audit-outbox原子，safe IDs/disabled ACK，无私有内容读权，默认启用不创建行。219必需/65真实PG、10新增/64纯规则、40实际执行与六提交变化、原209回归及共同门禁通过；配额、管理读取及阶段其余项继续。
