## 信任边界

`campusos.integration-access/v1`是宿主内部事实及同次调用的白名单决策合同。只有对应域验证器验证实际凭据后才能构造Principal；JSON/SDK类型正确不证明认证。当前没有接收此JSON并授权的公共HTTP入口。决策不是可重放授权令牌，也不对外返回完整事实。

Identity负责Integration身份/凭据当前行及规则，宿主注册表负责当前端点描述，原资源模块负责公开性和当前修订。`integration_allowed`不能从请求或Key自报，不能借现有后台MCP工具得到默认允许。凭据原值/摘要、用户原文与邮箱不属于本DTO。机器不会转换为User/Admin或代理用户。

## 输入及判定

根字段为contract、request_id、principal、target、facts、now_ms。target固定实际通道/端点/动作与单个资源kind/id；facts携带integration_id、credential_id、两类状态、credential_audience、not_before_ms/expires_at_ms、facts_version、当前endpoint及rules。Schema列出全部精确字段，所有对象禁止额外属性。

判定顺序如下：

1. 完整结构、Principal域组合、规则ID唯一及所有时间窗口先校验。opaque ID与G1相同，为1–128个ASCII字符，不转换数字、不trim。
2. 必须integration/integration_api/credential，Principal身份和credential_id与事实相符；主体active，凭据active、用途integration_api，且当前毫秒位于左闭右开的凭据窗口。
3. 允许通道仅integration_http/integration_mcp；首片动作/资源类型仅knowledge.source.read/public_collection。其他管理动作、私人资源和Host API不能由任意规则放行。
4. 当前endpoint必须enabled且integration_allowed，通道、ID、动作和resource_kind均匹配实际target。端点ID是精确宿主目录标识，不是可供调用者选择的URL。
5. 一条active且当前有效的规则必须完整匹配通道、端点、动作、资源类型并含精确资源ID。规则最多64条，每条1–32个不同ID；空规则集拒绝。不能跨规则借用动作、ID或有效期，多条命中取ASCII排序最小规则ID。

即使白名单允许，调用方仍需原模块的实时资源ACL/公开状态/当前修订，随后才可读取。它不授权Knowledge未实现的来源读取，也不替代G1 Scope委托或出站Broker。

## 决策复核

决策携带独立复制的完整request、effect、reason和允许时的rule_id。CheckIntegrationAccessDecision先重算原判定并逐字段匹配，拒绝伪造allow或见证；再要求当前完整主体、事实、端点和整个规则库存一致。当前facts_version必须来自未来真实当前事实来源，不能由调用者声明；本片不证明持久化版本防ABA。

当前显式时钟可以前进，复核会重新判断凭据及规则期限；回退拒绝。到期不得借用另一规则，命中见证变更时重做判定。所有加载与最终读取/返回顺序仍由调用方负责，本组件没有仓储、缓存、环境时钟或网络副作用。

## codec、错误及验收

字节输入限制32KiB/64层；严格拒绝重复键（含转义同名）、未知/缺失/null字段、尾随值、非法UTF-8和孤立surrogate。毫秒为0–9007199254740991的数学精确整数；codec不通过浮点舍入接受小数，允许等值整数表示。Schema检查结构，Go/oracle另检查expires_at_ms大于not_before_ms及规则ID唯一。

错误固定为integration.input_invalid/decision_mismatch/facts_changed或目录中的拒绝原因，不回显输入。当前错误没有生产HTTP映射。`integration.allowed`只表示上述机器白名单成立。
