# v1.2 G1：插件 v5 贡献点与调用 DTO 合同

> 状态：目标 Schema、SDK DTO 和 Linux 离线协商验收已交付；真实 Dispatcher、安装、授权与调用未接入。

## 1. 来源与选择

[包形态](v1.2插件v5包形态与版本协商合同.md)中的 provides 只声明 id、point 和版本。本合同为同一贡献 ID 增加输入/输出 Schema 标识、能力上限、数据模式及可选的包内配置 Schema 引用；两个投影必须一一对应。宿主拥有扩展点目录和 DTO Schema，插件不能通过自带的同名 Schema 替换已发布合同。宿主合同版本不相交、未知点、未知能力或 Schema 标识不匹配均拒绝。贡献 ID 在包内唯一；同名候选不可由后装插件静默覆盖，默认绑定由受权管理员明确配置。

机器合同：[provides Schema](plugin-v5-provides-v1.schema.json)、[宿主目录快照](plugin-v5-extension-catalog-v1.schema.json)、[三扩展点 DTO Schema](plugin-v5-extension-dtos-v1.schema.json)、[错误目录](plugin-v5-provides-v1.errors.json)、[SDK 类型](../../sdk/typescript/src/plugin-v5-provides.ts)、[可执行检查器](../../scripts/check-v12-plugin-v5-provides-contract.mjs)。离线目录夹具位于 SDK tests，不能当作已发布生产目录。

## 2. 首批扩展点

| 扩展点 | v1 能力上限与输入数据 | 输出信任边界 |
| --- | --- | --- |
| preview.renderer/v1 | pdf；仅受宿主授权的单项资源引用 | 返回 UI slot 与资源修订；宿主仍检查来源、ACL、修订及 Bridge |
| ai.chat/v1 | text；仅公开上下文或无宿主私有数据 | 文本与用量均不可信，宿主检查大小、预算、取消和终态 |
| knowledge.source/v1 | public_text；仅公开绑定与分页 | 外部 ID、标题、正文、URL、修订均不可信；宿主验证公开归属与大小，抓取只走 Egress |

调用请求携带 request_id、贡献 ID、实例代次与 deadline；Schema 限制类型、大小、分页和未知字段。响应不能携带 owner、ACL、User Token 或 Secret。Schema 拒绝此类额外字段只是一层输入边界；真实调用前后仍须由宿主重查 Principal、Grant/Consent、源资源 ACL、安装/功能状态和实例代次。返回的 HTTPS URL 并不因此成为安全可抓取目标。私人 RAG 走内置 Adapter，不把私人上下文转给外部 Provider；外部 Provider 注册也不取得消费 Host API 的权限。

配置 Schema 目前只冻结包相对路径与 digest 形状；受限 JSON Schema 子集、默认值/Secret 分离仍须在 G1 另一条合同中完成。V12-03a 组合完整 Manifest 并验证真实包字节，03c 完成类型化目录与 Dispatcher，08a 验证两个包的真实调用，14c 验证 AI/Knowledge 业务接入。本切片的 Linux 离线验收不能代替这些阶段。
