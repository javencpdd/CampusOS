四条既有Admin入口 `POST /threads/:id/pin|unpin|lock|unlock`接入独立命名 `community.thread.admin_flag/v1`。固定operation选择精确pin或lock权限；Thread ID取路由、版块/owner/状态/版本取实际Core行，客户端body/query/header不参与权限或状态事实。只允许active帖子上的当前独立Admin、精确角色执行权限与15分钟内MFA；不改变publication/moderation，不因User同编号owner或冻结版块grant获得此Admin能力。

初始完整执行见证和实际Thread策略绑定决策；事务内按Admin账号/会话、角色/绑定/权限、Thread行锁顺序复核，当前修订和非复用facts_version双CAS。每次包括重复同状态操作都产生新修订和typed Admin历史；业务状态、修订、动作、必需平台审计/outbox同事务，任一失败均回滚。最终复核完整见证及写后Thread，受管nonce没有前进即拒绝；counter仅展示字段，在CAS中保留。

结果和事件仅返回 `id,is_pinned,is_locked`，无正文/标题/owner/内部nonce。Admin页面成功后重新请求列表，既有消费不依赖完整Thread回执。错误401/403/409/503稳定且不泄露私有内容。原内部裸ID方法不作为新HTTP认证入口；User Moderation的pin/lock仍需独立当前权限合同接入，不冒用冻结take_down grant。
