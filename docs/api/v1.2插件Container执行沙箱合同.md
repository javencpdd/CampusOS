# v1.2 插件 Container 执行沙箱合同

> 更新时间：2026-10-27 14:33（Asia/Shanghai）
> 状态：V12-06 历史 Linux 范围已验收；当前 Windows 必需目标按用户决定限定为 Docker Desktop Linux 容器，补验中；原生 Windows Go 宿主为范围外历史，失败不改写为通过

## 1. 当前执行路径

在[镜像准入合同](v1.2插件Container镜像准入合同.md)的签名、当前信任、不可变发布身份与精确本地 RepoDigest 核验后，原生宿主显式设置 `CAMPUSOS_PLUGIN_CONTAINER_ENABLED=true`。默认关闭；不自动 pull，不接受 tag、远端 daemon 或用户传入的运行地址。API 容器不挂 Docker socket。

协调器复核当前 installation、Grant、所需 Consent、配置摘要/代次、preparation 和 operation lease，事务外创建真实进程。普通配置通过 Configure 传入，Secret 引用与明文、数据库凭据、User/Admin Token、受管实例 token 均不传给 guest。真实 Configure 响应、daemon 控制项核验通过后，才提交 Observe 和受管发布；审计回滚、领导权或当前事实变化时回收进程，不发布旧代次。

Wasm 和 Container 共用一个 PostgreSQL session advisory guard 与一个宿主总预算：最多16实例、1024MiB、4000 CPU millis；单实例最多256MiB、1000 CPU millis、并发1、调用5000ms。预算在创建前预留，实际进程退出且清理后释放。该配置为单写原生宿主部署，不是集群配额。

## 2. 进程与目录边界

固定本地 CLI、空独占 CLI 配置、有限环境，明确本地 daemon；不继承 Docker context、代理和 registry auth。Linux 使用 `/usr/bin/docker`、Unix socket；Windows 实现分支通过系统 Known Folder 的 Program Files 获取标准 Docker Desktop CLI 路径，通过系统 Windows 目录 API 设置子进程 SystemRoot，使用本地 `docker_engine` named pipe，须 Linux containers/cgroup v2。Windows 分支存在不等于实际 Windows 验收通过。

每个进程使用不可变平台配置 ID，禁止 pull；只读根、UID/GID65534、capabilities 全部丢弃、no-new-privileges、默认 Docker seccomp、独立 PID/cgroup namespace、IPC none、network none、64 PID、nofile64、内存硬限与 swap0、CPU quota、日志关闭。无宿主 bind、设备、socket、数据库网络、发布端口或特权目录。镜像声明 VOLUME 直接拒绝，避免创建匿名数据卷。

每实例仅有独立 `/tmp` tmpfs，noexec/nosuid/nodev，容量为有效 storage 预算且不超过1MiB；停止后删除。它不是平台持久数据目录。当前不开放持久文件或任意网络；未发布 Secret/Egress 能力拒绝。资源申请只能被声明、发布上限、管理员 Grant、部署上限的交集收窄。

Daemon inspect 核验实际镜像 ID、运行状态、资源/用户/目录/挂载/网络等配置；验收 guest 的 cgroup 文件仅用于真实目标证据，不信任任意第三方 guest 自报的控制值。Host 不凭 guest 自报内容解除隔离限制。

## 3. 有限 HTTP/gRPC 管道

镜像 EntryPoint 必须在独占 stdin/stdout 管道实现 `campusos.container-pipe/v1`；stdout 仅传协议，stderr 丢弃。既有任意监听 HTTP 服务、旧 generic gRPC/process runtime、WASI 程序不会自动适配。没有 callback URL、网络 listener、任意 fetch、扩展方法或运行凭据字段。作者 SDK 的正式封装仍属08a。

| Manifest transport | 管道内容 |
| --- | --- |
| `http` | HTTP/1.1 POST，`Content-Type: application/json`，有限 Frame JSON |
| `grpc` | HTTP/2 prior knowledge，unary `application/grpc+json`；5字节消息前缀、未压缩、单消息、`grpc-status: 0` trailer；相同 Frame JSON |

gRPC 帧和状态遵循 [gRPC HTTP/2 协议](https://github.com/grpc/grpc/blob/master/doc/PROTOCOL-HTTP2.md)允许的 JSON subtype；不宣称 protobuf/generated SDK。方法固定在 `/campusos.container.v1.Runtime/` 下，仅 `Configure`、`Invoke`、`Event`、`Health`、`HostResult`。

Frame 字段只有 `contract`、`kind`、可选 `payload`、`capability`、`failed`。严格拒绝未知字段、重复键、尾随 JSON、过深对象、压缩、多消息、缺失 gRPC trailer 和非200响应。消息最多96KiB，业务 payload最多64KiB；头8KiB，原始协议流每交换最多256KiB，含空闲时控制帧。超限或格式错误关闭真实进程。

1. Configure 发送普通 system/user 配置，响应 `ready`，不允许 Host 调用；Health 同样只能响应 ready。
2. Invoke 发送03c既有三类具名贡献的有限 payload，最终返回 `result`，由受管层再次验证类型、关联、代次和响应限额；Event 只接收既有安全元数据，返回 `{"ack":true}`。
3. Invoke/Event 可返回 `host`，只包含 capability 与 payload；宿主返回 HostResult，再继续结果。每次最多32次。宿主先检查签名 consumes，Broker 再按当前受管 token、声明∩Grant/所需Consent、Feature/Core ACL 和资源修订重核。token 仅保存在宿主内存，不给 guest。
4. Host 拒绝以 failed HostResult 返回；guest 可返回失败结果，不强迫恢复已被拒绝的授权。输出不能证明授权；受管层仍在调用前后检查当前事实。

## 4. 生命周期与验收

调用者取消/期限、坏协议、输出洪泛、超量 Host 调用均终止实际容器；OOM 通过 Docker State.OOMKilled 记录后才移除。进程退出撤下发布并写 runtime_lost，显式 enable/retry 才恢复已知失败。配置变化产生新代次，旧绑定不能使用。

重启先取得相同 PG guard，再清理同一数据库 namespace、保留标签和随机名称的孤儿容器，然后对账/准备新代次。其他部署保留。关闭流程先停止准入、终止并等待真实进程，再释放 guard 和 CLI 临时目录。

Linux 目标由 [runtime drill](../../scripts/v12-06-runtime-drill.sh) 创建独占 PG16 和实际签名 scratch guest，运行 race 测试二进制与真实 race cmd/server；HTTP/gRPC、CPU/RSS/OOM/取消/退出、目录/网络/凭据边界、当前私密状态/会话/信任/Grant到期、配置代次、元数据 ACK、审计回滚、leader 丢失、宿主强杀/孤儿围栏/Stop 都需有原始证据。机器报告独立于历史[首片报告](../项目计划书v1/项目计划v1.2/evidence/v12-06-container-image-linux.json)。

Windows 原生 API + Docker Desktop Linux containers 的完整执行、资源/目录/通信/取消与重启证据在历史 .127/.167 范围内尚缺，交叉编译、Linux 上的 PowerShell 或 WSL 验收不能追认该目标通过。当前用户已将本版 Windows 必需范围限定为 Docker Desktop Linux 容器（第 9 节），故不再要求以该原生目标退出；Docker Desktop 当前候选与原生 Linux Final 仍分别需要实际证据。


## 5. 本地启动目录合同（.126）

更新时间：2026-10-19 09:42（Asia/Shanghai）。Windows不再假设`C:\Program Files`或`C:\Windows`；两个目录分别来自系统API，允许不同盘符及Unicode，禁止通过ProgramFiles/SystemRoot/PATH等环境变量覆盖。这里只支持系统Program Files下的标准Docker Desktop安装路径；自定义/用户级安装没有自动搜索回退。

目录查询使用 [Known Folder API](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderpath) 读取位置但不验证/创建目标目录；[GetSystemWindowsDirectory](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemwindowsdirectoryw) 获取共享系统目录，避免把多用户的私人Windows目录当作SystemRoot。结果必须满足保守本地盘符绝对路径子集，UNC/设备/相对/点组件、控制字符及非常规根目录拒绝；查询失败不回退C盘或继承PATH。调用者已取消时不查询或启动。

当前合同、Linux真实Docker回归与Windows交叉编译见 [.126](../进度/v1.2-dev/v1.2.126-dev.md)和[本片报告](../项目计划书v1/项目计划v1.2/evidence/v12-06-local-command-linux.json)。Linux合同测试中的Windows目录reader是显式oracle，不是原生系统API验收；旧.125仍保留当时Linux全生命周期事实。Windows实际目标未通过，06继续保持进行中。

## 6. 原生 Windows 验收入口（.127）

更新时间：2026-10-19 10:04（Asia/Shanghai）。[PowerShell 入口](../../scripts/v12-06-windows-drill.ps1)调用[跨平台验收器](../../scripts/v12-06-portable-drill.py)。Windows目标需要系统级标准Docker Desktop、Linux containers/cgroup v2/default seccomp、本地已有`postgres:16-alpine`、原生Go 1.25工具链及支持race的MinGW GCC、Python 3.10+、PowerShell 7.2+；共同门禁还需要Git、Git Bash/GNU make、pnpm及项目依赖。脚本不安装工具或拉取镜像。

必须从共享真实控制台启动。正常关闭使用独立子进程组与定向`CTRL_BREAK_EVENT`；[Windows控制事件API](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent)要求发送方和目标组共享控制台。独立子进程测试先验证信号及退出码，实际服务器再验证正常回收；API失败、超时后的强杀均判失败，不能当作正常Stop。

```powershell
$evidenceDir = Join-Path (Get-Location) (".cache/v12-06-runtime/acceptance.windows-" + [guid]::NewGuid().ToString("N"))
.\scripts\v12-06-windows-drill.ps1 -Mode target -WorkDirectory $evidenceDir
.\scripts\v12-06-windows-drill.ps1 -Mode common -WorkDirectory $evidenceDir
.\scripts\v12-06-windows-drill.ps1 -Mode documents -WorkDirectory $evidenceDir
.\scripts\v12-06-windows-drill.ps1 -Mode seal -WorkDirectory $evidenceDir
```

`target`仅使用全新仓库内独占目录，先冻结源码和历史依赖，再构建并执行三份原生race测试PE与race服务器。真实编译分支记录OS API目录/本地named pipe；Windows测试控制命令也使用独占空CLI配置。scratch Linux guest以HTTP/gRPC执行，完整复用内核/目录/网络/配置/Host、故障/取消、真实PG当前授权/代次/leader、Admin HTTP及宿主强杀重启/正常Stop路径。PG仅绑定临时loopback端口且使用独占tmpfs，密码不入报告；结束清理本次拥有的PG/镜像，测试自行回收worker，保留其他部署。

失败时保留该目录及原始日志；先定位失败步骤。`target`不复用旧目录，源码变化需新建目标证据，不把旧二进制/日志套在新冻结摘要上。已通过的`target`可以继续执行尚未执行的`common`/`documents`/`seal`，不重跑目标步骤；门禁失败时保留已执行日志检查原因。

封存分别生成`v12-06-runtime-portable-linux.json`或`v12-06-runtime-windows.json`，保留原始产物摘要；Linux上的PE交叉编译、PowerShell语法/拒绝路径及证据检查器oracle单列。两个目标报告和原始目录归集到同一工作区后，执行`python scripts/v12-06-portable-drill.py exit`，同时核对当前规范化源码、历史依赖、原始测试/子进程证明、共同/文档门禁和摘要。规范化只处理CRLF/LF差别，每个目标仍保存实际字节摘要；任一目标缺失或漂移都不能生成阶段完成证据。

本轮实现/自动化/Linux目标与Windows缺项详见[.127](../进度/v1.2-dev/v1.2.127-dev.md)。当前没有Windows实机结果，不能将脚本实现、Linux PowerShell或WSL执行当作该目标通过。
