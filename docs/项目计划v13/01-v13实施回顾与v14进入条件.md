# CampusOS v13 实施回顾与 v14 进入条件

> 文档状态：已完成；`v0.13.0` Final 已通过。  
> 发布版本：`v0.13.0`  
> 关联计划：[v13 版本计划书](00-v13版本计划书.md)  
> 进度证据：[v0.13.13-dev](../进度/v0.13-dev/v0.13.13-dev.md)

## v13 已交付范围

- 结构化校园互助和校园二手列表改为批量 Detail 读取，并用查询预算保护分页行为。
- 统一错误合同保留历史响应字段，同时提供稳定 machine code、请求 ID、重试语义和安全脱敏。
- Observability Core 提供低基数指标、管理端摘要和默认关闭、仅 loopback 的 Prometheus 导出。
- Reliability 增加队列年龄、重试、dead-letter、消费与投递指标、告警规则和故障恢复 Runbook。
- 系统主题、首页包和个人主页风格包采用 `campusos.appearance-delivery/v1`，新应用必须通过 PC/移动端声明、双预览、响应式、对比度和 reduced-motion 检查。
- 管理员准入支持独立列表、暂停/恢复、版本冲突、最后管理员保护、会话撤销、required audit 与本机 CLI 恢复。
- Identity Core 支持加密保存 TOTP Secret、一次性 MFA Ticket、恢复码、Step-up 和 `off/enrollment_grace/required` 管理员策略。
- 容量工具、资源预算、隔离数据库容量演练、迁移/恢复演练和浏览器矩阵进入发布门禁。

## 兼容与迁移结论

- 数据库只新增 `000039` 与 `000040`；历史 migration、HTTP 顶层包络、旧风格资源读取和旧插件 Manifest 继续保留兼容路径。
- MFA、管理员准入和外观资源均为加法能力；停用策略或降级操作不得删除审计、MFA 数据、用户风格源包或会话安全记录。
- 新的外部插件脚手架声明 `>=0.6.0 <0.14.0` 与 Go SDK `v0.13`。已有包应先通过 `campusosctl plugin inspect` 验证，不能仅凭目录名判断可用性。

## 已知运行边界

- 真实生产压测、长稳数据、Prometheus Server 规则通知和外部 SMTP 成功投递仍需要在目标部署环境执行；仓库门禁只验证其代码、规则、隔离演练和本地合同。
- v13 不包含 Passkey、OAuth/OIDC、分布式 Session/限流、多节点 Worker、标准 MCP Server、标准 protobuf gRPC 插件协议、公开远程插件市场或 Agent 执行器。
- 风格包可使用受筛查的 `sandbox-worker.v1` 效果和授权数据查询，不能在应用主线程执行任意脚本，也不能获得数据库、JWT、Host Token 或任意宿主文件访问。

## v14 进入条件

1. 在接近生产的隔离环境采集持续负载、连接池、队列收敛和真实 Prometheus 告警证据，并将通过的预算版本化。
2. 为 Passkey/OIDC、分布式会话/限流或多节点 Worker 分别撰写威胁模型、迁移策略和回滚演练，不与业务功能捆绑上线。
3. 若推进标准 MCP、protobuf gRPC、远程插件市场或 Agent Runner，先冻结公开协议、最小权限、资源隔离、审计和兼容策略。
4. 保持所有新增模块、路由、迁移和资源包继续通过 `make release-check`、架构边界检查、数据库审计和双端外观矩阵。
