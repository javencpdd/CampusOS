# CampusOS v13 最终专业审计与后续路线

> 审计日期：2026-07-26
> 审计对象：`docs/项目计划v13/00-v13版本计划书.md` 与当前 `v0.13.0` 工作树  
> 结论：v13 最终接受范围已完成；首页包、响应式交互、主题运行时和内容治理产品缺口均已补齐
> 关联进度：[v0.13.14-dev](../进度/v0.13-dev/v0.13.14-dev.md)、[v0.13.15-dev](../进度/v0.13-dev/v0.13.15-dev.md)、[v0.13.16-dev](../进度/v0.13-dev/v0.13.16-dev.md)

## 1. 结论

审计没有发现仍未实现的 v13 P0/P1 业务能力。G0、A0-A6、B1-B3、C0 与 Final 均能从代码、迁移、测试或运行证据反向定位，完整发布门禁再次通过。

审计过程中发现一处验收覆盖缺口：原风格包浏览器矩阵静态校验了五个内置包，却只实渲染两套系统主题和两套个人主页包，漏掉 `campus-hero` 首页包。现已补入管理端切换、用户首页 Desktop/Mobile/Bridge 渲染和测试后回滚，五个内置包均有真实浏览器证据。

后续响应式复核又发现四项产品缺口：管理端桌面侧栏不可折叠；用户端主导航在窄屏只做横向滚动；课表步进器在横屏手机仍是桌面尺寸且使用英文组件语义；帖子列表把桌面表格压入移动视口。现已统一使用现有布局能力合同，分别交付桌面折叠、移动导航抽屉、44px 中文步进控件和紧凑帖子列表。

截图审查还定位到主题运行时兼容缺口：资源包 CSS 合同以 `.app-container[data-campusos-web]` 为根，而运行时根节点缺少 `app-container` 类，导致 Aurora 的正文表面和遮罩没有真正应用。兼容类及 reduced-motion 强制降级现已恢复，矩阵同时验证根合同与注入样式；资源包列表改为从 `data/resources` 自动发现，新增包无法再因漏改数组而逃离双端门禁。

同时发现早期计划文本将“未来通用第三方包隔离渲染 Runner”写成了 v13 强制实现，但最终代码只交付了严格静态导入门和仓库内置包发布矩阵。审计没有在 API 进程中仓促加入浏览器代码执行器，而是根据安全边界明确后置：没有独立进程/容器、资源配额、网络隔离和可信证明存储前，动态上传包不能宣称已获得真实渲染认证。

2026-07-26 的内容治理复核又发现三项产品闭环缺口：管理员把帖子移入回收站后作者没有消息提示；管理端只能
逐条治理；统一发布页在手机端未给出互助和二手入口。现已复用既有 `notifications` 表建立用户隔离的站内通知，
并把通知写入管理员回收命令的同一可靠事务；管理端增加当前页全选和逐项授权的批量操作；统一发布页按实际容器
切换控件，并在 PC/移动端都提供图文、普通、互助和二手四类入口。该补充不新增 migration，不把批量入口变成
绕过权限的服务端后门，也不把 30 秒站内轮询误称为邮件或实时推送。

## 2. 审计方法

1. 将计划总表和最终验收的每条承诺映射到实现入口、迁移、负向测试和用户界面。
2. 核对生成路由、Permission Code、错误目录、指标目录、数据库架构视图、资源 checksum 和版本合同。
3. 运行包含数据库 audit、历史迁移、v13 migration、隔离容量、备份恢复、构建和真实浏览器矩阵的完整发布门禁。
4. 区分仓库可验证结果与只能在真实部署环境验证的生产长稳、告警通知和外部邮件投递。

## 4. 当前已经具备的功能

### 4.1 性能与一致性

- 校园互助和二手列表使用批量 Detail 读取，并在缺 Detail 时稳定失败和记录完整性信号。
- 容量工具只访问 loopback 和固定有界读 API，受保护采样只能读取权限为 `0600` 的本地授权文件。
- Web/Admin 主资源包有版本化预算，查询、goroutine、heap、DB 等待和队列年龄进入候选比较。

### 4.2 错误与可观测性

- API 保留旧顶层包络并增加稳定 machine code、request ID、retryable 和安全 details。
- HTTP、数据库、Identity、Email、可靠任务和结构化内容使用低基数指标目录。
- Prometheus 导出默认关闭且只允许显式 loopback 地址；Admin 提供有界摘要而不暴露内部 Collector。

### 4.3 可靠任务运营

- Outbox Worker 具有 lease fencing、独立 consumer receipt、重试、dead-letter、最终化和故障恢复。
- 管理端能查看积压、最老事件、失败趋势和安全诊断；重放仍需权限、原因、审计和幂等保护。
- Worker 停止、consumer crash、SMTP 临时失败、最终化失败和 dead-letter 增长均有测试或 Runbook。

### 4.4 外观资源

- 系统主题、首页包和个人主页包属于 `data/resources`，不伪装成 External Plugin。
- 新导入和应用必须通过路径、HTML/CSS/JS、双端声明、双预览、对比度、配置值域和 reduced-motion 静态硬门。
- 五个仓库内置包由目录自动发现，均通过 Desktop `1440x1000`、Mobile Narrow `320x568`、Mobile
  `390x844`、Mobile Landscape `852x393` 和 Bridge `768x1024` 的真实浏览器矩阵。
- 用户端在紧凑模式使用独立主导航和帖子条目布局；课表继续使用日程视图并提供不小于 44px 的中文步进控件。
- 管理端桌面侧栏可折叠且保存本机偏好，紧凑模式继续使用遮罩抽屉；两种状态不会动态增删路由。
- 主题运行时同时保留 `campus-theme-root` 与风格包合同要求的 `app-container`，减少动态效果时强制关闭内容入场动画。

### 4.5 管理平面与身份安全

- 管理员准入账号独立于普通角色授权，可暂停/恢复，状态变更撤销 Session 并写 required audit/Outbox。
- 事务内保护最后一个可用管理员，提供需要部署 Secret 和本机确认的受控恢复命令。
- 支持 TOTP、恢复码、MFA 登录 Ticket、Session 认证强度和高风险 Step-up；Secret 不进入数据库明文、日志、插件或资源包。

### 4.6 内容治理与发布体验

- 管理员或其他治理主体把帖子移入回收站时，作者收到 `community.thread.trashed` 站内通知；用户自删和管理员
  删除自己的内容不会产生重复通知。
- 帖子状态、治理记录和通知在同一可靠事务中提交；通知保存失败时治理命令回滚。
- 用户通知 API 只按当前 JWT 用户读取和更新；跨用户标记已读按不存在处理。
- 管理端可全选当前页并批量置顶、锁定、审核、下架、恢复、回收或清除。每项继续经过原权限、板块作用域、
  状态机、审计和可靠事务，部分失败会明确汇总。
- 统一发布页在 PC 和移动端都提供图文、普通文本、校园互助和校园二手入口；专用编辑器继续支持安全图文、
  图片上传、纯文本和服务端预览。

## 5. 本次运行证据

以下命令在当前工作树再次通过：

```bash
RUN_RESTORE_DRILL=true RUN_BROWSER_SMOKE=true STYLE_PACK_SCREENSHOT_DIR=/tmp/campusos-style-pack-final make release-check
```

关键结果：

- 全量 Go 测试、合同、版本、架构和可靠性边界通过。
- 40 个 migration、68 张表与架构视图一致，数据库 78 项 audit 总违规数为 0。
- v10-v13 历史迁移及 `000039-000040` 的隔离 `up/down/up` 通过。
- 隔离容量、备份恢复、Web/Admin/docs-site/TypeScript SDK 和插件模板通过。
- 认证、帖子 CRUD、权限、管理员准入、MFA 策略、五包五视口矩阵和七视口响应式浏览器流程通过。

本轮前端补丁后的第一次完整门禁在隔离容量演练中因单次 Go `HeapAlloc` 快照增长超过 50% 预算失败；
没有调整预算、跳过检查或修改服务端实现。第二次执行同一完整命令通过全部阶段，因此接受本次工作树；单快照受
GC 时点影响的问题已登记为后续容量工具稳定性改进项，不能据此宣称完成生产长稳验证。

## 6. 兼容与回滚结论

- 数据库只追加 `000039-000040`，未改写历史 migration；生产继续以 forward-fix 为主。
- 统一错误保留旧顶层字段，旧客户端仍可按 `code/msg/data` 工作。
- 旧风格包保持 `legacy-readonly`，不会因升级被删除；新包静态失败时不能应用。
- MFA 策略可回到 `off`/grace，但不能删除审计、恢复旧 Secret 或放宽 Session 验证。
- 当前工作树尚未由本次 `nocommit` 流程创建提交或标签；正式分发前仍需审查差异并形成不可变发布提交。

## 7. 仍需后续完成的能力

这些不是 v13 已完成项，也不应在产品说明中提前宣称：

1. 真实生产流量下的长稳、峰值和多节点容量基线。
2. 外部 Prometheus Server、真实告警通知链路和告警响应演练。
3. 外部 SMTP 的退信、Provider 故障转移和集群级投递配额。
4. 通用上传风格包的独立进程/容器渲染 Runner、`pending-validation`、checksum 证明和可信报告存储。
5. Passkey、OAuth/OIDC、分布式 Session/限流和多节点 Reliability Worker。
6. 标准 MCP Server、正式 protobuf gRPC、Agent Runner、远程插件市场和真实 Discord/OneBot Adapter。
7. 邮件、浏览器 Push、WebSocket/SSE 或第三方平台通知，以及按事件类型配置的用户通知偏好。
8. 面向超大筛选结果的服务端异步批量治理任务、审批、取消、进度和幂等审计；当前批量范围仅为当前页。

## 8. 下一版本进入条件

- 先为候选能力写威胁模型、数据所有权、权限码、审计和回滚方案，再进入实现。
- 通用渲染 Runner 必须与 API 进程隔离，默认断网、只读输入、临时输出、限时限额，并验证报告与 checksum 绑定。
- 分布式身份或 Worker 改造必须先定义幂等、时钟、租约、Session 撤销和多节点一致性合同。
- 正式发布前将当前已通过门禁的工作树形成审查过的提交/标签，并保存对应候选环境证据。
