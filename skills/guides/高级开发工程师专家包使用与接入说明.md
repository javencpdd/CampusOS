# 高级开发工程师（senior-developer）专家包使用与接入说明

> 更新时间：2026-09-22（Asia/Shanghai）  
> 专家包源目录：`skills/sources/senior-developer/`  
> 适用对象：CampusOS 维护者、使用 Codex 开发 CampusOS 的开发者

## 1. 结论：当前状态与正确定位

`senior-developer` 当前是从 WorkBuddy 导入的**专家包**，不是一个已经注册为 CampusOS 仓库 Skill 的单一入口。它包含：

- 角色配置：`agents/senior-developer.md`，规定“先计划、增量实现、验证后交付”的工程协作风格；
- `fullstack-dev`：全栈架构、API、认证、配置、文件上传和发布检查参考；
- `frontend-dev`：高表现力页面、动效和 MiniMax 媒体资产生成参考；
- `browser-use`：使用 `browser-use` 命令行进行网页自动化的参考；
- 上述能力需要的参考资料、脚本、模板、字体和字体许可证。

因此，在**当前仓库状态**下，不能假定下面的调用可用：

```text
$senior-developer
$fullstack-dev
$frontend-dev
$browser-use
```

原因是 CampusOS 的自动发现只扫描 `skills/sources/<skill-name>/SKILL.md`，并由 `.agents/skills/<skill-name>/SKILL.md`
桥接发现；该专家包的三个 `SKILL.md` 位于二级目录 `skills/sources/senior-developer/skills/`，根目录没有
`SKILL.md`，所以同步检查会忽略它。此结论不是安装失败，也不代表包内容不可用。

## 2. 目录与各部分职责

| 路径 | 内容 | 当前用途 |
| --- | --- | --- |
| `agents/senior-developer.md` | 工程师角色、计划/实现/验证/交付约定 | 可作为人工阅读的协作规范；不是 Codex 自动发现入口。 |
| `skills/fullstack-dev/` | 全栈工作流和 9 份架构、API、认证、数据库、测试参考 | 设计大型跨前后端需求时按需阅读。 |
| `skills/frontend-dev/` | 页面设计、动效、MiniMax 媒体脚本、模板、字体 | 营销页、视觉动效或获授权的媒体生成任务时使用。 |
| `skills/browser-use/` | `browser-use` CLI 自动化说明与多会话/CDP 参考 | 仅在工具已安装且当前环境确实需要该 CLI 时使用。 |
| `.codebuddy-plugin/plugin.json` | WorkBuddy 的专家包元数据 | CampusOS/Codex 不读取它，不作为运行配置。 |
| `MANIFEST.md`、`MIGRATION.md` | 原始导出清单、跨平台迁移提示 | 用于来源和依赖审阅，不能替代 CampusOS 接入规范。 |

专家包约 6 MB，其中大量内容为字体及 OFL 许可证。字体如被用于产品资源，许可证文件必须随资源保留；
`frontend-dev/.DS_Store` 已被仓库 `.gitignore` 忽略，不应作为项目资源提交。

## 3. 三项能力何时适合 CampusOS

| 能力 | 适合使用 | 不宜使用 | CampusOS 优先入口 |
| --- | --- | --- | --- |
| `fullstack-dev` | 新模块、跨 Web/API/数据库的完整设计、认证或实时能力方案 | 单文件修改、小型缺陷修复、只改 schema | 先用 `campusos-project-onboarding` 了解现状；实现使用 `campusos-dev-nocommit`。 |
| `frontend-dev` | 官网、专题页、复杂交互动效、经确认的 AI 图像/音视频资产 | 后台 CRUD、普通表单、小幅样式修正 | 普通 UI 问题优先 `campusos-webui-regression`；现有设计系统优先于重新引入动效库。 |
| `browser-use` | 独立浏览器会话的流程验收、截图、表单操作、可复现网页采集 | 只读接口验证、已有 CUA/浏览器工具足够的情况 | 优先使用当前 Codex 的浏览器自动化与 `campusos-webui-regression`；仅在 CLI 已安装时补充使用。 |

`fullstack-dev` 的“Feature-first、边界验证、类型化错误、集中配置、健康检查和验证交付”原则与 CampusOS 目标一致。
但其中 Node、Django、React 的示例是通用参考，不应替代 CampusOS 既有 Go、Vue、PostgreSQL、Docker 和迁移规范。

## 4. 当前可用的人工参考方式

在尚未完成正式接入前，可以在任务提示中明确引用所需范围，例如：

```text
参考 skills/sources/senior-developer/agents/senior-developer.md 的“小步实现与验证”原则，
并结合 CampusOS 的 $campusos-dev-nocommit 完成此项 Go/Vue 功能；不要提交或推送。
```

大型跨层需求可再限定引用：

```text
参考 skills/sources/senior-developer/skills/fullstack-dev/SKILL.md 中的 API、认证和测试检查项，
但以 CampusOS 现有架构、迁移规范和专项 Skill 为准。
```

这属于“把文档作为任务上下文”，不是 `$` 形式的自动 Skill 调用。角色配置也不能覆盖 Codex 的系统规则、
仓库规则、用户授权边界或现有 CampusOS Skill 的约束。

## 5. 前端媒体与浏览器自动化的安全边界

### 5.1 `frontend-dev` 的 MiniMax 脚本

`minimax_image.py`、`minimax_video.py`、`minimax_tts.py`、`minimax_music.py` 依赖 Python 3、`requests` 和
`MINIMAX_API_KEY`（可选 `MINIMAX_API_BASE`）。密钥只能保存在个人环境变量或已批准的密钥管理配置中，不能写入
仓库、`plugin.yaml`、Docker 镜像层、进度文档或截图。

脚本可能产生外部 API 调用、费用和媒体版权风险。使用前必须让任务明确包含媒体生成，并先让需求方确认资产用途、
提示词、规格、预算和授权；不得因为参考包包含脚本就自行调用。CampusOS 已有图片生成能力时，应优先使用当前任务
可用且经用户授权的工具。

### 5.2 `browser-use` CLI

该子 Skill 的 `allowed-tools: Bash(browser-use:*)` 与 WorkBuddy 绑定，不能直接视为 Codex 权限。当前 Codex
会话是否可用取决于本机是否安装 `browser-use` CLI；先执行 `browser-use doctor`，再决定是否使用。

- 不要自动执行文档中的 `curl | bash` 安装命令；安装是外部软件变更，需用户明确授权。
- 不要自行连接用户真实 Chrome、导入 Cookie、创建云账号、申请 API Key 或启动公网隧道。
- 需要登录态时，先说明会使用哪个浏览器配置文件，并由用户确认；无登录态的页面可使用隔离测试会话。
- CampusOS 本地 Docker 验收优先经过现有 Docker 开发流程，不要把隧道暴露当作常规测试步骤。

## 6. 推荐的正式接入方案（尚未执行）

若希望 clone 后可直接以 `$` 形式调用，应将三个子 Skill **扁平化为独立、可发现的 CampusOS Skill**，不要为整个
专家包制作一个会无差别触发所有能力的巨大入口。建议命名为：

```text
skills/sources/senior-developer-fullstack/SKILL.md
skills/sources/senior-developer-frontend/SKILL.md
skills/sources/senior-developer-browser/SKILL.md
```

接入步骤：

1. 将相应子目录的 `SKILL.md`、`references/`、`scripts/`、`templates/` 和必要字体放入对应规范源目录；保留字体
   OFL 许可证。
2. 把 frontmatter 缩减为 CampusOS 规范支持的 `name`、`description`，移除或改写 WorkBuddy 专有字段，例如
   `allowed-tools`、`metadata.clawdbot`、多余的描述字段。
3. 以 CampusOS 的 Go/Vue/Docker/权限/迁移规则重写与项目冲突的泛化指令；新增 `更新时间`，且不要把角色人设
   伪装成工具权限。
4. 运行桥接同步脚本，为三个目录生成 `.agents/skills/` 发现桥接；不要写入用户级 `.codex` 或 `.agents` 目录。
5. 对每个源目录和桥接运行 Skill 校验、链接检查和 `git diff --check`；已打开的 Codex 会话若未刷新列表，重启一次
   Codex 后再以 `$senior-developer-fullstack` 等名称调用。

在完成上述改造前，保留当前导入包原样最安全：它既可供人工参考，也不会与 CampusOS 已有 Skill 名称或自动触发逻辑冲突。
