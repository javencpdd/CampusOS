# RSS 图文订阅

> 最新更新时间：2026-11-15（Asia/Shanghai）；当前插件版本 2.0.0。

RSS Publisher 把公开 RSS/Atom 内容整理成图文，预览后交给 CampusOS 编辑器，由你核对并手动发布。订阅、解析和界面属于插件；网络、配置、图片存储和发布权限由宿主通用接口管理。

## 开始使用

1. 管理员导入已签名的 2.0.0 包，安装、批准声明的能力并启用。
2. 用户在插件中心安装到本人账号，阅读当前用途说明、同意并启用。
3. 打开插件，添加最终公开 HTTPS 订阅地址；最多保存 6 个。
4. 点击“读取最新内容”，选择一篇“预览图文”，按需加载预览图片。
5. 点击“导入图文并编辑发布”，在宿主弹窗确认。图片转存后进入原生编辑器，核对来源、转载权限、图片和版块，再点击发布。

**普通浏览器即可使用，无需下载本机抓取助手或 Windows 直连启动器。** 插件使用 opaque iframe，通过本站地址加载，不依赖通配域名或额外 UI 端口。宿主仍限制它访问 Cookie、浏览器存储、页面 DOM 和业务数据。

## 抓取发生在哪里

插件 JS 负责解析和界面，通过通用 web.read 接口让服务器读取公开 HTTPS 资源。浏览器不会直接跨域读取 RSS 源，所以源站没有 CORS 支持也不要求用户下载程序。服务器无法访问源站时仍会失败，应检查服务器出站访问及最终地址。

仅接受公开 HTTPS，不接受登录凭据、私网、重定向或超限文件；每个源文档/图片最多 1 MiB。预览图片使用经过宿主校验的 Blob，导入图片归本人空间。取消导入不会自动发布；已经转存的图片保留在本人空间。

## 从 1.0.0 升级

1.0.0 的专用接口和本机助手已退役。管理员应通过原插件中心导入新签名版本并执行升级，重新核对 web.public.read 等能力；用户按新版本用途完成同意。不能覆盖旧包或继续沿用同一版本号发布不同字节。现有订阅字段保持兼容，正常升级会保留本人配置。

原 Windows 直连启动器仅适用于仍使用独立子域的其他插件的网络排障，不是 RSS 2.0.0 的使用步骤。

## 独立构建

在仓库根目录执行：

```bash
node plugins/campusos.rss-publisher/frontend/build.mjs
node --test plugins/campusos.rss-publisher/frontend/model.test.mjs
go run ./cmd/campusos-plugin-v5-check -root plugins
```

构建仅修改插件自己的 dist 和清单摘要；签名、导入、授权、启用沿用[插件体系](/plugins/overview)。安装和卸载不能修改宿主源码、依赖锁文件、二进制或核心数据库 schema。卸载插件也不会删除已经由你发布的社区文章。

## 服务器与本机代理的权限

本版本的读取位置是 CampusOS 服务器，界面只读说明这一点。服务器代理地址、认证、是否启用以及活动线路全部由管理员统一配置。用户插件 UI 不提供服务器代理开关、目录查询或线路选择；普通配置也不保存 proxy_profile 等服务器策略字段。

管理员可在部署配置中注册 HTTP/HTTPS/SOCKS5 端点（CAMPUSOS_PLUGIN_WEB_PROXY_PROFILES），再用 CAMPUSOS_PLUGIN_WEB_PROXY_PROFILE 选定活动编号；空编号表示管理员选择直连。策略统一用于订阅、预览图片及导入图片。代理不可用时请求失败，不绕过管理员策略自动直连；代理地址和口令不传给插件。

127.0.0.1 指 API 所在机器或容器，Windows 电脑的回环地址不能代替服务器地址。本机助手则是在用户电脑发请求，其代理应由本人配置并只作用于该客户端；旧助手没有代理配置入口且已退役，2.0.0 只提供免下载的服务器读取。若未来恢复可选本机读取，必须采用独立客户端与标准能力，不能把用户代理写到服务器或恢复宿主 RSS 注入。

部署示例及地址说明见 [宿主配置说明](/deployment/configuration#插件公开读取代理)。普通网页 JS 不能设置任意 HTTP/SOCKS 隧道，也不能绕过 CORS；仅打开浏览器代理不代表其他客户端进程自动使用它。
