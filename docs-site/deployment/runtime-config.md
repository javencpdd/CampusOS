# 后台修改运行配置

登录管理端，打开 **系统与运维 → 运行配置**。默认超级管理员具备此权限。

表单支持管理员 MFA、SMTP 邮件、插件界面允许来源，以及 AI 开关、请求超时和限额。还可以点击“打开配置文件”编辑当前部署的完整 env。布尔项用复选框，其他字段用下拉框或文本框。模型端点、凭据及模型绑定继续在模型管理中设置。

1. 修改需要调整的字段。SMTP 密码只显示“已配置”，留空保留原值；勾选“清除已保存凭据”才清空。
2. 点击 **仅保存** 或 **保存并重启 API**，在弹窗中选择验证方式：
   - **管理员密码**：再次输入当前登录管理员的密码；默认选中，尚未绑定 MFA 也可使用。
   - **MFA 验证码**：已绑定验证器时可选，输入当前6位验证码。
3. 验证通过后写入文件，选择重启时立即应用。密码验证只授权本次配置操作，不将登录会话升级为 MFA，也不修改账号密码或全局 MFA 开关。
4. 重启期间 API 短暂不可用；页面等待恢复，确认新配置已加载后显示“已生效”，不会自动刷新整个页面。

文件中原有注释及其他配置项会保留；同目录的 `.bak` 保存上一份文件，文件权限为0600。备份也含部署秘密，应与原配置一起私下保管。版本冲突会拒绝保存，请重新加载后核对修改。

## 直接编辑 env 文件

1. 点击 **打开配置文件**，通过当前管理员密码或 MFA 验证后打开文本编辑器。完整文件包含部署凭据，只有具备配置管理权限的管理员可以读取，请私下操作。
2. 编辑 `KEY=value`、注释或其他配置项，点击 **应用到运行配置**。常用字段同步显示为文本中的值，此时仅修改页面草稿，文件尚未写入。
3. 可以继续核对或修改表单；再次打开编辑器时，表单修改也会同步到文本。取消编辑器会放弃本次文本编辑，保留此前草稿。
4. 点击 **仅保存** 或 **保存并重启 API**，再次验证后才写入完整文件。文件版本不一致时拒绝覆盖，需重新加载核对。

支持单行字面值、单双引号和注释；重复键、变量插值、命令和多行值会被拒绝，并提示行号。文件上限 256 KiB。已有凭据在完整文件中是实际值；与表单中“留空保留”的密码框不同，直接修改或删除该行会修改或删除文件里的对应设置。

页面列出常用表单以外的改动键名。它们会保存，但 **API 应用重启只重新加载常用运行项**。端口、数据库连接、Docker 网络、镜像、挂载及密钥等仍须部署者执行 `docker-dev.* up` 或相应维护流程；重启成功不代表这些设置已经应用。修改数据库密码不会自动轮换数据库内的密码，也不要删除数据卷。

完整文件只保留在当前页面内存中，不写入浏览器持久存储。普通配置读取继续隐藏凭据；文件读取和写入都检查管理权限、确认身份、CSRF与当前文件版本，记录不含正文或凭据的操作审计。

## Docker 开发环境

使用 `docker-dev.* setup --start` 或 `up` 启动标准配置 `deploy/docker/.env.dev.local`，启动工具会将它注册为受管文件。已有容器升级到本功能后先执行一次：

```bash
./scripts/docker-dev.sh up
```

Windows PowerShell：

```powershell
.\scripts\docker-dev.ps1 up
```

此操作使用现有镜像。后台保存的是同一个 `.env.dev.local`；API 应用重启时重新读取白名单中的运行字段，以覆盖容器启动时的旧环境快照，无需 Docker Socket 或重建镜像。

端口、数据库、Docker 网络、挂载和加密主密钥由部署工具管理。手工修改这些参数仍需 `docker-dev.* up`；更换数据库密码还须按数据库维护流程同步，不能靠改环境文件完成密码轮换。

使用 `CAMPUSOS_DOCKER_DEV_ENV` 指定其他文件时，启动工具默认关闭编辑，避免误改标准部署的配置。

## 原生部署

部署者可设置 `CAMPUSOS_MANAGED_ENV_FILE`，指向 API 有读写权限的实际配置文件，再启动 API。文件及父目录不能是符号链接，文件不能允许组或其他用户写入。未注册文件时，页面显示此部署尚未开放编辑。

常用受管字段和完整文本编辑支持单行字面 dotenv 值和注释；双引号中的 `$$` 表示字面 `$`，不执行 Shell/Compose 变量插值。后台保存会自动转义。已有受管字段包含变量表达式、重复定义或不支持的语法时，编辑失败关闭，由部署者本地整理后重启。

当前已验证 Linux Docker 和 Linux 原生部署的保存与重启；PowerShell 启动合同保持一致，Windows 文件权限与实机重启需在目标环境另验。

## 失败时如何判断

- 提示配置已被修改：其他页面或本机编辑已先保存，重新加载后合并修改。
- 提示权限：使用具有配置管理权限的独立管理员；再次输入密码不能补足权限。
- 提示管理员密码不正确：重新输入当前管理员密码；错误密码不会退出登录或保存配置。连续失败会短暂限制当前管理员的密码验证尝试。
- 选择 MFA 后验证码错误：配置不会写入，可重新输入或切换管理员密码；尚未绑定验证器时直接选择密码即可。
- 提示文件不可编辑：检查受管路径、格式、权限及是否使用了自定义配置文件。
- 超时未确认重启：重新加载页面并检查平台日志，不要连续重复保存。不会将一次健康响应当作新配置已经生效。

配置保存在部署文件中，PostgreSQL 只增加读取/管理权限以及脱敏的操作意图审计，不保存 SMTP 明文凭据。文件写入和数据库不能合并为一个事务：审计失败不会修改文件；文件写入失败会保留此前已接受的意图记录。页面重新读取文件版本和 API 代次，以核对最终状态。


从v1.2.183起，上述两种验证方式同时可用。省略新验证字段的旧API客户端仍沿用原会话/MFA策略；显式密码方式必须每次提交当前密码，服务端在审计及文件写入前重新核对当前账号、会话、凭据版本和配置管理权限。再次输入的管理员密码不写入配置、备份、操作审计或Outbox，也不回传；审计只记录选用的方式。失败尝试限制在单个API进程内按管理员账号计数，API重启后重置。
