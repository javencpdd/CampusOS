# 初始管理员安全

> 更新时间：2026-10-29（Asia/Shanghai）
> 适用范围：当前v1.2开发候选，不代表整版正式发布。

## 默认管理员

正常应用首次启动时，如果独立管理域完全没有账号，会自动创建超级管理员：用户名 `admin`，初始密码 `admin`，联系邮箱 `admin@campusos.local`。直接在3001管理端使用用户名登录，无须先配置初始化凭证。

已有任何管理域账号时不再默认播种；修改后的密码不会因重启或重新构建镜像而重置。迁移仅建立表和角色参考数据，默认账号由应用服务在事务中创建，角色绑定、必需审计与Outbox一起提交。测试profile使用夹具，恢复审查中的实例不默认播种。

## 登录后修改密码

在管理端右上角点击“修改密码”，输入当前密码和两次新密码。新密码为6–64字节；成功后重新登录，该管理员的所有旧会话和未消费恢复票据失效，其他账号及系统配置保持原样。

已绑定认证器且部署要求MFA时，先完成“管理员认证”；没有绑定的初始账号可先修改密码。改密不会关闭MFA或删除认证器。

## 额外创建超级管理员

在API所在部署主机的仓库根目录执行：

```bash
python3 scripts/bootstrap-admin.py
```

默认定位当前Docker开发API容器，使用该容器现有的数据库配置执行本机CLI。只需输入新的用户名、邮箱和两次隐藏密码，不再输入 `AUTH_ADMIN_BOOTSTRAP_SECRET`。已有账号不会被覆盖；默认管理员和新增管理员可以同时存在，MFA、邮件、JWT、主题及其他配置都保持原样，创建后无需重启。

原生部署可使用 `--native`，或通过 `--runtime-profile` 显式复用私有运行JSON。命令需要本机部署控制权限，不开放给HTTP或插件。完整步骤在仓库 `docs/help/系统设计相关/v1.2独立管理员初始化与账号隔离.md`。

## 管理员与用户是两个身份域

当前共用一个PostgreSQL数据库，但账号、密码、会话和角色绑定分别存储：

| 身份域 | 主要表 | 登录入口 |
| --- | --- | --- |
| 用户 | `users`、`accounts`、`sessions`、`user_roles` | 3000，`/api/v1/auth/login` |
| 管理员 | `admin_accounts`、`admin_credentials`、`admin_sessions`、`admin_role_bindings` | 3001，`/api/v1/admin/identity/login` |

管理域账号不外键依赖用户账号。相同邮箱或数字ID不会合并身份；普通用户获得旧admin角色也不会自动开通管理域。历史用户域兼容凭据不是新的独立管理员密码。

## 二次认证配置

独立管理端敏感操作默认要求TOTP二次验证。部署者可在实际配置设置 `AUTH_ADMIN_MFA_REQUIRED=false` 关闭，未配置、空值或非法值保持开启。修改后执行 `docker-dev.* up` 应用环境；后台MFA页面展示当前生效状态和配置步骤。

开启时，首次登录后可按引导准备认证器、开始配置、添加密钥、输入6位验证码绑定，并等待下一组验证码确认身份。认证当前有效期15分钟。关闭开关仍保留密码、活跃会话、账号状态、角色/资源权限、CSRF与必需审计，不会删除既有绑定或将密码会话伪装为MFA。用户域和受托授权的独立MFA要求保持。

## 兼容配置与恢复

`AUTH_ADMIN_BOOTSTRAP_SECRET` 只控制原来的回环HTTP首次初始化入口，启用时为8–4096字节、须区别于旧用户域凭据。它可以保持原值或留空，不影响默认账号与本机新增命令；脚本不会自动改写配置。`--http` 显式保留旧客户端模式，已有有效安全管理员时仍拒绝首次初始化。

旧 `AUTH_BOOTSTRAP_ADMIN_SECRET` 仍用于用户域兼容引导及本地恢复；现行生产配置校验仍要求至少16字符。生产JWT、密码哈希、邮件及会话/MFA密钥要求保持。已有管理员遗失密码或认证器时使用独立Admin本地恢复流程；新增命令不会重置账号。
