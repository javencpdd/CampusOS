# 验证码策略配置

CampusOS 默认限制同一邮箱任意连续 `10` 分钟最多发送 `5` 个验证码，同一来源 IP 任意连续 `60`
分钟最多发送 `10` 个。注册、密码找回、邮箱绑定和辅助恢复共用这套 Identity Core 安全策略。

## 修改为 5 分钟最多 2 条

1. 登录管理端 `http://localhost:3001`。
2. 打开“用户与权限 -> 验证码策略”。
3. 将邮箱“统计窗口（分钟）”改为 `5`。
4. 将邮箱“最多发送（次）”改为 `2`。
5. 点击“应用策略”。

保存后立即生效，不需要重启。IP 限制仍会同时检查。

## 可配置范围

| 配置 | 范围 |
| --- | --- |
| 邮箱/IP 窗口 | 1 至 1440 分钟 |
| 邮箱次数 | 1 至 100 |
| IP 次数 | 1 至 1000 |

限流属于始终启用的安全能力，不能设置为零或通过插件开关关闭。读取需要
`identity.challenge_policy.read`，修改需要 `identity.challenge_policy.update`；修改会写 required
audit 和不含敏感字段的可靠事件。

## 密码找回的请求编号

普通“邮箱找回”发送成功后，Web 页面会在内存中保存 API 返回的 `challenge_id`。用户只需填写邮箱、
验证码和新密码，不需要抄写请求编号。只有管理员从另一设备发起的“辅助恢复”仍需用户输入邮件中的
请求编号。

## 收不到邮件

限流策略只决定是否允许创建验证码，不负责建立真实邮箱连接。若请求已受理但收不到邮件，检查 SMTP
配置、邮件投递状态和可靠任务，参见[邮件投递与 SMTP](/deployment/email-delivery)。开发环境的 Fake
Provider 不会向真实邮箱发送邮件。
