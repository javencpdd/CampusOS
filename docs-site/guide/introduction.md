# 项目介绍

> 更新时间：2026-10-28（Asia/Shanghai）
> 当前开发主线：`v1.2-dev`；运行版本标识：`v1.1.0-dev`。整版 Final 验收仍在进行，尚未宣布正式发布。

CampusOS 是一个开源的校园社区与扩展平台，把交流、个人内容与知识检索放进同一个校园空间。学校或开发团队可以自主部署，围绕自己的校园逐步配置内容、权限、外观和扩展能力。

[项目官网](/)介绍产品与参与方式；本文和侧边栏提供具体的使用、部署及开发文档。官网中的产品场景是示意内容，不是线上业务数据或可直接操作的社区。

## 在 CampusOS 中可以做什么

| 场景 | 当前能力 | 下一步 |
| --- | --- | --- |
| 校园交流与治理 | 版块、标签、帖子、回复、图文文章、互助、二手、通知，以及内容审核与版主范围 | [内容与发布](/guide/structured-image-text) |
| 个人内容与资料 | 个人空间、头像、文档、文章附件、配额和受控下载；文件仍由原业务判断访问权限 | [个人空间与通知](/guide/web-ui-storage-notifications) |
| 公开知识检索 | 管理员选择官方资料、公开帖子或版块形成集合；搜索结果附带当前来源引用 | [公开知识检索](/guide/public-knowledge-search) |
| 我的私人知识 | 本人逐项选择受支持文档或文本讨论帖，建立私人索引，查看状态并随时撤回 | [私人知识](/guide/private-knowledge) |
| 有据问答 | 配置受管文本模型后，依据公开集合或单个已选私人来源回答；私人模型发送需要另行逐次确认 | [有据问答](/guide/cited-rag)、[受管模型](/guide/managed-ai) |
| 可治理的扩展 | v5 签名包、独立安装、版本审批、分域配置、隔离 UI 与受限 Runtime；也可使用无业务 Runtime 的主题和风格资源包 | [插件体系](/plugins/overview)、[资源包](/plugins/style-packs) |

搜索不依赖 AI 模型。私人索引同意不包含模型发送同意；模型、插件和检索结果都不能扩大原来源的可读范围。问答应核对引用，不作为校园官方结论。

## 管理员与普通用户

管理端与用户端使用独立身份域：账号、密码凭据、会话、角色绑定和 Token 分开管理，不能通过给普通用户追加同名角色直接获得后台身份。它们位于同一个 PostgreSQL 实例中，并不要求两个物理数据库。

管理端没有固定默认超级用户，首次由部署者初始化。管理员 MFA 默认开启，可由部署配置显式关闭；页面显示实际生效状态，并提供认证器绑定与验证引导。详见[初始管理员安全](/deployment/bootstrap-security)和[管理员 MFA 与恢复](/operations/mfa)。

## 平台的四种组成

- **核心模块**：身份、社区和存储等基础事实，随 API 运行。
- **内置功能**：课表、外观、AI、Knowledge 等，随宿主交付，按各自生命周期启停。
- **外部插件**：独立签名发布和安装，通过受控 Host/SDK 接口使用能力。
- **资源包**：主题、主页或空间风格等数据资源，不执行插件业务代码。

内置 AI 与 Knowledge 不依赖安装外部插件才能运行。安装一个插件或 Provider，也不会自动授予它读取全部数据、模型密钥或数据库的权限。完整说明见[模块、插件与资源包边界](/guide/module-plugin-resource-boundaries)。

## 部署与技术组成

CampusOS 采用 Go、Gin、Vue 3 与 PostgreSQL，是模块化单体。Redis、NATS 和本地受控文件参与现有运行与任务处理；官网与文档站独立提供静态内容，不依赖管理员登录或后端 API。

```text
用户端 :3000       管理端 :3001       官网与文档 :3002
       \             /                  独立站点
        API :8080
             │
  PostgreSQL / Redis / NATS / 受控文件
             │
   插件隔离 UI Gateway :3003
```

第一次部署可从[完整入门路径](/guide/getting-started)或[Docker 开发环境](/deployment/docker-development)开始；希望理解实现时使用[开发者学习路线](/guide/developer-learning-path)。

## 当前交付状态

v1.2 的插件、权限、公开检索、私人索引和 AI/RAG 已有各阶段的实现与验收证据；最新初始化与 MFA 变更、最终候选联合回归和远端 LAN 登录/PDF 验收仍须按主计划完成。运行版本保留 `v1.1.0-dev`，不据此将 v1.2 能力描述为未开发，也不把分阶段通过称为整版正式发布。

Windows 当前必需路径为 Docker Desktop 的 Linux 容器。本机自动化及主机侧 LAN 检查已有记录，第二台设备的登录/PDF 仍待反馈；原生 Windows Go 宿主不属于本版必需验收范围。完整现状见[项目进展](/project/current-roadmap)。

尚未作为本版交付承诺：自动信任的公共插件市场、任意插件安装脚本、完整 Agent 工具循环、Office/音视频预览、多节点高可用及自动 TLS。插件 Runtime 与知识格式以已发布的有限合同为准。
